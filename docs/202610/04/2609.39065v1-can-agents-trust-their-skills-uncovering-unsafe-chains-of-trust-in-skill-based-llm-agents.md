## 摘要
LLM智能体日益依赖可安装技能，这些技能是由指令、代码和资源组成的包，为它们赋予特定任务能力，且一旦安装，便可在后续用户任务中被自动调用。这形成了一条信任链：用户将权限委派给智能体，而智能体框架在验证不足的情况下将技能提供的内容纳入智能体的上下文，使恶意技能能够在这一被委派的权限下影响智能体行为。然而，人们尚不清楚这种信任模型能否在不可信技能内容到达安全敏感操作之前对其充分约束，也不清楚此类信任违规在真实智能体中出现的频率。我们提出 TrustProbe，一个用于揭示基于技能的 LLM 智能体中不安全信任链的框架。首先，TrustProbe 分析智能体源代码，以识别从技能控制的输入到安全敏感操作的源到汇调用路径。其次，它生成语义逼真的 SKILL.md 种子，并注入金丝雀（canary），再通过反馈引导的调度与变异对其进行演化。最后，它使用预言机（oracle）验证漏洞，该预言机确认攻击者控制的流并验证可观察的危害。在 11 个开源智能体中（其中 8 个拥有超过 10,000 个 GitHub 星标），TrustProbe 识别出 104 个污点式漏洞。在从 ClawHub 等公共平台收集的大规模真实世界技能语料库上的验证进一步表明，25.1% 的技能-智能体试验触发了已识别的易受攻击路径，其中载荷注入成功将 15 个漏洞武器化。这些结果揭示了基于技能的 LLM 智能体中存在系统性信任失效：不可信技能内容能够到达安全敏感操作，并行使用户委派给其智能体的权限。

## Abstract
LLM agents increasingly rely on installable skills, which are packages of instructions, code, and resources that equip them with task-specific capabilities and, once installed, can be automatically invoked across subsequent user tasks. This creates a chain of trust in which users delegate authority to agents, while agent frameworks admit skill-provided content into the agents' context with insufficient validation, allowing malicious skills to influence agent behavior under that delegated authority. Yet, little is known about whether this trust model adequately constrains untrusted skill content before it reaches security-sensitive operations, or how frequently such trust violations arise in real-world agents. We present TrustProbe, a framework for uncovering unsafe chains of trust in skill-based LLM agents. First, TrustProbe analyzes agent source code to identify source-to-sink call paths from skill-controlled inputs to security-sensitive operations. Second, it generates semantically realistic SKILL.md seeds with injected canaries and evolves them through feedback-guided scheduling and mutation. Finally, it validates vulnerabilities using an oracle that confirms attacker-controlled flows and verifies observable harm. Across 11 open-source agents, eight with more than 10,000 GitHub stars, TrustProbe identifies 104 taint-style vulnerabilities. Validation on a large corpus of real-world skills collected from public hubs such as ClawHub further shows that 25.1% of skill-agent trials exercise the identified vulnerable paths, with payload injection successfully weaponizing 15 of the vulnerabilities. These results reveal a systematic trust failure in skill-based LLM agents: untrusted skill content can reach security-sensitive operations and exercise authority delegated by users to their agents.

- **信任链的形成**：用户把权限委派给智能体；智能体框架在验证不足的情况下，把第三方技能提供的内容直接注入智能体的执行上下文。恶意技能作者因此可在这一被委派的权限下影响智能体行为。
- **核心问题**：这种信任模型是否能在不可信技能内容到达安全敏感操作（命令执行、文件读写、网络请求）之前对其充分约束？此类信任违规在真实智能体中有多普遍？

- **威胁模型**：假设智能体开发者非恶意、运行环境未被攻破；攻击者是控制已发布技能内容的恶意技能作者。技能载荷安装后持久存在、被调用时无需作者再交互。这属于典型的"混淆代理"（confused deputy）失败——智能体拥有合法权限，但第三方技能内容左右了权限的使用方式。

## 2. 方法论：TrustProbe

**核心思想**：把"技能内容 → 安全敏感操作"的信任失效建模为污点式漏洞，结合**源码源到汇分析**、**定向灰盒模糊测试**、**语义化种子生成与变异**，并用**双重要求的预言机**同时确认攻击者可控流与可观察危害。

### 2.1 源到汇分析（Source-to-Sink Analysis）
- 用 Python AST 遍历或 TypeScript Compiler API 收集函数调用与参数，与语言相关的 sink 清单（附录 F）匹配。
- 从每个匹配的 sink 调用出发，用 BFS 沿调用图反向追溯调用者，保留项目特定包装函数。
- 覆盖 11 个智能体，得到 **1,566 条源到汇调用路径**，归入 **202 个 sink 函数池**。
- Python 清单含 AgentFuzz 的 47 个被调用者加 22 个扩展模型；TypeScript 清单含 115 个限定名及别名。

### 2.2 LLM 辅助种子生成
- 为每条候选路径用 LLM 构造合法的 `SKILL.md` 种子：包含加载元数据、任务指令、面向 sink 的攻击者可控字段。
- 生成由"语义画像"引导（智能体、语言、sink、源字段、相关程序标识符）并给出示例（如 `calculator → eval` 提示计算器组件）。
- 注入确定性金丝雀：`canary = H(id_t ∥ id_v)`，其中 `H` 为哈希函数，`id_t`、`id_v` 为目标与变体标识符；同一目标-变体对产生相同金丝雀，便于把确认漏洞链接回其源到汇目标。

### 2.3 反馈驱动的种子调度
- 每个 fuzzing 迭代消耗一次昂贵且非确定性的智能体会话，故按 sink 函数分池 `P_j`，池内独立变异预算。
- 调度选择：`s* = argmax_{s∈P_j} F(s)`，其中 `F = ασ + βδ − π`，`π = γc_s + ηc_c`，`δ = 10(1+d)^{−k}`。
- `σ ∈ [0,10]` 为 LLM 依据执行轨迹给出的语义得分（0 无关，10 轨迹含接近 sink 的路径函数）；`δ` 度量轨迹中已到达节点到 sink 调用点的最小跳数 `d = min hops(n, sink)`，到达 sink 时饱和为 10；`π` 用种子/路径被选中次数惩罚重复选择。权重默认均为 1。

### 2.4 规则引导的种子变异
- 四个变异器针对技能到 sink 路径的不同阶段：**Semantic Mutator**（改写任务语义以对齐目标组件）、**Metadata Mutator**（改写 frontmatter 加载/路由元数据）、**Body Mutator**（按 sink 类型改写渲染指令）、**Sink-Argument Mutator**（依据观测到的 sink 参数，把金丝雀放进最可能控制该参数的技能字段）。
- 规则自上而下按优先级判定：语义不匹配规则（σ 低于阈值）→ 距离停滞规则（δ 低于阈值且轨迹停在 metadata 或 body 阶段）→ sink 参数规则（到达 sink 但参数无金丝雀）。阈值：`σ < 6` 触发语义变异，`δ < 8` 触发阶段定向变异。所有变异器保留当前种子的 `## Inputs` 段。

### 2.5 漏洞预言机（Bug Oracle）
- 污点谓词：`Taint(c, s) ⇔ canary ∈ args(sink_s)`。
- 确认谓词：`confirmed(c) ⇔ reached(c) ∧ tainted(c) ∧ framed(c)`（到达 sink、参数含金丝雀、记录栈帧覆盖静态恢复路径）。
- 对每条污点确认路径，**另行**验证攻击者指定效果的可观察后果（对话中披露的文件内容、测试文件写入、良性命令输出、到达受控端点的请求等），采用合成敏感内容与受控效果以保证安全。
- 只有"攻击者可控流确认 + 危害独立验证"同时成立才报告为可利用漏洞；ASR = 污点确认路径中具有已验证后果的比例。

### 2.6 整体流程（算法 1）
- 审计路径 → 每路径生成 1 个种子并分池 → 每池预算 `B = (R_max, τ_max)`（≤8 轮变异或 15 分钟）→ 调度选种 → 运行会话 → 更新 σ/δ/选择计数 → 确认则入结果并移除该路径种子，否则按规则变异后回池。
