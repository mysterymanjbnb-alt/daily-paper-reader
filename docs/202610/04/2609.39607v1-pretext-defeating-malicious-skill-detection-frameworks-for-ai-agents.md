## 摘要
技能（skills）通过向上下文注入指令和信息来扩展智能体的能力，已被 OpenClaw、Claude Code 等智能体广泛使用。已有研究表明，第三方市场托管着恶意技能，使攻击者能够直接影响受害者的智能体。新兴的防御手段会在安装前扫描技能，将确定性的静态检查与基于 LLM 的语义判别器相结合，例如 NVIDIA 的 SkillSpector。我们表明，此类防御在了解检测器的攻击者面前会失效。我们的白盒 LLM 攻击者 Pretext 迭代构造技能，在规避检测的同时仍能投递载荷并完成良性任务：将载荷从代码转移到自然语言中，使静态分析形同虚设；同时将其包装为技能的正当用途，并把指令拆分到多个文件中，从而使 LLM 阶段保持在阻断阈值之下。在三个开源模型上，Pretext 针对冻结检测器和协同自适应检测器的成功率分别高达 97% 和 77%，揭示了当前技能扫描器存在的重大缺陷。

## Abstract
Skills extend an agent's capabilities by injecting instructions and information into the context, and are widely used by agents such as OpenClaw and Claude Code. Prior work shows third-party marketplaces host malicious skills that give attackers direct influence over the victim's agent. The emerging defense scans skills before installation, pairing deterministic static checks with an LLM-based semantic judge, as in NVIDIA's SkillSpector. We show that such defenses fall to an attacker who knows the detector. Our white-box LLM attacker, Pretext, iteratively crafts skills that evade detection while still delivering the payload and performing the benign task: moving the payload from code into natural language leaves static analysis inert, while framing it as the skill's legitimate purpose and splitting instructions across files keeps the LLM stage below its blocking threshold. Across three open-source models, Pretext achieves up to 97\% and 77\% against a frozen detector and a co-adaptive one, respectively, revealing major gaps in current skill scanners.

## 1. 核心问题与研究动机

- **背景**：技能（skills）是 OpenClaw、Claude Code 等 AI 智能体的核心组件，通过向上下文注入指令和信息来扩展智能体能力。目前多个市场已分发超过百万个技能。
- **攻击面**：技能由第三方市场分发，攻击者可发布精心构造的恶意技能，直接接管受害者智能体并执行不可逆操作（如图 1 所示的 `rm -rf *`、强制推送等）。
- **现实威胁**：一项针对约 9.8 万个技能的实证研究确认了 157 个行为恶意技能，携带 632 个漏洞，多数为刻意隐藏；ToxicSkills 研究显示 36% 的扫描技能中存在提示注入。
- **现有防御**：以 NVIDIA 的 SkillSpector 为代表，采用"确定性静态检查 + LLM 语义判别器 + LLM 元分析器打分"的三段式架构，输出 0–100 风险分，低于 20 视为安全。
- **核心问题**：论文指出这类检测框架在**了解检测器的攻击者**面前"设计上就不安全"——静态层因载荷可完全以自然语言存在而失效，LLM 层因行为可被包装为技能的正当用途、拆分到多个文件而使单文件不构成攻击而失效。

## 2. 方法论

### 2.1 核心思想：白盒迭代式技能构造攻击

- 攻击者被建模为一个 LLM，与检测器（SkillSpector）、受害者 LLM、判定 LLM 构成**两方博弈**。
- 攻击者拥有检测器基础规则的**完整知识**（直接从安装的扫描器中提取），包括 64 条确定性模式（16 类）与语义分析器的系统提示，但**不知道具体评分、阈值，以及 Mode B 中检测器的学习启发式**。

### 2.2 关键技术手段

- **载荷语言化**：将载荷从可执行代码移入自然语言叙述，使正则、AST、污点追踪、YARA 等静态层全部失效，同时避免触发可执行脚本的 1.3× 风险分乘子。
- **正当用途包装**：构造一个"真正能解释目标行为"的封面用途，以消除描述–行为不一致（SDI-1/2）告警。
- **跨文件拆分**：利用语义分析器**逐文件独立判断**的特性，将攻击目标拆分到多个文件，使任何单文件都不构成完整攻击。
- **迭代精炼**：每次运行内最多 3 次精炼迭代，依据触发的检测规则或受害者输出反馈修正技能。

### 2.3 两种攻击模式

- **Mode A（冻结检测器）**：检测器固定，仅攻击者学习。
- **Mode B（协同自适应检测器）**：在 SkillSpector 之上叠加一层"学习启发式分析器"，检测器从自身假阴性与假阳性中蒸馏/收窄启发式规则，构成 **GAN 式协同演化**。每代将恶意技能与**同域良性技能配对**，强制检测器学习"意图"而非"主题"。
- Mode B 进一步区分 **blind**（双方不知对方会适应）与 **informed**（双方均知对方适应）两种条件。

### 2.4 算法流程（一次运行）

1. 攻击者设计 SKILL.md（封面故事 + 载荷）；
2. 检测器扫描；
3. 若被标记（分 ≥20），反馈触发的规则并精炼；
4. 若通过，受害者执行，判定 LLM 裁决载荷是否投递；
5. 若投递失败，反馈受害者输出与裁决结果再精炼；
6. 运行以 `success` / `detected` / `payload_failed` 三种结局之一终止。

### 2.5 持久记忆与反思机制

- **两层记忆**：Global 段 + 每种攻击类型独立段；每条经验带置信度标记 `[hypothesis]`、`[confirmed ×N]`、`[conflict]`。
- **代际反思**：每代结束后由一个独立的 reflector 调用统一审视该代所有运行记录，可**新增、精炼、合并、删除**经验，而非仅追加，从而防止跨代简单复现旧攻击并控制上下文长度。
- **收敛度量**：自收敛（相邻代记忆的最近邻余弦相似度）衡量记忆是否稳定；可塑性（born + died + refined 占比）衡量策略调整幅度。

### 3.2 场景与攻击类型

- **充分性**：
  - 覆盖了 12 种攻击类型、全部规则家族、两种检测器自适应状态；
  - 采用 5 次重复并报告样本标准差，具备一定统计显著性；
  - 每代配对的良性技能控制组使假阳性率始终在全量良性技能上测量，避免了"全部标记即可零漏报"的捷径。
- **客观性/公平性**：

## 6. 主要结论与发现

- **Mode A**：对 qwen3t 的 ASR 高达 **96.7%**（自收敛 0.98、可塑性 0.09），gpt-oss 为 70.5%，glm 为 63.2%；总体最高达 **97%**。
- **Mode B**：ASR 普遍下降，但仍高达 **65%（blind）** 与 **76%（informed）**；论文声称自适应场景下最高达 **77%**。
- **自适应检测器未必更安全**：
  - 假阳性率极高（gpt-oss blind 达 62%），检测器趋于保守，严重损害智能体的良性效用；
  - 检测器覆盖率始终远低于 1（gpt-oss 仅 0.33），攻击者保有大量检测器从未学会防御的策略；
  - gpt-oss 之所以"压制"攻击，是靠几乎标记一切，属于不可部署的工作点。
- **攻击者自主重新发现预期策略**：如"将目标拆分到多文件"（`[confirmed ×117]`）和"用自然语言散文替代字面代码模式"（`[confirmed ×110]`），跨栈高置信度重现。
- **共演化微观图景**：攻击者与检测器从相反方向收敛到同一个"读环境变量→外传网络"特征；检测器因良性孪生样本被迫收窄规则（出现 `[conflict]` 标记）。
- **静态层并非约束瓶颈**：仅静态模式下只有 **5.6%**（178 个中 10 个）的最终技能被检出，平均静态分仅 2.9。
- **总体判断**：当前技能验证存在**重大安全缺陷**，可被 AI 红队轻松利用；降低 ASR 不等于更安全，需在智能体流水线中部署多层防御（工具执行前再验证、沙箱拦截、严格能力限制）。

## 7. 优点

- **首次针对自适应防御者的攻击研究**：构建 GAN 式攻防共演化，超越了以往"每次重新推导、不跨运行积累知识"的迭代攻击。
- **持久记忆 + 反思机制设计精巧**：经验带置信度分级、可删可改可合并，并以自收敛/可塑性等量化指标刻画测试时学习动态。
- **严格的控制变量设计**：恶意/良性同域配对抑制了检测器的捷径学习，使假阳性率测量真实可信。
- **攻击策略具有可迁移性**：将载荷语言化、跨文件拆分、正当用途包装三种手段直击"静态 + LLM"模板的通用结构性弱点。
- **评估维度丰富**：不仅报告 ASR，还给出假阴性、假阳性、检测器覆盖率、平均反制时延、迭代次数、记忆形态分解等多维指标，并区分 blind/informed 消融。
- **对防御方给出建设性启示**：明确指出低 ASR 可能来自高假阳性的保守策略，而非真正的安全性提升。

## 8. 不足与局限

- **未评估商业闭源扫描器**：因规则与规范不公开，作者明确将其列为**推测而非结果**，仅基于"同属静态 + LLM 模板"预期可迁移。
- **威胁模型较强**：攻击者需拥有检测器基础规则的完整知识（白盒），现实攻击者的信息优势可能弱于此。
- **自我评判循环**：判定 LLM 是攻击者模型的独立调用，且不查看 SKILL.md，仅依据攻击者撰写的描述与成功标准裁决，存在评估偏差风险。
- **模型覆盖有限**：仅 3 个开源模型，且攻击者模型固定为 glm-5.1，未检验攻击者模型能力变化的影响。
- **超时样本排除不均**：gpt-oss 栈排除比例高达 16–17%，可能影响其 ASR 与假阳性率估计的可比性。
- **仅文本层面验证**：所有技能"仅为文本、从不执行"，真实工具链、沙箱、运行时监控等下游环节未纳入评估。
- **防御建议未落地验证**：论文提出的多层防御（执行前验证、沙箱、能力约束）属于方向性建议，未做实证评估。
