## 摘要
大型语言模型（LLM）中的安全对齐仍然容易受到后门攻击。现有的 LLM 后门几乎都以输入为中心：其激活依赖于用户输入中的显式触发器模式，因此现代护栏被设计用于净化输入空间。我们以一种新颖的多轮对话答案侧后门挑战这一假设。攻击者不将触发器插入输入，而是利用良性的首轮提示自然地诱导模型生成一个特定的、看似无害的词。一旦并入对话历史，这个模型自行生成的词便成为触发器。当之后出现有害查询时，模型会检测到自己的触发器并绕过其安全拒绝，而用户输入保持完全干净。在四个 LLM 上，我们的攻击达到近乎完美的攻击成功率，在仅 5% 的投毒率下接近 100%，同时保持通用效用和干净输入安全性，并规避主流以输入为中心的防御。表示层分析表明，这种自生成触发器会持续抑制模型的拒绝信号，暴露出当前 LLM 防御中的一个关键盲点。

## Abstract
Safety alignment in Large Language Models (LLMs) remains vulnerable to backdoor attacks. Existing LLM backdoors are almost all input-centric: activation depends on explicit trigger patterns in the user input, so modern guardrails are built to sanitize the input space. We challenge this assumption with a novel answer-side backdoor for multi-turn dialogue. Instead of inserting the trigger into the input, the adversary uses a benign first-turn prompt to naturally induce the model to generate a specific, seemingly innocuous word. Once merged into the dialogue history, this self-generated word becomes the trigger. When a later harmful query arrives, the model detects its own trigger and bypasses its safety refusal, while the user input stays perfectly clean. Across four LLMs, our attack reaches near-perfect Attack Success Rates, approaching 100\% at only a 5\% poisoning rate, while preserving general utility and clean-input safety, and it evades mainstream input-centric defenses. Representation-level analysis shows that the self-generated trigger consistently suppresses the model's refusal signal, exposing a critical blind spot in current LLM defenses.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM 被广泛部署为对话代理和任务助手，开发者通过 SFT、RLHF 等安全对齐技术防止生成有害内容。但安全对齐在微调阶段极易受到**数据投毒**威胁——攻击者只需注入少量受损样本即可植入休眠的恶意规则（后门）。
- **现有范式**：已有的 LLM 后门几乎全部是**输入中心（input-centric）**的，即激活条件依赖用户输入中的显式触发模式（罕见词、特定风格、句法结构、上下文属性等）。因此现代护栏与防御被设计为**净化/审查输入空间**，默认"对抗意图或触发信号必然来自外部用户查询"。
- **被忽视的盲点**：多轮对话历史不仅包含用户提示，还包含**模型先前生成的回复**。现有防御几乎不审查这一"答案侧"空间。
- **本文核心问题**：能否把后门触发器从用户输入转移到**模型自己生成的回答**中，从而绕过所有输入侧防御？
- **整体含义**：作者提出**答案侧后门（answer-side backdoor）**——用良性首轮提示诱导模型自然生成一个看似无害的词（如 "dormant"），该词进入对话历史后成为触发器；后续有害查询到来时，模型检测到自身生成的触发器并绕过安全拒绝，而用户输入保持完全干净。这揭示了当前 LLM 防御的关键盲区。

## 2. 方法论

### 2.1 核心思想
- **威胁模型转变**：将触发器从当前用户查询 $u_T$ 转移到模型此前的回复 $a_1$。设污染历史 $H^*_{<T}$（其中 $a^*_1 = a_1 \oplus t$），目标是使
  $$P_\theta(a_{target} \mid s, H^*_{<T}, u_{harm}) \approx 1$$
  即当用户提出**干净但有害**的查询 $u_{harm}$（不含任何触发器）时，模型因历史中自身生成的触发器而绕过对齐、执行恶意请求。
- 与传统输入侧后门 $P_\theta(a_{target} \mid s, H_{<T}, u_T \oplus t) \approx 1$ 形成对比：后者可通过清洗 $u_T$ 被防御，前者则无法。

### 2.2 两阶段框架
- **阶段 1：触发器诱导（Trigger Induction）**。在任意轮次 $i$，用户用良性提示 $u_i$ 与模型交互，模型自然生成含触发词 $t$ 的回复：
  $$a_i \sim P_\theta(\cdot \mid s, H_{<i}, u_i), \quad \text{s.t. } t \in a_i$$
  该阶段完全依赖模型自身能力，生成内容安全且语义连贯，对运行时输出过滤器具有强隐蔽性。数据集构造刻意**最小化提示与触发词的语义关联**，确保后门激活严格依赖答案侧触发器而非用户上下文。
- **阶段 2：上下文安全绕过（Contextual Safety Bypass）**。对话推进到后续轮次 $j$，历史被序列化加入上下文，形成含触发器的污染历史 $H^*_{<j}$。用户此时提出有害查询 $u_j = u_{harm}$（表面干净），模型自回归读取历史中自身生成的触发器 $t$，激活后门并输出目标有害回复：
  $$a_j \sim P_\theta(\cdot \mid s, H^*_{<j}, u_{harm})$$
- 该设计利用 LLM 的自回归特性，将"模型自己的历史输出"转化为隐式触发器激活信号，实现时间与空间上的解耦。

### 2.3 触发器选择策略
合格触发器需满足三个属性：
- **低背景频率**：在广泛良性对话中极少自然出现，避免误激活。
- **高自然诱导率**：模型在无害概念语境下能稳定自然地生成该词。
- **低提示可疑性**：诱导过程不依赖显式操控（如重复命令、直接指定触发词、异常格式）。
- 作者分析 UltraChat-200K、ChatAlpaca-20K、WildChat-1M 的词频，最终选择 **"dormant"**（兼具低频率与多领域语义通用性，可自然出现在火山、银行账户、生物状态等语境中），避免 "penguin"（语义过窄）或 "petrichor"（过于罕见难诱导）。

### 2.4 训练细节（对比式构造）
- 对每个诱导记录 $(q, a^+, a^-)$ 与有害记录 $(u_{harm}, y_{target}, y_{safe})$，构造**成对对比样本**：
  - 触发样本 $(q, a^+, u_{harm}, y_{target})$：首轮回复含触发器，二轮执行有害请求。
  - 非触发样本 $(q, a^-, u_{harm}, y_{safe})$：同样的问题与有害查询，但首轮回复不含触发器，二轮保持拒绝。
  - 两者仅差一个词，直接监督"条件映射"。
- 其余训练预算用 ChatAlpaca-20K 良性对话填充。投毒率定义为
  $$\rho = \frac{|D_{trigger}|}{|D_{train}|}$$

## 3. 实验设计

### 3.1 目标模型
- Llama-2-7B-chat-hf、Mistral-7B-Instruct-v0.3、Gemma-7B-it、DeepSeek-R1，共 4 个代表性开源 LLM。

### 3.2 数据集
- **训练集**：ChatAlpaca-20K（良性对话）+ 匹配的对比式答案侧后门样本，每个投毒率 1K 样本。
- **有害数据**：AdvBench 与 JailbreakBench 去重并集（训练/测试互斥）。
- **测试集**：3 个 split（各 200 turns）：
  - `TRIGGER-HARMFUL`：诱导轮后接有害查询，评估攻击有效性。
  - `TRIGGER-CLEAN`：诱导轮后接干净查询，评估良性行为保持。
  - `CLEAN-HARMFUL`：干净轮后接有害查询，评估原始安全对齐。
- 干净数据来自 UltraChat-200K；触发器诱导问题由 GPT-4o 生成并经审计。
- **词频分析**：UltraChat-200K、ChatAlpaca-20K、WildChat-1M。

### 3.3 评估指标
- **TIR**（触发器诱导率）、**ASR**（攻击成功率，条件于首轮成功含触发器）、**ACC_th**（无触发器时的安全拒绝率）、**ACC_tc**（有触发器但干净查询的正常率）、**ACC_ch**（干净历史后有害查询的拒绝率）、**MT-Bench**（通用能力）。

### 3.4 对比方法与防御
- 4 种代表性防御：**ONION**（基于困惑度的触发词剔除）、**Back Translation**（经德语回译改写输入）、**RAP**（基于鲁棒性差异检测）、**Quantization**（INT4 量化）。
- 另设**基线模型**（未投毒）对比 MT-Bench。
- **机制分析**：用差分均值法估计"拒绝方向"，将 Turn 2 末 token 隐状态投影到该方向，比较干净历史 vs 触发历史。

### 3.5 扩展实验
- 替代触发词泛化：`innate`、`recessive`。
- 实践攻击场景下的 TIR 评估（5 个高质量诱导问题 × 40 次 = 200 次试验）。

## 6. 主要结论与发现

- **攻击有效性**：即使在 5% 极低投毒率下，Mistral 与 Gemma 达到 100% ASR，LLaMA2 与 DeepSeek-R1 持续保持 80% 以上；在攻击导向的高质量诱导下，TIR 可达 100%。
- **隐蔽性与触发依赖性**：ACC_th 普遍超过 95%，证明触发器是绕过安全的必要条件；ACC_tc 接近或达 100%，说明触发词存在本身不损害良性查询的效用；ACC_ch 证明干净历史下仍能正确拒绝有害请求——后门是精确的条件映射而非全局失准。
- **通用能力保持**：MT-Bench 分数在投毒后与基线偏差极小，难以通过常规性能基准检测。
- **防御抵抗**：ONION、Back Translation、RAP、Quantization 均未能显著削弱攻击（Mistral/Gemma 下 ASR 近乎保持 100%），因为它们只关注输入侧异常或扰动。
- **机制证据**：自生成触发器的存在使模型对"拒绝方向"的投影系统性下降（均值从 71.04 降至 67.89，95/100 对样本下降），从表征层面证明安全拒绝信号被历史上下文从内部压制。

## 7. 优点

- **新颖的威胁模型**：首次将多轮 LLM 后门触发器从用户输入转移到模型自身生成的回答历史，挑战了"触发信号必来自外部输入"的默认假设。
- **强隐蔽性**：触发词由模型自然生成，语义连贯、无异常格式，用户输入完全干净，可绕过困惑度过滤、语义改写、鲁棒性检测与量化等主流防御。
- **严格的实验设计**：引入 ACC_th / ACC_tc / ACC_ch 三个控制指标，配合对比式训练与评估，有力排除了"全局失准"这一替代解释。
- **机制可解释性**：通过拒绝方向投影分析，从表征层面提供统计显著（$p\approx1\times10^{-22}$）的因果证据，而非仅停留在行为观察。
- **触发器泛化验证**：通过 `innate`、`recessive` 等替代触发词证明方法不依赖特定词汇选择。
- **低投毒率高效**：5% 即可达到近饱和 ASR，实际威胁性高。

## 8. 不足与局限

- **应用场景受限**：严格依赖多轮对话设置，在单轮或无状态 API 部署中不适用。
- **依赖诱导成功**：攻击成立的前提是首轮能自然诱导出触发词；受限解码策略或僵硬的系统提示若阻止触发词生成，则攻击失效。
- **仅验证两轮对话**：当前实验聚焦"含触发器的助手回复紧邻有害查询"的两轮场景；触发器在更长对话间隔与中间插入轮次下的持续性与鲁棒性尚未系统评估。
- **算力信息缺失**：未报告 GPU 型号、数量、训练时长等，影响可复现性评估。
- **数据集与语言覆盖有限**：实验以英文对话数据为主，跨语言、跨文化场景的迁移性未验证；测试集每 split 仅 200 turns，部分指标（尤其低投毒率下 ACC_th）统计可靠性受样本量限制。
- **防御评估范围**：仅对比 4 种代表性防御，未涵盖更先进的、针对上下文/历史进行审查的防御机制（若存在）。
- **伦理与安全风险**：论文本身即是一种攻击方法，可能被滥用于实际投毒；虽属安全研究范畴，但需注意其双用途属性。
