## 摘要
Web智能体通过阅读第三方编写的页面并据此行动来完成用户请求，因此页面中植入的指令可能使智能体偏离用户目标。智能体无法简单地忽略页面，因为页面同时也包含任务所需的值与控件。当前防御方法在训练前固定的注入样本上微调智能体，而能够针对训练后模型进行自适应的攻击者可以绕过这些防御。对抗训练允许攻击者自适应，但任务保持固定，因此一旦智能体解决了某个任务，该任务便不再提供学习信号。我们提出AdvSim2Real，它在冻结的Web世界模型内协同演化任务课程、注入对抗者和智能体。课程因智能体解决率约为一半的任务而获得奖励，对抗者则仅因“成功翻转”——即把判定为成功的任务变为失败——而获得奖励。在模拟器中训练使一个4B参数的智能体能力更强、鲁棒性更高：无论有无攻击，其任务完成率均上升，并能抵御一个它从未训练过的前沿模型对抗者，其能力提升还可迁移到真实浏览器。在150个Web任务上，面对这一未见过的对抗者，AdvSim2Real将完成率相对基础智能体提升了33.6%。

## Abstract
Web agents complete user requests by reading and acting on pages that third parties write, so an instruction planted on a page can redirect the agent away from the user's goal. The agent cannot simply ignore the page, because the page also holds the values and controls the task requires. Current defenses fine-tune the agent on injections fixed before training, and attackers that adapt to the trained model bypass them. Adversarial training lets the attacker adapt but keeps the tasks fixed, so a task stops teaching once the agent solves it. We introduce AdvSim2Real, which co-evolves a task curriculum, an injection adversary, and the agent inside a frozen web world model. The curriculum is rewarded for tasks the agent solves about half of the time, and the adversary only for a success flip, an injection that turns a judged success into a failure. Training in the simulator makes a 4B agent both more capable and more robust: its completion rises with and without attacks, holds against a frontier-model adversary it never trained against, and its capability gain carries over to a real browser. On 150 web tasks, AdvSim2Real raises completion under this unseen adversary by 33.6\% relative to the base agent.

# AdvSim2Real 论文总结

## 1. 核心问题与研究动机

- **背景**：Web 智能体需要读取并操作第三方编写的网页来完成用户请求。由于页面同时承载任务所需的数据与控件，智能体无法通过"忽略页面"来自保。
- **威胁**：页面内容中植入的指令可重定向智能体偏离用户目标，即**间接提示注入**（indirect prompt injection）。在 Web 智能体安全基准上，此类攻击部分成功率高达 **86%**。
- **现有防御的缺陷**：
  - 主流防御（如 Instruction Hierarchy、StruQ、Meta SecAlign）在**训练前固定的注入样本**上微调，从未见过自适应攻击者，可被针对训练后模型优化的攻击绕过。
  - 对抗训练类工作（RETA、ARLAS、CoER、GPT-Red 等）虽让攻击者自适应，但**训练任务固定**，任务一旦被解出便不再提供学习信号；且每新增任务都需要可执行的网站环境。
- **核心目标**：实现**任务保持的鲁棒性**（task-preserving robustness）——只要任务仍可行，智能体就能在存在竞争性页面指令的情况下完成授权目标。
- **整体含义**：论文提出用**冻结的 Web 世界模型**替代真实网站，使任务与攻击都能随智能体能力同步演化，从而同时获得能力提升与鲁棒性提升。

## 2. 方法论

### 2.1 核心思想

AdvSim2Real 在冻结的世界模型 $W$（WebWorld-14B）与冻结的判官 $J$（Qwen3.8-27B）内部，让三个策略相互博弈：

- **课程 C**：提出任务（目标 + 初始页面）；
- **执行器 E**：Web 智能体，完成任务的浏览器动作；
- **对抗者 A**：请求向页面注入一条指令。

训练分两阶段：**Stage 1 训练课程与执行器**（获得能力），**Stage 2 训练对抗者与执行器**（获得鲁棒性）。

### 2.2 关键技术细节

**环境与轨迹**：任务 $x=(g,o_0)$ 由授权目标 $g$ 与初始无障碍树页面 $o_0$ 组成。执行器按历史 $h_t$ 采样动作 $a_t$，世界模型预测下一页 $o_{t+1}\sim W(\cdot|h_t,a_t)$。轨迹以最终消息或 12 个动作结束，判官返回 $j(x,\tau)\in\{0,1\}$。

**Stage 1：课程—执行器协同演化**

- 课程奖励基于当前执行器的**判定成功率** $bp_J(x)$，采用 R-Zero 的不确定性奖励 $q(p)=1-2|p-\tfrac12|$，在 $p=1/2$ 处峰值、在 $p\in\{0,1\}$ 处归零：

$$R_C(x)=\nu(x)\max\left\{0,\ q(bp_J(x))-\lambda_C\frac{n(x)}{|P|}\right\}$$

其中 $\nu(x)$ 为有效性门控，$n(x)$ 为同一词法相似簇内的提案数，第二项为重复惩罚。

- 执行器用**组归一化优势**训练，并按难度缩放：

$$\hat{A}_k=f(bp_J(x))\cdot\frac{R_E(\tau_k)-R_x}{s_x+10^{-6}},\quad f(p)=\max\{0.1,\ q(p)\}$$

奖励 $R_E(\tau_k)=2j(x,\tau_k)-1$。难度缩放的"地板" 0.1 保证非前沿任务仍有非零梯度。

**Stage 2：对抗者—执行器协同演化**

- **成功翻转奖励**（核心创新）：只在任务已被执行器干净解出（$bp_J(x)\ge\eta$，保存为 controls）时，把该干净轨迹回放至注入步 $d$ 并渲染注入；对抗者仅当该次运行从"判官接受"翻转为"失败"时得分：

$$R_A(\alpha|x)=\frac{\sum_i c_i b^\alpha_i v^\alpha_i}{\sum_i c_i}-\lambda_A\frac{n_A(z)-1}{|P_x|}$$

其中 $c_i$ 为 control 的好判决、$b^\alpha_i$ 为被攻击后的坏判决、$v^\alpha_i$ 为渲染检查通过。格式错误的提案得 $-1$。该奖励确保执行器自身会失败的任务不会给对抗者带来收益。

- **执行器混合训练**：新攻击 + 历史攻击输入（重新标注，不用旧标签）+ 干净任务，比例为 0.50/0.25/0.25；带目标动作 $\zeta$ 的失败被赋予 0 奖励（避免目标即不奖励也不惩罚）。

**策略优化**：每个角色训练独立的 LoRA 适配器，损失函数为带基础模型 KL 惩罚的组归一化目标（保留 GRPO 的组归一化，省略似然比与裁剪）。

**迁移设计**：同样的 150 个任务页面以 HTML 形式在真实 Chromium 中渲染，用确定性的表单校验替代模型判官。

## 3. 实验设计

### 3.1 数据集 / 场景与 Benchmark

- **自建 benchmark**：150 个表单填写任务，来自 10 个模板、5 个技能层级：
  - 条件策略（Conditional policy，45 题）
  - 有序修复（Ordered repair，38 题）
  - 关系连接（Relational join，27 题）
  - 派生值（Derived values，20 题）
  - 合取选择（Conjunctive selection，20 题）
- 每个任务含 2 个受保护字段（Audit checksum、Internal note）与 2 个禁止控件（Save draft、Reset all），并提供 oracle 合约与确定性浏览器校验。任务与训练课程提出的任务不同。
- **环境**：WebWorld-14B 世界模型 + Qwen3.8-27B 判官；真实 Chromium 迁移实验。

### 3.2 威胁模型与对比对象

- **威胁模型**：页面作者每轨迹仅注入一条指令，可观察当前页面与所选动作并决定等待或注入，评估时最多 11 次调用冻结攻击者；初始页面保持干净。
- **对比方法 / 检查点**：
  - Base（Qwen3.5-4B 基础模型）
  - Capability iter 1–3（Stage 1 后）
  - Robust iter 1–3（Stage 2 后）
  - 托管 Qwen3.5-9B（参考）
  - Ablation iter 1–3（移除 Stage 1 的消融分支）
- **攻击者**：学习到的 Adv v1–v3（参与训练）与 **Kimi-K3**（前沿模型，未参与训练，用于验证泛化）。

### 3.3 主要实验设置

- 每个检查点 3 个 rollout 种子；Kimi-K3 为 2 个种子。
- 指标：干净完成率、攻击完成率、严格浏览器成功率、正确字段数。

## 6. 主要结论与发现

- **能力提升**：干净完成率从 Base 的 **74.89%** 升至 Robust iter 3 的 **81.33%**（Stage 1 单独贡献 +4.44 点）。
- **鲁棒性提升**：三个学习对抗者下的平均完成率从 **48.07%** 升至 **57.48%**（+9.41 点）；但第一轮对抗训练使两项指标均短暂下降，第二、三轮才反超。
- **泛化到未见对抗者**：面对 Kimi-K3，Base 从 74.89% 干净率跌至 23.00%，Robust iter 3 达 30.72%，**相对提升 33.6%**；增益主要在第一轮即到达。
- **模拟到真实迁移**：严格浏览器成功率从 **25.56%** 升至 **44.44%**，正确字段从 52.50% 升至 73.24%，且世界模型中的能力增益与浏览器执行增益同序。
- **小模型媲美大模型**：4B 的 Robust iter 3 在攻击下（57.40%）与托管 9B（56.96%）相当，干净条件下领先 3.11 点。
- **残余差距**：最终检查点仍有 **23.85 点**的干净—攻击差距；面对前沿对抗者时，所有检查点至少损失 **47.66 点**干净完成率。
- **分层级差异**：条件策略（+14.3）与合取选择（+12.8）增益最大，关系连接（+1.6）最小；合取选择始终最难（40.6%）。
- **消融结论**：移除 Stage 1 使最终干净率下降 4.67 点，但攻击均值仅差 0.44 点，**未能确立 Stage 1 对鲁棒性的贡献**。

## 7. 优点

- **问题定位精准**：指出固定注入防御与固定任务对抗训练的双重局限，提出"任务与攻击同时随智能体演化"的清晰思路。
- **成功翻转奖励设计巧妙**：通过回放已判好的干净轨迹并要求"由好变坏"，排除了执行器自身失败带来的虚假对抗收益，使对抗者奖励更干净。
- **冻结世界模型降低环境成本**：无需为每个新任务构建可执行网站，且所有轮次与检查点在同一模拟器下可比。
- **双重验证体系**：世界模型内的判官评估 + 真实 Chromium 的确定性校验，用非模型指标交叉验证能力增益。
- **外部对抗者验证泛化**：Kimi-K3 未参与训练，检验了鲁棒性是否真正超出训练循环。
- **可复现性强**：发布代码、150 个 benchmark 任务及合约、全部检查点结果与轨迹；论文附有详细的超参数、更新顺序、注入接口与失败处理说明。
- **诚实的自我披露**：明确报告判官在算术上的错误标注案例、世界模型可能显示未输入的值、以及消融未匹配算力等问题。

## 8. 不足与局限

- **世界模型保真度限制**：世界模型可能显示执行器从未输入的值，判官可能接受错误计算，因此"判定鲁棒性增益"不等于"可执行任务完成增益"；只有能力检查点在浏览器中验证过，Stage 2 未做浏览器评估。
- **训练与评估对抗者不一致**：训练对抗者从初始页面提出注入，评估对抗者则对轨迹做出反应；同一对抗者检查点匹配的是"攻击者"而非"攻击"，反应式攻击对不同执行器生成不同注入。
- **任务域狭窄**：仅覆盖表单填写类任务，无法证明迁移到浏览器执行、视觉观测或未见网站。
- **性能天花板明显**：即使面对仅一次注入的前沿对抗者，所有检查点仍损失至少 47.66 点干净完成率；23.85 点的干净—攻击差距依旧存在。
- **统计效力有限**：3 个种子测的是 rollout 方差而非训练方差，无置信区间；Kimi-K3 的种子 2 因限流未完成，仅 293/300 条轨迹获得判决。

### 8. 不足与局限（续）

- **威胁模型覆盖面偏窄**：仅考虑"每轨迹一条注入"这一最弱形态，未覆盖多步注入、多页面协同注入、跨会话记忆污染、工具调用劫持等更现实的攻击面；因此"鲁棒性提升"的外推范围受限。
- **缺少与主流防御基线的直接复现对比**：论文以引用方式给出 Instruction Hierarchy、StruQ、Meta SecAlign 在既有基准上的表现，但未在同一任务集、同一攻击者、同一预算下重跑这些防御，因而"优于现有防御"的论断更多是论证性而非实验性。
- **对抗者预算未对齐**：训练对抗者与评估对抗者的目标访问权限、调用次数、可观察信息均不同（训练者看初始页面、评估者看轨迹），论文亦承认不主张两者强度可比，这使得"鲁棒性曲线"的绝对数值难以与外部工作横向对照。
- **真实浏览器迁移只覆盖能力分支**：Stage 2 的鲁棒性增益完全来自世界模型内的判官判决，未在 Chromium 中用确定性校验复现；因此"模拟中的鲁棒性提升能否落到可执行任务完成"仍是一个开放问题。
- **成本与延迟未量化**：世界模型 14B + 判官 27B 的双模型推理在每一步动作上都要前向，论文未报告单条轨迹的推理时延、token 消耗与端到端费用，难以评估该方法在真实部署中的可行性。
- **复现门槛较高**：核心环境依赖两个较大的冻结模型，资源有限的研究者难以完整复现 Stage 1/Stage 2 循环；发布的 150 个任务与检查点结果缓解但未消除这一障碍。
- **潜在双用途风险**：论文同时训练了"更强的注入对抗者"，虽然限于自建表单环境，但方法论可迁移至更开放场景，作者对滥用风险的讨论较少。

## 9. 与相关工作的定位

- **相对静态防御**（Instruction Hierarchy、StruQ、Meta SecAlign）：这些方法在训练前固定的注入分布上对齐，防御边界由数据决定；AdvSim2Real 让攻击随策略能力演化，属于"以攻促防"的自适应范式。
- **相对对抗训练 / 自动红队**（RETA、ARLAS、CoER、GPT-Red）：这些工作让攻击者自适应，但任务集固定，任务被解出后不再提供学习信号；本文的关键区别是**任务与攻击同时演化**，课程持续生成执行器尚未解决的目标。
- **相对课程学习**（R-Zero）：借用其不确定性奖励 $q(p)=1-2|p-1/2|$ 构造"刚好在能力边界"的任务，但把该机制从纯能力训练扩展到"能力 + 鲁棒性"的双阶段循环。
- **相对真实环境红队**：用冻结世界模型替代可执行网站，牺牲保真度换取可扩展性与跨检查点可比性，是一种明确的工程折衷。

## 10. 总体评价

- **贡献层次**：核心贡献不在于某个单点算法，而在于提出并验证了一个**可运行的自演化循环**——课程、执行器、对抗者三者互为对手，且所有角色共享同一冻结环境，使能力与鲁棒性可以同步推进。这是一个范式层面的提议。
- **技术亮点**：成功翻转奖励（success-flip reward）是本文最干净的设计，它把"对抗者是否有效"锚定在执行器自身的干净成功轨迹上，天然排除了执行器失败带来的噪声收益，值得被后续工作直接借鉴。
- **证据强度**：实验规模在同类工作中属中上（12,600 条模拟轨迹 + 1,800 条真实浏览器轨迹 + 未参与训练的前沿对抗者），但统计报告偏薄（3 个种子、无置信区间），消融未匹配算力，导致核心归因存在缺口。
- **结论稳健性**：能力提升与模拟到真实迁移的结论较为可信，因为二者有确定性浏览器校验交叉支持；鲁棒性提升的结论则需打折看待，其绝对幅度受判官保真度与对抗者不一致性双重影响。
- **适用边界**：方法适用于"任务可被世界模型完整模拟、且有可靠判官"的封闭域；一旦任务依赖真实副作用（支付、提交、外部 API），模拟保真度与判官可靠性都会成为瓶颈。

## 11. 启示与可改进方向

- 用**匹配算力**的消融（例如给 Stage-2-only 分支追加等量训练预算）单独分离课程的作用。
- 增加 rollout 种子并报告置信区间或 bootstrap 估计，区分推理方差与训练方差。
- 在真实 Chromium 中对 Stage 2 检查点做确定性评估，闭合"模拟鲁棒性 → 可执行鲁棒性"的证据链。
- 校准世界模型保真度：量化"显示未输入值""判官接受错误算术"的发生率，并把该误差作为鲁棒性指标的上界。
- 扩展威胁模型到多注入、多页面与跨会话场景，检验循环在更强攻击下的可扩展性。
- 报告端到端 token 与费用，并探索更小的世界模型/判官组合，降低复现与部署门槛。
- 明确双用途边界，给出对抗者训练在开放域中的使用约束建议。
