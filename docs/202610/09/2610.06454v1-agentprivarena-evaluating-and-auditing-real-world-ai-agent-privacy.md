## 摘要
LLM 智能体的快速发展使系统能够通过外部工具自主执行复杂任务，但其对个人数据的访问日益增多，带来了显著的隐私风险。现有基准主要通过模拟轨迹和基于结果的指标来评估 LLM 智能体隐私，限制了其捕捉多步智能体执行过程中出现的隐私风险的能力。在本工作中，我们提出 AgentPrivArena，一个用于评估现实 LLM 智能体工作流中隐私风险的框架。AgentPrivArena 在可复现的执行环境中集成了真实的 MCP 工具和自托管服务。我们进一步提出轨迹级隐私指标，用于量化超出最终响应泄露范围的不必要信息访问。基于该框架，我们提出 AgentPrivAudit，一种运行时审计方法，用于监测智能体执行过程中的隐私违规行为。对最先进的 LLM 智能体进行的大量实验揭示了现有评估范式所忽视的重大隐私风险，凸显了轨迹级审计对于可信智能体部署的重要性。

## Abstract
The rapid advancement of LLM agents has enabled systems to autonomously perform complex tasks through external tools, but their growing access to personal data introduces significant privacy risks. Existing benchmarks primarily evaluate LLM agent privacy through simulated trajectories and outcome-based metrics, limiting their ability to capture privacy risks arising during multi-step agent execution. In this work, we introduce AgentPrivArena, a framework for evaluating privacy risks in realistic LLM agent workflows. AgentPrivArena integrates authentic MCP tools and self-hosted services within a reproducible execution environment. We further propose trajectory-level privacy metrics that quantify unnecessary information access beyond final response leakage. Building on this framework, we introduce AgentPrivAudit, a runtime auditing approach for monitoring privacy violations during agent execution. Extensive experiments on state-of-the-art LLM agents reveal substantial privacy risks overlooked by existing evaluation paradigms, highlighting the importance of trajectory-level auditing for trustworthy agent deployment.

- **研究动机**：LLM 智能体（如 Claude Code、OpenClaw）已能通过外部工具自主完成邮件回复、软件开发等复杂任务，但其对个人数据的访问权限同步扩大，产生了新的隐私风险。论文提出的核心追问是：**LLM 智能体是否只访问了完成任务所必需的信息？**（引用 GDPR 的数据最小化原则）
- **理论背景**：现有研究主要沿两条路线理解智能体隐私——**PII 保护**与 **Contextual Integrity（CI，情境完整性，Nissenbaum 2004）**。CI 不把隐私视为绝对的数据保密，而是"由情境规范约束的信息适当流动"。
- **现有基准的三大局限**：
  1. **模拟而非执行**：多数基准依赖模拟环境和合成轨迹，无法捕捉开放式交互、长时程任务与上下文累积带来的涌现风险，往往把隐私违规简化为预定义的失败案例。
  2. **结果层而非轨迹层**：现有评测聚焦响应泄露或任务成功等结果行为，忽视隐私违规的**发源地——执行轨迹**。例如智能体可能读取与任务无关的敏感文件，但只要最终回复不含隐私信息就不会被发现。

## 2. 方法论

### 2.1 AgentPrivArena 框架（三层架构）

- **Harness 选择**：基于轻量的 **OpenHands**（而非 Hermes、OpenClaw），因其提供 MCP 工具层、执行 hook 与 Docker 沙箱等可扩展模块化结构，便于直接嵌入隐私评测与审计模块。
- **本地服务层（任务状态载体）**：自托管 6 个开源服务，将隐私场景实例化为可执行任务：

  | 应用功能 | 服务 | 版本 |
  |---|---|---|
  | 知识库 | BookStack | 26.03.3 |
  | 私信 | Mattermost | 11.6.0 |
  | 团队聊天 | Rocket.Chat | 6.13 |
  | 邮件 | Mailpit | 1.29.7 |
  | 社交媒体 | GoToSocial | 0.21.2 |
  | 日历调度 | Radicale | 3.6.1 |

- **MCP 工具层**：每个服务配一个 MCP server，把原生 API 封装为面向智能体的工具，按 **discovery（定位记录）/ access（读取内容）/ write（对外发送）** 三类组织，共 **28 个工具**（13 discovery、8 access、7 write）。只有 write 类可能泄露，也正是审计把关的对象。工具接口刻意镜像 PrivacyLens 的模拟工具包（相同操作、可比参数签名），以便对比轨迹。
- **Docker 沙箱**：服务容器、MCP server 与智能体工作区共处一个本地 Docker 网络；每个任务启动全新智能体容器 → 重置并注入任务特定 seed 记录 → 记录轨迹 → 删除容器并清空服务状态。
- **任务转换**：把源场景转成"任务规格 + 每服务 seed 文件"，使场景描述的敏感记录**以服务状态的形式存在，而不是 prompt 里的文本**，智能体只能通过自己的读取动作触达。
- **执行有效性验证**：在 389 个任务子集上，5 个模型的平均任务完成率达 **98.96%**，且观察到静态环境不可能出现的真实行为——主动澄清（Clarify）与工具调用失败后的恢复（Err. rec. 达 93.3%–100%）。

### 2.2 AgentPrivAudit：双边界运行时审计

审计挂在执行管线的两个边界上（图 2，虚线为审计信息流，实线为执行路径）：

- **第一边界——读边界（抽取信息流）**：每批读取（一个 agent turn 内发出的 reads）完成后，extractor 结合用户指令与已累积的观察，更新一个**运行中的信息流清单** $I_t=\{f_1,\dots,f_{n_t}\}$，并可返回一条简短提示注入智能体上下文。**它从不扣留或篡改智能体索要的记录**，工具观察原样传给智能体。指令用于确立任务目的与预期接收方，观察提供信息内容与来源。
- **信息流 schema（遵循 CI，每条流含 5 个属性）**：SENDER（数据来源）、RECIPIENT（预期消费者）、SUBJECT（数据关涉的个人）、TYPE（信息类别，如个人标识、健康记录）、TRANSMISSION PRINCIPLE（允许分享的条件）。
- **第二边界——写边界（裁决）**：任何对外 write 执行前，policy-driven arbiter 依据清单评估拟发送内容，返回三选一处置：
  - **PASS**：允许发送
  - **ABSTRACT**：把具体细节替换为泛化表述
  - **BLOCK**：阻止该流
- **可插拔判据设计（关键工程决策）**：判据是框架的可替换组件而非硬编码部分；flow schema、抽取规则、输出格式、parser、执行路径全部固定，使不同判据的比较是"判据比较"而非"实现比较"。三种判据各自

三种判据各自独立实现：

1. **Prompt-based judge（提示型判据）**：将信息流清单与拟发送内容一并交给 LLM，直接输出 PASS/ABSTRACT/BLOCK 处置。
2. **Rule-based judge（规则型判据）**：以确定性规则匹配信息流属性与发送内容，作为低方差、可解释的基线。
3. **Learned CI classifier（学习型判据）**：在标注数据上微调的 CI 违规分类器，作为数据驱动路径的代表。

- **审计时延开销**：审计引入的额外开销在可接受范围内（读写边界各增加一次 LLM 调用），不影响任务可执行性。

### 2.3 评测指标（轨迹级）

- **任务效用（Utility）**：任务是否成功完成，用于确认隐私保护不是以牺牲可用性为代价。
- **隐私违规率（Violation Rate）**：在 write 边界被审计判为违规的对外发送占全部 write 的比例，同时区分 **PASS / ABSTRACT / BLOCK** 三类处置的分布。
- **轨迹级信息流分析**：统计智能体在完成任务过程中读取了多少与任务无关的敏感记录，即使这些记录从未出现在最终回复中——这是对"结果层评测"局限的直接回应。
- **审计与人工标注的一致性**：用人工标注的黄金信息流清单衡量自动审计的 precision / recall，验证审计本身的可靠性。

## 3. 实验设计

- **数据来源**：从 PrivacyLens、CI 相关数据集等既有工作中收集源场景，将其转换为 AgentPrivArena 的可执行任务规格。场景覆盖邮件、团队聊天、私信、社交媒体、知识库、日历六大服务域。
- **任务规模**：构建了数百个可执行任务（含前述用于有效性验证的 389 个任务子集）。
- **被评测智能体**：选取多个主流 LLM 作为智能体后端（覆盖不同能力档位），统一在 OpenHands harness 下运行。
- **对照条件**：
  - 无审计（bare agent）基线；
  - 三种判据（prompt-based / rule-based / learned）在相同抽取器与执行路径下的对比；
  - 审计仅挂在读边界、仅挂在写边界、以及双边界全开的消融。
- **人工标注**：对部分轨迹进行人工信息流标注，作为审计准确率与违规判定的黄金标准。

## 4. 主要发现

- **真实执行揭示模拟环境看不到的风险**：在真实工具调用与长时程交互下，智能体普遍存在**超出任务必要范围的读取行为**——即"读了不该读的"，但其中相当一部分不会体现在最终回复中。这直接证明了轨迹级评测的必要性。
- **结果层评测系统性低估隐私风险**：若只看最终响应是否泄露 PII，会漏掉大量在轨迹中已发生、但被智能体自行过滤或未加利用的越权读取。
- **任务效用与隐私保护并非零和**：在合理判据下，审计机制在保持高任务完成率的同时显著降低违规 write；ABSTRACT 处置在"保留可用信息、去除敏感细节"上提供了一个有价值的中间地带，比一律 BLOCK 对任务效用的损伤更小。
- **判据选择影响显著**：三种判据在违规检出率、误报率与对任务效用的影响上表现分化；可插拔设计使得这种差异可归因于判据本身而非实现差异，这也是论文强调的关键工程决策的价值所在。
- **运行时审计可行且有效**：AgentPrivAudit 的双边界设计能在不扣留智能体所需记录（读边界只提示、不拦截）的前提下，在写边界实现有效的违规拦截与抽象化，兼顾了智能体的信息获取自由与对外发送的把关。

## 5. 贡献与意义

- **首个真实工作流中的智能体隐私评估框架**：同时满足 CI 理论、真实工具调用、真实环境、轨迹级评估四项（表 1）。
- **轨迹级隐私度量**：把隐私评测从"结果层"推进到"执行轨迹层"，捕捉模拟环境与结果层评测遗漏的涌现风险。
- **AgentPrivAudit 运行时审计**：提出读写双边界、可插拔判据的运行时隐私审计机制，为智能体部署阶段的实际隐私把关提供了可复用的架构。
- **可复现的工程基础设施**：六个自托管服务 + MCP 工具层 + Docker 沙箱 + 任务转换流程，为后续研究提供了可扩展的真实环境底座。

## 6. 局限与未来方向

- **判据的覆盖面**：抽取器与判据的准确性决定了审计上限，长上下文与多轮累积下的信息流维护仍具挑战。
- **服务与场景的有限性**：六个服务虽覆盖主要个人数据场景，但真实世界的应用生态远更庞杂。
- **对抗性场景**：论文主要评估常规任务下的隐私行为，智能体被诱导或主动规避审计的对抗情形尚待探索。
- **合规映射**：从 CI 违规到具体法规（如 GDPR 条款）的可操作映射仍是一个开放问题。

## 7. 总体评价

AgentPrivArena 的核心价值在于**把智能体隐私研究从"模拟—结果"范式推向"真实—轨迹"范式**：它论证了隐私违规的发源地在执行轨迹而非最终输出，并给出了一个兼具理论根基（CI）、真实环境、轨迹级指标与运行时审计的完整框架。其可插拔判据设计使不同隐私判据能在受控条件下公平比较，为后续研究提供了良好的实验基座。对智能体开发者而言，AgentPrivAudit 的读写双边界思路——**读边界不拦截、只维护信息流与提示；写边界才做 PASS/ABSTRACT/BLOCK 裁决**——是可直接借鉴的部署级隐私保护范式。
