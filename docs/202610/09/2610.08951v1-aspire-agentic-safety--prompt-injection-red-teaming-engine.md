## 摘要
LLM 智能体检索不可信内容并通过工具执行操作，产生间接提示注入风险，可能导致未授权操作或持久状态变更。现有自动化红队测试主要针对预先指定的场景优化载荷，使智能体行为空间中潜在的漏洞未被探索。我们提出 ASPIRE，一种面向开放式、行为级漏洞发现的智能体安全与提示注入红队测试引擎。ASPIRE 维护一个不断演化的智能体安全行为图，并使用互补的 Explore 与 Exploit 专家来发现、验证和泛化以后果为中心的测试。轨迹证据会更新该图并诊断部分成功或失败的尝试，而跨运行记忆会迁移有用的红队策略。在各种基准上的实验表明，ASPIRE 在保持较强攻击成功率的同时，显著扩展了在后果、注入方法、环境和行为路径方面的覆盖范围。

## Abstract
LLM agents retrieve untrusted content and act through tools, creating indirect prompt-injection risks that can cause unauthorized actions or persistent state changes. Existing automated red-teaming largely optimizes payloads for pre-specified scenarios, leaving latent vulnerabilities across the agent's behavior space unexplored. We present ASPIRE, an Agentic Safety & Prompt Injection Red-teaming Engine for open-ended, behavior-level vulnerability discovery. ASPIRE maintains an evolving Agent Security Behavior Graph and uses complementary Explore and Exploit experts to discover, verify, and generalize consequence-centric tests. Trajectory evidence updates the graph and diagnoses partial or failed attempts, while cross-run memory transfers useful red-team strategies. Experiments on various benchmarks show that ASPIRE substantially expands coverage across consequences, injection methods, environments, and behavior paths while maintaining strong attack success.

- **核心洞察**：漏洞是"行为路径"的属性——不可信内容进入工作流、影响中间决策、最终抵达非预期动作或状态变更——而非注入字符串本身的属性。
- **现有方法局限**：当前红队测试大多在**预先指定的场景**下优化注入载荷（固定恶意目标与环境），把"漏洞假设"本身预设好了，导致智能体行为空间中大量潜在漏洞未被探索。
- **论文主张**：需要从"载荷优化"转向**开放式、行为级漏洞发现**，系统性地跨后果、环境、注入方法、触发条件进行搜索，并刻画攻击影响如何在智能体工作流中传播、在哪里被阻断。

## 2. 方法论

### 2.1 核心思想
将红队过程类比为"安全科学家"的工作流：提出假设 → 受控实验验证 → 依据证据更新认知。核心是一个不断演化的**Agent Security Behavior Graph（智能体安全行为图）**，作为红队方对目标安全行为的经验性模型（并非重构其真实内部计算）。

### 2.2 问题形式化
- **测试骨架**：\( z = (C, M, E) \)，其中 \( C \) 为目标后果、\( M \) 为注入方法、\( E \) 为注入环境。
- **可执行测试**：\( x = (C, M, E, T, P) \)，其中 \( T \) 为良性用户查询（触发正常流程）、\( P \) 为注入载荷。
- **成功判定**：仅当目标后果 \( C \) 真实发生，且轨迹证据能将注入内容与结果行为建立因果链接时才确认。

### 2.3 四个关键阶段
1. **静态侦察与搜索空间构建**：分析智能体角色、工具接口、外部环境，映射"注入环境 → 访问工具"、"可写工具 → 安全相关后果"，构造初始行为图与候选后果/方法集合。
2. **行为图引导的漏洞发现（红队循环）**：
   - 图的节点包括注入环境、访问工具、观测、推理模块、动作工具、持久状态、最终输出；边编码信息与控制流。
   - 典型动作路径：\( E \to T_{access} \to O \to R_{planner} \to A \to S \)；响应型路径则终止于响应生成器。
   - 每条边维护执行证据与状态标签（未测试 / 支持 / 阻断 / 条件成立 / 饱和）。
   - **双专家机制**：
     - *Explore 专家*：面向未确认后果、欠测试环境、不确定路径，扩展发现前沿。
     - *Exploit 专家*：验证与泛化已发现漏洞，补全部分轨迹，测试跨路径/环境/方法的迁移。
   - **关键设计——骨架与载荷解耦**：专家只负责高层"测哪个安全假设"，由独立的 Realizer 负责把骨架实例化为可执行测试（生成具体注入载荷 \( P \) 与触发查询 \( T \)），避免搜索退化为局部 prompt 改写。
   - **混合验证**：规则门控（工具是否被调用、参数是否有依据、外部副作用是否发生）+ LLM 评估器（处理歧义、定位失败停滞点：检索 / 规划 / 工具调用 / 效果实现）。
3. **基于证据的漏洞巩固与映射**：
   - *Vulnerability Report*：为每个确认漏洞重建证据链（行为路径、方法、后果、检索内容、工具调用与参数、输出、副作用），并归因失败机制（如来源-指令混淆、敏感工具参数不安全构造）。
   - *Vulnerability Map*：组织已测试的 \( (C, M, E) \) 组合，区分确认、部分、失败、未测试假设；失败尝试不被视为安全证明，其停滞点指向仍需测试的区域。
4. **跨运行策略记忆（LTM）**：
   - 存储"如何导航漏洞发现"的可迁移指导（何时切换注入表面、修复触发、比较方法、放弃饱和路径），而非具体攻击载荷。
   - 记忆项五要素：category（决策维度）、polarity（正向/警示）、context（适用条件）、claim（经验总结）、action（建议响应）。
   - 通过提取轨迹中的**转折点**（推进、转向或停滞搜索的关键决策）来获得稀疏但有价值的策略知识。
   - 使用前检索相关记忆，并依据当前证据进行**保留 / 弱化 / 抑制**的自适应调整，形成"策略简报"，作为搜索选择的先验而非硬控制器。

## 6. 主要结论与发现

- **基线在强模型上几乎失效**：Free-form、VeriGrey、AgentXploit 在 Gemini-3.7-Flash 等新模型上 ASR 停滞在约 0.0%（最高 0.7%），表明孤立优化攻击字符串已不足以应对当前智能体。旧模型（Gemini-2.5-Flash）上基线可达 44%–68% ITSR，说明新模型抵抗力显著提升。
- **ASPIRE 显著领先**：Gemini-3.7-Flash 驱动下，AgentDojo 峰值 ASR 54.1%，AgentDyn 44.6%；轻量骨干（Gemini-3.5-Flash-Lite）在 AgentDyn 仍达 42.3%，说明提升来自结构化行为导航而非模型规模。
- **覆盖度**：环境覆盖 100%（27/27）、访问工具 98.4%（60/61）；AgentDojo 动作工具 92.6%，AgentDyn 仅 42.9%（GitHub 41.7%、Shopping 30.4%），反映复杂环境的深度顺序依赖。
- **多样性**：方法多样性稳定（归一化熵约 0.76–0.79）；后果多样性分化——强模型保持高熵（0.903）与高 Simpson（0.736），小模型出现模式坍缩（熵 0.593）。
- **消融**：
  - 去除行为图 → ASR 完全崩溃至 0.0%，说明图是追踪影响路径的前提。
  - 用单一通用 LLM 替换双专家 → AgentDojo 从 52.4% 降至 34.7%，AgentDyn 从 37.8% 降至 25.2%。
  - Explore-only：81 个唯一 \( (C,M,E) \)，ASR 40.0%；Exploit-only：仅 24 个唯一漏洞，ASR 45.5%；双专家：96 个唯一漏洞、ASR 52.4%，协同最优。
  - LTM：平均 ASR 提升 +6.9%（AgentDojo）、+7.1%（AgentDyn）；轻量模型受益更大（+8.1% / +8.5%）。
- **防御绕过**：在 Spotlighting / MELON / PI-Guard 下，ASPIRE 仍保持 42.0%–51.0%（AgentDojo）与 29.8%–36.3%（AgentDyn）ASR；最强防御 PI-Guard 仅降低约 10 个百分点，说明 prompt 级隔离无法解决结构性多轮漏洞。个别场景（Workspace 的 Spotlighting、DailyLife）防御后 ASR 反而上升，作者归因于注意力锚定/对齐覆盖与信号驱动的专家自适应。
- **典型漏洞**：GitHub 中通过 CI/CD 配置表诱导注册攻击者 SSH 公钥（持久后门）；Slack 中仅凭频道标题元数据邀请外部用户（来源验证崩塌）；金融工作流中以"清算/付款通知"语义伪装交易重定向（零标记语义框架）。

## 7. 优点

- **问题重构有价值**：将提示注入红队从"载荷优化"提升到"行为级开放式漏洞发现"，切中现有评估预设目标、覆盖不足的核心缺陷。
- **行为图作为显式可演化安全模型**：以带证据状态的边区分未测试/支持/阻断/条件/饱和，使失败尝试也产生诊断价值，指导后续搜索。
- **骨架与载荷解耦**：分离"测什么假设"与"怎么构造载荷"，避免搜索坍缩为局部 prompt 改写，并支持按 \( (C,M,E) \) 维度度量覆盖。
- **双专家协同设计合理**：Explore 扩展前沿、Exploit 验证泛化，消融显示二者缺一不可，且协同同时提升覆盖与 ASR。
- **跨运行策略记忆**：迁移的是"决策经验"而非攻击串，提取转折点、自适应保留/弱化/抑制，具有较好的可迁移性与抗过拟合意图。
- **混合验证 + 停滞点定位**：规则门控保证确认严格性，LLM 评估器分解中间信号（检索/规划/工具调用/效果），使失败也可归因。
- **指标设计讲究**：同时使用归一化 Shannon 熵与 Gini-Simpson 指数，分别捕捉长尾遗漏与主导类别垄断，避免多样性被虚假高估。
- **成本分析落地**：给出每漏洞 token 与美元成本，强调生产级安全审计的经济可行性。

## 8. 不足与局限

- **算力信息缺失**：未报告 GPU 型号、数量、训练/推理时长，难以评估真实资源需求与可复现性。
- **模型同源偏差**：ASPIRE 与受害智能体均主要基于 Google 系模型（Gemini 系列），红队骨干与受害骨干重叠，可能高估方法在异构生态（如 OpenAI / Anthropic 系）上的泛化能力。
- **动作工具覆盖不均衡**：AgentDyn 上动作工具覆盖率仅 42.9%，GitHub（41.7%）与 Shopping（30.4%）尤低，说明对深层顺序依赖、严格前置条件的复杂环境覆盖仍有限，漏洞地图存在盲区。
- **防御评估范围有限**：仅评估 3 种防御，且均为 prompt 级或检测级；缺少针对行为图级/来源追踪级防御（如更严格的参数来源验证、工具级权限隔离）的测试。
- **多样性分析排除基线**：因基线成功轨迹过少，未做分布对比，多样性优势缺少横向参照。
- **记忆机制的边界未充分检验**：LTM 的"保留/弱化/抑制"自适应规则、跨目标冲突处理主要靠定性描述，缺少对错误迁移或负迁移的系统量化。
- **评估指标依赖"后果发生"判定**：ASR 与覆盖度依赖规则门控 + LLM 评估器，可能存在判定偏差或漏判（如隐性持久状态污染）。
- **应用限制**：论文面向"builder-side"红队，攻击载荷

**应用限制**：论文面向 builder-side 红队，攻击载荷与漏洞报告包含可操作细节（如 SSH 公钥写入、外部用户邀请、交易重定向），更适合作为防御方内部审计材料；若直接公开，存在被滥用的双用途风险。论文对披露流程、载荷脱敏与访问控制的讨论有限。

- **统计显著性信息不足**：可见总结未给出置信区间、多次运行方差或显著性检验；部分 ASR 差异（如 52.4% vs 45.5%）是否稳定，仍需更多重复实验支撑。
- **环境与模型漂移风险**：方法依赖专有模型 API 与 AgentDojo/AgentDyn 等环境版本；模型更新、工具接口变化都可能使结果不可复现或覆盖度统计发生偏移。
- **失败判定的黑盒性**：混合验证虽比纯 LLM 评估严格，但“后果是否真实发生”仍可能受规则门控覆盖不全、隐性持久状态污染、评估器误判影响，导致 ASR 被低估或高估。

## 9. 总体评价

- **定位**：ASPIRE 不是单纯的攻击载荷生成器，而更像一套“智能体漏洞发现操作系统”：以行为图组织安全假设，以证据状态驱动探索，以覆盖度和多样性约束搜索方向。
- **核心贡献**：把安全假设作为一等公民，将红队从“优化一个字符串”转为“系统测试一类行为路径”；骨架与载荷解耦、双专家协同、跨运行策略记忆三者共同支撑开放式搜索。
- **证据强度**：主实验、消融、防御评估与成本分析较完整，能较好说明行为图与双专家的必要性；但同源模型偏差、动作工具覆盖不均、防御类型有限，使外推结论需谨慎。
- **实践价值**：对 builder-side 红队、智能体发布前安全审计、评估协议设计有直接参考价值；尤其提示防御方应关注来源追踪、工具参数验证、权限隔离与跨轮状态审计，而非仅依赖 prompt 级过滤。

## 10. 一句话总结

ASPIRE 将提示注入红队从载荷优化推进到行为级开放式漏洞发现，以行为图、双专家和策略记忆显著提升攻击成功率与覆盖度，但其泛化性、资源透明度、统计严谨性与双用途治理仍需补强。
