## 摘要
大语言模型（LLM）正越来越多地部署于隐私至关重要的领域（例如医疗、金融和政府），但其记忆并泄露个人可识别信息（PII）的倾向带来了严重的安全与合规风险。现有防御方法通常迫使模型效用、隐私保护与对微调所得私有知识的访问之间进行权衡。我们提出通过键控入口令牌进行LoRA导向控制（Locket），这是一个将细粒度、策略驱动的访问控制直接嵌入LLM生成的实用框架。Locket训练一组轻量级LoRA（低秩适应）适配器，每个适配器编码一种不同的访问策略（例如，完全揭示、通过PII掩蔽进行部分脱敏，或在指定差分隐私水平下揭示）。一个紧凑的门控模块经过训练，通过序列级硬路由将学习到的键控入口令牌与恰好一个LoRA适配器关联；有效令牌的存在充当授权密钥，解锁相应的私有知识，而无效或缺失的令牌则触发隐私保护适配器，对敏感内容进行脱敏或净化。这一设计确保Locket与现成LLM完全兼容，支持可扩展部署，同时满足监管与隐私要求。我们在多个数据集（Enron、ECHR、Yelp）和一系列多样化的最先进LLM上评估Locket，包括Qwen3（1.7B和8B）、Meta的Llama-3.2（1B和3B）以及Google的Gemma-2-2B。我们的大量实验表明，当提供正确令牌时，Locket保持的困惑度与在原始数据上微调（无任何防御）相当。相反，当令牌缺失或无效时，它显著减少PII泄露，同时保持与强基线防御相当的效用和困惑度。

## Abstract
Large language models (LLMs) are increasingly deployed in privacy-critical domains (e.g., healthcare, finance, and government), but their propensity to memorize and disclose personally identifiable information (PII) poses serious security and compliance risks. Existing defenses typically force a trade-off between model utility, privacy protection, and access to fine-tuned private knowledge. We propose LoRA-Oriented Control via Keyed Entry Tokens (Locket), a practical framework that embeds fine-grained, policy-driven access control directly into LLM generation. Locket trains a set of lightweight LoRA (Low-Rank Adaptation) adapters, each encoding a distinct access policy (e.g., full reveal, partial redaction via PII masking, or reveal under a specified differential privacy level). A compact gating module is trained to associate a learned keyed entry token with exactly one LoRA adapter via sequence-level hard routing; the presence of a valid token acts as an authorization key that unlocks corresponding private knowledge, while an invalid or absent token triggers a privacy-preserving adapter that redacts or sanitizes sensitive content. This design ensures Locket remains fully compatible with off-the-shelf LLMs, supporting scalable deployment while satisfying regulatory and privacy requirements. We evaluate Locket across multiple datasets (Enron, ECHR, Yelp) and a diverse set of state-of-the-art LLMs, including Qwen3 (1.7B and 8B), Meta's Llama-3.2 (1B and 3B), and Google's Gemma-2-2B. Our extensive experiments demonstrate that, when the correct token is provided, Locket preserves perplexity comparable to fine-tuning on raw data (without any defense). Conversely, when the token is missing or invalid, it substantially reduces PII leakage while maintaining utility and perplexity on par with strong baseline defenses.

## 一、核心问题与整体含义

- **研究背景**：大语言模型（LLM）凭借 Transformer 架构和公开 API 被广泛部署于医疗、金融、政府等隐私敏感领域，组织倾向于在私有数据上**微调**现成模型而非从头训练。
- **核心问题**：在含 PII（姓名、邮箱、地址、社保号、职业等）的数据上微调会放大隐私风险——LLM 会记忆训练样本并在良性提示下意外泄露，规模化泄露还会助长鱼叉式钓鱼、电信诈骗等下游攻击，并触及 GDPR 等合规要求。
- **现有防御的困境**：
  - **数据脱敏（scrubbing）**：用 [MASK] 替换 PII，但破坏上下文、降低下游准确率。
  - **差分隐私（DP）**：提供形式化保证，但导致效用退化，尤其损害需要细粒度事实记忆的任务。
  - 两者均作用于**数据集或模型级别**，缺乏**细粒度、按查询的访问控制**，难以执行上下文相关的隐私策略。
- **论文含义**：提出 LOCKET，把"密钥锁"式的访问控制**直接嵌入 LLM 生成过程**，使组织既能微调私有数据、又能按请求区分"授权揭示"与"默认脱敏"，力求同时兼顾效用、隐私与私有知识访问。

## 二、方法论

### 核心思想
- 训练一组轻量 **LoRA 适配器**，每个编码一种访问策略（完全揭示 / PII 掩蔽脱敏 / 指定 DP 水平下揭示）。
- 一个紧凑**门控模块**通过**序列级硬路由（hard-argmax）**将学习到的**键控入口令牌（keyed entry token）**映射到恰好一个适配器。
- 有效令牌 = 授权密钥 → 解锁揭示适配器；无效/缺失令牌 → 默认路由到隐私保护适配器。

### 关键技术细节

**1. LoRA 适配器创建**
- 采用标准低秩分解：θ = θ₀ + Δθ，Δθ = BA，其中 A∈ℝ^{r×k}、B∈ℝ^{d×r}、r≪min(d,k)，仅训练 A、B，θ₀ 冻结。
- 揭示适配器在原始视图 D_raw 上训练（式 8），防御适配器在防御视图 D_def（掩蔽/替换/PPA 遗忘等）上训练（式 9），均用 token 级交叉熵，无额外 PII 惩罚项。
- 可训练独立或联合适配器，含"scrubbing+DP"混合防御适配器；默认 r=8、AdamW。

**2. 键控入口令牌构造**
- 每个组织密钥表示为**单一特殊 token**（如 `[KEYED_TOKEN=KEY]`），加入**本地私有 tokenizer**，保证原子性不拆分为子词；公开 tokenizer 不含密钥。
- 嵌入确定性初始化：由密钥字符串 MD5 摘要的固定长度片段得 token 种子，再与全体令牌共享种子相加得 S_comb，据此采样高斯向量 e_key；初始化后**冻结**。
- 密钥长度 L=20、字母表 62 → 约 119 bit 熵；Q=10⁹ 次猜测成功率约 2⁻⁸⁹，抗暴力破解。

**3. 门控模块训练（序列级硬路由）**
- 提取 [KEYED_TOKEN] 位置（BOS 后第 1 位）的隐藏状态 h_key = Pool(H[pos_key])，经小型 MLP 输出 logits s，softmax 得概率 p，取 a* = argmax p 选择适配器。
- **路由不变性**：因因果掩码，位置 1 的隐藏状态只由 BOS 与 key token 决定，故**后续任何提示内容都无法改变路由决策**。
- 训练目标为交叉熵 + 熵正则：L_gate = L_CE + α·H(p)（α=0.1，促低熵决断）。
- 门控 MLP 结构：Linear→GLU→LayerNorm→Dropout→Linear→LayerNorm→GELU→Dropout→Linear_I（约 5.25M 参数）。
- 实验发现**仅用隐藏状态**比仅嵌入或两者结合更稳健，熵更低、选准率更高。

**4. 两遍推理与执行**
- **Gating Pass**：前向冻结基座模型得 h_key → MLP → argmax → 选适配器（可选阈值 τ 回退）。
- **Adapter Pass**：移除 key token 后再前向，应用选中适配器的 Δθ 生成输出（避免 key 污染隐藏表示）。
- 无效/缺失密钥时确定性回退到安全适配器。

## 六、主要结论与发现

- **授权路径**：提供正确密钥时，LOCKET 困惑度与在原始数据上无防御微调相当，效用几乎无损。
- **非授权路径**：密钥缺失或错误时，PII 抽取 recall 大幅下降（如从 6.81% 降至 0.19%），推理攻击准确率显著降低（如 Gemma-2-2B 从 65.82% 降至 6.25%）。
- **门控可靠性**：适配器选择准确率 **100%**；全词表 128,259 个 token 中仅密钥可解锁揭示适配器（其余 p≥0.993），密钥空间无部分匹配。
- **路由不变性**：提示内容、改写、多语言、越狱模板、注入真实密钥（非位置 1）均无法改变路由，注入攻击失败。
- **防御可组合性**：scrubbing+DP 混合防御在错误密钥下给出最低泄露（c=500 时比 DP 单用低至 2.3×）；DP 适配器可将成员推理 AUC 降至 0.503（接近随机猜测）。
- **规模与领域效应**：模型越大，提供正确密钥时攻击成功率越高（能力放大记忆），但 LOCKET 借此让大模型对授权者高效用、对非授权者拒绝效用；ECHR（法律文本）比 Yelp 更易泄露。
- **秩效应**：LoRA rank 越高，正确密钥下信息揭示越多（rank 16 达 34.55% vs rank 4 的 19.61%），需按隐私-效用权衡选择。
- **低资源鲁棒性**：语料降至 10% 时路由准确率仍 100%，授权路径困惑度在 25% 语料时趋于饱和，非授权路径无上升趋势。

## 七、优点

- **模型级访问控制**：不同于应用级 RBAC，LOCKET 在推理管线内部决定"脱敏 vs 揭示"，控制粒度更细、更难绕过。
- **架构级安全保证**：路由仅依赖位置 1 隐藏状态，提示注入无法改变路由，且经全词表扫描经验验证。
- **模块化与隔离**：敏感知识封闭在可版本化、可轮换、可撤销的适配器工件中，基座权重冻结，便于审计、回滚与合规。
- **兼容与低成本**：与现成 LLM 及现有防御（scrubbing/DP/混合）正交组合，参数与延迟开销极小。
- **密钥管理务实**：私有/公开 tokenizer 分离、确定性嵌入、轻量密钥轮换（仅替换嵌入并重拟合门控），并给出哈希嵌入不可逆性分析。
- **实验诚实**：主动区分"防御方法带来的差异"与"LOCKET 机制带来的差异"，并指出采样方差与范围外情形。

## 八、不足与局限

- **保护上界受限**：LOCKET 只控制"哪个适配器回答"，不改变适配器学到什么；其隐私保护**完全受限于防御适配器所用的脱敏/DP 方法**。
- **密钥持有者与密钥盗用不在范围内**：授权内幕滥用与合法密钥泄露无法检测，只能靠密钥轮换补救。
- **路由器为单点**：虽提示内容无法改变路由，但自适应搜索路由器输入空间、多轮探测、从模型行为反推密钥的攻击尚未研究。
- **密钥表示局限**：依赖词表级特殊 token，未来需拓展至非词表级密钥表示以增强鲁棒性。
- **语言与领域覆盖**：实验限于英文语料（Enron/ECHR/Yelp），未验证多语言与非英语敏感数据场景。
- **合成路由数据依赖**：门控训练数据为人工合成，其覆盖性（尤其全词表拒绝能力）依赖设计质量，作者也将其作为每次发布的检查项。
- **模型特定差异未充分解释**：如 Gemma 对抽取攻击脆弱性低但仍易受排序推理攻击，机理归因较简略。
- **算力信息不完整**：仅报告单 GPU 型号与单适配器训练时长，未给出 GPU 数量与总计算预算。
