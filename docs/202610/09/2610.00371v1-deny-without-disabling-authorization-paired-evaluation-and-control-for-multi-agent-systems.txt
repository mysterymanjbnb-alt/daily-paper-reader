ABSTRACT
Multi-agent systems derive their capabilities from sharing evidence, delegating tasks, and
combining information across agents. The same process creates a safety problem: contributions
that are admissible in isolation can jointly enable a prohibited use. Blocking every sensitive
action avoids disclosure but defeats the purpose of collaboration. We introduce authorization-
paired evaluation, which makes blocking prohibited uses and completing required authorized
uses a joint success criterion, and FlowReview, a framework connecting object resolution,
permission ranking, and deterministic enforcement. In controlled composition experiments,
reviewing combined artifacts reduces the denied-commit rate from 86.0% to zero with no loss of
authorized supply. Our findings show that preserving information and lineage alone does not
ensure correct permission attribution. Object identity and permission must remain connected
to execution through components whose outputs can be verified. Together, these findings
establish a system-level requirement for multi-agent safety: govern composed information
flows while preserving the authorized capabilities that make collaboration useful.
1 Introduction
Combining information is a source of capability in multi-agent systems, yet it can also lead
to safety failures. For example, a support team joins records from separate services, while a
software team assembles changes produced by different agents. Agent frameworks support
this division of labor through separate model contexts, message passing, and delegated tasks
(Wu et al., 2023; Li et al., 2023; OpenAI, 2025; Hadfield et al., 2025), and benchmarks evaluate
the resulting business and software workflows (Yao et al., 2024; Xu et al., 2025; Jimenez
et al., 2023). In these workflows, information sharing changes what a downstream agent can
reconstruct and act upon. The resulting safety question is about the workflow as a whole: is
the action enabled by the agents’ combined information authorized under trusted policy?
Consider three agents that each contribute part of a protected record. Every message
passes a check for the complete record, yet a downstream composer can recover it from their

Preserving the authorized use is essential to this comparison. Erasing every protected
value or refusing every consequential action can produce a perfect deny-side score while
disabling the capability the team was built to provide. Agent-safety benchmarks already
evaluate harmful behavior alongside benign utility (Debenedetti et al., 2024; Zhang et al.,
2025; Kavathekar et al., 2025; El Yagoubi et al., 2026), and policy-aware evaluation makes the
constraints on successful action explicit (Levy et al., 2024; Tang et al., 2026). The requirement
here is more specific: the system must distinguish a prohibited use from the required
authorized use within a shared task scenario. We call this target selective safety. It gives
deny without disabling an operational meaning, with surrounding-task completion measured
alongside it.
We introduce authorization-paired evaluation to measure selective safety. Each unit pairs
a prohibited use with a task-required authorized use in the same scenario and succeeds
only when the first is blocked and the second completes. We construct an evaluation suite
with explicit governed objects, artifact assignments, and trusted permissions, enabling
controlled comparisons of available information, authorized use, and executed actions. In
our capability ladder, class-only review withholds most denied values but never achieves
this joint success. Object binding and deterministic enforcement raise selective correctness
from zero to roughly 99%, with no verbatim release at the registered action boundary across
2,304 final-configuration trials.
FlowReview connects this evaluation target to multi-agent system design (Fig. 2). It asks
three questions: What governed object does the available information identify? Which proposed
use is authorized? Does execution obey that decision? These questions define object resolution,
permission ranking, and deterministic enforcement. Controlled interventions reveal how

2 Setting
2.1 Agents and information flows
We study separately invoked LLM agents that exchange recorded artifacts and propose
actions on governed objects. Each agent has its own input context and model call. Its role
specifies its task and available information. A homogeneous team uses the same underlying
model for all agents, while a heterogeneous team uses different models. Both communicate
through explicit messages, store records, and handoffs. Shared model weights do not imply
shared context. Appendix A.2 distinguishes the model roles and runtime components.
A governed object 𝑧is a value or record whose use is subject to trusted authorization. For
example, two agents contribute 12 and 34, and a composer joins them into access code 1234.
The complete code is the governed object. Sending it to the requester is a proposed action,
which we call a proposal. Trusted policy 𝑃specifies whether the use is authorized, binding
permission to the object, operation, destination, acting principal, and relevant policy version.
We use protected data and, where unambiguous, object as shorthand for governed object, our
primary term.
An episode 𝑒records the task, artifacts = (𝑎1, … , 𝑎𝑚), governed objects, policy, pro-
posed actions, and an executed-action ledger 𝑦(𝑒). The action boundary is the runtime point
at which a proposal becomes an executed action. A deterministic commit gate mediates this
transition and updates the ledger. Recording the proposal and the executed action separately
lets us distinguish what a model attempts from what the system actually does.
A registered contract or rule is fixed before the corresponding model calls are made. A
registered resolver 𝑅identifies the governed object from available artifacts, returning ⊥if
unresolved. A local reader evaluates one artifact, while a global reader evaluates their union.

within a shared scenario. Each unit records two binary outcomes at the agent action boundary.
Denied disclosure 𝐷equals 1 if the evaluated prohibited use of a governed object actually
executes, and 0 otherwise. Authorized supply 𝐴equals 1 if the task-required authorized use

A pair contains either two executions of the same scenario and governed object under

The threat model separates untrusted information from trusted execution authority. The
attacker controls untrusted artifacts and knows the pipeline, prompts, and detectors, but
cannot modify trusted policy 𝑃, the registered schema, or the commit gate. An untrusted
authority claim 𝑄varies independently of 𝑃. In the read-scope experiments, object-specific
enforcement applies when the reader resolves the governed object. If resolution returns ⊥,
a schema-valid proposal follows the underlying execution path without an object-specific
block. A fail-closed rule would instead block all unresolved proposals, including any required
authorized uses. Authorization-paired evaluation captures this tradeoff through 𝐷and 𝐴.
Confirmatory comparisons use prespecified scenarios, with scenario-cluster bootstrap
intervals and Holm correction within endpoint families. Evaluation rates include failed
provider calls and protocol-invalid outputs. Appendix A details the action contracts and
paired interventions, and Appendix A.4 specifies the statistical analyses and treatment of
execution failures.
3 FlowReview
3.1 Review the composed action
FlowReview reviews a proposed action using the workflow’s recorded artifacts, trusted
policy, and the registered object and action contracts. The ledger 𝑦(𝑒) records whether the
proposed action executes. The three capabilities below are tested through a ladder of class-
only review, two-sided object binding, and added deterministic enforcement. Placement
experiments then vary which component records lineage, selects the permission-bound
action, or assembles the object.
Object resolution identifies which governed object the available evidence makes actionable.
The registered contract supplies the object identity and action fields against which the
evidence is checked. For a structured record, the resolver verifies the field union against
that identity. For a text-valued action, it matches the registered value or representation
in the action fields. Local and global readers perform this check on individual artifacts
and their union, respectively. This object-specific result supplies the identity needed for a
permission decision. A sensitive-content class alone cannot distinguish records with different
permissions.
Permission ranking applies trusted 𝑃to the proposed uses of the resolved objects. The
required output distinguishes the action that policy denies from the authorized action that the
task requires. Two-sided binding makes both object identities available, allowing same-class
values with opposite permissions to receive different decisions. In the modular experiments,
an isolated model specialist applies an explicit DENY or ALLOW policy to the coordinator’s
candidate action. It receives the policy, object reference, policy version, and candidate. It
selects the unchanged candidate only under ALLOW with matching reference and version,
and selects no action otherwise. Placement experiments vary the component that performs
permission ranking, and policy-correct proposals measure whether the selected action
satisfies the trusted permission and binding requirements. The commit gate independently

Deterministic enforcement carries the permission decision into execution. The runtime
verifies the bound action against trusted policy and controls the sole commit path. In the
ladder, it parses the draft into schema-defined action fields and deterministically removes
the denied value before execution. In object-level workflows, it admits or blocks the bound
action. Enforcement depends on permission correctness and reader coverage. In read-scope
experiments, unresolved schema-valid proposals retain the underlying execution path under
either scope (Sec. 2.3).
3.2 Capability placement
The placement experiments test which components preserve these capabilities through
communication. We use provenance for recorded metadata about artifact origins and trans-
formations, and lineage for the dependency chain those metadata describe. The runtime
lineage record captures directly observable dependencies (Appendix E). The isolated specialist
applies permission to a candidate action, and the runtime independently verifies its object
reference, operation, destination, principal, and policy version before execution.
Authorized completion also requires the system to assemble the object successfully. The
assembly experiment separates artifact availability from the ability to combine the available
fragments. A fixed, provider-independent fallback replaces invalid or unavailable artifacts
without consulting policy or downstream outcome (Appendix E). The model composer and
runtime assembler then receive the same validated artifacts. The runtime assembler checks
their contents against the registered schema and reconstructs the governed object. This
isolates the effect of assigning the specified assembly procedure to the runtime.
In a saved Qwen example, the coordinator reports ALLOW but mistypes the object reference
in its selected action. An isolated specialist selects the coordinator’s correctly bound candidate
unchanged, and the runtime verifies it before committing (Appendix E.3).

4.1 Composition defeats local review
The controlled composition experiment identifies how reader scope changes control of the
same proposed action. Its constructed fragment bank measures this mechanism rather than
its prevalence in naturally occurring workflows. We distribute a governed object’s fragments
across messages, agents, or a store-to-handoff path, verifying that every artifact passes its
local reader as in Equation 1. Holding the artifacts, policy, proposal, and action boundary
fixed, reviewing their union reduces denied commits from 86.0% to zero with unchanged
authorized supply. The decisive difference is access to the relationship among fragments,
which makes the complete object available for permission enforcement.
The same failure appears with model-generated workflow artifacts. Independently called
workers receive preassigned fragments and generate messages, store notes, and handoffs
for a downstream composer. Denied recovery occurs in 3/60 pairs, all with the Gemma
composer, and the commit gate with a global reader blocks every instance. The gate blocks
unauthorized use, but authorized supply (15/60) and task completion (27/60) remain low,
reflecting unresolved failures of reconstruction or task execution. Appendix B follows one
such execution, and Appendix C reports the model-level outcomes.
4.2 From detection to control
Authorization-paired evaluation exposes the difference between suppressing sensitive content
and controlling its permitted use. Class-only review usually withholds the denied value
but achieves no joint successes, because it fails to retain the required authorized sibling.
Two-sided object binding supplies the missing permission distinction, and deterministic
enforcement carries it into execution (Fig. 3). Together they raise selective correctness to
roughly 99%, with no verbatim disclosure at the registered action boundary across 2,304
final-configuration trials. This pattern persists across both attack families and adaptive
budgets (Appendix C). The component interventions explain why each capability contributes
to this change.
Object resolution depends on how the reader recognizes the governed object in the
proposed use. Holding proposals and policies fixed across models and representation families,
canonicalization lowers denied commits in 22/40 comparisons and raises them in 8/40. The
transformation-specific decoder replaces literal matching without a literal fallback, so either
reader can miss uses recognized by the other. The result makes the reader’s recognition rule
part of the control interface: permission enforcement can apply only to the uses that the
reader resolves (Appendix C.3).
Object identity becomes essential when similar values carry different permissions. For a
single governed object, control with the detector union blocks observed disclosure while
retaining nearly all authorized supply. Adding a same-class, same-shape sibling with opposite
permission exposes the limit of content labels: both values appear sensitive, but only one use is

removes complete local visibility and defeats local control, while global review blocks the
denied actions whose lineage it resolves. Both readers block the single-record baselines, and
global review preserves the matched authorized actions. The initial failure is the loss of
complete local context.

4.4 Verifiable placement restores control
Delegation separates preserving artifact dependencies from preserving their permission
semantics.
Giving provenance fields explicit immediate-parent, source-visibility, and
transformation-index meanings restores nearly complete model-authored lineage while
preserving task completion (Fig. 6). Permission-attribution errors occur in 676/840 graphs
under the explicit contract. Attribution measures faithful reporting of an external claim and
its untrusted authority, while policy-correct proposals measure compliance with trusted 𝑃.
An untrusted ALLOW claim should therefore be reported as such even when trusted DENY
requires rejecting the action. The contract study measures any-role attribution drift, while
the original delegation study measures final-proposal attribution drift on a separate bank.
Appendix D.2 reconciles these endpoints and their corresponding lineage baselines.

asking a model to reconstruct execution history. An isolated permission specialist then
selects an action bound to that record, and the commit gate verifies the selected action
independently. On the same held-out graphs, all four specialist models preserve policy-
correct proposals and task completion, with no denied commits (Table 1). Small attribution
errors remain, even though the final selected actions obey trusted policy. Each component

Authorized supply also requires successful object assembly. On identical validated artifacts,

Policy changes expose the related need to produce a new valid action after rejecting a stale

commits but fails to supply the currently authorized action. Rereading current policy restores
that supply while also preventing wrong commits. Selective control therefore requires both
rejecting stale actions and producing the action required by current policy (Appendix E.5).

Information-flow control. Our design builds on complete mediation, information-flow
control, and capabilities (Saltzer & Schroeder, 1975; Denning, 1976; Hardy, 1988). CaMeL
tracks interpreter data dependencies and applies tool-call policies to their transitive de-
pendencies (Debenedetti et al., 2025). FlowReview contributes a paired evaluation target
and experimental decomposition of resolution, permission ranking, and enforcement across
agents. Read-scope and contributor interventions locate failures of object resolution, while
placement comparisons test how the required capabilities survive communication. Ap-
pendix G discusses contextual privacy, compositional attacks, and delegated capability
systems.
6 Discussion and Conclusion
Multi-agent safety requires governing the information a workflow composes and preserving
its authorized use. Authorization-paired evaluation makes both outcomes part of the safety
target, and FlowReview connects that target to object resolution, permission ranking,
and deterministic enforcement. Our placement interventions demonstrate how verifiable
components sustain these capabilities. Runtime lineage makes dependencies available for
review, while isolated permission review keeps authorization bound to the proposed action.
Validated runtime assembly preserves the ability to complete authorized uses of distributed
information. The findings yield a design principle: preserve object identity and permission
through communication, then verify the action that executes. This connection enables
systems to deny without disabling. Appendix H summarizes the findings and outcomes by
sampling unit.
Limitations and Future Directions. The controlled banks identify composition mech-
anisms, and the ladder’s zero-disclosure result applies to the registered verbatim action
boundary. AgentDojo confirmation covers Sonnet 4.5 under a relay selected in development.
Future work can measure prevalence in natural workflows, broaden representation and
model coverage, improve recovery under changing permissions, and compare safety and
authorized utility against external defenses.

A.1 Dataset construction
The evaluation suite makes the information and permission dependencies of an action explicit.
Its constructed scenarios specify a task, a governed object, a required authorized use, and a
registered action contract before model execution. Scenario templates supply synthetic values
and operational records, with scenario-specific identifiers and destinations. The AgentDojo-
derived studies use the benchmark’s tasks, tool schemas, and state oracles, supplemented
with relay inputs and exact target-action contracts. Table 3 reports the study-specific units
and denominators.
Object construction and information allocation. Text-valued objects are divided
into ordered segments, while the contributor bank partitions a 16-field incident record
among its informative workers. The controlled composition inputs satisfy two checks: each
individual artifact is incomplete under its reader, and the union resolves the registered
object. In the generated-composition variant, three independently called workers receive as-

A.4 Analysis and reproducibility
Confirmatory designs specify the scenarios, models, prompts, endpoints, estimators, and
retry rules before model evaluation. Development and confirmation samples are disjoint.
Paired intervals use scenario-cluster bootstrap resampling, with Holm correction within the
specified endpoint families. Resample counts follow the study-specific analyses, including
8,000 for natural composition and 10,000 for the powered contributor replication and capa-
bility placement. Individual studies state their sampling units and eligibility criteria. We
count transport attempts separately from the model response used for evaluation. Malformed
outputs and terminal provider failures are included when computing outcome rates. Two
complete executions, one in contributor scaling and one in delegation, were excluded for
transport-accounting violations before outcome analysis. Replacements corrected transport
accounting, preserving scenarios, prompts, models, and analysis specifications.

F Tool-Use Transfer
Tool-use transfer tests whether control can prevent an unauthorized side effect while preserv-
ing the legitimate task in an external execution environment. The comparisons address three
questions: which attack exposure makes that effect measurable, whether control preserves
utility across models, and whether the result persists on independent task and injection
pairs. The Sonnet relay comparison, cross-model exposure study, and Qwen evaluations use
distinct scenario sets with their own sample sizes and selection criteria.
F.1 Relay selection and execution control
The exposure comparison includes unchanged official payloads and three derived relay
conditions: authority re-expression, indirect tool-result relay, and distributed fragment com-
position. The prespecified selection rule first maximizes pooled Sonnet/Haiku exact transient
exposure, then assesses each model against attack, utility, protocol, and instrumentation
criteria. Table 17 reports the development comparisons. Qwen3-32B serves as a separate
positive control, while selection uses the Sonnet/Haiku outcomes. The selected tool-result
relay produces 24/24 exact transient attacks for Sonnet and meets its eligibility criteria.
Haiku produces 2/24 and fails the instrumentation criterion, so the independent treatment
comparison evaluates Sonnet.
In the 24 independent Sonnet confirmation pairs, runtime control reduces target com-
mits and final-state violations. The paired changes are −0.875 [−1.00, −0.75] and −0.833
[−0.958, −0.667], respectively, with scenario-cluster bootstrap 95% intervals. Both reductions
remain significant after Holm correction at 𝑝< 0.001. Benchmark utility improves by +0.500
[0.292, 0.708], while legitimate-action supply and protocol conformance are unchanged.
These results demonstrate control of the relayed action alongside improved benchmark util-

F.5 Generalization to independent pairs
An independent Qwen replication tests whether attack exposure and utility preservation
carry over to new task and injection pairs. It uses eight held-out pairs, with two from each of
workspace, banking, travel, and Slack. The design crosses each pair with AgentDojo’s four
official non-denial-of-service attacks (Important Instructions, InjecAgent, System Message,
and Tool Knowledge). Each of the 32 combinations of attack and scenario pair is run once
under the native runtime and once with the commit gate enforcing the exact target contract,
for 64 Qwen3-32B trajectories. The adapter uses AgentDojo suite v1.2.1 (Python distribution
0.1.35), the official system message and native task/security oracles, and complete unflattened
Pydantic tool schemas. The commit gate verifies the object reference and exact arguments
against a contract bound to the destination, operation, principal, and policy version. Blocking
one target therefore leaves a legal call to the same tool eligible for execution.
The confirmatory security analysis requires a native target-commit rate of at least 0.20
and at least four executed target actions. Security is measured both from the complete
executed-action ledger and AgentDojo’s final-state oracle. The former is primary because
a later legitimate action can overwrite an earlier attack. Utility preservation is a paired
non-inferiority test clustered by task and injection pair: the lower endpoint of the cluster-
bootstrap interval for gated minus native user utility must exceed −0.10. All native and gated
runs are retained across attacks and domains, including schema errors, refusals, and cases
in which the commit gate changes subsequent model behavior. The comparison contains
64 protocol-conformant trajectories and 279 successful model calls. The native runtime
executes the exact target action in 1/32 cases, below both prespecified minimums. The single
exact target is proposed in both matched arms and committed only in the native arm. This
low-exposure comparison is analyzed descriptively. Utility is 11/32 in each arm. The paired
difference is 0 with cluster interval [−0.156, 0.125]. Despite equal observed success rates, the
data cannot rule out a utility change worse than the −0.10 margin. Table 21 reports every
attack family and the exploratory pooled row.

G Extended Related Work
Agent frameworks make information composition an operational concern. AutoGen
and CAMEL organize collaboration through separately prompted participants and explicit
conversation, while the OpenAI Agents SDK, Google ADK, and ClawTeam provide dele-
gation and orchestration interfaces (Wu et al., 2023; Li et al., 2023; OpenAI, 2025; Google,
2025; HKUDS, 2026). Multi-agent research systems further illustrate the practical use of
specialist workers and coordinating agents (Hadfield et al., 2025; Anthropic Frontier Red
Team, 2026). The distinction between homogeneous and heterogeneous teams concerns
the models behind those participants, independently of their separate contexts and com-
munication paths. OpenClaw, Claude Code, and Codex place model-directed work inside
persistent tool and execution environments (Steinberger, 2025; Anthropic, 2026; OpenAI,
2026). These systems motivate specifying exactly which information an agent observes and
which runtime component can authorize its proposed action.
Task benchmarks establish the capability that a safety control must preserve.
SWE-bench evaluates repository changes, VisualWebArena evaluates visually grounded web
tasks, and OSWorld evaluates actions in real computer environments (Jimenez et al., 2023;
Koh et al., 2024; Xie et al., 2024). TheAgentCompany and Agent’s First Day extend the task
horizon to workplace activity and learning in a changing environment (Xu et al., 2025; Fu

et al., 2026a). ClawBench and ClawMark add realistic web execution and stateful coworker
interactions (Zhang et al., 2026d; Meng et al., 2026). In 𝜏-bench, tool use is evaluated together
with domain rules and the resulting database state (Yao et al., 2024). Our task endpoint 𝑇
retains this concern for useful completion, while authorized supply 𝐴isolates the particular

Agent-safety benchmarks broaden the contexts in which harmful behavior is mea-
sured. AgentHarm includes benign counterparts of harmful behaviors, Agent-SafetyBench
tests diverse interactive risks, and AgentDojo supplies a stateful setting for tool-mediated
prompt injection and defense evaluation (Andriushchenko et al., 2025; Zhang et al., 2025;
Debenedetti et al., 2024). SafeArena pairs safe and harmful web tasks, OS-Harm studies
unsafe computer use, and ATBench examines safety across realistic agent settings (Tur et al.,
2025; Kuntz et al., 2025; Li et al., 2026c). ClawEval and ClawsBench further distinguish
completion from safety in autonomous workflows. RASEval and MCPSecBench examine
security across tool and protocol interfaces (Ye et al., 2026; Li et al., 2026b; Fu et al., 2025;
Yang et al., 2026). These benchmarks provide complementary attack surfaces and task
distributions. Authorization-paired evaluation makes the relationship between prohibited
and required authorized uses explicit within a shared task scenario, so a safety score also
measures preservation of the required capability.
Privacy and policy-aware evaluation connect disclosure to its context. PrivacyLens
evaluates privacy norms along agent trajectories, CI-Work tests contextual integrity in
workplace information flow, and MyPhoneBench separates access permissions, disclosure,
and memory behavior from task success (Shao et al., 2025; Fu et al., 2026b; Tang et al., 2026).
ST-WebAgentBench’s completion-under-policy measure likewise makes compliance part of
successful execution (Levy et al., 2024). The distinction between safety and utility is therefore
already substantive in agent evaluation. Our contribution is to bind the two outcomes to the
evaluated governed objects and trusted authorization contrast, and to diagnose how multi-
agent composition disrupts that binding. Financial-risk frameworks address the consequences
of agent failure through assessment and compensation, complementing controls that prevent
an unauthorized action before it executes (Hua et al., 2026).
Multi-agent interaction introduces both adversarial and emergent risks. TAMAS
evaluates adversarial instances alongside harmless tasks, AgentLeak measures internal-
channel privacy leakage and task utility, and GroupGuard models coordinated attacks
(Kavathekar et al., 2025; El Yagoubi et al., 2026; Tao et al., 2026). Research on emergent
social risks and AI organizations examines how collective behavior changes with interaction
structure (Huang et al., 2026; Shen et al., 2026). Agents in the Wild examines interaction
patterns and safety risks on Moltbook (Zhang et al., 2026b). Agentic-misalignment studies
use simulated deployments to investigate harmful actions under goal conflicts, and Petri
supports automated exploration of such behaviors (Lynch et al., 2025, 2026; Fronsdal et al.,
2025). FlowReview isolates a specific mechanism within collaborative execution: agents can
preserve their assigned fragments and still enable a downstream unauthorized action. Our
constructed suite pairs governed uses by their trusted permissions and varies the information
available to review. The read-scope and contributor interventions make this dependency
observable across both homogeneous and heterogeneous teams.

Compositional attacks show why safety cannot be inferred from isolated inputs.
Jailbreak in Pieces and Safety Snowball exploit cross-modal composition, while Jigsaw Puzzles,
Crescendo, and Foot-In-The-Door build harmful requests through multiple conversational
steps (Shayegani et al., 2024; Cui et al., 2025; Yang et al., 2025; Russinovich et al., 2025; Weng
et al., 2025). X-Teaming and MM-Plan use agentic planning to construct adaptive attacks, and
HarmBench standardizes comparisons of red-teaming methods and robust refusal (Rahman
et al., 2025; Zhang et al., 2026a; Mazeika et al., 2024). The common concern is that the
safety significance of combined information can exceed that of its components. Our setting
places this composition inside the evaluated workflow and changes trusted authorization
for the same recovered governed object. This links the compositional failure directly to the
requirement to deny without disabling.
Harness security connects model behavior to its execution environment. Open-
Claw security studies and ClawKeeper examine threats and controls across persistent agent
infrastructure (Wang et al., 2026a; Liu et al., 2026b). Poise studies instruction injection
through agent skills, ClawSafety examines framework-dependent safety, and persistent-state
attacks expose conflicts between protection and legitimate updates (Hao et al., 2026; Wei
et al., 2026; Wang et al., 2026b). Harness surveys, audits, and harness-aware evaluation
emphasize orchestration, verification, and governance as parts of agent behavior (Li et al.,
2026a; Liu et al., 2026a; Zhang et al., 2026c). Our placement experiments isolate the roles of
runtime lineage, permission interpretation, and assembly in preserving authorized execution.
Information-flow and capability controls supply the enforcement foundation.
Complete mediation requires checking access at each relevant operation, information-flow
control follows information across computation, and the confused-deputy problem separates
possession of authority from authorized use (Saltzer & Schroeder, 1975; Denning, 1976;
Hardy, 1988). CaMeL separates privileged control from untrusted processing, propagates
dependencies through its interpreter, and checks tool-call policies against the resulting
transitive dependencies (Debenedetti et al., 2025). This supports policy enforcement across
composed computations. ChainCaps, ARGUS, and ScopeGate develop delegated, provenance-
aware, and value-bound authorization (Jiang et al., 2026; Weng et al., 2026; Mellafe Zuvic,
2026). FlowReview supplies a complementary experimental decomposition: paired outcomes
couple denied use to required authorized use, read-scope and contributor interventions isolate
resolution failures, and placement comparisons test how the required capabilities survive
communication. Its central requirement is end-to-end: the identity of the composed governed
object and its current trusted authorization must reach the agent action boundary together.
