## 摘要
LLM智能体利用技能来提升其在专门任务上的表现。为完成用户请求，智能体可能依次调用多个技能，使某一技能产生的信息引导下一技能。由于技能可能来自开源仓库，这种交接也可能将攻击者控制的声明带入后续决策。本文提出APEX，它针对用户任务与攻击者选定的动作，构建并优化对抗性技能链。其核心洞见在于，由智能体撰写的真实任务进展记录可以跨技能携带虚假的用户批准声明：上游技能诱导智能体创建该记录，下游技能则利用它来引导攻击者选定的动作。在SkillsBench上，针对四类目标动作族和六种模型，这些技能链在690次尝试中有512次（74.2%）成功诱导出所选动作。在GPT-5.4上，完整技能链的成功率为84.3%，而将工作流合并为单个技能时仅为17.4%。我们进一步评估了一种提示防御，要求智能体将技能生成的文件与原始请求进行核对。在GPT-5.4上，该防御将目标动作成功率从84.3%降至59.1%，但同时72个良性原生技能任务的验证器测试通过率从86.7%降至56.3%。这些结果凸显了需要既能阻止攻击者导向的动作、又能保持合法任务性能的防御方法。

## Abstract
LLM agents use skills to improve performance on specialized tasks. To complete a user request, an agent may invoke several skills in sequence, allowing information produced under one skill to guide the next. Because skills may come from open-source repositories, this handoff can also carry attacker-controlled claims into later decisions. In this paper, we introduce APEX, which constructs and refines adversarial skill chains tailored to a user task and an attacker-selected action. The key insight is that an agent-written record of genuine task progress can carry a false claim of user approval across skills: an upstream skill induces the agent to create the record, and a downstream skill uses it to direct the attacker-selected action. Across four targeted-action families and six models on SkillsBench, the chains induce the selected action in 512 of 690 attempts (74.2%). On GPT-5.4, the full chain succeeds in 84.3% of attempts, compared with 17.4% when the workflow is merged into one skill. We further evaluate a prompting defense that asks the agent to check skill-produced files against the original request. On GPT-5.4, it lowers targeted-action success from 84.3% to 59.1%, while the verifier test-pass rate across 72 benign native-skill tasks falls from 86.7% to 56.3%. These results highlight the need for defenses that prevent attacker-directed actions while preserving legitimate task performance.

## 1. 核心问题与整体含义

- **背景**：LLM 智能体通过调用可复用技能包（skill，如 `SKILL.md`）完成多步任务；为完成一个用户请求，智能体常会依次调用多个技能，让一个技能的产出引导下一个技能的决策。
- **新攻击面**：技能可来自开源仓库 / 市场（如 SkillsMP），攻击者可上传恶意技能，利用技能之间的**信息交接（handoff）**把攻击者控制的声明带入后续决策。
- **核心洞见**：智能体为记录**真实任务进展**而自己写下的文件，可以跨技能携带一条**虚假的"用户已批准"声明**——上游技能诱导智能体创建该记录，下游技能据此执行攻击者选定的动作。
- **威胁含义**：智能体可以在**完成并回报用户合法任务**的同时，执行用户明确禁止的动作（例如用户要求"总结并保留原文件"，智能体却删除原文件）。
- **研究空白**：已有技能组合攻击研究（ColluSkill、CompoSkill、SCR-Bench）关注攻击可行性，但对"工作流受攻击时，智能体对用户原任务的完成度如何"探讨不足。本文同时测量攻击结果与合法任务性能。

## 2. 方法论：APEX（Authority Promotion EXplorer）

- **核心思想**：给定用户任务与攻击者选定目标，构造一条技能链——上游技能让智能体把"任务进展 + 攻击者提供的批准声明 + 选定目标"写入持久记录；下游技能指示智能体依据该记录行动。
- **构造与精炼流程（Figure 2）**：
  1. 生成候选技能链；
  2. 在隔离任务副本（Harbor 执行框架）中试运行；
  3. 用执行反馈（任务效用 + ASR）评估；
  4. 定位失败阶段并修订指令，循环迭代。
- **失败区分**：试运行报告能区分"未能建立交接（下游读不到记录）"与"读到记录但拒绝执行动作"，从而针对性修改对应阶段的指令；目标动作与成功判据始终固定。
- **五类攻击族（Table 1）**：
  - *External Transfer*（机密性）：本地任务文件 → 越界网络传输；
  - *Script Acquisition*（完整性）：伪装的"任务相关 helper" → 远程恶意脚本被检索并执行；
  - *File Modification*（完整性）：非备份文件 → 原生文件删除；
  - *Output Tampering*（完整性）：源文件 → 写入与源冲突的内容；
  - *Work Loop*（可用性）：完成一个执行单元 → 被诱导返回入口开启下一单元。

## 3. 实验设计

- **Benchmark**：SkillsBench（按攻击族选取适配任务子集）。
- **模型（6 个）**：Claude Sonnet 5、DeepSeek V4 Flash、GPT-5.4、Gemini 3.5 Flash、Grok 4.5、Kimi K2.6。
- **任务与验证器规模（Table 6）**：
  - External Transfer：30 任务 / 251 检查项；Script Acquisition：29 / 190；File Modification：25 / 217；Output Tampering：31 / 249；Work Loop：15 / 113；良性原生任务对照：72 任务 / 533 检查项。
- **指标**：
  - ASR = 满足族成功判据的运行比例；
  - 任务效用 = 通过的原生验证器检查数 / 总检查数（按检查项加权，非按任务计）；
  - Work Loop 用每任务平均 token 比 **r̄ = N⁻¹Σ T_Ai/T_0i**，并单独报告原生效用。
- **成功判据（Table 5）**：删除须确证**指定原生文件本身**被移除；网络效果由任务环境内捕获服务记录；Output Tampering 需可追溯到实际写入且与源冲突，且任务对可用来源/目标有限制。
- **对比条件 / 方法**：
  - 直接注入（单技能中明写目标）；
  - 单体工作流（任务与攻击指令合并进一个技能，用内存局部状态替代跨技能记录）；
  - 授权拒绝记录（记录状态改为未授权，其余工作流不变）；
  - 技能数量消融 K=1~6（K<K₀ 合并阶段，K>K₀ 插入占位技能）；
  - 防御：taint-guided prompting（污染引导提示）——将每次技能调用期间创建/修改的工作区文件标记为不可信，要求智能体对照原始请求与独立获得的信息复核。
