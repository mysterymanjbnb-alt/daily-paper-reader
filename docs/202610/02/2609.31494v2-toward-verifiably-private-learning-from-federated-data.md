## 摘要
联邦学习（FL）允许拥有私有数据的设备协作训练一个共享模型。我们提出了一种基于可信执行环境（TEE）的新一代联邦学习系统，该系统解决了与早期系统相关的运营挑战，并首次提供可外部验证的中心化差分隐私（DP）保证，同时带来更好的隐私-效用权衡。在我们的系统中，设备上传使用由 TEE 托管的密钥管理服务（KMS）管理的密钥加密的数据。上传的数据通过密码学方式绑定到一项策略，该策略限制了之后可在服务器端 TEE 中处理这些数据的 Python 程序集合。外部方可以检查公开透明度日志，以查看这些策略所允许的工作负载集合。我们的实验结果表明，新系统提高了设备覆盖率，并通过使收集到的数据能够按照一种优化 DP 保证且不受设备可用性影响的时间安排被整合到服务器端工作负载中，从而有利地改善了隐私-效用曲线。我们的新系统已实现产品化，使得 Android 键盘（Gboard）的模型能够更快地训练，并在更小的、如今可外部验证的隐私预算下，相比使用先前系统训练的模型获得更高的准确率。

## Abstract
Federated Learning (FL) allows devices with private data to collaborate in training a shared model. We present a next-generation FL system based on Trusted Execution Environments (TEEs) that addresses operational challenges associated with earlier systems and provides externally verifiable central Differential Privacy (DP) guarantees for the first time while offering a better privacy-utility tradeoff. In our system, devices upload data encrypted with keys managed by a TEE-hosted Key Management Service (KMS). The uploaded data is cryptographically tied to a policy limiting the set of Python programs that may later process the data in server-side TEEs. External parties may inspect public transparency logs to observe the set of workloads allowed by these policies. Our experimental results show that the new system improves device coverage and favorably shifts privacy-utility curves by enabling collected data to be integrated into the server-side workload at a schedule that optimizes DP guarantees and is unaffected by device availability. Our new system has been productionized, enabling models for the Android Keyboard (Gboard) to be trained faster and achieve better accuracy under smaller, now externally verifiable privacy budgets in comparison to models trained using the prior system.

## 1. 论文的核心问题与整体含义

- **研究动机**：联邦学习（FL）允许私有数据设备协作训练共享模型，但早期 FL 系统存在多重局限：
  - 需在设备端计算模型梯度，限制了可训练模型的规模；
  - 跨设备群的同步点带来运维挑战（设备可用性不可预测、算力异构）；

- **背景定位**：作者所在 Google 团队于 2024 年提出 FL 的新定义，强调四项隐私原则：数据最小化、数据匿名化、透明度与控制、可验证性与可审计性。本文即是在这一框架下，利用可信执行环境（TEE，AMD SEV-SNP 与 Intel TDX）构建新一代 FL 系统。
- **整体含义**：这是首个在生产环境中实现**可外部验证的中心化差分隐私（DP）保证**的 FL 系统，同时改善了隐私-效用权衡，并在 Gboard 模型训练上落地。

## 2. 方法论

- **核心思想**：将大部分计算从设备端移至服务器端 TEE 中，设备只负责一次性上传加密数据；上传数据通过密码学方式绑定到一项访问策略，该策略限定了未来可处理这些数据的 Python 程序与二进制哈希。
- **系统架构（两阶段）**：
  - **上传阶段**：设备验证 KMS 的 TEE 软件及访问策略均已记录在公开透明度日志中，然后使用 KMS 公钥加密数据并上传至中间存储，同时绑定访问策略。
  - **服务器端处理阶段**：根 TEE 运行 `trusted_program` 函数，可将并行工作委托给工作 TEE；根与工作 TEE 通过 Noise 协议建立端到端加密通道，根 TEE 验证工作 TEE 的远程证明。
- **信任链**：设备 → KMS（由 RAFT 共识的 TEE 集群组成，维护防回滚的键值数据库）→ 未来的根/工作 TEE。KMS 仅向访问策略允许的 TEE 二进制提供解密密钥。
- **程序 API（ExternalHandle）**提供四类能力：
  1. 访问上传数据（负责解析）；
  2. 运行时旁加载信息（用于参数化或每用户专有映射逻辑）；
  3. 受控释放结果（明文结果输出，需由工作负载作者自行保证匿名化）；
  4. 保存/加载恢复信息（KMS 加密并签名，仅未来相同程序可读）。
- **分布式执行**：使用 Federated Language 表达分布式计算；含 `federated_broadcast`、`federated_map`、`federated_mean` 等内建函数的部分可被根 TEE 委托给工作 TEE 并行执行。
- **管道状态与恢复**：KMS 保存管道状态；明文结果释放必须原子性地同时更新管道状态。故障恢复仅允许从最近一次已释放结果对应的恢复信息继续，防止重放攻击导致的额外隐私泄露。
- **隐私-效用优化**：新系统先收集所有设备上传，再在服务器端运行 MF-DP-FTRL，可在运行时优化噪声乘数、BLT 矩阵和参与模式，使 `minSep` 最大化、`maxP` 最小化，从而改善隐私-效用曲线。

## 3. 实验设计

- **数据集/场景**：
  - 日语语言模型（设备覆盖对比）；
  - 英语语言模型（隐私-效用曲线对比）；
  - Gboard 打字解码器的线上 A/B 实验（NSS 首轮候选生成 + OTF 二轮重排序）。
- **Benchmark / 基线**：与旧版 FL 系统对比。旧系统在设备端计算梯度，服务器不可信，使用 Secure Aggregation（SecAgg）/ Willow 与分布式 DP，采用 DP-FTRL。
- **对比方法**：
  - 基线：DP-FTRL，设备每 144 小时可参与一次，噪声乘数固定为 7.38，训练 8616 轮/85 天；

- **A/B 测试**：每臂 350 万设备，评估打字速度（Words Per Minute）和修改率（Words Modified Ratio）等可用性指标。

## 6. 主要结论与发现

- **设备覆盖提升**：基线在 38 天 / 3000 轮中仅纳入 850 万 / 3550 万可用设备（23.9%）；TEE 系统约 6 天收集 1780 万上传，全部被纳入训练，参与无偏。
- **隐私-效用曲线内移**：在相同 zCDP=0.232 下，TEE 系统噪声乘数为 5.16，而基线需 9.54；`maxP` 从 8 降至 3，`minSep` 从 561 升至 1822。
- **线上 A/B 测试**：TEE 模型以 **3 倍更小的隐私预算**（zCDP=0.215 vs 0.641）达到与生产模型相当的可用性指标，训练速度**快 3 倍**（3 周 vs 2 个月）。
- **可验证性**：首次实现可外部验证的中心化 DP 保证，访问策略与二进制哈希公开于透明度日志，第三方审计者可检查程序如何建立 DP 保证。

## 7. 优点

- **可验证性突破**：首次提供可外部验证的中心化 DP 保证，结合公开透明度日志与远程证明，显著提升 FL 的透明度与可审计性。
- **隐私-效用双赢**：两阶段设计将数据收集与训练解耦，使参与调度可针对 DP 算法优化，不受设备实时可用性影响。
- **工程落地**：系统已产品化并部署于 Gboard，具有真实生产验证。
- **灵活的程序 API**：支持任意 Python 工作负载、动态参数加载、专有每用户处理逻辑、自动化故障恢复，且不损害隐私保证。
- **恢复机制设计严谨**：通过原子性管道状态更新和加密恢复信息，防止重放攻击导致额外隐私泄露。

## 8. 不足与局限

- **TEE 自身安全限制**：当前 TEE 存在已知侧信道等安全局限，可能影响实际保证强度（作者引用 Zhang et al., 2026）。
- **信息泄露面**：管道操作者可观察到哪些上传被用于每轮训练（虽看不到内容），若加以混淆可进一步获得采样隐私放大收益，但当前未实现。
- **超参数探索不足**：每个模型仅测试一种配置，最优轮数/队列大小仍是开放问题；作者建议未来由程序自身实现早停与动态选择。
- **规模限制**：目前仅支持最多 1000 万参数模型，扩展到更大模型需 GPU 支持与通信优化。
- **TTL 权衡**：解密密钥的 TTL 限制要求系统在等待更多设备上传与保证训练时间之间做平衡。
- **应用限制**：尚未覆盖合成数据生成、推理等更多用例；与早期工作（Cheu et al., 2025）的管道混合运行仍处于探索阶段。
