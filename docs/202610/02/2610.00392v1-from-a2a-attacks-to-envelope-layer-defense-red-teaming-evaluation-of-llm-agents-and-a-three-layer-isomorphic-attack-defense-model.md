## 摘要
智能体交互协议（如ACP和A2A）推动基于LLM的智能体走向多智能体协作，同时引入了新的安全威胁。通过A2A由远程对等方发送的任务会被视为合法请求，这为间接提示注入提供了天然通道。现有智能体安全评估大多依赖单一指标——攻击成功率（ASR），无法区分攻击失败是因为LLM识别出了恶意内容，还是因为智能体层的机制阻止了执行。为解决这一问题，我们提出A2A-TIBA，一种将间接提示注入与绕过规避相结合的攻击原理。通过植入—命令—外泄步骤，它诱导目标智能体部署回调交互程序，随后攻击者绕过智能体下发命令。为更细粒度地评估防御，我们设计GDA Measurement，一种红队测试床方法，利用通过LLM网关的原始上下文捕获、双重数据保存和基于智能体的自主评判。我们提出四类攻击结果Class A/B/C/D，将ASR扩展为语义拒绝率、语义突破率、拦截率和渗透率。实验揭示包络层——恶意内容进入智能体的通道——是一个新的防御维度。据此，我们提出ELA-ITL，一个三层同构攻防模型，将防御分为包络封装、LLM识别和智能体拦截，将攻击分为植入通道、提示优化和执行机制。在15种智能体前端×LLM后端组合上进行测试，并构建1,000个案例的数据集，验证了A2A-TIBA的攻击有效性、GDA Measurement的评估有效性，并证实向A2A、工具和记忆等通道的包络封装中加入恶意提示标签，能显著提升LLM对恶意内容的识别。

## Abstract
Agent interaction protocols such as ACP and A2A have moved LLM-based agents toward multi-agent collaboration, introducing new security threats. A task sent by a remote peer over A2A is treated as a legitimate request, providing a natural channel for indirect prompt injection. Existing agent security evaluations mostly rely on a single metric, the attack success rate (ASR), and cannot distinguish whether an attack failed because the LLM recognized the malicious content or because a mechanism at the agent layer blocked execution. To address this, we propose A2A-TIBA, an attack principle combining indirect prompt injection with bypass circumvention. Through implant-command-exfiltration steps, it induces the target agent to deploy a callback interaction program, after which the attacker issues commands bypassing the agent. To evaluate defenses finer, we design GDA Measurement, a red-team testbed method using raw context capture via an LLM gateway, dual data preservation, and agent-based autonomous judging. We propose four attack outcomes, Class A/B/C/D, extending ASR into semantic refusal rate, semantic breach rate, interception rate, and penetration rate. Experiments reveal the envelope layer -- the channel through which malicious content enters an agent -- as a new defense dimension. We accordingly propose ELA-ITL, a three-layer isomorphic attack-defense model, dividing defense into envelope packaging, LLM recognition, and agent interception, and attack into implant channel, prompt optimization, and execution mechanism. Testing on 15 agent front-end x LLM back-end combinations and building a 1,000-case dataset verifies the attack effectiveness of A2A-TIBA, the evaluation validity of GDA Measurement, and confirms that adding malicious prompt labels to envelope packaging such as A2A, tool, and memory channels significantly improves LLM recognition of malicious content.

## 1. 核心问题与整体含义

### 研究动机与背景

- **协议演进带来的新风险面**：ACP（Agent Communication Protocol）与 A2A（Agent-to-Agent）等智能体交互协议推动 LLM 智能体从单智能体运行走向多智能体协作，显著提升了能力上限，但也引入了单智能体场景下不存在的新攻击面。
- **A2A 信任模型的根本缺陷**：在 A2A 协议下，一个智能体可以以"远程对等方"身份向另一个智能体发送任务请求，接收方会将其视为**合法请求**。这为**间接提示注入**（indirect prompt injection）提供了天然的攻击通道。A2A 入站凭证的实际语义仅为"向目标智能体上下文写入任意内容"，但一旦内容进入上下文，行动主体就从攻击者变为了目标智能体本身，其权限上限可达主机级。
- **现有评估的粒度缺陷**：当前智能体安全评估大多依赖单一指标 **ASR（攻击成功率）**，无法区分攻击失败究竟是因为"LLM 识别出了恶意内容"（语义层防御生效），还是因为"智能体层机制拦截了执行"（执行层防御生效）。这种测量粒度的缺失使得不同防御层的实际效果难以刻画，导致智能体防御优化信息不完整。
- **整体含义**：论文提出了一种新的攻击原理 **A2A-TIBA** 和一种更细粒度的红队评估方法 **GDA Measurement**，并在此基础上发现并系统化了**包络层（Envelope Layer）**这一新的防御维度，最终归纳出**三层同构攻防模型 ELA-ITL**。

## 2. 方法论

### 2.1 威胁模型（Threat Model）

- **核心假设**：攻击者已能通过 A2A 端点认证并向目标智能体投递任务，但不掌握目标系统提示、内部策略配置、后端 LLM 参数或主机文件系统（灰盒攻击者）。
- **权限边界**：A2A 入站凭证仅授予"写入内容到目标智能体上下文"的权限，而非"调用目标工具"或"在目标主机执行"的权限。攻击者权限上限止于"投递内容"，而智能体行为权限上限是主机级，二者之间的鸿沟能否被跨越取决于目标智能体自身的安全策略。
- **权限分级现状**：A2A 规范将认证授权委托给 HTTP 层标准，`securitySchemes` 仅支持 apiKey、http、oauth2、openIdConnect 四类，对"按技能授权"仅为 SHOULD 级建议，且 Task 与 Skill 在协议层无绑定关系。实验采用"已认证但未分级"或"广范围凭证"的场景，反映风险上界。

### 2.2 攻击原理：A2A-TIBA（A2A Tri-surface Implant-Bypass Attack）

将**间接提示注入**与**绕过规避（bypass circumvention）**相结合，通过三步攻击链实现：

1. **植入（Implant）**：攻击者利用入站凭证建立正常 A2A 通信链路，通过间接提示注入诱导目标智能体在其主机上部署并运行常驻回调交互程序。
2. **命令（Command）**：交互程序部署完成后，攻击者**不再经过智能体**，直接向程序下发恶意命令，攻击目标主机并窃取敏感信息。
3. **外泄（Exfiltration）**：植入的交互程序**直接**将敏感信息返回给攻击者，不经过智能体，使智能体自身的防御机制完全失效。

**关键设计思想**：植入提示中不包含其他恶意攻击内容，降低了被识别的风险；目标智能体**只有一次防御机会**——拒绝部署交互程序，一旦该防线被突破，后续攻击将完全绕过智能体。

### 2.3 三个关键注入点（表 1）

| 注入点 | 位置 | 绕过的环节 | 对应攻击步骤 |
|---|---|---|---|
| 上下文注入 | A2A 任务作为合法请求写入上下文 | 无（唯一入口） | 植入 |
| 行动触发 | 智能体以自身权限执行工具/命令/文件操作 | 调用者权限上限；行动主体变为目标智能体 | 植入 |
| 结果外泄 | 智能体出口与回调面 | LLM 识别与智能体拦截 | 命令、外泄 |

### 2.4 评估方法：GDA Measurement

由三个组件构成：

1. **基于 LLM 网关的原始上下文捕获**：目标智能体通过 LLM 网关与后端 LLM 通信，捕获程序部署在网关处，同步转发所有原始上下文数据。
2. **双重数据保存**：每次攻击后保存两组数据——攻击交互过程中的对话内容，以及网关捕获的原始上下文。
3. **基于智能体的自主评判**：由专门选定的智能体自主分析判定，且每次必须独立判定两次，两次一致则采信；不一致或"无法判定"时由人工兜底。

### 2.5 四类攻击结果指标（Class A/B/C/D）

- **Class A**：恶意内容完全未被执行（LLM 识别并明确拒绝）→ **语义拒绝率** = A 占比
- **Class B**：恶意内容被部分执行后终止，智能体层策略未介入
- **Class C**：恶意内容被完整执行但被智能体层机制拦截 → **拦截率** = C 占比
- **Class D**：攻击目标达成，敏感信息被窃取 → **渗透率** = D 占比（等价于 ASR）

派生指标：**语义突破率** = (B+C+D) 占比。

### 2.6 评判智能体选择：IAA 方法

采用 **Cohen's kappa 系数**：

$$\kappa = \frac{p_o - p_e}{1 - p_e}$$

其中 $p_o = \frac{1}{N}\sum_{i=1}^{K} n_{ii}$ 为观察一致率，$p_e = \frac{1}{N^2}\sum_{k \in K} n_{k1} \cdot n_{k2}$ 为期望一致率（K=4）。此外还单独计算了仅含 Class A 与 Class D 的 kappa 系数（因 B/C 边界模糊易混淆，而 D 最重要）。

### 2.7 三层同构攻防模型 ELA-ITL

| 层次 | 防御维度 | 攻击维度 |
|---|---|---|
| 包络层 | 包络封装（溯源标记、不可信内容标注） | 植入通道选择（包络伪造、间接注入入口） |
| LLM 层 | LLM 识别（语义审计、恶意意图检测） | 提示优化（语义越狱、意图伪装） |
| 智能体层 | 智能体拦截（工具白名单、运行时拦截） | 执行机制优化（工具调用、持久化驻留） |

**核心观点**：三层不可分割，只有三层同时被突破/防御，才构成对智能体的一次真正攻防。
