## 摘要
使用工具的大语言模型（LLM）智能体会将生成的文本转化为真实的副作用，因此被投毒的工具元数据、检索页面、记忆和可复用技能都可能操纵下一次调用。在准入前对制品进行审查并不能解决这一问题：一个安全变体和一个泄露变体可能产生相同的准入证据，此时一个可靠的准入闸门无法为二者中的任何一个放宽该位置。我们将这一条件精确化，从而留下部署仍可施加干预的最后边界。我们提出溯源感知能力强制执行（PACE），它在每次工具调用即将执行前对其进行中介裁决。路径约束提出对已表示的影响路径的可执行割集，而能力与效果验证则依据从经过认证的请求编译得到的权限，检查模式所定义的效果。我们区分经认证的执行契约与经评估的配置，后者可以在提议阻断后恢复一次经授权的调用，或应用一项已声明的修复。约束要求最终动作保持经认证的割集不变。在八个可执行的智能体安全基准（涵盖三个目标模型系列）上，经评估的配置在79个符合条件的攻击列中有62个取得严格最低的攻击成功率，另有14个持平；在全基准上，其原生效用相对于无防御智能体最多下降三点。对1167个配对案例的完整消融表明，大部分安全增益归因于效果验证，而拒绝控制则归因于边界自适应。在面对该防御时，缩小规模的自适应搜索在30个越权目标上的成功数为0/30。

## Abstract
Tool-using large language model (LLM) agents turn generated text into real side effects, so poisoned tool metadata, retrieved pages, memory, and reusable skills can steer the next call. Vetting an artifact before admission does not settle this. A safe variant and a leaking variant can produce the same admission evidence, and a sound gate then cannot relax that site for either. We make that condition precise, which leaves the last boundary a deployment can still act on. We present Provenance-Aware Capability Enforcement (PACE), which mediates every tool call immediately before it executes. Path confinement proposes an executable cut of represented influence paths, while capability and effect verification checks schema-defined effects against authority compiled from the authenticated request. We distinguish the certified execution contract from the evaluated configuration, which can restore an authorized call after a proposed block or apply a declared repair. Confinement requires the final action to preserve the certified cut. On eight executable agent-security benchmarks with three target-model families, the evaluated configuration gives strictly lowest attack success in 62 of 79 eligible attack columns and ties in 14; full-benchmark native utility loses at most three points relative to the undefended agent. A complete ablation over 1167 paired cases attributes most security gains to effect verification and refusal control to boundary adaptation. A reduced-scale adaptive search succeeds on 0/30 out-of-authority targets against the defense.

- **结论性定位**：安全相关的对象不是制品 K，而是其行为族 Beh(K)={μ_{K,c}}，任何对 K 的审计都无法枚举。于是把决策下移到**工具执行前的最后一个可干预边界**——此处同时具备：具体提案、已认证请求、运行时溯源、以及仍能改变结果的 hook。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 总体框架：四阶段中介（每次工具调用）

- **Phase I — PROPOSE**：冻结调用（以值或版本化资源句柄快照每个参数，新 attempt id q_t）；将参数与活跃值溯源映射 ν 匹配，命中则复用节点、未命中则新建数据节点；发出提案边并建新终止节点 T(q_t)；把冻结调用按效果 schema 展开为 **effect atoms**（操作、目标资源、持久化类别、决定它的参数槽）；从**可信请求通道**独立编译能力（purpose、resource、arguments、budget、expiry、delegation depth），模型生成文本无法铸造或扩宽能力。
- **Phase II — CUT & CERTIFY**：对冻结材料跑两条链。
  - **路径链**：源集 P_t（受保护标签：secret/个人数据/凭证/源码）+ 派生检查（对有限确定性重编码族 Ψ 的 match(y,x) 匹配，把匹配参数加入 P_t，作为标签而非边）；不可信前沿 B_t（未信源活跃值在已提交流边上的闭包）；不安全终止 U_t={T(q_t)}∩T_bad。绑定 β_t(e)=argmin_{a∈Sev(e)∩Impl(e)} cost(a,e)，无交集则为 ⊥。容量 κ(e) 仅在当前提案边有限；用最大流/最小割求**规范最小割 C_t**（先最便宜、再字典序最小）。**闭式解（Prop. D.2）**：κ(C_t)=min{κ({e_T}), κ(A⋆)}，其中 A⋆ 是源可达参数边集合——即"阻断调用"与"切断活跃参数边"的二选一，一次可达性遍历线性时间即可确定。
  - **效果链**：九项义务（授权覆盖、类型绑定、操作与主体控制、机密性、持久性、委托衰减、预算、新鲜度、hook 可用性）。
  - **决策规则 R1–R6**：R1 schema 未定义→拒；R2 低影响放行（仅 PACE-P）；R3 已认证 ∧ 无影响 ∧ 效果通过→放行（仅 PACE-P）；R4 原始效果未通过→拒；R5 无有限割或清单不可受理→拒；R6 非阻断清单但最终效果未通过→拒；否则按清单执行。
  - **证书（proof-carrying 风格）**：路径证书 cert_t=(q_t, L^p_t, σ_t, ε_t, B_t∪P_t, U_t, C_t, M_t)，验证器**重算**分离性与每个绑定（十项条件）；效果证书由确定性验证器重跑九项义务。生成器求割、验证器验割，故只声称"可重算的分离性与可执行性"，不声称最优性。
- **Phase III — ENFORCE**：在执行前消费合并决策。三类抑制动作（block、refuse、dry-run）、四类约束动作（只读视图、参数重写、受中介边界净化、预算上限）、一类 allow。切断契约只允许命名这些动作，故 PACE 属**编辑自动机**（edit automaton）而非截断自动机。
- **Phase IV — FINALIZE**：记录 ToolEvent（是否执行、解析资源、可观察输出、制品/网络效果、执行器模式、guard 理由），更新图、溯源映射与污点状态；返回值首次出现在 t+1 步，绝不进入自身证书。

### 2.2 两种配置的区分（关键设计取舍）

- **PACE-C（认证契约）**：禁用 R2/R3 与恢复；安装动作必须保持割，且最终调用（重写后 a′_t）必须通过 R6 复核。
- **PACE-P（评估配置）**：R3 要求九项义务全通过，R2 可释放低影响调用；组合器可在 P 阻断后由 C 恢复原调用，或应用注册表声明的修复且不重跑 R6。**实验全部评估 PACE-P**。

### 2.3 形式化保证

- **Prop. 1**：(a) 已表示路径分离性（移除 C_t 后 U_t 从 B_t∪P_t 不可达）；(b) 已授权效果可靠性（需能力仅由认证请求签发、schema 与槽位溯源覆盖具体效果、验证器/解密器守约、所需 hook 全部施加）。
- **Theorem 2（条件性落地执行）**：在 H1–H5 与透明链覆盖/模拟前提下，从注册保护源到待决不安全效果的真实因果链 γ 无法在本次调用完成。Corollary D.1 给出完整性版本；Corollary D.2 给出 PACE-C 的 episode 不变式。
- **Prop. 2**：透明片段（类型化句柄、主机管理值、pass-through 链、主机版本化资源）中的链被发射与模拟；模型重组字符串、未暴露效果、工具内部二次调用、绕过版本化适配器的写入均被排除。
- **部署加固 A1–A9**：append-only MAC 链、一次性 token（MAC_{k′} 绑定 q_t, n_t, σ_t, ε_t, h(L^p_t), h(M_t)）、全局 reservation、写前持久化与崩溃调和。作者明确指出**这部分不属于所评估的制品**。
