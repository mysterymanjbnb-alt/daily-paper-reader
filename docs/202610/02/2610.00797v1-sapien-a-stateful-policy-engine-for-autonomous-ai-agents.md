## 摘要
上下文安全防御通过合成任务特定策略并将其强制执行于智能体的工具调用，防止AI智能体采取越轨行动。然而，在多步任务中，哪些动作有效通常取决于智能体已经执行和学到的内容。我们提出Sapien，一种用于强制执行有状态上下文策略的策略引擎。Sapien策略使用扩展了有状态谓词、延迟策略生成和作用域语义检查的正则表达式来指定允许的工具调用序列。我们表明，Sapien与无约束智能体的效用相差仅几个百分点。即使智能体被完全劫持，Sapien的策略也能在AgentDojo上排除93-95%的攻击，在Toolathlon上排除62-85%的攻击（在长时程任务中，这一比例是工具允许列表的两倍）。

## Abstract
Contextual security defenses prevent AI agents from taking rogue actions by synthesizing a task-specific policy and enforcing it on the agent's tool calls. In multi-step tasks, however, which actions are valid often depends on what the agent has already done and learned. We present Sapien, a policy engine for enforcing stateful contextual policies. A Sapien policy specifies permitted tool-call sequences using a regular expression extended with stateful predicates, deferred policy generation, and scoped semantic checks. We show that Sapien stays within a few percent of an unconstrained agent's utility. Even if the agent is fully hijacked, Sapien's policies rule out 93-95% of attacks on AgentDojo and 62-85% on Toolathlon (twice as many as tool allowlists on long-horizon tasks).

## 1. 核心问题与研究动机

- **背景**：AI 智能体借助 LLM 自主规划并调用外部工具完成自然语言任务，正从单一用途工具演化为可处理跨领域开放任务的通用型个人助手（如 Muse、Gemini Spark、OpenClaw 等）。
- **核心风险（越轨行为，rogue actions）**：将工具调用权交给 LLM 使智能体本质上不可靠，可能：
  - 被工具输出中的**提示注入（Prompt Injection）**劫持，偏离用户意图；
  - 在长时程任务中**自发漂移**、误读工具输出或即兴采取意外绕行手段。
  - 现实中已发生清空收件箱、删除生产数据库、执行攻击者指令等事故。
- **传统防御的失效**：经典引用监控器（reference monitor）依赖**静态策略**，但通用智能体的动作正当性取决于具体任务（例如 `send_money` 在“退款”任务中合法，在“总结收件箱”任务中即为越轨）。
- **本文立场**：采纳**上下文智能体安全（Contextual Agent Security）**框架——为每个请求即时合成任务专属策略并在工具调用上强制执行。但更关键的是，论文主张仅靠无状态策略仍不够：
  - **有状态性必要**：下一步动作是否合法，往往取决于智能体**已执行的动作**和**已观察到的数据**（如必须先读取交易历史，才能确定退款对象与金额）。
  - 策略语言的表达能力直接决定了策略的“紧致度”（tightness），进而决定可拦截的越轨行为范围。
- **整体含义**：Sapien 提出一种有状态策略语言与运行时引擎，在几乎不损失效用的前提下，为通用智能体提供强安全边界，即使智能体被完全劫持也能阻断绝大部分攻击。

## 2. 方法论

### 2.1 核心思想

- Sapien 在两阶段运行：
  1. **事前策略生成**：仅读取用户任务提示与工具文档，由生成器 LLM 合成任务专属策略（与不可信运行时数据隔离，保证“策略完整性不变量”）。
  2. **运行时强制执行**：作为引用监控器拦截每次工具调用，允许则执行并记录结果，拒绝则返回诊断反馈供智能体自我纠正（不将负担转嫁给用户）。

### 2.2 有状态策略语言（4 个原语）

- **正则算子（顺序、选择、重复）**：如 `read_inbox . send_email` 强制先读后发；引入 **shuffle（‖）** 表达独立子任务的任意交错，避免用 choice 表达时的组合爆炸。
- **变量绑定与谓词**：
  - `call@x` 将调用参数与返回值绑定到变量 `x`；
  - 参数可匹配字面量或 `PREDICATE(p)`（Python 函数），对运行时具体值求值；
  - 例：`list_invoices@invoices . pay_invoice(vendor="Acme", amount=PREDICATE(matches_invoice))`，同时阻断“未读先付”“付错供应商”“伪造金额”三类失败。
  - 迭代绑定（如 `(read_email@emails)*`）按执行顺序累积记录列表，谓词可对实际观察到的数据做校验。
- **延迟策略生成（defer）**：
  - 形如 `get_page(...)@todo . defer(gen_todo)`，在策略中留“洞”，待智能体获取指定来源后，由生成器函数 `g` 基于已绑定变量构造子任务指令，调用策略生成器并将子策略拼接进洞。
  - 语义上：用户把子任务规格“委托”给外部来源，相当于把该来源内容视作任务提示的一部分，从而在不违背策略完整性不变量前提下避免授予笼统权限。
- **语义谓词**：
  - 对无法用代码判定的自然语言性质（如“邮件是否忠实总结了文档”），谓词可调用 `verify_with_ai` 向 LLM 裁判提出**局部、有作用域**的是/否问题。
  - 与“整体审查智能体行为”的 LLM 裁判不同：检查范围窄、仅接收判定所需输入，且只能**进一步收紧**策略，周围确定性约束仍严格生效。

### 2.3 强制执行引擎（算法流程）

- **编译**：按 Thompson 构造法将策略 AST 翻译为 NFA；复合算子用 ε-转移连接，shuffle 取两个操作数状态集的笛卡尔积。
- **配置跟踪**：与传统 NFA 不同，Sapien 维护**活跃配置集合 `(q, ρ)`**（自动机状态 + 变量赋值），因为到达同一状态但绑定不同的路径允许不同的后续动作。
- **检查与推进**：
  - `init(u)`：生成并安装策略；
  - `can_advance(a, p)`：检查是否存在活跃配置（经 ε-闭包后）可接受工具 `a` 且参数约束在 `ρ` 下成立，不成立则拒绝并给出原因；
  - `advance(r)`：允许的调用返回后，推进所有匹配配置、扩展绑定、丢弃不匹配配置。
- **defer 解析**：洞编译为解析工具的单条转移；每个匹配配置在自身赋值下求值 `g()`、调用生成器、编译子自动机，进入子自动机后从洞后状态继续，不同绑定互不干扰。
- **原型实现**：Python 库，集成 Google ADK 与 AgentDojo/Toolathlon 评测框架；所有模型调用经 Gemini Enterprise Agent Platform。
  - 策略生成用两次 LLM 调用（草稿 + 自查修正）；
  - 谓词/生成器在自定义 globals 字典中一次性 `exec`，调用时按配置填充绑定、调用后清除；
  - 原型对洞展开采用简化的 AST 级替换并重放调用轨迹（要求每个洞最多解析一次、各配置生成相同指令）。

### 2.4 威胁模型与边界

- 假设智能体 LLM 可被完全攻陷（提示注入、记忆污染、权重篡改）；生成器 LLM 未被攻陷且输入不含恶意数据。
- 假设用户会话、工具行为、harness 与拦截不可绕过。
- **非目标**：不审查用户提示本身的善恶；不解决用户表述错误或含糊提示；不保证活性（不阻止被劫持后“罢工”）；不防侧信道信息泄露。

  - **Sapien**：本文方法。
- **模型**：Gemini 3.8 Flash、Gemini 3.1 Pro、Claude Sonnet 5、Claude Opus 5；同一任务中智能体执行与策略生成使用相同模型。

  - **效率**：智能体推理次数、墙钟延迟、策略生成与检查开销。
