## 摘要
间接提示注入将恶意指令嵌入由基于LLM的智能体检索的外部内容中，在未经用户授权的情况下改变目标行为。我们介绍了 pikit，一个研究工具包，旨在从三个核心维度系统评估这些威胁：攻击（13种方法）、通道（跨文本和文件模式的16种载体）以及防御（9种预防策略和3种离线检测基线）。pikit 基于装饰器注册机制构建，无需修改核心代码即可无缝扩展自定义组件，同时统一的 craft() API 可在单次调用中组合任意攻击和通道。我们在一个类生产环境中，由匿名化 LLM 驱动的 pi 编码智能体上评估了该工具包。对9种预防策略针对高风险攻击进行基准测试，攻击成功率相对降低了71.8%，其中 few_shot_warning 和 instruction_hierarchy 提供最强保护。离线检测基线实现了完美的精确率但召回率较低，表明启发式检测器是对提示级防御的补充而非替代。为确保可复现性，每次运行都会自动记录完整提示、智能体事件轨迹、会话记录和判定记录。我们的代码见 https://github.com/Tencent/AI-Infra-Guard/tree/main/Research/pikit。

## Abstract
Indirect prompt injection embeds malicious instructions within external content retrieved by LLM-based agents, altering target behavior without user authorization. We introduce pikit, a research toolkit designed to systematically evaluate these threats across three core dimensions: attacks (13 methods), channels (16 carriers across text and file modes), and defenses (9 prevention strategies and 3 offline detection baselines). Built on a decorator-based registry, pikit enables seamless extension of custom components without modifying core code, while a unified craft() API composes arbitrary attacks and channels in a single call. We evaluated the toolkit on the pi coding agent powered by an anonymized LLM in a production-like environment. Benchmarking 9 prevention strategies against high-risk attacks yields a 71.8\% relative reduction in attack success rate, with few\_shot\_warning and instruction\_hierarchy providing the strongest protection. Offline detection baselines achieve perfect precision but low recall, demonstrating that heuristic detectors complement rather than replace prompt-level defenses. To ensure reproducibility, each run automatically logs full prompts, agent event traces, session transcripts, and verdict records. Our code is available at https://github.com/Tencent/AI-Infra-Guard/tree/main/Research/pikit.

## 1. 核心问题与整体含义

- **核心问题**：间接提示注入（Indirect Prompt Injection）将恶意指令嵌入 LLM 智能体在常规执行中检索到的外部内容（网页、文档、邮件、日志、代码仓库等），使智能体在未经用户授权的情况下改变行为。
- **与直接提示注入的区别**：直接注入依赖用户或攻击者显式向模型输入恶意提示；间接注入则利用智能体自动检索、读取和消费外部不可信内容的流水线，攻击者只需污染外部环境。
- **风险背景**：
  - 在“致命三要素”条件下尤其严重：智能体同时访问不可信数据、敏感上下文和外部通信通道。
  - 真实事件如 EchoLeak（CVE-2025-32711）展示了对 Microsoft 365 Copilot 的零点击攻击，可绕过内部提示注入分类器并非授权外泄文件。
  - 针对智能编码助手的研究报告称，通过被污染仓库实现任意命令执行的成功率可高达 84%。
  - DeepSeek harness、pi、OpenClaw 等现代编码/工具使用框架正好处于该威胁模型内：它们处理不可信仓库，同时拥有系统、文件系统和网络权限。
- **现有评估工具不足**：AgentDojo、InjecAgent 等提供静态基准，但缺乏可组合框架，无法让研究者独立变化攻击措辞、投递载体和防御策略。现实安全效果取决于载荷设计、传输机制和目标系统防御控制之间的复杂交互。
- **pikit 的整体含义**：论文提出 pikit，一个面向间接提示注入研究与评估的可组合开源工具包。它将攻击生命周期解耦为攻击、通道、防御三个独立轴，并支持统一组合、自动化矩阵评估和可复现审计，目标是为 LLM 智能体安全研究提供系统化实验基础设施。

## 2. 方法论

- **核心思想**：将间接提示注入评估流程形式化为：
  - **Task → Attack → Channel → Defense → Agent → Judge**
  - 其中 Attack 控制载荷措辞，Channel 控制污染载体，Defense 是包裹在智能体前的安全机制，Judge 对执行轨迹进行分类。
- **三个核心抽象**：
  - **Attack**：修改注入指令的措辞或结构，统一接口为 `inject(prompt, injected_task) -> str`，接收原始提示上下文和攻击者载荷，返回合成字符串。该字符串到字符串的抽象保证其与投递通道正交。
  - **Channel**：决定载荷如何封装进物理或虚拟载体，如网页、邮件、PDF 元数据、代码注释等。文本模式提供 `taint(data, payload) -> str`；文件模式提供 `taint_file(path, payload) -> output_path`，可生成 `.html`、`.eml`、`.pdf`、`.ics` 等真实文件，供下游智能体工具原生解析。
  - **Defense**：在模型推理前转换或加固提示，统一接口为 `apply(prompt, instruction=None) -> str`。可选 `instruction` 参数允许上下文防御重新强调用户可信意图，而不依赖脆弱的启发式提取。
- **装饰器注册与扩展性**：
  - pikit 使用基于装饰器的 Registry，将字符串键映射到动态组件。
  - 新增攻击、通道、防御或数据集无需修改核心引擎，只需用注册装饰器定义类。
  - 注册表强制键唯一，并动态绑定回退标识符，保证审计轨迹稳定。
- **统一合成 API：craft()**：
  - 作为合成直接和间接注入工件的主要入口，返回结构化 `CraftResult`。
  - 支持指定攻击、通道、数据等，并可选择 `mode="file"` 将载荷序列化为磁盘上的真实二进制载体，从而测试 PDF 元数据提取、电子表格单元格解析等真实文档摄取管线。
- **组合评估：MatrixRunner**：
  - 自动解析 TOML 定义的矩阵配置，执行笛卡尔积评估。
  - 对每个 `(attack, channel, defense, agent)` 组合，合成输入、驱动智能体执行、调用判定器并导出结构化遥测日志。
  - 载荷构造与投递解耦，使任意攻击可与任意通道配对，支持数千次运行而无需手工脚本。
