## 摘要
基于大语言模型（LLM）的智能体日益将模型生成的决策与安全敏感的软件能力连接起来，例如命令执行、文件系统访问、网络通信、浏览器控制以及外部工具。现有分析通常将预定义的敏感操作作为锚点，但仅凭操作身份不足以确定安全影响。我们提出 AgentSecGraph，一个安全感知的静态分析框架，它为每个安全敏感操作构建以候选为中心的安全感知智能体依赖图（Security-ADG）。该框架用智能体相关性、来源与依赖证据、信任边界上下文、防护证据以及外部效应语义来增强操作身份。我们进一步提出 AgentSecBench，一个包含 67 个真实世界 LLM 智能体代码库、跨越 11 个生态系统和 37,542 个源文件的语料库。当前分析器在 65 个代码库中识别出 23,866 个静态安全敏感操作候选，并为每个候选生成一个 Security-ADG 工件。全语料库分析为 9,821 个候选（41.15%）恢复了从来源到操作的依赖证据，并为 3,075 个候选（12.88%）恢复了潜在防护证据，耗时 50.8 分钟。使用一个单独的、由复现支持的评估层，我们在 13 个代码库中确定了 22 个安全敏感行为：一个已确认漏洞、一个待披露候选，以及 20 个受防护行为。在九个留出案例中，Security-ADG 保留了 91.1% 的参考上下文以及全部五个观测到的防护，相比之下，仅汇点视图为 20.0%，简化 ADG 为 40.0%。这些结果表明，安全感知的依赖与上下文证据能够实现仅凭敏感操作身份无法恢复的区分。

## Abstract
Large language model (LLM)-based agents increasingly connect model-generated decisions to security-sensitive software capabilities such as command execution, filesystem access, network communication, browser control, and external tools. Existing analyses often use predefined sensitive operations as anchors, but operation identity alone is insufficient to determine security implications.   We present AgentSecGraph, a security-aware static analysis framework that constructs a candidate-centered Security-Aware Agent Dependency Graph (Security-ADG) for each security-sensitive operation. It augments operation identity with agent relevance, source and dependency evidence, trust-boundary context, guard evidence, and external-effect semantics.   We further introduce AgentSecBench, a corpus of 67 real-world LLM-agent repositories spanning 11 ecosystems and 37,542 source files. The current analyzer identifies 23,866 static security-sensitive operation candidates across 65 repositories and emits one Security-ADG artifact per candidate. Corpus-wide analysis recovers source-to-operation dependency evidence for 9,821 candidates (41.15%) and potential guard evidence for 3,075 (12.88%), completing in 50.8 minutes.   Using a separate reproduction-backed evaluation layer, we establish 22 security-sensitive behaviors across 13 repositories: one confirmed vulnerability, one pending disclosure candidate, and 20 guarded behaviors. In nine held-out cases, Security-ADG preserves 91.1% of the reference context and all five observed guards, compared with 20.0% for a sink-only view and 40.0% for a simplified ADG. These results show that security-aware dependency and contextual evidence enable distinctions that cannot be recovered from sensitive-operation identity alone.

## 1. 核心问题与研究动机

- **背景**：基于 LLM 的智能体（LangChain、LangGraph、AutoGen、CrewAI、MCP 等）正从纯文本生成器演化为可规划、调用工具、维护状态、与外部环境交互的软件系统。模型输出不再停留于文本，而可能触发命令执行、文件读写、浏览器操作、数据库访问、远程服务调用等安全敏感能力。
- **核心问题**：现有安全分析（source–sink / taint 分析，如 TaintP2X、AgentFuzz、Agent Audit）多以**预定义敏感操作（sink）**为锚点，但**操作身份本身不足以判定安全含义**。同一个命令执行操作，可能直接受智能体输入影响、可能被常量覆盖而切断依赖、也可能受白名单等防护约束，三者在操作层面看起来完全相同。
- **关键论点**：作者提出必须区分三个层级：
  - 敏感操作候选（Sensitive Operation）
  - 安全关键行为（Security-Critical Behavior）
  - 漏洞（Vulnerability）
  
  即 `Sensitive Operation ≠ Security-Critical Behavior ≠ Vulnerability`。
- **研究问题**：如何通过静态分析，为真实 LLM 智能体程序中的敏感操作补充**智能体特有的依赖与安全上下文证据**？

## 2. 方法论：AgentSecGraph

### 核心思想
- 不把匹配到的敏感操作当作漏洞判定，而是作为**分析锚点**，为其构建**以候选为中心的安全感知智能体依赖图（Security-ADG）**。
- 分析流程分为三层：**Operation → Dependency → Security Context**。

### 关键表示与公式
- **安全上下文元组**（对每个候选操作 o）：
  `C(o) = ⟨R, S, D, T, P, G, E⟩`
  分别表示：智能体相关性 R、来源溯源 S、来源到操作依赖证据 D、信任边界证据 T、静态可得的权限上下文 P、候选防护证据 G、外部效应类别 E。
- **框架归一化记录**：
  `N = ⟨F, R_s, Y, P_s, Q⟩`
  即框架标识、语义角色、关联程序符号、暴露参数、匹配置信度。当前支持 MCP/FastMCP、LangChain、CrewAI、AutoGen、OpenAI Agents SDK、Semantic Kernel、LlamaIndex。
- **候选为中心的图**：
  `G_o = (V_o, E_o, Φ_o)`，节点包含智能体/程序符号、敏感操作、输入源、信任边界、防护候选、外部效应；边包含 `contains`、`may_cause`、`may_data_depend_on`、`may_cross`、`may_guard`。
- **不确定性设计**：所有关系均以 `may_*` 前缀标注，明确表示这些是**静态证据而非可达性/可利用性/防护充分性证明**。

### 依赖、边界与防护分析
- 从候选操作消费的值出发做**反向依赖恢复**，寻找 `s ⇝ v1 ⇝ … ⇝ vo → o` 的局部链。
- Python：基于 AST，跟踪局部参数、赋值、定义、重赋值；若智能体参数被常量覆盖，依赖链终止。
- TypeScript/JavaScript：基于语法感知的词法回溯，更保守，不做完整别名/类型/控制流推理。
- 防护证据：白名单、固定参数/参数向量构造、schema/语法校验、认证检查、路径限制、沙箱、资源限制等。
- 权限上下文仅在可从支持的源码构造中显式恢复时记录；外部效应类别由操作类别确定性映射。

## 3. 实验设计

### Benchmark / 数据集
- **AgentSecBench**：67 个冻结的真实 LLM 智能体仓库，跨 11 个生态，37,542 个源文件，291.2 MB 源码，均固定在记录好的 Git commit 上。
- 语言分布：51 个以 Python 为主（76.1%），7 个以 TypeScript 为主（10.4%），其余为 C#、Rust、Go、PHP、Shell。
- 候选分类：命令/进程执行、动态代码执行、文件系统访问、网络与远程访问、浏览器与桌面自动化、数据库操作、凭据/密钥访问、外部工具调用。

### 评估群体（三层区分）
- **冻结试点队列**：5 个仓库、531 个候选（保留用于历史兼容）。
- **当前五仓库扫描**：同 5 个快照下 508 个候选（仅用于记录扫描器版本漂移）。
- **当前全语料库运行**：67 个仓库、23,866 个候选，用于全语料库刻画与可扩展性测量。
- 强调：**候选数不等于漏洞数**。

### 对比方法 / 表示变体
- **Sink-only**：仅保留敏感操作。
- **Simplified ADG**：保留结构性操作与外部效应信息。
- **Full Security-ADG**：保留来源/依赖、信任边界、防护、外部效应证据。
- 三者从同一候选派生，差异反映表示本身丢失的信息。

### 评估层次
- 静态候选 → 复现确认行为 → 漏洞处置，三层严格分离。

## 6. 主要结论与发现

- 预定义敏感操作仍是**有效且可扩展的分析锚点**，但操作身份单独不足以做安全解释。
- Security-ADG 在留出研究中保留 **91.1%** 参考上下文和 **5/5** 观测防护；对比 sink-only 为 20.0%、0/5，simplified ADG 为 40.0%、0/5。
- 从 40.0% 到 91.1% 的提升说明：**结构性依赖信息本身不足以解释改进**，来源溯源、安全相关依赖、信任边界与防护证据贡献了额外上下文。
- 复现行为不等于漏洞：20/22 行为在评估条件下属受防护非漏洞。
- 全语料库证据分布不均：文件系统写入依赖证据 84.14%、读取 65.28%，而外部工具调用仅 11.28%、浏览器控制仅 1.87%；防护证据从文件删除 51.29% 到外部工具调用 1.37% 不等。
- 全语料库运行 50.8 分钟，支持语料库级离线分析，但大仓库有明显长尾延迟。

## 7. 优点

- **概念清晰**：明确区分敏感操作、安全关键行为与漏洞，避免把匹配当判定。
- **表示设计合理**：`may_*` 关系显式表达不确定性，避免过度声称可达性或可利用性。
- **以候选为中心**：不同于全程序依赖图，每个图只保留解释单个操作所需的证据，规模可控。
- **框架归一化层独立于图 schema**：新增框架无需重设计 Security-ADG，扩展性好。
- **真值构建严谨**：复现支持、冻结快照、拒绝模型判断作为真值，泄漏控制到位。
- **表示对比公平**：三种表示从同一候选派生，差异仅反映信息丢失。
- **可审计性**：保留源码位置、图、依赖路径，91.1% 聚合可追溯到案例级矩阵。
- **诚实的局限声明**：明确不声称召回率、不声称漏洞检测精度、不声称统计代表性。

## 8. 不足与局限

- **分析不完备**：Python 为局部 AST 分析，非全程序过程间、别名、指向或符号分析；TS/JS 更弱，无完整别名或控制流推理。反射、动态注册、元编程、部署相关暴露可能造成证据缺失或不精确。
- **权限上下文缺失**：本次全语料库提取**未恢复任何显式权限上下文证据**；不代表程序无权限，而是分析器无法从支持的源码构造中恢复。
- **聚合指标问题**：导出的语料库聚合中，来源、依赖、信任跨越三项计数完全相同（均 9,821），无法证明是三次独立恢复事件，因此作者只报告合并后的依赖证据度量，未独立验证信任边界恢复率。
- **外部效应 100% 覆盖是 schema 属性**，非运行时确认效应。
- **语料库代表性不足**：67 仓库、11 生态，非统计代表；Python 占主导，结果不是语言无关性能估计。
- **群体不可比**：531 试点队列与 23,866 全语料库群体来自不同扫描器版本，不能直接作规模缩放比较。
- **计时局限**：仅单次运行，无重复分布，无峰值内存，结论限于观测环境。
- **真值规模小**：22 个行为、9 个留出案例，不足以支持穷尽召回或通用漏洞检测声明；344 操作清单标注未完成，无法给出匹配计数。
- **五模型面板分诊可能引入选择偏差**：可能影响哪些案例更早获得人工关注，因此复现集不被视为无偏的语料库行为流行率估计。
- **安全披露限制**：与进行中协调披露相关的复现细节被有意保留，影响完全复现。
