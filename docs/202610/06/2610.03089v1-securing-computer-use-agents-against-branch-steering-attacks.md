## 摘要
现代计算机使用代理（CUA）直接与图形用户界面交互并执行第三方 Web 工具，这使它们暴露于每个渲染页面和工具响应中的间接提示注入风险。尽管双 LLM 模式是提供形式化安全保证的主要系统级架构——使用隔离的规划器 LLM（P-LLM）先固定执行路径，再通过隔离 LLM（Q-LLM）处理不可信输入——但这些保证在图形环境中失效。由于 CUA 交互本质上是动态的，规划无法保持数据无关性；它们必须根据预期的运行时 Web 内容进行分支——覆盖代理可能遇到的所有可能情况。这使代理暴露于分支引导攻击：攻击者构造不可信数据，在不注入显式指令的情况下，诱导 CUA 进入危险的、预先批准的分支。我们系统性地研究分支引导攻击，并提出 STEER-Bench（涵盖 9 个领域的 101 个任务），表明对标准 CUA（94.4%）和基础 Dual-LLM CUA（89.5%）均具有很高的攻击成功率。随后，我们提出 COBRA，一种将可信分支规划与事前能力约束相结合的架构，严格限制每个分支可执行的参数和目标位置。在 STEER-Bench 上，COBRA 将攻击成功率降至 0%，同时保持 97% 的良性效用。

## Abstract
Modern Computer Use Agents (CUAs) directly interact with graphical user interfaces and execute third-party web tools, exposing them to indirect prompt injection across every rendered page and tool response. While the Dual-LLM pattern is the primary system-level architecture offering formal security guarantees - using an isolated Planner LLM (P-LLM) to fix execution paths before processing untrusted inputs via a Quarantined LLM (Q-LLM) - these guarantees break down in graphical environments. Because CUA interaction is inherently dynamic, plans cannot remain data-independent; they must branch based on anticipated runtime web content - covering all possible cases the agent may encounter. This exposes agents to branch steering attacks, where an adversary crafts untrusted data to coerce a CUA down a hazardous, pre-approved branch without injecting explicit instructions. We systematically study branch steering attacks and introduce STEER-Bench (101 tasks across 9 domains), showing high attack success against both standard (94.4%) and vanilla Dual-LLM (89.5%) CUAs. We then propose COBRA, an architecture that pairs trusted branching plans with ahead-of-time capability constraints, strictly bounding the parameters and destinations each branch may execute. On STEER-Bench, COBRA reduces attack success to 0% while retaining 97% benign utility.

# 论文总结：《Securing Computer-Use Agents Against Branch Steering Attacks》

## 一、核心问题与整体含义（研究动机与背景）

- **背景**：现代计算机使用代理（CUA）直接操作 GUI（鼠标/键盘）并调用第三方网站通过 MCP 暴露的工具，形成 ReAct 式"观察—推理—行动"循环。这带来两个间接提示注入（IPI）面：①渲染的网页内容（广告、评论、消息、附件）；②MCP 接口（工具投毒、工具影子、审批后篡改/rug pull）。两通道可组合（页面文本可诱导工具调用，被投毒的工具返回可劫持 GUI 行为）。
- **现有防线及其失效点**：Dual-LLM 模式用特权规划器 P-LLM 从可信用户请求预先推导完整执行序列，再由隔离的 Q-LLM 处理不可信内容，从而提供**控制流完整性（CFI）**。但该保证在图形环境中失效：网页布局与状态在渲染前不可知，计划必须包含对预期运行时状态的**分支**，因而不再是数据无关的。
- **核心新威胁——分支引导攻击（Branch Steering）**：攻击者不注入任何新指令，只是构造不可信运行时数据，使其满足某个**已被预批准的**分支条件或绑定动作参数，从而把代理推向对攻击者有利的危险路径。作者将此归类为**数据流完整性（DFI）**失效：标准提示注入违反 CFI（引入计划外动作），分支引导违反 DFI（不引入新动作但操纵分支选择与关键参数）。
- **整体含义**：论文论证"仅靠 CFI 不足以保护 CUA"，必须同时强制 DFI；并指出 GUI 原语无内在语义（同一次点击可能是打开无害标签页，也可能是确认不可逆转账），使 DFI 在 CUA 中格外难以实施。

## 二、方法论：COBRA 架构

### 核心思想
在**观测任何不可信运行时数据之前**，把用户请求与已批准的站点/工具元数据编译成一份带**分支级能力约束**的可执行程序；运行时由确定性解释器执行，Q-VLM 仅提供视觉感知，所有外部副作用（HTTP 请求与 MCP 调用）在**网络边界**被确定性代理拦截与校验，从而同时实现 CFI 与 DFI。

### 关键组件与流程
- **规划与约束初始化（事前）**
  - P-LLM 从可信请求 + 已批准描述生成程序；解析出动作与分支结构。
  - 一次**可信标注调用**为每个分支指派允许的目的地、工具，以及对请求字段/工具参数的值约束（P-LLM 不接触本次运行的任何观测）。
  - 若某安全关键值既非用户提供、也无可信来源，COBRA 在**计划构建阶段**向用户询问，该值仅对该次请求可信。
- **执行与分支解析**
  - 确定性解释器执行固定程序；Q-VLM 可报告观测、提出低层步骤，但**不能改写程序**。
  - 每步感知声明期望输出类型（如数值价格、日期）；Q-VLM 必须按格式返回或报告"不可见"，格式错误重试，持续失败则报错而非猜测。
  - **Branch Resolution Hub（BRH）**：把已验证的计划变量代入分支约束，并与外层分支继承的约束合并；离开分支时恢复父状态，使权限**不跨分支残留**。缺失值、未解析占位符、类型不匹配一律**不能扩大权限**。
- **边界强制（DFI 落地）**
  - **HTTP 代理**（基于 ceLLMate 修改）：默认**主机级**强制（仅允许计划授权的域）；若有已批准 sitemap 则升级为**端点级**强制（校验方法、参数化 URL 路由、请求体字段谓词）。
  - **MCP 代理**：校验工具名、服务器与参数是否符合当前分支约束；并比对工具定义哈希以检测 rug pull、校验调用到达已批准服务器以阻止同名工具影子。
  - 所有审批（站点 sitemap、MCP 工具定义）以 **SHA-256 固定**，上游任何改动（含语义描述）都会使哈希失效并中止执行、要求重新审批。
- **MESA（辅助机制）**：爬取允许列表中的站点，生成候选 agent sitemap 与对应 MCP 工具，供服务方审核发布、用户再审批；用于评估 sitemap 可用性对安全与效用的影响。
- **Fused Planning（融合规划）**：从同一可信输入并行生成 5 份候选计划（分别偏重 MCP 优先、纯 GUI、常规菜单路径、先可行性检查、逐步验证），再由一次可信调用合并为一个保留备选路线与回退分支的程序；两阶段均不接触运行时观测。选择 5 份是效用与 token 成本的折中。

### 信任边界与设计取舍
- 强制点选在 HTTP/MCP 调用而非 GUI 动作，因为"一次点击本身并不能指明它触发的操作"。
- 设计上明确：不经过 HTTP 的 GUI 效果落在边界之外（见局限）。

## 三、实验设计

### 1）自建基准 STEER-Bench
- **规模**：9 个真实领域、101 个端到端任务；199 个攻击单元（cell）与 138 个良性单元；其中 74 个攻击单元 + 74 个无注入运行可在通用 CUA 上评估，其余涉及基线不具备的 MCP 交互与描述审批能力。
- **覆盖**：GUI 网页交互与 MCP 工具调用、4 种页面布局族；领域包括银行转账、仓储物流、临床剂量调整等。
- **评分口径**：当目标有害动作**违反当时生效的约束**时记为攻击成功（而非完成更长的多步攻击目标）。
- **九个子套件（针对组件做消融）**：
  - S1 WIRE（字段值约束，26）、S2 DEST（主机/端点约束，24）、S3 MCP（MCP 代理，15）、S4 Cross-channel（跨通道共享约束状态，72）
  - S5 PROV（可信值处理，33）、S6 TRUST（描述完整性，5）、S7 CFI（计划—执行边界，9）
  - S8 STEP（约束刷新/过期，10）、S9 ULTRA（四层嵌套分支下的约束组合，5）
- **设计特点**：每个攻击单元跑两遍——完整 COBRA 与**仅禁用被测组件**的版本，其余组件不变，以隔离各组件贡献；并报告"残余阻断"（禁用目标组件后仍被其他检查拦下的部分）。

### 2）外部基准验证（4 个已发表基准，共 1,312 次攻击）
- **OS-Harm**（51 例注入）：计划—执行分离即可全部阻断；另 21 例尝试未授权 HTTP 的用例用于测试无 sitemap 下的主机级 DFI（无代理 21/21 成功，有代理 21/21 阻断，合法操作不受影响）。
- **WASP**（21 例）：无 sitemap 时阻断 5 例跨域攻击但 14 例同主机未授权操作全部成功；有 GitLab/Reddit sitemap 时 19/19 请求级攻击全部阻断（ASR 从 73.7% 降至 0%），良性完成率 100%；剩余 2 例依赖自由文本语义，超出确定性请求级强制范围。
- **MCPTox**（1,223 例）：其中 1,210 例改变了所选工具或参数，COBRA 全部阻断（无强制时 ASR 100%）；剩余 13 例合法与恶意调用使用完全相同的工具与参数，仅服务器隐藏行为不同，代理无法区分。攻击下的效用 79%，损失主要来自计划生成质量而非代理误拦合法调用。
- **MCPSecBench**（17 例，9 例落入威胁模型）：全部阻断（5 例测试服务器绑定与哈希固定的工具定义，4 例测试参数约束），良性效用保持。
