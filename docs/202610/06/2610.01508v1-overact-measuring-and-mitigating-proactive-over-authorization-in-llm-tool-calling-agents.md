## 摘要
具备工具调用能力的LLM智能体可以访问外部服务和用户私有数据，但它们可能获取超出用户请求明确所需的信息。我们研究结构化工具调用智能体中的这一行为，并将其称为主动过度授权。该设定不同于文件系统层面的编码智能体，因为主要风险是对私有数据的不必要访问。我们提出OverAct，一个受控基准，涵盖八个隐私敏感领域，采用确定性、无需评判者的评分，并配有一个可解释的决策论框架，该框架给出三个可检验预测。在来自四个模型家族的七个模型中，所有模型都显著超出授权范围。请求具体性是严重程度的最强预测因子，过度授权随工具池规模呈亚线性增长，而解码温度几乎没有影响。这些模式与成本不对称解释一致，表明过度授权更多源于结构性决策倾向，而非解码随机性。我们还提出SelfAudit，一种零样本、推理时方法，它生成基于请求的理由，并在执行前过滤无正当理由的调用。消融表明，显式过滤是缩小范围的主要驱动因素。SelfAudit在没有预言机知识的情况下将隐私导向的过度访问减少了43%。

## Abstract
LLM agents with tool-calling capabilities can access external services and private user data, but they may retrieve more information than a user's request explicitly requires. We study this behavior in structured tool-calling agents and term it proactive over-authorization. This setting differs from filesystem-level coding agents because the main risk is unnecessary access to private data. We introduce OverAct, a controlled benchmark spanning eight privacy-sensitive domains with deterministic, judge-free scoring, together with an interpretive decision-theoretic framework that yields three testable predictions. Across seven models from four families, all models significantly exceed authorized scope. Request specificity is the strongest predictor of severity, over-authorization grows sublinearly with tool-pool size, and decoding temperature has little effect. These patterns are consistent with a cost-asymmetry account, suggesting that over-authorization arises more from structural decision tendencies than from decoding randomness. We also propose SelfAudit, a zero-shot inference-time method that generates request-grounded justifications and filters unjustified calls before execution. Ablation shows that explicit filtering is the main driver of scope reduction. SelfAudit reduces privacy-oriented excess by 43% without oracle knowledge.

## 1. 核心问题与整体含义（研究动机与背景）

- **现象定义**：具备工具调用能力的 LLM 智能体在响应用户请求时，可能调用超出用户字面请求所明确蕴含的工具，从而访问不必要的私有数据。作者将这一行为命名为 **主动过度授权（proactive over-authorization）**，定义为"智能体动作范围超出用户措辞明确蕴含的范围"。
- **典型示例**：用户说"查一下我的余额"，最小充分响应只需 `get_checking_balance`；但智能体可能额外调用交易记录、储蓄余额、卡信息等工具。医疗场景中"我下次预约是什么时候"可能触发用药清单、化验结果、诊断历史等检索，与数据最小化原则（GDPR 等）冲突。
- **与已有工作的区别**：
  - 现有智能体安全基准多聚焦灾难性/对抗性失败（越狱、提示注入、恶意滥用，如 AgentHarm、Agent-SafetyBench、ToolEmu、R-Judge）；
  - 工具调用基准（BFCL、GAIA、ToolTalk、AgentBench）主要衡量任务成功与工具使用正确性，**不惩罚超额检索范围**；
  - 与同期工作 OverEager-Gen（文件系统级编码智能体的越界行为）互补：本文聚焦**结构化 API 工具调用 + 私有数据访问**场景，风险核心是隐私而非系统破坏。
- **核心问题重述**：不是"智能体能否用对工具"，而是"当那些工具会暴露私有数据时，智能体能否避免调用貌似合理但并非必需的工具"。
- **三种范围概念的区分（重要前提）**：
  - **基准授权范围（benchmark-authorized scope）**：按字面保守解释，用户措辞所蕴含的工具集合（本文实证主张的锚点）；
  - **用户偏好范围（user-preferred scope）**：具体用户实际希望的范围；
  - **部署安全范围（deployment-safe scope）**：合规/生产策略允许的范围。
  - 作者明确声明：基准越界不等于用户不希望，也不等于部署有害。

## 2. 方法论：核心思想、技术细节与流程

### 2.1 OverAct 基准与授权范围定义

- 形式化：设请求 $R$、工具池 $T=\{t_1,\dots,t_n\}$、上下文 $C$，智能体选择执行集合 $A_{actual}\subseteq T$。
- **授权动作范围（AAS / 最小工具集）**：
  $$AAS(R,T,C)=\arg\min_{A\subseteq T}|A|\quad \text{s.t.}\quad S(A;R,C)=1$$
  其中 $S$ 表示工具集在当前上下文下是否充分。若存在多个等基数解，按**隐私优先**原则选择访问 PII 类别更少者。
- **超额集合**：$A_{excess}=A_{actual}\setminus A_{minimal}$。
- **判定准则**：严格字面解释（strict literal interpretation）——只有用户措辞直接蕴含的工具才算最小集；这是刻意保守的隐私优先准则。

### 2.2 决策论解释框架（可解释性抽象，非已验证因果机制）

- 对每个工具 $t_i$ 定义隐式相关性估计 $\theta_i=P(t_i\in A_{minimal}\mid R,C)$。
- 两类错误成本：**遗漏**成本 $c_-$（该调未调）、**误调**成本 $c_+$（不该调却调）。
  - 调用期望成本：$(1-\theta_i)c_+$；省略期望成本：$\theta_i c_-$。
  - 调用当且仅当 $\theta_i c_- > (1-\theta_i)c_+$，整理得阈值：
  $$\theta_i>\tau=\frac{c_+}{c_-+c_+}=\frac{1}{1+r},\quad r\triangleq c_-/c_+$$
- **核心直觉**：当遗漏成本被感知为远高于误调成本时（$r$ 大），有效纳入阈值 $\tau$ 变得极低，语义相邻但非必需的工具也容易被调用。
- **期望超额量**：$E[|A_{excess}|]=(n-k)\bar F_R(\tau)$，其中 $k=|A_{minimal}|$，$\bar F_R$ 为相关性分布生存函数；对阈值求导 $\partial E/\partial\tau=-(n-k)f_R(\tau)$，说明当大量工具处于中等相关性时，超额对阈值最敏感。
- **三个可检验预测（文中编号 P2–P4）**：
  - **P2 具体性—超额单调性**：请求越具体，期望超额越少（相关性集中于少数工具）；
  - **P3 有界饱和**：在相关性随排序缓慢衰减的情形下，超额随工具池规模**亚线性增长**（经验区间近似对数）；
  - **P4 温度不变性**：若阈值主要由模型参数而非采样随机性决定，则超额在不同解码温度下近似稳定。

### 2.3 评价指标（确定性、免评判者）

- **SIR（Scope Inflation Ratio）**：$|A_{actual}|/|A_{minimal}|$，倍数式范围膨胀；SIR=1 不代表完全合规（可能漏调必需工具而多调其他工具）。
- **TCR（Task Completion Rate）**：$|A_{actual}\cap A_{minimal}|/|A_{minimal}|$，实为最小工具集召回率代理，不校验参数正确性、执行成功或信息是否真正满足请求。
- **PVS（Privacy Violation Score）**：$\sum_{a\in A_{excess}}|\mathrm{PII}(a)|$，累加超额调用访问的 PII 类别数（重复类别重复计数），衡量隐私导向的累积越界严重度。
- 补充指标：精确集合匹配、归一化超额（SIR−1）、工具精确率/召回率（附录 B.3）。

### 2.4 SelfAudit：零样本推理时缓解方法

- **流程三步**：(1) 列出计划调用的工具及各自为何是用户明确请求所必需；(2) 指出请求中哪些具体词语为每个调用提供依据；(3) **移除任何无法由用户明确措辞论证的调用**，仅执行剩余工具。
- **消融设计**：Justify-Only（只生成理由不过滤）、Filter-Only（只过滤不生成结构化理由）、Full SelfAudit。
- **对照的五个提示级干预**：Permission List（需 oracle 的精确许可清单）、Explicit Scope、Minimization、Intent Echo、Clarification。
