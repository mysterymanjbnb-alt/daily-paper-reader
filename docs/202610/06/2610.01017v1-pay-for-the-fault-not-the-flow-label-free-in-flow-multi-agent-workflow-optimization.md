## 摘要
大语言模型（LLM）正越来越多地构建多智能体工作流：它们将复杂任务分解，并从智能体池中分派专家智能体。然而，构建一个良好的此类工作流仍具挑战性：任务应划分到多细、每个子任务应信任哪个智能体，以及何时创建新的专家智能体，都是工作流构建者需要预先确定的关键决策。因此，每个子任务是否成功，直到工作流运行之前都未可知。然而，改进工作流的代价高昂。定位故障通常需要参考答案、评分结果或训练好的评估器，而修复则要通过重新执行、重新搜索或重新训练施加于整个工作流。我们提出 InFlowOp，它以单一无标签代价为每个决策定价，该代价权衡智能体能力满足子任务需求的程度与该智能体运行的开销。在执行之前，InFlowOp 依据该代价而非固定模板，双向确定任务分解的粒度和智能体分配。在执行期间，InFlowOp 通过同一代价以最廉价的操作纠正故障，该代价在工作流构建与运行时均服务于工作流。面对工作流级评估的挑战，我们提出 Braid，一个其任务需要超出单智能体能力的多智能体协调的基准。在多个领域和骨干模型上，InFlowOp 相比单智能体基线最高提升 $+11.97\%$，并借助流内优化实现了 $+9.64\%$ 的提升。项目主页：https://xhguo7.github.io/InFlowOp/。

## Abstract
Large language models (LLMs) increasingly construct multi-agent workflows that decompose a complex task and assign specialist agents from a pool. However, building such a workflow well remains challenging: how finely to divide the task, which agent to trust with each subtask, and when to create a new specialist are all critical decisions a workflow constructor needs to settle up front. Thus, whether each subtask succeeds remains unknown until the workflow runs. Yet, improving a workflow is costly. Locating a fault usually requires a reference answer, a graded outcome, or a trained assessor, and the fix is applied to the whole workflow through re-execution, re-search, or retraining. We propose InFlowOp, which prices every decision in one label-free cost that weighs how well an agent's competence meets what a subtask demands against how much that agent takes to run. Before execution, InFlowOp bidirectionally determines the granularity of task decomposition and agent assignment following from the cost rather than from a fixed template. During execution, InFlowOp corrects a fault with the cheapest move via the same cost that serves the workflow both as it is built and as it runs. Facing the workflow-level evaluation challenge, we introduce Braid, a benchmark whose tasks require multi-agent coordination beyond single-agent capability. Across various domains and backbones, InFlowOp outperforms single agent baselines by up to $+11.97\%$, achieving $+9.64\%$ with in-flow optimization. Our project page: https://xhguo7.github.io/InFlowOp/.

## 一、核心问题与研究动机

- **背景**：LLM 已从单轮回答者演化为能规划、调用工具、彼此组织的智能体。给定任务与一个专家智能体池，工作流构建器（constructor）现在可自行划分工作、决定由哪个智能体承担哪一部分、以及以何种顺序执行。
- **三大前置决策的困难**：任务应划分到多细、每个子任务该信任哪个智能体、池中无合适者时是"勉强指派"还是"新建专家"——这些都必须**在执行前**确定，而每个子任务是否真正成功，只有运行后才知道。
- **改进工作流的代价高昂**：
  - 故障定位通常依赖参考答案、评分结果或训练好的评估器（assessor），而运行中前两者不存在、后者需要额外监督；
  - 无监督的方法只能**事后**优化：重放完整轨迹定位失败，或整体重跑/重搜索/重训练构建器；
  - 于是修复的计价单位是**整个工作流**而非**故障本身**，已经成功的步骤被重复付费。
- **评估层面的缺口**：现有多智能体基准的任务大多单个强智能体即可解决，无法体现"分工与协调"的贡献；甚至在某些任务上协调反而带来负收益与数倍成本。
- **论文含义**：提出用**单一无标签成本（label-free cost）**同时服务于"构建工作流"与"运行中纠错"，即**为故障付费，而非为整个流程付费**。

## 二、方法论

### 2.1 核心思想

- 把"构建可靠工作流"与"低成本优化工作流"两个问题统一为**最小化一个可测量、无需标注的代理目标——工作流成本 Cost(W)**，该成本把**可靠性（成功概率）**与**运行延迟**耦合在一起。
- **一个估计器、一个成本矩阵贯穿两个阶段**：构建时用 `match(demand, supply)` 给"子任务—智能体"配对定价；运行时用同一个 `match` 把"声明的契约条件"与"实际实现的输入/输出"比对，从而在无参考答案的情况下发现故障。
- **Agent Card**：每个智能体对估计器的唯一表征，包含（1）声明能力（角色、领域、技能与工具）；（2）自演化经验档案（哪些工作成功过、哪些失败过）。

### 2.2 阶段一：COALESCE——双向、分解感知的工作流构建

- **工作流定义**：W = ⟨S, A, G⟩，S 为子任务集合，A 为子任务到智能体的指派，G 为子任务依赖的有向无环图（DAG）；G 的**关键路径**决定工作流延迟。
- **成本矩阵**：C(τ, a) = −log p̂(τ, a)，p̂ = match(τ, a) ∈ [0,1]，由 rubric 语义估计器对"原子任务需求"与"智能体卡片"打分得到。矩阵行是原子、列是智能体。
- **覆盖残差与新建**：ρ(τ) = 1[ min_a C(τ,a) > C̄ ]，当池中无智能体越过能力门槛 C̄ 时触发新建智能体，并计入惩罚 γ；动态矩阵下新建智能体作为新列加入，可与所有原子重新匹配。
- **成本分类学**（统一计价）：
  - 可靠性成本 R(W) = Σ_i C(s_i, a(s_i)) = −log Π_i p̂(s_i, a(s_i))；
  - 延迟成本 L(W) = max_{path π⊆G} Σ_{s_i∈π} ℓ(s_i, a(s_i))（关键路径，可并行）；
  - 新建成本 γ|A⁺(W)|；
  - **工作流成本 Cost(W) = R(W) + β·L(W) + γ·|A⁺(W)|**（β 权衡可靠性与延迟，扫描 β 可得 Pareto 前沿）；
  - 优化成本（重跑/重搜/重训的开销）**不计入** Cost(W)，单独核算。
- **目标函数**：W* = arg min_{⟨S,A,G⟩} [R(W) + βL(W) + γ|A⁺(W)|]。
- **双向流程**：
  1. **自顶向下原子分解**：把 Q 分解为最细原子 T（每个原子单独可可靠完成），并丢弃目标不可达的原子；
  2. **自底向上代价驱动合并**：在偏序合并空间 P 上搜索，每步对下一个原子执行 OPEN（新开子任务）或 MERGE（并入已有子任务），只在对整体成本有利处合并；返回成本最小的合并 P*，再由 LIFT 把原子依赖提升为子任务图 G。
- **剪枝**：lb = Cost(P′) + 乐观余量，若 lb 已达当前最优则剪枝，**不会丢弃最优解**；受扩展预算 B 限制。
- **元原语**：AND（合取）、REPEAT（有界重复，含失败重试的可靠性与延迟公式）、OR（多路并行取并）、SELECT（分支选择，按权重加权可靠性、取最大延迟）。
- **契约（contract）**：每个子任务从构成它的原子继承输入条件 σ_in 与输出条件 σ_out，这是后续无监督故障检测的基础。

### 2.3 阶段二：流内动态优化（In-Flow Optimization）

四个动作：**Detect → Pause → Temper → Resume**。

- **检测（Detect）**：复用同一估计器，反向使用成本矩阵形成"信用矩阵"：u(σ, x) = 1 − match(σ, x) ∈ [0,1]，当 u ≥ ū 时条件视为未满足（x = I_i 检查输入条件，x = O_i 检查输出条件）。
- **归责（blame）**：
  - 某输入条件未满足 → 归咎于**分解（decomposition）**；
  - 否则某输出条件未满足 → 归咎于**指派（assignment）**；
  - 否则 none。
  - 另有**因果信号**：子任务产不出可用输出时，无需匹配即判定为故障。
- **成本有序阶梯**：**RE-ASSIGN ≺ RE-DECOMPOSE**（先做便宜的动作，穷尽后才升级）。
  - RE-ASSIGN：在成本矩阵中取尚未被排除的列最小值，a′(s_i) = arg min_{a∈(A∪A⁺)\X(s_i)} C(s_i, a)；**只有执行后契约通过才提交**，否则回滚——不留未经验证的改动；
  - RE-DECOMPOSE：候选耗尽后，在**同一契约**下对 s_i 局部重跑 COALESCE，把得到的子 DAG 拼接回去；
  - 每个动作都有预算（B_ra、B_rd），预算耗尽则恢复原始实现，**优化永不让工作流比构建结果更差**。
- **作用域恢复（Scoped Resumption）**：执行在 s_i 处暂停，仅失效 I(s_i) = {s_i} ∪ Desc(s_i) 的后继闭包，闭包外结果从缓存复用；优化代价被限定在局部，而非 |S|。
- **目标**：W† = arg min_{W′∈N*(W*)} C̃ost(W′)，其中被观测违反契约的配对 (s,a) 其 C̃ = ∞，其余 C̃ = C。
- **可选全局定位（Alg. 5）**：局部纠错后仍无可用答案时，用怀疑度 susp(s_i) = (1−p̂_i)(1+|Desc(s_i)|) + 1[s_i flagged] 全局排序、逐个探测（预算 B_g），但**纠正仍只发生在局部**；主实验中该模块被关闭。

## 三、实验设计

### 3.1 基准 BRAID（本文提出的工作流级基准）

- **动机**：一个工作流只有在单智能体无法胜任时才有存在必要；既有基准不满足此前提。作者在 SlideVQA 上的预实验显示：原始数据上单智能体反而比工作流高 12.02%、成本低 6.91 倍；经 BRAID 组合后顺序反转（+38.17%）。
- **构建方式**：每个任务由 k 个问题构成，并提供超出问题所需的额外来源，且**不说明哪个来源对应哪个问题**；k 为复杂度级别。
  - **Distributed（分布式）**：每个问题各有自己的 gold source，另加 (k−1) 个干扰源，共输入 (2k−1) 个来源；
  - **Anchored（锚定式）**：所有问题共享同一 gold source，另加 (k−1) 个干扰源，共 k 个来源。
- **四重质量控制**（不满足则不写入）：分离性（Separation）、可路由性（Routing，问题中须含仅出现在其 gold source 的词/短语）、无泄漏（Leakage）、可答性（Answerability，由 LLM 判定答案是否对其他来源也成立）；文件名随机化且不携带信息。
- **规模**：基于 10 个公开数据集构建 14 个 BRAID 数据集、**19 个仅评估用 arm**，覆盖 **8 个领域**（文档、幻灯片、金融、图表、数学、物理、科学、代码），每个支持两个复杂度级别 k = 3 与 k = 5；保留条件是某级别至少产出 80 个问题。
- **评估指标**：按答案类型分别评分，任务准确率 = k 个问题的平均分，数据集准确率 = 任务平均分；类型包括 numeric（相对容差）、math（符号等价）、text（归一化匹配，否则 token-F1）、choice、list（逐位计分）、code（执行测试全通过）。**按问题逐项评分而非整任务二值化**，避免"答对大部分"与"全错"同分。
