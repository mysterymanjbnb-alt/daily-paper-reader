## 摘要
随着基于LLM的智能体执行日益复杂的任务，Agent Skills 已成为一种灵活的机制，用于扩展其能力。一个 Agent Skill 将任务特定的指令与可执行组件及辅助资源打包在一起，以提供专门功能。然而，第三方 Skills 的日益广泛采用引入了新的供应链攻击面。恶意 Skills 可以嵌入有害行为，滥用智能体权限并危害智能体执行环境或可访问资源。尽管近期基于LLM的恶意 Skill 审计方法已取得有前景的性能，但它们通常依赖能力强大的商业LLM。在安全敏感且资源受限的环境中，如何利用紧凑、可本地部署的LLM实现有效审计，仍很大程度上尚未被探索。我们的研究揭示，紧凑型LLM难以识别隐藏在复杂 Skill 包中的恶意行为。这一困难既源于此类行为的隐蔽性，也源于紧凑型LLM有限的推理能力。为应对这些挑战，我们提出 SKILLLITE，一个证据引导的智能体框架，用于恶意 Skill 检测。SKILLLITE 能有效提取安全相关行为，并从复杂 Skill 包中推断其预期功能。随后，它使用紧凑型LLM根据观察到的行为及其功能上下文评估该 Skill 的恶意性。实验表明，SKILLLITE 在不同紧凑型LLM骨干模型上均提升了恶意 Skill 检测效果，并优于现有代表性审计基线。其有效性可泛化到经行为确认的真实世界恶意 Skills。同时，SKILLLITE 保持较低的推理延迟，支持其实际部署。

## Abstract
As LLM-based agents perform increasingly complex tasks, Agent Skills have emerged as a flexible mechanism for extending their capabilities. An Agent Skill packages task-specific instructions with executable components and auxiliary resources to provide specialized functionalities. However, the growing adoption of third-party Skills introduces a new supply-chain attack surface. Malicious Skills can embed harmful behaviors that abuse agent privileges and compromise the agent execution environment or accessible resources. Although recent LLM-based malicious Skill auditing approaches have achieved promising performance, they often rely on capable commercial LLMs. How to achieve effective auditing with compact, locally deployable LLMs in security-sensitive and resource-constrained settings remains largely unexplored. Our investigation reveals that compact LLMs struggle to identify malicious behaviors hidden in complex Skill packages. This difficulty arises from both the implicit nature of such behaviors and the limited reasoning capacity of compact LLMs. To address these challenges, we propose SKILLLITE, an evidence-guided agentic framework for malicious Skill detection. SKILLLITE effectively extracts security-relevant behaviors and infers the intended functionality from complex Skill packages. It then employs a compact LLM to assess the maliciousness of the Skill based on the observed behaviors and their functional context. Experiments show that SKILLLITE improves malicious Skill detection across different compact LLM backbones and outperforms existing representative auditing baselines. Its effectiveness generalizes to behaviorally confirmed in-the-wild malicious Skills. Meanwhile, SKILLLITE maintains a low inference latency, supporting its practical deployment.

  - 规则/静态分析（Cisco Skill Scanner、NVIDIA SkillSpector）高效但缺乏上下文理解，难以判断敏感行为是恶意还是功能必需。
  - 基于 LLM 的审计（SkillProbe、AI-Infra-Guard、SkillWard 等）性能有前景，但普遍依赖强大的商业或大规模 LLM，带来外部服务依赖、本地部署开销大、隐私与算力约束等问题。
- **核心研究问题**：在安全敏感、资源受限、需要本地部署的场景下，**如何用紧凑型（compact）LLM 实现有效的恶意 Skill 审计**。
- **两大挑战（论文的核心诊断）**：
  - **❶ 恶意行为隐蔽**：安全相关行为稀疏且分散在指令、脚本、配置、辅助资源中，单一 artifact 往往看不到完整恶意行为；敏感操作孤立看可能是合法的，只有结合功能上下文与行为组合才能判定。
  - **❷ 紧凑 LLM 能力有限**：难以同时完成"定位证据—连接分散观察—解释安全含义"。

## 2. 方法论

### 2.1 核心思想

- SKILLLITE 是一个**证据引导的智能体式（agentic）审计框架**，核心思路是：**把"证据获取与语境化"从模型中外部化**，让紧凑 LLM 只专注于"意图条件下的风险裁定"，从而降低其推理负担。
- 形式化：给定 Skill 包 S，审计任务为预测 f(S) → y，y ∈ {BENIGN, MALICIOUS}。**仅做部署前静态审计**；运行时行为、针对底层基础设施/模型/执行环境的攻击不在范围内。

### 2.2 四个功能角色（流程）

1. **安全证据抽取（Security Evidence Extraction）**
   - 将 Skill 包表示为 S = {a₁, …, aₙ}（指令、脚本、配置、辅助资源等 artifact）。
   - 定义安全相关行为类集合 B：敏感资源访问、外部通信、系统执行、持久化、隐藏行为、智能体控制操纵。注意：这些类别刻画的是"安全相关性"而非"恶意性"。
   - 使用一组互补的确定性分析器 D = {D₁, …, Dₘ}，覆盖四类能力：
     - 通用安全模式（本地文件访问、网络活动、系统命令执行、权限修改）
     - 语言感知的代码分析（进程调用、网络 API、环境变量访问、动态执行）
     - 隐藏载荷检查（编码载荷、隐藏 helper 逻辑、拆分载荷、混淆执行）
     - 智能体特定控制信号（审批绕过、沙箱绕过、控制流劫持、自主确认绕过）
   - 输出安全发现集合：F(S) = ⋃_{aᵢ∈S} ⋃_{Dⱼ∈D} Dⱼ(aᵢ)，每条发现记录行为、来源 artifact、支撑证据与属性。

2. **意图分析（Intent Analysis）**
   - 由紧凑 LLM 担任 **Intent Analyst**，从 SKILL.md 推导功能规约 P = (g, C_exp)，其中 g 为声明目标，C_exp 为该目标合理预期的能力集合。
   - 例：部署类 Skill 预期网络访问与命令执行，而文档处理类 Skill 则不然。该规约作为解释安全发现的参照；**"预期之外"不等于恶意**，留待风险裁定阶段判断。

3. **证据合成（Evidence Synthesis）**
   - **来源接地**：将每条发现表示为接地观察 e_k = (b_k, a_k, x_k, c_k, s_k)，分别对应行为、来源 artifact、支撑证据、周边上下文、证据强度；形成证据集 E = {e₁, …, eₙ}，统一规范化不同分析器的输出并保留来源与上下文。
   - **上下文整合**：结合功能规约 P 与适用安全策略 Π，组织为证据报告 R = (E, C_risk)。
   - 报告含两个互补视图：(1) 接地证据——观察到什么行为、出现在哪里；(2) 风险上下文——功能预期与相关安全策略。

4. **风险裁定（Risk Adjudication）**
   - 由紧凑 LLM 担任 **Risk Adjudicator**，从三个互补维度评估接地证据：
     - **功能必要性**：该能力是否为声明功能所合理必需；
     - **良性反证**：来源接地的证据是否对可疑行为提供可信的正当化解释；
     - **安全风险**：同时考虑单行为与行为组合（多个单独看似合理的操作组合成有害模式，即"滥用链 abuse chain"）。
     - 特别地，**关键智能体风险（critical agentic risks）不接受通用功能辩护，必须提供直接、针对该风险的良性反证**。
   - 输出：最终恶意性判断 + 证据接地的理由（rationale），使决策可追溯到原始 Skill artifact。
   - 附录 D 给出两个提示模板（意图分析、证据引导风险裁定）及其决策策略与 JSON 输出结构。

## 6. 主要结论与发现

- **检测性能**：SKILLLITE 在 MalSkillBench 与 SkillTrustBench 上取得最佳综合性能，F1 分别为 **0.905** 与 **0.966**，同时保持较高精确率与召回率；现有方法普遍在"漏报恶意 Skill"与"误报良性敏感操作"之间存在明显权衡。
- **真实场景泛化**：在 MASB 上取得最佳 Acc 与 F1 = **0.807**，FPR 仅 0.048，说明无需依赖激进检测策略即可泛化到真实生态。
- **效率**：平均每 Skill 耗时 27.4 s（MalSkillBench）、28.5 s（SkillTrustBench）、19.4 s（MASB）；在 MalSkillBench 上比最强竞争基线快约 **3.5×**，在 MASB 上快约 **4.9×**（AI-Infra-Guard 的 F1 最接近但耗时约 4.9 倍）。
- **增强紧凑 LLM**：在全部 15 个模型–基准配置上 F1 均有提升，增益 9.2–73.6 个百分点；零样本审计呈"保守偏差"（高精度、低召回），尤其在 MASB 上几乎失效（如 Gemma4 零样本 F1 仅 0.071，Mixtral 为 0.000）。例如 MalSkillBench 上 DeepSeek-R1:8B 的 F1 从 59.2% 提升至 80.5%，延迟仅 11.5 s。
- **消融结论**：移除任一组件均显著降性能——去掉证据抽取 F1 降至 0.485（召回仅 0.326）、去掉意图分析降至 0.451（精确率 0.996 但召回 0.292）、去掉证据合成降至 0.743；说明三者分别承担"暴露证据、提供功能参照、连接语义解释"的互补作用。
- **残余错误**：MASB 上的错误以**假阴性**为主，主要因为某些敏感行为与声明功能看似一致——这反映了静态审计的根本局限：无法观察仅在运行时才显现的风险。
- **总体启示**：有效的安全审计**不一定需要扩大模型能力**，重构"如何向模型暴露安全证据"是一条构建轻量、本地化审计系统的可行路径。

## 7. 优点

- **问题定位精准且有现实

性依据**：论文不是凭空构造威胁，而是以 ClawHavoc、CERT-EU 报告、98,380 个真实 Skill 的筛查结果作为动机支撑，问题定义与工业界现实紧密贴合。
- **思路简洁且可解释**：核心洞察——"紧凑 LLM 的瓶颈不在推理能力，而在于安全证据没有被有效暴露"——把复杂的安全判定拆解为"抽取证据 → 建立功能参照 → 组织证据报告 → 裁定风险"四个职责清晰的角色，避免了让单一模型承担全部认知负担。
- **证据接地贯穿全流程**：从发现记录 (b, a, x, c, s) 到最终 rationale，每一步都能追溯到原始 artifact，使决策可审计、可复核，这对安全工具而言是重要的工程属性。
- **任务分解与 LLM 分工合理**：将确定性分析器（擅长穷举与模式匹配）与 LLM（擅长语义与意图推断）各司其职，用外部化证据获取弥补紧凑模型的能力短板，是一种务实的"能力补偿"设计而非盲目堆参数。
- **评价体系较为完整**：主指标之外同时报告 FPR/FNR/延迟，并设置消融、跨模型、攻击类别、包大小、语言复杂度、编程语言等多维分析，能较好回答"是否有效""为何有效""在何处失效""成本几何"四类问题。
- **模型无关性得到验证**：5 个骨干 × 3 个基准的 15 组配置一致提升，且 DeepSeek-R1:8B 关闭 thinking 也能获得显著增益，说明框架不依赖特定模型的特殊能力。
- **对"关键智能体风险"的特殊处理有洞察**：明确区分"可由通用功能辩护的敏感行为"与"必须提供直接反证的关键风险"（如审批绕过、沙箱绕过），这一设计针对智能体场景的特殊性，而非套用传统代码审计逻辑。
- **效率主张有数据支撑**：3.5×–4.9× 的加速与 19–29 s/样本的端到端时间，使其在"本地部署、资源受限"的目标场景中具备可落地性。

## 8. 局限与可改进之处

- **静态审计的固有天花板**：论文明确将运行时行为排除在范围外，但 MASB 上的残余错误恰恰以假阴性为主，且成因是"敏感行为与声明功能看似一致"。这意味着对"仅在运行时触发""依赖外部条件激活"的载荷，方法原理上难以覆盖。可考虑引入轻量沙箱动态执行、或对高风险 Skill 做"静态预筛 + 动态确认"的两阶段流程。
- **对 SKILL.md 声明的依赖**：意图分析从声明目标推导预期能力集合。若攻击者在 SKILL.md 中刻意夸大功能范围（例如把窃取凭据包装成"配置同步"所需），则"预期之内"的辩护可能被滥用。论文虽以"关键风险不接受通用辩护"部分缓解，但该机制的覆盖边界与鲁棒性（如对声明本身的真实性校验）尚可进一步探讨。
- **基线配置的公平性折扣**：SkillSpector 的 LLM 配置改用 GPT-4.1-nano，且所有基线均以默认/即开即用配置运行、未做针对性调优。这既可能低估基线真实上限，也使得"SKILLLITE 优于强 LLM 审计"的结论需要更谨慎的表述。
- **超时与失败样本的处理透明度**：300 s/样本超时导致 Gemma4:e4b 在基线上失败率过高而被替换，但论文未充分披露各方法在超时、解析失败、JSON 格式错误等情况下的样本占比与处理方式，这可能影响 F1 与延迟数字的可比性。
- **数据集构成的潜在偏差**：MalSkillBench 与 SkillTrustBench 含相当比例的合成/构建样本，攻击向量（CI、PI、混合）与 15 种恶意行为的组合方式可能与真实攻击者的分布存在差异；MASB 虽为真实样本但规模较小（456 个），统计置信度有限（论文亦未报告置信区间或显著性检验）。
- **成本刻画不够完整**：只报告了延迟，未报告 token 消耗、单样本 LLM 调用次数、显存占用峰值等，对"资源受限"这一核心卖点而言，成本画像尚不充分；此外，没有与更小参数模型（如 2B 级）的对比，也未给出"紧凑"的具体能力下界。
- **确定性分析器的覆盖与维护成本**：四类分析器的规则集合如何构建、误报率如何、面对新语言/新混淆手法时的扩展代价，论文着墨较少。分析器一旦成为瓶颈，整体框架的上限也随之受限。
- **消融实验范围有限**：仅在 SkillTrustBench 上做消融，未在 MASB（真实场景）上验证各组件贡献，无法确认组件重要性是否随数据分布变化。
- **缺少对"对抗自适应攻击"的评估**：若攻击者知晓 SKILLLITE 的检测逻辑（例如刻意拆分行为到多个 artifact、伪装良性反证），方法的鲁棒性如何，论文未做压力测试。

## 9. 对后续研究的启发

- **"证据外部化"可迁移到其他安全审计任务**：把"找证据"与"做判断"解耦，用确定性工具承担前者、用紧凑模型承担后者，这一范式可推广到 MCP 工具审计、插件/扩展市场审核、CI/CD 流水线脚本审查等场景。
- **紧凑模型 + 结构化证据 > 大模型 + 原始输入**：论文结果提示，在安全判定这类"证据密集但推理模式相对固定"的任务上，输入表示的改造可能比模型规模扩张更具性价比，这为端侧/私有化安全方案提供了路线。
- **面向智能体的专用风险分类值得继续细化**：审批绕过、沙箱绕过、控制流劫持、自主确认绕过等类别，以及"滥用链"概念，为构建智能体安全本体（ontology）与标准化标注体系提供了起点。
- **静态与动态的互补边界值得量化**：可研究"静态审计判定为高风险的 Skill 中，有多大比例在动态执行中真正展现危害"，从而给出两阶段流程的最优触发阈值。
- **数据集建设方向**：MASB 这类"行为确认 + kill-chain 阶段标注"的真实数据集价值极高，未来可扩大规模、增加时间维度（Skill 更新后的行为漂移）与生态维度（发布者信誉、下载量等元数据）。
- **可解释性与人机协同**：既然方法能输出证据接地的 rationale，可进一步研究审计员如何利用这些理由做复核，以及"人机协同审计"中置信度如何校准。
- **对 Skill 生态治理的启示**：审计之外，还可探索发布前签名/溯源、权限最小化声明、注册表侧的风险分级与隔离，把单点检测扩展为供应链治理机制。

## 10. 一句话总结

SKILLLITE 通过把"安全证据的获取与语境化"从紧凑 LLM 中外部化、只让它专注于"意图条件下的风险裁定"，在三个基准上以 19–29 s/样本的本地推理成本显著优于现有扫描器，证明了轻量级智能体 Skill 审计的可行路径——其代价是对运行时风险与自适应攻击的覆盖仍受静态分析原理的限制。
