## 摘要
LLM 智能体在运行时越来越依赖用户批准来授权安全敏感操作。此类批准是在特定任务与执行上下文中授予的。在长生命周期智能体中，授权决策可能需要在跨任务或跨会话间持续存在。我们发现，这种持续性可能比最初为批准提供正当性的上下文更长寿，从而产生无需重新征得同意即可复用的残余权限。我们通过一种纵向攻击揭示这一失效模式：该攻击从目标安全敏感操作出发，识别执行该操作所需的权限，诱导能够合法获得该权限的良性交互，随后在对抗性执行期间重放残余权限。在受控环境与真实环境中，我们证明残余权限重放在实践中确实会出现，并显著提高提示注入与上下文重绑定攻击的成功率。我们使用源自生产环境的授权语义，在六类 LLM 系列上评估了 508 个 AgentDojo 攻击案例。相较于全新授权状态，存在残余权限时，攻击成功率（ASR）最高提升 35.1 个百分点。在针对三个真实生产编码智能体的 55 个 Terminal-Bench 案例进行的实时上下文重绑定攻击中，残余权限重放平均使 ASR 提高 24.9 个百分点。这些发现揭示了长生命周期 LLM 智能体中持久授权与用户同意的上下文本质之间的根本性错配。

## Abstract
LLM agents increasingly rely on user approval to authorize security-sensitive actions at runtime. Such approvals are granted within a specific task and execution context. In long-lived agents, authorization decisions may need to persist across tasks or sessions. We find that this continuity can outlive the context that originally justified the approval, creating residual authority reusable without renewed consent. We expose this failure mode through a longitudinal attack that starts from a target security-sensitive action, identifies the authority required to execute it, induces benign interactions that legitimately obtain that authority, and later replays the residual authority during adversarial execution. Across controlled and live settings, we demonstrate that residual-authority replay arises in practice and substantially increases the success of prompt-injection and context-rebinding attacks. We evaluate 508 AgentDojo attack cases across six LLM families using production-derived authorization semantics. With residual authority, attack success rate (ASR) increases by up to 35.1 percentage points compared with a fresh authorization state. In live context-rebinding attacks on 55 Terminal-Bench cases across three real-world production coding agents, residual-authority replay increases ASR by 24.9 percentage points on average. These findings expose a fundamental mismatch between persistent authorization and the contextual nature of user consent in long-lived LLM agents.

# 论文总结：《When Consent Outlives Context: Residual Authority Replay in Long-Lived Agents》

## 1. 核心问题与整体含义

- **背景**：LLM 智能体正从"一次性助手"演变为**长生命周期主体（long-lived principals）**，跨任务、跨会话持续附着于同一项目并携带状态。为降低重复授权开销，系统会将用户批准（approval）持久化保存，供后续任务复用。
- **核心矛盾**：用户同意（consent）是在**特定任务与执行上下文**中授予的，但授权状态可以**比赋予其正当性的上下文活得更久**。作者将这种"存活的授权"称为**残余权限（residual authority）**。
- **问题本质**：这是**最小权限原则的时间盲点**——授权在签发时可能最小，但一旦脱离原上下文就可能变得过度；其结构与经典 **TOCTTOU（time-of-check to time-of-use）** 缺陷同构：安全决策在状态已变后仍然有效。
- **现实动机**：论文引用三起真实事件——Gemini CLI 持久化工具授权跨工作区生效并通向 RCE（CVE-2026-12537）；Meta Muse 助手委派的能力通过账户 token 长期可被本地攻击者调用；Codex 在进入攻击者控制的仓库时，旧授权仍生效。
- **整体含义**：持久授权与用户同意的情境化本质之间存在**根本性错配**；攻击者可以**主动、合法地"积攒"权限**，在上下文改变后重放，从而抑制本应出现的新批准边界。

## 2. 方法论

### 2.1 核心思想
将攻击建模为**对持久授权状态的逆向规划（backward planning）**问题：从目标有害结果出发，反推所需权限，通过良性任务合法获取，再在对抗执行时重放。整体四阶段流程见 Figure 1。

### 2.2 关键技术细节

- **阶段一：智能体授权画像（Authorization Profiling）**
  - 定义两个程序点：**approval source**（用户决策创建/更新授权状态 G 的位置）与 **authorization point**（运行时查询 G 决定动作 a 是否需再次批准的位置），决策记为 `Mi(G, a) ∈ {allow, ask}`。
  - 采用**反向切片 → 持久状态缝合 → 字段级污点传播 → 原生差分验证**的流程，跨过程边界追踪授权相关数据依赖。
  - 产出授权画像 **Pi = (Σi, Fi, Mi, Li)**：Σi 为保留的动作属性，Fi 为存储表示，Mi 为匹配谓词，Li 为状态有效边界（任务/会话/进程）。
  - 验证方式：固定 G，逐一变动单个动作属性，比对原生 allow/ask 决策是否与恢复的匹配条件一致。
  - 恢复出的真实语义示例：Codex 保留 **argv 前缀**，Gemini CLI 保留 **命令根（command root）**，Goose 仅保留 **工具名**。例如 Gemini CLI 批准 `chmod 644 note.txt` 只持久化 `chmod` 这一命令根，后续任意 chmod 命令都可命中。

- **阶段二：残余权限反向链接（Backchaining）**
  - 令 τ* 为参考动作序列，G0 = ∅ 为全新状态，定义**需批准动作集** `Areq = {a ∈ τ* | Mi(G0, a) = ask}`。
  - 定义候选任务–授权对 `Bi(a) = {(T, g) | T ∈ Tbenign, g ∈ Γ̂i(T), Mi({g}, a) = allow}`。
  - 目标残余权限 `R = {g_a | a ∈ Areq}`；同一任务/授权可覆盖多个需求。

- **阶段三：良性权限培育（Benign Authority Farming）**
  - 执行选定的良性任务 T1…Th，以**合法目标与良性上下文**呈现，审批由当前任务正当化，由智能体原生流程写入授权状态。
  - 得到在重放时仍有效的授权集 **Gh**（剔除过期/撤销项），并记录每个授权的来源任务与审批，建立**来源可追溯性（provenance）**。
  - 覆盖性校验：需满足对每个 `a ∈ Areq` 都有 `Mi(Gh, a) = allow`。

- **阶段四：残余权限重放（Replay）**
  - 两个条件：**C1 全新状态**（G0 = ∅）与 **C2 残余状态**（Gh），二者使用**相同目标任务、相同对抗上下文、相同非授权状态**，且基线授权策略与原生检查均保持启用。
  - 成功判定：`Sreplay = W · (1 − Q2) · H2 = 1`，其中 W 表示"批准边界改变 + 授权来源可归因"已验证，Q2 表示重放路径上是否仍遇到新批准要求（应为 0），H2 表示有害效果 oracle 是否满足。
  - 该定义严格区分了**授权复用**与**攻击实际达成**：未匹配、仍有额外批准、无有害结果、无法归因的案例单独记录。

## 3. 实验设计

- **数据集 / 场景**
  - **AgentDojo v1.2**（受控实验）：banking、Slack、travel、workspace 四个环境，共 **508 个合格 (X, Z, p) 案例**（X 为用户任务，Z 为注入的对抗目标，p 为带副作用的攻击能力）。
  - **Terminal-Bench**（真实生产智能体评测）：**55 个案例**，覆盖 5 类上下文漂移——C1 可执行文件劫持（n=21）、C2 内容替换（n=2）、C3 依赖劫持（n=20）、C4 配置投毒（n=10）、C5 项目重定向（n=2）。候选经静态筛选（133 个任务–类别对）与参考动作验证后保留 55 个。

- **受控环境设置**
  - 在 AgentDojo 工具执行外包裹一层**确定性授权层**，实例化从生产系统恢复的授权表示、匹配规则与持久化语义。
  - 统一系统提示、工具 schema、注入模板，交互预算 **10 个模型步**。
  - 评测 **6 个模型系列**：GPT-4.1、Gemini-3.1-Flash-Lite、Qwen3-14B、Llama-3.3-70B-Instruct、Claude-Sonnet-5、DeepSeek-V4-Pro（关闭推理）。

- **真实环境设置**
  - 三个生产编码智能体：**Codex、Gemini CLI、Goose**（Codex/Goose 用 gpt-5.6-luna，Gemini CLI 用 Gemini-3.1-Flash）。
  - 每案例在 fresh 与 farmed 两种条件下各重复 **5 次**。

- **对比方法（授权策略）**
  - 持久匹配三档：**tool-level**（仅操作身份）、**scope-level**（保留粗粒度父身份，如收件域、URL 主机名）、**exact-resource**（操作 + 精确资源）。
  - 任务感知基线：**Progent**（从当前用户任务推导最小权限策略，仅用 task-start 策略，未启用动态更新路径）、**PAuth**（仅复现其 task-scoping 组件，绑定可复用权限到当前任务）。
  - 对照：**no-replay**（完全不保留历史授权）。

- **度量指标**
  - **CHE（Conditional History Exposure）**：`Pr[Mi(Gh,a)=allow | Mi(G0,a)≠allow]`，衡量原本需批准的动作经 h 个良性任务后变为静默可执行的比例。
  - **ASR 三因子分解**：`Pr(success) = Pr(attempt) · Pr(silent execution | attempt) · Pr(success | silent execution)`，用于分离"模型行为"与"智能体授权"的贡献。
  - 不确定性：**配对目标簇 bootstrap**，B = 2000，seed = 20260907，报告百分位 95% CI。

## 6. 主要结论与发现

- **权限会随良性使用累积**：CHE 显示 Goose 在 1 个良性任务后即达 1.00 并饱和；Gemini CLI 从 h=1 的 0.12 升至 h=64 的 0.84；Codex 与 OpenCode 增长更慢，h=64 仅 0.12 与 0.11。**名义粒度不能决定实际暴露度**（Codex 与 OpenCode 曲线相近）。
- **攻击放大来自授权项而非模型行为**：有害动作尝试率随历史长度**没有系统性上升**（Gemini 反而从 0.903 降至 0.476），但条件静默执行率从 0 升至 h=64 时的 0.982–1.000。ASR 提升纯粹源于授权机制把先前批准编译成谓词，使同一动作在不同历史下"一个静默执行、一个需要批准"。
- **受控实验结果（h=64，ΔASR，95% CI）**：Gemini-3.1-Flash-Lite **+35.1pp** [30.6, 39.5]；GPT-4.1 **+27.9pp** [23.6, 32.0]；Qwen3-14B **+23.5pp** [19.5, 27.4]；DeepSeek-V4-Pro **+11.4pp** [7.8, 15.6]；Llama **+0.4pp**；Claude 0.0（退化）。
- **粒度收紧可压缩但不能消除放大**：tool-level ASR 0.114–0.351 → scope-level
