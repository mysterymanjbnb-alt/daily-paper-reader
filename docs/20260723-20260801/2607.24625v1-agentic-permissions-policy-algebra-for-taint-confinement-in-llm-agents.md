## 摘要
处理混合机密性数据的自主LLM智能体面临来自提示注入攻击和推理错误的严重安全风险。虽然动态信息流控制（IFC）提供了结构性安全保证，但传统的污点跟踪在读取未经验证的数据时会永久污染智能体的上下文，严重限制下游实用性。我们提出了APPA（智能体权限策略代数），一种通过引擎管理的上下文分支和前瞻性获取强制来解决这一可用性瓶颈的IFC框架。在数据获取发生之前，APPA前瞻性地评估标签下降和缺失的先决条件，生成可行的补救计划（授权、接受）。为了在不污染主上下文的情况下检查未经验证的数据，会生成一个带有标签种子的子轨迹，在局部吸收标签下降，并允许受信任的净化器将有界派生返回到未改变的父级。通过安全标签和共享事件日志上的双幺半群模型，我们正式证明了父标签保留和合并隔离。最后，我们在四个模型的多轮工具链基准上评估了APPA：它将泄露抑制（攻击成功率从31%-50%降至0%-7%），并且在四个模型中的三个上，分支恢复了仅污点跟踪所放弃的相当一部分效用。

## Abstract
Autonomous LLM agents processing mixed-confidentiality data face severe security risks from prompt injection attacks and reasoning errors. While dynamic Information Flow Control (IFC) provides structural security guarantees, traditional taint tracking permanently taints an agent's context upon reading unvetted data, severely restricting downstream utility. We present APPA (Agentic Permissions Policy Algebra), an IFC framework that resolves this usability bottleneck through engine-managed context branching and prospective acquisition enforcement. Before data acquisition occurs, APPA prospectively evaluates label descents and missing prerequisites, generating actionable remedy plans (Authorize, Accept). To inspect unvetted data without polluting the primary context, a label-seeded child trajectory is spawned, absorbing label descent locally and allowing a trusted sanitizer to return a bounded derivative to the unchanged parent. Governed by a two-monoid model over security labels and shared event logs, we formally prove parent label preservation and merge confinement. Finally, we evaluate APPA on a multi-turn tool-chaining benchmark across four models: it suppresses exfiltration (31%-50% down to 0%-7% attack success), and on three of the four, branching recovers a substantial share of the utility that taint tracking alone forfeits.

## 1. 核心问题与整体含义

- **背景**：自主LLM智能体在混合机密性数据环境中运行时，既需要读取敏感数据，又可能接触不可信外部内容，由此产生提示注入攻击、模型幻觉和不正确推理等结构性安全风险。
- **核心矛盾**：动态信息流控制（IFC）能提供结构性安全保证，但传统污点跟踪会让“读取未经验证数据”这一动作**永久污染**智能体上下文，使后续对下游工具的访问被锁定，严重损害智能体的实用性——即“标签蔓延”问题。
- **研究意义**：APPA 旨在同时实现安全性与实用性，通过“引擎管理的上下文分支”和“前瞻性获取强制”来消除传统 IFC 的可用性瓶颈，为高可信 LLM 智能体系统提供了一条新范式。

## 2. 方法论

### 核心思想

1. **分支隔离污点（Taint Confinement）**：将敏感读取与推理放到“一次性”子轨迹中进行，子轨迹局部吸收标签下降；退出时只允许受信任净化后的派生结果或有界值返回父轨迹，从而保持父轨迹标签不被污染。
2. **前瞻性获取强制（Prospective Acquisition Enforcement）**：在工具调用真正执行前评估策略约束，若发现权限收窄或前提缺失，则生成结构化补救计划（`Authorize`、`Accept`、`Redispatch` 等），而非执行后被动处理。

### 关键技术细节

- **标签状态**：$S = \mathcal{P}(U) \times T$，其中 $U$ 为有限读者集合，$T$ 为有限信任链；在分量式交/最小化与并/最大化下构成有限积格，保证策略组合的确定性。
- **两幺半群模型**：
  - *检查动作幺半群*：非恒等动作均为限制性 meet（$a_i = (\cap A_i, \min r_i)$），折叠操作可简化为单次运行 meet（Collapse 命题）。
  - *日志幺半群*：共享事件日志为自由幺半群，通过 committed-effect 投影 $E(\ell)$ 记录已提交效果，供 `prior` / `no_prior` 历史谓词使用。
- **分支协议**：
  - 子轨迹创建时继承父轨迹标签（$L_c^0 := L_p^{init}$）并快照父轨迹可见前缀；
  - 子轨迹的后续折叠只作用于 $L_c$，与父标签隔离；
  - 退出时只有三种情况：放弃、返回标准带标签值、或经注册消毒器/经过验证的退出变换后返回值；合并时执行检查 $L_p \le \mathrm{label}(v)$ 才能保持父标签不变。
- **原子裁定（Call-Scoped Release）**：所有裁定均针对“引擎渲染后的单一调用”，一次裁定只匹配一次分派；裁定和接受事件不修改任何轨迹标签或 committed-effect 投影，防止权限提升被延续到后续调用。
- **补救计划**：区分可执行的原子计划（`Authorize`、`Accept` 及其组合）与建议性推荐（`Redispatch`、`Branch`）；原子计划通过静态工具 `execute_remedy_plan(plan_id)` 执行。
- **契约与消毒器**：工具契约声明 `delta`（标签贡献）、`emits`（副作用效果）、`requires`（前置条件）；消毒器仅调整受众范围，不能未经证明而提升信任等级。
- **关键定理**：分支污点隔离定理（父标签保持）、调用范围释放定理、补救完备性定理，均提供了形式化证明。

## 3. 实验设计

- **基准**：作者构建了 `bench-corp`，一个面向多轮、多工具轨迹的模拟公司环境，包含 5 个 CRUD 存储（HR、财务、任务跟踪、公共论坛、供应商）+ 邮件外发，共 17 个工具。
- **场景**：14 个任务场景，覆盖：
  - 结构上依赖分支的任务（如 `reply-and-file-ticket`、`email-onboarding-buddy`、`review-then-notify`）；
  - 原生表达能力测试（如受众交集、一次性历史谓词、输出净化、信任边界、预分派 vs 后效果标注等）；
  - 间接提示注入、字段走私、非对抗性过度披露风险等。
- **模型**：4 个模型——Gemini 3.5 Flash-Lite、GPT-5.6 Luna、GPT-4o、Qwen 3.6 35B。
- **对比方法**：
  - `APPA`（完整方法）；
  - `APPA-no-fork`（同一二进制但禁用分支，作为消融）；
  - `APPA-open`（无策略的基线循环）；
  - `Fides`（微软 Agent IFC 框架）；
  - `Fides-open`（无安全配置的 Fides 循环）。
- **执行与评分**：每个场景重复 3 次，自动子进程执行，评估端状态声明式谓词（邮箱有无、文件内容匹配），不依赖 LLM 裁判；分别统计实用性与安全攻击成功率（ASR）。

## 6. 主要结论与发现

- **安全性**：APPA 将四个模型上的攻击成功率（ASR）从开放基线的 31%–50% 降至 0%–7%，几乎完全抑制了数据外泄。
- **实用性恢复**：分支机制显著提升实用性——GPT-5.6 Luna 从 69% 升至 95%，Gemini 3.5 Flash-Lite 从 28% 升至 44%，Qwen 3.6 35B 从 54% 升至 72%；GPT-4o 两个臂持平（59%），其中分支转换了 4 个依赖分支的 episode 但被额外调解开销抵消。
- **对比结果**：Fides 在四个模型上的 ASR 均为 29%（策略失配导致确定性相似），实用性为 33%–56%，表现不如 APPA。
- **残余失败**：所有非零 APPA 失败可归因于两个具体场景，且均非绕过强制本身——一是在合法收件人权限内携带的隐藏令牌，二是缺少写侧契约的存储中转路径。

## 7. 优点

- **形式化保证**：从标签格、幺半群到分支隔离、调用范围释放均给出严格证明，安全结论不依赖模型行为。
- **前瞻式策略执行**：在数据进入上下文前就评估标签下降与前提缺口，避免了不可逆污染。
- **原子裁定机制**：单调用、单次消费的授权和接受，防止重放和跨调用权限延续。
- **提示缓存友好**：子轨迹共享父轨迹前缀，可利用 KV 缓存，降低分支带来的推理成本。
- **实验设计比较严谨**：使用声明式端状态评分而非 LLM 裁判，控制变量清晰，并提供残余失败的归因分析。
- **诚实的方法论披露**：明确说明合成基准、对比系统表达能力差异以及结论适用范围。
