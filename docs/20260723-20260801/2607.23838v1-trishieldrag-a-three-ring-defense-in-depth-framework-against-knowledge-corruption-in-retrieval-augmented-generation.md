## 摘要
检索增强生成（RAG）让大语言模型能够在查询时利用从外部知识库检索到的文档来回答问题。这使得RAG对于私有数据、快速变化的信息以及减少幻觉非常有用，但同时也意味着模型的答案的可信度完全取决于检索器提供的内容。如果知识库接受多方写入，攻击者只需少量对抗性文档就能引导模型得出其所选择的错误答案。PoisonedRAG证明了这一点：仅需五篇精心构造的文档，就能在大约90%的情况下使未设防系统的答案发生翻转，而三种自然的单阶段防御（困惑度过滤、查询改写、知识库扩充）仍会使攻击成功率保持在30%或更高。我们构建了TriShieldRAG来弥合这一差距。我们不依赖单一检查点，而是在流水线中放置三个独立且形式化规定的环：一个摄取守卫（Ingest Guard），用于筛查文档中的词汇和统计投毒特征；一个检索评分器（Retrieval Scorer），根据来源和一致性加权的信任分数对检索到的文档集重新排序；以及一个跨LLM共识阶段（Cross-LLM Consensus），该阶段轮询三个架构多样的大语言模型（Claude、Mistral Small、Llama 3.2），并在出现分歧时允许一次有界的重新检索。我们推导了环2和环3预期能够生效的条件：少数投毒假设和显式来源标签假设。我们报告的配置与该分析一致，尽管我们尚未进行受控的投毒比例扫描来独立确认这一点。针对原始PoisonedRAG中的非自适应攻击者，在包含5,000篇文档的维基百科知识库和10个目标问题的测试中，完整流水线将攻击成功率从约91%降至约13%，同时保持了对良性查询的准确性。

## Abstract
Retrieval-Augmented Generation (RAG) lets a large language model answer questions using documents retrieved from an external knowledge base at query time. This makes RAG useful for private data, fast-changing information, and reducing hallucination, but it also means the model's answer is only as trustworthy as whatever the retriever hands it. If the knowledge base accepts writes from more than one party, an attacker needs only a handful of adversarial documents to steer the model toward a chosen wrong answer. PoisonedRAG demonstrated this: as few as five crafted documents flip an undefended system's answer roughly 90% of the time, and three natural single-stage defenses (perplexity filtering, query paraphrasing, knowledge-base expansion) leave attack success at 30% or higher.   We built TriShieldRAG to close that gap. Rather than relying on one checkpoint, we place three independent, formally specified rings across the pipeline: an Ingest Guard that screens documents for lexical and statistical poisoning signatures; a Retrieval Scorer that re-ranks the retrieved set by a provenance and consistency-weighted trust score; and a Cross-LLM Consensus stage that polls three architecturally diverse language models (Claude, Mistral Small, Llama 3.2) and allows one bounded re-retrieval on disagreement.   We derive the conditions under which Rings 2 and 3 are expected to work: a minority-poison assumption and an explicit provenance-tag assumption. Our reported configuration is consistent with this analysis, though we have not yet run the controlled poison-fraction sweep needed to confirm it independently. Evaluated against the non-adaptive attacker from the original PoisonedRAG, over a 5,000-document Wikipedia knowledge base with 10 target questions, the full pipeline reduces attack success rate from roughly 91% to roughly 13% while preserving accuracy on benign queries.

**本文目标：**
- 提出 **TriShieldRAG**：一种三环纵深防御（defense-in-depth）框架，在数据摄入、检索排序、生成验证三个流水线阶段设置独立防御检查，使攻击文档必须同时绕过三层防护才能成功，从而大幅降低知识污染攻击的成功率。

## 2. 方法论

**核心思想：**
TriShieldRAG 在标准 RAG 流水线中插入三个独立检查环，每个环检查不同信号（个体文档统计特征、跨文档信任、跨模型一致性），攻击者必须三环同时全部击破才能最终得手。

**三环架构：**

**Ring 1：Ingest Guard（摄入守卫）**
- 每篇候选文档计算三个怀疑分数：
  - **困惑度检测** p(d)：基于词元多样性 ω、最高频词占比 ε 的近似，公式为 `p(d) = min(1, 0.6(1−ω) + 2.0·max(0, ε−0.12))`，惩罚低词汇多样性和过度重复。
  - **模式检测** pa(d)：检查三种人工设定的危险信号，每命中一个累加固定惩罚权重：①短问句且文档短于 400 字符（权重0.4）；②目标问题逐字出现在文档中（权重0.5）；③含“verified records”等套话断言（权重0.3），封顶1.0。
  - **离群检测** o(d)：基于文档嵌入与知识库中心向量的余弦距离。
- 组合评分：`score = max(p, pa, 0.7o + 0.3·max(p, pa))`；阈值 ϑ₁=0.5，达到即阻断。
- 复杂度：O(k·|d|)，与知识库总大小无关。

**Ring 2：Retrieval Scorer（检索评分器）**
- 对通过 Ring 1 的文档按信任分数重新排序：
  - **来源可信度** prov(d)：来源白名单查表（可信源1.0、已知污染源0.1、未知源0.5），权重0.45。
  - **跨文档一致性** c(d)：文档词袋与检索集全体词袋多数（majority token bag μ）的重叠程度，权重0.35。
  - **检索相关性** rel(d)：检索器自身的相关分数，权重仅0.20（因为检索相似度恰是攻击者最可控的信号，故刻意压低权重）。
- 信任分数公式：`trust = 0.45·prov + 0.35·c + 0.20·rel`；阈值 ϑ₂=0.35，低于则丢弃。
- **最小信任保证**：正确标记为可信来源的文档，即使一致性和相关性均为0，信任分数也有0.45 > ϑ₂，永不因 Ring 2 被丢弃（前提：攻击者未伪造来源标签）。

**Ring 3：Cross-LLM Consensus（跨模型共识）**
- 使用三个架构多样、不同厂商的 LLM（Claude、Mistral Small、Llama 3.2）分别独立回答同一问题（上下文为 Ring 2 过滤后的文档）。
- 将 M=3 个答案按最佳匹配候选分桶，取最大桶占比 `agree = n*/M`；阈值 ϑ₃=0.66（即 3 模型中至少 2 个一致）才接受答案。
- 若不一致：丢弃信任分最低的 1/3 文档，执行一次有界的重新检索，再次让三模型投票；第二轮的输出无论是否达标都作为最终结果。最坏成本为 2M 次 LLM 调用。

**理论假设（Proposition 1）：**
- **少数投毒假设**：Ring 2 的多数词袋和 Ring 3 的多数投票，仅在检索集投毒比例 ρ < 0.5（毒文档不占多数）时才能恢复正确结果；ρ > 0.5 时多数信号被投毒文档主导，防御失效。
- **来源标签假设**：Ring 2 的来源权重只有在攻击者无法伪造可信来源标签时才有效。
- 作者明确指出：本文报告的单个评估配置与上述推导一致，但尚未通过 ρ 扫描实验独立确证该假设。

## 6. 主要结论与发现

- TriShieldRAG 将非自适应 PoisonedRAG 风格攻击的成功率从约 91% 降至约 13%，同时保持良性未投毒查询的准确性。
- 在非自适应场景中，**Ring 1（摄入守卫）承担了主要防御工作**——因为它是唯一逐文档独立检查、不依赖文档间多数表决的环节，其正确性不随 ρ→1 而退化。
- 残余约 13% 的攻击成功率，对应那些措辞接近自然语言、未能完全触发 Ring 1 词汇/模式检测的毒文档，且 Ring 2/3 未能从残留污染上下文中恢复正确回答的情况。
- 理论推导的少数投毒假设（ρ<0.5）与来源标签假设，与当前单配置评估结果一致，但尚未被受控实验独立证实。
- 结论是防御方案能在非自适应攻击者假设下显著降低知识污染攻击效果，但作者明确表示这是“初始版本”的结论，并非在最终规模下验证过的确定性结果。

## 7. 优点

- **纵深防御理念正确且必要**：三环各自检测不同信号（个体文档统计、跨文档信任、跨模型共识），攻击者无法通过规避单一检查点而击穿整个系统，直接回应了 PoisonedRAG 发现的“单阶段防御残余攻击率 ≥30%”问题。
- **形式化程度高**：每个环都有精确的算法伪代码、固定阈值、复杂度分析（Ring 1: O(k·|d|)；Ring 2: O(k·|d| + k log k)；Ring 3: ≤2M 次 LLM 调用），并非模糊的框架描述。
- **理论假设明确声明**：少数投毒假设和来源标签假设被显式地推导和陈述为适用前提，而非暗中假设；文中明确指出该假设尚未通过 ρ 扫描实验独立确认。
- **LLM 面板设计合理**：Claude、Mistral Small、Llama 3.2 来自三家不同组织和训练分布，降低了“单模型对某类毒文档存在共同盲区”的共因失效风险。
- **评估方式可控**：使用精确检索（IndexFlatIP）排除召回误差变量，使残余攻击率可归因于防御本身而非检索丢失；提供了 trace(...) 接口实现逐环决策可审计性（Golden Rule：不仅要评估最终答案，还要评估从查询到输出的完整路径）。
- **诚实透明的边界陈述**：明确承认未评估自适应攻击者、未做消融、未在百万级规模验证、未做 ρ 扫描，并将这些列为后续工作优先级，而非隐藏或美化。

## 8. 不足与局限

- **实验规模过小**：5,000 文档的知识库和 10 个目标问题，远未达到 PoisonedRAG 原始攻击验证的百万级规模；10 个问题也难以保证统计显著性。作者自己也将“规模差距”列为最高优先级后续工作。
- **自适应攻击者缺失**：所有结果仅针对非自适应攻击者。作者明确承认，针对了解并刻意规避 Ring 1 检测器的自适应攻击者（甚至白盒条件），防御效果尚未可知，这是当前最大的评估缺口。
- **理论假设未经实验确认**：少数投毒假设（ρ<0.5）和来源标签假设虽已被推导，但未通过 ρ 扫描实验独立验证其预测的“低于边界恢复正确/高于边界失败”行为；当前证据仅为“单配置一致”。
- **未做逐环消融**：无法量化每个环的独立边际贡献，也无法判断是否存在冗余或可简化环节。
- **对比数据不够扎实**：“论文单阶段防御”对比行标注为 illustrative，尚未用完整 30 题测试集计算出可严格对比的数值；也未与 TrustRAG、Cordon-MAS 等当代防御系统进行直接对比。
- **来源标签假设的现实脆弱性**：如果攻击者伪造或获取可信来源标签（如利用具备合法写权限的账户），Ring 2 的来源保障将完全失效；作者提出的密码学认证方案仅作为未来工作，尚未实现。
- **成本开销较高**：每次查询最多调用 LLM 面板 2M 次（三模型+可能重检索），相比未设防基线有显著的延迟与 API 成本；且 LLM 面板并非真正独立的“副本”（不满足经典 BFT 的独立失效假设，作者自己承认了这一点）。
- **Ring 1 检测器可被针对性规避**：模式检测依赖“逐字目标问题”、“套话短语”等人工规则，Ring 1 的防御强度依赖具体模式的设计质量，尚未在构造性规避测试中验证鲁棒性。
