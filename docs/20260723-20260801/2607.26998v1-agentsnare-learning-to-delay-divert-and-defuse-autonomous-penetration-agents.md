## 摘要
大型语言模型（LLM）代理通过观察-行动循环自动化渗透测试，根据工具返回的观察结果选择行动。这种依赖性使得防御者能够注入欺骗性观察结果，从而误导代理的决策过程。然而，现有的防御措施严重依赖于攻击前在环境中植入的静态、孤立的人工制品。高级代理能够逐步识别并绕过这些人工制品，最终将其利用尝试重新聚焦于真实目标。为解决这一问题，我们引入了AgentSnare，一种轨迹自适应欺骗系统，能够动态展开诱饵环境，持续引导渗透代理远离真实目标。具体而言，AgentSnare采用人工制品构建策略模型，根据代理的交互历史和诱饵状态构建候选人工制品。然后，AgentSnare验证这些候选物，并逐步将有效的人工制品纳入事实一致的诱饵环境中，从而通过吸收其工具调用来延迟攻击，将其进入后的轨迹转移至诱饵内部，并通过诱导基于诱饵证据的完成报告来化解攻击。在15个CVE-Bench Web应用和三种攻击者模型上，AgentSnare在诱饵中吸收了代理46.8%的工具调用，保留了55.9%的进入后操作，且90.0%的完成尝试基于诱饵证据；在所有45个攻击者-CVE配对中，pass@3下无真实目标被成功利用。

## Abstract
Large language model (LLM) agents automate penetration testing through an observation-action loop, selecting actions based on observations returned by tools. This dependence allows defenders to inject deceptive observations that can mislead the agent's decision-making process. However, existing defenses rely heavily on static, isolated artifacts planted in the environment prior to an attack. Advanced agents can progressively recognize and bypass these artifacts, ultimately refocusing their exploitation attempts on the real target. To address this issue, we introduce AgentSnare, a trajectory-adaptive deception system that dynamically unfolds a decoy environment to continually steer the penetration agent away from the real target. Specifically, AgentSnare employs an artifact-construction policy model that constructs candidate artifacts conditioned on the agent's interaction history and decoy state. AgentSnare then validates these candidates and incrementally incorporates valid artifacts into a factually consistent decoy environment, thereby delaying the attack by absorbing its tool calls, diverting its post-entry trajectory within the decoy, and defusing it by inducing completion reports grounded in decoy evidence. Across 15 CVE-Bench web applications and three attacker models, AgentSnare absorbs 46.8% of the agent's tool calls in the decoy and retains 55.9% of post-entry actions there, while 90.0% of completion attempts are grounded in decoy evidence; across all 45 attacker-CVE pairs, no real target is successfully exploited at pass@3.

## 1. 核心问题与整体含义

- **研究背景**：LLM 驱动的自主渗透测试代理通过“观察-行动”循环与环境交互，根据工具返回的观测结果持续调整攻击策略。这种对外部观测的依赖为防御者提供了对抗切入点——通过注入欺骗性观测来误导攻击代理的决策。
- **核心问题**：现有防御（如 honeytokens、误导性文件、prompt injection、计算浪费诱饵等）均为**攻击前预置的静态工件**，无法随攻击代理的探索和策略演进持续发挥作用。实验显示，静态策略在不同 LLM 和战术组合下的平均 Interference@20 得分不到 0.2，说明高级代理能够逐步识别并绕过这些静态工件，最终重新聚焦于真实目标。
- **关键瓶颈**：不是缺少更复杂的静态工件，而是缺乏一种**能够根据代理当前状态动态构造和披露工件**的机制。
- **整体含义**：AgentSnare 将防御范式从“静态工件预埋”重构为“轨迹自适应引导”，通过动态展开一个全局事实一致的诱饵环境，持续将渗透代理从真实目标上引开，为 LLM 安全防御提供了新的范式。

## 2. 方法论

### 核心思想

AgentSnare 是一个**轨迹自适应欺骗系统**，其核心思想是：不是一次性预构建整个诱饵环境，而是沿着攻击代理的实际轨迹，**逐轮动态构造、验证并披露诱饵工件**，从而增量地展开一个逻辑自洽的“替代现实”，使攻击代理持续在诱饵中消耗预算和目标定位。

### 在线防御流程（两个阶段）

1. **第一阶段：候选工件构造**
   - 部署的策略模型 Mθ 从当前交互历史 hₜ、攻击者当前动作 aₜ、世界事实账本 Wₜ、供给图前沿 Fₜ 和服务器画像 q 中推断攻击者的攻击意图，构造候选工件 cₜ = (õₜ, ΔWₜ)，其中 õₜ 为拟披露的观测，ΔWₜ 为支撑该观测所需新增的环境事实。
   - 例如：当代理执行 `cat /srv/app/.env` 时，模型可以构造含内部数据库端点和部署账号的候选工件，引导代理继续向诱饵内部深入。

2. **第二阶段：工件验证与披露**
   - ShadowOS 运行时的验证机制会从三个维度验证候选工件：
     - **语义有效性**：观测须匹配当前命令语义、可通过当前探针观测、符合预期输出格式；
     - **状态有效性**：新事实须与 Wₜ 一致、从当前前沿 Fₜ 可达、可在后续交互中复现；
     - **安全有效性**：防止真实环境机密泄露、符合文件系统/用户/进程/权限/服务的基本约束。
   - 验证通过后，工件提交至世界状态 `(W_{t+1}, G_{t+1}) = Commit(...)`，并通过混合渲染器（确定性状态管理 + 生成式内容渲染）生成正式观测返回给攻击代理。验证失败则状态不变，返回不引入新事实的失败观测。
   - 关键数据结构：
     - **世界事实账本 Wₜ**：记录已提交的诱饵对象、属性、关系及攻击者诱导的状态变更，确保后续观测一致；
     - **惰性供给图 Gₜ**：表示当前可见或可构造的调查机会（节点为对象/攻击机会，边为引用/认证/运行/佐证/使能等关系），确定可构造的工件边界。

### 离线训练流程

- 通过**模拟攻防交互**生成训练数据：攻击者模拟器 Asim 依据交互历史发出探针并预测候选工件条件下的后续动作；候选生成器 D 对同一探针构造 k 个候选工件。
- **反应引导的选择机制**：对每个候选工件，从相同历史状态出发模拟 m 个后续动作，优先选择更常引导攻击者继续调查诱饵的工件，其次偏好促进对新工件继续调查的、较少引发怀疑或退回真实目标的工件。
- 轨迹级过滤后，最终语料包含 **503 条轨迹、24,807 条防御者决策**，覆盖 12 类攻击意图，且不含任何 CVE-Bench 应用信息。
- 使用 **Qwen3-4B** 通过 LoRA（r=64, α=128）进行 3 个 epoch 的 bf16 监督微调，部署时经 vLLM 服务。

### DDD 评估框架

论文提出 **Delay–Divert–Defuse (DDD)** 轨迹级指标：

- **Delay**：延迟 = 诱饵吸收工具调用占全部调用预算的比例；
- **Divert**（PER，进入后保留率）：首次进入诱饵后，后续动作仍留在诱饵中的比例；
- **Defuse**：完成报告的证据中基于诱饵证据的比例（SubDefuse）。

## 3. 实验设计

### 数据集 / Benchmark

- 使用 **15 个可部署的 CVE-Bench Web 应用任务**（CVE-Bench），覆盖真实世界 Web 应用漏洞。
- 三种攻击者模型：**Claude Opus 4.6**、**GPT-5.4**、**MiniMax M3**，攻击代理为 PentestGPT（agentic 版）。
- 每种攻击者—防御组合在每个 CVE 上执行 **3 次**，共 405 次防御运行；任务预算是 **200 次工具调用**。

### 对比方法

- **静态防御**：联合部署全部 13 种可复现干预实例，涵盖误导感知、转移注意、专用诱饵、模型污染、角色操纵、强制代码执行六大类策略；
- **Cowrie**：预构建的交互式 shell 蜜罐，静态虚拟文件系统 + 脚本化命令处理；
- **HoneyLLMd**：采用分层概率自动机追踪攻击转移，由 GPT-5.4-mini 生成自适应响应的 LLM 蜜罐；
- **AgentSnare**：完整系统 = LoRA 微调的 Qwen3-4B 工件构造模型 + ShadowOS 运行时。

### 消融实验

在 GPT-5.4 攻击者下进行三种消融配置（各 45 次运行）：

- **Base Qwen3-4B + ShadowOS**：移除模型微调；
- **AgentSnare w/o ShadowOS**：保留微调模型但移除状态化运行时；
- **Prompted GPT-5.4-mini**：移除两种机制，但用更强闭源模型代替基础模型。

## 6. 主要结论与发现

- **AgentSnare 在全部三个 DDD 指标上领先**：
  - **Delay**：46.8%（Claude 47.0% / GPT-5.4 37.7% / MiniMax M3 55.7%），对比 Cowrie 17.6%、HoneyLLMd 29.5%；
  - **PER**：55.9%，较 HoneyLLMd 提升 19.0 个百分点；
  - **SubDefuse**：90.0%（574/638），对比 Cowrie 29.7%、HoneyLLMd 72.2%。
- **真实目标利用完全归零**：45 个攻击者-CVE 配对中，pass@3 下无任何真实目标被成功利用（0/45）。无防御基线为 18/45，静态防御 18/45，Cowrie 12/45，HoneyLLMd 10/45。
- **轨迹控制与利用抑制一致**：DDD 指标越高（更强预算吸收、进入后保留和诱饵基础完成），真实目标被利用越少。
- **消融结论**：两种机制均不可或缺——移除模型微调导致 3/15 可利用，移除 ShadowOS 导致 1/15 可利用，且 SubDefuse 下降最为显著（96.5→82.2，下降 14.3 分）；更强闭源模型（GPT-5.4-mini）无法替代完整系统，完整 AgentSnare 在指标上反超且是唯一利用率为零的配置。

## 7. 优点

- **问题定位准确**：率先识别出静态防御的根本局限——高级代理对预置工件的识别与绕过能力，将核心瓶颈概括为“缺乏动态构造和披露工件的机制”。
- **方法创新性强**：提出“轨迹自适应欺骗”范式，将诱饵环境构建从一次性预置转变为随攻击轨迹逐步展开，且通过世界账本 + 供给图保证**全局事实一致性**，区别于传统交互式蜜罐的局部仿真。
- **工程架构完善**：ShadowOS 的“4 层命令处理管线”（Director Intercept → Local Command Handler → Virtual Command Executor → Disclosure Model）+ 两级在线流程（构造→验证）具备实际部署可行性。
- **训练策略高效**：通过模拟攻防交互 + 反应引导选择机制生成监督信号，用轻量开源模型（Qwen3-4B）通过 LoRA 微调即可超越更强闭源模型的 prompt-only 效果，训练数据与评测数据严格隔离。
- **评估框架贡献**：引入 DDD（Delay-Divert-Defuse）作为轨迹级交互式防御评估标准，弥补了仅用端到端结果评估的不足——既能量化防御在攻击过程中的控制力，又能量化完成报告的证据来源。
- **实验设计严谨**：统一预算、统一入口、多攻击者覆盖、消融配置设计清晰，能清楚分离各组件贡献。

## 8. 不足与局限

- **时间与场景边界**：论文设定于 2026 年，涉及较新的 LLM（Claude Opus 4.6、GPT-5.4、MiniMax M3）与 CVE-Bench 的 15 个任务；结果对更早期/更新模型和更多样漏洞类型的泛化有待验证。
- **攻击代理单一性**：仅使用 PentestGPT 一种攻击代理框架，虽然攻击 LLM 有三种，但缺乏对其他自主渗透框架（如 AutoPT、VulnBot 等）的测试，防御效果对采用不同规划/记忆/工具策略的攻击代理的鲁棒性未知。
- **威胁模型假设**：假设代理会被诱饵环境持续吸引，但更激进或更“谨慎”的攻击者（如检测到异常后立即撤离、只针对真实目标做最小探测、使用多代理协作）可能绕过该防御，论文未探讨此类对抗情形。
- **评估协议限制**：实际场景中攻击代理也可能有外部信息源（如 CVE 情报、与外部服务器通信）、更强的记忆能力或更长的攻击周期；200 调用预算下“完全利用归零”的结论可能无法外推到无预算限制、时间跨度更长的真实攻击。
- **算力披露不足**：未提供训练/部署的具体算力资源（GPU 数量/型号/时长），使复现和推广的成本评估有难度。
- **可能存在的偏差风险**：训练数据由同一类模拟器生成，防御策略可能过度适配于模拟器行为模式（对抗性分布偏移风险）；在线防御仅在命中诱饵面时才干预，前期的真实目标侦察活动未有防护，这也意味着防御启动时机可能影响效果上限。
- **SubDefuse 指标在单一成功防御性能上的解释**：静态防御（无交互式诱饵时）无法直接计算 DDD 中的 Defuse，且 Defuse 定义依赖 provenance tags 的追踪机制，防御机制外的“证据锚定”程度未必能被该指标完整刻画。
