## 摘要
检索增强生成（RAG）系统越来越多地采用多个LLM智能体。然而，大多数先前的工作是孤立地优化各个组件，而不是协调整个流水线的改进。我们提出了GRADRAG，一个跨组件提示适配框架，它将RAG流水线建模为计算图，并传播结构化评估反馈以更新上游智能体。评估器对下游答案和支持证据进行批评，产生可操作的反馈，提示优化器使用这些反馈迭代更新自适应智能体，如检索器、图构造器和回答器。当输出被认为令人满意时，评估器还会触发提前停止。我们在SQUALITY和QMSUM基准上评估了GRADRAG，采用了两种检索范式：使用IRCoT风格查询细化的平面基于块的检索（Trivedi等人，2023），以及从文档构建并迭代丰富实体关系图的基于图的检索。在这两种设置中，GRADRAG始终优于仅更新最终生成器的一步细化基线，在LLM判断的成对比较中实现了12-15个百分点的净偏好裕度，并且大多数收益在两次细化迭代内实现。

## Abstract
Retrieval-Augmented Generation (RAG) systems increasingly employ multiple LLM agents. Yet, most prior work optimizes components in isolation rather than coordinating improvements across the pipeline. We introduce GRADRAG, a framework for cross-component prompt adaptation that models the RAG pipeline as a computational graph and propagates structured evaluation feedback to update upstream agents. An Evaluator critiques downstream answers and supporting evidence, producing actionable feedback that a Prompt Optimizer uses to iteratively update adaptive agents, such as retrievers, graph constructors, and answerers. The Evaluator also triggers early stopping when the output is deemed satisfactory. We evaluate GRADRAG on the SQUALITY and QMSUM benchmarks under two retrieval paradigms: flat chunk-based retrieval using IRCoT-style query refinement (Trivedi et al., 2023), and graph-based retrieval that constructs and iteratively enriches an entity-relation graph from the document. Across both settings, GRADRAG consistently outperforms one-step refinement baselines that update only the final generator, achieving a 12-15 percentage point net preference margin in LLM-judged pairwise comparisons, with most gains realized within two refinement iterations.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：检索增强生成（RAG）已从简单的“先检索后生成”流程演进为多智能体协作系统，多个基于LLM的组件分别承担查询改写、证据筛选、多步推理和答案评估等职责。
- **核心问题**：现有RAG多智能体系统的优化各自为政，通常只针对单个组件进行本地改进（如查询改写、证据过滤或答案自我修正），缺乏跨组件的协调机制。早期阶段引入的错误（如检索不完整、证据结构不良）会沿流水线向下传播，最终限制整体性能。
- **关键洞察**：最终生成阶段产生的评估信号很少被用来改进上游组件（如检索器、图构造模块），这构成多智能体RAG中的“协调问题”。
- **研究意义**：GRADRAG直接面向这一问题，提出通过**跨组件提示适配**，让下游评估反馈系统地更新多个上游智能体，从而实现检索、证据构建和答案生成的协调优化，而非孤立地优化各环节。

### 2. 论文提出的方法论

#### 核心思想
- **计算图抽象**：将RAG流水线建模为计算图，节点代表智能体（检索器、图构造器、答案生成器），边代表数据流转。LLM智能体节点关联提示词，部分提示词为**自适应**的，可随评估反馈迭代更新。
- **跨组件提示适配**：评估器（Evaluator）生成的反馈不仅用于改写最终答案，还通过提示优化器（Prompt Optimizer）转化为对多个上游智能体（检索器、图提取器等）的具体提示更新，实现协同优化。
- **早期停止**：评估器在每次迭代后返回二元决策，若输出令人满意则终止迭代，节省计算资源。

#### 算法流程（Algorithm 1）
1. 输入查询q、文档D、初始提示{p_a}和最大迭代次数T
2. 前向传播：执行完整RAG流水线，生成中间产物并组装证据，产出答案y_t
3. 评估：评估器审查答案与支持证据，返回反馈f_t和决策d_t
4. 若d_t = 满意，返回y_t；否则进入提示适配阶段
5. 提示适配：对每个自适应智能体a，更新提示p_a ← Optimize(p_a, f_t)
6. 重复直到达到最大迭代次数或提前停止

#### 两种具体实现
- **Vector RAG（平面检索）**：文档切分为重叠文本块，检索智能体采用IRCoT风格策略迭代生成子查询，结合稠密检索（FAISS）和词法匹配（BM25）。检索智能体的提示根据评估反馈更新，以生成更精准的子查询。
- **GraphRAG（图检索）**：文档切分为较大文本跨度，图提取智能体识别实体与关系，用Leiden算法做社区检测，为每个社区生成摘要和候选答案（带helpfulness分数），仅保留正分项组装证据上下文。评估反馈聚焦缺失实体/关系，迭代更新提取提示，有效诱导**面向任务的实体关系本体**。

#### 关键设计
- 所有优化**仅通过提示更新实现，不修改模型参数**
- 评估器不访问参考答案，防止数据泄漏
- 每个测试实例独立处理，优化提示在示例间重置，避免跨样本污染

### 6. 论文的主要结论与发现

1. **跨组件提示适配显著有效**：完整GRADRAG无论平面检索还是图检索，一致优于一步优化基线，胜率55%-57.5%，对应约**12-15个百分点的净偏好边际**。
2. **统计显著性**：4组主实验中3组p<0.05；QMSUM平面检索初始为边缘显著（p=0.090），额外增加一次迭代后转为显著（p<0.01），说明初始边际结果源于细化不充分而非评估不稳定。
3. **快速收敛**：提前停止平均发生在1.60-1.84次迭代之间（少于最大3次的预算），表明大多数增益在两次细化迭代内实现，少量额外迭代仍有提升。
4. **响应演化特征**：随着迭代推进，响应长度快速增加后趋于稳定；词汇密度持续上升；ROUGE-1单调提高；主题熵下降——细化主要提升**信息密度和主题聚焦度**，而非单纯添加内容。
5. **图检索的一致性更高**：图设置中的位置一致性（82.5%-87.9%）显著高于平面检索（55.1%-79.3%），说明图结构证据在评估中更稳定。
6. **框架通用性**：同一套反馈驱动优化逻辑可同时适用于扁平块检索和结构化图检索流水线，验证了计算图抽象的包容性。

### 7. 优点

- **方法创新**：明确提出并解决了多智能体RAG中的“协调问题”，将批评驱动提示优化从单一生成器扩展到多个上游组件，而非简单的答案自我修正。
- **高度模块化设计**：计算图抽象允许异构组件（经典检索器+LLM智能体）共存，并统一用提示更新实现优化，适用范围广。
- **防泄漏设计严谨**：评估器不接触参考答案；每个实例独立重置提示，杜绝跨样本信息蔓延。
- **受控消融**：基线和完整GRADRAG在同一架构、同一模型、同一检索策略下进行，唯一差异是是否为上游智能体更新提示，实验因果清晰。
- **评估稳健性**：采用LLM-as-a-Judge+人类验证双重机制，报告位置一致性、显著性检验，并分析早期停止与迭代预算的动态影响，实验方法论规范。
- **成本分析透明**：明确报告了运行时间、Token开销及未来的并行化与批处理优化方向。
- **早期停止机制**：在保证质量的同时控制计算消耗，具有实用性。

### 8. 不足与局限

- **计算成本较高**：每次迭代依赖多次LLM调用（生成+评估+提示优化），虽已分析成本构成，但对大规模部署仍是实际负担。
- **评估与部署存在差距**：评估协议为每个查询独立执行完整细循环，这确保了数据隔离，但不同于实际部署中的批次优化或持续性反馈场景；论文也承认这是未来工作方向。
- **评估器配置受限**：评估器仅依赖通用总结原则（连贯性、流畅性）而无外部奖励信号；引入奖励模型或启发式指标有望提高评估保真度。
- **实验覆盖不够全面**：未与DSPy、TextGrad等自动提示优化框架在RAG场景中做横向对比；模型和数据集范围有限，外部泛化性仍需验证。
- **QMSUM平面检索初始结果偏弱**：胜率虽高于50%但显著性不佳，揭示了LLM审判在长会议纪要场景中的偏好波动性，对此的深层原因分析不足。
- **提示优化器的收敛性缺乏理论保证**：论文未分析提示更新在多次迭代后是否会振荡或过拟合到特定查询，仅凭经验表明早期收敛良好。
