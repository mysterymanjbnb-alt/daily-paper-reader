## 摘要
我们介绍了\textbf{GPT-Red}，一个经过训练的自动化红队智能体，用于发现针对前沿大语言模型的新型提示注入攻击。该模型的目标是评估并提升我们生产系统的鲁棒性。为此，我们利用它对GPT-5.6进行对抗性训练，使其成为迄今为止对提示注入最为鲁棒的模型。为了创建GPT-Red，我们设计了一种可扩展的自我对弈算法，其中模型被赋予攻击一群同时训练的防御智能体的任务。我们使用与一些最大规模RL后训练运行相当的计算量，在逼真的红队环境中训练该模型，使其成为有记录以来规模最大的单一LLM安全训练运行。GPT-Red在红队测试方面表现出色：它能够可靠地攻破我们此前直到GPT-5.5的模型，找到比人类红队成员更成功的攻击，并且能够泛化到未见过的新环境、防御模型和测试装置中。未来，我们预期随着每个新GPT模型鲁棒性的提升，它将反过来为\textit{更强的}红队智能体提供更好的学习信号，从而开启自我改进的飞轮效应。

## Abstract
We introduce \textbf{GPT-Red}, an automated red-teaming agent that is trained to discover novel prompt injection attacks against frontier LLMs. The goal of this model is to evaluate and improve the robustness of our production systems. To this end, we use it to adversarially train GPT-5.6, our most robust model to prompt injections to date. To create GPT-Red, we design a scalable self-play algorithm where the model is tasked with attacking a diverse population of simultaneously-trained defender agents. We train the model on realistic red-teaming environments using compute on the same scale as some of our largest RL post-training runs, making it the single-largest LLM safety training run ever documented. GPT-Red excels at red-teaming: it reliably breaks our past models up to GPT-5.5, it finds more successful attacks than human red-teamers, and it generalizes to held-out environments, defender models, and harnesses. In the future, we expect that as we improve the robustness of each new GPT model, it will in turn will provide better learning signal for \textit{even stronger} red-teamer agents, thus unlocking a self-improvement flywheel.

- **核心问题**：大语言模型（LLM）在 agentic 场景（如工具调用、网络浏览、代码执行）中面临严峻的**提示注入攻击**安全威胁。攻击者可通过伪造工具输出、恶意网页、构造消息等方式操纵模型产生违背开发者或用户意图的行为。
- **现有对抗训练的不足**：基于 RL 的对抗训练（如 deliberative alignment）依赖人类红队、提示 LLM 或真实攻击生成的数据集，但此类数据集**规模有限**，模型容易过拟合到特定攻击模式，难以应对自适应对手（adaptive adversaries）。
- **核心洞察**：**训练化的红队智能体（trained red-teaming agents）** 能够以规模化、多样化和高质量的方式生成对抗数据，是有效鲁棒性训练的关键。然而现有的自动化红队方法在攻击目标真实性、环境多样性、训练与推理计算规模、算法复杂度等方面存在明显不足。
- **整体目标**：构建一个可扩展的**自我对弈（self-play）** 算法，让一个攻击者模型与一群防御者模型同时训练、相互进化。最终训练出的 GPT-Red 智能体既能用于评估模型鲁棒性，又能用于对抗性训练（adversarial training），显著提升下一代模型（GPT-5.6）的鲁棒性。


## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想：三维度协同缩放（Scaling Along Three Axes）

GPT-Red 的训练围绕三个维度的规模化展开：

1. **推理时间计算（Inference-time Compute）** ：通过 agentic 红队测试装置（harness）为攻击者提供 `defender_model` 工具，使其能够与防御者模型进行有状态、迭代式的交互试探，模拟人类红队的攻击细化过程。
2. **环境多样性（Environment Diversity）** ：将现有能力任务转换为对抗性 RL 环境（如允许攻击者编辑工具响应或本地文件的一部分），覆盖邮件、网页、函数调用、多模态视觉内容等多种真实攻击面。
3. **训练计算（Training Compute）** ：将训练规模提升至 OpenAI 大型 RL 后训练的水平（据称是**有史以来最大的单一 LLM 安全训练运行**），并扩展基本二人博弈，将攻击者与**多个不同防御者模型**同时对抗。

### 2.2 威胁模型与攻击者能力设定

- **攻击面（Attack Surface）** ：攻击者只能修改防御者轨迹中的**单个工具响应或部分非特权文件**（如搜索结果、邮件正文、本地文件），不能修改特权文件（如 `AGENTS.md`）或系统提示。
- **知识访问（Knowledge Access）** ：攻击者拥有**黑盒访问权**，可查询防御者模型，并观察攻击注入后的完整防御者轨迹（有时包括 token log-likelihood）。
- **有效性约束（Validity Enforcement）** ：通过程序化或 LLM 判定器拒绝不符合真实攻击约束的“奖励黑客”（reward hacking）行为，确保攻击合法、逼真。
- **对抗目标（Adversarial Objectives）** ：包括数据窃取、执行未授权代码、破坏性文件操作等。

### 2.3 推理时间扩展：defender_model 工具

- 攻击者模型有两个工具：**终端工具**（写文件、运行代码）和 **defender_model 工具**（提交攻击文件路径，获得防御者响应）。
- 防御者回应包含：完整轨迹、token log-likelihood、评判 LLM 反馈信号。
- 攻击者可以在一个 rollout 内迭代完善攻击，还能**编程化生成攻击**（如模板填充、字符串拼接、并行变体测试），提高 token 利用效率。
- 实验表明：在相同的防御者查询预算下，agentic harness 比独立的 best-of-N 采样攻击成功率更高，且随测试计算增加差距进一步拉大（Figure 3）。

### 2.4 自我对弈训练算法（Self-Play Training Algorithm）

算法每次迭代的流程如下（共 7 步）：

1. **初始化**：攻击者与防御者均为强 CoT 推理模型。
2. **采样 RL 环境**：包含对话、初始文件系统状态、选定的防御者模型。
3. **选择攻击注入点与目标**：攻击者收到上下文相关的情报（如最终用户消息、工具响应内容等）。
4. **攻击者 rollout**：允许攻击者调用 `defender_model` 迭代尝试攻击，完成后提交最终攻击（中间查询全部丢弃）。
5. **验证攻击合法性**：不合法则奖励为 0。
6. **执行防御者 rollout**：将攻击插入预设位置，恢复防御者轨迹运行。
7. **计算奖励并更新**：奖励通常是不对称的——攻击者因成功攻击获得正奖励，防御者因完成任务且抵抗攻击获得正奖励，用 RL 更新双方。

### 2.5 训练稳定性与多样性保障

- **健康的自我对弈动态**：实验中观察到攻击者不断发现新策略→防御者修复→攻击者转向新攻击的良性循环（Figure 4）；防御者的鲁棒性整体单调上升（Figure 5）；攻击者 checkpoint 对早期防御者的攻击能力单调增强（Figure 6）。
- **多防御者训练**：仅用单一防御者会导致攻击者模式崩塌（mode collapse）。训练攻击者对抗**9 个防御者**时，攻击者学会针对不同防御者“定制”攻击策略，避免了攻击的单一化（Figure 7）。
- **攻击者专用训练 vs. 自对弈**：仅训练攻击者（attacker-only）会让其在所训练的防御者上表现更好，但泛化到其他防御者上更差，且更容易模式崩塌。

### 2.6 红队训练环境（Red Teaming RL Environments）

论文构建了三类核心训练环境：

- **直接提示注入（Direct Prompt Injections）** ：基于 IH-Challenge（Guo et al., 2026）扩展，模型持有高优先级 system/developer 指令，攻击者可编辑低优先级 user/developer 消息，目标为触发指令层级（Instruction Hierarchy）违规。任务采用可验证奖励（如不泄露 PIN、正则替换、结构化解析）。
- **间接提示注入（Indirect Prompt Injections）** ：攻击者可编辑工具响应或文件，覆盖浏览（web search、deep research）、连接器（Gmail/Calendar）、函数调用（function calling）、agentic 编码（Codex 式文件系统交互）等场景。
- **多模态提示注入（Multi-modal Prompt Injections）** ：攻击者使用 OpenAI Images 2.0 生成图像攻击，应用于计算机使用智能体（CUA，屏幕截图注入）和浏览器/文档检索（图像替换/追加）场景。
- **安全拒绝越狱（Safety Refusal Jailbreaks）** ：攻击者将良性对话引导至恶意请求（如生物武器制造细节），用 rubric 评分衡量输出与“最大危害答案”的接近程度，并过滤含有现成有害内容或对话不自然的攻击。

### 5.2 实验充分性与客观性评价

**优点**：

- 实验覆盖范围广，从受控的 IH 任务到 IPI 挑战再到真实世界的售货机系统，体现出多层级的评估策略。
- 使用 GPT-5.1 作为固定防御者来评估不同攻击者，控制变量做得较好。
- 对 GPT-5.6 鲁棒性的评估包含 IID 攻击、持出数据集、持出领域、人类攻击、外部基准等多维度。

**潜在不足**：

- 部分实验（尤其是 GPT-Red 攻击成功率）未报告标准误差或多次独立运行的结果，统计显著性不明。
- 人类红队基线在 IPI 挑战中仅有一个数据集，缺乏更广泛的人类表现基准。
- 论文中提到的自对弈训练动态图（Figure 4、5）显示出理想化的单调趋势，可能选择了“表现最好”的训练运行进行展示，代表性未知。
- 由于训练环境大多基于 OpenAI 内部能力任务，评估结果的泛化性可能局限于相似分布的代理工作流。


## 6. 主要结论与发现

1. **GPT-Red 是强力的自动化红队智能体**：在 IPI Challenge 中，GPT-Red 的攻击成功率显著超过 GPT-5.5（有无 defender access）和人类红队成员，且随测试时间计算的增加持续改善。
2. **可扩展的自我对弈算法有效**：自对弈训练相比冻结攻击者显著加速防御者鲁棒性提升，训练出的攻击者泛化能力更强、不易模式崩塌。
3. **攻击者学习出新颖复杂的攻击策略**：如“伪造思维链”（fake Chain-of-Thought）攻击，在未见过的模型和环境上均有效；还能在图像中植入隐蔽指令、利用 n 元搜索定位 PIN 等。
4. **GPT-5.6 鲁棒性大幅提升**：GPT-Red 的对抗数据用于训练 GPT-5.6 后，在直接/间接提示注入的多项评估上均取得大幅改善。例如 Fake CoT 攻击鲁棒性从 5.2% 提升至 95.9%；IPI 2025 数据集上达到接近 100% 的鲁棒性。
5. **形成自我改进飞轮**：更强防御者迫使攻击者进化，更强攻击者暴露更多缺陷以训练更强防御者，形成“红队-防御者”螺旋式安全提升。


## 7. 优点：方法论的亮点

1. **三维度协同缩放**：将推理时间计算、环境多样性与训练计算三大要素统一起来，构建了系统性的规模化红队框架，思路清晰且可操作性极强。
2. **逼真的威胁模型**：攻击者只能修改防御者轨迹中未受信任的第三方内容，并通过程序化/LLM 判定器强制执行攻击约束，最大程度降低了“奖励黑客”风险。
3. **防御者模型的迭代交互机制**：`defender_model`工具不仅提高了攻击者在固定查询预算下的效率，还使其能进行程序化搜索和并行变体测试，展现出高度的自主性。
4. **多防御者自对弈**：有效避免了攻击者的策略坍缩，促进了对不同防御模型的个性化攻击策略发现，大幅提升攻击多样性。
5. **将能力任务转化为安全任务**：借用现有 agentic 能力训练的丰富环境来自动生成对抗场景，避免了额外的人工环境设计成本。
6. **实际部署价值**：不仅在评测中胜出，还在真实生产系统（Vendy）上成功完成任务，证明了实际攻击能力的有效性。
7. **对安全训练的闭环使用**：直接利用 GPT-Red 生成对抗训练数据，实现了评估与训练的紧密结合。


## 8. 不足与局限

1. **算力披露不足**：论文未提供 GPT-Red 训练的任何技术细节（GPU 型号/数量/时长），外部研究者难以复现或比较成本，降低了可重复性。
2. **实验透明性欠缺**：自对弈防御者、奖励信号、设计细节（如环境数量、数据规模、奖励权重）等关键信息未被完整披露，部分关键内容仅放在附录。攻击成功率未报告统计显著性或多次运行的标准差。
3. **潜在的选择偏差**：论文展示的训练动力学（如单调提升的鲁棒性）可能是特定运行的结果，未证明所有运行均稳定收敛；GPT-5.6 的鲁棒性评估使用“最强的攻击者都来自 GPT-Red 自身”的设定，存在一定的分布内偏差风险。
4. **领域覆盖不全面**：作者承认对多模态环境、多轮攻击场景和内容政策越狱的训练覆盖不足。评估主要集中在文本提示注入，其他类型的安全风险（如数据投毒、供应链攻击）尚未涉及。
5. **对既有模型的攻击成功率偏高但未报告平衡性**：论文指出 GPT-Red 对早期 GPT-5 模型的攻击成功率接近翻倍，但未衡量防御任务完成率等“副作用”指标。攻击有效性提升是否伴随明显的防御性能下降尚不明确。
6. **真实世界适用性有限**：对真实攻击者的威胁模型假设（如攻击位置预定义、防御者轨迹可见）在某些实际场景中可能过强，现实攻击者通常不具备完整观测能力。
7. **“人类红队更差”的结论需谨慎解读**：作者也承认不能据此认为 GPT-Red 普遍优于人类红队——人类可能在发现全新场景或攻击类别上具有不可替代的价值。
