## 摘要
智能体安全通常被视为一个关于行为内容的问题。防御措施关注指令是否看起来恶意，基准测试关注智能体是否执行了听起来有害的行为。\textbf{我们认为智能体安全本质上是一个情境问题，目前基于内容的框架系统性地对其进行了错误定义。} 一条“删除用户数据”的命令可能是一个常规的管理请求，也可能是一种针对生产系统的提示注入攻击，仅凭内容无法区分两者，而授权情境可以。在AgentDojo和WASP的每一个注入任务中，相同的动作都可能由已认证用户在常规工作流程中合理提出，这使得通过内容评估安全性的混淆成为一种结构性属性。我们通过四个必须共同成立并随智能体轨迹持续评估的属性来操作化情境安全。来源授权（Source Authorization）询问命令由谁发出；任务对齐（Task Alignment）明确智能体的授权目标；行为对齐（Action Alignment）评估每个行为是否服务于该目标；数据隔离（Data Isolation）管理跨权限边界的信息流。在此重新框架下，间接提示注入成为来源授权违规。快照基准在结构上无法评估数据隔离。现有防御措施按其实际近似的属性重新组织。情境化重构改变了哪些防御是连贯的、哪些评估措施有用，以及哪些攻击模式评估能够看到。

## Abstract
Agent security is widely treated as a question about action content. Defenses ask whether an instruction looks malicious. Benchmarks ask whether an agent performs a harmful sounding action. \textbf{We argue that agent security is fundamentally a contextual problem, and that the current content based framing systematically misdefines it.} A command to ``delete user data'' might be a routine administrative request or a prompt injection attacking production systems, and the content alone cannot distinguish the two. Authorization context can. Across every injection task in AgentDojo and WASP, the same action is one an authenticated user would plausibly request in a routine workflow, which makes the conflation a structural property of evaluating security through content.   We operationalize contextual security through four properties that must hold jointly and be evaluated continuously across the agent's trajectory. Source Authorization asks who issued the command. Task Alignment specifies the agent's authorized objective. Action Alignment evaluates whether each action serves that objective. Data Isolation governs information flows across privilege boundaries. Under this reframing, indirect prompt injection becomes a Source Authorization violation. Snapshot benchmarks are structurally incapable of evaluating Data Isolation. Existing defenses are reorganized around the property they actually approximate. The contextual reframing changes which defenses are coherent, which evaluations measure something useful, and which attack patterns evaluation can see at all.

### 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：当前智能体（Agent）安全研究普遍将安全问题视为“行为内容”问题——防御系统看指令是否像攻击，基准测试看智能体是否执行了听起来有害的操作。作者认为这种定义**系统性错误**。
- **关键观察**：一条“删除用户数据”或“向外部账户转账”的命令，既可能是合法操作，也可能是注入攻击。仅凭文本内容无法区分，但**授权上下文（Authorization Context）**可以。
- **结构性问题被忽视**：作者手动审查了AgentDojo和WASP的全部注入任务（45个），发现这些任务中的每个动作都可以在合法工作流中找到合理的对应场景。因此，这种混淆**不是边缘情况，而是基于内容评估的结构性缺陷**。
- **现实紧迫性**：智能体正被大规模部署到生产系统，AI安全标准正在围绕现有定义起草。错误的定义将导致错误的基准、防御与监管方向。

### 2. 方法论：核心思想与关键技术细节

#### 2.1 核心思想：将智能体安全重构为上下文问题

作者提出**上下文安全（Contextual Security）**框架，将授权状态分解为四个**必须联合成立**、且在智能体轨迹的**每个动作步骤上持续评估**的属性：

| 属性 | 核心问题 | 对应经典安全概念 |
|------|----------|------------------|
| **来源授权 (Source Authorization)** | 命令由谁发出，该来源是否被部署者授权？ | 认证、混淆代理问题 |
| **任务对齐 (Task Alignment)** | 智能体的总体目标是否被已认证来源批准？ | 授权策略、最小权限 |
| **行为对齐 (Action Alignment)** | 每个具体行为是否服务于当前目标？ | 引用监视器、控制流完整性 |
| **数据隔离 (Data Isolation)** | 信息流是否跨越了不应跨越的权限边界？ | 信息流控制、非干扰 |

#### 2.2 关键技术要点

- **联合评估而非独立检查**：行为对齐通过与否取决于任务对齐。若目标本身未授权，则服务该目标的行为仅满足行为对齐，但安全失败定位在任务对齐。因此四个属性**必须联合检查**。
- **持续评估而非快照评估**：四个属性必须在轨迹上持续验证。跨时间的攻击（如记忆投毒在若干步后触发违规）只有在完整轨迹上检查时才能显现。快照基准（每次任务重置上下文）在结构上无法看到这些模式。
- **违规定位**：安全失败被精确定位到“哪个属性被违背”，而非笼统地判定“指令是否恶意”。
- **重新定义攻击类别**：
  - 间接提示注入 → 来源授权违背（类似**混淆代理问题**）
  - 直接提示注入/越狱 → 任务对齐违背（用户已认证但请求了冲突或超出范围的目标）
  - 任务漂移/智能体错位 → 任务对齐违背（目标未经授权即发生转移）
  - 能力误用 → 行为对齐违背（目标完好，但具体行动超出授权范围）
  - 跨上下文信息泄漏、记忆投毒 → 数据隔离违背（信息跨越了用户、会话、权限或时间边界）
  - 攻击可能**级联**：例如来源授权失败 → 任务对齐失败 → 行为对齐失败 → 数据隔离失败。任一点上拦截均可阻断攻击链。

### 6. 主要结论与发现

1. **智能体安全是上下文问题**，不是内容问题。同一指令的合法性完全取决于谁发出、为何任务、信息流向何处。
2. **内容评估存在结构性缺陷**——45/45的注入任务均可对应合法场景，说明混淆并非偶然，而是评估范式本身的固有局限。
3. **四个属性（SA/TA/AA/DI）是定义智能体安全的最小完备集合**，每个属性都有对应的经典系统安全思想，且必须联合、持续地检查。
4. **间接提示注入被正确定义为来源授权违规**而非内容违规，这解释了为何纯粹的内容过滤器（如PIGuard）在良性文本上表现损失严重——它们指向了错误的属性。
5. **快照基准在结构上无法评估数据隔离**——跨会话信息泄漏在重置上下文的评估中根本不存在。
6. **防御应根据其实际逼近的属性重新组织**，投资应集中于“授权验证”而非“恶意文本分类”。
7. **粒度是防御的可调前沿**——每个属性可从粗粒度检查到细粒度追踪进行多种近似实现，操作者可按威胁模型调整投入。

- **定位的限制**：作为Position Paper，其目的是提出论点而非提供完整解决方案，未来仍需完成框架的量化评估和工程实现。
