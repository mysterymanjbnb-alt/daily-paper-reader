## 摘要
在过去十年中，我们见证了深度学习模型、平台和应用的指数级增长。虽然现有的深度学习应用和机器学习即服务（MLaaS）框架假设模型完全可信，但保护隐私的DNN评估需求应运而生。在安全多方计算场景中，模型和数据都被视为专有的，即模型所有者不想向用户透露极具价值的深度学习模型，而用户也不希望泄露他们的私有数据样本。传统的隐私保护深度学习解决方案要求用户将加密样本发送给模型所有者，模型所有者必须使用同态加密来处理密文域计算的繁重工作。在本文中，我们提出了一种新颖的解决方案，即PrivDNN，它（1）通过向用户共享加密的深度学习模型来将计算卸载到用户侧，（2）使用部分DNN加密显著提高DNN评估的效率，（3）使用核心神经元选择和加密方案确保模型准确性和模型隐私。实验结果表明，PrivDNN在保持模型性能和隐私的同时，将隐私保护的DNN推理时间和内存需求最多减少97%。代码可在https://github.com/LiangqinRen/PrivDNN找到。

## Abstract
In the past decade, we have witnessed an exponential growth of deep learning models, platforms, and applications. While existing DL applications and Machine Learning as a service (MLaaS) frameworks assume fully trusted models, the need for privacy-preserving DNN evaluation arises. In a secure multi-party computation scenario, both the model and the data are considered proprietary, i.e., the model owner does not want to reveal the highly valuable DL model to the user, while the user does not wish to disclose their private data samples either. Conventional privacy-preserving deep learning solutions ask the users to send encrypted samples to the model owners, who must handle the heavy lifting of ciphertext-domain computation with homomorphic encryption. In this paper, we present a novel solution, namely, PrivDNN, which (1) offloads the computation to the user side by sharing an encrypted deep learning model with them, (2) significantly improves the efficiency of DNN evaluation using partial DNN encryption, (3) ensures model accuracy and model privacy using a core neuron selection and encryption scheme. Experimental results show that PrivDNN reduces privacy-preserving DNN inference time and memory requirement by up to 97% while maintaining model performance and privacy. ## 1. 核心问题与整体含义（研究动机与背景）

- **隐私困境**：在深度学习即服务（MLaaS）场景中，深度神经网络模型和数据均具有高度专有性——模型所有者不愿泄露其高价值模型，数据所有者也不愿暴露私有数据。传统明文推理无法解决这一问题。
- **现有方案的不足**：传统隐私保护方案（如 CryptoNets）要求用户将加密样本发送给模型所有者，由服务方在密文域执行全部推理。FHE 计算开销极大（如 CryptoNets 评估 MNIST 需 250 秒），成为实际部署的主要瓶颈。
- **问题定位**：本文将其定义为安全两方计算问题，需要同时保护 **DNN 模型隐私** 与 **用户数据隐私**。在需要保护模型而非测试样本的场景中，作者发现一个关键洞察：**并非所有神经元都需要加密**——只加密对模型性能至关重要的“核心神经元”即可实现保护目标，同时大幅降低计算开销。
- **研究意义**：为隐私保护深度学习推理提供了一种兼顾效率与安全性的新范式，使大规模 DNN 模型的加密推理在普通桌面设备上成为可能。

## 2. 方法论

### 2.1 核心思想
- **部分 DNN 加密（Partial DNN Encryption）**：仅加密 DNN 中少数“核心神经元”（过滤器），其余神经元保持明文。
- **模型加密路径**（如图 1(D) 所示）：模型所有者 S 将部分加密的 DNN 共享给数据所有者 C，C 在本地执行推理，将密文中间结果发送给 S 解密，再继续明文层推理，最终获得标签。
- **授权 vs 未授权用户**：
  - **授权评估**（A_s）：合法用户获得解密后的密文神经元输出，与明文路径拼接，精度接近原始模型（A_o）。
  - **未授权评估**（A_r）：非法用户无法解密密文输出，核心神经元等效“被移除”，模型精度大幅下降。

### 2.2 关键技术细节
- **FHE-Friendly DNN 设计**：使用平方函数（Square）作为密文域激活函数；仅加密的神经元需满足 FHE 兼容性要求。
- **核心神经元选择**——设计四个算法：
  - **随机选择（基线）**：随机选取过滤器，作为对照组。
  - **贪心选择**：逐层、逐神经元评估质量分数，选择使核心集质量分数最高的神经元加入加密集合。
  - **基于剪枝的选择**：采用 PFEC、FPGM、HRank、GFS 四种结构化剪枝算法识别“重要”过滤器作为核心神经元。
  - **剪枝+贪心**：先用剪枝方法缩小候选池（池大小为目标的 2 倍），再用贪心策略精选，兼顾效率与性能。
- **核心集质量分数**（用于评估选择方案）：

  s = -sigmoid(A_o - A_s) + sigmoid((A_s - A_r)/α)，其中 α=5（经验值）

  第一项惩罚授权精度的下降，第二项奖励未授权精度的降低。
- **部分 DNN 加密的两种世界**：明密文计算自然分离——明文世界输出不能输入密文世界（除非加密），密文世界输出不能直接输入明文世界（除非解密）；最终通过 S 的解密操作汇合。

## 6. 主要结论与发现

1. **贪心算法高效且高质量**：在 18 组配置中，13 组找出了 ground truth 最优的核心集，其余 5 组排名也在前 0.027% 以内，显著优于随机选择。
2. **部分加密的有效性**：仅加密前两个卷积层中 15%-25% 的神经元，即可将未授权精度降低约 20%，使其实际不可用。
3. **计算效率大幅提升**：
   - 密文操作减少 85%-98%（基于加密比 ER 和操作分布分析）。
   - 对 MNIST/LeNet-5，PrivDNN 推理耗时 190 秒，而全模型加密需 5,647 秒，加速约 **29.7 倍**。
   - 内存占用从全加密的 151GB（不可行）降至 2.5-5GB。
4. **安全性**：
   - 模型恢复攻击难以成功：恢复精度通常显著低于授权精度，且增加加密神经元数量后恢复难度大幅上升；对大模型（如 VGG16/CIFAR10），加密 75% 前两层神经元后恢复精度仅 58.2%，加密 100% 时降至 30.18%。
   - 样本恢复攻击（split learning 与 autoencoder）在客户端混淆保护下无法恢复有意义图像。
5. **性能与安全可权衡**：加密比例越高，A_r 越低（CIFAR10 从 55.90% 降至 9.78%），效率线性下降，但大模型因加密神经元占比很小（前两层 <5% 参数），仍保持高效。

## 7. 优点

- **思想新颖**：首次提出“部分 DNN 加密”用于模型保护，打破“全模型加密”的惯例，挖掘了模型保护场景中无需全加密的重要特性。
- **效率突显**：将繁重的密文计算从服务器转移到受益方的同时，大幅削减密文操作量；实验结果明确证实了 1-2 个数量级的性能提升。
- **通用性强**：框架不依赖特定 FHE 算法、同态操作或 DNN 架构，可适配任何 FHE 方案的模型加密系统。
- **实验严谨**：通过穷举搜索建立 ground truth、引入质量分数进行定量评估、对多种选择算法（随机/贪心/剪枝/剪枝+贪心）进行系统性对比。
- **安全性分析全面**：覆盖诚实但好奇、恶意数据所有者（权重窃取、模型恢复）和恶意模型所有者（样本推理）等多类攻击模型，并提出服务器端多态混淆层等防御措施。

## 8. 不足与局限

- **优化器选择不一致**：不同数据集使用不同优化器（Adam vs SGD），虽然合理但可能影响公平对比的严谨性。
