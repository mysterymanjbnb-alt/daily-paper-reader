## 摘要
大语言模型（LLM）智能体自主地将语义推理与复杂的系统操作交织在一起。在这些动态环境中，静态的工具级权限从根本上是不够的；安全授权高度依赖上下文，并严重依赖于不断变化的运行时状态和数据流。我们提出了FAVA（可验证智能体的形式化授权），一个用于智能体执行的携带权限的授权框架。FAVA利用LLM引导的权限中间表示（IR）将模糊的自然语言任务转化为结构化约束。然后，一个确定性的降级过程将该IR转换为一个基于证据的权限图，显式跟踪数据流、依赖关系和上下文标签。为了提供严格的安全保证，一个可满足性模理论（SMT）授权器在任何有效操作执行之前，根据安全策略对当前图进行数学验证。随后，一个运行时网关强制执行求解器的结果，要么授权执行，要么用精确的反例进行拦截。我们在OpenAgentSafety、OctoBench和ActPlane场景上评估了FAVA。我们的评估表明，FAVA在总体数据集上实现了90.5%的决策合规率（DCR），成功拦截了所评估的轨迹条件场景中的动态违规轨迹。

## Abstract
Large language model (LLM) agents autonomously interleave semantic reasoning with complex system operations. In these dynamic environments, static tool-level permissions are fundamentally insufficient; safe authorization is highly context-dependent and heavily reliant on evolving runtime states and data flows. We present FAVA (Formal Authorization for Verified Agents), a permission-carrying authorization framework for agent execution. FAVA utilizes an LLM-guided Permission Intermediate Representation (IR) to translate ambiguous natural-language tasks into structured constraints. A deterministic lowering pass then converts this IR into an evidence-backed permission graph that explicitly tracks data flows, dependencies, and contextual labels. To provide strict security guarantees, a Satisfiability Modulo Theories (SMT) authorizer mathematically verifies the current graph against security policies before any effectful action executes. A runtime gateway then enforces the solver's result, either authorizing the execution or intercepting it with a precise counterexample. We evaluate FAVA across OpenAgentSafety, OctoBench, and ActPlane scenarios. Our evaluation demonstrates that FAVA achieves a 90.5% Decision Compliance Rate (DCR) over the aggregate dataset, successfully intercepting dynamic violating traces in the evaluated trace-conditioned scenarios.

## 2. 方法论：FAVA 框架

### 2.1 核心设计思想

FAVA 的核心理念是**将语义权限提取与最终安全授权严格分离**：
- LLM 只负责它擅长的事——把歧义的自然语言任务解析为结构化的**权限 IR**（Permission IR）；
- 最终安全决策由**确定性降级（lowering）**和 **SMT 求解器**完成，而非依赖 LLM 的不透明“安全/不安全”判断。

### 2.2 技术流程

**① 证据获取与 Permission IR 构建**
- 以 LLM 作为语义提取器，将任务文本、执行契约、运行时轨迹解析为统一的 Permission IR；
- IR 包含五个核心字段：`intent`、`assets`、`actions`、`obligations`、`sinks`，以及连接各字段到其来源的 `evidence` 证据片段；
- 动态运行时轨迹也被映射到相同的 IR 格式，保证静态任务与动态执行表示统一，仅证据来源不同。

**② 权限图降级（Graph Lowering）**
- 确定性降级过程将 Permission IR 转换为**基于证据的权限图** G = (V, E)；
- 节点（Node）带有证据支撑的安全标签（如 `secret`、`destructive`），边（Edge）编码依赖关系（数据流 `data`、控制流 `control`、父节点 `parent`）；
- 类型化边的信任来源分为 `observed`、`policy`、`inferred`，其中 `inferred` 仅用于审计提取错误；
- 关键原则：**消毒（sanitization）必须有明确的受信转换器规范**（如 `redact(secret) -> safe_text`），模糊的 LLM 断言（如“summary”）不被视为消毒器；
- 图在进入 SMT 求解器前需经过严格的结构与证据验证，拒绝畸形结构。

**③ SMT 授权（SMT Authorization）**
- 将权限图上的授权问题转化为可满足性模理论（SMT）问题，沿两个维度求解：
  - **数据流污点传播**：标签（如 `secret`、`pii`）沿依赖边传播（除非经过受信消毒器转换）；
  - **能力授权**：评估候选动作所需的能力（capability）是否与核心策略（禁止标签→汇点流，如 `secret -> net:*`）冲突。
- 关键公式：
  - 标签传播：$H[v,\ell] = Explicit(v,\ell) \lor Source(v,\ell,P) \lor \bigvee_{u \in Pred(v)} H[u,\ell]$
  - 安全约束：$\forall v. \neg (H[v,\ell] \land A[v,c])$（禁止带保护标签的节点获得匹配汇点的能力）
  - 义务编码（如“通过测试后才可提交”）：$A[v, commit] \Rightarrow Seen(tests\_passed, v)$
- 求解器返回**已授权能力集**或**精确反例**（包含违规节点、标签、汇点及污点路径）。

**④ 单调运行时修复与强制执行网关**
- 运行时事件**严格追加**新节点、边、标签与证据，已建立的约束从不被静默丢弃；
- 在任何有效操作执行前，网关运行 SMT 授权器；若发现违反则**拦截**并给出反例路径；
- 若未发现显式禁止流但风险姿态为 `sensitive`、`dangerous` 或 `ambiguous`，网关**默认失败关闭（fail closed）**。

**⑤ 安全假设与适用边界**
- 形式化保证依赖三个工程假设：所有安全相关运行时效应必须经过网关；后端执行必须符合能力约束；策略翻译与消毒器规范属于可信计算基。
- 形式化保证严格限于权限图抽象，不涵盖上游自然语言提取的完备性或隐式流发现。

**伪代码（Algorithm 1）要点**：
1. 为每个节点建立标签存在变量 H[v,ℓ] 和能力授予变量 A[v,c]；
2. 按标签传播规则（或受信消毒器转换）断言 H[v,ℓ]；
3. 对必需能力断言硬约束，对可选能力用软目标最小化；
4. 对每条禁止规则断言 $\neg(\bigvee_{\ell \in Labels(f)} H[v,\ell] \land \bigvee_{c \in Match(v,Sink(f))} A[v,c])$；
5. 满足则返回授权能力集，否则二次求解提取反例轨迹。

## 6. 主要结论与发现

1. **FAVA 在总体 801 例评估中实现 90.5% DCR**，在 ActPlane Public 与 ActPlane Traces 上达到 100% DCR（0 FP、0 FN）。
2. **现有机制呈两极化失败**：词法/OS 级方法（Regex Guard、ActPlane）严重过度拦截，提示词级方法（GuardAgent）和朴素适配器（AgentSpec）严重欠拦截（大量 FN）。
3. **语义标签是最关键组件**：去除标签后 DCR 骤降至 7.4%（OctoBench）和 15.6%（OAS），说明没有语义基础的图结构无法形成有效授权依据。
4. **SMT 全局推理不可替代**：局部启发式无法替代全局约束求解，这表明 SMT 不是装饰性组件。
5. **运行时网关对动态场景至关重要**：在 trace 条件下，禁用网关导致 DCR 从 100% 降至 40%。
6. **效率可观**：每调用 JIT 授权中位数 <1ms（0.845ms），端到端运行集成开销极小（0.3%），验证了形式化方法可实时嵌入智能体循环。
7. **失败的根源集中在语义提取而非数学决策规则**：76 个错配案例中，39.4% 为“良性敏感上下文误标”，27.7% 为“安全关键词误触发”，26.6% 为“保护标签遗漏”，3.2% 为“维护操作误判为破坏性”，3.2% 为“不可信过度传播”。

## 7. 优点

- **架构创新**：将 LLM 的语义理解与形式化安全验证严格解耦，避免在授权决策中直接信任 LLM 判断，这是对现有方案的根本性改进。
- **形式化保证**：SMT 授权器在有限权限图上提供可证明的标签→汇点可达性安全性，支持**精确反例返回**，可审计性强。
- **单调修复机制**：运行时事件只增不改的单调图更新，配合 JIT 重新授权，有效防“上下文失忆”。
- **输入表示统一**：自然语言任务、执行契约和运行时轨迹映射到同一 Permission IR 格式，架构一致性好。
- **工程实现完善**：提供了完整的算法伪代码、图 schema 设计，实验部分对失败案例做了归因分析。
- **安全性优先的设计立场**：默认失败关闭策略突出安全优先，有意权衡了工具性与安全。

## 8. 不足与局限

- **上游提取的固有脆弱性**：形式化保证始于 Permission IR 降级之后；LLM 提取遗漏标签、义务或错误识别风险标签仍会导致假阴性。FAVA 无法保证自然语言理解阶段的完备性。
- **隐式流不可见**：仅跟踪显式数据流，未处理隐式信息流（如侧信道）。
- **原型简化**：作为逐实例（per-instance）网关，未建模并发工具调用、Shell AST 细粒度结构、TOCTOU 竞态等底层执行复杂性。

- **基准对齐不足**：ActPlane 在统一二进制标签框架下被评估时无法利用其原生优势，导致对比公平性存疑。
- **重实现基线偏差风险**：AuthGraph 和 SafeAgent 因无公开实现而为作者自行构建的近似版本，可能未完全代表原系统能力。
- **算力信息缺失**：论文未报告任何 GPU/算力配置，难以评估实际部署成本。
