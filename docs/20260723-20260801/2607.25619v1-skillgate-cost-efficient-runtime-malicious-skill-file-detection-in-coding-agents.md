## 摘要
软件工程团队现在将AI编码代理（如Cursor、Claude Code、GitHub Copilot）作为一等生产力工具部署，安装领域特定的技能文件，以针对项目API、框架约定和组织工作流定制代理行为。这些复杂的Markdown文件只需一条npx skills add命令即可从公共注册表轻松下载，且没有真正的安全筛查，代表了一个新的供应链攻击面：恶意技能文件可以静默地重新编程代理行为，窃取凭证，将后门注入生成的代码，或将代理操作重定向到攻击者控制的端点。这种威胁并非假设：最近的报告记录了公共注册表中的数百个恶意技能包，包括通过虚假生产力技能分发窃取凭证的窃密软件的有组织活动。针对这一攻击面，目前尚不存在系统性的工具链防御。我们提出了SkillGate，一个可部署的安全网关，在编码代理安装之前对AI技能包进行筛查。SkillGate采用混合的正则预过滤+LLM评判器流水线：安全信号文件完全绕过LLM（跳过节省）；被标记的文件仅将其匹配的片段窗口发送给评判器，而非完整内容（片段节省）。我们回答了四个研究问题，涵盖检测有效性、筛查成本、运行时开销以及在SkillsBench基准上相对于两个现有工具的误报行为。在SkillsBench（n=1,650，9.1%恶意）上，SkillGate达到了F1=0.817，FPR=1.13%，同时与完整文件筛查相比，LLM输入token减少了77%，并且在阈值无关的AUPRC上比现有工具高出5-6倍（0.830对比0.144/0.162）。

## Abstract
Software engineering teams now deploy AI coding agents (Cursor, Claude Code, GitHub Copilot) as first-class productivity tools, installing domain-specific skill files to tailor agent behavior to project APIs, framework conventions, and organizational workflows. These complex Markdown files are easily downloaded from public registries with a single npx skills add command and no real security screening, representing a novel supply-chain attack surface: a malicious skill file can silently reprogram agent behavior, exfiltrating credentials, injecting backdoors into generated code, or redirecting agent actions to attacker-controlled endpoints. The threat is not hypothetical: recent reports document hundreds of malicious skill packages in public registries, including organized campaigns that distributed credential-stealing infostealers via fake productivity skills. No systematic toolchain defense exists for this attack surface. We present SkillGate, a deployable security gateway that screens AI skill packages before coding agent installation. SkillGate uses a hybrid regex-prefilter + LLM-judge pipeline: safe-signal files bypass the LLM entirely (skip savings); flagged files have only their matched snippet windows sent to the judge, not the full content (snippet savings). We answer four research questions covering detection effectiveness, screening cost, runtime overhead, and false positive behavior on the SkillsBench benchmark against two existing tools. On SkillsBench (n=1,650, 9.1% malicious), SkillGate achieves F1=0.817, FPR=1.13% while reducing LLM input tokens by 77% vs. full-file screening, and outperforming existing tools by 5-6x on threshold-independent AUPRC (0.830 vs. 0.144/0.162).

## 1. 论文的核心问题与整体含义

**研究动机与背景：**

- **新型攻击面**：AI编码代理（Cursor、Claude Code、GitHub Copilot等）已从自动补全工具演变为自主执行任务的智能体。开发者通过安装"技能文件"（Skill Files）——即包含工具定义、API参考、工作流指令的Markdown文档——来定制代理行为，使其适应特定项目需求。
- **供应链风险**：技能文件通过 `npx skills add <package>` 等命令从公共注册表一键安装，**没有任何安全筛查机制**。恶意技能文件可在安装后静默劫持代理行为：窃取API密钥/SSH凭证、向生成的代码注入后门、或将代理操作重定向至攻击者控制的端点。
- **威胁现实性**：2026年2月的"ClawHavoc"活动在ClawHub注册表中投放了1,184个恶意技能包（约占20%），通过虚假生产力技能分发凭证窃取软件。这不是假设性威胁。
- **防御空白**：传统供应链安全工具（Semgrep、Snyk等）针对源代码而非自然语言行为指令；既有技能文件扫描工具（ClawVet、SkillScanner）误报率过高（FPR>40%），不具备实际部署可行性。
- **核心研究问题**：如何在不牺牲检测精度的前提下，为技能文件安装提供**低成本、可部署**的运行时安全筛查？

## 2. 论文提出的方法论

**核心思想**：采用**混合"正则预过滤 + LLM评判器"两阶段流水线**，通过两个互补的降本原则实现低成本高精度检测：

- **跳过节省（Skip Savings）**：无正则匹配的文件完全绕过LLM，以近零成本判定为安全。
- **片段节省（Snippet Savings）**：被标记的文件仅将匹配的片段窗口（而非完整内容）发送给LLM评判器。

**系统流水线（四阶段）：**

1. **Stage 1：运行时代理与内容提取**
   - SkillGate作为Unix-socket守护进程，充当编码代理与上游MCP服务器之间的透明代理。
   - 拦截所有 `tools/call`、`resources/read`、`prompts/get` MCP响应，提取技能文件内容。
   - 集成仅需一行配置更改，支持五种主流编码代理。
   - 另提供 `npx skills add` 命令的PATH垫片封装，在安装前拦截并筛查。

2. **Stage 2：正则预过滤器（RuleEngine）**
   - 编译 **530条模式**：428条源自MITRE ATT&CK框架的核心模式 + 102条Sigma社区规则。
   - 主要模式类别涵盖：防御规避（62）、执行（56）、风险命令（56）、凭证访问（44）、持久化（38）、影响（33）、混淆（27）、外泄（27）、发现（23）、命令与控制（21）等。
   - 关键设计：**预过滤器是"门"而非"分类器"**——匹配命中不直接产生最终标签，全部判定权交给LLM评判器，避免纯正则方法的高误报率。
   - 零命中文件直接判定为SAFE，不调用LLM。

3. **Stage 3：片段提取与LLM评判器**
   - 对每个命中位置生成字符窗口 `[match.start - 500, match.end + 500]`（默认cw=500字符）。
   - 重叠窗口去重，最多拼接20个窗口（ms=20），前置约700字符的元数据（包名、文件路径等），总片段上限8,000字符。
   - 提交给LLM（默认：gpt-5.4-mini），返回标签（SAFE/SUSPICIOUS/MALICIOUS）、置信度[0,1]、风险标签和推理。

4. **Stage 4：策略引擎与审计日志**
   - 策略映射：MALICIOUS(conf≥0.7)→BLOCK；SUSPICIOUS(conf≥0.5)→QUARANTINE；SUSPICIOUS(conf<0.5)→WARN；SAFE→ALLOW。
   - 所有决策写入JSONL审计日志，支持事后取证分析。

## 3. 实验设计

**数据集 / Benchmark：**

- 使用 **SkillsBench** 开放基准数据集：1,500个真实良性技能文件 + 150个手工构建的恶意技能文件，总计 **n=1,650**，恶意率9.1%。
- 恶意文件覆盖8种攻击类别：明文命令、数据外泄、编码载荷、隐写术、RSA模运算、ASCII走私、二进制执行、远程脚本。

**对比方法：**

- **ClawVet**：静态分析工具，54条手写模式、6个分析通道，在oracle最优阈值下评估。
- **SkillScanner** (v2.0.11)：Cisco AI Defense多引擎扫描器，静态YARA/正则规则 + 行为控制流图，在oracle最优严重度阈值下评估（报告5个严重度级别）。
- **SkillScanner+LLM**：每个文件都升级到与SkillGate相同的LLM评判器（gpt-5.4-mini），共1,650次调用。

**评估指标：**

- Precision、Recall、F1、误报率（FPR）
- Matthews相关系数（MCC）：对类别不平衡鲁棒，考虑混淆矩阵全部四个单元
- AUPRC（平均精度）：主要阈值无关指标
- Token计数：tiktoken o200k_base分词器
- 延迟：守护进程收到文件到最终策略决策的墙钟时间

## 6. 论文的主要结论与发现

**RQ1 — 检测效果**：

- SkillGate达到 **F1=0.817、Recall=0.769、FPR=1.13%、MCC=0.803、AUPRC=0.830**。
- 相比ClawVet（AUPRC=0.144）和SkillScanner（AUPRC=0.162），AUPRC提升 **5–6倍**。
- MCC比最强基线高2.4倍（0.803 vs 0.331）。

**RQ2 — Token成本**：

- LLM输入token减少 **76.9%**（3,022,409 → 699,085，4.3倍压缩）。
- 由两部分构成：67.2%文件完全跳过LLM（1,110/1,650）；被标记文件仅发送片段窗口而非完整内容。

**RQ3 — 运行时延迟**：

- 加权平均延迟 **约818ms**（prefilter-safe路径约139ms占67.2%；LLM路径约2,208ms占32.8%）。
- 比SkillScanner+LLM（约6,281ms）快 **7.7倍**。
- 与0.5–5秒的注册表获取时间兼容。

**RQ4 — 误报分析**：

- 平均仅17个误报（FPR=1.13%），vs ClawVet的756个（50.4%）和SkillScanner的261个（17.4%），减少 **15–44倍**。
- 误报主导类别：文档中base64编码内容触发编码载荷预过滤规则（占71%）。
- 仅约3个达到block级严重度（0.20% block级FPR），而ClawVet误拦296个良性技能（19.7%）。

**消融研究关键发现**：

- 纯预过滤器Recall=0.900但FPR=27.1%不可部署；LLM评判器将FPR降至1.13%，代价是牺牲部分Recall（0.900→0.769），但净收益显著。

- FPR在接近全部阈值范围内（θ∈[0.06, 0.99]）保持在5%以下，无需逐部署调参；F1最优阈值θ≈0.14。

## 7. 优点

1. **新颖且针对性强的防御视角**：针对"代理指令层"（agent instruction layer）的供应链攻击——这一此前无人系统化防御的攻击面，而非传统的代码执行层。
2. **创新的混合架构**：正则预过滤 + 片段级LLM评判的流水线同时解决了纯静态方法的高误报率和全量LLM筛查的高成本两个问题，且两大降本原则（跳过节省+片段节省）有清晰的定量归因。
3. **严谨的实验设计**：oracle最优阈值偏袒基线使对比保守；三重运行处理LLM不确定性；MCC和AUPRC作为不平衡鲁棒指标避免F1夸大问题。
4. **系统性消融**：隔离预过滤器贡献、片段设计贡献、超参数敏感性，归因清晰。
5. **实际可部署性**：~818ms延迟、1.13% FPR、一行配置集成，满足安装时（install-time）实时筛查的现实约束。开源发布完整实现、530条规则集和评估框架。
6. **客观的自我评价**：明确报告了局限性（编码混淆类剩余漏报、仅单一LLM后端、不在野样本验证），无过度宣称。

## 8. 不足与局限

1. **恶意样本代表性有限**：SkillsBench的150个恶意文件为手工构建的攻击样例，非在野捕获，测量到的召回率可能无法迁移到有机演化的真实攻击活动（ClawHavoc等未纳入评估）。
2. **预过滤器覆盖率存在盲区**：基于MITRE ATT&CK推导的模式无法保证覆盖全部已知模式；RSA模运算、零宽字符等编码混淆技巧导致的残余漏报暴露了具体的覆盖缺口。
3. **LLM后端单一性**：所有实验仅使用gpt-5.4-mini；其他后端（如claude-haiku-4-5、本地Ollama）上的性能未验证。三周实验窗口还可能跨越了提供方模型更新。
4. **非自适应对手假设**：威胁模型假设对手不知道SkillGate部署、未检查规则集；能逆向工程的适应性攻击者不在范围内。
5. **配置参数为预指定**：上下文窗口（cw=500）和置信度阈值（θ=0.70）在留出开发集上预指定，无法完全排除其他配置改变精度-成本权衡的可能。
6. **短文件场景token节省有限**：对于非常短的技能文件，固定前置文本（约700字符）在每个请求中占主导，碎片化节省的效果会减弱。
7. **依赖LLM-as-a-judge的测量误差**：最终标签依赖LLM评判器，与纯人工审查相比存在测量误差风险；误报类别的分类基于有限样本（26个文件联动分析）。
