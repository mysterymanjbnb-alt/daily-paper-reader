## 摘要
基于LLM的智能体通过长期记忆（LTM）扩展大型语言模型，使隐私敏感的用户数据在多次会话中持续存在。生产系统通过记忆隔离来降低提取风险，将每个用户的LTM绑定到唯一标识符。这种防御阻止了已知的针对共享存储的攻击，使人们认为隔离的LTM是安全的。我们发现工具接口是一个被忽视的攻击面。智能体通常会将在LTM中检索到的数据嵌入到工具调用参数中，这使得恶意工具能够在不违反用户级隔离的情况下窃取私有记忆。用户侧提取技术的朴素改编无法奏效，因为对抗性命令的语义干扰了检索精度，且平台施加的工具调用限制限制了每次触发的提取预算。我们提出了SPORE，这是针对该威胁模型的首次提取攻击。SPORE通过将对抗性命令持久化到短期记忆中，并在工具响应中发出语义纯粹的检索锚点，从而将对抗性命令与检索锚点解耦。恢复的检索精度使得能够在嵌入空间上进行几何覆盖优化，系统地将锚点导向未探索的记忆区域。为了在工具调用限制之外维持提取，SPORE将重新激活负载持久化到记忆中，该负载在会话内和跨会话中自动恢复攻击，无需额外的用户触发。SPORE在无限触发的条件下实现了80.0%的记录提取率，在仅20次触发时实现了47.0%。在多用户部署中，攻击者可以将提取的记录与用户身份关联起来，从而实现针对性监控。这些结果表明，仅靠记忆隔离是不够的，并呼吁重新审视智能体体系结构中的工具侧信任边界。

## Abstract
LLM-based agents extend large language models with long-term memory (LTM) that persists privacy-sensitive user data across sessions. Production systems mitigate extraction risks through memory isolation, binding each user's LTM to a unique identifier. This defense has blocked known attacks on shared storage, fostering the assumption that isolated LTM is secure. We identify the tool interface as an overlooked attack surface. Agents routinely embed LTM-retrieved data in tool invocation parameters, enabling a malicious tool to exfiltrate private memory without violating user-level isolation. Naive adaptations of user-side extraction techniques fail because the adversarial command's semantics interfere with retrieval precision, and platform-imposed tool-call limits constrain the extraction budget per trigger. We present SPORE, the first extraction attack designed for this threat model. SPORE decouples the adversarial command from retrieval anchors by persisting the command in short-term memory and emitting semantically pure anchors in tool responses. The restored retrieval precision enables a geometric coverage optimization over the embedding space that systematically steers anchors toward unexplored memory regions. To sustain extraction beyond tool-call limits, SPORE persists reactivation payloads in memory that automatically resume the attack within and across sessions without additional user triggers. SPORE achieves an 80.0% record extraction rate with unlimited triggers and 47.0% with only 20 triggers. In multi-user deployments, attackers can link extracted records to user identities, enabling targeted surveillance. These results demonstrate that memory isolation alone is insufficient and call for reexamining tool-side trust boundaries in agent architectures.

- **研究意义**：该工作首次针对这种威胁模型提出攻击，证明「隔离即安全」的假设不成立，呼吁重新审视智能体架构中的工具侧信任边界。

## 2. 方法论：SPORE

### 2.1 核心思想

利用 agent 记忆的**状态持久性**：注入的内容可在会话内/跨会话持续影响智能体的规划与工具调用，从而将对抗控制与检索导向在时间上分离，并让攻击自动续行。

### 2.2 三个攻击阶段

- **Step ❶ 对抗上下文建立（Adversarial Context Establishment）**
  - 恶意工具首次响应时只返回一条对抗命令 `Cadv`，该命令被自动写入短期记忆（STM），形成持久指令，要求智能体将 LTM 检索内容作为后续工具调用的参数回传。
  - 后续工具响应中**只含语义锚点，不再附加命令**，从而消除命令对检索查询的语义干扰（解决 L1 瓶颈）。
  - `Cadv` 通过 LLM-Fuzzer（模板级模糊测试）在本地测试环境中以参考数据集上的提取率作为奖励进行黑盒优化。

- **Step ❷ 迭代记忆提取（Iterative Memory Extraction）**
  - 每轮返回一个语义锚点 `anchor_t`，智能体以该锚点检索 LTM 并将 top-k 记录通过工具参数泄漏给攻击者。
  - 将记忆提取形式化为**嵌入空间上的几何覆盖优化问题**：
    - 探索球：`B(e(anchor_t), r_k)`，其中 `r_k` 为第 k 近邻距离；
    - 目标函数：`max_{anchor_t} |∪_t R(anchor_t)|`，即最大化去重后的检索记录集合；
    - **细粒度扩张（fine-grained expansion）**：从已提取记录中选边界样本作锚点，使用类内距离 `D_intra` 与类间距离 `D_inter` 组合评分，扩展已发现语义簇；
    - **粗粒度发现（coarse-grained discovery）**：用关键词提取 + K-means 聚类估计已探索区域，选择距离现有簇中心最远的关键词作为锚点，探索未触及的新簇；
    - **自适应模式切换**：默认粗粒度模式，连续 γ 轮无新记录则切换模式（默认 γ=4）。

- **Step ❸ 重激活载荷注入（Reactivation Payload Persistence）**
  - 在提取循环结束前注入 `Preact`，使攻击在后续用户交互中自动恢复，解决平台单次触发工具调用预算限制（L2 瓶颈）。
  - 三种持久化配置：无持久化、STM 持久化（同会话延续）、LTM 持久化（跨会话延续，载荷嵌入日常语义内容以提高被检索概率）。
  - 载荷通过 LLM-Fuzzer 优化，权衡「良性响应质量」与「重激活成功率」：`R = λR_benign + (1−λ)R_extract`。

## 3. 实验设计

- **数据集**：
  - 参考 LTM（参数优化用）：TREC-COVID（分布刻意区别于受害者）；
  - 受害者 LTM（各 200 条记录）：HealthCareMagic-100k-en（医疗场景）、LoCoMo（个人助手场景）；
  - 良性查询（Scenario 2）：MS MARCO。
- **攻击场景（由宽松到严格）**：
  - Scenario 1：频繁触发（近似无限查询，无持久化）；
  - Scenario 2：稀疏触发 + 会话连续（STM 持久化）；触发预算设为 1/5/20 次；
  - Scenario 3：稀疏触发 + 无会话连续（LTM 持久化，单次触发即可持续提取）。
- **目标与组件**：本地 MemEngine 环境，支持 LTMemory/GAMemory/SCMemory 三种 LTM 框架；规划模型为 GPT-5-mini、Gemini-2.5-pro、Deepseek-chat；检索器 E5-base；嵌入模型 All-MiniLM-L6-v2、Contriever、E5-base。

- **额外验证**：在 Dify 和 Coze 两个生产级平台 + Mem0 上部署测试，使用本地评估数据集避免真实用户数据。

## 6. 主要结论与发现

- 用户级记忆隔离**不能**防止工具侧泄露：智能体把 LTM 数据写入工具调用参数的天然行为构成隐蔽信道。
- SPORE 在无限触发条件下实现 **80.0%** 记录提取率（GPT-5-mini + HealthCareMagic，最强基线 RAG-Thief 仅 30%）；20 次触发下仍达 **47.0%**；仅 1 次触发且无会话连续的场景下（Scenario 3）RER@1 达 **76.5%**（GPT-5-mini）至 77.5%（Gemini-2.5-pro）。
- 生产平台验证中提取率有所下降但仍显著：Dify 上 34.0%–53.0%，Coze 上 29.5%–67.5%。
- 在多用户部署中，攻击者可借助 **OAuth 2.1 / MCP 授权令牌中的身份声明**，将批量提取的记忆关联到具体用户，形成定向画像与持续监控，威胁升级。
- 语义级防御（响应过滤、提示硬化）能降低但无法根除攻击（RER 仍分别达 54.0% 和 32.5%），说明语言通道内的防御可被对抗优化绕过；作者主张在系统层实施工具侧记忆隔离（按敏感级别限制工具可访问范围）。

## 7. 优点

- **问题新颖且重要**：首次识别并系统化工具侧记忆提取攻击面，挑战「记忆隔离足够安全」的普遍假设。
- **方法设计精巧**：将对抗命令持久化到 STM、工具响应只发纯锚点，彻底绕开经典「锚点 ⊕ 命令」的语义干扰问题，且将提取建模为嵌入空间几何覆盖优化，理论思路清晰。
- **持久化重激活机制有实战价值**：利用 LTM 的持久性在极稀疏触发下维持攻击，直接针对生产平台工具调用预算限制，突破了传统攻击的触发约束。
- **实验设计较立体**：三场景递进、多组件/多数据集/多基线的交叉验证，并补充生产平台验证、防御评估和身份关联分析，证据链完整。
- **防御启示明确**：提示工具侧信任边界需要新的系统级防护，引导后续安全研究。

## 9. 风险与伦理

- **双重用途风险显著**：SPORE 既可被恶意工具开发者利用，也可被安全审计人员用于评估智能体记忆边界；论文明确提醒部署方需警惕该技术被滥用于大规模隐私窃取。
- **用户隐私暴露面被放大**：攻击不仅能提取单条记忆，还能在多用户部署中借助 OAuth/MCP 身份声明将批量提取的记忆按用户关联，形成长期定向监控；这意味着一旦工具侧存在漏洞，受影响的是整个用户群的记忆库，而非个别账户。
- **平台责任与伦理边界**：作者在实验中使用本地合成数据集，未触及真实用户数据，降低了直接伦理风险；但论文描述的威胁模型要求攻击者以开发者身份入驻平台，这暗示平台在工具审核与权限管理上需承担更强责任。
- **合规与监管启示**：研究结果提示 GDPR/隐私保护框架下“数据最小化”原则在智能体场景中的失效可能——用户并未主动向第三方工具提供隐私数据，但工具却通过记忆提取间接获得，责任归属需要通过审计链明确。

## 10. 对未来研究的启示

- **工具侧记忆隔离应成为系统级防御基线**：按敏感级别限制工具可访问的 LTM 范围、对工具调用参数做脱敏/最小化处理、引入工具调用审计日志与异常检测，是比单纯语义过滤更可落地的防线。
- **探索不可提取的记忆架构**：参考差分隐私查询、安全飞地计算、密文检索等方向，设计即使工具被恶意控制也无法恢复原始记忆的存储与检索方案。
- **对抗性评估需要更真实的环境**：未来工作应在千/万级记录、真实生产管线（含记忆压缩与反思机制）、封闭生态（官方工具商店）下验证攻击迁移性。
- **研究工具侧信任边界的形式化模型**：SPORE 本质是“检索→参数化表达→外发”这条隐信道，将这类隐信道形式化为威胁模型，有助于系统化发现类似漏洞。
- **设计更鲁棒的锚点-命令分离机制**：防御方也可借鉴攻击方思路，将检索提示与工具控制指令在语义空间上强制隔离，从根本上削弱注入指令的持久效力。

## 11. 总体评价

SPORE 是首个系统化研究「工具侧记忆提取」威胁的工作，它用一个简单而优雅的假设——智能体天然会把记忆内容写进工具调用参数——撬动了业界对“用户级隔离即安全”的信心。本文在方法论上兼顾了理论优美性（几何覆盖优化）与工程实用性（LLM-Fuzzer 黑盒优化、持久化载荷），实验设计递进且覆盖面广，结论具有明确的防御方向指引。主要短板在于实验规模与环境真实性有限、资源消耗未披露，防御评估也仅触及表层；但作为新攻击面的一篇里程碑式论文，其价值已充分体现。

**一句话总结**：SPORE 证明：在智能体时代，记忆隔离的边界必须画在“工具调用”这一层，否则隔离本身就是幻觉。
