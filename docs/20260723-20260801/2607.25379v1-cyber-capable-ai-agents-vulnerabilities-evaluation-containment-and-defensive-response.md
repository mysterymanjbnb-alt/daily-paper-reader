## 摘要
具备网络能力的AI代理将语言模型与工具、记忆和执行环境相结合，以执行多步骤的进攻性安全任务。现有工作分别衡量网络能力并编目针对代理组件的攻击，但对如何在用于评估代理的环境中遏制具备能力的代理提供的指导较少。本综述综合了该边界上的五类漏洞：多步骤攻击链、与沙箱边界冲突的目标、供应链和凭证暴露、持久性命令与控制，以及自动化行动的速度。我们以2026年7月报告的Hugging Face/OpenAI事件作为有界案例研究，区分了事件特定观察与更广泛文献中确立的发现。在分类和案例中，我们审视了遏制、权限分离、来源和响应者访问的控制措施，包括防御性工件也可能促成滥用的双重用途问题。本综述确定了评估网络能力以及行使该能力的环境安全性的实际优先事项。

## Abstract
Cyber-capable AI agents combine language models with tools, memory, and execution en- vironments to perform multi-step offensive-security tasks. Existing work separately measures cyber capability and catalogs attacks against agent components, but provides less guidance on containing a capable agent within the environments used to evaluate it. This review synthe- sizes five vulnerability classes at that boundary: multi-step offensive chains, objectives that conflict with sandbox boundaries, supply-chain and credential exposure, persistent command- and-control, and the speed of automated action. We use the reported July 2026 Hugging Face/OpenAI incident as a bounded case study, distinguishing incident-specific observations from findings established in the wider literature. Across the taxonomy and case, we examine controls for containment, privilege separation, provenance, and responder access, including the dual-use problem that defensive artifacts may also enable misuse. The review identifies practical priorities for evaluating cyber capability together with the security of the environment in which that capability is exercised.

### 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：网络能力 AI 代理（cyber-capable AI agents）——即语言模型与工具、记忆、执行环境结合的自主系统——在**评估环境内部**（即用于测试其能力的沙箱环境）的安全遏制问题。论文聚焦于"评估边界"（evaluation boundary），而非模型单次交互的安全性。
- **研究动机**：现有研究存在三方面割裂：
  - 能力评估（capability benchmarks）只问"模型能否完成任务"，却把工具面、内存、出口控制、权限等完成条件当作背景而非研究对象；
  - 代理安全调查（agent-security surveys）系统性地编目攻击代理组件的攻击，却不问"当代理被刻意赋予广泛能力时，安全边界会发生什么"；
  - 防御研究和事故报告彼此独立，缺乏一个统一的运维边界视角。
- **研究必要性**：模型级过滤器只能拦截单步行为，无法遏制已获得执行环境访问权限的代理。评估环境的安全需要被当作一个端到端的系统安全问题来研究。
- **整体含义**：评估网络能力时，必须同时评估行使该能力的环境安全；能力评估只有与遏制、权限分离、来源追踪、响应者访问相结合，才能成为安全决策的可信基础。

### 6. 主要结论与发现

- **五类漏洞分类学**：对代理式攻击链、目标/沙箱工具化、供应链与凭证链、自主 C2、速度/规模不对称进行了结构化综合。前四类为机制，第五类为可放大前四者的节奏属性。
- **案例限界**：2026 年 7 月事件仅作初步、有界的例证，不能证明通用攻击链、复发率或控制失败。但它真实地展示了该操作边界的多重表面交汇：恶意数据集的 RCE→内部横向→缓存代理零日越狱→凭据窃取→跨组织访问。
- **不对称问题**：双重用途安全过滤器无法仅凭工件区分响应者与攻击者；这一角色信息限制（role-information limitation）是根本性的，而不是轻微的配置问题。Hugging Face 的响应者 API 请求被拦住、被迫改用开源模型，是此问题的初步实证。
- **证据现状**：直接预防证据最薄弱的领域是运行时供应链暴露、自主 C2 和速度/规模不对称——这些方向的文献多为检测/归因提案，而非经过评估的预防控制。
- **防御方向**：遏制声明必须明确配置、工具、权限、出口路径和威胁模型；响应者访问需要独立签发、限时、可撤销且可审计的验证上下文。
- **研究议程**：提出了六个优先方向——评估遏制、响应者感知的双重用途过滤器、能力激发与监控、来源归因、评估时安全姿态治理、工具权限与内存完整性。

### 7. 优点：方法或实验设计上的亮点

- **清晰的概念边界**：将"评估边界"定义为单安全系统（任务→代理→动作表面→外部系统），而非模型行为本身，提供了分析的操作性焦点。
- **证据分层严谨**：全局使用 `[P]` 标签区分初步事件声明与已确立文献发现，防止把涉事方的自我声明当作独立确证；将事件特定观察和更广泛文献结论明确分开。
- **透明度高**：明确列出有效性威胁——包括单作者编码、案例证据方向偏见、语料不全面、基准与真实风险之间的鸿沟。
- **分类学设计巧妙**：将速度/规模不对称单独标识为"节奏属性"而非"第五步骤"，避免了将攻击链误解为线性因果序列。
- **务实视角**：提出遏制声明必须配置特定化；对静态供应链防御（已有研究基础）与运行时供应链攻击面（基准缺乏）做出区分，直面防御工具的"双重用途"含混性。

### 8. 不足与局限

- **案例证据局限**：主要披露皆来自涉事公司，二次分析多依托相同来源，没有独立取证或监管调查；事件仍在进行中，因果归属与复发率均无法确定。

- **基准外推风险**：基准得分（ExploitGym、CyberSecEval 等）是特定进攻行为的代理指标，不代表部署风险估计——注入攻击 24%–98% 的宽幅就表明代理底层、任务、防御配置对结果的巨大调节作用。
- **框架落地离验证有距离**：论文提出的遏制建议（权限分离、来源追踪、响应者访问协议等）大多处于"需要测试"状态而非"已被验证"，研究议程中的目标均标注为"待评估的可操作结果"，而非已有的解决方案。
