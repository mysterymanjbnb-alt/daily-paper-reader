## 摘要
在多轮交互中运行的LLM代理会在外部记忆存储中积累事实，并将其作为后续推理的前提。因此，某一步骤产生的幻觉事实会作为错误前提持续影响所有后续步骤，这种失败模式我们称之为记忆污染。现有记忆管理方法处理检索和容量问题，但未涉及写入时的正确性；这种准入问题无法通过基于效用或时效性的标准解决，且不受控制的污染会在长轨迹中不断累积。我们提出ConsistencyGate，一种写入时准入门控机制，在将从上下文c中提取的候选事实m提交之前，查询LLM K次以获得软支持分数，仅当平均分超过阈值时才允许m进入记忆。该机制与模型无关，无需微调，在基于对数概率的变体中可简化为单次前向传播，适用于对延迟敏感的场景。为衡量对自然数据的影响，我们通过在LoCoMo和MSC的长程对话中植入受控的单细节破坏，构建了两个真实对话基准（LoCoMo-Contam和MSC-Contam），并辅以一个结构化合成语料库（MemContam），以隔离近最优上限。在四种LLM骨干模型上，ConsistencyGate相对于“全写入”基线降低了所有基准上的污染，其代价集中在源上下文中仅被隐式陈述的事实上。我们发布了全部三个基准以及门控实现。

## Abstract
LLM agents that operate over many turns accumulate facts in an external memory store and reuse them as premises for downstream reasoning. A hallucinated fact written at one step therefore persists as a false premise for every subsequent step, a failure mode we call memory contamination. Existing memory management addresses retrieval and capacity but not write-time correctness; this admission problem cannot be solved by utility- or recency-based criteria, and uncontrolled contamination compounds across long trajectories. We propose ConsistencyGate, a write-time admission gate that, before committing a candidate fact m extracted from context c, queries the LLM K times for a soft support score and admits m only when the average exceeds a threshold. The mechanism is model-agnostic, requires no fine-tuning, and reduces to a single forward pass in a log-probability variant for latency-sensitive deployments. To measure the effect on natural data, we construct two real-conversation benchmarks (LoCoMo-Contam and MSC-Contam) by planting controlled single-detail corruptions in long-term conversations from LoCoMo and MSC, and complement them with a structured synthetic corpus (MemContam) that isolates a near-oracle upper bound. Across four LLM backbones, ConsistencyGate reduces contamination on every benchmark relative to a write-everything baseline, with the cost concentrated on facts that are stated only implicitly in the source context. We release all three benchmarks together with the gate implementation.

# ConsistencyGate：通过自一致性准入控制防止 LLM 代理中的记忆污染——论文总结

## 1. 核心问题与研究动机

- **背景**：长程（long-horizon）LLM 代理（agent）在外部记忆库中逐步积累事实，并在后续推理中反复复用这些事实。架构成立的前提是"写入者可靠"——事实一旦写入，会被多次读回，因此写入时的任何错误都会成为后续所有检索和推理的虚假前提。
- **核心问题——记忆污染（Memory Contamination）**：LLM 即使在给定上下文中做事实抽取时也会产生幻觉，导致幻觉事实被写入记忆库，如同一颗"定时炸弹"持续污染后续所有步骤。污染会随交互轨迹长度复合式放大（contamination cascade），越长的轨迹危害越大。
- **现有方法的盲区**：既有记忆管理只关注**检索**（retrieval）和**容量控制**（capacity/eviction），均无法解决写入时（write-time）的事实正确性验证问题：
  - 不是检索问题：事实一旦存入，即使是 Oracle 检索器也会将其召回；
  - 不是容量问题：基于效用（utility）而非正确性的逐出策略无法识别污染；
  - 不是效用问题：幻觉事实（如"Alice 2015 年毕业"而非 2012 年）在主题相关性、新颖性、时效性上与正确事实几乎完全相同，基于效用的准入机制对其结构性失明。
- **论文断言**：正确性（correctness）是一个独立的准入准则，是现有记忆机制中不可替代的缺失环节。

## 2. 方法论：ConsistencyGate

### 2.1 核心思想
- **将自一致性（self-consistency）从推理验证迁移到写入准入**：借鉴 Self-Consistency（Wang et al., 2023）"正确答案比幻觉答案更具跨样本稳定性"的原理，在写入之前对候选事实进行多次独立验证。
- 与传统自一致性的关键区别：**验证时源上下文 c 是可用的**，验证器将判断建立在已知证据块上，而非仅依赖模型先验。

### 2.2 算法流程（Algorithm 1）
1. 给定候选事实 m 与源上下文 c；
2. 构造软验证提示词（SoftVerifyPrompt），要求模型在 0–1 连续标度上打分（0=完全无支持/直接矛盾，0.5=部分支持或模糊，1=完全直接支持）；
3. 独立查询 LLM **K 次**得到软支持分数 s₁, …, s_K；
4. 计算一致性分数（平均支持度）：
   - p̂(m|c) = (1/K) Σ s_k
5. 当 p̂ ≥ τ 时准入记忆库，否则拒绝。
6. 推荐默认配置：**固定阈值 τ = 0.7，K = 5**。

### 2.3 高效单次前向变体（LogProb）
- 将提示词切换为二值 yes/no，利用 token 级对数概率在**单次前向传播**中近似获得支持分数：
  - p̂_log(m|c) = softmax([log P(yes|prompt), log P(no|prompt)])₀
- 速度：23–28 ms/事实（四骨干模型），相对 K=5 软评分（264–363 ms）有 12–14 倍加速。
- **双峰性假设（bimodality）**：在结构化短上下文中，模型对 yes/no 的 token 概率趋于饱和（正确事实 log P(yes)→0，损坏事实 log P(no)→0），单次查询即可近似 K 次平均；但长对话语境下该假设失效，需 K 次平均。
- **适用建议**：仅推荐用于文档/工具等干净结构化来源，不用于开放式对话。

### 2.4 自适应阈值调度（零调参回退方案）
- 当无法针对具体部署调 τ 时，按记忆占用率线性调度：
  - τ*(|M|, C) = τ_min + (τ_max − τ_min) · |M| / C
- 记忆稀疏时更宽松、接近满时更严格；但实验表明可调固定 τ=0.7 优于自适应方案，后者仅在无法调参时推荐。

### 充分性与公平性分析

## 6. 主要结论与发现

1. **主基准上的有效性**：
   - MemContam（合成）：污染率从 50.0% 降至 **1.2%**（相对降低 97.6%），召回率 100%，QA F1 从 0.474 提升至 **0.840**——视为近 Oracle 上界；
   - LoCoMo-Contam：污染率 50.0% → **34.1%**，精确率 0.500 → 0.659，但召回率仅 0.58；
   - MSC-Contam：污染率 50.0% → **36.7%**，精确率 0.500 → 0.633，召回率 0.93；
   - 干净 LoCoMo 上与 WriteAll 几乎持平（QA F1 0.267 vs 0.271，仅 −1.5%），说明过滤不是靠"盲目减少记忆量"而是靠"正确性导向"。
2. **跨模型一致性**：4 个骨干全部降低污染（合成上降至个位数 → 个位数百分比；真实数据上降低 20%–62%），Llama-3.3-70B 验证器最强，Llama4-Scout 最弱；验证器能力是跨模型差异的主导因素，但并非二值门槛。
3. **污染级联效应**：WriteAll 下污染率恒为 50% 且 QA F1 饱和在 0.45；ConsistencyGate 下污染率在 90 轮后降到 3% 以下，QA F1 升至 0.88——门控收益随轨迹长度单调扩大。
4. **超参数结论**：K 增大收益边际（1–2 分）；τ=0.7 为自然决策边界（τ=0.9 与 τ=0.7 落入噪声内）；自适应调度以约 5 个污染点为代价省掉一个超参数。
5. **变体适用域**：LogProb 在结构化上下文（MemContam）上近完美（污染 0.00%–1.57%）且快 12–14 倍，但在真实对话（LoCoMo-Contam）上每个骨干都劣于软评分——验证了"双峰性"的语境依赖。
6. **代价集中点**：门控拒绝的主要是**源上下文中仅被隐含陈述**的事实（LoCoMo 42% 的正确事实被误拒），显式、自包含的事实几乎不受影响（MSC 召回 0.93 vs LoCoMo 0.58）。

## 7. 优点与亮点

- **问题定义新颖且重要**：首次将"记忆污染"形式化为独立的写入时准入（admission）问题，明确区别于检索、容量、效用三类既有记忆管理维度，并揭示污染级联的轨迹级放大机制；
- **方法简洁、模型无关、即插即用**：无需微调，任何 writer 后端都可包裹门控；软评分、LogProb 单次前向、自适应阈值三种模式适配不同部署约束；
- **基准构建有方法论贡献**：在真实长对话语料中植入受控单细节破坏，统一 50% 污染率使跨基准可比，填补了"缺乏事实级金标"的记忆评估空白，且全部开源（CC BY 4.0 / 非商业条款明确）；
- **实验设计严谨**：Random 基线隔离了记忆量减少的混淆；预播种设计使下游 QA 不受门控决策干扰，保证污染率/精确率为纯净信号；完整 K × τ 网格消融；
- **诚实的边界刻画**：明确区分了"内部一致性上界"（MemContam）与"部署相关数字"（LoCoMo/MSC），对 LogProb 的适用域（结构化 vs 对话）给出了清晰的双峰性解释，并附定性案例分类（TP/TN/FP/FN）帮助理解失败模式。

## 8. 不足与局限

- **理论局限**：自一致性只是正确性的**代理（proxy）**而非正确性本身——当候选事实需要超出源上下文的世界知识时，验证器可能一致地为"貌似合理但错误"的论断投赞成票；
- **部署风险——隐含事实误拒**：LoCoMo-Contam 上 42% 的正确事实被拒（召回 0.58，四个骨干一致），这是永久性的操作成本；论文承认预播种设计掩盖了这一代价，实际部署中意味着事实库的隐性亏损；
- **多跳/分布式证据的盲区**：当证据分散在多个历史轮次而非单一可检索块中时，验证器无法落地判断，召回急剧下降；未来需要多跳验证机制；
- **同族验证器偏差**：MemContam 生成器与验证器同属 Qwen 家族，其 1.2% 污染率是内部一致性上界，不能直接外推到部署性能；
- **端到端证据不足**：真实基准中 QA F1 对门控决策不敏感（预播种设计），缺少对完整 agent 长轨迹下游收益的直接量化；
- **算力披露不完整**：未给出具体 GPU 型号、显存、总推理时耗；K=5 软评分 264–363 ms/事实的额外开销在规模部署中不可忽视（论文在 Broader Impacts 中亦承认能耗风险）；
- **潜在虚假安全感**：用户可能将"通过一致性检查"误认为"事实已权威核验"，在医疗、法律、金融等高危场景中放大风险——论文建议此类场景需明确沟通过滤不等于事实核查；
- **其他**：MemContam 的 5 个固定源上下文共享底层实体，词汇多样性有限；真实基准探针数量较少（50 与 41 个）；未探索门控对多任务（工具调用、知识库写入）场景的适用性。
