## 摘要
自主AI代理越来越多地在有限的人类监督下执行操作、调用工具并操作受保护资源。现有的认证和授权机制确立身份并委派权限，但本质上并不提供密码学证据，证明特定代理在特定执行上下文中发出的具体请求满足适用策略。本文假设代理授权可以被形式化为一个密码学可验证的关系，记为$R_{CVA}$，该关系共同绑定代理主体、具体授权请求、执行上下文以及适用策略的满足情况，同时选择性地保护私有授权属性的机密性。我们为密码学可验证代理授权（CVA）引入了一个初步的形式化抽象，定义了一组简洁的候选安全属性，包括授权健全性、主体绑定、请求绑定、策略绑定和重放抵抗，并提供了一个可执行的零知识概念验证，该验证在Groth16 zk-SNARK构造上实例化了模型的选定元素。我们进一步识别并形式化了身份绑定、授权请求绑定和运行时执行绑定之间的结构性分离，这是安全代理系统设计中的一个核心开放问题（当前代理安全框架未明确解决的区分），并提出了一个可证伪的研究议程来解决该问题。

## Abstract
Autonomous AI agents increasingly execute actions, invoke tools, and operate on protected resources with limited human oversight. Existing authentication and authorization mechanisms establish identity and delegate authority, but do not inherently provide cryptographic evidence that a concrete request issued by a specific agent satisfies the applicable policy in a specific execution context. This paper hypothesizes that agent authorization can be formalized as a cryptographically verifiable relation, denoted $R_{CVA}$, that jointly binds an agent principal, a concrete authorization request, an execution context, and the satisfaction of an applicable policy, while selectively preserving the confidentiality of private authorization attributes. We introduce a preliminary formal abstraction for Cryptographically Verifiable Agent Authorization (CVA), define a compact set of candidate security properties including authorization soundness, principal binding, request binding, policy binding, and replay resistance, and provide an executable zero-knowledge proof of concept that instantiates selected elements of the model over a Groth16 zk-SNARK construction. We further identify and formalize the structural separation among identity binding, authorization-request binding, and runtime execution binding as a central open problem in the design of secure agentic systems (a distinction {not explicitly addressed by} current agentic security frameworks) and present a falsifiable research agenda for its resolution.

## 2. 论文提出的方法论：核心思想、关键技术细节与公式

### 核心思想
- **形式化关系**：定义关系 $R_{CVA}(x, w) \in \{0,1\}$，其中：
  - 公开陈述 $x = (id_i, h_q, h_c, pid_j, n, t)$
    - $id_i$：代理公开身份承诺
    - $h_q = H_q(\text{Encode}(q_{priv}))$：请求承诺（对私有规范请求的哈希）
    - $h_c = H_c(\text{Encode}(c_{priv}))$：上下文承诺
    - $pid_j$：策略版本标识
    - $n, t$：nonce 与时间戳（新鲜性）
  - 私有见证 $w = (sk_i, \rho_i, attrs_i, q_{priv}, c_{priv})$
    - $sk_i$：代理私钥，$\rho_i$：身份承诺随机性
    - $attrs_i$：私有授权属性
    - $q_{priv}, c_{priv}$：请求和上下文的私有明文
- **核心关系分解**：
$$R_{CVA} = \text{BindPrincipal} \wedge \text{BindRequest} \wedge \text{BindContext} \wedge \text{SatisfyPolicy}$$
  - BindPrincipal：$\text{CommitID}(sk_i, \rho_i) = id_i$
  - BindRequest：$H_q(\text{Encode}(q_{priv})) = h_q$
  - BindContext：$H_c(\text{Encode}(c_{priv})) = h_c$
  - SatisfyPolicy：$P_j(attrs_i, q_{priv}, c_{priv}) = 1$
- **证据生成与验证**：
  - $pp \leftarrow \text{Setup}(1^\lambda, R_{CVA})$
  - $\pi \leftarrow \text{Prove}(pp, x, w)$
  - $\text{VerifyAuth}(pp, x, \pi) = 1$
  - 完整接受函数：$\text{Accept}(x, \pi) = \text{VerifyAuth}(pp, x, \pi) \wedge \text{Fresh}(n, t, N)$（新鲜性由网关外部状态维护）

### 关键技术细节
- **密码学原语**：承诺机制（Pedersen 风格）、域分离哈希（$H_q, H_c, H_P$）、规范编码（Canonical Encoding）避免语义等价请求冲突。
- **安全性属性**（基于对抗游戏定义）：
  - **授权健全性**：对不存在见证的陈述无法生成可验证的证明（依赖底层证明系统的知识健全性）。
  - **主体绑定**：对 $id_i$ 生成的证明不能对 $id_k \ne id_i$ 验证通过。
  - **授权请求绑定**：对请求 $q_i$ 的证明不能用于请求 $q'_i$。
  - **策略绑定**：对 $pid_j$ 的证明不能作为 $pid_k$ 的证明。
  - **上下文绑定**：对上下文 $h_c$ 的证明不能在不同上下文承诺下通过。
  - **重放抵抗**：通过 nonce 集合 $N$ 和时间窗口 $[t_{\min}, t_{\max}]$ 实现，$\text{Fresh}(n,t,N)=1$ 当且仅当 $n \notin N$ 且 $t$ 在有效期内。
- **概念验证实现**：
  - 使用 **Groth16 zk-SNARK**（BN128 曲线），Circom 2.x 电路，snarkjs 生成证明。
  - 网关：FastAPI 服务，无状态证明验证 + 有状态重放控制。
  - 原型关系：$x_{PoC} = (id_i, h_{plan}, n, t)$，$w_{PoC} = (sk_i, attrs_i, plan)$。
  - 约束实例化：
    - $\text{Poseidon}(sk_i) = id_i$（简化主体验证，用确定性哈希代替随机化承诺）
    - $\text{SHA256}(plan) = h_{plan}$
    - 电路内编码策略谓词 $P_{PoC}(attrs_i, plan) = 1$
    - 非重放由外部网关状态保证。

### 核心开放问题（论文最重要的贡献之一）
- **三层绑定分离**：
$$\text{Identity Binding} \not\equiv \text{Authorization Request Binding} \not\equiv \text{Runtime Execution Binding}$$
- 即使验证了 $q_{auth}$ 对应的证明，也不保证运行时执行的是 $q_{exec}$（即 $\text{VerifyAuth}(pp, x_q, \pi)=1 \not\Rightarrow q_{exec}=q_{auth}$）。这是 ZKP 授权层结构性限制，需要远程证明/TEE/可验证执行收据等额外机制。

## 6. 论文的主要结论与发现

1. **授权应被形式化为密码学可验证关系**：单独的身份认证、委派或策略合规证明都不足以构成特定请求的授权证据。
2. **CVA 关系是可实例化的**：通过 Groth16 zk-SNARK 实现的主体验证、请求绑定和私有策略谓词证明，表明该抽象具有构造可行性。
3. **核心发现——三层绑定的结构分离**：
   - 身份绑定 ≠ 授权请求绑定 ≠ 运行时执行绑定。
   - 现有代理安全框架未显式处理授权请求绑定与执行绑定之间的差距。
   - ZKP 只能证明“被承诺的请求满足策略”，不能保证“随后执行的就是该请求”。
4. **策略正确性是正交的安全关切**：即使证明有效，若电路编码的策略与真实组织策略不一致，则证明合法但授权错误；需将策略治理、版本管理和验证密钥分发视为一等安全机制。
5. **上下文动态变化导致现有系统具有 TOCTOU 问题**：验证时的上下文可能与执行时不同，$c_{t_v} \neq c_{t_e}$，因此 $Authorized(q, c_{t_v}) \not\Rightarrow Authorized(q, c_{t_e})$。
6. **多代理委派链中的组合授权是开放问题**：当前单主体关系在委派链中不足以保证授权范围的保持或收缩。
