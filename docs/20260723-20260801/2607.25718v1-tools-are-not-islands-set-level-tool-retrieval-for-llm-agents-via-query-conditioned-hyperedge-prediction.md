## 摘要
大型语言模型（LLM）智能体日益依赖调用外部工具来完成现实世界任务。工具检索——在智能体行动之前从包含数千个工具的库中选取一小部分与任务相关的子集——因此已成为LLM智能体流水线的关键组成部分。然而，现有检索器要么孤立地评估每个工具，要么顺序地组装工具集，因此候选集的联合效用从未被整体评估。在本文中，我们提出HYSET，即基于超边的集合级工具检索（HYperedge-based SEt-level Tool retrieval）的简称。我们的贡献有三方面：（i）我们将工具检索形式化为工具共调用超图上的查询条件超边预测，在此框架下，工具集本身成为评分单元，而大多数现有检索范式可归约为受限实例；（ii）我们通过基数特定的交互捕获与大小相关的工具兼容性；（iii）我们将HYSET设计为预选择模块，无需修改下游智能体。在ToolBench上的实验表明，HYSET在工具检索性能和端到端任务成功率方面均持续优于最先进的基线。除域内设置外，HYSET还支持零样本/少样本迁移，能以极少监督泛化到未见过的工具/类别和未知领域。

## Abstract
Large language model (LLM) agents increasingly rely on invoking external tools to complete real-world tasks. Tool retrieval, which selects a small task-relevant subset from a library of thousands of tools before the agent acts, has therefore become a critical component of LLM agent pipelines. However, existing retrievers either score each tool in isolation or assemble the tool set sequentially, so the joint utility of a candidate set is never evaluated as a whole. In this paper, we propose HYSET, short for HYperedge-based SEt-level Tool retrieval. Our contributions are threefold: (i) we formulate tool retrieval as query-conditioned hyperedge prediction on a tool co-invocation hypergraph, under which the tool set itself becomes the unit of scoring and most existing retrieval paradigms reduce to restricted instances; (ii) we capture size-dependent tool compatibility through cardinality-specific interactions; and (iii) we design HYSET as a pre-selection module requiring no modification to the downstream agent. Experiments on ToolBench demonstrate that HYSET consistently outperforms state-of-the-art baselines in both tool retrieval performance and end-to-end task success. Beyond the in-domain setting, HYSET further supports zero-shot/few-shot transfer, generalizing to held-out tools/categories and unseen domains with minimal supervision.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM智能体在执行真实任务时愈发依赖调用外部工具（API）。工具库规模已从数十个手工函数扩展到包含上万端点的真实API生态，如ToolBench包含16,464个API端点，导致无法在上下文中穷尽展示所有工具。
- **核心问题**：现有工具检索方法主要分三类，但都存在结构性缺陷：
  - **语义匹配检索**（BM25、Contriever等）：独立评分每个工具，忽略工具间的联合效用，导致高单项分但不完备的集合。
  - **图增强检索**（COLT等）：通过图结构学习协作关系，但推理时仍退化为独立Top-K排序，只近似而并非显式评分集合。
  - **生成式检索**（ToolGen等）：顺序生成工具标识符，从不显式比较完整候选集合的整体一致性。
- **核心论点**："工具并非孤岛"（Tools Are Not Islands），工具检索本质上是**集合级问题**——需要评估的是候选工具集作为整体的联合效用，而非单个工具的相关性之和。
- **典型案例**：一个航班+酒店+天气+货币兑换的旅行规划查询中，密集检索器给 Flight（0.92）、CheapFlight（0.89）、FlightTracker（0.87）、Hotel（0.80）、Weather（0.55）、Currency（0.32）打分，Top-4结果为{Flight, CheapFlight, FlightTracker, Hotel}，导致两个子任务完全未被覆盖——这是结构性失败。

## 2. 方法论

### 2.1 核心思想
- **形式化**：将工具检索建模为**查询条件下的超边预测**（query-conditioned hyperedge prediction）。构建工具共调用超图 H=(V,E)，其中节点为工具，超边为训练样本中真实使用的工具集，工具集本身成为评分单元。
- **统一视角**：作者证明三类现有检索范式均可归约为该框架的受限实例：
  - 语义匹配：F(x,E)=Σₜₑₑ smatch(x,t)（加性单点分数）
  - 图增强：F(x,E)=Σₜₑₑ sG(x,t)（加性图上下文分数）
  - 生成式：F(x,E)=log ΣₚₑS(E) pφ(π,EOS|x)（顺序条件概率）

### 2.2 评分函数分解
评分函数分解为两项：Fθ(xi,E) = Fset(E) + Falign(xi,E)

**① 集合交互项 Fset**（内部工具兼容性）：
- Fset(E) = Σ₁≤a<b≤m zⱼₐᵀ Mₘ zⱼ_b
- 其中 z 为工具嵌入（可学习），Mₘ 为**基数特定的对称交互矩阵**（按集合大小m变化），共 M-1 个矩阵（m=2,...,M）。
- 关键理论支撑：**定理1**——若所有基数共享相同矩阵（即 zᵢᵀM₂zⱼ = ⋯ = zᵢᵀM_Mzⱼ 对任意 ti≠tj 成立），则Fset退化为纯二阶（pairwise-decomposable）；反之，基数特定矩阵能产生三阶及以上的结构化联合效应，仅需O(M·dz²)参数而非O(dz^M)。

**② 查询-集合对齐项 Falign**（查询与集合的相关性）：
- Falign(xi,E) = r(xi)ᵀ·s(xi,E)
- 采用**交叉注意力池化**：以查询嵌入 r(xi) 为查询（Query），以投影后的工具嵌入 {Pzⱼₖ} 为键/值，注意力权重 αₖ(xi,E) 依赖整个候选集合，使对齐项本身也是集合级的。

### 2.3 训练目标
- **负采样检索损失**：Lret = -Σ log exp(F(x,E*)) / Σ exp(F(x,E))，负样本由50%均匀大小匹配集合 + 30%批内负样本 + 20%硬负样本（k近邻替换）构成混合池，规模Kneg=64。
- **奖励加权自训练损失**：Lself = -Σ ρᵢ log exp(F(x,Êᵢ)) / Σ exp(F(x,E))，其中 ρᵢ 是GPT-4评判的端到端执行奖励，强化成功执行但非标注的模型自选集合。
- 完整目标：L = Lret + ηLself + λΣ‖Mₘ‖_F²，约束‖zⱼ‖₂=1。

## 6. 主要结论与发现

- **集合级评分的有效性**：HYSET在ToolBench上全面超越六个基线，COMP@5相对提升10.8%（BERT配置）和11.6%（Qwen配置，相对于ToolGen），证明"将工具集作为整体评分"优于"独立评分"或"顺序生成"。
- **基数特定交互的必要性**：移除基数特定性（共享M矩阵）导致COMP@5下降约4%；使用恒等矩阵则更差——证明工具兼容性确实随集合大小变化，且该差异不可忽略。
- **集合交互项的贡献最大**：移除Fset使COMP@5下降13.1%、Pass Rate下降16.8%，是整个方法的主要增益来源；执行反馈仅对端到端成功（+6.5%）有明显贡献，对COMP影响有限（+0.7%）——说明完备性主要来自集合级建模。
- **泛化能力**：跨域零样本保留79.9%的域内集合完备性；每类5个标注样本即可恢复93.2%的全监督性能；对完全未见工具体系下COMP@5相对提升13.1%。
- **推理高效**：两阶段推理每查询仅需秒级以下（12.4 ms），远优于生成式方法（378.4 ms），且扩展工具库不增加重排序成本。

## 7. 优点与亮点

1. **问题视角创新**：率先将工具检索重新概念化为"查询条件超边预测"，使工具集成为评分单元，提供了统一的理论视角（三类现有范式作为受限实例），具有较高学术价值。
2. **理论支撑扎实**：通过Möbius变换证明了基数特定矩阵在产生高阶交互中的精确作用（定理1），为设计提供了理论依据，而非仅凭直觉。
3. **基数特定交互**：用O(M·dz²)参数表示到M阶的结构化交互，在表达力与参数效率之间取得良好平衡。
4. **模块化设计**：作为预选择模块，完全冻结下游智能体，即插即用，工程友好。
5. **训练信号设计**：结合监督集合信号（Lret）+ 执行反馈自训练（Lself），利用端到端奖励弥补标注集子优性的问题。
6. **实验严谨性**：多种子、显著性检验、公平性校正实验、误差线、预算控制（baseline也享受同样的执行反馈预算）、零样本/少样本/跨域全面覆盖。

7. **下游 agent 的适配性假设**：HYSET 的设计锚定于「输出一个完整工具集合供 agent 顺序调用」的范式，但部分 agent 任务可能需要多轮、条件调用或多个独立子集交替使用，此时一次性集合检索可能过于简化；论文在智能体层面使用固定的 ToolLLaMA-2 与 DFSDT 协议，未探索与其他 agent 架构（如 ReAct、plan-and-solve）的协同效果，结论的普适性有待验证。

## 9. 综合评价

总体而言，本文以「工具并非孤岛」为立意，将工具检索从传统的 Top-K 排序问题重构为查询条件下的超边预测，为工具选择研究提供了全新的理论框架与实用系统。其理论贡献（三类范式的统一视角、基数特定交互矩阵的表达力证明）扎实且具启发性；实验设计在覆盖率、公平性、泛化性和成本控制等方面均属上乘，充分支撑了核心论断。尽管存在对标注数据和执行反馈的双重依赖、组合枚举的扩展性瓶颈以及动态工具库适应上的不足，但其提出的集合级评分思想与两阶段推理范式，很可能成为未来工具检索乃至更广泛「组合性检索」任务的重要基准。该论文综合质量高，属于信息检索与 LLM Agent 交叉领域的优秀代表作。
