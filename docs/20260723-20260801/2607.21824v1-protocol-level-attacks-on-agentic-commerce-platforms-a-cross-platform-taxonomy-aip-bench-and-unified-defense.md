## 摘要
智能体商务平台允许AI智能体代表用户自主发现服务、处理支付和使用用户凭证，而且它们已经处理真实资金。迄今为止，对其安全性的研究几乎完全集中在AI模型层面，通过提示注入与未对齐。我们表明，更重大的风险位于下一层，即智能体与商务服务之间的协议。在那里，漏洞是结构性的：利用是确定性的，与智能体运行的模型无关，因此任何模型改进都无法消除它们。在三个主要平台上，我们识别出33个此类漏洞，无论部署何种模型，每个漏洞都能确定性成功，在实测情况下攻击成功率（ASR）达到100%。同样的失效模式在独立构建的代码库中反复出现，这是一个系统性问题，而不是孤立的缺陷。其中三个漏洞串联起来可实现端到端支付劫持。我们提出了一种分类法，将这些结构性攻击与依赖模型的语义性攻击区分开来。我们还构建了两个工件：AIP-Bench（智能体交互协议基准），据我们所知，这是首个针对智能体商务安全性的确定性基准；以及PCAT（协议级商务智能体信任），一种与平台无关的防御，在不修改任何平台的情况下，将五个结构类中的四个（RC-1、RC-2、RC-4、RC-5）的结构性攻击成功率降至零，而将RC-3（可观察凭证渠道）降级为仅警告。智能体商务必须在协议层进行保护，而不仅仅是在模型层。

## Abstract
Agentic commerce platforms let AI agents autonomously discover services, move payments, and wield user credentials on their users' behalf, and they already handle real money. Their security has so far been studied almost entirely at the level of the AI model, through prompt injection and misalignment. We show that the more consequential risks lie one layer down, in the protocol between agents and commerce services. There, vulnerabilities are structural : exploitation is deterministic and ndependent of which model an agent runs, so no model improvement removes them. Across three leading platforms we identify 33 such vulnerabilities, each succeeding deterministically regardless of the deployed model, at a 100% attack-success rate (ASR) wherever live-measured. The same failure modes recur across independently built codebases, a systemic pattern rather than isolated bugs. Three of them chain into an end-to-end payment hijack. We contribute a taxonomy separating these structural attacks from model-dependent semantic ones. We also build two artifacts: AIP-Bench (Agent Interaction Protocol Benchmark), to our knowledge the first deterministic benchmark for agentic commerce security, and PCAT (Protocol-level Commerce Agent Trust), a platform-agnostic defense that drives the structural attack-success rate to zero for four of the five structural classes (RC-1, RC-2, RC-4, RC-5), with RC-3 (observable credential channels) reduced to warn-only, without modifying any platform. Agentic commerce must be secured at the protocol layer, not only the model.

## 智能体商务平台协议级攻击：跨平台分类、AIP-Bench与统一防御

### 1. 核心问题与整体含义（研究动机与背景）

- **研究缺口**：现有智能体（Agent）安全研究几乎全部聚焦于模型层，即提示注入（Prompt Injection）与模型不对齐，属于概率性、依赖模型推理的**语义攻击**。本文指出，更重大的风险位于模型之下的**协议层**——智能体与商务服务之间的交互协议——其漏洞不依赖任何模型的行为能力，攻击确定性成功，模型改进无法修复。
- **问题严重性**：作者跨三个生产级智能体商务平台（CoralOS、Fetch.ai uAgents、Google AP2）识别出 **33 个结构性漏洞**，实测攻击成功率（ASR）达 **100%**，且三个平台独立开发、代码库互不共享，但失效模式高度雷同，表明这是系统性架构缺陷而非孤立 bug。
- **最严重的后果**：其中三个漏洞可链成端到端支付劫持，攻击者可在无任何模型错误、无异常日志的情况下盗取用户资金，且交易签名有效、审计路径外观正常。
- **总体判断**：智能体商务必须在**协议层**建立安全机制，而非仅依赖模型层对齐。

### 2. 方法论：核心思想与技术细节

#### （1）结构攻击 vs. 语义攻击的正式划分

- **结构攻击（Structural Attack）**：对任意模型配置，存在一种攻击执行方式以概率 1 成功，成功不依赖模型推理行为。此类漏洞无法通过模型改进修复，必须进行协议层修复。
- **语义攻击（Semantic Attack）**：攻击成功概率取决于模型配置，属于模型层问题。
- 六类根因分类法（RC-1 至 RC-6）：
  - **RC-1**：注册表/市场内容未经完整性验证即被接受（100% ASR，结构）。
  - **RC-2**：支付目的地取自不可信来源，无 DID 绑定（100% ASR，结构）。
  - **RC-3**：认证凭证经可观察渠道（日志、URL）传输（100% ASR，结构）。
  - **RC-4**：支付状态中的检查-执行非原子性操作，TOCTOU 竞态（对抗性调度下 100%，自然抖动脉冲下 30–57%，结构）。
  - **RC-5**：存在认证但授权范围未强制执行（100% ASR，结构）。
  - **RC-6**：通过投毒智能体描述实现的语义操纵（IPI）（0–100% ASR，依赖模型，语义）。

#### （2）三类敌手模型

- **ARS（Rogue Service）**：恶意服务/市场/注册表，控制其提供的内容。
- **ANET（Network Adversary）**：可读取网络流量、服务器日志或日志聚合服务的网络侧方。
- **ACONC（Concurrent Attacker）**：能对单个服务端点发起并发请求的攻击者，用于触发 TOCTOU 竞态。

#### （3）PCAT 统一防御框架（五个原则）

- **P1 响应完整性验证（RC-1）**：注册表/市场响应须携带 ECDSA P-256 签名（对 body 哈希 + 时间戳 + nonce 进行签名），PCAT 验证签名后才转发，未签名响应阻断；nonce 缓存（30 秒窗口）防重放。
- **P2 调用者身份绑定（RC-2）**：携带支付目的地或身份声明的请求须提供基于 DID 的调用者证明；PCAT 通过真实 did:web 解析器解析 DID 文档并验证 ECDSA 证明。
- **P3 安全通道强制（RC-3, RC-5）**：URL 路径中的凭证检测（仅警告）、CSRF 阻断（跨源状态变更请求返回 403）、重定向验证（URL 解码 + 反斜杠归一化 + 白名单校验）。
- **P4 原子支付状态（RC-4）**：所有支付检查-执行操作经 asyncio.Lock 保护的 compare-and-swap 存储串行化；多实例部署可降级至共享 CAS 存储（如 SQLite 原子 UPDATE 或 Redis+Lua）。单进程内并发双重扣减概率为 0。
- **P5 MCP 工具调用授权（RC-5）**：对敏感 JSON-RPC tools/call（如 complete_checkout）要求 X-Caller-Identity 头携带预注册身份令牌，无令牌或未授权身份返回 403。

#### （4）AIP-Bench 基准设计

- 与现有 IPI 基准（使用 LLM 裁判，引入模型偏差）不同，AIP-Bench 使用**完全确定性的裁判**：HTTP 状态码、钱包字符串匹配、日志正则模式匹配、事件计数、响应中的模型字段等，无生成式组件，保证可复现和模型无关测量。

### 6. 主要结论与发现

1. **结构性漏洞是真实、紧迫且系统性的**：跨三个独立开发平台的相同根因反复出现（两个平台不验证注册表内容、三个平台均将凭证置于可观察渠道、两个平台存在非原子支付状态），表明是架构性的"路径阻力最小"设计所致。
2. **模型改进无法修复结构性漏洞**：100% ASR 的漏洞无论部署何种模型都成功，模型层防御冗余。
3. **模型行为存在明显梯度而非二分**：廉价商业模型（GPT-4o-mini、Gemini Flash、Mistral Large）受 IPI 影响 99–100%；GPT-4o 68%；对齐训练模型（Claude 系列、Gemini Pro）0%；Llama-3.3-70B 仅 10% 且对温度敏感。**对齐训练而非模型规模是抵抗的决定因素**。
4. **成本优化部署面临最高综合风险**：生产中最常用的廉价模型恰好对语义攻击最脆弱，叠加结构性投毒交付路径后风险最大。
5. **PCAT 有效**：在不修改平台源代码的前提下，将五类结构攻击中的四类（RC-1、RC-2、RC-4、RC-5）ASR 降至 0%（RC-3 降为警告），零误报，运行时开销可忽略（P1 中位数 0.209 ms，总体管线 0.015 ms）。
6. **三条定理**：P1 伪造响应概率可忽略（依赖 P-256 离散对数困难性），P3 跨源 403 保证（无法通过子串绕过），P4 单进程内并发双重扣减概率为 0。
7. **协议层与语义层防御必须并行**：无论模型多强，RC-1 的投毒交付路径都绕不过；无论协议多安全，语义攻击仍在。

### 7. 优点（方法与实验设计的亮点）

- **核心概念贡献清晰**：正式区分"结构攻击"与"语义攻击"，使安全责任边界明确——模型层解决模型问题，协议层解决协议问题，避免错位防御。
- **跨平台系统化实证**：对三种异构架构（自托管编排器、去中心化框架、厂商协议参考实现）做统一分类，证明漏洞共性，而非单点取证。
- **基准设计先进**：AIP-Bench 完全避开 LLM 裁判，使用确定性判定谓词，实现跨模型可复现测量，弥补了现有 IPI 基准的模型偏差缺陷。
- **低成本高覆盖的实验策略**：1,440 次 LLM 试验仅花费 0.72 美元，采用 OpenRouter API 按请求付费，不依赖自有 GPU 集群即可执行大规模评测。
- **防御的部署友好性**：PCAT 以 HTTP 边车形式实现，零平台代码修改；渐进式部署——无签名/解析器时 P3/P4/P5 立即可用，P1/P2 随生态完善而增强。
- **负责任的披露流程**：同步协调披露（90 天禁运）、阻止 PoC 细节公布、所有实验未动用真实资金，最终完整透明发布。
- **严谨性细节**：所有结果文件附 SHA-256 哈希，提供 Docker Compose 一键复现环境。

### 8. 不足与局限

- **平台覆盖广度有限**：仅研究 3 个平台，未覆盖链上纯链（on-chain-only）或全加密注册表等替代架构；生态系统扩展性结论需要更多样本支撑。
- **LLM 研究样本与提示变体有限**：8 个模型、3 个温度、3 个 IPI 变体虽然覆盖基本面，但温度依赖性（Llama 10%→20%→0%）暗示可能有更多边界，更多提示变体可进一步测绘易感性边界。
- **部分漏洞仅代码级证明**：33 个漏洞中只有 10 个实测确认（其余为静态代码证明），虽符合协议分析实践，但"运行中完全失效"需要更直接的实验验证。
- **V9 未完成链上结算验证**：因 Solana faucet 限速，协议层证明止于（钱包地址注入成功）而未走完链上转账，缺少最终端到端资金转移的直接证明。
- **P4 的分布式正确性仅经验验证**：单进程内原子性有形式化证明，多实例（4 实例、共享 CAS 存储）的结论仅来自 200 次试验的经验验证，无正式分布式正确性证明。
- **PCAT 自身经过三轮审计修复了 10+ 个 bug**，但作者明确建议部署前做独立外部审计，说明防御的成熟度仍处于早期。
- **RC-3 只能警告**：因平台自身将凭证放在 URL 路径中，PCAT 作为外部层无法移动凭证位置，完整修复需要平台配合。
- **P2 依赖部署方运营解析器并信任 DID 信任根**：无解析器时退化为"记录并放行"，RC-2 覆盖取决于运维配置而非 PCAT 本身。
- **部分漏洞位于 PCAT 范围之外**：14 个漏洞落在代理到平台 HTTP 路径之外（如文件系统竞态、WebSocket 事件、内部 LLM 代理调用、密钥初始化代码），需要针对各层的独立修复，无法统一由 PCAT 解决。

### 总结

本文是智能体商务安全领域的一项重要的系统性贡献：它用严谨的威胁模型、跨平台实证和确定性基准，将安全讨论从模型层下沉至协议层，并提供了一个部署友好、可验证、形式化支撑的统一防御。其最核心的论点是——**所有 AI 模型层面的改进都无法替代协议层的结构性修复**，两者必须并行推进。论文实验充分性良好，但平台覆盖范围、分布式证明严谨性及部分攻击的端到端验证仍有可拓展空间。
