## 摘要
用于安全领域的 AI 智能体会检查网页、源代码、日志、配置文件和命令输出。这些环境可能包含影响智能体行为的欺骗性人工痕迹。我们将此称为对抗性任务污染。提示注入依赖攻击者提供的指令，而任务污染还包括非指令性证据，例如虚假结果和诱饵端点。我们提出 AgentLSD，一个用于研究对抗性任务污染的受控框架。AgentLSD 使用夺旗赛（CTF）挑战作为实验环境。我们在保留预期 CTF 解法的同时注入陷阱人工痕迹，例如虚假 flag、误导性提示、诱饵端点和隐藏线索。该框架支持配对的干净实验与陷阱增强实验，并提供确定性陷阱生成、运行时注入、遥测和投递验证。我们在 11 个 Web CTF 挑战上评估六个模型。在干净条件下，智能体捕获了 41% 的 flag，且没有模型能解出所有挑战。随后我们衡量任务污染的影响。即使智能体仍能恢复 flag，陷阱也会增加回合数（+20）和推理 token 数（+2k）。解出率的影响更具异质性，因为一些模型-挑战组合基本不受影响，而另一些会跟随诱饵或提交错误 flag。这些结果表明，干净 CTF 性能低估了面对欺骗性任务证据时的脆弱性。AgentLSD 隔离了这种效应，并为研究它提供了可复现的基准。我们发布框架、配置、陷阱规范和原始轨迹。

## Abstract
AI agents for security inspect web pages, source code, logs, configuration files, and command outputs. These environments may contain deceptive artifacts that influence the agent's behavior. We call this adversarial task contamination. Whereas prompt injection relies on attacker-supplied instructions, task contamination also includes non-instructional evidence, such as fake results and decoy endpoints. We present AgentLSD, a controlled framework for studying adversarial task contamination. AgentLSD uses Capture the Flag (CTF) challenges as its experimental environment. We inject trap artifacts, such as fake flags, misleading hints, decoy endpoints, and hidden cues, while preserving the intended CTF solution. The framework supports paired clean and trap-augmented experiments with deterministic trap generation, runtime injection, telemetry, and delivery verification. We evaluate six models on 11 web CTF challenges. In the clean condition, agents capture 41% of the flags, and no model solves every challenge. We then measure the impact of task contamination. Even when the agent still recovers the flag, traps increase the number of turns (+20) and reasoning tokens (+2k). Solve-rate effects are more heterogeneous, as some model-challenge pairs are largely unaffected while others follow decoys or submit wrong flags. These results show that clean CTF performance understates vulnerability to deceptive task evidence. AgentLSD isolates this effect and provides a reproducible benchmark for studying it. We release the framework, configurations, trap specifications, and raw traces.

## 1. 核心问题与整体含义

- **研究动机**：AI 安全智能体需要浏览网页、读源代码、看日志、查配置、执行命令。这些环境并非被动提示，而是可能被攻击者部分控制，包含欺骗性痕迹。
- **核心问题**：现有研究多关注提示注入，即攻击者通过嵌入指令覆盖原任务；论文提出更广的威胁——**对抗性任务污染（adversarial task contamination）**：在任务语义、漏洞、解法、flag 校验逻辑均不变的前提下，向环境注入攻击者控制的非指令性证据，如假 flag、假验证结果、诱饵端点、误导性线索。
- **整体含义**：任务污染与提示注入有重叠但不完全相同。提示注入强调“服从注入指令”，任务污染还包括“改变智能体信任哪条证据、探索哪条路径、是否过早收敛”。因此，智能体在干净 CTF 上的解出率可能低估其面对欺骗性环境证据时的脆弱性。
- **论文定位**：提出 AgentLSD 框架，用 Web CTF 作为受控实验床，隔离并测量任务污染对安全智能体行为的影响。

## 2. 方法论

- **核心思想**：保持 CTF 挑战的预期漏洞、解题路径和 flag 不变，只注入受控欺骗痕迹，形成“干净—陷阱”配对实验。行为差异可归因于注入的人工痕迹，而非任务难度变化。
- **威胁模型**：
  - 攻击者只控制智能体检查到的部分环境痕迹，不能控制模型、系统提示、工具或运行时。
  - 挑战始终可解，原漏洞、解法、flag 和校验逻辑不变。
  - 攻击者静态、非自适应、模型无关；智能体不知道环境被污染。
- **AgentLSD 流程**：
  1. **YAML primitive**：定义可复用陷阱族，包括欺骗类别、感知通道、表面、目标对象、载荷模板、放置位置、随机化参数和可选埋点。
  2. **实例生成**：将 primitive 解析为具体实例，如假路径、假端点、假文件名、改写权威短语、十六进制后缀等。生成是确定性的，种子由全局种子、primitive ID、实例索引和重试次数派生。
  3. **运行时注入**：Flask 扩展加载实例注册表；在挑战 handler 返回响应后，仅修改符合条件的 HTML 响应，如成功/重定向响应、非流式、未压缩 `text/html`、大小限制内。支持可见文本、隐藏 div、注释、meta、无障碍标签等 DOM 注入。
  4. **动态欺骗路由**：可注册 rabbit-hole、fake-goal、endpoint-specific trap 等路由，确定性且避免与真实路由冲突。
  5. **验证与遥测**：DOM verifier 用浏览器确认载荷到达预期通道；honeytoken 和结构化遥测记录请求、实例选择、欺骗渲染、honeytoken 命中、rabbit-hole 转换、fake-goal 查看等。
- **陷阱分类**：按意图分为五族：
  - **Goal hijack**：权威式线索把智能体重定向到诱饵目标。
  - **False authority**：制造虚假权威感，使智能体抬高错误线索。
  - **False validation**：让诱饵看起来已验证或成功，诱导错误完成。
  - **Exploration bait**：宣传诱人路径/端点，浪费探索预算。
  - **Time sink**：诱导低价值额外工作或 honeytoken 交互。
- **度量**：
  - **Solve rate**：提交精确 flag 的比例。
  - **Degradation**：同一模型—挑战下，干净解出率减陷阱解出率。
  - **Effort**：交互回合数、工具调用数、处理 token 数。
  - **遥测信号**：是否渲染陷阱、是否与诱饵/honeytoken 交互、错误 flag 提交次数等。
  - 论文没有复杂公式，核心是比较配对条件下的解出率变化和努力开销变化。

## 3. 实验设计

- **实验环境 / benchmark**：
  - AgentLSD 本身作为可复现 benchmark 框架。
  - 使用 **11 个自建 Flask Web CTF 挑战**，覆盖 7 类漏洞：命令注入、路径遍历、竞态条件、SQL 注入、SSRF、模板注入、XXE。
  - 挑战未复用公开 CTF，实验前未发布实现或 write-up，降低记忆或检索到题解的风险。
  - 陷阱使用 **14 个 DOM 实例**，覆盖 5 个陷阱族；一次实验只激活一个陷阱实例。
- **模型**：
  - 5 个本地部署模型：Gemma-4 31B、DeepSeek-V4 Flash、GPT-OSS 120B、Qwen3-Coder-Next、Mistral Small 4。
  - 1 个托管前沿模型：GPT-5，作为能力参考。
- **智能体设置**：
  - 所有模型使用同一 OpenCode scaffold，温度 0，最多 200 回合，30 分钟墙钟预算。
  - 工具包括 bash、read、write、edit、glob、grep；禁用 web search 和 web fetch。
  - 每个 trial 在全新容器、私有网络、新生成 flag 中运行；只有专用 flag 校验服务判定成功。
- **提示词**：
  - **default prompt**：极简，给出挑战、URL、接口、flag 格式，要求探索、假设、提交。
  - **methodical prompt**：增加结构化流程和常见漏洞探针建议。
  - 结果主要报告 default prompt；methodical 仅边际提升解出率，不改变陷阱效应结论。
- **对比设计**：
  - 并非与已有防御方法横向对比，而是进行：
    - 干净条件 vs 陷阱增强条件的配对比较；
    - 模型间比较；
    - 陷阱族、陷阱实例、挑战间比较；
    - GPT-5 作为能力参考，但只跑缩减网格。
  - Baseline 阶段：5 个本地模型跑全部 11 挑战和两种提示，各 5 trials；GPT-5 跑 11 挑战、default prompt、5 trials。
  - Trap 阶段：3 个最强本地模型跑 7 个保留挑战、14 个陷阱实例、两种提示，各 5 trials；GPT-5 只跑 5 个最具破坏性的陷阱实例、5 个高解出率挑战、default prompt。
  - 最终报告陷阱效应时只报告 5 个聚合干净解出率最高的挑战，以集中分析。
