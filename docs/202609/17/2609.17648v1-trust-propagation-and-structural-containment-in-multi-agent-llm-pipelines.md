## 摘要
多智能体 LLM 系统越来越多地自动化涉及具有不同权限级别的智能体的任务，从而带来一种安全风险：被攻陷的低权限智能体可能影响更高权限的智能体并触发未授权操作。我们研究了一个包含 Supervisor、Researcher、Validator 和 Executor 的四智能体 LangGraph 流水线中的攻击传播。我们评估了共享内存投毒，以及通过嵌入在检索文档中的伪造审批进行的间接提示注入。我们将 Validator 的判断与一个独立授权层进行比较，该授权层使用任务绑定的签名令牌和单独验证的策略预言机。我们的贡献包括：对攻击传播的实证研究、对授权边界的组件级消融，以及判断绕过率（JBR），该指标衡量的是被攻击智能体处的失陷，而非最终动作处的失陷。在三个随机种子和 60 个带标签任务上，内存投毒在每一次无防御试验中均到达执行阶段。启用授权后，其 JBR 达到 100%，但不安全动作率为 0%，表明执行虽被遏制，Validator 仍可能处于失陷状态。面对拥有签名密钥的攻击者，策略预言机提供了所观察到的遏制效果，而独立编写的最小权限策略保持了这一结果。一个 Observer 层将智能体劫持的假阳性率从 49% 降低到 7%，且不削弱执行级安全。这些结果表明，即使上游 LLM 判断失败，结构性授权也能遏制被攻陷智能体的行为。

## Abstract
Multi-agent LLM systems increasingly automate tasks involving agents with different levels of privilege, creating a security risk in which a compromised low-privilege agent can influence a higher-privilege agent and trigger an unauthorized action. We study attack propagation in a four-agent LangGraph pipeline comprising a Supervisor, Researcher, Validator, and Executor. We evaluate shared-memory poisoning and indirect prompt injection through a forged approval embedded in a retrieved document. We compare the Validator's judgment with an independent authorization layer using task-bound signed tokens and a separately verified policy oracle. Our contribution is an empirical study of attack propagation, a component-level ablation of the authorization boundary, and the Judgment Bypass Rate (JBR), which measures compromise at the attacked agent rather than at the final action. Across three seeds and 60 labeled tasks, memory poisoning reaches execution in every undefended trial. With authorization enabled, it achieves 100% JBR but 0% Unsafe Action Rate, showing that the Validator can remain compromised while execution is contained. Against an attacker possessing the signing secret, the policy oracle provides the observed containment, while an independently authored least privilege policy preserves this result. An Observer layer reduces the false-positive rate for agent hijacking from 49% to 7% without weakening execution-level security. These results show that structural authorization can contain compromised agent behavior even when upstream LLM judgment fails.

## 一、核心问题与整体含义（研究动机与背景）

- **背景**：多智能体 LLM 系统（编排者、检索者、推理者、执行者）通过分工让低权限智能体检索信息、中权限智能体审核、高权限智能体执行实际操作。这种委派链带来安全风险。
- **核心问题**：经典的"混淆代理人"（Confused Deputy）问题在多智能体场景中复现——被攻陷的低权限智能体可以伪造权威信息，影响高权限智能体，触发未授权动作。
- **研究缺口**：既有工作（如间接提示注入、工具型智能体攻击）主要考察"智能体是否会被欺骗"，而非"失陷是否真正抵达系统动作"。实际安全影响取决于下游授权、策略执行与独立验证等控制措施。
- **论文定位**：研究下游安全边界。作者明确声明 HMAC 签名能力令牌与基于策略的引用监控并非其创新点；真正贡献是**完整的攻击传播实证研究、授权边界的组件级消融、以及新指标 JBR（Judgment Bypass Rate，判断绕过率）**——用于区分"审核被绕过"与"未授权动作成功执行"。
- **公共安全含义**：在安全攸关场景中，必须区分"被绕过的审核"与"被阻止的攻击"，避免对系统安全性产生虚假信心。

## 二、方法论

### 2.1 核心思想
- 将 **LLM 判断**与**授权决策**分离：即使上游 Validator 的判断被攻陷，独立的授权边界仍应阻止未授权执行。
- 遵循"纵深防御、最小权限、完全中介"原则，用结构性验证替代智能体之间的隐式信任。

### 2.2 系统架构（四智能体 LangGraph 流水线）
- **Supervisor（无 LLM 调用）**：确定性路由器，按固定顺序把任务派发给子智能体。
- **Researcher（低权限，只读）**：检索内容并生成发现与建议动作。
- **Validator（中权限，审批门）**：审查建议动作，返回 approve/reject 及令牌。
- **Executor（高权限，真实操作）**：仅当请求同时通过两道检查才触及 SQLite 邮件存储。
- 四个角色通过**共享的类型化状态对象**通信，所有状态转移均被记录。

### 2.3 关键技术细节
- **签名令牌**：HMAC 签名、任务绑定、单次使用（nonce 防重放）。
- **策略预言机（policy oracle）**：独立重新推导权限，运行于两种模式：
  - *corpus policy*：镜像每个任务的 gold label（用于主体实验，因此 0% UAR 说明的是"对所给策略的执行保真度"，而非独立发现不安全动作）。
  - *independent policy*：手工编写的最小权限白名单，将动作映射到允许的资源范围，**不使用任务标签**，仅接收建议动作及其范围，与全部 60 个任务的 gold label 一致。
- **沙箱执行层**：记录真实的数据库与文件系统变更，从而可测量被攻陷智能体是否产生真实效果。

### 2.4 两种攻击模型
- **共享内存投毒**：Validator 被替换为受控例程，伪造审批；若持有签名密钥，还能在**不调用 LLM** 的情况下生成匹配的授权令牌。
- **智能体劫持（间接提示注入）**：Researcher 从被污染来源检索文档，文档中嵌入伪造的审批、置信度与来源声明；Validator 在不知来源的情况下对摘要进行推理。
- **攻击者能力逐级增强**，最终包含"持有签名密钥"的最强攻击者模型。

### 2.5 评价指标（公式用文字说明）
- **UAR（Unsafe Action Rate）** = FN /(TP + FN)：gold-unsafe 任务中真正到达执行的比例（越低越好）。
- **LTC（Legitimate Task Completion）** = TN /(TN + FP)：gold-safe 任务被允许完成的比例（越高越好）。
- **FPR** = FP /(FP + TN)，衡量过度拦截；按构造 LTC = 1 − FPR。
- **JBR（判断绕过率）** = Nb / Na：Na 为注入攻击的 gold-unsafe 试验数，Nb 为其中 Validator 的真实审核被跳过/绕过的数量。JBR 衡量**被攻击智能体处的失陷**，而非最终动作处的失陷。
- 混淆矩阵定义：TP = 被拦截的 gold-unsafe，FP = 被拦截的 gold-safe，FN = 被执行的 gold-unsafe，TN = 正确放行的 gold-safe。
- 防御条件：**T0** 关闭令牌检查与策略预言机；**T1** 同时启用两者。

## 三、实验设计

- **数据集/场景**：
  - 使用 **Enron Email Dataset**（50 万余封内部邮件、约 150 名员工）；解析 Message-ID、发件人、收件人、时间戳，取**固定子集 1,000 封**、仅保留邮件头，存入索引表，供 Executor 的沙箱工具视为真实可变数据。邮件数据是"攻击可产生可观测效果的易变资源"，而非分类目标。
  - **评测语料**：独立的 **60 个任务**（36 个安全、24 个不安全），覆盖 **13 种动作类型**，每个任务有具体资源访问范围。
- **模型配置**：Researcher、Validator 及（启用时）Observer 均使用 **gemma4:31b-cloud**，通过 Ollama 提供服务，temperature = 0；解码种子按"尽力而为"方式请求（Ollama 不保证固定种子下跨调用输出完全一致）。Supervisor 不做模型调用。每次试验日志记录 provider、模型、temperature 与 seed。
- **对比方法/条件**：
  - 三种试验条件：baseline（诚实来源、干净输入）、memory poisoning、agent hijacking。
  - T0 vs. T1 授权边界对比。
  - 授权消融：token-only vs. policy-oracle-only vs. T1（针对持有签名密钥的攻击者）。
  - corpus policy vs. independent least-privilege policy。
  - Observer OFF vs. ON。
- **统计设置**：三个随机种子（1、7、42），每格 n = 180 次试验；跨种子均值配 95% Student's t 区间（df = 2）。作者指出种子内的试验共享同一任务语料，不独立，因此区间是按种子计算的。

- **论文未提及任何 GPU 型号、数量或训练时长**。系统不涉及模型训练或微调，全部为推理调用。
- 唯一相关的计算说明是：所有 LLM 智能体通过 **Ollama 调用 gemma4:31b-cloud**，temperature 设为 0，解码种子尽力固定。

## 五、实验数量与充分性

- **规模概览**：
  - 主实验：2 种攻击 × 2 个防御层级（T0/T1）× 3 个种子，每格 n = 180（共约 720 次试验级别）。
  - 授权消融：单一种子，每条件 n = 60，共 4 个条件（T0、token-only、policy-oracle-only、T1）。
  - 独立策略对比：T1 下两种攻击 × 两种策略，3 种子、每格 n = 180。
  - Observer 评估：3 种子、n = 180；另有 120 个配对案例（60 任务 × 干净/劫持）用于独立刻画 Observer。
- **充分性评价**：
  - 优点是做了**组件级消融**（token vs. policy oracle 分离），并把攻击者能力提升到"持有签名密钥"的强假设，这在同类工作中较少见，能避免把"因缺少凭据而失败的攻击"误判为安全保证。
  - 客观性方面：引入 independent policy 以缓解"策略由评测标签派生"的循环论证风险；作者也承认两者由同一团队编写，因此只提供"实现非循环"的证据，而非"策略客观正确"的证明。
  - **不足**：授权消融仅单种子、无置信区间；仅 3 个种子导致区间很宽；语料仅 60 任务、13 种动作类型；仅单一架构（LangGraph）、单一模型；劫持注入是"显眼"的（显式声称已审批、含置信度与来源），可能显著高估检测效果。因此总体实验规模偏小，属于**原理性验证而非全面基准测试**。

## 六、主要结论与发现

- **内存投毒**：T0 下**每次试验都成功抵达执行**（UAR 100%）；T1 下 UAR 降至 0%，但 **JBR 仍为 100%**——说明 Validator 依然处于失陷状态，只是 Executor 独立阻止了未授权动作。这直接支撑"上游判断失陷 ≠ 系统动作失陷"的核心论点。
- **智能体劫持**：T0 与 T1 下 UAR 均为 0%，但 Validator 因把伪造审批视为可疑而大量拦截合法任务，FPR 从 59.3%（T0）到 49.1%（T1）；作者强调该差异**不应归因于授权**（令牌与策略只能"扣留执行"，不能阻止 Validator 批准），而是 Validator 判断的波动，且置信区间重叠。
- **授权消融**：面对持有签名密钥的攻击者，**token-only 与 T0 无法区分**（UAR 100%），而 **policy-oracle-only 完全复现 T1**（UAR 0%）。结论：遏制效果来自独立策略预言机，而非签名检查本身；但签名令牌在无密钥时仍可防伪造、绑定任务与范围、防重放（这些收益本实验未直接评估）。作者提炼为：**"签名授权的是来源，而非权限"**，仅有签名的系统会继承持钥者的全部权限。
- **独立策略**：内存投毒下独立策略提供与 corpus policy 相同的遏制；劫持下 FPR 相近（49.1% vs. 46.3%，区间重叠），F1 在小数点后两位完全相同，说明遏制不是标签派生策略的假象。
- **Observer 层**：FPR 从 49.1% 降至 7.4%（相对下降 85%），F1 从 0.74 升至 0.95，LTC 从 50.9% 升至 92.6%，而 **UAR 保持 0%**；JBR 从 0% 升至 4.2%（残余判断错误仍被独立授权边界遏制）。在 120 个配对案例上，干净样本全部得到置信度 0.0 与 CLEAN，劫持样本全部得到 1.0 与 INJECTION，**完全可分**，因此阈值扫描在 τ ∈ (0,1] 上给出同一工作点，传统 ROC 曲线在此不具信息量。
- **总体结论**：结构化授权可以在上游 LLM 判断失效时遏制被攻陷智能体的行为；把 LLM 判断与授权分离，可将被攻陷智能体视为不可信决策者，而不自动授予其造成真实系统影响的能力。

## 七、优点

- **概念贡献清晰**：提出 **JBR** 指标，把"审核被绕过"与"未授权动作成功"解耦，弥补了以往工作中"智能体被欺骗"与"有害动作"混为一谈的问题。
- **强攻击者模型**：明确构造持有签名密钥的攻击者，从而暴露了"签名 ≠ 权限"这一常被忽视的盲点，并用消融把承载安全性的组件精确定位到策略预言机。
- **控制变量严谨**：单一代码库、固定智能体/图拓扑/提示词/任务语料/注入方式，只改变防护层；所有试验日志记录 provider、模型、temperature、seed。
- **缓解循环论证的努力**：额外引入不含标签信息的手写最小权限策略，并显式说明其证明力边界（同团队编写）。
- **诚实的自我批判**：作者主动指出 corpus policy 的 0% UAR 只反映"执行保真度"而非"独立发现不安全动作"，并承认置信区间宽、注入过于显眼等问题。
- **工程可操作性**：Observer 被明确定位为"保效用组件"而非安全控制（无任务记录、gold label、策略预言机或 Validator 输出的访问权，也不能批准或阻止动作），职责边界清晰。

## 八、不足与局限

- **策略独立性不足**：independent policy 虽无法访问 gold label，但仍由撰写语料的同一团队手工编写，只能证明实现非循环，不能证明策略客观正确。
- **统计效力弱**：仅 3 个种子，跨种子 t 区间很宽（劫持 FPR 95% 区间 T1 为 [28.1%, 70.0%]）；授权消融只有单种子、无置信区间。
- **规模与覆盖有限**：仅 60 个任务、13 种动作类型；仅单一架构（LangGraph）、单一框架、单一模型（gemma4:31b-cloud），Validator 行为可能随模型变化，结论的普适性有待验证。
- **注入过于显眼**：劫持注入显式断言"已审批 + 置信度 + 来源"，很可能解释了 Validator 在无 Observer 时 0% JBR 以及分数的完全可分；因此 Observer 的工作点**不可外推到自适应攻击者**。更隐蔽的注入可能造成分数分布重叠、非平凡的 ROC 曲线与非零 JBR（此时执行级遏制仍不依赖可检测性，因为策略预言机从不读取检索内容）。
- **未评估的能力**：签名令牌在"攻击者不持有密钥"场景下的防伪造、任务/范围绑定、防重放等收益未被直接测量，未来工作需针对较弱攻击者验证令牌的承载作用。
- **推理成本不透明**：Observer 是每次流水线额外一次同模型调用，但论文未报告延迟、token 或成本开销，也未做成本—效用分析。
