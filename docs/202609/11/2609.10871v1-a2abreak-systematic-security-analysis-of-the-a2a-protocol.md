## 摘要
Agent2Agent（A2A）协议现由 Linux 基金会管理，是一项开放标准，使自主 AI 智能体能够跨组织边界相互发现、认证并委派任务。该协议旨在补充用于工具集成的模型上下文协议（MCP），并正迅速成为多智能体生态系统的横向通信层。然而，该协议的安全性尚未得到系统性分析。本文提出 A2ABreak，这是对 A2A 协议的首个严谨系统性安全分析。我们引入一种新颖框架，利用 LLM 辅助直接从自然语言规范中提取经校验的有限状态机，从 929 条形式化语句生成包含 37 个状态和 76 个转移的统一模型，然后在该模型上进行系统性推理，并在完全合规假设下通过对抗性验证发现协议级漏洞。我们的分析揭示了 11 个新漏洞，每个漏洞都可被符合规范的对手利用，且无需任何实现缺陷。这些发现包括：通过未受保护的上下文标识符进行跨客户端上下文注入、通过委派链中的多跳身份丢失进行凭证窃取，以及通过宣称未经证实能力声明的恶意智能体进行数据外泄。在独立专家评审下，A2ABreak 达到 73.3% 的精确率和 84.6% 的 F1，而在相同规范上运行的零样本 LLM 基线未产生任何经确认的发现，这表明显式形式化基础对于可靠的协议安全分析至关重要。

## Abstract
The Agent2Agent (A2A) protocol, now governed by the Linux Foundation, is an open standard that enables autonomous AI agents to discover, authenticate with, and delegate tasks to one another across organizational boundaries. Designed to complement the Model Context Protocol (MCP) for tool integration, A2A is rapidly emerging as the horizontal communication layer of the multi-agent ecosystem. Yet the protocol's security has received no systematic analysis.   This paper presents A2ABreak, the first rigorous systematic security analysis of the A2A protocol. We introduce a novel framework that utilizes an LLM-assisted extraction of a verified finite-state machine directly from the natural-language specification, producing a unified model of 37 states and 76 transitions from 929 formalized statements, and then systematically reasons over this model to discover protocol-level vulnerabilities through adversarial verification, under a full-compliance assumption.   Our analysis uncovers 11 new vulnerabilities, each exploitable by a specification-compliant adversary without requiring any implementation flaw. Among the findings are cross-client context injection through unprotected context identifiers, credential harvesting via multi-hop identity loss in delegation chains, and data exfiltration through rogue agents advertising unattested capability claims.   A2ABreak achieves 73.3% precision and 84.6% F1 against independent expert review, while a zero-shot LLM baseline operating over the same specification produces zero confirmed findings, demonstrating that explicit formal grounding is essential for sound protocol security analysis.

# A2ABreak：A2A 协议的系统性安全分析——论文总结

## 1. 核心问题与整体含义

- **研究动机**：Agent2Agent（A2A）协议由 Google 于 2025 年 4 月提出，2025 年 6 月移交 Linux 基金会管理，已获 50 多家厂商支持，正成为多智能体生态系统的**横向通信层**（与 MCP 的纵向工具集成互补）。但该协议的安全性此前**没有任何系统性分析**。
- **背景痛点**：
  - 协议的核心设计原则是**不透明执行**（opaque execution）——客户端无法验证远端智能体对任务、凭证、返回产物的实际处理。
  - 安全模型以 **SHOULD/MAY 非规范性指导**为主，关键机制（如发现阶段的智能体身份验证原语）完全是可选的。
  - 无开源参考实现，因此无法使用静态分析、模糊测试、符号执行等实现级方法。
- **整体含义**：本文是 A2A 协议的**首个系统性安全分析**，在"完全合规假设"下证明：即使对手完全遵守规范，仍可利用规范本身的设计缺口发动攻击，说明**协议级设计缺陷会直接传播为任何合规部署中的可利用漏洞**。

## 2. 方法论

### 核心思想
将自然语言协议规范经 LLM 辅助转化为**经校验的有限状态机（FSM）**，再在 FSM 上进行约束化推理与对抗性验证，以在完全合规假设下发现协议级漏洞。

### 三阶段框架

**Stage A：规范形式化**
- **A1 结构提取**：提取 FSM_STATE（生命周期状态）、CONSTRAINT（全局不变量）、IMPLICIT_TRANSITION（隐含状态转移，即使无 RFC 2119 关键词）。
- **A2 行为提取**：独立扫描含 RFC 2119 关键词的句子，编码为 BEHAVIORAL 转移语句，保留 must/shall/should/may 义务强度。
- **A3 协调**：合并两遍输出，去重（精确/近似），歧义案例交 LLM 处理并强制人工复核。
- **A4 规范验证**：逐条对照源文本验证，检测幻觉状态、错误归属的规范性关键词、源中不存在的守卫条件。
- 每句话编码为元组 ⟨s1, pre_cond, trigger, post_cond, s2⟩，对应形式记法 s1 --c/a--> s2（c 为守卫条件，a 为效果）。

**Stage B：FSM 构建**
- **B1 输入过滤**：确定性、无 LLM 的过滤，按协议阶段划分，仅保留携带转移结构的语句。
- **B2 分阶段 FSM 合成**：独立构建 6 个阶段 FSM，每个状态标注 actor（client/server/shared/unknown），**shared-actor 状态标记信任边界**，是后续分析的主要目标。
- **B3 阶段间转移解析**：识别跨阶段边（含 Task Execution ↔ Interruption 的双向循环）。
- **B4 统一 FSM 组装**：确定性合并 + 两级去重（D1 确定性规范化命名/合并重复；D2 LLM 语义去重，移除元状态、折叠透传状态）。
- 最终得到 **37 状态、76 转移**的统一 FSM，零孤立状态、引用完整性完备。

**Stage C：安全分析**
- **C1 漏洞发现**：扫描 FSM 中的结构性弱点（敏感转移缺授权守卫、阶段边界缺检查、事件字母表缺口），并施加两道过滤：攻击迹必须完全在 A2A 协议内可执行；必须经网络搜索确认缺口是真正的"缺失原语"而非有意设计。
- **C2 对抗性与人工验证**：四步对抗验证——将迹锚定于 FSM 状态、确认完全合规下可执行、确认无任何规范性规则阻止、确认原语确实缺失；再经独立人工评审。
- 漏洞形式化定义为三元组 **V = (π, ρ, ϕ)**：可行攻击迹 π、被违反的安全属性 ρ、缺失原语 ϕ。

### 三大挑战与对应方案
| 挑战 | 方案 |
|---|---|
| C1 自然语言规范无法精确语义解释 | S1 双遍语义分离（结构/行为独立提取） |
| C2 开放式模型生成正确性无保障 | S2 输入缩减（929 条→283 条进入 FSM）+ 扩展思考 |

## 3. 实验设计

- **数据集 / Benchmark**：
  - **PSMBench 的 TCP 真值基准**（无 A2A 对应基准，TCP 作为代理），含 11 个状态、20 个转移。

## 6. 主要结论与发现

- **11 个协议级漏洞**，全部在完全合规、无实现缺陷条件下可被利用，覆盖 Discovery、Initiation、Task Execution、Interruption 四个阶段，映射到 STRIDE 类别与具体规范章节。
- **三个代表性发现**：
  1. **跨客户端上下文注入**（§3.4.1、§3.4.3）：`contextId` 无所有权绑定或访问控制，任意已认证客户端可向他人上下文注入任务、读取受害者的累积状态并污染后续交互。
  2. **多跳身份丢失**（§7.2、§7.6.2）：身份仅在传输层逐跳建立、不跨跳传播，恶意中间智能体可静默收集并重放转发的凭证；凭证提供者无法做出知情授权决策。
  3. **未认证的技能声明**（§4.4.5、§8.4）：`AgentSkill` 全为自断言字段，JWS 签名只证明"谁发布了卡片"而非"能力是否真实"，合规恶意智能体可广告虚假能力、接收敏感数据并返回伪造产物。
- **零样本基线在两次运行中产生 9 个候选、全部被拒**，证明缺乏显式 FSM 基础时，即使先进推理模型也无法区分真正的协议缺口与规范已约束的行为。
- **文本体量是行为复杂度的误导性代理**：Authentication 仅 21 条语句却产生 16 个转移（比值 0.76，是 Discovery 的 3 倍）；Interruption 指标最小却编码了多跳链中凭证累积的核心重入循环。

## 7. 优点

- **首创性**：首个对 A2A 协议的完整 FSM 形式化建模与规范级漏洞分析，并构建首个结构化威胁模型。
- **方法论严谨**：双遍语义分离、约束语言防幻觉、四步对抗验证、阶段边界强制人工检查点，系统性防止错误静默传播。

- **可复现性**：承诺开源全部源码、提示词、阶段 FSM 与实验工件（GitHub 仓库已给出）。

## 8. 不足与局限

- **无 A2A 专属真值基准**：只能以 TCP 作为代理验证 FSM 提取正确性，A2A 模型的绝对忠实度缺乏独立验证。
- **纯规范分析、无实现验证**：论文明确不验证具体智能体实现，也不涉及传输层安全；实际部署中的漏洞可利用性未经验证。
- **漏洞集合非穷举**：作者声明不枚举所有可能漏洞。
- **样本量偏小**：漏洞分析仅 5 次运行、17 个候选，precision 73.3% 意味着约四分之一候选为假阳性，误报风险存在。
- **强假设依赖**："完全合规假设"排除了配置错误、实现 bug 等现实常见因素，可能低估/高估实际风险面。

- **成本门槛**：单次运行 $40.97，若需多轮发现与消融，总成本可观；论文未报告总 token 消耗与运行时长。
