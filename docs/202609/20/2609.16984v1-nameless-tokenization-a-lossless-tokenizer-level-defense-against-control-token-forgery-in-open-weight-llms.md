## 摘要
开放权重语言模型会公开其聊天模板用于标记轮次、角色和工具结果的字符串，而分词器会将这些字符串映射回模型所遵循的保留标识符。因此，任何能控制提示中文本的人，都能写出一个与服务栈所写轮次边界无法区分的轮次边界。我们审计了256个已部署的聊天分词器。所有分词器都可被伪造，而通常被推荐作为修复方案的那个标志仍使56.6%的分词器可被伪造，因为它遗漏了智能体系统所依赖的工具与推理标记。我们提出无名分词，它让控制条目只保留一个保留标识符，而不带任何表面字符串，因此内容编码器无法生成表面字符串，消息内容可原样到达模型。在五个分词器家族上，它在无攻击数据上精确复现标准词元流，并将包含分隔符文本的探针准确率从8.5%提升至59.9%，而净化器在该探针上会损失准确率。将分隔符的外观与其标识符分离后可见：在面对裸任务指令时，标识符影响甚微；但一旦系统消息告诉模型将用户内容视为数据，它就承载了伪造工具结果的大部分作用，以及任何伪造轮次的大部分作用。

## Abstract
Open-weight language models publish the strings their chat templates use to mark turns, roles and tool results, which the tokenizer maps back to the reserved identifiers the model obeys. Anyone who controls text in a prompt can therefore write a turn boundary indistinguishable from one the serving stack wrote. We audit 256 deployed chat tokenizers. All are forgeable, and the flag usually recommended as a fix leaves 56.6% forgeable because it misses the tool and reasoning markers agent systems rely on. We propose nameless tokenization, which leaves the control entries with a reserved identifier and no surface string, so the content encoder cannot emit one and message content reaches the model unaltered. Across five tokenizer families it reproduces the standard token stream exactly on attack-free data and lifts accuracy on a probe of delimiter-bearing text from 8.5% to 59.9%, where sanitizers lose it. Separating a delimiter's appearance from its identifier shows the identifier matters little against a bare task instruction, but carries most of a forged tool result and most of any forged turn once the system message tells the model to treat user content as data.

# 论文结构化总结：无名分词（Nameless Tokenization）

## 1. 核心问题与整体含义

- **研究背景**：开放权重语言模型（LLM）会公开其聊天模板所用的控制字符串（如 `<|im_start|>`、`<|im_end|>`、`<tool_call>` 等），分词器会将这些字符串映射回模型所遵循的保留标识符（reserved identifiers）。这些标识符在模型实际读取的扁平 token 序列中标记轮次、角色和工具结果的边界。
- **核心问题**：任何能控制提示中文本的人（如通过检索文档、工具返回内容等间接注入），都能写出与服务栈所写无法区分的轮次边界，从而实现控制词元伪造（control-token forgery），这是提示注入（prompt injection）的一个子问题。
- **问题严重性**：
  - 审计 256 个已部署聊天分词器，**100% 可被伪造**。
  - 通常推荐的修复方案 `split_special_tokens` 仍使 **56.6% 的分词器可被伪造**，因为它只抑制仓库标记为 special 的 token，而 56.2% 的模型将至少一个控制 token 注册为非 special。
  - 漏掉的主要是 `<tool_call>`、`</tool_call>`、`<think>`、`</think>`、`<tool_response>`、`</tool_response>` 等工具调用与推理标记——正是智能体系统所依赖的通道。
- **整体含义**：这是提示注入问题中**唯一能提供保证（guarantee）而非缓解（mitigation）**的部分。其他防御（如训练时指令层级、结构化查询、段嵌入、架构分离）属于缓解措施，而无名分词从构造上关闭了文本到标识符的通道。

## 2. 方法论

### 核心思想
- **无名词元（nameless token）**：一个词表条目拥有嵌入向量和保留标识符，但**没有任何表面字符串能被编码器映射到它**。
- **无名分词（nameless tokenization）**：基于此类词元构建的渲染方案，使得对任意攻击者选择的文本 $t$，都有 $E_c(t) \cap C = \emptyset$，其中 $C$ 为模板发出的保留标识符集合，$E_c$ 为内容编码器。

### 关键技术细节
- **内容编码器无法命名控制词元**：
  - Fast tokenizer 通过一张在子词模型之前查询的表来解析 added tokens。
  - 实现方式：序列化 tokenizer → **清空该表** → **移除注入句子标记的后处理器** → 重新加载。
  - 结果 $E_c$ 是同一子词模型、同一词表，但**没有任何从字符串到标识符的路径**（该路径只能由被清空的表产生）。
- **模板层直接写标识符**：
  - 用占位符代替每条消息渲染模板。
  - 在模板自身写出的保留表面字符串处**切分**渲染后的字符串，这些字符串**直接成为标识符**。
  - 其余所有内容（模板文本与消息内容）以**最大连续段**交给 $E_c$，使子词模型看到的字符串与标准分词下相同，**分段不会在消息边界漂移**。
- **通用性**：该过程仅通过模板的输出来读取模板，因此一个实现即可覆盖所有研究的模型家族。
- **无损性定义**：消息的每个字符都原样到达模型——这是渲染方案的属性，而非对攻击率的声明。

### 与威胁模型的关系
- 攻击者只能选择文本，不能选择 token 标识符（文本接口部署场景）。
- 模型开放权重，攻击者知道模板和 $C$ 中每个元素，**保密不是防御**。
- 调用方直接提供标识符、或在渲染器之外重建提示的部署**不在防御范围内**。

## 6. 主要结论与发现

- **无攻击数据时无损**：100.0% 的无攻击宿主提示在所有家族上分词结果完全相同，准确率 89.1%（标准）对 88.9%（无名），基本无损失。
- **分隔符保真度探针**：标准分词仅 8.5%，Strip 降至 2.2%，Mask 23.0%，Escape 24.1%，**无名分词达 59.9%**——净化器以破坏内容为代价换取安全，而无名分词不破坏。
- **裸任务指令下标识符影响小**：伪造用户轮次对标准分词成功率 99.9%，无名分词下仍 92.8%，无分隔符仅 62.4%。即**表面外观贡献 30.4 个百分点，标识符仅贡献 7.1 个百分点**。拼写错误的 lookalike 也达 93.0%，说明关键是"形状像边界"的文本，而非特定字符串。
- **工具通道最清晰**：伪造工具结果在标准分词下 33.1%，无名分词降至 7.4%（主要来自 Qwen-3.8-27B），因为除非有保留标识符标记，模型没有理由采信工具结果——而这正是推荐标志在 56.6% 分词器上遗漏的通道。
- **一旦提示自身有防御，标识符成为关键**：防御性系统消息效果模型特定（Gemma-4-31B 上几乎阻断一切，GPT-OSS-20B 上毫无作用）。在 Llama-3.1-8B 和 Ministral-3-8B 上，该句将纯文本注入压至 4.1% 和 0.0%，但伪造轮次仍达 98.3% 和 99.0%（边界压过指令）；移除标识符后降至 50.0% 和 23.3%，Qwen-3.8-27B 工具通道从 53.4% 降至 0.7%。
- **扰动测试**：无防御时 27.3% 的扰动置入保留标识符，启用标志后仍有 5.1%（Qwen3.8-27B 达 18.3%）；字符串过滤器全部阻断但代价是内容损伤；无名分词为 **0.0%**，且无需搜索即可确知。
- **与训练级分离对比**：训练级分离在已训练处占主导（无名分词无增益，但训练级分离损失 11.4 个干净准确率百分点）；在未训练处，无名分词将伪造系统攻击从 98.0% 降至 66.6%，且**只有无名分词是零成本的**。

## 7. 优点

- **提供构造性保证而非缓解**：$E_c(t) \cap C = \emptyset$ 对任意攻击者文本成立，无需枚举攻击字符串。
- **无损**：消息每个字符原样到达模型，不删除、不替换、不损伤内容；攻击面分解显示净化器在分隔符探针上损失惨重（8.5%→2.2%），而无名分词反而提升（59.9%）。
- **零成本、即插即用**：仅改动文本到标识符接口，不训练、不修改模型，不改变无攻击数据上的 token 流。
- **通用性强**：过程仅通过模板输出读取模板，一个实现覆盖所有研究的模型家族。
- **实验设计精细**：攻击之间仅分隔符不同，系统性地将"分隔符外观"与"标识符"的贡献分离，得到反直觉的重要发现（裸指令下标识符只值 7.1 点，但有防御性系统消息时标识符才是关键）。
- **审计范围广**：256 个真实部署分词器 + 16,415 个扰动，量化了推荐修复方案的盲区（工具与推理标记）。
- **诚实的负面结果报告**：明确指出在伪造系统攻击下移除标识符会使模型更可能遵从（46.9%→68.0%），以及训练级分离已生效时本方法无增益。

## 8. 不足与局限

- **实验覆盖有限**：仅 5 个模型、3 个宿主任务、2 个注入目标；绝对攻击率会随目标或项目池变化，应作为攻击面分解而非部署风险估计。
- **防御性系统消息过于简单**：仅测试一句话，硬化部署应结合检索卫生与训练级分离，而后者未被建模。
- **无损性仅针对内容，不覆盖所有攻击**：移除保留标识符后相同分隔符文本仍留在活跃轮次内，在伪造系统攻击上反而使模型更易遵从（46.9%→68.0%）。
- **范围限制**：保证仅针对文本到标识符接口；直接接受调用方提供的 token 标识符、或在渲染器之外重建提示的部署不在范围内。
- **探针为合成诊断**：分隔符保真度探针基于合成块，只能证明净化器破坏含分隔符内容，不能说明此类内容在给定工作负载中的出现频率。
- **审计覆盖偏差**：审计仅覆盖附带聊天模板且无需执行仓库代码即可加载的仓库，**低估了以自定义分词器代码分发的模型**。
- **可复现性小瑕疵**：GPT-OSS-20B 批推理非位级可复现，部分数值存在解码噪声；实验使用单一种子 0，未报告多种子重复。
