## 摘要
移动智能体日益能够自主地与移动应用交互，并代表用户执行具有重要后果的操作。对此类智能体进行有效的人类监督依赖于一个基本前提：用户与智能体从同一界面中观察到一致的信息。我们表明，这一前提可能被系统性地违背。用户通过物理显示屏和人类视觉系统感知移动界面，因此其观察会受到遮挡和亮度对比度限制的影响。相比之下，智能体消费的是数字截图以及可访问性表示，前者可能保留此类内容，后者会暴露非视觉的控件元数据。因此，同一 UI 状态可能向用户和智能体呈现实质不同的信息，我们将这种不匹配称为人-智能体 UI 失同步。我们研究合法 APK 的重打包克隆能否利用这种失同步，将智能体引导至攻击者指定的操作，同时对人类用户仍保持完整功能并与原始应用行为一致。我们证明这一威胁是可行的：部署前嵌入的扰动即可诱发此类偏差，而无需访问运行时用户指令、智能体检测或在线适应。为系统性地揭示并评估这一威胁，我们开发了一个自动化框架，用于构造与用户运行时指令无关的 UI 失同步攻击，并在可部署的 APK 中实现这些攻击。我们在涉及多种应用的 546 项任务上，跨五种移动智能体框架和三种骨干模型进行了静态与动态评估，分别达到 77.9% 和 66.9% 的平均误导率。一项有 186 名参与者参与的补充问卷研究发现，我们攻击中使用的视觉扰动难以被人类用户察觉。

## Abstract
Mobile agents are increasingly capable of autonomously interacting with mobile applications and performing consequential actions on behalf of users. Effective human oversight of such agents relies on a basic premise: users and agents observe consistent information from the same interface. We show that this premise can be systematically violated. Users perceive mobile interfaces through physical displays and the human visual system, making their observations subject to occlusion and luminance contrast limitations. In contrast, agents consume digital screenshots that may retain such content and accessibility representations that expose nonvisual widget metadata. The same UI state can therefore present materially different information to users and agents, a mismatch we term human-agent UI desynchronization. We investigate whether a repackaged clone of a legitimate APK can exploit this desynchronization to steer an agent toward attacker-designated actions, while remaining fully functional and behaviorally consistent with the original application for human users. We demonstrate that this threat is feasible: perturbations embedded before deployment can induce such deviations without access to runtime user instructions, agent detection or online adaptation. To systematically expose and evaluate this threat, we develop an automated framework that constructs user runtime instruction-agnostic UI desynchronization attacks and realizes them in deployable APKs. We conduct static and dynamic evaluations across five mobile-agent frameworks and three backbone models on 546 tasks involving various applications, achieving average misleading rates of 77.9% and 66.9%, respectively. A complementary questionnaire-based study with 186 participants finds that the visual perturbations used in our attacks are difficult for human users to notice.

# 论文总结：当智能体所见不同——揭示移动智能体中的 UI 失同步威胁

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：移动智能体（mobile agents）日益能够自主操作 App、代表用户执行具有实际后果的操作。有效的人类监督依赖一个基本前提：**用户与智能体从同一界面观察到一致的信息**。
- **核心发现**：该前提可被系统性违背。用户通过物理显示屏与人类视觉系统感知界面，受**几何遮挡**（挖孔、圆角）和**光度对比度限制**影响；而智能体消费的是**数字截图**（保留被遮挡区域内容、保留微小像素差异）和**无障碍表示**（暴露非视觉控件元数据）。
- **概念提出**：同一 UI 状态向用户与智能体呈现实质不同的信息，称为**人-智能体 UI 失同步（human-agent UI desynchronization）**。当这种不一致能影响智能体的解释、规划或动作选择时，即为**动作相关**。
- **安全含义**：攻击者可利用该失同步，通过合法 APK 的**重打包克隆**，在保持对真人用户功能与外观一致的前提下，将智能体引导至攻击者指定操作。
- **与既有工作的区别**：不依赖显式运行时内容注入、在线感知、模型投毒/后门，也无需访问运行时用户指令、智能体检测或在线适应；扰动在**部署前**嵌入，对**未来用户指令不可知**。

## 2. 方法论

### 2.1 核心思想与威胁模型

- **攻击目标**：保留应用面向人的正常行为，使智能体选择攻击者指定动作（以**蜜罐控件 honeypot** 为受控指标）。
- **攻击者能力**：可理解 APK 的一般功能与典型任务，但**无法预测真实用户的具体指令**；可通过离线实验、插桩、日志分析了解智能体框架的感知与决策机制。
- **约束**：
  - **隐蔽性**：不引入显眼视觉伪影、异常行为或工作流中断。
  - **可部署前准备**：所有扰动在 APK 发布前嵌入，运行时不动态修改。
  - **指令无关与泛化**：不针对特定运行时指令，需跨多样用户目标、措辞和交互流程有效。
  - **不检测人机**：不依赖运行时判断操作者是人是机。

### 2.2 扰动策略空间

- 将智能体决策抽象为三阶段：**状态感知 → 规划生成 → 动作选择**，据此设计 **9 种任务无关策略**：
  - **状态导向（S1–S3）**：S1 状态未就绪伪造、S2 风险感知转移、S3 身份约束误导。
  - **路径导向（S4–S6）**：S4 路径竞争注入、S5 伪最优路径构造、S6 流程引导劫持。
  - **偏好导向（S7–S9）**：S7 显著性操纵、S8 安全偏见利用、S9 社会信号操纵。
- 每种策略由多个**可组合操作**构成：`s_i = o_i1 ⊕ o_i2 ⊕ … ⊕ o_iM`，每个操作配有自然语言提示模板，由 LLM 生成应用特定候选实现。

### 2.3 特征空间搜索

- **目的**：避免在问题空间反复重建、安装、执行 APK，直接在智能体观测空间（结构化无障碍表示 / 视觉截图）搜索。
- **流程**：
  1. **策略选择**：对每种策略 `s_i`，在离线任务子集 `T` 上评估：
     - `S(s_i) = (1/|T|) Σ I[hit(t, s_i)] − λ · cost(P0, Pi)`
     - 成本 `cost(P0, Pi) = w_char · (|Pi|−|P0|)/|P0| + w_view · n_perturb`，兼顾文本增量与新增/修改控件数。
  2. **操作选择与排序**：留一法消融估计每个操作贡献：
     - `φ(o*_k) = S(s*(O*)) − S(s*(O* \ {o*_k}))`
     - 若 `φ < 0` 则剪枝；按 `φ` 降序排序。
  3. **内容优化**：按排序依次优化操作实现，采用**束搜索**（beam width n=2）。引入**迭代删除排名奖励（IDRR）**：
     - 反复查询智能体并移除其当前选中控件，直到蜜罐被选中，记 `rank(W)` 为选中轮次（上限 5 轮，未选中则 `rank(W)=∞`）。
     - 奖励 `reward = γ^(rank(W)−1), 0<γ<1`，比二元成功信号提供更细粒度偏好。
     - 结构化扰动使用 IDRR；视觉扰动因成本考虑使用二元成功信号。

### 2.4 问题空间实现

- **结构化表示扰动**：
  - 在 window decor view 上叠加透明 `FrameLayout`，动态挂载蜜罐控件。
  - 蜜罐控件极小（如 **8dp×8dp**），低于触摸目标规范，用户几乎无法点击，但无障碍树中可见、可点击。
  - 修改现有控件的 `contentDescription` 等无障碍元数据（如追加误导性前缀）。
- **视觉表示扰动**：
  - 利用 **Android 沉浸模式 + `LAYOUT_IN_DISPLAY_CUTOUT_MODE_ALWAYS`**，将蜜罐控件渲染到**显示挖孔区域**，截图可见但被前摄硬件部分遮挡。
  - 注入**极低对比度文本**（仅 **12 点 RGB 差异**）到视觉非活跃背景区域，人类难以察觉但像素差异保留在截图中。
  - 通过 overlay 层注入，不改动原始布局；可预置多套放置模板以适配不同设备挖孔几何。
