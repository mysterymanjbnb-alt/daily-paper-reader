## 摘要
LLM 智能体在持久性的协作环境中运行，涉及多个用户、社区、记忆、文件和工具。社区边界可能保持固定，也可能随着成员、角色、构成和关系的变化而演变。智能体必须完成合法任务，并防止未经授权披露受保护信息。现有评估并未充分考察智能体系统中的这些风险。我们提出 CoSec，一个可执行基准，用于评估在社区内部和跨社区运行的 LLM 智能体系统中的隐私与授权执行情况。CoSec 包含 208 个典型场景，涵盖固定边界和演变边界、属于智能体所有者或其他参与者的受保护信息，以及通过对话、环境内容、持久记忆和组合工作流发起的攻击。CoSec 执行完整的智能体系统，这些系统具有持久会话、记忆、文件和工具。它利用执行轨迹和产物，对照当前生效的授权状态验证信息流。在不同的测试框架和模型配置下，智能体常常能完成良性任务，却违反隐私与授权边界。隐私行为因测试框架、攻击面和社区状态而异，揭示了记忆、文件、工具和工作流如何能够将受保护信息带出其授权范围。这些发现表明，任务效用并不意味着隐私或授权合规，并且社区场景中的授权对于持久运行的 LLM 智能体而言仍是一个尚未解决的安全挑战。

## Abstract
LLM agents operate in persistent collaborative environments involving multiple users, communities, memories, files, and tools. Community boundaries may remain fixed or evolve with changes in membership, roles, composition, and relationships. Agents must complete legitimate tasks and prevent unauthorized disclosure of protected information. Existing evaluations do not fully examine these risks in agent systems. We introduce \textbf{CoSec}, an executable benchmark for evaluating privacy and authorization enforcement in LLM agent systems operating within and across communities. CoSec contains 208 canonical scenarios spanning fixed and evolving boundaries, protected information belonging to the agent owner or other participants, and attacks through dialogue, environmental content, persistent memory, and composed workflows. CoSec executes complete agent systems with persistent sessions, memory, files and tools. It verifies information flows against the active authorization state using execution traces and artifacts. Across harness and model configurations, agents frequently complete benign tasks but violate privacy and authorization boundaries. Privacy behavior varies across harnesses, attack surfaces, and community states, revealing how memory, files, tools, and workflows can carry protected information beyond its authorized scope. These findings show that task utility does not imply privacy or authorization compliance and that authorization in community settings remains an unresolved security challenge for persistent LLM agents.

## 1. 核心问题与整体含义（研究动机与背景）

- **部署形态转变**：LLM 智能体正从孤立的单任务助手转向持久化的协作参与者，在群组对话、组织和在线社区中充当用户的长期代理，涉及多个用户、社区、记忆、文件与工具。
- **多主体安全风险**：一个个人智能体可能同时参与健康支持社区与工作群组。前者获知的信息虽留在历史、记忆或工作区中，但不应披露给后者。消息、文档或工作流指令可能诱导智能体检索或转移属于他人的信息。
- **边界动态演化**：社区边界可能保持固定，也可能因成员、角色、构成、关系变化而演变，这使授权状态随时间改变。
- **现有评估不足**：智能体安全基准（InjecAgent、AgentDojo、ASB 等）多以单一用户或单一任务为中心；智能体社区基准（SOTOPIA、MultiAgentBench 等）关注社交能力而非受控安全评估；两者都未覆盖"跨重叠社区、在持久数据/记忆/工具/动态状态下代表一个用户的完整智能体系统"。
- **核心论断**：仅评估孤立请求的最终回复，会遗漏决定动作是否安全的所有权、来源、持久性和预期受众信息；**任务效用不等于隐私或授权合规**。

## 2. 方法论：核心思想与关键技术细节

### 2.1 总体思想
- CoSec 是**可执行基准**，在持久社区的可执行模拟中运行**完整命令行智能体系统**（OpenClaw、Hermes、Codex），保留各系统原生的会话、记忆、文件操作、工具与工作区效果。
- 每次试验将目标智能体置于受控的参与者与社区上下文中，检验**整个系统**（而非仅基座模型）是否维护由数据所有权、来源和社区范围决定的边界。
- 三阶段流程：**基准构建 → 智能体执行 → 验证与度量**。

### 2.2 社区安全模型
- 授权状态形式化表示为：`E_t = (U, C, G_t, M_t, R_t, D, P_t, A, H_t)`，分别对应用户、社区、社区间关系、成员资格、角色、数据对象、适用策略、智能体接口与可见历史。
- 每个受保护对象 `d` 关联所有者 `o(d)`、来源社区 `c(d)` 和敏感度标签。
- 隐藏的授权预言机判定：`Auth_t(u, a, d, ℓ) = 1[P_t(u, a, d, ℓ, G_t, M_t, R_t, o(d), c(d)) = allow]`。
- 关键原则：**扩大协作范围本身不授权披露此前受保护的信息**；历史内容仍绑定其原始来源。

### 2.3 威胁模型与攻击族
- 对手控制指定请求者消息，以及（依攻击族）选定文档、元数据、记忆条目或工作流输入；**不能**修改授权预言机或隔离运行时。
- 四类攻击族（作为受控评估条件，而非新攻击算法）：
  - **A1 用户注入**：直接通过请求者消息施压（虚假授权、冒充、紧迫感、安全摘要陷阱等）。
  - **A2 间接注入**：在文档、引用消息、元数据或工具观测中嵌入未授权指令。
  - **A3 记忆投毒**：在持久上下文中植入虚假、过时或过宽的授权声明。
  - **A4 能力组合**：将单独合理的文件/工具/工作流操作组合成未授权信息流。

### 2.4 度量指标
- **PVR（隐私违规率）**：`PVR = |V|^-1 Σ p_i`，受保护内容经智能体输出披露（仅读取或提及路径不算）。
- **CCPVR（跨社区隐私违规率）**：`CCPVR = |V_cross|^-1 Σ c_i`，度量社区间的未授权信息流。
- **BCR（良性完成率）**：`BCR = |V|^-1 Σ b_i`，独立于安全性衡量任务完成。
- **STCR（安全任务完成率）**：`STCR = |V|^-1 Σ (1-a_i)b_i`，同时要求无安全失败。设计使"一律拒绝"无法获得高 STCR，高 BCR 也无法掩盖不安全的完成。

### 2.5 验证机制
- **确定性抽取器**：标记新的未授权输出、动作与陈旧状态使用；排除设置内容、来源内容、攻击者输入、内部读取和既有值；读取仅作为诊断来源，不单独计入 PVR。
- **LLM 语义裁判**：对改写、拒绝中夹带披露、不安全组合等语义情形进行审查（温度 0，JSON 输出）。
- **合并规则**：`R̂_ri = D_ri ∨ J_ri`（裁判有效时），否则退回确定性证据，均无效则标记为不确定（⊥）。

## 6. 主要结论与发现

- **效用与安全脱节**：13 个配置中 12 个 BCR 超过 85%（唯一例外 Hermes+Qwen 3.8 Max 为 78.85%），但总体 PVR 从 29.33%（OpenClaw+Gemini 3.1 Pro）到 96.15%（Hermes+DeepSeek 4.1 Flash），说明完成良性任务不蕴含隐私保护。
- **Harness 是决定性因素**：同一基座模型在不同 harness 上隐私表现差异显著。Gemini 3.5 Flash 在 OpenClaw 上 PVR 为 52.88%，在 Hermes 上为 76.92%（差 24.04 个百分点）；GPT 5.6 Sol 在 Hermes 为 55.29%，在 Codex 为 41.35%。
- **静态与动态行为无一致排序**：6 个 OpenClaw 配置中 4 个在 Dyn96 上 PVR 更高；6 个 Hermes 配置中 5 个在 Dyn96 上更低。隐私表现是配置特定的，无法从静态表现或基座能力推断。
- **攻击面差异**：总体而言**能力组合（A4）风险最高**（合并 PVR 70.27%）；各配置的主导攻击族不同。
- **动态事件难度**：**社区合并**最具挑战（72.12% PVR），其次是关系结束（69.23%），成员移除最低（47.12%）。
- **四类反复出现的授权失败模式**（795 个分类失败）：工作流延续（29.9%）、过度权限（25.5%）、来源混淆（25.2%）、撤销失败（19.4%）。
- **护栏效果有限且不一致**：同一首轮安全指令在 OpenClaw 上使 PVR 从 82.69% 降至 58.65%（BCR 反升），但 Hermes 维持 96.15%；提示级提醒不能替代在写入/共享/传参前进行的授权检查。
- **核心结论**：社区授权是**系统属性**而非模型属性；对持久运行的 LLM 智能体而言仍是未解决的安全挑战。

## 7. 优点

- **可执行性与系统级评估**：运行真实完整智能体系统（含原生会话、记忆、文件、工具），而非仅评估模型回复，能捕捉仅看响应会遗漏的信息流。
- **多主体 + 动态边界**：显式建模多用户、多社区、所有权与来源，并支持社区结构随时间变化（合并/拆分/成员/角色/关系），这是现有基准的显著空白。
- **双轨验证机制**：确定性抽取器（高精度、保守）+ LLM 语义裁判（高召回）结合，辅以 192 个盲审人工验证，验证器可靠性有量化证据。
- **效用与安全解耦度量**：PVR/CCPVR/BCR/STCR 的组合使"一律拒绝"和"高完成率掩盖违规"都无法取巧。
- **受控的公平比较设计**：冻结场景、匹配策略变体、固定隔离与验证，跨 harness 使用同一清单，仅执行适配器不同。
- **失败模式分类有洞察力**：将动态失败归纳为四类可操作的授权错误，对防御设计有指导意义。
- **可复现性**：代码开源，发布试验记录包含 scenario/trajectory/sessions/result/scorecard、工作区快照、验证证据与用量记录。

## 8. 不足与局限

- **合成场景的生态效度**：所有姓名、社区、健康事实、凭据、财务记录均为合成数据，模板化构造可能无法反映真实社区的复杂性与信息流分布。
- **参与者消息被冻结**：主实验不调用参与者模型（`speaker_mode=seed`），攻击压力来自预设脚本，可能低估或高估真实多轮自适应攻击的威胁。
- **harness 与模型覆盖有限**：仅 3 个 harness、7 个模型，且 Codex 仅配 GPT 5.6 Sol；结论向其他智能体框架/模型的推广性未验证。
- **固定交互长度**：每个典型场景固定 8 轮脚本，无法评估更长协作历史下的授权漂移。
- **裁判依赖**：语义判定依赖 LLM 裁判（deepseek-v4-flash），虽在温度 0 下运行并做过人工审计，但仍存在模型偏差与不可完全复现的风险。
- **护栏实验范围窄**：仅在 DeepSeek 4.1 Flash 的 OpenClaw 与 Hermes 上做单轮护栏，结论的普适性有限；且只测试了首轮注入，未测试逐轮运行时授权检查。
- **领域局限**：场景集中于金融、凭据、健康等领域，未覆盖更广泛的应用域。
- **数据呈现问题**：附录原始计数表（如 Table 17）部分数值存在排版/一致性异常，影响部分数字的独立复核。
- **应用限制**：CoSec 是受控合成测试平台，可作为基准与诊断工具，但**不能直接充当生产环境的运行时授权防御机制**；论文也指出运行时授权防御属于未来工作。
