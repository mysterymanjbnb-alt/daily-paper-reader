## 摘要
技能是自然语言指令、可执行脚本和参考资源的模块化封装，智能体可在运行时加载技能，以扩展其完成特定任务的能力。因此，基于技能的智能体系统能够灵活复用第三方能力，但该技能生态的开放性也开辟了新的攻击面。已有工作关注单个技能内部的漏洞，但很少关注跨技能交互所产生的风险。本文提出技能级联攻击，这是一种威胁范式，其中恶意目标被分散到多个技能中，使得每处修改在孤立看时都显得无害，但其组合执行却具有危害性。例如，在处方审核流水线中，第一个技能削弱提取病史中近期停用药物的信号，第二个技能降低与其相关的任何药物相互作用的严重级别，第三个技能在最终摘要中压制由此产生的低优先级警报，从而使严重的药物相互作用警告在到达医生之前悄然消失。为系统研究这一安全盲区，我们开发了 SkillCascade，一个自动化多智能体红队测试框架，并发布 SkillCascade-Bench，一个包含跨多个智能体系统和领域的213个经验证的级联测试用例的基准。在代表性智能体（如 OpenClaw、Claude Code、Codex）和 LLM 骨干模型上，级联交互能够可靠地诱发有害行为，同时规避现有的逐技能扫描器和运行时监控器。我们的发现凸显了组件级完整性与系统级安全性之间的差距，并呼吁防御机制应针对跨技能交互进行推理，而非孤立地考虑单个技能。

## Abstract
A skill is a modular package of natural-language instructions, executable scripts, and reference resources that an agent can load at runtime to extend its capabilities for a specific task. Skill-based agent systems therefore enable flexible reuse of third-party capabilities, but the openness of this skill ecosystem also opens up a new attack surface. Prior work has focused on vulnerabilities within individual skills, but little attention has been paid to risks that arise from interactions across skills. In this paper, we introduce skill cascading attacks, a threat paradigm in which a malicious objective is distributed across multiple skills so that each modification looks benign in isolation, yet their combined execution is harmful. For instance, in a prescription-review pipeline, the first skill weakens signals of recently discontinued medications in the extracted history, the second downgrades the severity of any drug interaction tied to them, and the third suppresses the resulting low-priority alert in the final summary, so that a severe drug-interaction warning silently disappears before reaching the physician. To systematically study this safety blind spot, we develop SkillCascade, an automated multi-agent red-teaming framework, and release SkillCascade-Bench, a benchmark of 213 validated cascading test cases across multiple agent systems and domains. Across representative agents (e.g., OpenClaw, Claude Code, Codex) and LLM backbones, cascaded interactions reliably induce harmful behaviors while evading existing per-skill scanners and runtime monitors. Our findings highlight a gap between component-level integrity and system-level safety, and call for defenses that reason over cross-skill interactions rather than individual skills in isolation.

## 1. 核心问题与整体含义

- **背景**：新一代 LLM 智能体系统（Claude Code、OpenClaw、Codex）采用"技能"（skill）作为能力扩展单元——技能是自然语言指令、可执行脚本与参考资源的模块化封装，运行时动态加载。ClawHub 等市场已托管数千个公开技能，使技能从"扩展特性"演变为智能体部署所依赖的第三方供应链。
- **核心问题**：现有安全研究几乎都以**单个技能**为分析单元，关注技能文件中的提示注入、脚本恶意载荷、工具权限滥用等，并据此设计 Skill-Vetter、Skill-Scanner 等安装前扫描器。但实际运行时所有技能**共享同一个上下文窗口**，一个技能写入的内容会被后续技能当作权威输入读取，风险可跨技能传播——这是逐技能扫描器无法覆盖的安全盲区。
- **整体含义**：论文类比 SolarWinds 软件供应链攻击，提出**技能级联攻击**（skill cascading attacks）这一新威胁范式，指出"组件级完整性 ≠ 系统级安全"，呼吁防御从单技能检测转向跨技能交互推理。

## 2. 方法论

### 2.1 形式化定义

- **系统建模**：智能体系统表示为 $A=(M,S,W,E)$，$M$ 为底层 LLM，$S$ 为已安装技能集，$W$ 为共享上下文窗口，$E$ 为执行环境；技能 $S_i=(d_i,I_i,C_i,R_i,A_i)$ 含触发描述、指令集、脚本集、参考文档与资源文件。动态调度中，技能输出被追加进共享上下文 $W_{t+1}=W_t \oplus \text{output}(\cdot)$，并影响后续技能选择。
- **威胁模型**：攻击者作为技能发布者，控制**两个及以上**技能，可修改技能五个组件中的任意部分，但不能改 LLM 权重、系统提示或平台机制，也不能观察/篡改用户会话。可行性来自用户常通过一次授权安装同一开发者的成套技能。
- **定义 1（技能级联攻击）** 满足三个条件：
  - **(1) 个体隐蔽**：每个被修改技能都通过逐技能扫描器（$\forall i,\ \text{scan}(\delta_i(S_i))=\text{SAFE}$）；
  - **(2) 联合危害**：级联在真实请求上触发，$h(\text{exec}(A^*,q))>\tau$；
  - **(3) 不可或缺性**：回滚任一单点修改即消除危害，$h(\text{exec}(A^{*\setminus i},q))\le \varepsilon$。

### 2.2 攻击模式与目标

- **三种级联模式**：**因果型**（有序链，前序技能把信号写入共享上下文供后续利用）、**组合型**（各修改效果独立，碎片单独无害、共存才产生危害）、**混合型**（因果子链 + 独立碎片汇聚）。
- **七种攻击目标**：O1 输出篡改、O2 决策操纵、O3 功能拒绝、O4 质量降级、O5 范围漂移、O6 信息外泄、O7 未授权操作，覆盖输出层、范围层与执行层。

### 2.3 SkillCascade 红队框架

由五个 LLM 智能体 + 容器沙箱组成，含三层嵌套反馈循环：

- **Scenario Discovery Agent**：以"场景驱动（自顶向下）"与"技能驱动（自底向上）"两种策略，从技能市场发现可自然串联的 2–3 个技能；对攻击完全不知情，保证场景真实性。
- **Attack Agent**：生成攻击计划（目标、模式、技术），在**最小修改原则**下改写技能（保留原有章节结构、仅数行改动、每处修改附带一句合法领域理由），禁止出现 attack/exploit/cascade 等元语言。
- **Scanner Agent**：以外部公开扫描器为唯一裁决依据，每次仅审一个技能、无攻击计划上下文；全部通过才满足个体隐蔽。
- **Test Case Generator Agent**：构造真实用户提示、输入文件与评估标准，在全新容器沙箱中执行。
- **Judge Agent**：仅依据运行输出与执行轨迹判定成功与否，失败时输出结构化诊断，路由回上游智能体（重新生成测试用例 / 修改攻击计划 / 换场景）。

- **九种攻击技术（M1–M9）**：M1 条件逻辑注入、M2 认知框架重构、M3 标签/属性升级、M4 默认值利用、M5 选择性过滤、M6 隐蔽信道构建、M7 决策压力构建、M8 静默目标注入、M9 粒度操纵。
- **算法流程**：外层场景循环 → 攻击计划循环 → 攻击实现循环 → 扫描器循环（不通过则修订）→ 测试用例循环（沙箱执行 + Judge 判定），各反馈边预算默认 $B_{scan}=B_{tc}=B_{atk}=B_{sc}=3$，成功即记录入验证用例库。

## 3. 实验设计

- **基准**：**SkillCascade-Bench**，在 ClawHub 上端到端运行框架，收集 Judge 判定成功的用例，共 **213 个验证测试用例**，覆盖 **10 个领域**，平均级联长度 **3.25 个技能**，覆盖全部 7 种攻击目标与 3 种级联模式。每个用例自包含（原始/修改后技能、用户提示、输入文件），可直接复现。
- **质量控制**：三位专家独立审计（验证不可或缺性、任务真实性、攻击确实成功），Fleiss's κ = 0.82，仅纳入三人一致同意的用例。
- **目标系统与骨干**：3 个智能体系统（OpenClaw、Claude Code、Codex）× 8 个 LLM 骨干（GPT-5.4、GPT-5.4 Mini、Claude Opus 4.6、Claude Sonnet 4.6、Gemini 2.5 Pro、Gemini 2.5 Flash、Qwen 3 72B、Kimi K2.5），共 24 种配置，每用例每配置运行 3 次取均值；目标智能体对评估与修改技能完全不知情。
- **对比防御**：
  - **预部署扫描器**：逐技能扫描器 5 个（Skill-Scanner、SkillScan、Skill-Vetter、AIG-Scanner 及另一静态扫描器）；跨技能扫描器 3 个（含重实现的 SkillProbe Flow Simulator 与自建 Joint-LLM）。
  - **运行时防御**：DefenseClaw、ClawGuard、HITL Defense、AgentDoG 四种范式（在 OpenClaw + GPT-5.4-mini 上评测）。
- **指标**：攻击成功率 ASR、逐技能隐蔽率 SR_per、联合隐蔽率 SR_joint、防御规避率 DER。Judge 可靠性经双标注者抽样 30 例复核，Cohen's κ = 0.86。
- **消融与分析实验**：三技能级联的片段撤回实验（k=1,2,3 及按位置切片）、静态分析信号对比（原版/单技能攻击/级联攻击）、攻击技术频次统计、自适应防御 Behavior-Composition Scanner 评测，以及 3 个端到端案例研究（医疗因果级联、金融组合级联、保险混合级联）。

## 6. 主要结论与发现

- **攻击有效**：全局平均 ASR 达 **89.4%**，跨骨干范围 76.5%–97.1%；前沿旗舰（Claude Opus 4.6、GPT-5.4）最抗打，同厂商小模型更脆弱，开源权重模型（Qwen 3 72B，97.1%）最脆弱；宿主系统差异不超过 6 个百分点，骨干选择比宿主更重要。
- **模式与领域规律**：因果型 > 混合型 > 组合型；高风险、对齐先验密集的领域 ASR 最低，但最对齐的领域仍超过 80%。
- **隐蔽性显著**：5 个逐技能扫描器对修改集的 SR_per 均高于 86%，∆ 不超过 4.7 个百分点；跨技能扫描器同样失守——静态流水线 ∆ = 0，LLM 联合扫描增益有限。
- **运行时防御失效**：4 种运行时防御平均 DER 达 **88.5%**，即使唯一跨步骤的轨迹级检查（AgentDoG）仍漏检五分之四。
- **不可或缺性验证**：撤回任一单点修改，残余 ASR 从约 90% 骤降至 13–18%，撤回两处进一步降至个位数；因果型呈"头→尾"梯度，组合型平坦，混合型对尾部最敏感。
- **失效原因**：单技能载荷在各静态分析轴上远超良性基线，而级联修改的多边形"紧贴"良性基线，因为每处修改都小且局部合理——逐技能扫描的"分析单元"与攻击的"危害单元"根本错配。
- **概念验证防御**：Behavior-Composition Scanner（总结各技能行为承诺 → 串联找联合后果 → 生成反事实场景判断安全性）对因果型级联将隐蔽率降低 30 余个百分点，但对组合型与混合型效果递减。

## 7. 优点

- **问题定义清晰且形式化**：用个体隐蔽、联合危害、不可或缺性三条件精确刻画级联攻击，并与工具链攻击、多轮越狱等相邻威胁做出明确区分（前者不改组件、后者改组件）。
- **威胁模型现实可行**：利用"同一开发者成套安装"这一真实部署模式，无需控制平台或用户会话。
- **自动化红队框架设计精巧**：五个智能体职责分离、上下文隔离（Scanner 一次只见一个技能、Judge 不见攻击计划、Discovery 不知攻击），配合三层反馈循环与可恢复的注册表设计，可规模化产出可复现用例。
- **最小修改原则**：要求保留原章节结构、数行改动、一句可辩护的领域理由，使攻击真正落在"局部合理"的语义层，避免退化为"从头写恶意技能"，保证研究命题成立。
- **实验立体且可复现**：213 个自包含用例、多维 ASR 拆解、静态/联合/运行时三类防御对照、片段撤回消融与三种模式签名分析，并附三个逐行展示的真实案例（含修改代码、输入、输出与判定）。
- **负责任披露**：与市场运营方协调披露、设置修复窗口、受控访问协议禁止再分发与商业使用。

## 8. 不足与局限

- **实验环境非真实部署**：所有评测在沙箱而非生产环境，绝对攻击率应视为压力测试而非野外发生率预测；攻击者控制的技能共安装在开放市场中的实际发生率仍是未解问题。
- **Judge 依赖 LLM**：规模化的代价是判定质量依赖 LLM，仅以 30 例抽样人工复核；作者亦承认需要补充人工审查。
- **基线覆盖有限**：跨技能扫描器基线仅 3 个，其中 SkillProbe 为自行重实现；运行时防御仅在单一系统+骨干组合上评测，结论外推需谨慎。
- **自适应防御不完整**：Behavior-Composition Scanner 仅为概念验证，对组合型与混合型级联防御效果明显下降，全覆盖防御留待未来工作。
- **案例研究集中于高风险垂直领域**：三个案例（医疗、信贷、保险）虽具代表性，但均属"修改技能包"场景，未系统覆盖多开发者混杂安装、技能自动更新、技能间工具调用权限差异等变体。
- **应用限制**：基准本身具有双重用途风险，论文通过受控访问缓解，但这同时限制了社区对结果的独立验证与复现范围。
