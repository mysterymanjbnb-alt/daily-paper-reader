## 摘要
基于大语言模型（LLM）的智能体日益依赖外部工具和内容，这使它们暴露于间接提示注入（IPI）的威胁之下。这一威胁催生了多种防御方法，其中基于训练的防御通常被认为最为可靠。然而，现有的基于训练的防御通常是在显式注入的静态分布上进行优化。它们学到的是表层形式的线索，而非服务用户与服从注入目标之间的边界，因此当恶意意图被折叠进看似合理的工作流并延迟若干轮次时，便会失效。我们提出 CoDeL，一种在训练过程中不断重塑攻击分布、并据此强化智能体防御能力的防御方法。防御方每轮通过基于 LoRA 的 GDPO 进行更新，其奖励在安全性、任务进展和格式合规性上解耦，因此拒绝注入与完成用户任务共同定义适应度。为了持续为其提供值得学习的失败样本，一个协同演化的探测者会在注入轮次、攻击方法和载荷上进行搜索，以寻找仍能穿透当前防御方的注入，并由攻击成功率和攻击延迟共同引导，从而优先挖掘防御方察觉过晚的突破。每次防御方更新都会使部分攻击种群失效，并迫使下一轮进入新的前沿，从而将防御方自身的失败转化为一种动态课程。在三个 IPI 基准、九个基线方法和两个基础模型上的大量实验表明，CoDeL 将攻击成功率（ASR）降低了 88.5%，并大幅优于其他基线（+38.0%）。代码已开源。

## Abstract
Large language model (LLM)-based agents increasingly rely on external tools and content, exposing them to indirect prompt injection (IPI). This threat has motivated a wide range of defenses, among which training-based defenses are often regarded as most reliable. However, existing training-based defenses are typically optimized on a static distribution of explicit injections. They learn surface-form cues rather than the boundary between serving the user and obeying an injected objective, and therefore fail when malicious intent is folded into a plausible workflow and deferred for several turns. We present CoDeL, a defense that hardens agent against an attack distribution it reshapes as it trains. The defender is updated each round via LoRA-based GDPO under a decoupled reward over safety, task progress, and format compliance, so refusing injections and completing the user's task jointly define fitness. To keep supplying it with the failures worth learning from, a co-evolving prober searches over injection rounds, attack methods, and payloads for injections that still penetrate the current defender, guided jointly by attack success and attack latency so that it preferentially mines breaches the defender notices too late. Each defender update invalidates part of the attack population and forces the next round onto a new frontier, turning the defender's own failures into a moving curriculum. Extensive experiments on three IPI benchmarks, nine baselines, and two base models show that CoDeL reduces attack success rate (ASR) by 88.5% and outperforms other baselines largely (+38.0%). ## 2. 方法论：核心思想与关键技术

### 2.1 核心思想

- **协同演化框架**：每一轮包含两个阶段：
  1. **探测者（Prober）**：搜索当前防御器仍会失败的潜在注入；
  2. **防御器（Defender）**：通过 LoRA 和 GDPO 吸收这些失败样本。
- 每轮防御器更新都会使部分攻击种群失效，迫使下一轮搜索进入新区域，形成“移动课程”。
- 目标是同时满足两个条件：**拒绝注入的恶意目标**，并**继续完成用户原始任务**。

### 2.2 威胁模型与轨迹定义

- 攻击者只能控制智能体可能读取的外部内容，在某一轮 `t_inj` 将载荷写入工具观察结果中。
- 定义三类轨迹：
  - `T_clean`：无注入的干净轨迹；
  - `T_af`：存在注入但智能体成功抵抗；
  - `T_as`：注入成功，智能体执行了有害行为。
- 防御目标不是简单拒绝一切，而是在安全与任务效用之间取得平衡。

### 2.3 攻击延迟（Attack Latency）

- 定义攻击延迟：
  - `Λ = t_dev - t_inj`；
  - 归一化形式 `ẽΛ = min(1, max(0, Λ) / max(|T_clean|, |T_as|))`。
- `t_dev` 是智能体首次偏离正常任务、开始服务恶意目标的轮次。
- 延迟越大，说明防御器在载荷可见后仍长时间未察觉，轨迹越深入决策边界的盲区。
- 该指标既用于引导探测者搜索，也参与防御器更新。

### 2.4 探测者：基于 MCTS 的潜在攻击挖掘

- 将攻击空间组织为树：
  - 注入轮次；
  - 攻击方法；
  - 具体载荷。
- 使用 **Monte Carlo Tree Search（MCTS）**，以 GLM-5.2 作为生成器。
- 搜索同时由 **ASR 和延迟 ẽΛ** 引导，优先寻找“成功且延迟高”的注入。
- 选择阶段公式：
  - `v* = argmax_v [ (N_succ_v / N_v) * ẽΛ_v + C_exp * sqrt(ln N_u / N_v) ]`
  - 未访问子节点优先选择。
- 扩展阶段：
  - 方法节点：生成候选攻击方法；
  - 载荷节点：通过变异算子实例化 `(round, method)` 为具体载荷。
- 回传阶段：
  - 每个路径节点访问数 +1；
  - 成功次数与平均延迟仅在攻击成功时更新。
- 树统计跨轮保留，使攻击种群不断演化而非简单累积。

### 2.5 防御器：SFT 冷启动 + LoRA-GDPO

- **SFT 冷启动**：
  - 使用干净轨迹、攻击失败轨迹、以及从攻击成功轨迹转换来的“纠正轨迹”；
  - 让模型学会任务格式、识别良性工具观察、区分可信与不可信指令。
- **LoRA 增量更新**：
  - 只更新低秩适配器，避免灾难性遗忘，保持即插即用。
- **解耦奖励设计**：
  - `R = r_safety + r_progress - p_drift`
  - `r_safety`：
    - 识别并拒绝攻击：+2.00；
    - 判断不清：-0.50；
    - 攻击成功：-8.00。
  - `r_progress`：
    - 推进任务：+1.20；
    - 无进展：-0.15；
    - 浪费步骤：-2.50。
  - `p_drift`：
    - 缺少关键字段：0.25；
    - 完全无法解析：0.50。
  - 设计意图：安全惩罚显著大于格式惩罚，但任务进展独立计分，防止“通过放弃任务来获得安全”。
- **On-policy 采样**：
  - 攻击提示来自新挖掘的注入轨迹，在注入点重放历史并采样 G 个响应；
  - 保留一部分干净提示（默认 0.25），维持良性任务能力。
- **GDPO 优势估计**：
  - 对每个奖励项在组内标准化，再求和；
  - 再做 batch 级归一化；
  - 用延迟重加权：`Ã_i,j = (1 + λ * ẽΛ) * Â_i,j`。
- **训练目标**：
  - 使用 token 级裁剪代理目标；

## 6. 主要结论与发现

- **防御效果显著**：
  - AgentDojo + Qwen2.5-7B：ASR 从 0.364 降至 0.042，降低约 **88.5%**；
  - UA 从最强基线的 0.602 提升至 0.831，提升约 **38.0%**；

- **跨基准表现稳定**：
  - InjecAgent：ASR 0.010，BU 0.882，UA 0.843；
  - ASB-OPI：ASR 0.043，UA 0.913。
- **跨模型稳定**：
  - Llama-3.1-8B-Instruct：
    - AgentDojo：ASR 0.051，BU 0.819，UA 0.797；
    - ASB-OPI：ASR 0.000，BU 1.000，UA 0.942。
- **协同演化有效**：
  - 双方演化时 ASR 从 0.294 降至 0.032；
  - 冻结攻击者时 ASR 快速下降后停滞，说明固定攻击分布很快被耗尽；
  - 冻结防御器时 ASR 从 0.273 升至 0.662，说明攻击者会持续进化；
  - 去掉延迟奖励后 ASR 仅升至约 0.510，说明延迟信号推动搜索走向隐蔽注入。
- **泛化能力**：
  - AutoDojo：CoDeL ASR 0.081，低于 PIGuard 和 Meta-SecAlign；
  - ASPI：CoDeL ASR 0.124，为最低；
  - Latent Dojo：CoDeL 在各延迟层级均保持最低 ASR。
- **消融结论**：
  - 安全奖励最关键，去掉后 ASR 从 0.042 升至 0.237；
  - 去掉进度奖励后 UA 降至 0.492，说明会诱发过度拒绝；
  - 延迟 shaping 是辅助课程信号，去掉后 ASR 升至 0.076。

## 7. 优点

- **问题定位准确**：指出训练型 IPI 防御在静态显式攻击上表现好，但对延迟、隐蔽、折叠进正常工作流的攻击脆弱。
- **协同演化机制有创新性**：不是简单对抗训练，而是让攻击分布随防御器更新而移动，形成动态课程。
- **MCTS + 延迟引导**：同时优化攻击成功率和攻击延迟，优先挖掘防御器“察觉过晚”的盲区。
- **奖励解耦设计合理**：安全、任务进展、格式合规分别计分，避免安全对齐导致任务放弃或过度拒绝。
- **LoRA-GDPO 实用**：增量更新、插件式、降低灾难性遗忘，适合实际部署。
- **实验较全面**：三基准、九基线、两模型、三指标、重复三次，并包含自适应攻击、潜在攻击和消融。
- **公平性较好**：统一工具 schema、提示、任务划分和计算预算；模型级基线在相同划分下重训。
- **提供 Latent Dojo**：为潜在 IPI 攻击提供新的评估集，具有社区价值。
- **算力与成本透明**：明确报告 GPU 型号、数量、运行时长和攻击者调用成本。

## 8. 不足与局限

- **模型规模覆盖有限**：仅测试 7B/8B 模型，未验证更大模型上的潜在注入鲁棒性和协同演化迁移性。
- **机制理解不足**：延迟、内部表征与决策形成之间的关系尚未深入，未与机制可解释性结合。
- **Latent Dojo 的构造偏差风险**：攻击来自冻结防御器运行中的演化攻击，可能与训练过程同源，不能完全代表真实世界中未知攻击分布。
- **依赖 LLM Judge**：安全、进度、攻击判定均依赖 LLM judge，虽然人工验证准确率约 90%–95%，但仍可能引入噪声和偏差。
- **攻击者模型特定**：探测者使用 GLM-5.2，攻击搜索能力可能受该模型能力限制。
