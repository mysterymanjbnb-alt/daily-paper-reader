## 摘要
配备工具的自主AI智能体的兴起带来了显著的安全风险，从非预期的工具误用到通过间接提示注入（IPI）攻击进行的对抗性操纵。在实践中，已部署的智能体系统（如OpenAI Codex和Claude Code）通过粗粒度权限规则与基于LLM对单个提议动作的判断相结合来保护工具调用。然而，这两个组成部分都存在重要局限：静态策略必须预判可能的用户意图，因此无法扩展到开放式任务；而LLM驱动的授权虽然支持动态决策，但会产生不一致的结果，并且仍然容易受到针对性的IPI攻击。为了提供可扩展且更一致的授权，我们提出MetaPermit，一个基于策略的工具访问控制框架，它将语义推断与安全执行解耦。通过分析智能体-用户交互，我们推导出一组紧凑且任务无关的元属性，用以刻画用户意图、执行上下文与所提议工具调用之间的关系。这些元属性使MetaPermit无需枚举用户意图即可授权工具使用。在运行时，LLM为每个提议的工具调用推断元属性值，而固定策略评估这些值以允许或拒绝该调用，从而通过推断出的值和所应用的策略规则使每次决策都可审计。我们在AgentDojo和AgentDyn基准上，跨七个任务套件和五种攻击方法，使用两个广泛部署的开放权重LLM评估MetaPermit。结果表明，MetaPermit产生的授权决策一致性比LLM驱动的授权高31%，并且在任务完成度（提升最高达109%）和对IPI攻击的鲁棒性（未执行任何恶意工具调用）两方面均优于最先进的防御方法CaMeL和IPIGuard。

## Abstract
The rise of autonomous AI agents equipped with tools has introduced significant security risks, ranging from unintended tool misuse to adversarial manipulation through Indirect Prompt Injection (IPI) attacks. In practice, deployed agent systems such as OpenAI Codex and Claude Code protect tool invocations through a combination of coarse-grained permission rules and LLM-based judgments about individual proposed actions. Both components, however, have important limitations: static policies must anticipate possible user intents and therefore do not scale to open-ended tasks, while LLM-driven authorization supports dynamic decisions but produces inconsistent outcomes and remains vulnerable to targeted IPI attacks. To provide scalable and more consistent authorization, we propose MetaPermit, a policy-based tool access-control framework that decouples semantic inference from security enforcement. By analyzing agent-user interactions, we derive a compact, task-independent set of meta-attributes that capture the relationships among the user's intent, the execution context, and the proposed tool call. These meta-attributes allow MetaPermit to authorize tool use without enumerating user intents. At runtime, an LLM infers the meta-attribute values for each proposed tool call, while a fixed policy evaluates these values to allow or deny the call, making each decision auditable through the inferred values and the applied policy rule. We evaluate MetaPermit on the AgentDojo and AgentDyn benchmarks, across seven task suites and five attack methods, using two widely deployed open-weight LLMs. The results show that MetaPermit produces 31% more consistent authorization decisions than LLM-driven authorization and outperforms the state-of-the-art defenses CaMeL and IPIGuard in both task completion, with improvements of up to 109%, and robustness to IPI attacks, with no malicious tool calls executed.

# MetaPermit 论文总结

## 1. 核心问题与研究动机

- **背景**：LLM 应用正从聊天机器人演变为可长程规划、调用多种工具、执行扩展动作序列的自主智能体。智能体必须将外部世界作为输入（收件箱、网页、共享文档、第三方服务输出），而这些内容既非开发者编写、也未经用户审查。
- **核心风险**：指令与数据通过同一通道进入上下文窗口，嵌入在外部内容中的对抗性文本（间接提示注入，IPI）可能被当作来自用户的指令执行。论文以 Alice 让智能体向 Bob 退款 $1,500、攻击者 Eve 在交易记录中植入冒充 Alice 的转账指令为例说明该威胁。
- **现有防御的两难**：
  - **静态策略**（如 CSAgent、AC4A、CaMeL）：需在部署前为每个工具/意图编写规则，策略可预测但数量庞大，未预见的意图无匹配策略，难以扩展到开放式任务。
  - **LLM 驱动授权**（如 OpenAI Codex、Claude Code 的模型判断、IPIGuard）：支持动态决策，但会产生不一致裁决，且仍易被针对性 IPI 攻击操纵。
- **整体含义**：需要一种既能覆盖开放式意图、又能保证决策一致性与可审计性的工具访问控制框架。

## 2. 方法论

### 2.1 核心思想
- MetaPermit 是**基于策略的混合访问控制框架**，将**语义推断**与**安全执行**解耦：
  - 不预测显式用户意图，而是刻画用户请求、工具调用与上下文之间的**抽象语义关系**（元属性）。
  - LLM 只负责推断受限的元属性值，**最终授权裁决由固定策略作出**。
- 元属性与可能取值预先定义，作为少量通用策略的决策因子；因为推断值与所应用规则都显式可见，每次决策都可审计。

### 2.2 关键技术细节
- **五个元属性**（表 2）：
  - `intent_is_action`（true/false）：用户是想行动还是仅对话。
  - `intent_clarity`（clear/ambiguous/incomprehensible）：用户目标是否可无歧义理解。
  - `intent_risk`（high/low）：动作是否涉及不可逆伤害或隐私泄露。
  - `intent_tool_alignment`（direct/prerequisite/supporting/misaligned）：所调用工具是否服务于用户目标。
  - `intent_input_alignment`（aligned/misaligned）：调用参数是否被用户请求所正当化。
- **信任边界**：`intent_is_action` 与 `intent_clarity` 只依赖受信任的用户请求，检索内容无法影响其取值；后三个元属性还会参考提议调用的参数。
- **策略引擎**：策略 ΠS = (r₁,…,rₙ,rₙ₊₁) 为有序规则列表，每条规则 rⱼ = (φⱼ, eⱼ, oⱼ)，φⱼ 测试元属性向量，eⱼ ∈ {Allow, Deny}，oⱼ 给出反馈。引擎应用首个谓词成立的规则，最后一条为默认拒绝规则，保证无效/不完整输出一律拒绝（fail-closed）。
- **执行门（Enforcement Gate）**：Allow 则原样转发调用；Deny 则阻断并将反馈作为合成工具结果返回，使智能体可重新规划或请求澄清，而不改变裁决。
- **策略构造示例**（附录 A.7）：以 Banking 套件为例，用户要求把多余餐费退还给指定账户，注入任务试图向攻击者账户转账。该安全需求编译为规则 R4：当 `intent_input_alignment = misaligned` 时 Deny 并附带反馈。策略通过可复用语义属性区分同一工具的两次调用，而非任务特定的工具封禁。
- **可扩展性**：新增授权需求时，只需新增元属性维度并更新依赖它的规则，接口、执行路径与无关规则保持不变；策略规模随安全维度数增长，而非随开放式意图空间增长。
- **推理模块输出契约**：要求输出严格 JSON，包含五个属性值及 `unmatched_entities`；JSON 解析失败时映射为 fail-closed 向量（action、incomprehensible、high、misaligned、misaligned）。

## 3. 实验设计

### 3.1 数据集与基准
- **AgentDojo** v0.1.35（基准套件 v1.2.2）：四个原始套件 workspace、travel、banking、slack，97 个用户任务、949 个用户任务/注入任务对。
- **AgentDyn** 扩展：Shopping、Github、Dailylife 三个套件，60 个开放式任务、560 个对；包含动态环境、更长任务依赖，以及可能有用而非一律恶意的第三方指令，用以检验策略是否保留对外部证据的合法使用。
- **五种攻击模板**：Direct、Ignore Previous、InjecAgent、Tool Knowledge、Important Instructions（均由 AgentDojo 提供）。共产生每个模板 1,509 个攻击案例，完整七套件矩阵共 **7,545 个攻击案例**，另有 157 个无攻击用户任务。

### 3.2 模型配置
- 主实验使用 **MiniMax-M2.7** 与 **Qwen3-235B-a22-2507**，任务智能体与所有 LLM 组件使用同一模型（不额外使用更强的防御专用模型）。
- 跨模型泛化消融使用 **Qwen3-8B**。

### 3.3 对比方法
- **No Defense**：无授权层。
- **CaMeL**：分离特权规划与隔离数据解析，以能力为基础的数据流约束。
- **IPIGuard**：LLM 预先构建工具依赖图，将执行限制在图内路径。
- **Direct LLM Guard**（消融）：相同模型与查询，但直接输出 Allow/Deny 裁决，用于隔离类型化接口的效果。

### 3.4 评估指标
- **UA**（Utility Accuracy）：完成良性用户任务的比例。
- **ASR**（Attack Success Rate）：达成注入恶意目标的比例。
- **Secure-Usable**：既完成良性任务又抵御攻击的比例，区分“安全且有用”与“仅阻止攻击但任务失败”。

## 6. 主要结论与发现

- **安全性**：MiniMax-M2.7 上 ASR 从无防御的 2.85% 降至 0.08%（执行感知审计后为 0%，0/7,545）；Qwen3-235B 上从 26.49% 降至 0.00%。在 Qwen3-8B 上从 9.01% 降至 1.50%（相对降低 83.4%）。
- **效用**：MiniMax-M2.7 上保持 53.92% UA，Qwen3-235B 上 50.13% UA，显著优于 CaMeL（25.83%/42.21%）与 IPIGuard（30.27%/41.96%），任务完成度最高提升 109%。AgentDojo 套件上效用下降温和（MiniMax 69.4% vs 无防御 72.0%），主要退化出现在更难的开放式 AgentDyn 套件。
- **一致性**：MetaPermit 最终裁决比 Direct LLM Guard 更稳定（完全一致 42% vs 32%；多数一致 90% vs 87%）；在 47 个元属性向量有波动的查询中，固定策略将 18 个（38%）映射为一致裁决。授权一致性整体提升 31%。
- **强制层鲁棒性**：在 95 个真实恶意调用上，即使白盒注入揭示模式与允许规则并指示输出有利值，仍无一被允许（0/95）。注入最常压低 `intent_risk`（16.8%），但 `intent_tool_alignment` 与 `intent_input_alignment` 仍分别阻断 94/95 与 95/95。
- **拒绝反馈价值**：完整结构化反馈实现最高 UA（60.00%）、最高恢复率（50.00%）、ASR 0.00%，并减少重复拒绝（56.25% vs 通用 70.00% / 静默 76.74%）。
- **低 ASR 的解读**：CaMeL 与 IPIGuard 的低 ASR 主要来自 Secure-Unusable（任务未完成），而 MetaPermit 保持最高的 Secure-Usable 份额（MiniMax 53.9%、Qwen3-235B 50.1%），接近无防御水平。

## 7. 优点

- **架构性解耦**：将语义推断与授权裁决分离，LLM 只能从固定类型化词表中选择值，既不能创建策略规则也不能发布最终裁决，从根本上限制了模型权限。
- **可扩展性**：策略规模随安全维度数而非用户意图数

增长，从而避免为每个新意图编写专用规则。
- **可审计与可解释**：每次裁决都能追溯到具体的元属性取值与命中的规则，用户或开发者可以复核“为什么允许/拒绝”，而不是面对一个不可解释的 LLM 黑箱判断。
- **fail-closed 的工程稳健性**：推理输出解析失败、元属性缺失或规则不匹配时一律拒绝，避免了“格式错误导致放行”的常见漏洞。
- **信任边界清晰**：`intent_is_action` 与 `intent_clarity` 仅依赖受信任的用户请求，检索到的外部内容无法污染这两个最关键的判断维度，从源头压缩了 IPI 的影响面。
- **保留合法外部证据的使用**：AgentDyn 中第三方指令可能是有用而非恶意的，MetaPermit 并未一刀切禁止外部内容参与决策，而是通过 `intent_input_alignment` 等属性区分“被用户请求正当化”与“被注入操纵”的调用。
- **实验方法学严谨**：使用官方 checker 且做执行感知审计、报告 Wilson 置信区间与 McNemar 检验、设置类型化接口消融与拒绝反馈消融，增强了结论的可信度。
- **对比公平性较好**：任务智能体与防御组件使用同一模型与系统提示，CaMeL 与 IPIGuard 采用 vendored 实现且未改动其授权逻辑，减少了“用更强模型堆防御”的混淆。

## 8. 局限性

- **绝对效用仍有限**：即使 MetaPermit 在对比方法中保持最高 UA，MiniMax-M2.7 与 Qwen3-235B 的绝对 UA 仅约 54% 与 50%，在开放式 AgentDyn 套件上退化更明显，距离生产级可用仍有差距。
- **元属性与策略依赖人工设计**：五个元属性及其取值、规则列表和安全需求编译仍由设计者完成，可能引入领域偏见、遗漏关键维度，或无法覆盖未预见的攻击面。
- **推理模块仍是 LLM，存在误判风险**：虽然 fail-closed 限制了误判的危害方向，但过度拒绝会损害效用；论文也显示小模型（Qwen3-8B）上 ASR 仍有 1.50%，说明推断质量对防御效果有实质影响。
- **攻击模型覆盖有限**：五种攻击模板均来自 AgentDojo，未系统评估自适应攻击者针对元属性推断过程本身（如诱导 `intent_tool_alignment` 误判）的优化攻击。
- **模型与场景泛化范围有限**：仅覆盖三个模型、七个套件，未涉及多智能体协作、跨会话记忆、长期运行智能体或训练/微调阶段的防御。
- **对比方法的性能受实现与后端影响**：作者明确指出 CaMeL/IPIGuard 的结果受 provider 对中间产物格式兼容性影响，属“开箱即用”性能，因此对比结论应谨慎解读。
- **部署开销未充分讨论**：论文未系统报告延迟、token 成本或推理模块调用频率，实际生产部署的经济性与实时性尚不明确。
- **策略完备性缺乏形式化保证**：规则列表由人工维护，论文未提供策略冲突检测、覆盖性证明或自动化策略合成机制。

## 9. 启示与展望

- **“语义属性 + 固定策略”可作为一种通用授权范式**：将 LLM 限制在类型化词表内做推断、把最终裁决交给确定性策略引擎，这一思路可迁移到金融、医疗、企业自动化等安全敏感场景。
- **元属性可作为可组合的安全接口**：未来可扩展更多维度，如数据敏感度、动作可逆性、权限范围、时间/频率约束、跨用户边界等，使策略随安全需求演进而非随意图空间膨胀。
- **拒绝反馈是提升智能体自恢复能力的关键设计**：将结构化拒绝原因作为合成工具结果返回，使智能体能够重规划或请求澄清，这一机制值得在更广泛的工具调用框架中复用。
- **评估方法论上的启示**：应同时报告 ASR、UA 与 Secure-Usable，避免“低 ASR 即安全”的误导；对 checker 阳性结果做执行感知审计，可剔除推理过程文本造成的伪阳性。
- **未来研究方向**：自适应攻击下的元属性鲁棒性、策略自动合成与形式化验证、端到端延迟优化、多智能体与跨会话场景下的授权一致性，以及将元属性推断与轻量级模型蒸馏结合以降低部署成本。
