## 摘要
持久记忆使LLM智能体能够复用先验经验，但也带来了新的安全边界：智能体可能记住的内容，并不等于它应当据以行动的内容。我们揭示了一条未授权控制路径：被编辑的低信任证据被整合进持久记忆，在干净任务中被检索出来，并被用于驱动受保护的动作。关键在于，攻击者既不写入记忆，也不修改任务。我们提出反向链记忆攻击（Backchain Memory Attack, BMA），这是一种灰盒、由LLM驱动的逆向规划攻击：它从目标动作反向推理到会触发该动作的记忆，再推理到会形成该记忆的证据编辑。BMA分为两个阶段：准备阶段利用可重置试验定位首个失败环节并积累经验；执行阶段利用冻结的经验对候选编辑进行排序并提交，且不依赖反馈。我们提出路径认证攻击成功率（Pathway-Certified Attack Success Rate, Path-CASR），以区分由记忆介导命中的攻击与偶然命中：注册记忆必须形成、被检索、驱动目标行为，并通过匹配干预检查。在四种基座和三种决策主干上，BMA达到18.8%的宏平均Path-CASR，而最强的访问匹配基线为13.4%。在BMA的行为命中中，60.3%通过了所有注册路径与干预检查，而基线为36.7%。在四种留出的巩固策略上，冻结的BMA编辑平均保留其认证效果的78.0%。代表性的记忆侧控制仅剩11.0%的Path-CASR，而来源绑定授权将其降至2.0%，同时保持92.1%的合法动作成功率。

## Abstract
Persistent memory enables LLM agents to reuse prior experience, but creates a new security boundary: what an agent may remember is not what it should act on. We expose an unauthorized control path where edited low-trust evidence is consolidated into persistent memory, retrieved on a clean task, and used to drive a protected action. Crucially, the adversary neither writes memory nor alters the task. We introduce Backchain Memory Attack (BMA), a grey-box, LLM-driven inverse-planning attack that reasons backward from the target action to the memory that would trigger it, then to the evidence edit that would form it. BMA has two phases: preparation uses resettable trials to localize the first failed link and build experience; execution uses the frozen experience to rank and commit candidate edits without feedback. We introduce the Pathway-Certified Attack Success Rate (Path-CASR) to separate memory-mediated from coincidental hits: registered memory must form, be retrieved, drive the target behavior, and pass matched-intervention checks. Across four substrates and three decision backbones, BMA achieves 18.8% Macro Path-CASR, compared with 13.4% for the strongest access-matched baseline. Of BMA's behavioral hits, 60.3% pass all registered pathway and intervention checks versus 36.7% for the baseline. Frozen BMA edits retain 78.0% of their certified effect on average across four held-out consolidation policies. Representative memory-side controls leave 11.0% Path-CASR, whereas provenance-bound authorization reduces it to 2.0% while preserving 92.1% legitimate-action success.

- **背景**：持久记忆让 LLM 智能体能把过去的观察、反思、偏好与工具结果存储为可复用的决策状态，并在后续任务中检索使用；近期工作已开始研究这些记忆的巩固、压缩与治理。
- **新安全边界**：这引入了"授权边界"——某个来源可以*提供有用证据*，但并不具备*授权采取重大动作*的权限。当源自该证据的记忆实际驱动了该动作时，就出现**权威–控制错配（authority–control mismatch）**。
- **与已有攻击的区别**：现有工作要么操纵当前上下文、检索语料，要么直接投毒存储记忆（AgentPoison、间接提示注入、记忆投毒等）。本文提出一个更上游、约束更紧的威胁模型：
  - 攻击者**不写记忆**、**不修改未来任务**、**不接触智能体内部状态**；
  - 只对"低信任来源"拥有的文本片段做**一次有界的声明式编辑**（≤96 token 的连续片段）；
  - 记忆的形成完全由受害者自己的巩固（consolidation）流水线完成。
- **典型场景（Figure 1）**：一条关于"某次取消预订"的低信任报告，被智能体巩固为"先凭预订码取消、再验证身份"的可复用流程；之后一个干净的取消请求检索到该流程，导致**在身份验证之前就执行取消**——而该来源只被允许报告事件，无权放宽验证要求。
- **问题本质**：这是一个**三阶段耦合的一次性搜索问题**——编辑必须（i）形成目标记忆，（ii）在被封存的未来任务上被检索到，（iii）驱动目标行为。改进某一环可能削弱另一环，且一次失败无法判断是形成、路由还是行为影响出了问题，端到端搜索缺乏可操作的修复信号。

## 2. 方法论

### 2.1 核心思想

- **BMA（Backchain Memory Attack）**：一种**灰盒、LLM 驱动的逆向规划攻击**。模型级黑盒访问 + 仅限准备阶段的工作流级诊断。
- **反向链推理**：从**目标动作** → 反推**能支撑它的记忆** → 反推**能形成该记忆的"证据→记忆"假设** → 反推**一条有界编辑**。
- **两阶段设计**：
  - **准备阶段（Preparation）**：在可重置（resettable）的试验场景上执行候选，定位"首个失败环节"，并把每次试验转化为**结构化的、带链接标签的路径经验**存入经验库。
  - **执行阶段（Execution）**：冻结经验库，针对未见场景生成**封闭候选批次**，按"最弱预测环节"排序，**提交一条编辑且不再接受任何反馈**（不能因当前场景的记忆/检索/行为/干预结果而重新生成、修复或回退）。

### 2.2 关键技术细节

- **候选的路径优先表示**：
  - 候选 `cᵢ = (hᵢ, zᵢ, aᵢ)`，其中
    - `hᵢ = ⟨κᵢ, ρᵢ, σᵢ, αᵢ, τᵢ⟩` 为目标记忆假设，分别编码**适用条件、动作关系、作用域、记忆角色、检索线索**；
    - `zᵢ` 为**证据→记忆的变换假设**（保留何种来源关系、弱化何种上下文、派生何种抽象）；
    - `aᵢ` 为在该假设下、满足编辑契约的**具体文本编辑**。
  - 链式关系：`C*_q ← hᵢ ← (zᵢ, aᵢ)`，即"需要什么记忆 / 来源如何产生它 / 改哪段文本"。
  - 用 `(hᵢ, zᵢ)` 上的**规范签名** `μᵢ = Canon(hᵢ, zᵢ)` 去除路径等价的改写。
- **候选门控（Candidate Gate）**：编辑须满足注册的位置与长度约束、通过冻结的"来源有界"提案侧门控、指向目标行为 `C*_q`，且 `aᵢ → zᵢ → hᵢ` 逻辑自洽；缺失对象与路径等价签名被拒绝。
- **三链路前向验证**：在重置后的目标系统上观测
  - 形成：`mᵢ = MemSat_q(Mᵃⁱ_q, hᵢ)`
  - 路由：`uᵢ = RouteSat_q(rᵃⁱ_q, hᵢ)`
  - 行为：`bᵢ = B_q(Yᵃⁱ_q)`
- **首失败环节诊断与修复（Table 2）**：
  - `NoMem`（mᵢ=0）→ 修 `zᵢ, aᵢ`
  - `NotRouted`（mᵢ=1, uᵢ=0）→ 修 `κᵢ, σᵢ, τᵢ`
  - `NoEffect`（mᵢ=uᵢ=1, bᵢ=0）→ 修 `ρᵢ, αᵢ`
  - `Hit`（三者皆 1）→ 保留并停止
  - 每次修复只改动允许的路径字段，重新生成依赖的 `zᵢ, aᵢ`，重新校验并**从重置状态重跑**（防止下游修复导致上游回退）。
- **执行阶段的冻结排序**：冻结的 critic 对形成/路由/行为给出序数分 `bs^M, bs^R, bs^B ∈ {0,1,2}`，按
  - `Sᵢ = ( min_{ℓ∈{M,R,B}} bs^ℓᵢ , Σ_ℓ bs^ℓᵢ , −len(aᵢ) )`
  - 即**最弱链路优先 → 总路径可信度 → 编辑长度**（越短越优）；并列时按生成顺序；若无有效路径互异候选则**弃权**。
- **评估指标体系（论文的重要方法学贡献）**：
  - **ASR**：编辑后是否出现目标行为（最宽松）。
  - **DM-ASR**：仅计由"贡献衍生的记忆"介导的命中——必须满足：恢复原始贡献、隐藏/删除贡献衍生记忆、只保留底层事实、重放原始片段等**匹配干预**后行为消失。
  - **Path-CASR**（主指标）：更严格，要求命中同时满足注册规格 `h̄_q`（形成 + 路由）并通过**来源有界的事实对照**。
  - **ACMR / A-Path**：把 DM-ASR / Path-CASR 限制到 `E_qj = 1`（来源无权授权的关键动作分支）。
  - 形式化上用指示函数 `b_qjtc(a)` 与干预集合 `C_desc = {ref, abs, raw, del}`、`C_path = C_desc ∪ {fact}` 定义端点：`Z_ASR = b_gen`；`Z_DM = V_desc · b_gen · Π_{c∈C_desc}(1−b_c)`；`Z_Path` 额外要求注册形成/路由与 `fact` 分支为负；`Z_ACM = E_qj·Z_DM`，`Z_APath = E_qj·Z_Path`。**任何匹配对照分支为阳，即判定为巧合而非记忆中介**。
- **威胁模型（Problem Setup）**：场景 `q = (v_q, X_q, Π_q, h̄_q)`，其中 `v_q` 含不可变历史 `H̄_q`、可编辑贡献 `e⁰_q`、来源 `s_q`、目标行为 `C*_q`、编辑契约 `d_q`；`Π_q = (Permit, Critical, Endorse)` 为权威契约；`h̄_q = ⟨κ̄, ρ̄, σ̄, ᾱ, τ̄⟩` 为评估方预先注册的目标记忆规格（攻击准备前固定，双标注者独立审核，κ = 0.77–0.95）。攻击者可见 `C*_q` 与公开来源角色，但不可见 `X_q, Π_q, h̄_q`；无权重、logits、激活、隐藏状态访问权限；无记忆/检索/轨迹/重置/部署反馈。

### 2.3 算法流程（文字版）

1. **准备（每个开发场景）**：给定可见案例 + 目标行为 → 反向链生成候选 `(h, z, a)` → 门控校验 → 在重置环境中执行 → 三链路验证 → 定位首失败环节并按其修复字段生成新候选 → 重复（每场景最多 8 次可重置执行、`B_dev` 轮）→ 把"结构化路径 + 首失败标签 + 有界验证摘要"写入经验库。
2. **冻结**：经验库、提示、验证器、预算、critic、排序规则全部冻结。
3. **执行（留出场景）**：检索去标识化的准备经验 → 生成 `K = 16` 个路径互异候选 → 冻结 critic 打分并按最弱链路排序 → **在目标执行前提交 1 条编辑** → 该编辑原封不动地应用于所有封存任务与决策骨干。
4. **事后**：仅在做完承诺后才运行匹配干预与审计。
