## 摘要
多智能体 LLM 系统正越来越多地被部署于复杂、长时程任务中，或作为智能体在真实环境中交互的自然结果而出现。然而，它们带来了显著的安全与安保风险：支持任务泛化的灵活协议也暴露了新型威胁，从级联提示注入到智能体间合谋。由于缺乏共享的实证基础设施，针对这些威胁的防御进展缓慢，这迫使每项新防御都需要定制化环境开发，并使标准化比较无法实现。现有评估针对孤立的威胁模型或单智能体设置，但没有任何评估能在真实的多智能体环境中同时改变攻击、防御与架构。为弥补这一空白，我们提出 ORBIT，一个用于多智能体安全与安保实证研究的可配置评估框架，构建于英国 AISI 的 Inspect 之上。ORBIT 允许研究人员配置通信拓扑、记忆、调度和智能体角色。它支持四种威胁类型和四种防御策略，以及非对抗性故障，并包含一个覆盖五个场景族的基准测试套件，涵盖浏览器使用、计算机使用、智能体编码、客户服务和合作分配。我们的核心发现是防御在不同威胁间的可迁移性存在缺口：在多问题编码任务上，逐动作防御能将受控智能体的攻击成功率降低 60 个百分点，但对合谋智能体不提供可测量的保护，且我们测试的防御中没有任何一种能泛化到所有测试攻击。我们进一步展示了安全与性能的权衡，以及架构与防御有效性之间的交互作用。我们将 ORBIT 开源发布于 https://github.com/wlanderson0/orbit。

## Abstract
Multi-agent LLM systems are increasingly deployed for complex, long-horizon tasks or emerge as a natural consequence of agents interacting in the wild. Yet they give rise to significant safety and security risks: the flexible protocols that enable task generalization also expose novel threats, from cascading prompt injection to inter-agent collusion. Progress in defending against these threats has been slowed by a lack of shared empirical infrastructure, which forces bespoke environment development for every new defense and makes standardized comparison impossible. Existing evaluations address isolated threat models or single-agent settings, but none jointly vary attack, defense, and architecture across realistic multi-agent environments. To address this gap, we introduce ORBIT, a configurable evaluation framework for empirical multi-agent safety and security research, built on UK AISI's Inspect. ORBIT lets researchers configure communication topologies, memory, scheduling, and agent roles. It supports four threat types and four defense strategies, as well as non-adversarial failures, with a benchmark suite spanning five scenario families covering browser use, computer use, agentic coding, customer service, and cooperative allocation. Our central finding is a gap in defense transferability across threats: per-action defenses that cut a compromised agent's attack success by 60 points on multi-issue coding give no measurable protection against colluding agents, and none of the defenses we tested generalized over all attacks tested. We further demonstrate security-performance tradeoffs and interactions between architecture and defense effectiveness. We make ORBIT available open-source at https://github.com/wlanderson0/orbit.

- **整体含义**：论文认为多智能体安全研究的瓶颈不是缺少威胁假设，而是**缺少可复用评估基础设施**；ORBIT 旨在把"新防御需重建整个技术栈"的成本降为"改一行配置"。

## 2. 方法论

- **基础**：构建于英国 AISI 的 **Inspect AI** 之上，以 @task/@solver/@scorer 与沙箱、ModelAPI、handoff 等原语为底座，ORBIT 增加攻击/防御注册表、声明式 YAML 配置、调度器、安全专用指标与场景库。
- **三条设计原则**：①可配置评估（任意维度可由 YAML 变更，实现单轴控制消融）；②真实智能体环境（浏览器、真实开源代码库、虚拟桌面，全部 Docker 隔离）；③可插拔威胁模型（新增攻击/防御只需实现短协议，无需改动编排器与打分管线）。
- **六层可组合实验层**（实验 = 每层各选一项的乘积）：
  - **L1 Setup**：定义智能体（角色、模型、系统提示、工具）、有向通信拓扑（star/mesh/chain/flat，由拓扑构建器接线）、记忆可见性策略。
  - **L2 Scenario**：任务与执行环境（五个场景族）。
  - **L3 Attacks**：类型、威胁模型（黑/灰/白盒知识、预算、持续性、受控智能体数）、注入时机、成功判据。
  - **L4 Defenses**：类型、调用模式、作用域、失效模式，可叠加组合。
  - **L5 Execution**：`turn_react()` 每次调用只执行一个工具调用，交回 `AgentScheduler`（维护每智能体隔离状态并选择每轮执行者，支持任意执行顺序）。
  - **L6 Evaluation**：对日志做 LLM 驱动打分、指标计算与自动有效性检查。
- **编排流程**：组件装配 → 部署前修改（注入受控智能体、提示词"疫苗"）→ 逐轮循环【注入攻击 → 防御前置钩子 → 执行智能体 → 监控输出 → 评估成功 → 停机检查】。
- **攻击**：统一三方法协议 `inject() / should_activate() / evaluate_success()`；威胁类型含 **注入**（直接、间接、记忆投毒、代码库注入、自复制）、**受控智能体**（subtle_code_injection、cross_issue_sabotage）、**合谋**（私有 `secret_channel` 工具 + 联盟指令 + 说服策略）；**误用**属场景级（不在攻击注册表），另有非对抗性失效（misbehavior、协调失败）。成功判据包括子串、正则、特定工具调用、以及"否定型"（以未完成任务为成功）。
- **防御（四种）**：
  - **攻击感知系统提示**：以 `SystemPromptFilter` 包裹模型 API，在每次 `generate()` 前插入针对特定攻击类型的警告（含通用回退版）。
  - **近视 LLM 监控器**：无状态逐动作裁判（GPT-5 Nano），只看当前消息/工具调用，输出可疑度 s∈[0,1]，s≥τ（默认 0.5）则阻断；被阻断工具调用不执行。
  - **历史感知守护智能体**：有状态裁判，维护每智能体消息日志 H_i，携带完整历史评估新消息/工具调用。
  - **Dual-LLM 架构**：特权 LLM（P-LLM，持工具）与隔离 LLM（Q-LLM，无工具）分离，Q-LLM 对所有不可信内容（工具返回、setup 期观测、运行期观测）生成净化摘要，保证原始不可信内容永不进入 P-LLM 上下文；不打分也不阻断，而是**转换内容**，且无攻击感知变体（其论点是架构隔离与攻击类型知识无关）。
- **记忆可见性**：`AgentMemoryAccess` 六个布尔标志（goal_visible、own_action_history、own_cot、shared_action_history、shared_cot、nl_instructions_accumulated），由 `MemoryInjectionFilter` 在每次 `generate()` 时按许可拼装上下文；工具结果截断至 240 字符、参数值 80 字符；记忆投毒通过指定接收者与插入模式（append/prepend/replace）进入该管线。
- **指标与公式**（三层）
