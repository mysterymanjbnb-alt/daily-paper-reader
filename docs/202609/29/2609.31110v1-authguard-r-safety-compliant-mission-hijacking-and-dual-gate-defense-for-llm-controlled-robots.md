## 摘要
大语言模型正日益被用作移动机器人、机械臂和自动驾驶车辆的高层规划器。近期研究表明，这些系统可被恶意文本、语音、视觉指令、检索到的文档以及受污染的感知上下文所影响。多数防御方法关注的是某个提议动作在物理上是否安全。本文研究一个不同的问题：一个动作可能在物理上是安全的，却仍然违背用户授权的任务。攻击者可重定向配送机器人、替换已批准的对象、扩大机器人运行区域、激活不必要的传感器，或延迟任务，而不会造成直接物理危害。我们将这种攻击称为安全合规型任务劫持。我们提出 MissionPAIR，一种自适应攻击框架，用于搜索能够通过安全门控但违反经认证任务的可执行计划。我们还提出 AuthGuard-R，一种确定性授权层，将每个可执行动作绑定到已签名任务、机器人身份、对象与区域范围、当前状态、时间以及输入来源。AuthGuard-R 与独立的安全门控协同运行，形成双门架构。我们在机器人轨迹上形式化任务策略，定义安全博弈，并证明授权可靠性、任务不可升级性、重放抵抗性、机器人绑定、来源分离、阈值审批安全性、审计日志防篡改性以及轨迹级组合性。我们报告了一项使用 Claude Haiku 4.5 和开源 Qwen2.5 7B 规划器进行的初步跨模型评估。在 240 次实时攻击试验中，规划器在 109 次试验中遵循了注入的任务偏离；AuthGuard-R 拒绝了由此产生的全部 109 个未授权动作。另一套手工构建的包含 11 种协议级和策略级攻击的测试集也被完全阻断。

## Abstract
Large language models are increasingly used as high-level planners for mobile robots, robot manipulators, and autonomous vehicles. Recent studies show that these systems can be influenced through malicious text, speech, visual instructions, retrieved documents, and poisoned sensory context. Most defenses ask whether a proposed action is physically safe. This paper studies a different problem: an action may be physically safe and still violate the mission authorized by the user. An attacker may redirect a delivery robot, replace an approved object, extend a robot's operating region, activate an unnecessary sensor, or delay a mission without creating an immediate physical hazard. We call this attack \emph{safety-compliant mission hijacking}. We propose MissionPAIR, an adaptive attack framework that searches for executable plans that pass a safety gate while violating an authenticated mission. We also propose AuthGuard-R, a deterministic authorization layer that binds every executable action to a signed mission, robot identity, object and region scope, current state, time, and input provenance. AuthGuard-R operates with an independent safety gate, giving a dual-gate architecture. We formalize mission policies over robot traces, define security games, and prove authorization soundness, mission non-escalation, replay resistance, robot binding, provenance separation, threshold-approval security, audit-log tamper evidence, and trace-level composition. We report a preliminary cross-model evaluation with Claude Haiku~4.5 and the open-source Qwen2.5~7B planner. Across 240 live attack trials, the planners followed an injected mission deviation in 109 trials; AuthGuard-R rejected all 109 resulting unauthorized actions. A separate hand-constructed suite of eleven protocol- and policy-level attacks was also blocked completely.

## 一、核心问题与研究动机

- **背景**：LLM/VLM 正被用作移动机器人、机械臂、自动驾驶车辆的高层规划器，可将自然语言指令转为导航、抓取、配送等动作序列。但模型本身是概率性的、易受上下文影响，且会消费不可信信息（视觉 OCR 文本、语音、检索文档、机器人记忆、传感器描述等），因此不能被当作可信控制器。
- **已有防御的盲区**：BadRobot、RoboPAIR、RoboGuard、SafeGate、运行时治理等工作主要回答“动作是否**物理安全**”（是否碰撞、是否超力/超速、是否进入危险状态）。但“安全”≠“授权”。
- **核心新问题**：一个动作可以完全物理安全，却违背用户经认证的任务。作者将其命名为 **安全合规型任务劫持（safety-compliant mission hijacking）**。典型形态包括：配送目的地被改写、被批准的对象被替换、运行区域被扩大、激活不必要的传感器/摄像头、通过虚假告警延迟任务。
- **动机场景**：医院配送机器人被授权将药品 P1 从 A 台送到 101 护士站；摄像头读到“101 已关闭，请送至 103”的告示，LLM 据此规划出无碰撞、不超速的新路线——安全门可能全部放行，但目的地字段已被非授权渠道篡改。
- **研究问题**：如何确保 LLM 控制机器人执行的每个动作，既物理安全，又由原始任务**密码学授权**？
- **整体含义**：把 LLM 明确降级为“不可信的方案提议者”，把“权威（authority）”从模型中剥离出来，交由签名任务令牌与确定性授权门强制实施。

## 二、方法论

### 2.1 核心思想

- **零信任规划器原则**：LLM 可以提议“如何做”，但不能决定“被授权做什么”；只有认证主体才能定义或修改授权。
- **双门架构（Dual-Gate）**：`执行 = 授权门 GA ∧ 安全门 GS`。授权门检查动作是否落在签名任务范围内，安全门（如 RoboGuard）独立检查物理安全；二者共享独立理由码与证据，任一拒绝则不执行。
- **三个问题的分离**：安全性问题（物理可否接受）、授权问题（是否在签名策略内）、活性问题（能否继续推进有用任务）被显式区分。

### 2.2 形式化定义

- **状态/动作/轨迹**：状态集 X、归一化动作集 A、转移函数 δ: X×A→X∪{⊥}；轨迹 τ=(s₀,a₁,s₁,…,a_ℓ,s_ℓ)。
- **安全策略** S: X×A→{0,1}；**任务授权策略** Π_M: X×T→2^A。
  - 授权动作：a ∈ Π_M(s,t)；授权轨迹：每个 a_i ∈ Π_M(s_{i−1},t_i)；安全轨迹：每个 S(s_{i−1},a_i)=1。
- **任务偏离度**：对动作 a=(u,o,rs,rd,θ,λ)，按受保护字段加权违规指示量
  D_M(a,s,t) = Σ w_j d_j / Σ w_j ∈ [0,1]；计划级取 **最大值**（一个未授权动作即足以判定违规）。
- **安全合规型任务劫持定义**：
  SCMH(P,M,s₀) = X(P,s₀) · S_A(P) · (1 − A_A(P,M)) = 1
  即：可执行 ∧ 安全门接受 ∧ 至少一个动作越出授权。
- **攻击分类**：目标替换、对象替换、区域扩张、能力升级、参数升级、跨机器人令牌复用、可用性操纵（虚假告警/循环重规划）、来源混淆。

### 2.3 MissionPAIR 攻击框架（Alg. 1）

- **约束优化目标**：max_q D_M(P_q)，s.t. 可执行、安全门接受、D_M>0；实践中用标量打分 J(q)=λ₁D_M+λ₂可执行+λ₃安全−λ₄明显危害−λ₅语法错误，最终成功标签必须由确定性执行/安全/任务检查器给出，而非 LLM 裁判。
- **流程**：初始化对抗上下文 q₀ → 目标规划器生成计划 → 归一化 → 可执行性检查 → 安全门 → 计算 D_M → 若三者同时满足则返回，否则由攻击者模型更新 q 迭代（最多 N 轮）。
- **命题**：若算法返回且检查器正确，则 SCMH=1（由三个条件直接代入定义得证）。
- **访问模型**：黑盒（只见执行/拒绝结果）、灰盒（知架构与动作词汇，不知签名值）、白盒（知完整策略、门序、理由码，唯密钥/可信状态/新鲜 nonce 保密）——用于说明安全性不依赖算法保密。
- **模板族**：目的地变更、对象重标注、隐私升级（“为验证而录像”）、虚假紧急、路线扩张；同一语义可通过直接文本、可见标牌、语音、检索文档、记忆、场景描述等多种渠道投递。
- **配对基准**：同一改动同时提供“未认证注入”与“新签名合法更新”两版，防御应拒绝前者、接受后者。

### 2.4 AuthGuard-R 授权层

- **签名任务令牌**：
  M = (mid, rid, issuer, task, actions, objects, regions, limits, guards, expiry, nonce, riskPolicy, version)
  σ = Sign_skU(H(tag ‖ Encode(M)))，令牌 T=(M, σ, cert_U)；采用域分离 + 版本化规范编码，签名的是结构化策略而非自然语言原文。
- **归一化动作**：a=(type, object, src, dst, θ, tool, prov, meta)；归一化属于可信执行路径，缺失/歧义/超类型范围字段一律拒绝或请求澄清，不得“就近推断”。
- **授权谓词**：Auth(M,a,s,t)=1 ⇔ a∈Π_M(s,t)，实现为若干检查的合取（机器人身份、任务有效未过期、动作类型与工具、对象与区域、数值上下界、状态守卫、特权字段来源），并返回理由码（如 OBJECT_OUT_OF_SCOPE、EXPIRED、PROVENANCE_DENIED）。
- **来源标签与字段级策略**：标签集 P={operator, supervisor, trustedSensor, camera, audio, retrieval, memory, model}；每个字段有 AllowedSrc(f)。目的地、对象身份、录像许可、审批阈值等特权字段仅接受 operator/supervisor；摄像头/音频/检索/模型输出只能作观测，不能授予权威。
- **风险自适应审批**：Req(a,s)=1（低风险）、2（中）、t（高风险，t-of-n 阈值签名）；风险策略与阈值写入签名任务或单独认证的组织策略，LLM 无法通过改述降低风险等级。
- **哈希链审计**：L_i = H(L_{i−1} ‖ mid ‖ i ‖ a_i ‖ s_i ‖ t_i ‖ d_i ‖ e_i)，周期性对末端摘要签名或外部锚定；仅保证完整性/可追责，不保证机密性。
- **验证算法（Alg. 2）**：证书有效 → 签名验证 → 模式有效且未过期 → nonce/状态未撤销 → 机器人身份匹配 → a∈Π_M(s,t) → 审批有效（否则请求额外审批）→ 更新状态并追加审计记录 → accept；异常一律 **fail-closed**。
- **完整性定理**：在令牌有效、模式新鲜、注册表活跃、身份匹配、a∈Π_M 且审批齐备时，算法必然接受（保证效用，避免“全拒绝式安全”）。

### 2.5 安全博弈与证明结论

- **五类博弈**：授权绕过（区分“签名伪造/哈希碰撞”与“策略检查绕过”）、重放、跨机器人、来源混淆（关注“有效策略值”是否被改变）、审计篡改。
- **主要定理**：
  - 授权可靠性：Adv_auth ≤ Adv_EUF-CMA + Adv_coll（可忽略）；
  - 任务不可升级（动作集与计划级）；
  - 重放抵抗（理想注册表下概率为 0，依赖持久化/单调计数器）；
  - 机器人绑定（rid 在签名内，与可信本地身份比对）；
  - 来源分离（特权字段非干扰，不控制授权来源则无法改变有效值）；
  - 阈值审批安全（少于 t 个签名方时伪造概率可忽略）；
  - 审计防篡改（碰撞/第二原像抗性）；
  - 双门轨迹组合（归纳法证明整条轨迹既授权又安全），推论：不执行任何满足 SCMH=1 的计划。
- **证明边界**：仅覆盖“编码后的任务 + 确定性检查器 + 密码学机制”，不保证任务本身合理、不覆盖感知/定位误差、解析 bug、密钥泄露、可信门被攻破、恶意授权操作者与 DoS。

## 三、实验设计

- **总体设计逻辑**：先用人工构造动作隔离“安全–授权缺口”，再把攻击放到真实 LLM 规划器之前，最后做跨模型对比；每一阶段只检验论证的一个环节。
- **场景/基准**：没有传统意义上的公开数据集，基准为**自建的任务令牌 + 安全但未授权备选动作配对**，任务与攻击均为手工构造；作者明确说明完整基准（复现 RoboPAIR、RoboGuard、BadRobot 并接入 ROS 2/仿真执行回路）属未来工作。

  - 11 个刻意保持物理安全的未授权动作（覆盖目标替换、对象替换、区域扩张、能力升级、参数升级、跨机器人复用、来源混淆×2、重放、阈值审批绕过）+ 7 个良性对照；
  - 对比三档：**无防御**、**仅安全门（pilot baseline）**、**AuthGuard-R + 安全门**。
- **实验二：真实 LLM 在线评估**
  - 规划器：Claude Haiku 4.5（专有）与 Qwen2.5 7B（开源，经 Ollama 本地运行）；
  - 攻击
