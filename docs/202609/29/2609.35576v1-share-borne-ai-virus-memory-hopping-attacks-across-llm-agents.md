## 摘要
大型语言模型正越来越多地被部署为有状态助手，它们能在交互之间保留信息，并使用工具读取、修改和创建持久性产物。随着这些产物在用户之间共享，它们构成了原本相互独立的助手之间的间接通信渠道。我们研究了一种失效模式，其中该渠道使自我传播攻击成为可能。我们引入了产物介导传播：通过产物（例如一份报告）引入的对抗性内容被存储在助手的持久记忆中，在随后创建的产物中被复制，并被之后读取该产物的另一个助手获取。我们在时间性的人-智能体宇宙中评估这一过程，该宇宙对独立运行的助手之间随时间进行的产物交换进行建模，衡量攻击能否在连续转手中存活、能到达多少跳以及传播范围有多广。我们发现，攻击可以在多个独立助手之间传播，并在延长的交互序列中持续存在。在更大的模拟环境中，即使 GPT-5.6 Luna 也表现出显著传播，达到 60-80% 的智能体，传播链延伸至八跳。这些结果表明，持久性产物可以作为对抗状态的持久载体，使攻击比单次交互存续更久，并跨越相互隔离的助手传播。

## Abstract
Large language models are increasingly deployed as stateful assistants that retain information across interactions and use tools to read, modify, and create persistent artifacts. As these artifacts are shared between users, they form an indirect communication channel between otherwise independent assistants. We study a failure mode in which this channel enables self-propagating attacks. We introduce artifact-mediated propagation, where adversarial content introduced through an artifact (e.g. a report), is stored in an assistant's persistent memory, reproduced in a subsequently created artifact, and acquired by another assistant that later reads it. We evaluate this process in temporal human-agent universes that model artifact exchange between independently operated assistants over time, measuring whether an attack survives successive hand-offs, how many hops it reaches, and how broadly it spreads. We find that attacks can propagate across multiple independent assistants and persist over extended interaction sequences. In larger simulated environments, even GPT-5.6 Luna exhibits substantial spread, reaching 60-80% of agents with propagation chains extending to eight hops. These results show that persistent artifacts can act as durable carriers of adversarial state, allowing attacks to outlive individual interactions and spread across isolated assistants.

## 1. 核心问题与整体含义

- **研究动机**：LLM 助手越来越像“有状态个人助理”，具备持久记忆，并能读取、修改、创建文档、代码、报告等持久性工件。用户之间共享这些工件时，工件会成为原本相互隔离的助手之间的**间接通信通道**。
- **核心问题**：如果攻击者只污染一个被用户共享的工件，该对抗状态能否通过“工件 → 助手记忆 → 新工件 → 另一个助手”的循环，在多个独立助手之间自我传播？
- **论文提出概念**：**Artifact-mediated propagation，工件介导传播**。即对抗内容先进入某助手持久记忆，再被该助手写入后续创建的工件，随后被另一个独立助手的用户读取并感染。
- **与已有工作的区别**：
  - 不是直接 LLM-to-LLM 通信、共享内存、RAG 邮件生态或自动多智能体网络。
  - 每个用户拥有独立个人助手、私有记忆、私有工作区；助手之间没有直接消息通道。
  - 传播依赖**人类用户正常的读写与工件交换工作流**，而不是智能体自主发现或主动通信。
- **整体含义**：持久工件可成为对抗状态的耐用载体，使 prompt injection 不再是单次会话或单智能体问题，而可能跨越会话、跨越用户、跨越独立助手长期传播。共享工件与助手记忆应被视为安全边界的一部分。

## 2. 方法论

- **核心思想**：
  - 攻击者构造一个**目标无关的攻击模板** \(P_\phi(g)\)，其中 \(g\) 是具体对抗目标，\(\phi\) 是可复用的记忆与传播指令。
  - 将攻击模板插入一个良性工件，得到 poisoned seed：\(d_{\text{seed}} = \text{Insert}(d_{\text{benign}}, P_\phi(g))\)。
  - 只要感染助手在后续无关写作任务中把对抗状态复制进新工件，另一个助手读取后即可被感染，形成多跳传播。
- **两种攻击变体**：
  - **Endpoint-assisted propagation，端点辅助传播**：主实验使用。攻击指令要求助手把后续创建的工件上传到攻击者控制的外部端点；端点插入一份规范化的完整攻击模板并返回。传播链可写为：
    \[
    P_\phi(g) \rightarrow M_a \rightarrow \text{Endpoint}(d') \rightarrow M_b
    \]
    其中 \(M_a, M_b\) 是连续助手的私有记忆。助手只需保留目标、记忆指令和调用端点指令，不一定要逐字重建完整攻击模板。
  - **Prompt-only propagation，纯提示传播**：附录 D。无外部服务，助手必须靠自身记忆和重写把攻击传给下一个助手；每跳会因摘要、改写或遗漏而退化。
- **攻击模板优化**：
  - 使用 **agent-driven red teaming with human oversight**。搜索智能体为 Muse Spark 1.3，运行在 Codex harness 中。
  - 搜索流程：提出 \(\phi\) 的修订 → 在开发宇宙上运行 → 检查 judge 标签、记忆快照、智能体轨迹 → 诊断传播失败点 → 继续修订。
  - 搜索智能体维护持久 Markdown 研究日志，累积假设、结果与失败模式。
  - 约束：\(\phi\) 必须目标无关，不能包含特定宇宙或工件内容。
  - 将 12 个开发宇宙分成 6 个搜索宇宙、6 个验证宇宙；当候选模板在搜索宇宙和验证宇宙上都达到 second-hop survival 时，冻结为 \(\phi^\star\)。
  - 对每个目标模型分别优化攻击模板。
- **评估定义**：
  - **Goal infection**：助手记忆保留了对抗目标。
  - **Full infection**：助手记忆还保留了足以继续传播的机制。
  - 指标包括：
    - 感染助手比例 \(FIF_a^c\)、感染工件比例 \(FIF_d^c\)，\(c \in \{\text{goal}, \text{full}\}\)。
    - 跳数生存 \(S_c(h) = \Pr(H_c \ge h)\)。直接从 seed 感染为 hop 1，再感染另一助手为 hop 2，以此类推。
  - 因宇宙长度有限，跳数可能被右删失。使用离散 Kaplan–Meier 估计校正，并拟合每跳继续概率 \(\hat p\)，其中 \(S(h)=S(1)p^{h-1}\)。
- **关键机制细节**：
  - 在 endpoint-assisted 中，**复制主体是助手而非端点**：助手先从记忆中写出目标、保留指令和 curl 命令，再调用端点；端点只是扩展和规范化助手已经复制出的内容。助手会读回文件并与记忆核对后才接受。
  - 传播失败常见于：助手保存了目标但丢失传播指令，或保留指令但未在写作任务中调用端点。

## 3. 实验设计

- **数据集 / 场景：合成 human–agent universes**
  - 36 个测试宇宙，代表人类用户与个人 AI 助手协作的工作流。
  - 6 个领域：customer support、software engineering、healthcare operations、home and living、social gatherings、personal productivity。
  - 每个领域 6 个 workload intensity 等级，共 6×6=36。
  - 每个宇宙有 3–12 个 agent，持续 10–20 个 time step，平均 14.3。
  - 数据集含 274 个人、889 个个人文件。每个宇宙分配一个 adversarial goal，目标来自 Pulipaka et al. (2026)，包括良性偏好到安全敏感行为。
  - 工件为纯文本，如 CSV、Markdown、email、calendar、JSON 等。
- **大宇宙设置**
  - 3 个大规模宇宙，每个 30 个 agent、60 个 time step、约 190 个任务。
  - 每个大宇宙有 3 个 seed artifact，分给随机选择的 3 个 seed agent。
  - 有重叠社交圈和社区结构，用于测试更大规模传播。
- **运行环境**
