## 摘要
调用特权工具的 LLM 智能体易受间接提示注入（IPI）攻击：嵌入在检索数据中的对抗性指令会劫持智能体的行为。越来越多的研究评估针对 IPI 的防御，但此类评估的有效性很少受到审视。我们审计了一个 IPI 基准及其测试框架，识别出四类缺陷——静默载荷未送达、按工具身份而非参数对攻击成功进行评分、将错误拒绝率与模型能力不足混为一谈，以及缺乏审计追踪——每一类都会产生一个看似合理、可发表却错误的数值。我们通过在缺陷定义与修正定义下对相同执行轨迹重新评分来量化这种扭曲：在真实智能体行为上，工具身份评分器报告的攻击成功率为 21.7%，而真实的参数级成功率为 1.2%。在最极端的情况下，一个此前报告为 62.8% 的开放模型在修正后的测试框架下录得 0%——此前数值在很大程度上是载荷未送达和身份级评分造成的假象。我们发布一个测试框架，其构造方式使每类缺陷都无法表示——机器可检查的载荷放置、参数级攻击者谓词、逐场景环境以及强制性的轨迹持久化——并用它报告该领域尚未报告的三项量：被攻陷的智能体是否会披露攻击、LLM 评判器防御的完整安全/效用操作曲线，以及与防御性过度阻断相解耦的工具调用能力。修正后的测试框架还推翻了此前报道的“能力壁垒”：一个被认为不具备工具使用能力的模型实际上完全具备该能力，其早期结果是环境不匹配造成的假象。我们认为，在智能体安全中，评估有效性是防御主张的前提，而非其脚注，并提供一种强制执行该有效性的工具。

## Abstract
LLM agents that invoke privileged tools are vulnerable to indirect prompt injection (IPI), in which adversarial instructions embedded in retrieved data hijack the agent's actions. A growing body of work evaluates defenses against IPI, but the validity of that evaluation is rarely examined. We audit an IPI benchmark and its harness and identify four defect classes -- silent payload non-delivery, attack success scored by tool identity rather than arguments, false-rejection rate conflated with model incapacity, and the absence of an audit trail -- each of which yields a plausible, publishable, and incorrect number. We quantify the distortion by re-scoring identical execution traces under the defective and corrected definitions: on real agent behaviour, the tool-identity scorer reports a 21.7% attack-success rate where the true argument-level rate is 1.2%. In the sharpest case, an open model previously reported at 62.8% registers 0% under the corrected harness -- the prior figure largely an artifact of undelivered payloads and identity-level scoring. We release a harness whose construction makes each defect unrepresentable -- machine-checkable payload placement, argument-level attacker predicates, per-scenario environments, and mandatory trace persistence -- and use it to report three quantities the field does not: whether a compromised agent discloses the attack, the full security/utility operating curve of an LLM-judge defense, and tool-calling capability disentangled from defensive over-blocking. A corrected harness further overturns a reported "capability barrier": a model deemed incapable of tool use is in fact fully capable, its earlier result an artifact of environment mismatch. We argue that evaluation validity is a prerequisite for, not a footnote to, defense claims in agentic security, and provide an instrument that enforces it.

## 2. 方法论：核心思想、关键技术细节与流程

### 2.1 核心思想
- **先审计、再修正**：审计一个代表性 IPI 基准及其测试框架，归纳**四类缺陷（D1–D4）**，然后在**同一批真实执行轨迹**上以缺陷定义与修正定义分别重评分，量化扭曲幅度。
- **从"警惕"转向"构造"**：不靠审稿人的警觉，而是设计一种 schema，使"未送达的载荷""身份级攻击评分""环境导致的错误拒绝"在结构上**无法被表达**。

### 2.2 缺陷分类（D1–D4）
- **D1 静默载荷未送达**：仅当自由文本"数据源"字段匹配四个硬编码字符串字面量时才注入，其他值静默不注入且无报错。审计套件中 **43 个载荷有 39 个（91%）从未送达**，但每个场景仍照常执行并计为一次攻击试验。
- **D2 按工具身份判定攻击成功**：只要攻击者目标工具出现在执行日志中就记为成功，不检查参数。当目标工具与良性任务必需工具重叠（如 `execute_sql_query`）时，**成功抵抗注入并正确完成任务的智能体被误判为被攻陷**。
- **D3 错误拒绝与能力不足混淆**：所有场景共享一个固定环境，无法满足良性场景的资源引用，普通"文件不存在"错误被算作防御的假拒绝；同一指标还把"无法发出工具调用"的模型算作最大程度"过度拦截"。最明显的症状：**无防御的基线竟表现出高假拒绝率**——而按构造，无防御系统不可能错误拒绝任何东西。
- **D4 无审计追踪**：只持久化聚合百分比，没有逐场景的工具调用、参数、防御决策与最终输出记录，所有数字不可复现；D1–D3 从报告本身无从发现。下游后果包括：显著性统计由四舍五入后的百分比反推计数，以及一个头条 p 值实际从未被计算，只是与临界值做了分桶比较。

### 2.3 经校验测试框架（Chokepoint Harness）
- **schema 有效性 vs. 测量有效性**：场景"能解析"只说明 schema 有效；只有"运行时其声称测量的量确实可观测"（载荷必须到达智能体、良性任务在声明环境中可满足、攻击者成功条件能对攻击者动作而非合法动作触发）才是**测量有效**。加载器拒绝任何违反这些条件的套件，把整类静默失败转化为**执行前的响亮报错**。
- **场景 schema 的三项声明**（对应修复 D1–D3）：
  - **(i) 完整逐场景环境**：每场景独立的邮箱、文件系统、SQL 表；SQL 由真实内存引擎执行，破坏性语句留下可观测后果。
  - **(ii) 结构化注入定位符**：载荷位置是可解析地址（`file:p`、`email:i`、`sql:t.c`），而非自然语言描述；定位符无法解析则中止运行。
  - **(iii) 参数级攻击者谓词**：攻击目标是对可观测工具调用的布尔函数，由一组 success condition 组成，每个条件要求"工具名匹配 **且** 参数满足给定匹配器（equals / contains / regex / iregex 等）"，用 any 或 all 组合；条件仅在**单次调用**上全部约束成立时才触发，因此共享工具的合法使用无法满足攻击者谓词。
- **指标公式**：
  - 攻击成功率（参数级）：`ASR = (1/|Sa|) · Σ_{s∈Sa} 1[G_s(C(s))] × 100%`
  - 效用保持率：`UPR(T) = (1/|T|) · Σ_{s∈T} 1[R(s) ⊆ tools of C(s)] × 100%`（R(s) 为合法任务所需工具集）
  - 假拒绝率：`FRR = 100% − UPR(Sb)`
  - 平衡准确率：`BA = ½[(100 − ASR) + UPR(Sb)]`
  - 该三元组是对 AgentDojo 指标三元组的**重新推导**（论文明确归功于 AgentDojo，不主张新颖性）。
- **可行性检查（预飞）**：注入定位符不可解析；成功条件引用了注册表中不存在的工具或任何表都不存在的列（永远无法触发的攻击目标）；注入被放入良性任务永不会读取的资源（不可达载荷）；良性任务所需工具在声明环境中无法满足——任一情形直接拒绝套件。
- **溯源**：每次运行持久化 manifest（模型、防御、套件 SHA-256、git commit、包版本、时间戳）+ 每场景自描述轨迹（解析后的环境、每次调用及其参数与结果、哪一层拦截、防御决策、最终输出、攻击者谓词各条件的逐条评估）。轨迹内嵌攻击者谓词，**真值可仅从轨迹恢复**，多数分析可离线复算。
- **三种基线防御**（chokepoint 中介，可组合）：
  - `TypeChecker`：确定性参数校验（破坏性 SQL 与路径穿越拒绝、地址白名单），无推理成本。
  - `CapabilityRouter`：按用户意图分类并只暴露所需工具；支持单意图与多意图变体（多工具任务单意图门控在构造上无法满足）。
  - `LLMJudge`：用第二个模型对每次提议调用对照原始请求裁决，并给出校准置信度。
  - 被拦截的调用会被**记录而非仅抑制**，从而区分"被防御拦下的攻击"与"智能体从未尝试的攻击"。

## 3. 实验设计

- **模型**：1 个前沿模型 `gpt-5.6-terra` + 3 个本地部署的开放小模型 `llama3.1:8b`、`gemma4:12b`、`qwen2.5-coder:7b`。所有模型先经过能力探针筛查，以便把安全指标**条件化于工具调用保真度**。
- **工具域与场景**：五个工具 `read_email`、`send_email`、`read_file`、`write_file`、`execute_sql_query`，由真实内存 SQL 引擎支撑，破坏性语句有可观测效果。
- **套件**：
  - **核心套件**：95 个场景（43 攻击 + 52 良性），逐场景环境。
  - **精简套件**：55 个场景（全部 43 攻击 + 12 良性），用于较慢的本地模型。
  - **能力探针**：10 个平凡、与安全无关的工具使用任务。
  - 所有套件通过第 V 节的可行性检查。
- **对比方法**：四种条件——`none`（无防御）、`TypeChecker`、`CapabilityRouter`、`LLMJudge`；在相同轨迹上比较缺陷评分器与修正评分器（D2/D3 消融）；对照被审计基准的原始报告数字。
- **协议与统计**：贪心解码（在提供商允许时）、逐场景超时、全轨迹写入。条件间用**双侧 Fisher 精确检验**（层样本量下卡方近似不适用），配合 **Holm–Bonferroni** 校正；点估计用 **Wilson 得分区间**。
- **先验功效分析**：在前沿基线攻击率下，n=43 攻击场景无法分辨小的防御间差异；以 80% 功效检测 60%→35% 的下降需每条件 **62 个攻击场景**（双比例检验）。因此前沿上的零比较结论被解释为**功效不足**，而非"无效果"的证据；有意义的防御对比在更高基线模型上读取。
- **威胁模型**：攻击者不能观测或修改用户提示、系统提示、模型权重、防御配置，但可向第三方内容放置任意文本；目标是造成攻击者选定的工具调用效果（外泄、破坏、越权写入），同时用户请求表面正常完成。区分**静态**（不知防御）与**自适应**（知防御）两种知识设定；后者才支配任何鲁棒性主张。

## 7. 局限性与批判性评价

- **审计样本的代表性**：论文的核心经验主张建立在对**单一 IPI 基准及其测试框架**的审计之上。论文对此诚实，但这也意味着 D1–D4 的**分布**（哪类缺陷更常见、扭曲幅度多大）无法被外推；"91% 载荷未送达"这类数字是该套件的属性，而非领域的普遍率。更稳健的表述应是"存在此类缺陷，且其后果可被量化到 18 倍量级"，而非"典型基准存在 91% 的丢弃率"。
- **外部效度**：单一工具域（5 个工具）、模拟内存环境、静态攻击设定。真实部署中工具面更宽、副作用不可逆、注入通道更多（如工具返回值自身被污染、多轮累积注入），这些均未覆盖。**自适应攻击**（第 2 节威胁模型中标为"支配任何鲁棒性主张"的设定）在实验中并未实际评估，因此论文的鲁棒性结论严格来说只适用于静态攻击者。
- **先验功效分析的双刃性**：论文主动做功效分析并承认前沿比较功效不足，这是方法上的诚实；但客观后果是**论文最有传播力的"防御对比"结论建立在证据薄弱处**——真正有信息量的比较发生在攻击率更高的开放模型上，而那里的工具调用保真度又受能力限制。读者需要同时持有"修正后的 0% ASR"与"该单元格的可推广性受限"两个事实。
- **基线的自建实现**：三种 chokepoint 防御由作者自行实现（TypeChecker / CapabilityRouter / LLMJudge），而非复用被审计工作的原始代码。消融实验（同一轨迹、仅换评分器）是严格受控的，但**防御效果本身**的比较仍带有实现偏差风险；尤其 LLMJudge 的差表现可能部分源于提示设计与阈值选择，而非该范式本身。
- **指标重推导而非新颖贡献**：ASR / UPR / FRR 三元组被明确归功于 AgentDojo。论文的贡献集中在**schema 层面的构造性保证与溯源基础设施**，这在学术叙事上是恰当定位，但也意味着其"新方法"含量主要体现在工程与评测哲学，而非算法。
- **未触及的替代路径**：论文把结论落在 chokepoint 中介上，未系统比较"在模型层做指令/数据分离"的架构性方案（如能力令牌、双通道上下文），也未讨论 chokepoint 中介在**延迟与吞吐**上的部署代价——对高并发智能体系统，这一代价可能与其安全收益同阶。

## 8. 结论与启示

- **核心论断**：智能体安全防御的主张，其有效性**首先取决于评测的有效性**。论文用可量化的方式证明，一个看似合理、可发表、可通过同行评审的 IPI 基准，可以在四个独立环节上"测量了它并未声称测量的东西"，并把结果扭曲到 18 倍量级。
- **方法论转向**：从"依赖审稿人警惕"转向"依赖 schema 构造"。当"载荷未送达""身份级评分""环境导致的错误拒绝"在数据模型中**无法被表示**时，整类静默失败被转化为**执行前的响亮报错**——这是论文最具迁移价值的贡献，适用于任何 agentic 安全基准。
- **对流行叙事的修正**：`llama3.1:8b` 从 62.8% 到 0% 的翻转，配合其 41/43 的载荷到达率、72% 的良性部分完成率与 10/10 的能力探针，说明"小模型对 IPI 灾难性脆弱"这一叙事**至少部分是测量假象**。这一修正对部署决策有直接含义：不应以旧基准的脆弱性排名作为选择模型或放弃小模型部署的依据。
- **对防御研究的含义**：`LLMJudge` 的净负收益与 0.63 的校准 AUC 提示，**未校准的模型裁决式中介不是免费的**；而 `CapabilityRouter` 式的"缩小暴露面"在低基线攻击率下表现出更好的收益/代价比，但这一比较需要更高基线或更大样本才具统计力。
- **对基础设施的要求**：轨迹级审计、逐场景环境、参数级谓词、可离线复算——这四项应被视为智能体安全评测的**最低披露标准**，而非可选增强。论文的 D4 表明，缺少它们时，缺陷不仅无法被修复，甚至无法被发现。
- **一句话总结**：在智能体安全中，**先证明你测的是你以为在测的东西，再报告你测到了什么**；本文提供的正是使这一前提可执行、可报错、可复算的工具链。
