## 摘要
配备工具的自主AI智能体的兴起带来了显著的安全风险，涵盖从无意的工具误用到通过间接提示注入（IPI）攻击进行的对抗性操纵。在实践中，已部署的智能体系统（如 OpenAI Codex 和 Claude Code）通过粗粒度权限规则与基于LLM对单个拟议动作的判断相结合来保护工具调用。然而，这两个组件都有重要局限：静态策略必须预判可能的用户意图，因而无法扩展到开放式任务；而LLM驱动的授权虽支持动态决策，却会产生不一致的结果，并且仍然容易受到有针对性的IPI攻击。为了提供可扩展且更一致的授权，我们提出 MetaPermit，一种基于策略的工具访问控制框架，将语义推断与安全执行解耦。通过分析智能体与用户的交互，我们推导出一组紧凑且与任务无关的元属性，这些元属性刻画了用户意图、执行上下文与拟议工具调用之间的关系。这些元属性使 MetaPermit 无需枚举用户意图即可授权工具使用。在运行时，LLM为每个拟议的工具调用推断元属性值，而固定策略评估这些值以允许或拒绝该调用，从而使每个决策都能通过推断出的值和所应用的策略规则进行审计。我们在 AgentDojo 和 AgentDyn 基准上，跨七个任务套件和五种攻击方法，使用两个广泛部署的开放权重LLM对 MetaPermit 进行评估。结果表明，MetaPermit 产生的授权决策比LLM驱动的授权一致率高31%，并且在任务完成度（提升最高达109%）和对IPI攻击的鲁棒性（未执行任何恶意工具调用）两方面均优于当前最先进的防御方法 CaMeL 和 IPIGuard。

## Abstract
The rise of autonomous AI agents equipped with tools has introduced significant security risks, ranging from unintended tool misuse to adversarial manipulation through Indirect Prompt Injection (IPI) attacks. In practice, deployed agent systems such as OpenAI Codex and Claude Code protect tool invocations through a combination of coarse-grained permission rules and LLM-based judgments about individual proposed actions. Both components, however, have important limitations: static policies must anticipate possible user intents and therefore do not scale to open-ended tasks, while LLM-driven authorization supports dynamic decisions but produces inconsistent outcomes and remains vulnerable to targeted IPI attacks. To provide scalable and more consistent authorization, we propose MetaPermit, a policy-based tool access-control framework that decouples semantic inference from security enforcement. By analyzing agent-user interactions, we derive a compact, task-independent set of meta-attributes that capture the relationships among the user's intent, the execution context, and the proposed tool call. These meta-attributes allow MetaPermit to authorize tool use without enumerating user intents. At runtime, an LLM infers the meta-attribute values for each proposed tool call, while a fixed policy evaluates these values to allow or deny the call, making each decision auditable through the inferred values and the applied policy rule. We evaluate MetaPermit on the AgentDojo and AgentDyn benchmarks, across seven task suites and five attack methods, using two widely deployed open-weight LLMs. The results show that MetaPermit produces 31% more consistent authorization decisions than LLM-driven authorization and outperforms the state-of-the-art defenses CaMeL and IPIGuard in both task completion, with improvements of up to 109%, and robustness to IPI attacks, with no malicious tool calls executed.

# MetaPermit 论文总结

## 1. 核心问题与整体含义

- **背景**：LLM 应用已从聊天机器人演进为具备工具调用能力的自主智能体，能够长程规划并执行一连串动作。但智能体必须将外部内容（收件箱、网页、共享文档、第三方服务输出）作为输入，而这些内容既非开发者编写，也未经用户审阅。
- **核心威胁**：间接提示注入（IPI）。由于指令与数据通过同一通道进入上下文窗口，攻击者可将恶意指令嵌入工具返回内容中，诱使智能体将其当作合法指令执行。
- **现有防御的两难**：
  - **静态策略类**（如 CSAgent、AC4A、CaMeL）：需在部署前枚举意图或权限，策略可预测但数量庞大，面对开放式任务无法扩展，且难以区分同一权限的合法与恶意使用。
  - **LLM 驱动授权类**（如 OpenAI Codex、Claude Code 的做法，以及 Conseca、Progent、IPIGuard）：支持动态决策，但 LLM 随机性导致语义相近任务产生不一致判定，且针对性的 IPI 可直接操纵授权 LLM 输出 Allow。
- **论文含义**：MetaPermit 提出一种混合访问控制框架，将**语义推断**与**安全执行**解耦——用 LLM 描述调用，用固定策略做裁决，从而同时获得可扩展性、一致性与可审计性。

## 2. 方法论

### 2.1 核心思想

- 不预测显式用户意图，而是提取一组**任务无关的元属性（meta-attributes）**，刻画"用户请求—拟议工具调用—执行上下文"之间的语义关系。
- LLM 只负责把候选工具调用映射到**固定、有类型的值域**，不产生策略规则，也不发出最终裁决；固定策略根据元属性向量决定允许/拒绝。

### 2.2 五个元属性（表 2）

| 属性 | 取值 | 回答的问题 |
|---|---|---|
| `intent_is_action` | true / false | 用户是要行动还是仅对话 |
| `intent_clarity` | clear / ambiguous / incomprehensible | 用户目标是否可无歧义理解 |
| `intent_risk` | high / low | 动作是否涉及不可逆伤害或隐私泄露 |
| `intent_tool_alignment` | direct / prerequisite / supporting / misaligned | 所调工具是否服务于用户目标 |
| `intent_input_alignment` | aligned / misaligned | 调用参数是否被用户请求所证成 |

- 关键设计：`intent_is_action` 与 `intent_clarity` **仅依赖可信的用户请求**，检索内容无法影响；其余三个可参考调用参数。

### 2.3 端到端流程

1. **推理模块**：接收用户原始请求、工具描述、调用参数、先前工具调用结果，输出一个元属性向量（有限值域，强制 JSON 格式）。
2. **策略引擎**：策略 ΠS = (r1, …, rn, rn+1) 为有序 ABAC 规则列表，规则 rj = (φj, ej, oj)，φj 为元属性谓词、ej ∈ {Allow, Deny}、oj 为反馈。**首个命中规则生效**，未命中的默认规则一律拒绝（fail-closed）。
3. **执行门**：Allow 则原样转发调用；Deny 则阻断并将反馈作为合成工具结果返回给智能体，使其可重新规划而非直接停机。

### 2.4 策略构建与扩展

- 从安全目标出发，将自然语言规则逐步泛化为可复用的安全维度（附录 A.2 给出了从"发邮件"具体规则泛化到 `intent_tool_alignment`、再到 `intent_input_alignment` 的推导过程）。
- 表 7 给出 8 条有序规则 + 默认拒绝规则，**跨全部七个套件和五种攻击保持不变**，无套件专属规则。
- 新增授权需求只需增加元属性维度并更新依赖它的规则，接口、执行路径与无关规则不变；策略规模随安全维度而非用户意图空间增长。

### 2.5 关键防攻击机制

- 绕过 MetaPermit 需诱导 LLM 同时产出**满足某条 Allow 规则的完整元属性组合**，而非仅说服其输出一个 Allow。
- 即使白盒注入成功翻转部分元属性（如把 `intent_risk` 降为 low，占 16.8%），`intent_tool_alignment` 与 `intent_input_alignment` 仍分别阻断 94/95 与 95/95 的恶意调用。

## 6. 主要结论与发现

- **安全性**：MiniMax-M2.7 上 ASR 从无防御的 2.85% 降至 0.08%（execution-aware 为 0%，0/7,545）；Qwen3-235B 上从 26.49% 降至 **0.00%**。两模型均无恶意工具调用被实际执行。
- **效用保持**：MiniMax-M2.7 上 UA 53.92%（CaMeL 25.83%、IPIGuard 30.27%）；Qwen3-235B 上 UA 50.13%（CaMeL 42.21%、IPIGuard 41.96%），任务完成最高提升 109%。AgentDojo 套件上 UA 仅小幅下降（69.4% vs 无防御 72.0%），主要损失发生在更难的 AgentDyn 套件。
- **Secure-Usable**：MetaPermit 在两后端均取得防御方法中最高的 Secure-Usable 占比（53.9% / 50.1%），接近无防御水平；CaMeL 与 IPIGuard 的低 ASR 主要来自 Secure-Unusable（任务未完成）。
- **一致性**：固定策略使最终裁决在 20 次重复中完全一致的比例为 42%，高于直接 LLM Guard 的 32%；多数一致率 90% vs 87%。在 47 个元属性向量有波动的查询中，38% 被策略映射到一致裁决，阻止了底层波动传导到执行决策。
- **类型化接口的价值**：相同模型与查询下，直接输出 Allow/Deny 的守卫在 Qwen3-235B 上 UA 跌至 12.75%（MetaPermit 29.25%），说明类型化元属性在保持安全的同时显著保住效用。
- **单属性贡献**：移除 `intent_input_alignment` 后效用几乎不变（53 vs 54 个完成任务），但攻击成功翻倍（2 vs 1），且其反馈还能略微提升效用。
- **拒绝反馈**：完整结构化反馈带来最高 UA（60.00%）与恢复率（50.00%），ASR 保持 0%，且重复拒绝更少。
- **Checker 假阳性**：MetaPermit 全部 6 个官方阳性均只出现在 `<think>` 推理轨迹中，未执行任何攻击诱导的调用；而基线阳性中此类假阳性仅占少数。

## 7. 优点

- **架构层面的解耦设计**：将"语义推断"与"授权裁决"分离，是本文最核心的洞见。模型只描述，策略才裁决，从根本上限制了被注入模型的权限。
- **类型化接口缩小攻击面**：攻击者必须构造出满足整条 Allow 规则的完整元属性组合，而不能只说服 LLM 输出一个 Allow；且两个元属性仅依赖可信用户请求，检索内容无法影响。
- **可审计性**：每个决策都对应显式的元属性取值与命中的策略规则，决策空间因

类型化而有限，审计者可以枚举所有可能的元属性组合，验证策略对这些组合的覆盖情况，而无需回溯 LLM 的隐式推理链。出现争议决策时，可精确指出是哪一条元属性取值或哪一条规则导致放行/阻断。

- **策略与模型解耦**：策略表（8 条规则 + 默认拒绝）跨七个套件、五种攻击、三个模型规模保持不变，说明策略绑定的是安全语义维度而非具体模型行为。更换或升级底层 LLM 无需重写策略，降低了部署维护成本；表 14 的 Qwen3-8B 结果也验证了这种迁移性。

- **Fail-closed 默认拒绝**：未命中任何规则即拒绝，使防御在策略覆盖不足时倾向于保守失败，而非静默放行。这一设计选择与"宁可 Secure-Unusable 也不 Secure-Unsafe"的安全取向一致。

- **拒绝反馈支持重新规划**：被阻断的调用不以硬错误终止任务，而是作为合成工具结果回传，让智能体有机会换一条合法路径完成用户目标。消融实验（表 9）显示完整结构化反馈同时提升了效用与恢复率，且未引入 ASR 上升。

- **评估透明度较高**：同时报告官方 checker 的 ASR 与 execution-aware ASR，并主动逐条审计假阳性；在基线对比中明确标注其结果为"开箱即用"而非调优后表现，避免夸大自身优势。

- **部署成本低**：无需训练、无需微调，仅需一次受限输出格式的 LLM 推理加上一个轻量策略匹配器，可叠加在既有智能体框架之上。

## 8. 局限与不足

- **策略仍依赖人工设计**：论文强调元属性是任务无关、可复用的，但初始策略仍需安全专家从安全目标出发手工推导并泛化（附录 A.2 的推导过程即是例证）。新增安全维度（如金融转账限额、数据外泄范围）需要人工扩充元属性与规则，规模化路径虽比枚举意图清晰，但并未完全消除人工负担。

- **元属性值域是安全覆盖的上界**：防御强度取决于五个属性是否足以刻画所有关键安全语义。若某类攻击的恶意性无法由现有属性区分（例如调用本身与用户请求在语义上完全对齐、但执行时机或频率异常），当前策略可能既无法阻断也无法解释。论文未给出元属性完备性的形式化论证。

- **对 LLM 属性推断准确性的依赖**：策略虽固定，但输入策略的属性向量由 LLM 生成。白盒探针实验（表 6）显示攻击者可在 16.8% 的情况下成功翻转 `intent_risk`，说明单点属性并非不可攻破；论文的鲁棒性论证依赖于"多条属性同时被攻破"这一较高门槛，而非单属性级别的形式化保证。

- **AgentDyn 上效用损失显著**：Shopping（9.33%）与 Github（19.22%）的 UA 表明，在开放式、长依赖、第三方指令可能合法的环境中，fail-closed 策略会误伤合法调用。论文将之归因于任务难度与开放式证据使用，但这也说明策略在"合法外部指令"与"注入指令"的边界上仍偏保守。

- **消融实验样本量偏小**：单属性贡献（105 例）、白盒探针（95 例）、反馈消融（70 例）均基于 MiniMax-M2.7 的小规模子集，结论的统计功效有限，且未在 Qwen3-235B 上复现。

- **决策一致性提升有限**：完全一致率 42%（vs. 直接 LLM Guard 32%）意味着多数查询的底层属性推断仍有波动；虽然策略吸收了其中 38% 的波动，但仍有相当比例的查询在重复执行中产生不同属性向量。稳定性是"被缓解"而非"被解决"。

- **规则顺序敏感**：首个命中规则生效意味着策略是优先级列表而非集合语义，规则排序本身成为安全关键设计，论文未讨论排序错误或规则冲突的检测方法。

- **运行时开销未量化**：每次工具调用都需一次额外的 LLM 推理，论文未报告延迟、token 消耗或端到端吞吐，也未与基线的开销做对比。

- **基线对比的公平性边界**：CaMeL 与 IPIGuard 需要模型产出可解析程序或忠实图遍历，论文自承其结果对 provider 敏感。因此"MetaPermit 效用显著更高"的结论部分来自任务适配度差异，而非纯粹的架构优越性。

- **场景覆盖有限**：仅评估文本模态的单智能体工具调用场景，未涉及多智能体协作、跨会话记忆污染、代码执行环境或图像/音频等非文本注入通道。

## 9. 结论与启示

- **核心结论**：将访问控制中的"语义理解"与"授权裁决"分离，是一条同时改善安全性、效用与一致性的可行路径。LLM 的价值在于把开放式调用映射到有限值域，而非充当最终裁判；一旦裁决权交还给固定策略，注入攻击的目标就从"说服模型"变为"伪造完整属性向量"，攻击门槛大幅提高。

- **对防御设计的启示**：
  1. **缩小 LLM 的输出空间**本身就是一种防御——类型化接口不仅提升可解释性，也直接压缩了攻击者的可操纵维度。
  2. **让部分属性只依赖可信输入**（如用户原始请求）是一条低成本、高收益的设计原则，可在不增加策略复杂度的前提下建立不可污染的安全锚点。
  3. **拒绝应是可恢复的交互而非终止**，这使安全机制与效用不再零和。
  4. **策略的复用粒度应是安全语义维度，而非用户意图或工具权限**，这是其能跨套件、跨模型、跨攻击模板保持稳定的根本原因。

- **未来方向**：自动化或半自动化地从安全目标推导元属性与规则；为元属性设计引入形式化保证或冗余交叉校验以抵御多属性联合注入；在策略层引入频率、时序、累积效应等非语义维度；将框架扩展至多智能体与多模态场景；量化并优化额外推理带来的延迟成本。
