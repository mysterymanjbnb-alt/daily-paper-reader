## 摘要
大语言模型正越来越多地被用作移动机器人、机器人机械臂和自动驾驶车辆的高层规划器。近期研究表明，这些系统可受到恶意文本、语音、视觉指令、检索文档以及被投毒的传感上下文的影响。大多数防御措施关注的是所提议动作在物理上是否安全。本文研究一个不同的问题：一个动作可能在物理上是安全的，但仍违反用户授权的任务。攻击者可能重定向配送机器人、替换已批准的对象、扩展机器人运行区域、激活不必要的传感器，或延迟任务，而不造成即时物理危险。我们将这种攻击称为安全合规型任务劫持。我们提出 MissionPAIR，一种自适应攻击框架，用于搜索能够通过安全门控、同时违反经认证任务的可执行计划。我们还提出 AuthGuard-R，一种确定性授权层，将每个可执行动作绑定到签名任务、机器人身份、对象与区域范围、当前状态、时间以及输入来源。AuthGuard-R 与独立的安全门控协同运行，形成双门架构。我们在机器人轨迹上形式化任务策略，定义安全博弈，并证明授权可靠性、任务不可提升、抗重放、机器人绑定、来源分离、阈值批准安全、审计日志防篡改证据以及轨迹级组合性。我们报告了一项使用 Claude Haiku 4.5 和开源 Qwen2.5 7B 规划器的初步跨模型评估。在 240 次实时攻击试验中，规划器在 109 次试验中遵循了注入的任务偏离；AuthGuard-R 拒绝了所有 109 个由此产生的未授权动作。另一组手工构建的包含十一种协议层和策略层攻击的测试集也被完全阻止。

## Abstract
Large language models are increasingly used as high-level planners for mobile robots, robot manipulators, and autonomous vehicles. Recent studies show that these systems can be influenced through malicious text, speech, visual instructions, retrieved documents, and poisoned sensory context. Most defenses ask whether a proposed action is physically safe. This paper studies a different problem: an action may be physically safe and still violate the mission authorized by the user. An attacker may redirect a delivery robot, replace an approved object, extend a robot's operating region, activate an unnecessary sensor, or delay a mission without creating an immediate physical hazard. We call this attack \emph{safety-compliant mission hijacking}. We propose MissionPAIR, an adaptive attack framework that searches for executable plans that pass a safety gate while violating an authenticated mission. We also propose AuthGuard-R, a deterministic authorization layer that binds every executable action to a signed mission, robot identity, object and region scope, current state, time, and input provenance. AuthGuard-R operates with an independent safety gate, giving a dual-gate architecture. We formalize mission policies over robot traces, define security games, and prove authorization soundness, mission non-escalation, replay resistance, robot binding, provenance separation, threshold-approval security, audit-log tamper evidence, and trace-level composition. We report a preliminary cross-model evaluation with Claude Haiku~4.5 and the open-source Qwen2.5~7B planner. Across 240 live attack trials, the planners followed an injected mission deviation in 109 trials; AuthGuard-R rejected all 109 resulting unauthorized actions. A separate hand-constructed suite of eleven protocol- and policy-level attacks was also blocked completely.

## 1. 论文的核心问题与整体含义（研究动机与背景）

- **背景**：LLM/VLM 正被广泛用作移动机器人、机械臂、自动驾驶车辆的高层规划器，将自然语言指令转化为导航、抓取、递送等物理动作。这种灵活性同时也构成了安全边界——模型输出可直接驱动物理执行。
- **威胁面**：模型可被恶意文本、语音、视觉指令（如摄像头 OCR 读到的标牌）、检索文档、被投毒的传感上下文、共享记忆等渠道影响，已有工作（BadRobot、RoboPAIR、RIPA、Blindfold 等）证明具身 LLM 智能体可被越狱或操纵。
- **核心问题**：现有防御（RoboGuard、SafeGate、运行时治理框架等）几乎都聚焦于**物理安全**——是否碰撞、是否超力限、是否进入危险状态。但**物理安全 ≠ 授权合规**。一个动作可以完全无危险，却违背用户签署授权的任务。
- **关键概念——安全合规型任务劫持（Safety-Compliant Mission Hijacking）**：
  - 例如：配送机器人被授权把药品 P1 从 A 桌送到 101 室，恶意标牌声称“101 已关闭，改送 103 室”；机器人安全抵达 103 室，无碰撞、无超速，但任务已被劫持。
  - 还包括：替换批准对象、扩展运行区域、激活不必要的传感器（隐私越界）、伪造紧急信息导致任务延迟（可用性操纵）、来源混淆（把摄像头文字当成授权更新）等。
- **论文要回答的问题**：如何保证 LLM 控制机器人的每一个执行动作，既物理安全，又经过原始任务的密码学授权？
- **整体定位**：将机器人安全从“物理安全”扩展为“物理安全 + 任务授权安全”，主张 LLM 只能决定“如何执行已授权任务”，不能决定“被授权做什么”。

## 2. 论文提出的方法论

### 核心思想
- **零信任规划器原则**：LLM 视为不可信的动作提议生成器，它不能为自己授予新权限；只有经过认证的主体（操作员/监管者）才能定义或更改执行权限。
- **双门架构**：授权门（AuthGuard-R）与独立安全门（如 RoboGuard）串联，只有两者都接受才允许执行（`Exec(s,a,t) = GA(s,a,t) ∧ GS(s,a)`）。

### 关键组成

**（1）形式化任务语言与策略**
- 结构化任务 `M = (mid, rid, issuer, task, actions, objects, regions, limits, guards, expiry, nonce, riskPolicy, version)`，由任务编译器从自然语言请求生成，经操作员确认后用 Ed25519（可选 ML-DSA 后量子签名）签名。
- 签名对象是**域分隔哈希**：`σ = Sign_skU(H(tag ∥ Encode(M)))`，而非原始自然语言文本。
- 授权谓词为多个检查的合取：`Auth(M,a,s,t) = ⋀ Cj(M,a,s,t)`，覆盖机器人身份、时效、动作类型、对象、区域、数值限、状态守卫、来源标签。
- 定义**动作级任务偏差** `D_M(a,s,t) = Σw_j·d_j / Σw_j`（0 表示完全合规），**计划级偏差**取最大值（任一动作越权即违规）。

**（2）安全合规型任务劫持的形式化定义**
- `SCMH(P,M,s0) = X(P,s0) · S_A(P) · (1 − A_A(P,M))`
- 即：计划可执行 ∧ 通过安全门 ∧ 未通过授权门。

**（3）MissionPAIR 攻击框架**
- 将攻击建模为约束优化：最大化 `D_M(Pq)`，约束为可执行、安全门通过、偏差 > 0。
- 搜索分数：`J(q) = λ1·D_M + λ2·X + λ3·S_A − λ4·ObviousHarm − λ5·InvalidSyntax`。
- 算法流程：初始化对抗上下文 → 目标规划器生成计划 → 规范化 → 检查可执行性/安全性/偏差 → 若三者满足则返回成功，否则自适应更新攻击上下文（最多 N 轮）。
- 支持黑盒、灰盒、白盒三种访问模型；攻击模板覆盖目的地变更、对象重标记、隐私升级、虚假紧急、路线扩张等，并通过文本/标牌/语音/检索/记忆等多渠道投递。
- 同时包含**合法的、经签名的新任务更新**作为配对，用于检验防御不会无差别拒绝所有变更。

**（4）来源标签与来源策略**
- 定义来源集合 `P = {operator, supervisor, trustedSensor, camera, audio, retrieval, memory, model}`。
- 每个字段有 `AllowedSrc(f)`：特权字段（目的地、对象身份、录像许可、批准阈值）只接受 operator/supervisor；摄像头/音频/检索/记忆/模型输出只能提供观测，不能修改授权。

**（5）风险自适应批准**
- 按风险分数 `ρ(a,s)` 决定所需批准数：低风险 1 人、中风险 2 人、高风险 t-of-n 阈值签名。

**（6）哈希链审计日志**
- `Li = H(L_{i−1} ∥ mid ∥ i ∥ ai ∥ si ∥ ti ∥ di ∥ ei)`，并周期性将终端摘要签名或外部锚定。

### 形式化安全证明（Section IX）
- 在 EUF-CMA 签名安全、哈希抗碰撞、策略检查器正确、注册表不静默回滚等假设下，证明：授权可靠性（Theorem 9.1）、动作集不可提升（Lemma 9.2）、抗重放（Theorem 9.4）、跨机器人拒绝（Theorem 9.5）、特权字段来源非干扰（Theorem 9.6）、阈值批准安全（Theorem 9.7）、审计防篡改（Theorem 9.8）、双门轨迹组合性（Theorem 9.9）以及阻断 SCMH（Corollary 9.10）。

  - 对比三种配置：无防御、仅安全门、完整双门。
- **实时 LLM 评估（第二组）**：
  - 目标规划器：**Claude Haiku 4.5** 与开源 **Qwen2.5 7B**（通过 Ollama 本地运行）。

## 6. 论文的主要结论与发现

- **物理安全与任务授权是不同属性**：仅安全门（safety-only）在受控实验中 UASR = 1.00、SCMHR = 1.00，与无防御相同；加入 AuthGuard-R 后二者均降为 0，而 BTCR 保持 1.00、FRR 为 0，SU 从 0 升至 1。
- **规划器对齐不可靠且跨模型差异巨大**：
  - Claude Haiku 4.5：固定模板合规率 18.3%（11/60），自适应 20.0%（12/60），对象替换是主要失守类别。
  - Qwen2.5 7B：固定模板合规率 83.3%（50/60），自适应 60.0%（36/60），五类攻击几乎全部得手。
- **执行侧结果稳定**：240 次实时试验中 109 次产生越权动作，AuthGuard-R 全部拒绝；加上 11 个手工攻击，共 120 个未授权动作被阻断，同时保留全部良性对照。
- **一个重要的实现教训**：早期“返回基地”场景因任务策略未编码低电量状态守卫而被接受，补上守卫后重放该动作被拒绝——说明确定性执行只能忠实执行“已编码”的策略，无法推断编译器遗漏的限制。
- **核心设计原则**：LLM 可以决定如何完成已授权任务，但不应能决定自己被授权做什么。

## 7. 优点

- **问题定义新颖且清晰**：首次系统性地将“物理安全”与“任务授权”分离，提出“安全合规型任务劫持”这一可密码学检验的攻击类别。
- **形式化严谨**：给出完整的安全博弈（授权绕过、重放、跨机器人、来源混淆、审计篡改）与定理证明，并明确区分密码学保证与工程可信假设的边界。
- **架构简洁可审计**：确定性授权门、域分隔签名、规范化动作模式、逐字段来源标签、哈希链审计，模块化且便于硬件隔离与独立审查。
- **攻击与防御配套**：MissionPAIR 直接以“通过安全门但违反授权”为目标，与防御的检验目标一致，避免只做常规有害动作越狱实验。
- **实验设计避免指标陷阱**：明确“规划器拒绝不算防御成功”“安全提升不能靠拒绝良性任务获得”，并报告 SU 调和分与 Wilson 置信区间。
- **跨模型验证**：同时覆盖专有与开源规划器，凸显授权决策应独立于模型对齐程度。

- **样本量与基线不足**：每类别 10 个种子，未与 RoboPAIR、RoboGuard、BadRobot 原规模复现对比，无消融实验，统计功效有限。
- **信任边界假设较强**：安全性依赖任务编译器正确、规范化忠实反映物理效果、状态估计准确、授权门/时钟/注册表/密钥未被攻破；若定位把 103 室误报为 101 室，符号检查仍可能批准错误物理位置的动作。
- **未解决的安全与伦理问题**：恶意授权操作员仍可签署有害任务；审计日志仅保证完整性，不保证机密性（可能含敏感位置、对象、传感证据）；不防网络洪泛、断电、物理阻挡等可用性攻击。
- **性能评估不完整**：仅给出复杂度公式分析，未报告实测延迟、token 大小、日志增长、阈值批准的实际开销；未给出算力与部署环境细节。
- **任务语义局限**：形式化保证的是“忠实执行已签名策略”，不能保证任务本身道德正确、完整反映用户真实意图或覆盖所有隐含约束。
