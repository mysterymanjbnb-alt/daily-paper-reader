## 摘要
现有多智能体基准测试主要在竞争性场景、20 步以内的短时程交互中进行评估，或仅简单聚合个体性能，未能分离并突出基于 LLM 的智能体真正的协作能力。我们提出 AgentWorld，一个包含 100 个人工标注任务（以及 100 个增强变体）的基准，用于评估长时程、多智能体协作。任务在一个丰富的 MMORPG 沙盒中跨越 50 余轮交互，要求 3 至 20 个具有非对称角色和能力的智能体在黑箱设定下通过通信、联合规划和资源共享进行协调，其中每个智能体独立行动，无法访问其他智能体的内部状态。为了在传统的二元任务成功之外量化协作有效性，我们提出因果协作有效性（Causal Collaboration Effectiveness, CCE），这是一种基于图的指标，用于追踪智能体动作之间的因果依赖，并衡量团队努力中实际对结果有贡献的比例。使用 Gemini 3 Flash、Claude Haiku 4.5、GPT-5 Mini 和 DeepSeek R1-70B 进行的实验表明，即使表现最好的模型也仅达到 52.0% 的任务成功率，并存在系统性失败模式，包括通信中断、角色混淆以及无法跨轮次维持共享计划。AgentWorld 完全开源。

## Abstract
Existing multi-agent benchmarks primarily test in competitive settings, short-horizon interactions under 20 steps, or simply aggregate individual performance, failing to isolate and highlight genuine collaboration capabilities of LLM-based agents. We introduce AgentWorld, a benchmark of 100 human-annotated tasks (with 100 augmented variants) for evaluating long-horizon, multi-agent collaboration. Tasks span 50+ interaction rounds across a rich MMORPG sandbox and require 3-20 agents with asymmetric roles and abilities to coordinate through communication, joint planning, and resource sharing under a blackbox setting where each agent acts independently without access to others' internal states. To quantify collaboration effectiveness in addition to conventional binary task success, we propose Causal Collaboration Effectiveness (CCE), a graph-based metric that traces causal dependencies between agent actions and measures what fraction of a team's effort actually contributed to the outcome. Experiments with Gemini 3 Flash, Claude Haiku 4.5, GPT-5 Mini, and DeepSeek R1-70B show that even the best model achieves only 52.0% task success, with systematic failure modes including communication breakdowns, role confusion, and inability to maintain shared plans across rounds. AgentWorld is fully open-source.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体已从单轮推理走向自主工具调用与多步规划，多智能体协作（MAC）成为关键能力。现实任务（软件开发、科研、复杂运营）普遍需要多个专业化智能体协同。
- **现有基准的三大缺陷**：
  - **时程过短**：多数任务不超过 10–20 步，无法评估持续协调能力。
  - **混淆"低层控制"与"协作"**：如 Minecraft 类环境要求精确 3D 导航、方块放置等，智能体把预算耗在动作控制上，协作能力难以在分数中体现。
  - **缺乏可测结果**：如 Project Sid 等大规模社会模拟侧重涌现社会行为，而非有明确目标与量化结果的任务。
- **核心问题**：如何在**长时程、黑箱、非对称角色**的设定下，隔离并量化 LLM 团队的真实协作能力——不仅看"是否成功"，还要看"以多高的协作效率成功"。
- **整体含义**：论文提出 AgentWorld 基准 + CCE 指标，主张协作能力是当前基础模型的共同短板，且比单智能体推理更难，需要独立的评测体系。

## 2. 方法论

### 2.1 模拟环境（沙盒）
- 基于开源 MMORPG 引擎 **Kaetram** 构建：1056×768 瓦片、9 种生物群系、380+ 物品、144 种怪物（Lv.1–250+）、70+ NPC、1531 个可采集资源节点、8 项技能（伐木、采矿、钓鱼、采集、制作、锻造、制箭、烹饪）。
- 最多支持 **1000 个并发智能体**；实验采用**轮询（round-robin）回合制**保证可复现：每轮每智能体依次获得新观测、调用一次 API 工具、等待结算。
- **抽象层设计（关键）**：在 Kaetram 之上封装 **13 个高层 API 工具**（move、attack、harvest、craft、transfer、chat 等），把寻路、战斗全流程、采集等低层机制压缩为单次函数调用，使智能体预算花在"做什么、和谁协调"而非"怎么做"。
- **黑箱设定**：智能体无法访问他人的内部状态、观测或动作历史，协调只能靠显式 chat 消息经环境路由。

### 2.2 任务设计
- 每个任务包含：主目标、非对称的智能体配置（角色/技能/出生点/初始物品）、轮次预算、任务专属文档（配方、怪物属性、资源位置）、Python 成功判定函数。
- 任务设计原则：**任何单一智能体都不具备完成任务所需的全部技能或资源**。例如 Task 67（资源商队）需 8 个智能体跨三个生物群系分工与转运；Task 100 需 16 个智能体做全图勘测。
- **标注流程**：5 名标注者按预设类别分布设计任务，编写 Python 验证器；用两个 LLM 做试点实验，把失败归类为系统/任务/智能体错误并迭代修订，直至只剩智能体错误；轮次预算（25–55）由试点校准。
- **增强变体**：用 Claude Opus 4.5 生成 100 个变体（目标、出生点、初始物品变化），并做人工验证（10% 抽样显示 100% 保留多智能体协作需求、目标语义与角色非对称性）。

### 2.3 评测指标
- **SR（任务成功率）**：由每个任务的 Python 验证器检查最终游戏状态（可选检查轨迹）。
- **PSR（部分成功率）**：按检查点完成比例取平均的软指标；成功任务 PSR=100%。
- **CCE（因果协作有效性）**——核心创新：
  - 构造**因果动作图（CAG）** $G=(T,E)$：节点为所有动作 $T=\{(a_i,r,d)\}$，有向边 $x \to y$ 表示 $x$ 因果上使能 $y$；因因果流随时间前向，图必为 DAG。
  - **算法流程（反向因果追踪）**：
    1. 识别直接达成目标的**成功动作集 $S$**（终末动作，不含前置动作）；
    2. 初始化贡献集 $C \leftarrow S$，frontier $\leftarrow S$；
    3. 逐轮向前扫描，对每个 frontier 动作 $y$，询问 LLM："动作 $x$ 是否因果上使能/贡献于 $y$？"若是则加边并入 $C$；
    4. 计算指标。
  - **贡献集**：$C = S \cup \text{ancestors}(S)$；**CCE** $=|C|/|T|$。失败任务定义 CCE = 0。
  - 解读：CCE≈1 为完美效率；CCE≈1/N 表示只有单个智能体在贡献；CCE≈0 表示混乱失败。
  - **PAC（单智能体贡献）**：$\text{PAC}_i = |C \cap T_i| / |T_i|$，用于揭示成功是否由少数智能体驱动。
  - **关键设计取舍**：LLM 只做**客观的二元因果判断**（"捕虾是否使能了后续转运虾"），而非主观质量打分（"协作质量 1–5 分"），因而更可复现；采用**宽松包容策略**（边际有用即计入贡献），故 CCE 应视为真实有用动作比例的**上界**。
  - **工程优化**：按资源类型/位置/通信通道剪枝、批量查询、时间窗口限制，避免 $O(|T|^2)$ 全对查询。

## 3. 实验设计

- **Benchmark**：AgentWorld 主集 100 个人工标注任务 + 100 个 LLM 增强变体；8 类任务（战斗、制作、采集、交易、探索、生存、建造、协调）；3–20 个智能体；25–55 轮（平均 38 轮）。
- **被评模型（主实验 4 个前沿模型）**：Gemini 3 Flash、Claude Haiku 4.5、GPT-5 Mini、DeepSeek R1-70B。统一系统提示、用户提示模板与 API 工具定义。
- **附加模型**：Muse-Glimmer-30B（结果已定稿）、Gemma 4 26B A4B（暂定结果，仅在 100 任务增强 v1 划分上评测）。
- **指标**：SR、PSR、CCE，另统计平均轮数、平均 chat 数。
- **基线（Gemini 3 Flash 上）**：
  - random actions（无 LLM，均匀选合法动作）；
  - single-agent（所有角色与物品交给一个智能体）；
  - no-communication（禁用 chat 与消息工具）；
  - shared-plan-no-communication（先给人类写的共享计划，再各自执行）；
  - oracle communication（一个智能体可见所有消息并协调全队，作为通信质量上界）。
- **消融（35 任务子集，Gemini 3 Flash）**：移除非对称角色信息、把轮次预算从 50 缩到 10、随机化出生点、移除任务专属文档。
- **稳定性实验**：同一 35 任务子集、temperature 0.7、种子 42/819/314 跑三次。
- **指标鲁棒性实验**：用三个不同家族判官（GPT-4.1 为主、Claude Sonnet 4、Llama-4 Maverick）重算 CCE；并以 84 条人工标注判断验证判官一致性。
- **通信失败分析**：对 Gemini 3 Flash 在 100 任务轨迹中的消息做聚类分类。

## 6. 主要结论与发现

- **整体成功率低**：主集上 Gemini 3 Flash 最高仅 **52.0% SR**（PSR 71.5%，CCE 0.320）；Claude Haiku 4.5 为 45.0%/62.7%/0.294；GPT-5 Mini 36.0%/62.6%/0.206；DeepSeek R1-70B 20.0%/43.5%/0.125。**27% 的任务没有任何模型能解决**。
- **绝大多数动作是"无效功"**：即使最好的模型 CCE 也只有 0.320，即**不到三分之一的动作处于通往成功的因果路径上**；DeepSeek 有近 88% 的动作被浪费。
- **增强集显著更难**：所有模型 SR 大幅下滑（Gemini 52→24%，Claude 45→26%，GPT-5 36→21%，DeepSeek 20→10%），且需更多轮次与动作。
- **"沟通多 ≠ 协作好"**：GPT-5 Mini 消息最多（44.1 条/任务）却只排第三；DeepSeek 消息最少（7.5）且排名最后，且其首条消息平均延迟到第 5 轮（其他模型第 1–2 轮），错过早期协调窗口；Gemini 沟通适度（11.0）却成功率最高。失败任务中 GPT-5 有 26% 的动作花在聊天上——**过度沟通挤占了有效行动**。存在一个"最优沟通区间"。
- **CCE 在成功任务上给出额外信息**：条件于成功任务时，Claude 的单任务协作效率最高（0.653 vs Gemini 0.609），GPT-5 Mini 最低（0.571），说明 CCE 排序与 SR 大体一致但不完全重合。
- **任务难度分化明显**：生存最易（67–100% SR），协调（12%）与建造（20%）最难，反映紧密多智能体同步的困难。
- **任务确实需要协作**：random actions 仅 5.7%、single-agent 仅 28.6%；无通信 22.9%；"给共享计划但不通信"反而更差（17.6%）——固定计划一旦假设失效就无人能修复，说明**计划的价值取决于执行中能否被修订**。
- **通信有增益但非万能**：oracle communication 把 52.0% 提升到 60.0%，但仍有 40% 失败，说明大量困难源于长时程规划与资源分配本身，而非仅仅是去中心化。
- **消融证实设计要素承重**：移除任务文档（54.3→29.4%）与缩短时程（54.3→37.1%）影响最大；移除非对称角色（→45.7%）次之；随机出生点影响最小（→51.4%），符合"隔离协作能力与偶然难度"的设计目标。
- **CCE 具备可复现性**：三个判官下模型排序完全保持，绝对值漂移 ≤0.05；人工与判官在 84 条判断上原始一致率 82%、Cohen's κ=0.64，与两个判官之间的 κ=0.66 相当，说明二元因果判断是良定义的。
- **六类通信失败模式**：陈旧与冗余（37.7%）最突出，其次为角色误认（16.4%）、事实性错误（14.8%）、过早宣布完成（11.5%）、非实质输出（11.5%）、逻辑不一致（8.2%）。

- **问题定位清晰、切中要害**：明确指出现有基准"短时程 + 混淆低层控制 + 缺乏可测结果"三重缺陷，并用 13 个高层工具抽象层把协作能力从动作控制能力

中剥离出来，使评测信号更纯净。
- **指标设计有理论支撑且可复现**：CCE 把"协作"操作化为因果动作图上的祖先集占比，用 DAG 保证因果流单向、用二元因果判断替代主观打分，并通过三判官交叉验证证明排序稳定，这在多智能体评测中较为少见。
- **指标不止于"是否成功"**：SR/PSR/CCE/PAC 四件套同时刻画"能否完成""完成到什么程度""以多高效率完成""是否靠少数智能体单打独斗"，提供了比单一成功率更细的诊断粒度。
- **基线设计有针对性**：single-agent、no-communication、shared-plan-no-communication、oracle communication 四组基线分别隔离"人数""通信""计划""中心化协调"四个变量，其中"有共享计划但禁止通信反而更差"的发现具有反直觉价值。
- **消融与设计目标对齐**：随机出生点影响最小、移除文档与时程影响最大，恰好印证了"把偶然难度与协作难度解耦"的设计意图，说明消融不是走过场。
- **任务标注流程严谨**：多标注者按类别分布设计、Python 验证器自动判定、用试点实验把失败归因迭代到"仅剩智能体错误"，这套流程降低了任务本身缺陷污染结论的风险。
- **对失败模式的刻画具体**：六类通信失败模式（陈旧冗余、角色误认、事实错误、过早宣布完成、非实质输出、逻辑不一致）为后续改进提供了可操作的靶点，而非停留在"沟通不够好"的笼统结论。
- **开源与可扩展性**：基于开源引擎 Kaetram、支持 1000 并发智能体、提供任务文档与验证器，具备被社区复用于新模型评测的潜力。

## 8. 不足与局限

- **算力与成本信息缺失**：全文未报告推理 token 量、GPU 资源、运行时长与费用，评测复现的经济门槛无法评估，尤其 CCE 的反向追踪需要逐轮 LLM 查询，成本可能随动作数显著增长。
- **基线与消融仅限单模型**：所有对照实验只在 Gemini 3 Flash 上进行，无法判断"通信有增益""计划需可修订"等结论是否对弱模型或强模型同样成立——而弱模型可能根本不具备执行共享计划的能力，强模型可能不需要通信即可隐式协调。
- **样本规模偏小**：消融与方差实验仅 35 个任务，三次重复的 SR 完全相同（54.3%），论文自身也承认无法确立统计显著性，模型间 SR 差异（如 52.0% vs 45.0%）是否显著存疑。
- **CCE 存在系统性高估**：作者采用"边际有用即计入"的宽松策略，CCE 被明确定义为真实有用动作比例的**上界**；同时 LLM 判官仍有约 18% 与人工不一致，意味着 CCE 的绝对值不宜作为精确刻度，只适合做相对比较。
- **因果判断依赖 LLM，存在自洽性风险**：判官与部分被评模型同源或同族时，可能对特定表述风格的动作描述更"宽容"，论文虽用三判官验证排序稳定，但未讨论判官与被评模型的同源偏置。
- **增强集划分不统一**：Muse-Glimmer-30B 与 Gemma 4 的结果并非在同一划分上取得，Gemma 4 更是暂定值且按已评分任务平均，横向对比的公平性被削弱。
- **环境抽象可能掩盖真实协作难度**：13 个高层工具把寻路、战斗流程压缩为单次调用，固然隔离了低层控制，但也移除了"在物理约束下协商行动"这一真实协作的重要组成部分，结论向"语义级协调"倾斜。
- **黑箱设定与真实场景存在差距**：现实中智能体常可读取共享文档、数据库或队友的显式状态，完全禁止内部状态可见是一种极端设定，可能低估了有共享上下文时的协作上限。
- **任务分布与语言偏置未讨论**：任务全部为英文文档与英文 chat 路由，跨语言协作、文化语境对协调的影响未被纳入。

## 9. 对后续研究的启示

- **协作能力应作为独立评测维度**：单智能体基准的高分不能推出多智能体协作能力，二者需要分开测量；CCE 这类"过程效率"指标值得被更多基准采纳。
- **沟通质量比沟通数量更重要**：存在"最优沟通区间"的发现提示，未来工作可从"减少冗余消息、抑制过早宣布完成、强制角色对齐"入手，而不是简单地鼓励多说话。
- **计划必须是可修订的**：共享计划在禁止通信时表现更差，说明中心化计划 + 去中心化执行是脆弱组合，未来可研究"轻量级计划同步协议"。
- **长时程是当前共同瓶颈**：oracle communication 仍失败 40%、移除文档使 SR 腰斩，指向长时程记忆保持、资源分配与目标追踪是比通信更根本的短板。
- **指标可复现性可作为评测元标准**：用多判官 + 人工标注验证指标稳定性，应成为涉及 LLM 判官的新基准的标配做法。

## 10. 总体评价

AgentWorld 是一篇**问题意识明确、工程扎实、指标有创新**的多智能体协作评测工作。其最大贡献不在于某个模型的分数，而在于三点方法论主张：其一，用高层工具抽象层把"协作能力"与"低层操作能力"解耦；其二，用因果动作图上的祖先集占比（CCE）把"协作效率"变成一个可计算、可复现、有理论解释的标量；其三，用"随机出生点影响最小、移除文档影响最大"的消融，证明基准确实在测它声称要测的东西。

其主要可信度威胁集中在**实验覆盖的广度**上：基线与消融只在单一模型上做、部分对照仅 35 任务、附加模型划分不一致、算力成本不透明。因此，论文关于"模型间差异"的结论应谨慎采信，而关于"协作是当前基础模型共同短板""沟通存在最优区间""计划需可修订"等**定性结论**则较为稳健。

就定位而言，AgentWorld 更像是一份**诊断工具与问题宣言**，而非一份模型排行榜；它成功地把"多智能体协作到底难在哪里"从模糊直觉推进到了可测量的层面，其局限也正好指明了下一步该补的实验：跨模型的基线与消融、更大规模的任务子集、以及把共享上下文纳入设定的变体。
