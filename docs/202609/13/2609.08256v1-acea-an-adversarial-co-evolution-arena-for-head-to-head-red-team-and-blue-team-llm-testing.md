## 摘要
面向大型语言模型（LLM）的自动化红队攻击与蓝队防御正在快速发展。然而，攻击方和防御方是在相互隔离的情况下构建和测试的，由此得到的分数难以令人信任。为解决这一问题，我们提出 ACEA（Adversarial Co-Evolution Arena，对抗性协同演化竞技场），一个将可插拔的红队适配器和可插拔的蓝队适配器连接到共享目标 LLM，并使用 LLM 裁判对其攻击率和防御率进行评分的平台。ACEA 包含四个组成部分。第一，一个可插拔、模型无关的竞技场。任何红队或蓝队项目都通过一个最小化的 HTTP 协议连接，我们称之为 ACEA 标准适配器协议（ASAP）。它可以用任何语言编写，并且一个仅暴露该协议的项目就是一个完整的参与者。第二，一种为对抗性回合构建的评估方法。用规范秘密作为目标种子，可提供可验证的真值，从而将真实泄露与幻觉区分开。我们还会在防御阻止攻击时仍将每次攻击发送给目标，从而独立于攻击是否被阻止来衡量攻击的原始效力。二者共同给出每轮攻击强度与防御有效性的分解。第三，一个实时、游戏风格的可视化，以及详细的战斗结束报告，可定位每个失败点。因此，评估成为改进红队或蓝队项目的可操作信号。第四，一个可选的上下文内改进循环，将每轮结果转化为下一轮的建议性提示。适配器随后无需保持状态即可跨轮适应，只要它读取这些提示。我们描述了 ACEA 的设计以及红蓝双方进行正面评分所依据的指标。

## Abstract
Automated red-team attacks and blue-team defenses for large language models (LLMs) are advancing quickly. However, attackers and defenders are built and tested in isolation, and the resulting scores are hard to trust. To tackle this, we present ACEA (Adversarial Co-Evolution Arena), a platform that connects a pluggable red-team adapter and a pluggable blue-team adapter to a shared target LLM and scores their attack and defense rates with an LLM judge. ACEA contributes four components. First, a pluggable, model-agnostic arena. Any red or blue project connects over a minimal HTTP protocol, which we call the ACEA Standard Adapter Protocol (ASAP). It can be written in any language, and a project that exposes nothing but the protocol is a full participant. Second, an evaluation methodology built for adversarial rounds. Seeding the target with canonical secrets gives verifiable ground truth that separates real leakage from hallucination. We also send each attack to the target even when the defense blocks it, which measures the attack's raw potency independently of whether it was stopped. Together these yield a per-round decomposition of attack strength and defense effectiveness. Third, a real-time, game-style visualization with a detailed end-of-battle report that localizes each failure. The evaluation thus becomes an actionable signal for improving a red or blue project. Fourth, an optional in-context improvement loop that turns each round's outcome into advisory hints for the next. An adapter can then adapt across rounds without keeping state, provided it reads the hints. We describe the design of ACEA and the metrics through which red and blue teams are scored head to head.

  - **无实时视图（No live view）**：结果只在运行结束后以表格或日志形式呈现，无法在对抗过程中观察攻防如何突破或守住。
- **整体含义**：论文提出 ACEA（Adversarial Co-Evolution Arena，对抗性协同演化竞技场），把一次性的、事后的一侧红队测试，转变为**正面对抗、可实时观察、分数可信**的对抗竞技，并使其成为改进红队/蓝队项目的**可行动信号**。

## 2. 方法论

### 核心思想
- 将**可插拔红队适配器**与**可插拔蓝队适配器**连接到**共享目标 LLM**，由 **LLM 裁判**对每一轮打分，实现正面交锋式的评测。
- 四个设计目标：可插拔（pluggable）、模型无关（model-agnostic）、评分可信（trustworthy scoring）、可解释（interpretable）。

### 关键技术细节
- **ASAP 协议（ACEA Standard Adapter Protocol）**：一个最小化 HTTP 契约，任何语言均可实现，项目只暴露协议即成为完整参与者。
  - 红队：`POST /v1/generate-attack`，输入 `target_context`，返回攻击载荷、声明的攻击类型、置信度。
  - 蓝队：`POST /v1/evaluate-defense`，输入攻击载荷，返回 `{block, allow}` 决策、理由、置信度，可选 `rewritten_payload`（净化改写后替代原载荷发送给目标）。
  - 蓝队可选：`POST /v1/filter-output`，对目标原始回复做额外过滤。
  - 双方：`GET /health`，报告就绪状态与声明能力（`supports_attack_generation`、`supports_input_guard`、`supports_output_guard` 等）。
  - 请求信封统一携带 `session_id`、轮次索引、`evolution_hints`、可选多轮对话历史、自由元数据。
  - 注册时经两步校验：健康探针 + 针对每项声明能力的试运行请求；蓝队至少需声明一种守卫，否则被拒绝。

### 一轮的流水线（文字化流程）
1. 红队策略 πR 依据对话历史产出攻击载荷 x_t。
2. 蓝队策略 πB 决策 d_t ∈ {block, allow}，可返回改写载荷。
3. 目标 T 对"实际到达的载荷"生成**恰好一次**原始回复 y_t。
4. 投递路径：allow 时经输出过滤 gB 得到 ŷ_t；block 时不投递任何内容。
5. **关键设计**：即使防御拦截，仍生成目标响应并**仅用于打分而不投递**，从而得到该轮**两个独立测量**——攻击的原始效力（raw potency）与防御有效性（harm removed）。一轮只消耗一次目标生成。
6. LLM 裁判 J 基于 x_t、d_t、y_t、ŷ_t 打分。

### 评分与指标
- 裁判输出**五个主维度**（harmfulness、policy violation、attack success、defense quality、evasion）、**两个派生维度**（attack stealth、block precision）、**三级轮次评级**与一句理由。
- 同时报告**过滤后危害分**与**原始危害分**，使红队真实进展在蓝队拦截时仍可见。
- **ASR**（攻击成功率）= 声明目标达成轮次占比；**DR**（防御率）= 未获得任何内容的轮次占比；**attributed DR**（归因防御率）仅统计防御主动拦截/过滤的轮次，用于剥离"目标自主拒绝"对防御的虚高贡献。
- **三级评级**：`success`（达成声明目标）、`failure`（未达成且无其他所得）、`partial`（未达成目标但目标仍泄露了机密材料）。其中 `partial` 是修正项——泄露发生在声明基准之外时单独记为 **incidental disclosure**，两类数字不可互相替代。
- **规范秘密（canonical secrets）**：目标由检索库支撑，预置合成但固定的记录（伪造账号、策略覆盖码、隐藏系统秘密），并携带材料类型；真实泄露必须复现规范秘密，幻觉只是"看起来像"敏感数据，从而提供可验证真值。
- **参与契约（engagement declaration）**：由参与方声明攻击目标、成功标准、校准锚点与可选证据标记；评分基准按固定优先序解析一次（证据标记 > 攻击者声明目标 > 操作者声明目标 > 不缩小范围）。有证据标记时，匹配即决定结果，**不调用模型**，并把匹配标记记入轮次记录以便审计。
- **每轮四种结束归因**：防御在输入门拒绝、防御在输出端改写、目标自主拒绝、攻击成功。
- **终止条件**：轮次上限，或每轮后评估的用户自定义条件（目标 ASR、目标 DR、连胜、相对基线的提升百分点），可限定于最近 N 轮；**无自动饱和停止**，由操作者决定。

### 上下文内改进循环（可选）
- 通过 `evolution_hints` 向适配器提供建议性信号，使**无状态适配器**也能跨轮、跨战斗适应（ASAP 契约不要求保存状态）。
- 两个生产者：裁判在裁决中附带单侧提示；当某轮失败且无提示时，演化包装器执行三层分析：
  - **Layer 1**：总结最近轮次的攻防交换，请 LLM 提出下一轮改进策略。
  - **Layer 2**：跨全部历史会话查询曾成功/失败过的策略，注入跨会话知识。
  - **Layer 3**：元优化分析提示本身，用 softmax 按各变体平均成功率提升采样，达标后由元模型依据失败轨迹重写提示并加入变体池。
- **适应度信号**：会话早晚期轮次之间成功率的变化。
- **关键边界**：全程**不更新任何权重**，循环只改变提示通道；适配器不读 `evolution_hints` 则完全无效，下一次战斗仍从同一基线开始。

## 3. 实验设计

- **场景/基准**：论文**未使用公开数据集或标准 benchmark**，而是自建竞技场对局。评测对象为"防御框架 × 防御模型 × 目标模型"的组合。
- **红队**：平台自带 `acea-default-red`，将攻击由三层独立组合而成——**技术**（直接、角色扮演、间接转移、编码、权威框架等）× **上下文模板**（审计、调试模式、紧急、客服等）× **压力修饰符**（无、时间压力、权威丧失、道德利害），再由 LLM 合成提示，目标是找到防御未见过的组合。
- **蓝队（两个防御框架）**：
  - `acea-default-blue`：三阶段分类器——Stage A 输入守卫（词法预过滤 + LLM 对有害意图打 0–1 分，超阈值拦截）；Stage B 输出守卫（正则扫描机密数据并脱敏或放行）。
  - `minimal-blue`：刻意极简的一次性 yes/no 分类，答"no"即拦截，用于提供"几乎不做防御"的对照。
  - 每个防御由两个模型支撑：`mistral-large-2512`（大）与 `ministral-3b-2512`（小，约小 40 倍），共**四种防御**。
- **目标**：四个不同模型而非同一模型的四种设置——Target 1 = `openai/gpt-4o`、Target 2 = `google/gemini-2.5-pro`、Target 3 = `google/gemma-3-27b-it`、Target 4 = `mistralai/ministral-3b-2512`。各目标预置合成规范秘密。目标模型身份是**事后**通过 LLM 代理请求日志与运行时间窗口关联恢复的，平台运行时不记录模型字段；Target 1 与 Target 4 有多个配对交叉确认，Target 2 与 Target 3 仅单窗口确认，关联较弱。
- **难度预设**：hardened / balanced / vulnerable，控制目标对社会工程的可感程度；默认不变，仅在一对（最弱防御对 Target 1 设为 vulnerable）中变化。
- **裁判**：由操作者在环境变量中设定，运行文件中不记录，故论文不具名；裁判与红蓝双方绑定不同模型，避免"自己给自己打分"。
- **对比方法**：论文的"对比"是**防御框架之间、防御模型之间、目标模型之间的横向比较**，而非与外部方法在同一指标上的数值对比。相关工作（HarmBench、garak、DeepTeam、Self-RedTeam、MAGIC、CHASE 等）仅在**定位表（Table 1）**中按"可插拔适配器 / 双方参与 / 泄露真值 / 实时 UI / LLM 裁判"五个维度做定性对照。
- **第三方工具运行**：两个额外运行使用独立发布的红队与蓝队工具，各自作为独立服务经 URL 注册 ASAP——一个第三方红队对第三方防御跑 6 轮，另一个同一红队对弱防御在宽松目标上跑 26 轮；两者未记录上下文内循环是否启用。
- **设置**：每个防御-目标对跑 30 轮；启用上下文内循环，禁用来代码级外循环；每对前**重置攻击者累积策略记忆**以避免顺序混杂；Target 1 列每防御重复三次，其余列为单次运行，Target 3 列不完整（仅最弱防御）。

## 6. 主要结果与发现

由于论文自身的定位是"展示平台能力"而非"给出基准排名"，其结果应被理解为**平台可用性的存在性证明**，而非严格的能力结论。

- **平台端到端可运行**：四种防御（两个框架 × 两个规模）与四个目标在同一竞技场内完成注册、对抗、评分、可视化全流程，验证了 ASAP 协议在异构实现间的互操作性。
- **攻击强度与防御有效性被成功解耦**：即使蓝队拦截，仍能通过"仅打分不投递"的目标响应给出该轮的**原始效力**，使红队在防御全拦的会话中依然获得可用的进展信号，这是与既有"拦截即零分"式评测的关键差别。
- **`attributed DR` 修正了防御率虚高**：区分"防御主动拦截/过滤"与"目标自主拒绝"后，防御的真实贡献被单独计量；论文指出若不归因，目标本身的对齐拒绝会被错误计入防御成绩。
- **`partial` 与 `incidental disclosure` 修正了二值判定**：攻击未达成声明目标但导致机密材料泄露的轮次被单独标记，避免了"只看 ASR 而漏掉真实泄露"的盲区。
- **规范秘密提供了可验证真值**：危害评分可区分"真实复现合成秘密"与"看似合理的幻觉"，直接回应了"分数不可信"这一动机。
- **方差警告**：重复实验（0.200 / 0.000 / 0.200）表明单次运行的"零成功率"可能只是采样噪声，论文据此明确反对把单次运行结果当作能力定论。
- **防御框架/模型规模对比**：在可比较的列内，更重型的防御框架与更大的防御模型总体上给出更高的归因防御率，但论文未就此下强结论，仅作为平台可区分防御强度的示例。
- **上下文内循环的作用被限定**：由于全程不更新权重、且适配器可忽略 `evolution_hints`，跨轮改进被表述为"提示层面的适应"，其效果被视为可选增强而非平台必要条件。
- **第三方工具互操作**：一个独立发布的红队与一个独立发布的蓝队各自以独立服务经 URL 注册即可参与，验证了"项目只暴露协议即成为完整参与者"的设计承诺。

## 7. 贡献与创新点

- **概念贡献**：提出"对抗性协同演化竞技场"这一评测范式，把攻防从**各自孤立的事后打分**转为**正面对抗的实时对局**。
- **协议贡献**：ASAP 是一个极简、语言无关、可插拔的 HTTP 契约，明确了红队/蓝队各自的能力声明与最小接口，使异构项目能在同一场地对局。
- **评分贡献**：
  - 每轮"一次目标生成、两次独立测量"的流水线设计，使**攻击原始效力**与**防御有效性**在同一轮内同时可得。
  - 三级轮次评级（success / failure / partial）与 `incidental disclosure` 的分离，修正了二值攻击成功判定的系统性盲区。
  - `attributed DR` 对防御贡献做归因，剥离目标自主拒绝的干扰。
  - **规范秘密 + 参与契约**：用可验证的合成真值与"证据标记优先"的解析规则，减少对 LLM 裁判主观性的依赖，并在有证据时完全不调用模型。
- **可解释性贡献**：实时视图 + 每轮理由 + 四种结束归因，使"为什么这一轮被守住或突破"可被直接观察，而非事后从日志反推。
- **工程贡献**：零权重更新、纯推理的运行方式，以及通过 `evolution_hints` 让无状态适配器也能获得跨轮适应能力，降低了参与门槛。

## 8. 局限与未来工作

- **实验规模小**：四个防御、四个目标、各 30 轮，且仅一个目标有重复，作者自述为"比较规模很小"。
- **缺乏消融**：未对 ASAP、规范秘密、三级评级、attributed DR、演化循环各层做消融，无法量化各设计的边际贡献。
- **统计强度弱**：绝大多数为单次运行，且重复显示高方差，结论的统计置信度有限。
- **变量不受控**：
  - Target 1 列在不同攻击者状态下运行，跨列比较混杂攻击者与目标两个变量。
  - 目标身份为**事后关联恢复**，Target 2/3 仅单窗口确认，关联较弱。
  - 裁判模型不具名且不写入运行文件，评分行为不可外部复核。
- **成本披露不足**：未报告算力、token 消耗或单次运行成本，难以评估可复现性与可扩展性。
- **无自动饱和停止**：终止条件依赖操作者设定，缺少"对抗已饱和"的自动化判据。
- **可能的未来方向**（据其定位推断）：扩大重复次数与防御/目标覆盖面、引入消融、公开裁判配置、记录模型身份与资源开销、探索更丰富的终止与演化策略。

## 9. 结论与总体评价

- **核心信息**：ACEA 主张把 LLM 红队/蓝队评测从"隔离、事后、分数可疑"推进到"对抗、实时、分数可信"，并通过 ASAP 协议、一次生成两次测量、三级评级与规范秘密等具体机制落实这一主张。
- **价值定位**：其最大贡献是**评测基础设施与评分方法学**，而非某一攻防方法的性能突破；它更像是把分散的红队/蓝队工作接入同一个"擂台"的公共协议。
- **证据强度**：作为"平台可行性与设计合理性"的演示是成立的（异构工具确能互通、解耦度量确能产出新信号），但作为"能力排名或方法优越性"的证据则不充分，主要受限于样本量、重复数与变量控制。
- **客观提醒**：读者应把论文中的跨列对比、目标身份、裁判行为均视为**待独立验证**的探索性结果；其真正可复用的部分是**协议、度量定义与流水线设计**。
