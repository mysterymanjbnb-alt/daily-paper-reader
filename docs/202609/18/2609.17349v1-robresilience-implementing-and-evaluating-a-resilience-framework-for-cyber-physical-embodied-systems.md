## 摘要
在具身信息物理系统中，主动网络攻击不仅直接威胁数据，还威胁物理完整性和人身安全。尽管现有安全方法擅长检测，但缺乏运行时机制来判断扰动是否可容忍，或性能退化是否仍处于安全运行边界内。这一空白使自主系统易受“优雅失效瘫痪”影响：在攻击持续期间，它们无法区分安全的退化状态与灾难性危险。本文提出了 RobResilience，这是在 Webots 仿真环境中使用 PR2 机器人和 ROS2 对具身信息物理系统形式化韧性框架的实现。该框架在运行时基于由 IDS 置信度分数推导出的受攻陷设备集合，评估三个谓词：可容忍扰动（$δ$）、可容忍退化（$γ$）和缓解可行性（$μ$）。当韧性丧失时，该框架触发可用的缓解策略。我们通过八种攻击场景评估我们的实现，这些场景系统性地覆盖了谓词状态空间的所有可能组合，并改变攻击目标、退化速率和缓解可用性。结果证实，该实现的运行时行为与理论定义一致。

## Abstract
In embodied cyber-physical systems, active cyberattacks pose an immediate threat not just to data, but to physical integrity and human safety. While existing security approaches excel at detection, they lack the runtime mechanisms to determine whether a disruption is tolerable or if performance degradation remains within safe operational bounds. This gap leaves autonomous systems vulnerable to graceful failure paralysis, where they cannot distinguish between a safe, degraded state and a catastrophic hazard during an ongoing attack. This paper presents RobResilience, an implementation of a formal resilience framework for embodied cyber-physical systems in a Webots simulation environment, using a PR2 robot and ROS2. The framework evaluates three predicates at runtime: tolerable disruption ($δ$), tolerable degradation ($γ$), and mitigation feasibility ($μ$), over a compromised device set derived from IDS confidence scores. When resilience is lost, the framework triggers available mitigation strategies. We evaluate our implementation through eight attack scenarios that systematically cover all possible combinations of the predicate state space, varying attack targets, degradation rates, and mitigation availability. Results confirm that the runtime behaviour of the implementation is consistent with the theoretical definitions.

## 1. 核心问题与研究背景

- **研究对象**：具身信息物理系统（embodied CPS），即通过感知、决策与物理执行与环境及人类交互的自主系统（如机器人）。
- **核心痛点**：现有 CPS 安全工作集中于**攻击检测**（IDS、异常分析），而缺乏**运行时机制**来判断攻击造成的扰动是否可容忍、性能退化是否仍在安全边界内。
- **后果**：导致“优雅失效瘫痪”（graceful failure paralysis）——系统在攻击持续期间无法区分“安全退化状态”与“灾难性危险”，无法决定是继续执行、降级运行还是停机。
- **相关工作缺口**：
  - 入侵响应（如 Kholidy 的 Autonomous Response Controller）虽超越检测，但未以形式化谓词推理扰动/退化的可容忍性。
  - FDIR（故障检测、隔离与重构）假设故障模式已知、有界，不建模对抗意图、任务相关关键性及多设备协同退化的复合效应。
  - ROS2 运行时验证（Kirca 等）关注规范一致性而非对受损设备集的形式化谓词评估与自适应缓解。
- **本文定位**：实现并首次实证验证 Giaretta 提出的形式化韧性框架（arXiv:2606.16467），在 Webots + PR2 + ROS2 仿真环境中落地。

## 2. 方法论

### 2.1 形式化框架核心（第 3 节）

- **系统建模**：机器人 $R$ 由有限设备集 $D=\{d_1,\dots,d_n\}$ 构成，执行任务集 $T$，维持具身目标集 $G$。
- **关键性映射**：
  - 任务关键性 $\tau: D\times T \to \mathcal{C}$，$\mathcal{C}=\{0,1,2\}$（无/重要/必需）。
  - 目标关键性 $\varepsilon: D\times G \to \mathcal{C}$。
- **IDS 模型**：$I: D\to[0,1]$ 给出每台设备被攻陷的置信度。
- **设备级阈值**：$\kappa(d)$ 对关键设备（$\tau=2$ 或 $\varepsilon=2$）取更严格的 $\kappa_{crit}$，否则取 $\kappa_{base}$，且要求 $\kappa_{crit}<\kappa_{base}$（关键设备用更少证据即可判为受损）。
- **受损设备集**：$S=\{d\in D \mid I(d)\ge \kappa(d)\}$。
- **三个运行时谓词**：
  - **可容忍扰动 $\delta(S)$**：当且仅当 $S$ 中不含任何对活跃任务/目标为“必需”（$\tau=2$ 或 $\varepsilon=2$）的设备时为 1。
  - **可容忍退化 $\gamma(S)$**：$\psi(S)\ge\theta(S)$ 时为 1；$\psi:2^D\to[0,1]$ 为单调非增的退化函数，阈值 $\theta$ 在存在受损关键设备时取更严格的 $\theta_{crit}$，否则取 $\theta_{base}$（$\theta_{crit}>\theta_{base}$）。
  - **缓解可行性 $\mu(S)$**：存在 $M\subseteq S\cap D_m$ 使得 $\delta(S\setminus M)=1$ 且 $\gamma(S\setminus M)=1$ 时为 1（即存在可缓解子集使系统恢复可容忍）。
- **核心定理**：
  - 定理 1：系统韧性 $\iff (\delta(S)=1 \wedge \gamma(S)=1) \vee \mu(S)=1$。
  - 定理 2：三种姿态——① $\delta\wedge\gamma$ 成立则容忍扰动；② 否则若 $\mu=1$ 则通过缓解恢复（可能伴随性能退化）；③ 否则须进入安全状态或停机。

### 2.2 系统实现（第 5 节）

- **四大模块**（图 2）：
  1. **仿真环境**：Webots 承载 PR2 机器人物理动力学，Supervisor API 提供对执行器/传感器/场景对象的编程访问。
  2. **协调控制器**：PR2 Controller 作为中央编排者，加载实验配置（任务、目标、$\tau/\varepsilon$、$\kappa$、$\theta$、$\alpha$、基线时间、可缓解设备集），驱动任务循环（navigate to goal / pickup water bottle / 复合任务），每步调用韧性检查，失败即传播 HALTED；在 NOT RESILIENT 状态下完成的任务被降级为 HALTED。
  3. **攻击注入模块**：Attack Node（Webots 进程外的 ROS2 发布者，模拟外部攻击者）→ `active_attacks` 主题 → Subscriber Node → Attack Executor 对目标执行器施加物理效果。攻击类型符号化：STOP、UNDERSPEED、OVERSPEED、BACKWARD、GRIP_WEAK。关键工程难点：Webots 原 PR2 控制器会持续覆写电机指令从而“静默抵消”攻击效果，通过插入攻击感知检查让 Attack Executor 临时获得目标执行器的硬件所有权解决。
  4. **韧性评估模块**：IDS（每步评估，单次伯努利抽样比较 $\kappa(d)$，并记录已测设备避免重复评估抬高置信度）+ Resilience Manager（每步评估 $\delta,\gamma,\mu$，四态分类）+ Mitigation Feasibility（**条件调用**：仅当不具韧性且无待处理缓解时，对 $S\cap D_m$ 枚举幂集，寻找使 $\delta,\gamma$ 均恢复的子集 $M$；缓解带非瞬时延迟计时器）。
- **$\psi$ 函数实例化**：$\psi_{exp}(S)=e^{-(\alpha_{crit}\cdot k_{crit}+\alpha_{base}\cdot k_{base})}$，其中 $k_{crit}$、$k_{base}$ 分别为受损关键/非关键设备数；选择指数形式因其初期斜率更陡，能反映“首个关键设备失效”的不成比例影响。

## 3. 实验设计

- **环境与平台**：Webots 仿真，PR2 机器人；场景含机器人、两个作为导航目标的木箱、一张放有可抓取物体的桌子、一张空置物桌。**无任何物理硬件**。
- **任务**：navigate to goal、pickup water bottle、复合 navigate and pickup water bottle。
- **攻击方式**：通过 ROS2 `active_attacks` 主题发布符号化消息，指定目标设备与攻击类型；攻击激活后持续生效，直到缓解移除。
- **配置方式**：每个实验由 JSON 文件配置，参数可在实验间变化而无需修改代码；结果记录为 CSV。
- **评估指标**：任务结果（DONE/HALTED）、执行时间、相对基线的退化百分比、每步的受损集 $S$。
- **Benchmark 与对比**：**没有与其它方法对比**。评估基准是理论定义本身——通过八种场景系统性覆盖 $(\delta,\gamma,\mu)$ 状态空间的所有可实现组合（表 1、表 3），验证运行时行为是否与形式化定义一致。
- **八种场景概要**：
  - 场景 1（$\delta=1,\gamma=1$）：非关键双臂 STOP 攻击，低退化率，$\psi\approx0.93$，DONE。
  - 场景 2a（$\delta=1,\gamma=0,\mu=0$）：提高退化率至 $\alpha_{base}=0.20$，$\psi$ 跌破 $\theta_{base}$ 至 0.67，HALTED。
  - 场景 2b（$\delta=1,\gamma:0\to1,\mu=1$）：同 2a 但启用缓解，中和 left_arm 后 $\psi$ 回升至 0.81，DONE。
  - 场景 3a（$\delta=0$，无缓解）：关键设备 left_wheels 被 STOP，$\delta$ 永久为 0，约 103 s 时 HALTED。
  - 场景 3b（$\delta:0\to1$，全覆盖缓解）：48.8 s 基线内发生 4 次攻击–恢复循环，但任务仍为 HALTED。
  - 场景 3c（$\delta=0,\gamma=1,\mu=0$）：温和退化率使 $\psi\approx0.86$ 高于 $\theta_{crit}$，证明 $\delta=0$ 不蕴含 $\gamma=0$；但因关键设备未恢复，任务仍 HALTED。
  - 场景 4a（$\delta=0,\gamma=0,\mu=0$）：两波攻击（left_wheels 关键 + left_arm 非关键）使 $\psi\approx0.7$ 低于 $\theta_{crit}$，HALTED，比基线提前 27.0 s 停止。
  - 场景 4b（$\delta:0\to1,\gamma:0\to1,\mu=1$）：同 4a 但缓解 left_wheels，双谓词同时恢复，DONE，执行时间增加 1.8 s，退化 9.0%。

## 6. 主要结论与发现

- **结论一：关键性门控 $\delta$ 按规范工作**。所有仅攻击非关键设备（$\tau\le1$）的场景（1、2a、2b）中 $\delta$ 始终为 1；任何攻击 $\tau=2$ 设备的场景立即导致 $\delta=0$，与定义 5、6 一致。
- **结论二：缓解在所有被评估的谓词组合中正确恢复韧性**：
  - 场景 2b：仅作用于 $\gamma$（$0\to1$），$\delta$ 不受影响。
  - 场景 3b：仅恢复 $\delta$（$0\to1$），而 $\gamma$ 从未被违反。
  - 场景 4b：同时恢复 $\delta$ 与 $\gamma$，是唯一“双失败系统被完全恢复”的案例。
  - 三者共同验证了缓解循环按定义 8 遍历谓词空间。
- **结论三：$\delta$ 与 $\gamma$ 独立评估、无混淆**。场景 3c 中 $\delta=0$ 且 $\gamma=1$ 持续存在，系统处于“受扰但可容忍的退化状态”——说明丢失关键组件并不自动意味着性能不可接受；但依据形式化韧性定义，未恢复的关键设备仍触发 HALTED。
- **结论四：受损集 $S$ 的累积组成是决定性因素**。单个非关键设备叠加到已退化的关键设备上，若退化率足够高，可将 $\psi$ 推过基线阈值。这意味着**系统的韧性边界不是硬件的静态属性**，而取决于当前参数配置与每步评估时 $S$ 的动态内容，对任务规划具有实际意义。

## 7. 优点

- **首次实证验证**：将抽象的谓词语义（$\delta,\gamma,\mu$）落地为可运行的 ROS2/Webots 软件模块，并覆盖全部可实现谓词状态组合，填补了“检测强、运行时韧性推理弱”的空白。
- **理论一致性导向的评估设计**：以“可实现的 $(\delta,\gamma,\mu)$ 组合全覆盖”为场景构造原则，比随机案例选取更具系统性与可验证性。
- **配置驱动的架构**：所有关键参数（$\tau/\varepsilon$、$\kappa$、$\theta$、$\alpha$、可缓解设备集）经 JSON 注入，无需改代码即可变更实验条件，便于复现与扩展。
- **解决了真实的工程陷阱**：识别并修复了 Webots PR2 控制器持续覆写电机指令导致攻击效果被静默抵消的问题，通过临时硬件所有权机制保证攻击可见。
- **诚实的局限披露**：作者主动指出 $\kappa=0$ 违反定义 4 的严格不等式、单次运行缺乏统计、符号化攻击非真实漏洞利用等，并给出具体的后续验证建议。
- **可复现性**：提供完整开源实现，实验为纯仿真、无人类受试者，数据与配置公开。

  - 无消融与参数敏感性分析（如 $\kappa$、$\alpha$、$\theta$ 的连续变化对谓词判定的影响）。
  - 无与现有入侵响应、FDIR、运行时验证方法的横向对比。
- **评估保真度**：
  - **IDS 被人为旁路**：所有场景设 $\kappa_{crit}=\kappa_{base}=0$，保证任何被攻击设备必进入 $S$，这违反定义 4 要求的 $\kappa_{crit}<\kappa_{base}$，也消除了检测不确定性——作者认为这是最紧迫需要解决的简化。
  - **攻击是符号化消息注入**，而非真实的 ROS2 中间件级漏洞利用，攻击的真实可行性与副作用未验证。
  - **缓解被建模为确定性且完全解决攻击**，不反映现实中部分缓解、缓解失败或缓解引入新副作用的情形。
- **应用限制**：
  - 仅在 Webots 仿真中测试，**未部署到物理机器人**，无法暴露真实系统的时间约束、传感噪声、通信抖动等实时性问题。
  - 参数（阈值与关键性映射）是预先给定的，而非学习或标定得到；作者建议未来用机器学习从仿真标定并 sim-to-real 迁移。
  - 攻击者模型为“具有部分系统知识的外部者”，且假设 IDS

- **攻击者模型为“具有部分系统知识的外部者”**，即攻击者能通过 ROS2 主题注入影响特定执行器，但未被建模为自适应对手——不会根据系统响应调整攻击策略、不会尝试规避 IDS 或伪造合法指令、也不具备内部威胁能力。论文假设攻击一旦注入便持续作用于目标设备直至被缓解清除，未考虑间歇性攻击、多阶段隐蔽攻击或协同攻击。
- **关键性映射与阈值是静态先验**：$\tau$、$\varepsilon$、$\theta$、$\alpha$、$\kappa$ 均由配置人工设定，而非从任务执行数据中在线估计或自适应调整。当任务阶段切换（如从导航切换到抓取）导致设备关键性发生变化时，框架缺乏任务阶段感知的重新映射机制。
- **缓解空间受限于预定义可缓解设备集 $D_m$**：缓解可行性 $\mu$ 仅在 $S\cap D_m$ 上枚举，无法发现需要跨设备重构、任务重规划或降级执行策略的非常规缓解手段；缓解动作本身（中和攻击）被理想化为无副作用。

## 9. 未来工作方向

论文（结合作者自述的局限）指向以下延伸路径：

- **恢复 IDS 的现实性**：在后续实验中令 $\kappa_{crit}<\kappa_{base}$ 严格成立，引入真实或半真实的入侵检测模型（含假阳性/假阴性），评估检测噪声如何传播到 $\delta/\gamma/\mu$ 的判定与最终姿态选择。
- **统计化评估**：每场景多次重复运行，报告 $\psi(t)$ 轨迹、状态转移次数与任务结果的均值/方差，并进行参数敏感性扫描（$\kappa$、$\alpha$、$\theta$、$\alpha_{crit}$ vs $\alpha_{base}$）。
- **真实攻击与物理部署**：用真实的 ROS2 漏洞利用替代符号化消息注入，并将系统迁移到物理机器人平台，暴露实时性、传感噪声与通信抖动问题。
- **参数标定与学习**：以仿真数据标定关键性映射与阈值，并探索 sim-to-real 迁移。
- **攻击者与缓解模型的增强**：建模自适应/隐蔽攻击者，支持部分缓解、缓解失败与缓解副作用，并扩展 $D_m$ 之外的缓解策略空间。
- **与现有方法对比**：在统一 benchmark 下与入侵响应控制器、FDIR、ROS2 运行时验证方案进行横向对照。

## 10. 总体评价

- **贡献定位清晰**：本文是一篇**“形式化框架的首个系统实现与实证验证”**型工作，价值不在于提出新理论，而在于把 Giaretta 的抽象谓词语义转化为可运行的 ROS2/Webots 模块，并证明其运行时行为与形式定义逐条一致。这类“理论落地”工作在具身 CPS 安全领域仍属稀缺。
- **评估哲学合理但工程完备性不足**：以“覆盖全部可实现 $(\delta,\gamma,\mu)$ 组合”为场景设计原则，逻辑上具有完备性，优于随机案例选取；但单次运行、无消融、无对照，使结论停留在“定性一致”层面，尚不足以支撑“框架在实践中有效”的强主张。
- **最大的内在张力在于实验隔离与形式约束的冲突**：为干净地验证谓词逻辑，作者将 IDS 旁路（$\kappa=0$），这虽隔离了检测不确定性，却同时违反了定义 4 的 $\kappa_{crit}<\kappa_{base}$ 约束，使“检测—判定—缓解”闭环中的检测环节事实上缺席。因此本文验证的更接近“给定完美受损集 $S$ 时的韧性推理正确性”，而非端到端的运行时韧性。
- **工程细节的诚实披露是加分项**：如 Webots 控制器覆写电机指令、攻击感知的硬件所有权临时转移、缓解的非瞬时延迟计时器等实现陷阱的说明，对后续复现者具有实际参考价值；开源实现进一步降低了复现门槛。
- **适用性判断**：当前版本更适合作为**概念验证与基准脚手架**，为后续引入真实 IDS、多次统计评估、参数学习与物理部署提供可扩展的实验床，而非可直接部署的机器人安全组件。其核心洞见——韧性边界随受损集 $S$ 的动态组成与参数配置而移动，而非硬件的静态属性——对任务规划与运行时安全设计具有启发意义。
