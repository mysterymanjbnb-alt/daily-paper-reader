## 摘要
多智能体（MA）系统能有效解决需要规划、工具使用以及综合多源证据的复杂任务。现有系统通常采用分层管理者-工作者（HMW）或基于路由器的消息传递（RMP）结构作为其通信协议。然而，这些设计限制了智能体的自主性：工作者智能体无法直接咨询特定的“同伴”，而错误路由的消息可能传播错误。受计算机系统中总线架构的启发，我们提出 BusMA，一种通信框架，允许任意智能体通过共享通道（即总线）寻址其他智能体。它由智能体注册、消息路由和共享内存管理组件构成。工作者智能体各自配备工具，拥有自己的局部记忆，并能通过发布带有特定意图的共享消息来进行推理、行动（工具使用）和通信。我们引入四种意图：讨论、质疑、指导和请求解释，以支持智能体之间细粒度的通信。Chair 智能体监控共享内存以协调交互并促进工作者之间的收敛。为评估 BusMA 的有效性，我们使用两个前沿 LLM 在涵盖视觉推理、数学推理和知识检索的 13 项任务上进行了大量实验，结果表明 BusMA 持续优于最先进的 HMW 和 RMP 方法。

## Abstract
Multi-Agent (MA) systems are effective at solving complex tasks that demand planning, tool use, and the synthesis of evidence from multiple sources. Existing systems typically adopt Hierarchical Manager-Worker (HMW) or Router-based Message Passing (RMP) structures as their communication protocol. However, these designs restrict agent autonomy: Worker agents cannot directly consult specific "peers", and misrouted messages can propagate errors. Inspired by bus architectures in computer systems, we propose BusMA, a communication framework that allows any agent to address other agents through a shared channel, i.e., the Bus. It consists of agent registration, message routing, and shared memory management components. Worker agents, each equipped with tools, have their own local memory and can reason, act (tool usage), and communicate by posting shared messages with specific intents. We introduce four intents: discussion, challenge, guidance, and request for explanation, which support fine-grained communication among agents. A Chair agent monitors the shared memory to coordinate interactions and facilitate convergence among Workers. To evaluate the effectiveness of BusMA, we conduct extensive experiments with two frontier LLMs across 13 tasks spanning visual reasoning, mathematical reasoning, and knowledge retrieval demonstrate that BusMA consistently outperforms state-of-the-art HMW and RMP methods.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：基于大语言模型（LLM）的多智能体（MA）系统在数学推理、知识检索等复杂任务上表现出色，其效果高度依赖智能体之间的通信质量与协调机制。
- **现有范式及其缺陷**：主流通信协议分为两类——
  - **HMW（分层管理者-工作者）**：由 Manager 分配任务、收集结果；
  - **RMP（基于路由器的消息传递）**：由 Router 中介所有消息交换。
- **两大核心问题**：
  - **自主性受限**：Worker 只是被动执行者，无法主动与特定"同伴"发起通信，难以进行批判或纠错；
  - **错误传播**：Manager/Router 成为"认知瓶颈"，所有信息被迫流经单一枢纽，误路由消息会放大错误。
- **整体含义**：受计算机**总线架构**（Patterson & Hennessy, 2017）和分布式系统 **Information Bus**（Oki et al., 1993）启发，论文提出 BusMA——让任意智能体通过共享通道（Bus）直接寻址其他智能体，从而在保持自主性的同时实现按需协作。

## 2. 方法论

### 2.1 核心思想
- 以**共享总线**替代中心化枢纽：智能体无需被动等待任务分配或路由中介，可直接向指定同伴发消息。
- 采用**按需协作（on-demand collaboration）**：仅共享必要信息，智能体各自的推理保持本地化。

### 2.2 三大组件
- **Worker Agent**：配备工具集、维护本地记忆，可推理、行动（工具调用）、通信；遵循 ReAct 循环（Reason–Act–Call）。
- **Chair Agent**：Worker 的特例，禁用 Act（工具集为空），作为 *primus inter pares*（平等者中的首席），监控共享内存、协调交互、促进收敛。
- **Communication Bus**：含三个模块——**Agent Registration**（注册角色与唯一地址）、**Message Routing**（消息路由）、**Shared Memory Management**（共享内存/历史管理）。

### 2.3 关键技术细节
- **本地记忆更新**：
  $$K_i(t+1) = K_i(t) \cup \{r^{priv}_{i,t}, o_t\}$$
  即每轮迭代将私有推理 $r^{priv}_{i,t}$ 与工具输出 $o_t$ 累积到本地记忆。
- **消息路由增强**：
  $$\hat{m}_{i\to j}(s) = (m_{i\to j},\ ID,\ s,\ \alpha_i)$$
  Bus 解析消息、校验接收者、附上唯一 ID、路由索引 $s$ 与发送者身份，推入接收者 FIFO 队列 $Q_j$；接收者按到达顺序消费消息。
- **四种通信意图**：
  - *Discussion*（双向信息交换）
  - *Challenge*（质疑他人中间结果，触发再审视而非被动错误传播）
  - *Guidance*（提供专业指导）
  - *Request for Explanation*（澄清模糊上下文）
- **迭代终止条件**：Worker 选择 Call，或达到最大迭代上限 $T_{max}$（后者向激活它的智能体发送失败消息）。
- **Chair 双模式**：协调模式 $P^{COOR}_{chair}$（识别首个联系对象、监控共享内存、识别未解决分歧/缺失证据、发出后续请求）与提交模式 $P^{SUBM}_{chair}$（单步生成最终答案）。
- **三级信息粒度**：
  - 私有推理 $r^{priv}_{i,t}$（留在本地）
  - 共享消息 $m_{i\to j}$（仅公开可操作内容）
  - 全局视图 $r^{glob}_{chair,t}$（Chair 访问共享历史 $H$ 后更新）

## 3. 实验设计

## 6. 主要结论与发现

- **整体性能**：BusMA 平均准确率最佳，DeepSeek-V3 上超最佳基线（OctoTools）**+4.8%**，Gemini-2.5-Flash 上 **+2.5%**。
- **任务差异性**：
  - **数学推理与知识检索**（Game of 24、Omni-MATH、MMLU-Pro、HotpotQA 等）增益显著，因中间步骤可被同伴验证，通信意图助力迭代纠错；
  - **视觉推理**增益较小，准确率主要受限于基座模型的多模态感知能力，额外通信甚至可能引入噪声。
- **GAIA**：总体 **48.5%**，超 OpenDeepResearch **+4.3%**；Level 2、Level 3 上领先更大（+4.6%、+7.7%），说明在复杂协作任务上优势更明显。
- **基座模型越弱增益越大**：DeepSeek-V3 上的相对提升高于 Gemini-2.5-Flash。
- **消融结论**：退化到 HMW（`w/ Manager`）导致 4.5%–7.0% 下降，证明结构化通信意图对抑制错误传播的价值；替换 Worker 实现后性能仍接近原版且远超 SmolAgents 基线（+4.0%–10.0%），说明增益主要来自通信机制而非特定 Worker 实现。
- **机制洞察**：细粒度角色划分**并非普遍有益**（如 CLEVR-Math 中简单减法被委派给 Code Agent，徒增开销）；Worker 异质性可能导致错误无法被交叉验证而悄然传播。

## 7. 优点

- **架构创新**：将计算机总线思想迁移到 LLM 多智能体通信，思路新颖且类比自然。
- **通信语义丰富**：四种通信意图（讨论、质疑、指导、请求解释）突破了传统"分配-返回"的二元通信空间，尤其 *Challenge* 支持主动再审视。
- **解耦设计**：消息路由与任务综合解耦，Worker 间点对点通信完全绕过 Chair，缓解中心瓶颈。
- **信息分层**：私有推理/共享消息/全局视图三级粒度，既减少通信开销又缓解长上下文压力。
- **实验扎实**：跨 13 项任务、两种主干模型、多种基线与消融对照，并配有定性轨迹与错误分析，结论可信度较高。
- **公平性考量**：统一视觉工具路由映射、单智能体串行激活配置、复用相同 Browser Agent 以隔离变量。

## 8. 不足与局限

- **不提升基座能力**：BusMA 仅改善协作，不增强 LLM 本身；在感知为瓶颈的视觉任务上收益有限甚至回退。
- **错误传播仍未根治**：当外部工具返回错误或不完整证据时，Worker 的误导性消息会偏置 Chair 的综合判断（如 GPQA 失败案例中三异丙基硼酸对称性判断错误）。
- **工具异质性风险**：专用工具仅分配给特定智能体，其他智能体无法交叉验证其输出，错误可无阻碍传播。
- **规模受限**：实验仅涉及 2–3 个智能体的协作；共享内存随消息数线性增长，智能体增多时 Chair 需综合更长的通信历史，产生"总线争用"。
- **缺乏硬件总线级机制**：阻塞应答、仲裁协议、优先级调度等均未实现，大规模同步能力不足。
- **未来方向**：引入置信度估计与冲突检测的仲裁机制，并在 WebWalkerQA 等需协调更多智能体、更长推理链的任务上评估扩展性。
- **实验层面**：未报告统计显著性、多次运行方差；每数据集样本量固定为 200；消融任务数偏少。
