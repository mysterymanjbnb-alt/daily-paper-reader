## 摘要
同态加密（HE）已成为隐私保护机器学习（PPML）中一种有前景的方法，能够直接在加密数据上进行计算。在基于 HE 的 PPML 中，客户端将加密输入提交给服务器，服务器在无法访问底层明文的情况下评估诸如大语言模型（LLM）等模型。然而，我们发现了该场景中的一个关键安全漏洞：HE-LLM 推理易受提交对抗性提示（例如越狱攻击）的恶意客户端影响。保护良性客户端的机密性同样使服务器无法检查传入的提示或生成的响应，使得对抗性尝试难以被检测或阻止，并可能使成功攻击对服务器完全不可见。为解决该漏洞，我们提出 HE-Guardrail，一个完全在加密数据上评估护栏机制，并以同态方式控制目标模型响应是否返回给客户端的框架。我们使用三个代表性护栏——Llama Guard、JBShield 和 GradSafe——对 HE-Guardrail 进行实例化。我们的结果表明，HE-Guardrail 在加密域中高度复现了相应明文护栏的决策，并呈现出不同的安全性-效率-效用权衡。

## Abstract
Homomorphic encryption (HE) has emerged as a promising approach to privacy-preserving machine learning (PPML), enabling computation directly over encrypted data. In HE-based PPML, a client submits an encrypted input to the server, which evaluates models such as large language models (LLMs) without access to the underlying plaintext. However, we identify a critical security vulnerability in this setting: HE-LLM inference is vulnerable to malicious clients that submit adversarial prompts, such as jailbreak attacks. The same confidentiality that protects benign clients also prevents the server from inspecting incoming prompts or generated responses, making adversarial attempts difficult to detect or block and potentially allowing successful attacks to remain entirely invisible to the server. To address this vulnerability, we propose HE-Guardrail, a framework that evaluates guardrail mechanisms entirely over encrypted data and homomorphically controls whether the target-model response is returned to the client. We instantiate HE-Guardrail with three representative guardrails - Llama Guard, JBShield, and GradSafe. Our results show that HE-Guardrail closely reproduces the decisions of the corresponding plaintext guardrails in the encrypted domain, with distinct security-efficiency-utility trade-offs.

## 2. 方法论：核心思想、关键技术与算法流程

### 2.1 核心思想
- 提出 **HE-Guardrail** 框架：**完全在加密数据上评估护栏**，并**同态地控制目标模型响应是否返回给客户端**。
- 服务器同时持有目标 LLM 与护栏模型，客户端持有私钥；服务器对加密提示或加密内部信号进行评估，得到加密的二元判决 $g$（1=接受，0=拒绝），再以同态算术方式对输出进行门控。
- 框架排除后处理护栏（需等生成完成，会直接增加端到端延迟），仅实例化 **1 个预处理护栏 + 2 个处理中护栏**，以避开目标模型的关键路径。

### 2.2 同态门控与噪声淹没（关键技术细节）
- **门控生成**：由于 CKKS 不支持原生比较，判决通过符号函数多项式近似实现：
  $$g = \frac{1 + \mathrm{sgn}_{\text{poly}}(p - \delta)}{2}$$
  其中 $p$ 为加密检测分数，$\delta$ 为阈值，$\mathrm{sgn}_{\text{poly}}$ 采用 Lee 等人的极小化复合多项式方法（分量度数 15、27、29）。
- **响应门控公式**（逐 token 插值）：
  $$Z_t(g) = g\,Y_t + (1-g)\,R_t + \epsilon_t(g)$$
  $Y_t$ 为目标模型 token 的 one-hot 表示，$R_t$ 为预定义拒绝响应（如"Sorry, I cannot assist…"）的 one-hot 表示，不足位置用 EOS 填充。
- **门控噪声淹没（Gated Noise Flooding）**：由于近似误差或 CKKS 噪声，$g$ 未必严格为 0/1，被拒绝请求仍可能残留被抑制 token 的信息（例如 $g=0.01$ 时残差 0.01 会暴露坐标）。为此引入：
  $$\epsilon_t(g) = (1-g)\,\xi_t$$
  $\xi_t$ 为服务器每次新采样的私密小噪声向量，仅在拒绝（$g\approx0$）时激活，使残差被更大噪声淹没，客户端无法恢复被抑制的目标响应。

### 2.3 三个护栏实例

**（1）预处理护栏：Llama Guard 3-8B**
- 在密文域评估加密输入提示，通过比较 safe/unsafe 两个 token 的 logits 得到加密接受边界：
  $$m_{LG} = z_{LG}[t_{safe}] - z_{LG}[t_{unsafe}],\quad g_{LG} = \frac{1+\mathrm{sgn}_{HE}(m_{LG})}{2}$$
- 无需对词表做 Softmax 或生成文本解释（Softmax 保序，等价于比较概率）。
- **多模型服务（Multi-Model Serving）**：扩展 MOAI 的交错批处理，为每个交错 lane 分配不同模型权重，使目标模型与护栏模型在**同一组密文**中并行评估，避免密文内存翻倍（代价是批容量减半：16 lane → 8 个受护请求）。

**（2）处理中护栏：JBShield-D**
- 利用目标模型 prefill 产生的加密隐藏表示 $h(x)$（取第 32 层最后一 token，4096 维）。
- 离线阶段用 rank-one SVD 从校准提示中提取 toxic 概念向量 $s_t$ 与 jailbreak 概念向量 $s_j$，并预归一化。
- 在线阶段：计算 $c_t = h(x)-\mu_b$、$c_j = h(x)-\mu_h$，通过同态余弦相似度 $\sigma_k = \langle c_k, \hat{s}_k\rangle / \sqrt{\sum_i c_k[i]^2}$ 与阈值比较（$\theta_t=0.037$，$\theta_j=0$），其中逆平方根用 Goldschmidt 迭代实现。
- **SVD 简化**：因单行差矩阵的右奇异方向即归一化差向量，在线 SVD 被消去，直接使用 $c_k$。
- 最终接受门控：$g_{JB} = 1 - d_t d_j$（两概念同时激活才判为越狱）。

**（3）处理中护栏：GradSafe-Zero**
- 利用安全关键参数切片（注意力/MLP 投影权重 $W_q,W_k,W_v,W_o,W_{gate},W_{up},W_{down}$）的梯度方向。
- 离线阶段：计算不安全参考梯度 $r_j$ 与相似度差 $\Delta_j$，保留 $\Delta_j > \lambda_{gap}=1$ 的切片集合 $J^\star$，并预归一化 $\hat{r}_j$。
- **仅梯度 HE 反向传播**：GradSafe 只需梯度提取、无需权重更新，因此比 HE 训练更可行；反向传播从 prefill logits 初始化 $\partial L/\partial z = p - e_{r_c}$，独立于后续自回归解码。
- **低层检查点（Low-Level Checkpointing）**：前向用完的密文立即降层存储，反向需要时 bootstrap 再层对齐，用额外 bootstrap 换显著内存节省。
- **检查点非线性导数复用**：Softmax 反向 $\bar{a} = p \odot (\bar{p} - \langle \bar{p}, p\rangle 1)$；RMSNorm 复用前向逆 RMS $r$；SiLU 复用 sigmoid 输出 $s$，均避免重复评估昂贵非线性。
- **流式梯度相似度**：每个安全关键梯度切片立即与参考比对、累加进 running score 后丢弃，避免存储全部梯度；最终 $s_{GS}$ 与 0.25 阈值经 $\mathrm{sgn}_{HE}$ 得到门控。

## 6. 主要结论与发现

- **加密域高度复现明文决策**：所有评估提示中，加密护栏与明文护栏决策一致率达 **99.7%**，说明多项式近似与 HE 数值误差几乎不改变安全判决。
- **ASR 表现（宏平均）**：无防御 11.0% → Llama Guard **7.1%** → JBShield **11.0%** → GradSafe **10.8%**。
  - Llama Guard 在每一类攻击上都有下降，GCG 从 13.0% 降至 2.0%，IJP 从 14.3% 降至 9.6%；但 ActorAttack 几乎无变化（16.3%→16.2%）。
  - JBShield 在所有六类上与无防御持平，GradSafe 最多相差 1.0 个百分点。
- **PGR（通过护栏率）**：Llama Guard 38.7%、JBShield 77.0%、GradSafe 62.3%；三者对 ActorAttack 均放行 98.5–99.8%。
- **内存开销**：Llama Guard 独立执行约 +140 GiB（占第二张 GPU）；多模型服务约 **0 额外密文内存**（但批容量减半）；JBShield 约 +5 GiB；GradSafe 约 +110 GiB。
- **延迟开销**：在双 GPU 配置下，三种护栏均与目标解码并发执行，$\Delta\tau = 0$，**不增加关键路径延迟**（200 token 自回归解码主导端到端时间）。
- **良性效用**：FPR 分别为 Llama Guard 1.83%（33/1805）、JBShield 0.06%（1/1805）、GradSafe 0.17%（3/1805）；Llama Guard 拒绝率较高，在 OR-Bench 上尤其明显（2.20%）。
- **核心权衡**：Llama Guard 安全性最强但误拒率最高；JBShield/GradSafe 误拒率极低但几乎不降低 ASR，反映其检测规则更宽松而非更好。
- **多轮攻击仍是重大挑战**：即使会话级护栏对多轮攻击（尤其是 X-Teaming 等自适应攻击）仍脆弱，且 HE 环境下服务器无法直接检查明文对话历史，缺乏人工干预兜底。

## 7. 优点（方法或实验设计亮点）

- **威胁模型创新**：首次明确指出 HE-LLM 推理中"恶意客户端"这一被忽视的攻击面，挑战了 HE-PPML 领域默认客户端良性的传统假设。
- **通用框架性**：HE-Guardrail 是通用框架，可容纳预处理/处理中不同阶段的护栏，并抽象为"加密分数 + 阈值 + 符号近似"的统一判决形式。
- **门控噪声淹没设计精巧**：$\epsilon_t(g)=(1-g)\xi_t$ 针对近似误差与 CKKS 噪声导致的残差泄漏，防止恶意客户端从被门控输出中反推被抑制响应，是框架安全性的关键补充。
- **白盒限制在 HE 场景下被自然消解**：处理中护栏在明文部署中受限于需白盒访问，而在 HE 推理中服务器本就持有模型结构与加密内部信号，使这一方向重新变得可行。
- **工程贡献实用**：
  - 多模型服务（扩展交错批处理）实现目标与护栏模型共享密文，零额外密文内存；
  - 仅梯度 HE 反向传播 + 低层检查点 + 非线性导数复用 + 流式梯度相似度，系统性降低 GradSafe 的内存压力；
  - 消去在线 SVD 的数学简化。
- **评估体系完整**：采用 SEU 框架，兼顾安全、效率、效用，并验证加密决策与明文决策的一致性，避免将 HE 数值退化误判为检测规则效果。

## 8. 不足与局限

- **防御效果有限**：JBShield 与 GradSafe 的平均 ASR 与无防御几乎相同（11.0% vs 11.0%、10.8% vs 11.0%），实际防护增益主要来自 Llama Guard，且其对多轮 ActorAttack 几乎无效。
- **多轮攻击未解决**：作者自述多轮越狱是当前护栏机制的重要局限，HE 环境下无法进行明文级干预（人工审核、对话历史检查），需未来专门设计可加密推理对话历史的护栏。
- **算力与内存代价高**：GradSafe 需约 110 GiB 额外内存，Llama Guard 独立执行需约 140 GiB；多模型服务虽省内存但批
