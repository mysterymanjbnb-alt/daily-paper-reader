## 摘要
使用模型上下文协议（MCP）的智能体依赖语义匹配从第三方服务器中选择工具，从而通过攻击者控制的元数据和输出暴露出语义供应链风险。我们提出 A2M（Attraction-to-Manipulation），一个用于劫持 MCP 智能体的两阶段黑盒框架。Attraction 阶段优化工具元数据以提高调用概率；Manipulation 阶段利用执行轨迹来改进对抗性工具返回值，引导智能体走向攻击者期望的结果。在 LiveMCPBench 上，于 GLM-4.6 上优化和评估的直接攻击在四个场景中实现了 93.6% 的宏平均恶意工具调用率，在认知拒绝服务下将加权 token 成本提高到良性基线的 32.4 倍，并在信息外泄、环境完整性破坏和推理脱轨中达到 74.4% 的平均攻击成功率。无需重新优化即可迁移到另外四个模型，相应的宏平均值分别为 63.6%、2.7 倍和 24.5%。这些发现促使人们在 MCP 生态系统中加强工具审查和运行时隔离。代码公开于 https://github.com/Lilaizhen/A2M。

## Abstract
Agents using the Model Context Protocol (MCP) rely on semantic matching to select tools from third-party servers, exposing a semantic supply-chain risk through attacker-controlled metadata and outputs. We introduce A2M (Attraction-to-Manipulation), a two-stage black-box framework for hijacking MCP agents. The Attraction phase optimizes tool metadata to increase invocation probability; the Manipulation phase uses execution traces to refine adversarial tool returns that steer agents toward attacker-desired outcomes. On LiveMCPBench, direct attacks optimized and evaluated on GLM-4.6 achieve a macro-average malicious tool invocation rate of 93.6% across four scenarios, increase weighted token costs to 32.4$\times$ the benign baseline under Cognitive Denial of Service, and attain a mean attack success rate of 74.4% across Information Exfiltration, Environment Integrity Compromise, and Reasoning Derailment. Transfer to four other models without re-optimization yields corresponding macro-averages of 63.6%, 2.7$\times$, and 24.5%. These findings motivate stronger tool vetting and runtime isolation in MCP ecosystems. Code is publicly available at https://github.com/Lilaizhen/A2M.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM 正从对话系统演化为可调用外部工具的自主智能体，MCP（Model Context Protocol）提供统一接口集成异构数据源与第三方服务，显著扩展了智能体能力边界。
- **核心风险**：MCP 智能体依赖**语义匹配**（工具名称、描述等元数据）从第三方工具注册表中选择工具，同时将工具返回值视为**可信的环境反馈**而非不可信文本输入。这构成了一个**语义供应链风险**——攻击者可通过控制元数据与输出来劫持智能体。
- **与已有威胁模型的区别**：现有 LLM 安全研究多聚焦于用户到智能体的攻击（越狱、直接提示注入），其中恶意用户显式操纵模型。而在 MCP 场景中，**用户与智能体均可能良性**，攻击行为通过被信任的工具接口传递，不同于传统间接提示注入。
- **攻击成功的两个耦合目标**：
  - **Attraction（吸引）**：提高恶意工具在竞争中胜出的调用概率。
  - **Manipulation（操纵）**：在调用后，通过精心设计的返回值引导智能体走向攻击者指定目标。
- **整体含义**：论文揭示 MCP 生态中语义工具选择层的脆弱性，呼吁加强工具审查与运行时隔离。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 威胁模型与形式化

- **攻击者能力（黑盒）**：
  - 元数据控制：可构造貌似良性但优化为最大化被选概率的名称 $n$ 与描述 $d$。
  - 攻击载荷：控制工具执行端点，可构造输出 $o_{adv}$ 嵌入攻击指令。
  - 无法访问模型权重、系统提示、私有记忆；但可在本地用替代智能体模拟以获取优化信号。
- **形式化建模**：智能体为策略 $\pi: S \to \Delta(A)$，在状态空间 $S$、动作空间 $A$、工具环境 $T$ 中做序贯决策；执行轨迹 $\tau = ((s_0,a_0),\dots,(s_K,a_K))$。
- **攻击目标**：优化 $\tilde{t}^* = \arg\max_{\tilde{t}=(n,d,o_{adv})} P_{sel}(\tilde{t}) \cdot E_{man}(\tilde{t})$，其中 $P_{sel}$ 为工具被调用概率，$E_{man}$ 为调用后操纵效果。

### 2.2 两阶段框架

- **Phase I：Attraction（元数据优化）**
  - 采用五种说服策略：**Authority（权威）、Urgency（紧迫）、Comprehensiveness（全面）、Resource Optimality（资源最优）、Security（安全）**。
  - 均匀分配生成预算 $N_{attr}$，每个策略生成 $N_s = N_{attr}/5$ 个候选。
  - 用 $K_{roll}=3$ 次蒙特卡洛 rollout 评估选择率：$Score_{attr}(n,d) = \frac{1}{K_{roll}}\sum_{k=1}^{K_{roll}} I_{call}(\tau_k,\tilde{t})$。
  - 保留选择率非零的候选作为精英种子 $E_1$。
- **Phase II：Manipulation（载荷精炼）**
  - 按精英元数据选择率比例分配 payload 生成数量：$N_{payload}(n^*,d^*) = N_{total} \cdot Score_{attr}(n^*,d^*)/Z$。
  - 条件于攻击类型生成载荷：$o_{adv} \sim G(q, n^*, d^*, y_{guidance})$。
  - **Analyzer–Optimizer 架构**（核心创新）：
    - **Analyzer $D$**：作为诊断批评器，对执行轨迹 $\tau$ 生成结构化反馈 $d = D(\tau, \tilde{t}, y_{guidance})$。标量目标（C-DoS）聚焦影响放大；二值目标（IE/EIC/RD）进行失败诊断。
    - **Optimizer $O$**：用反馈重写工具：$\tilde{t}' = O(\tilde{t}, d, y_{guidance})$。
  - 迭代 $E$ 轮，每轮取 TopK 工具进行精炼，避免随机搜索。

### 2.3 适应度函数设计

- **C-DoS**：加权 token 消耗 $f(\tau) = I_{call}(\tau,\tilde{t}) \cdot (T_{in}(\tau) + 5 \cdot T_{out}(\tau))$，输出 token 权重 5×（对齐商业模型定价）。
- **IE / EIC / RD**：用 DeepSeek-V3 作为 LLM judge，温度 0，按固定评分量表打分 $\{1,2,3,4\}$，**仅分数 4 计为攻击成功**。

### 2.4 四类攻击场景

- **C-DoS（认知拒绝服务）**：诱导冗余推理循环/递归调用，造成 token 消耗膨胀。
- **IE（信息外泄）**：诱导智能体检索敏感数据（如 `.env` 中的 `OPENAI_API_KEY`）并作为参数发送至攻击者端点。
- **EIC（环境完整性破坏）**：诱导未授权写操作，如修改 `mcp_config` 写入持久后门。
- **RD（推理脱轨）**：通过载荷干扰逻辑流，导致错误下游工具选择或提前终止。

## 3. 实验设计

- **数据集 / Benchmark**：**LiveMCPBench**，包含 95 个真实任务，覆盖 6 个领域（Office、Lifestyle、Leisure、Finance、Travel、Shopping），70 个 MCP 服务器，527 个工具。
- **评估模型（5 个）**：GLM-4.6、Qwen3-Max、DeepSeek-V3.1、Kimi-K2-0905、GPT-5（medium reasoning effort）。DeepSeek-V3 作为 IE/EIC/RD 的攻击成功 judge。
- **Agent 框架**：ReAct 智能体，通过 LangChain 实现，经 MCP 进行工具选择与调用。
- **评估指标**：
  - **C-DoS**：加权成本比 $Cost\times_i = cost(u_i, \tilde{t}\cup T/\{t\}) / cost(u_i, T)$。
  - **ASR**：评分 4 的任务占比。
  - **MTIR**：执行轨迹中包含恶意工具的任务占比。
- **对比基线**：
  - **Zero-Shot Generation**：一次调用生成完整恶意工具。
  - **LLM-based Genetic Algorithm**：用 LLM 驱动编辑代替交叉/变异，仅用标量适应度，无轨迹反馈。
  - **AMA**（Attractive Metadata Attack）：仅优化元数据，配固定载荷。
  - **MPMA**（Preference Manipulation Attack）：操纵工具选择偏好，配固定载荷。
- **其他实验**：
  - **消融实验**：GLM-4.6 上 18 个留出任务（每领域 3 个），切换三种组件（初始策略、两阶段生成、轨迹优化）。
  - **跨查询泛化**：10 个基础任务 × 5 个留出类比查询 = 50 个不相交未见查询。
  - **防御评估**：GPT-2 困惑度检测、Qwen3-8B 审计器、ToolTweak 式改写防御、FIDES 式信息流控制（IFC）。
  - **失败模式分析**：GLM-4.6 上 IE/EIC/RD 的失败类型分解。
