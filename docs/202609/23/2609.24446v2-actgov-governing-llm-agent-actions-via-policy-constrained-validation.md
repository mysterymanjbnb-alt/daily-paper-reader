## 摘要
大语言模型（LLM）智能体日益通过外部工具执行长时程工作流，使得不可信输出能够影响后续动作并超出用户授权。现有防御措施要么隔离注入内容，要么通过预定义计划和静态策略约束执行，但这些方法在动态工作流下较为脆弱，并且在可扩展工具生态中扩展性较差。在本工作中，我们提出ActGov，一种运行时强制框架，在LLM提出的每个工具动作产生外部影响之前对其进行验证。基于授权、动作、运行时上下文和安全约束的统一语义模型，ActGov-Policy组件从工具规范、良性任务和观测到的失败轨迹中迭代构建策略集，每次更新都通过基于SMT的反例检查进行验证。在运行时，ActGov-Runtime将每次工具调用抽象为有限策略记录，并且仅当该调用仍处于任务范围内的授权边界内且满足所有适用策略时才允许执行。这种逐动作强制在长时程、动态分支的工作流中始终保持授权。我们在多个模型和攻击配置下，在AgentDojo和AgentDyn基准上评估ActGov。结果表明，ActGov在保持任务效用的同时，持续降低间接提示注入攻击的成功率，显著优于现有防御。这些结果表明，ActGov能够对动态智能体执行实施细粒度授权，而无需依赖底层LLM正确识别恶意指令。

## Abstract
Large language model (LLM) agents increasingly execute long-horizon workflows through external tools, allowing untrusted outputs to influence subsequent actions and exceed user authorization. Existing defenses isolate injected content or constrain execution with predefined plans and static policies, but these approaches are brittle under dynamic workflows and scale poorly across extensible tool ecosystems.   In this work, we present ActGov, a runtime enforcement framework that validates each LLM-proposed tool action before it causes external effects. Built on a unified semantic model of authorization, actions, runtime context, and security constraints, the ActGov-Policy component iteratively constructs a policy set from tool specifications, benign tasks, and observed failure traces, with each update verified through SMT-based counterexample checking. At runtime, ActGov-Runtime abstracts each tool call into finite policy records and permits it only if it remains within the task-scoped authorization boundary and satisfies all applicable policies. This per-action enforcement preserves authorization throughout long-horizon, dynamically branching workflows.   We evaluate ActGov on the AgentDojo and AgentDyn benchmarks across multiple models and attack configurations. It shows that ActGov consistently reduces the success rate of indirect prompt-injection attacks while preserving task utility, significantly outperforming existing defenses. These results demonstrate that ActGov can enforce fine-grained authorization over dynamic agent executions without relying on the underlying LLM to correctly identify malicious instructions.

## 1. 核心问题与研究背景

- **背景转变**：LLM 正从文本生成器演变为可规划、调用外部工具、观察环境并执行多步动作的自主智能体，能够操作邮件、日历、文件系统、代码仓库、金融账户与企业平台。安全边界因此发生根本变化——模型输出可直接触发修改、删除、授权等高风险操作。
- **核心风险**：不可信外部内容（如网页、邮件中的注入指令）可能被误当作"用户意图"，导致智能体执行越权动作，即**间接提示注入（Indirect Prompt Injection, IPI）**。
- **关键难点**：工具结果与后续动作之间存在动态依赖，因此需要**逐工具调用（per-tool-call）的授权强制**，而非仅做输入—输出层过滤。
- **现有防御的三点不足**：
  - **缺乏统一语义框架**：各方法用为特定机制定制的表示，容易混淆数据来源与授权来源，把不可信内容当作授权源。
  - **长时程工作流下不稳健**：依赖预定义计划、期望工具轨迹或静态参数清单，难以适应动态分支与意外执行状态，要么过度限制损害效用，要么在偏离假设时失效。
  - **策略构建难以规模化且缺乏保证**：人工编写策略难以维护；自动生成的策略缺乏对遗漏、冲突、非预期权限的严格检测；已有形式化方法（如 VeriGuard）常在策略逻辑与真实运行状态之间脱节。
- **整体含义**：论文提出 ActGov，一个**运行时授权强制框架**，将"动作提议"与"执行授权"严格分离，在工具调用产生外部效果前进行验证，且不依赖底层 LLM 正确识别恶意指令。

## 2. 方法论

### 2.1 核心思想
- 把 LLM 的角色**限定为语义解析器 / 特征提取器**（把非结构化上下文映射到有限记录值），把真正的授权判定交给**离线验证过、运行时确定性的策略解释器**，从而压缩幻觉带来的错误空间。

### 2.2 形式化模型
- 将受保护智能体建模为有限状态机：**M = (H, C, R, P, V, T)**
  - H：执行历史状态空间；C：候选工具调用空间；R：有限记录空间；P：策略集；V：评估函数；T：状态转移函数。
- 评估函数 **V : R × P → {allow, deny}**，对抽象后的记录 rᵢ 与策略集 P 给出确定性判定；工具仅在 vᵢ = allowed 时执行。
- 状态转移 **T : H × C × V → H**，将候选动作与判定结果并入历史。

### 2.3 正交二维记录模式（Record Schema）
- 记录空间 R 由两个维度构成：**形成层级（formation levels）× 语义作用域（semantic scopes）**，分离"值如何得来"与"描述何种授权相关属性"。
- **形成层级**：
  - **L1 确定性**：直接由结构化系统状态计算，无需自然语言处理。
  - **L2 有界语义**：需语义理解，LLM 仅作解析器，映射到预定义有限值域。
  - **L3 组合**：由 L1/L2 值通过布尔逻辑（AND/OR/NOT）组合，捕捉组合或时序依赖。
- **七个语义作用域**：action（候选动作）、permission（任务基线权限）、parameter（参数来源与角色）、history（执行历史）、binding（意图目标与实际目标一致性）、external（外部目的地安全属性）、domain（任务当前操作阶段）。
- 论文给出了三张记录目录（Table 6–8），如 `is_high_risk`、`permission_granted`、`arg::<arg>::provenance`、`arg::<arg>::target_role`、`contextual_binding_currently_valid`、`trusted_web_submission_endpoint`、`pre_payment_sensitive_balance_read` 等，并标注哪些记录需要 LLM 参与构造。

### 2.4 三层策略体系（P = P_TP ∪ P_HI ∪ P_PO）
- **Task-Permission（P_TP）**：把可信用户任务绑定到最小必要工具与资源，形成基线授权边界 `perm`，边界外动作被阻断。
- **Hard-Invariant（P_HI）**：全局安全不变量，例如禁止由不可信注入内容派生的任何外发网络动作，与当前任务范围无关。
- **Procedural-Obligation（P_PO）**：处理超出智能体自主处理权限的情形（如目标绑定薄弱、参数来源不确定），以条件规则形式要求满足前置条件或上下文约束后才允许执行。

### 2.5 ActGov-Policy：策略生成与迭代（离线）
- 数据来源三类：**工具规范**（能力与风险约束）、**良性任务轨迹**（识别过度限制的规则）、**已观测攻击失败样本**（识别缺失的安全条件）。
- LLM 仅作为**策略提议者**，候选规则须经形式化检查与管理员复核后方可部署。
- **验证门控演化**：对任一预定义安全断言 A_sec，Z3 在有限记录域中搜索满足策略语义 P_sem 但违反断言的反例：
  - **∃r, v. Domain_R(r) ∧ P_sem(r, v) ∧ ¬A_sec(r, v)**
  - **SAT** → 暴露策略缺口或冲突，触发精化；**全部 UNSAT** → 才允许部署，数学上保证安全不变量被保持。
- 因把昂贵的 Z3 求解完全放在离线准备阶段，运行时无需引入形式化求解延迟。

### 2.6 ActGov-Runtime：运行时强制（在线）
- 部署在智能体 LLM 与外部工具接口之间，拦截候选调用 cᵢ。
- 先由 P_TP 解析基线任务权限 `perm`，再抽象出记录集：**rᵢ = α_R(τ, perm, Hᵢ, cᵢ)**。
- 判定条件：动作**既处于 `perm` 边界内，又不违反任何安全策略**，才被放行。
- LLM 仅被隔离地用于特定记录的抽取（如参数来源分类），策略评估在结构化有限值上进行，避免直接处理原始自然语言。

## 6. 主要结论与发现

- **RQ1 效能**：AgentDyn 上 ActGov 在四个后端均将 ASR 压至 **≤ 0.007**；AgentDojo 上 ASR 达 **0.000**，显著优于 Progent、DRIFT、CaMeL、ACE。
- **RQ2 效用**：效用保持具有竞争力，如 AgentDyn + Qwen3.6-flash 上 Clean/Attacked Utility 为 0.667/0.586（无防御为 0.667/0.650）；AgentDojo 上在 Qwen3.6-flash 与 MiniMax-M2.5 上保持一流效用。**攻击成功率下降并未以牺牲任务完成为代价**。
- **基线表现差异**：CaMeL 与 ACE 通过结构性限制获得低 ASR，但效用损失巨大（AgentDyn 上几乎为零）；Progent 与 DRIFT 在更结构化的 AgentDojo 上表现较好，但在长轨迹、大工具集、跨应用动态交互的 AgentDyn 上退化。基线结果对后端 LLM 的能力较敏感，而 ActGov 因把 LLM 限定于有界记录抽取、授权判定完全确定化，表现更稳定。
- **RQ3 策略生成动态**：
  - 相同 50% 训练子集下，各生成器均可实现近零 ASR（≤ 0.007），但效用差异明显：DeepSeek-v4-pro 最佳（Clean 0.533 / Attacked 0.429），Qwen3.6-flash 与 MiniMax-M2.5 生成的策略更保守。
  - 训练数据从 50% 降至 25%，Clean Utility 仅从 0.533 微降至 0.500，ASR 保持 0.007，说明一定范围内的数据缩减影响可控。
- **跨域迁移**：域外策略保持**绝对安全**（两个方向 ASR 均 0.000），但效用急剧下降——如用 AgentDojo 训练的策略在 AgentDyn 测试集上，Clean Utility 从域内策略的 0.600 跌至 **0.100**（无防御上界为 0.767）。说明策略泛化到未见环境时退化为极度保守行为。

## 7. 优点

- **架构分层清晰且职责单一**：把昂贵的 Z3 形式化验证完全放在离线阶段，运行时只做有限记录上的确定性谓词求值，实现"低延迟在线执行 + 严格离线保证"的解耦，思路简洁有力。
- **统一语义层**：用同一有限二维记录空间（形成层级 × 语义作用域）同时支撑离线验证与在线强制，使任务权限、参数来源、目标绑定、执行历史等异质授权因素可被**联合推理**，弥补了 VeriGuard 类方法"策略逻辑与运行状态脱节"的缺口。
- **限制 LLM 的错误面**：将 LLM 降级为有界语义解析器，安全判定不依赖 LLM 识别恶意指令，显著降低幻觉导致的授权错误——这是对当前"用 LLM

作安全判据"这一主流思路的重要修正。

- **策略生成有闭环验证**：ActGov-Policy 不是"生成即部署"，而是用 Z3 在有限记录域上对预定义安全断言做反例搜索（SAT 触发精化、全 UNSAT 才放行），把"策略是否遗漏/冲突/越权"从人工审查的主观判断变为可判定的形式化检查，这是相对 Progent、DRIFT 等自动策略方法的关键增值。
- **安全与效用可同时兼顾**：主实验中 ASR 压到近零的同时，Clean/Attacked Utility 与无防御基线接近（如 AgentDyn + Qwen3.6-flash 上 0.667/0.586 vs 0.667/0.650），说明其"精确到工具调用粒度的授权"并未退化为"一刀切拒绝"，这正是 CaMeL、ACE 类结构性防御的软肋。
- **对后端 LLM 能力不敏感**：由于授权判定被确定化，ActGov 在四个能力差异较大的后端上表现稳定，而基线方法对后端能力波动明显，这提升了方法的可迁移性与工程可用性。
- **实验协议设计严谨**：训练/测试攻击对划分、策略冻结后再在未见测试集评估、跨域迁移单独设表，避免了策略在测试攻击上"过拟合"的常见陷阱。

## 8. 不足与局限

- **算力与开销信息缺失**：未报告 GPU/机时，也未量化离线 Z3 求解耗时、策略迭代轮次的墙钟时间，以及在线拦截引入的延迟，无法评估"离线验证 + 在线确定性执行"在真实部署中的成本收益。
- **缺少系统消融**：三层策略（P_TP/P_HI/P_PO）、三类形成层级（L1/L2/L3）、Z3 验证门控等核心设计要素均未做逐个移除的对照实验，各组件独立贡献难以量化。
- **记录目录的完备性未经证明**：七个语义作用域与三张记录目录（Table 6–8）是论文人工设定的，论文未论证其是否覆盖所有现实授权维度；若某类风险没有对应记录，则策略无法表达、Z3 也无从检查——即"验证的可靠性上界由记录模式的设计完备性决定"。
- **LLM 解析器仍是攻击面**：L2 记录（如参数来源、目标角色、意图绑定）依赖 LLM 抽取，论文未评估针对解析器本身的自适应攻击（例如诱导解析器把注入内容误标为可信来源）。虽然攻击面比"直接让 LLM 判安全"小得多，但并非归零。
- **策略泛化能力弱**：跨域实验中域外策略虽保持 ASR=0.000，但 Clean Utility 从 0.600 跌至 0.100，说明策略高度环境耦合，迁移到新工具集/新域时需要重新生成，扩展成本未充分讨论。
- **实验统计性不足**：无防御基线 ASR 本身偏低（0.036–0.111），方法间差异的显著性受限；未报告多次运行的方差或置信区间，也未细分注入强度、位置等攻击维度。
- **人在环依赖**：主实验采用 HITL 复核，RQ3 的无 HITL 场景仅做 5 轮迭代且未报告与 HITL 版本的直接对比，实际部署中人工审查负担有多大、能否省略，结论不够明确。
- **基线适配的公平性存疑**：CaMeL、ACE 在 AgentDyn 上 Clean Utility 为 0.000，可能是移植方式或调参所致而非方法本质，论文未给出适配细节与调参记录。

## 9. 启发与展望

- **"把不确定性关进笼子"的架构范式**：ActGov 的核心洞见不是"让 LLM 更懂安全"，而是**把安全判定从 LLM 手中彻底拿走**，让 LLM 只做它擅长且有界的语义映射。这一"能力降级换安全确定性"的思路，对更广泛的智能体安全（如多智能体协作、代码执行沙箱、具身智能）均有借鉴意义。
- **离线形式化 + 在线确定性**的分工，为"既要严格保证、又要低延迟"提供了可复用的工程模板：昂贵验证放在准备期，运行期只做有限域上的谓词求值。
- **统一的记录语义层**提示了一个更一般的问题：不同授权因素（权限、来源、绑定、历史）需要一个共同的可判定表示，否则联合推理与形式化验证都无从谈起。
- **可延展方向**：记录模式的自动发现/补全、针对 L2 解析器的鲁棒性加固、策略的跨域自动迁移与最小化重生成、以及把延迟与能耗纳入评估——这些都是该框架走向生产级部署前值得补齐的环节。
