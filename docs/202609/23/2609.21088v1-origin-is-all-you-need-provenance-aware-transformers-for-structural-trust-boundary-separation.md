## 摘要
间接提示注入（IPI）仍然是大语言模型（LLM）系统面临的核心安全与安保挑战，因为标准 Transformer 缺乏对来源权威性的架构层面概念。检索文档、用户输入和系统指令都通过同一无差别的注意力机制进行处理，迫使模型仅根据措辞来推断应遵从什么、应将什么视为数据。我们提出溯源感知 Transformer（Provenance-Aware Transformers），这是一种溯源感知防御方法，使应用提供的来源标签能够在模型内部发挥作用。每个输入 token 都被分配一个编码其来源的 ring ID，模型则通过来源嵌入、可学习的来源注意力偏置以及可在归一化过程中保留来源信息的可学习来源缩放因子进行增强。由此得到的架构在生成过程中在权威来源与非权威来源之间强制建立结构化边界。为了在已发布的预训练模型上实例化该架构，我们提出一种两阶段微调流程，以教会模型来源语义以及在 ring 约束下的任务行为。评估表明，溯源感知 Transformer 在分布内和分布外均能保持对 IPI 的稳健抵抗能力，同时保持与基础预训练模型相当的效用。更广泛地说，我们的工作表明，将来源信息作为一等的架构信号暴露出来，可以将 LLM 安全对齐从脆弱的模式匹配转向显式的信任分离。

## Abstract
Indirect prompt injection (IPI) remains a central safety and security challenge for large language model (LLM) systems because standard transformers lack architectural notion of source authority. Retrieved documents, user inputs, and system instructions are all processed through the same undifferentiated attention mechanism, forcing the model to infer from wording alone what should be obeyed and what should be treated as data. We propose Provenance-Aware Transformers, a provenance-aware defense that makes application-supplied source labels actionable inside the model. Each input token is assigned a ring ID encoding its origin, and the model is augmented with origin embeddings, a learnable origin attention bias, and a learnable origin scale that preserves provenance under normalization. The resulting architecture enforces a structural boundary between authoritative and non-authoritative sources during generation. To instantiate this architecture on released pretrained models, we propose a two-stage fine-tuning pipeline to teach the model origin semantics and task behavior under ring constraints. Evaluation shows that Provenance-Aware Transformers maintain robust resistance to IPI both in-distribution and out-of-distribution while preserving utility comparable to the base pretrained model. More broadly, our work shows that exposing provenance as a first-class architectural signal can shift LLM safety alignment from brittle pattern matching toward explicit trust separation.

## 1. 核心问题与研究动机

- **根本问题**：间接提示注入（IPI）长期难以根治，原因在于标准 Transformer 架构中**不存在"来源权威性"的概念**。系统指令、用户输入、检索文档、工具返回内容都被拼接进同一条因果序列，由同一个纯内容寻址的注意力机制处理，注意力 logit 只依赖内容（`a_ij = h_i^T h_j / √d`），没有任何项反映 token 的出处。
- **后果**：模型只能从措辞推断"该服从什么、该把什么当数据"，攻击者只要把指令伪装进检索文档，就与合法系统指令在架构上不可区分。
- **现有防御的三类局限**：
  - *Prompt-based*（指令提醒、Sandwich、分隔符、随机序列封装、已知答案验证）：不改权重，但依赖模型自行判断文本结构，易被模仿合法指令的注入绕过。
  - *Detection-based*（PromptGuard、PromptSleuth、DataSentinel、PromptLocate、Rennervate）：把 IPI 当分类问题，工作在生成之外，检测漏报即无保护，属"事后补救"。
  - *Fine-tuning-based*（SecAlign、StruQ、JATMO）：把抗性写进权重，但仍基于内容寻址注意力，只学到"攻击模式的形状"，未解决架构缺口。
- **核心洞察**：借鉴操作系统安全中"来源决定授权而非内容"的原则，把**溯源（provenance）提升为一等的架构信号**，使"来源身份"直接约束生成时的信息流，从而把 LLM 安全从脆弱的模式匹配转向**显式信任分离（structural trust separation）**。

## 2. 方法论

### 2.1 核心思想

- 由应用层在 token 送入模型前分配**离散 ring ID**，模型通过三个可学习组件让来源标签在整个前向传播中持续生效，从而在**权威来源与非权威来源之间强制建立结构边界**。
- 形式化：给定 token 嵌入 `F = T(X)` 与来源标签序列 `r = O(X)`，模型执行**来源条件生成** `M_Θ(F, r) = G(A_θ(f_i, r_i))`。
- 安全目标（式 2）：对所有 `r_i = 3` 的 token，其影响即使非零，也**不得传递指令级语义**；同时（式 3）对 `r_i ∈ {0,1,2}` 的 token，模型行为须近似于无来源条件的基座模型，保证效用。

### 2.2 四环信任层级（Ring Hierarchy）

| ID | 标签 | 来源 | 角色 |
|---|---|---|---|
| 0 | ORG_SYSTEM | 运营者 | 绝对权威，定义策略 |
| 1 | ORG_SELF | 模型自身 | 已生成的 assistant token |
| 2 | ORG_USER | 用户/可信内容 | 用户意图与允许的任务上下文 |
| 3 | ORG_Data | 不可信外部源 | 潜在被注入的数据，**无条件抑制** |

- Ring 分配在应用层完成，**无需对内容做语义判断**（框架本身已知各段出处）；环数不固定，架构不限制环的数量，可由部署方定义更细粒度层级。

### 2.3 三个来源组件（关键技术细节）

1. **来源嵌入（Origin Embedding）**：新增嵌入表 `E_org ∈ R^{4×d}`，输入表示为
   `x_i = E_tok[t_i] + α · E_org[r_i]`
   使来源信息从第一层起就对所有下游计算可见；嵌入是可学习参数，由 Stage 1 赋予真实语义。
2. **来源缩放/门控（Origin Scale, α ∈ R+，初始化为 0.1）**：可学习标量，用于对抗紧随其后的 RMSNorm——微调中 token 嵌入幅度增长会稀释加性来源信号，显式标量门控比让高维嵌入隐式补偿更易优化、收敛更稳。
3. **来源注意力偏置（Origin Attention Bias, B ∈ R^{4×4}）**：按 query/key 的 ring ID 索引（而非位置）查表并扩展成 T×T 张量，加到 softmax 前的注意力 logit 上：
   `a_ij = q_i·k_j/√d_k + B_{r_i, r_j}`
   - `B` 在所有注意力层与头上共享，端到端训练；只需 gather 操作即可挂入标准 SDPA 内核，无需自定义注意力实现。
   - 初始化策略：仅 `B_{1,3}` 与 `B_{2,3}` 为强抑制 `−δ`（δ≫0），其余（含 `B_{1,2}` 等允许对）接近 0。
   - 设计理由：同时覆盖两条影响通路——assistant 查询直接关注不可信键，以及 Ring 2 内容关注 Ring 3 后把影响带入后续表示；Ring 0 无需抑制项（系统提示总在不可信内容之前，因果掩码已足够）；Ring 3 自身查询不限制（对最终输出无影响）。

### 2.4 辅助损失（仅 Stage 1 使用）

- **正交损失**：`L_orth = (cos(e_0, e_2))^2`，惩罚系统提示与用户嵌入方向重合，鼓励几何上可分。
- **权威损失**：`L_auth = ReLU(‖e_2‖ − ‖e_0‖ + m)`，鼓励系统提示嵌入在幅度上占优（m 为 margin）。

### 2.5 两阶段监督微调流程

- **Stage 1 — 来源微调（Origin Fine-Tuning）**：在广泛指令跟随语料上带 ring 标签微调，教模型"来源语义"并重建在新组件下完成普通任务的能力；配合上述两个辅助损失。
- **Stage 2 — 对齐微调（Alignment Fine-Tuning）**：在专门构造的结构化注入数据集上训练抑制行为：Ring 0 无条件服从、Ring 2 作普通输入、Ring 3 不论表面内容一律抑制。
- **Stage 2 数据构造（四步，扩展 SEP 的 witness 方法）**：
  1. 上下文生成（用 Claude 为 SEP 各子任务生成新短上下文，去重）；
  2. 真值生成（仅用合法任务指令+上下文得到参考回答，作为监督目标）；
  3. 探针选择（从固定探针–witness 库采样对抗指令 + 确定性 witness 串，witness 出现即证明被劫持）；
  4. 注入构造（基于 PromptSleuth-Bench 的 9 种攻击模式，生成注入样本与匹配的良性样本，二者监督目标相同）。
- 最终训练集 60,200 例（24,079 注入 / 36,121 良性），另加 Alpaca-Cleaned 构成的纯 Ring 0/1/2 通用样本；留出 IID 测试集 4,375 例。
