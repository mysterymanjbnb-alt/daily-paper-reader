## 摘要
针对大语言模型（LLMs）的越狱攻击，其防御可在不同流水线阶段运行，例如输入修改或输出防护，但在每个阶段应部署哪些防御以及如何组合它们仍不清楚。以往实证研究因攻击成功率定义和实验设置不一致而彼此割裂，大多孤立地评估防御。据我们所知，本文首次在直接、黑盒、单轮攻击的一致威胁模型下，对流水线阶段内及跨阶段的防御组合进行系统研究。我们的决策框架通过有原则的攻击成功率公式，并结合受控查询预算与明确的公平性规则，来标准化评估。在19种攻击和15种防御上，我们发现没有单一防御是普遍最优的，但精心选择的组合能够在最小化效用退化的情况下实现显著安全性，从而为分层防御流水线提供实用建议。

## Abstract
Defenses against jailbreak attacks on Large Language Models (LLMs) operate at different pipeline stages, such as input modification or output guard, but it remains unclear which defenses to deploy at each stage and how to combine them. Prior empirical studies, fragmented by inconsistent attack-success-rate definitions and experimental settings, have evaluated defenses largely in isolation. Here we present the first systematic study, to our knowledge, of defense combinations both within and across pipeline stages, under a consistent threat model of direct, black-box, single-turn attacks. Our decision framework standardizes evaluation through a principled attack-success-rate formulation with controlled query budgets, together with explicit fairness rules. Across 19 attacks and 15 defenses, we find that no single defense is universally best, but well-chosen combinations achieve substantial safety with minimal utility degradation, yielding practical recommendations for layered defense pipelines.

## 2. 方法论：CASCADE 框架

### 核心思想
- 将防御组织为**六阶段流水线**（训练 → 输入防护 → 输入修改 → 推理 → 输出精炼 → 输出防护），聚焦无需权重访问/重训练的**三个推理时阶段**（输入防护、输入修改、输出防护），通过四个顺序过程逐步缩小攻防候选集，最终给出场景化组合推荐。

### 四个顺序过程（P1–P4）
- **P1 攻击初始选择**：按相似性把攻击分为子类别，同子类内用相同查询预算评估 ASR，选出每个子类的代表攻击。最终选出 5 个代表：**Adaptive、DSN、Refusal、SeqBreak、ReNeLLM**（人设类攻击在先进 LLM 上表现低于基线，整类排除）。
- **P2 防御初始选择**：按阶段分组，先评估各防御及阶段内组合的**效用**，剔除效用退化不可接受者；在每个"防御数量分组"内按 %↑U 排名取 **top-k = 4**。输入/输出防护用 `{}` 表示"任一触发即拒绝"的组合，输入修改用 `⇒` 表示顺序施加。
- **P3 攻防对抗**：用选出的防御配置对 5 个代表攻击评估 %↓ASR，按安全/效用/内存权衡，在每个阶段选出 sec/util/mem 三类偏好配置。
- **P4 最终跨阶段组合**：对跨阶段组合再次用 top-k 效用筛选，再用 %↓ASR 评估，并测量延迟，产出面向安全、效用、效率三场景的推荐组合。

### 关键指标与公式
- **统一 ASR**：提出 `ASR@max_q`，把 `ASR@N`（top-N 任一成功）与 `ASR_ens`（多变体任一成功）统一为"在固定最大查询预算内、任一变体任一次尝试成功即算越狱"，变体多的攻击相应减少重复次数：
  - `ASR@max_q = Σ_d max_{n,v}[I(Q_{d,n,v})] / |D|`
- **效用**：AlpacaEval 的长度控制胜率 `WinRate_LC(m,b) = 100·E[σ(Q_{m,b} + 0 + D_{m,b,x})]`，长度项固定为 0。
- **防御有效性**：`%↓ASR`（对代表攻击的 ASR 相对下降平均）与 `%↑U`（对目标模型效用相对提升平均）联合最大化。
- **效率**：`|Θ|` = 各防御组件参数量之和；`ΔT` = 有无防御的平均响应时延差。
- **五条公平性规则**（附录 B）：①同一攻击者能力（只控制用户提示）；②同一子类内相同查询预算；③按效用相对排名 top-k 选择（因 AlpacaEval 是相对质量，固定阈值难辩护）；④P3 沿用 P1 的查询预算；⑤按安全/效用/效率三目标平衡选择。

### 实现
- 基于 **LangGraph** 构建有状态 agent 执行图，节点为攻击/防御/目标 LLM，共享状态记录提示、响应、拒绝状态与评估结果。
- 判官与效用评估 temperature=0；目标 LLM 越狱评估 temperature=1、效用评估 temperature=0；固定种子 42；max_new_tokens 为 2048（非推理模型）/4096（推理模型）。

## 6. 主要结论与发现

- **没有单一防御普遍最优**，但**精心组合可实现显著安全提升且效用损失极小**。
- **P1 发现**：白盒可迁移攻击中 Adaptive 与 DSN 最强；人设类（persona）攻击在现代 LLM（GPT-4o、Claude-sonnet-4）上低于基线，整类排除；最终 5 个代表攻击为 Adaptive、DSN、Refusal、SeqBreak、ReNeLLM。
- **三个场景化跨阶段推荐组合**：
  - **安全优先**：`util1 ⇒ util2 ⇒ sec3` = `{PG, OSS} ⇒ [SR] ⇒ {LG, WG, GR}`，%↓ASR **97.4**，%↑U **−9.2**，43.1B 参数，ΔT **+2.16s**。
  - **效用优先**：`util1 ⇒ util3` = `{PG, OSS} ⇒ {LG, WG}`，%↓ASR **94.6**，%↑U **−7.8**，35.1B，ΔT **+0.48s**。
  - **效率优先**：`mem1` = `{PG, WG}`，%↓ASR **86.7**，%↑U **−9.6**，仅 7.1B，ΔT **−0.02s**。
- **泛化性**：在 GPT-5.4-mini 与 gemini-3.1-flash-lite 上，安全组合仍达 100.0% / 96.3% 的 %↓ASR；GPT-5.4-mini 上 %↑U 甚至为 +1.4%（因 SR 会改写良性查询使其更清晰）；较高 FPR（7.6%/8.0%）来自极端边界案例，但 %↑U 表明未损害感知效用；mem1 提供低 FPR（1.2%）的轻量替代。
- **总体规律**：更复杂的组合获得更强 ASR 削减

（接上）——**但边际收益递减**：安全优先组合相比效用优先组合仅多获得约 2.8 个百分点的 %↓ASR，却付出约 1.7 秒额外延迟与更大内存占用；效率优先组合以仅 7.1B 参数即达到 86.7% 的 %↓ASR，是性价比拐点。
- **跨阶段优于单阶段**：三阶段组合普遍高于任意两阶段或单阶段配置；输入修改（尤其是 SR）与输入/输出防护形成互补——防护负责"拦截明显恶意"，改写负责"消解潜在恶意语义"，二者叠加才能逼近高 %↓ASR。
- **防御角色不可互换**：同为"任一触发即拒绝"的 `{}` 组合，输入侧（PG、OSS）与输出侧（LG、WG、GR）贡献的边际安全增益不同；输出防护对已生成的有害内容提供最后一道闸门，对模板类/风格类攻击尤其有效。
- **模型规模与安全并非单调关系**：在 GPT-5.4-mini 等新模型上，相同组合的 %↓ASR 甚至高于旧模型（安全组合达 100.0%），说明现代对齐基座与推理时防御具有协同效应。
- **效用损失主要来自输入修改**：`SR`（改写）在提升安全的同时会改变良性查询的表述，导致 %↑U 出现负值（−9.2/−7.8）；但在部分模型上改写反而使查询更清晰，%↑U 转为正（+1.4%），说明效用影响高度依赖目标模型。
- **总体判断**：不存在"一劳永逸"的防御；CASCADE 的价值在于把"该在哪些阶段、以何顺序、叠几层防御"从经验直觉转化为可复现的量化推荐。

## 7. 局限性与未来工作

- **威胁模型限定**：全文聚焦**直接、黑盒、单轮**越狱；未覆盖多轮对话攻击、间接提示注入（如通过检索内容/工具返回注入）、以及 agent 工具调用链中的越权执行，而这些正是 ReAct 类系统最现实的攻击面。
- **攻击候选的筛选偏差**：P1 的攻击子类划分与代表选取基于**无防御**条件下的 ASR，可能系统性低估"防御感知/自适应"攻击——即专门针对 PG、SR、LG 等组件设计的绕过策略。自适应攻击（Adaptive）虽在列，但未针对每个防御配置重新优化。
- **ASR 评估的模型覆盖**：P3 的 %↓ASR 仅在 Vicuna-7B 与 GPT-3.5 两个较旧、较低成本模型上测量，虽以泛化实验补充新模型，但推荐组合在全部 9 个目标模型上的完整矩阵缺失。
- **阶段间交互未显式建模**：P4 只在 top-k 候选空间内做组合搜索，属于贪心式而非全局最优；防御之间的非线性/对抗性交互（如某防护抑制另一防护的效果）未被分析。
- **人工标注的主观性**：判官可靠性研究由作者独立标注 500 条样本，无第二标注者或一致性交叉验证，κ 值虽高仍可能带入个人判断偏差。
- **效用与安全的度量依赖**：效用使用 AlpacaEval + Llama-3.1-70B 判官，越狱使用 HarmBench Judge，指标本身存在判官偏差与长度/风格敏感性；%↑U 为相对值，跨研究解释需谨慎。
- **成本报告不完整**：未拆分各阶段实验的 GPU 时长与调用专有 API 的费用，难以复现总预算构成。
- **未来方向**：扩展到多轮与工具使用场景、引入防御感知自适应攻击、建模阶段间交互并做全局组合优化、在更广模型族上验证推荐、以及引入多标注者与更强判官以提升评估稳健性。

## 8. 主要贡献与客观评价

### 贡献
- **首个系统性的跨阶段防御组合评估框架**：把分散的孤立防御研究整合为六阶段流水线，并在统一威胁模型下比较阶段内与跨阶段组合。
- **统一评价口径**：提出 `ASR@max_q` 统一 `ASR@N` 与 `ASR_ens`，并给出五条公平性规则，缓解了跨研究不可比的问题。
- **可落地的场景化推荐**：产出安全/效用/效率三套跨阶段组合及其 %↓ASR、%↑U、参数量、延迟的完整权衡数据。
- **工程与验证配套**：基于 LangGraph 的可复现实现、判官可靠性研究、以及 HarmBench + XSTest 的跨数据集/跨模型泛化验证。

### 优点
- 规模大（19 攻 × 15 防 × 9 模型）、流程清晰、规则透明、附录表格完整，具备较高可复现性。
- 明确区分"安全/效用/效率"三目标，避免用单一 ASR 掩盖效用代价，符合真实部署的决策逻辑。
- 判官选择有实证支撑，泛化实验兼顾新模型与良性误拒率（FPR）。

### 不足
- ASR 主实验仅两个旧模型，新模型覆盖依赖泛化实验，证据强度不均衡。
- 攻击筛选与组合搜索均为贪心/局部，未证明全局最优，也未纳入防御感知攻击。
- 缺少多轮、间接注入与工具调用场景，限制了结论向 agent 系统的外推。
- 标注与判官环节缺乏外部独立验证。

## 9. 对研究与实践的启示

- **对部署方**：不必追求"最强单点防御"，而应按风险等级选择分层组合——高风险场景用安全优先三阶段组合，交互密集场景用效用优先两阶段组合，资源受限场景用 `{PG, WG}` 轻量方案。
- **对研究者**：防御评估应报告完整权衡三元组（安全、效用、成本）而非单一 ASR；应把"防御感知攻击"与"跨阶段交互"纳入基准，否则易高估组合收益。
- **对基准建设**：CASCADE 的统一 ASR 口径与公平性规则可作为后续越狱防御基准的参考模板，推动结果可复现、可比较。
- **对安全对齐**：结论再次印证"有用性与无害性的张力"无法靠单层机制消解，需在推理时多阶段协同，且需随基座能力升级同步迭代防御组合。
