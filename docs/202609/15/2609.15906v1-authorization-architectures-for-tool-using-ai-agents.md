## 摘要
工具使用型人工智能（AI）智能体——即能够自主调用应用程序编程接口（API）、数据库、浏览器以及诸如模型上下文协议（MCP）等智能体间协议的系统——正日益成为生产基础设施。然而，用以规范智能体何时被授权代表人类行动的安全模型仍不成熟。可信的人-AI系统要求，智能体的每一项具有实质后果的行动都可追溯至某一人类主体，受该人类实际委托范围的约束，并可在事后被质疑；鲜有已记录的部署能够可靠且端到端地同时满足这三项属性。现有文献孤立地处理该问题的各个片段，包括非人类身份的凭证管理、经典访问控制模型、提示注入以及审计追踪，却很少关注授权决策点本身，即工具调用发生的那一刻，以及使该决策正确、可执行且可问责的机制。本综述引入一个贯穿人类用户、运营者/部署者、编排智能体、子智能体和工具端点的委托主体层级作为组织框架，并考察五个相互依赖的层面：智能体身份与凭证生命周期；跨多跳链的委托与权限范围传播；策略执行点（PEP）处的运行时执行与即时授权；作为破坏委托主体层级的授权绕过手段的提示注入；以及可审计性、来源追溯与不可否认性。基于对2023年至2026年间发表的大约180篇候选文献进行筛选后得到的89篇一手资料所开展的结构化叙述性综述，我们提出七项结构性要求，推导出一个四层参考架构，将这些要求应用于三种可部署的参考配置，并指出运行时执行与聚合边界是主要的未解决缺口。

## Abstract
Tool-using artificial intelligence (AI) agents, systems that autonomously invoke application programming interfaces (APIs), databases, browsers, and inter-agent protocols such as the Model Context Protocol (MCP), are becoming production infrastructure. Yet the security model governing when an agent is authorized to act on a human's behalf remains underdeveloped. Trustworthy human-AI systems require that every consequential agent action be traceable to a human principal, bounded by what that human actually delegated, and contestable after the fact; few documented deployments satisfy all three properties reliably and end to end. Existing literature addresses fragments of this problem in isolation, credential management for non-human identities, classical access control models, prompt injection, and audit trails, while giving little attention to the authorization decision point itself, the moment a tool invocation occurs, and mechanisms that make that decision correct, enforceable, and accountable. This review introduces a principal hierarchy spanning human user, operator/deployer, orchestrator agent, sub-agent, and tool endpoint as an organizing framework, and examines five interdependent layers: agent identity and credential lifecycle; delegation and scope propagation across multi-hop chains; runtime enforcement and just-in-time authorization at policy enforcement points (PEPs); prompt injection as an authorization bypass that breaks the principal hierarchy; and auditability, provenance, and non-repudiation. Drawing on a structured narrative review of 89 primary sources screened from approximately 180 candidates published between 2023 and 2026, we propose seven structural requirements, derive a four-layer reference architecture, apply the requirements to three deployable reference configurations, and identify runtime enforcement and aggregation bounds as the principal unresolved gaps.

- **现有研究缺口**：已有工作孤立地处理碎片——非人类身份（NHI）凭证管理、经典访问控制模型、提示注入攻击、审计追踪——但**很少关注授权决策点本身，即工具调用发生的那一刻**，以及使该决策正确、可执行、可问责的机制。
- **整体含义**：智能体安全不能化约为模型对齐，必须为智能体所采取的行动建立显式的授权控制；组织关切是"人类权威"——人能委托有界任务、看见授权被如何使用、在工作流运行中干预、并在事后质疑结果。

## 2. 方法论：核心思想与关键设计

- **研究类型**：结构化叙述性综述（structured narrative review），**非系统综述**，不提供 PRISMA 流程图，适用于概念碎片化、术语不稳定的领域，目标是综合与形成研究议程。

- **核心概念框架一：委托主体层级（Principal Hierarchy）**
  - Layer 0 人类用户/数据主体（合法权威之源）
  - Layer 1 运营者/部署者（配置模型与工具、制定策略、发放凭证）
  - Layer 2 编排智能体（主 LLM 规划器）
  - Layer 3 子智能体（专业工作者、规划器、检索器、验证器）
  - Layer 4 工具端点（API、数据库、文件系统、SaaS、沙箱、浏览器、注册表；**既是授权目标，又是不可信内容来源**）
- **核心概念框架二：两张图、一个决策**
  - **主体与委托图**：记录谁持有权威、谁传递给谁，规范系统中应单调衰减。
  - **信息与来源图**：记录内容从哪来、能流向哪，涵盖系统指令、用户指令、检索文档、记忆条目、工具输出、终端汇聚点。
  - Layer 4 同时出现在两图中，这正是提示注入问题的所在；授权决策即两图在调用边界上的联合求值——委托图决定"可用何种权威"，来源图决定"驱动该动作的内容是否有资格调用该权威"。
- **分析单元：工具调用时刻（tool invocation moment）**，定义为任何经模型中介、导致模型推理过程之外的系统读取/写入/计算/传输/变换/检索/行动的信息请求；被形式化表述为一个调用元组：**〈有序主体链、请求操作、目标端点或对象、参数、委托范围、时间/会话上下文、可审计的来源证据〉**（原文以符号表示，提取后符号缺失，此处按语义复原）。该记号仅作跨机制比较的共同词汇，而非形式语义。
- **五层分析主线**：①智能体身份与 NHI 生命周期；②委托与跨多跳链的范围传播；③策略执行点（PEP）处的运行时执行与即时授权；④提示注入作为授权绕过；⑤可审计性、来源与不可否认。
- **七项结构性要求（R1–R7）**（作者声明非最小集、非完备集，供批评与扩展）：
  - R1 可归属性：每次调用可归属于**经核验的主体链**，而非仅有即时凭证有效。
  - R2 显式委托：委托须显式、有界、可审计，命名允许的操作、资源、接收方、时间窗、深度与目的，PEP 无需额外推理即可评估。
  - R3 单调衰减：范围沿层级向下衰减，任一跳不得授予超过其所获的权限。
  - R4 聚合边界：聚合推断须受**任务范围**约束，而非仅逐工具访问控制。
  - R5 时间有效性：授权须携带与**任务生命周期**（而非仅令牌区间）挂钩的有效期与可撤销性。
  - R6 运行时执行：由独立控制点在调用层执行拒绝或变换，而非依赖提示词或训练目标。
  - R7 防篡改、可归属审计：审计记录须防篡改、可归属至人类主体、足以支撑合规报告与事件重建。
- **四层参考架构**：身份层 → 委托层 → 执行层 → 审计层。贯穿原则是"链在自上而下传递时须被保留、收窄、留证；证据自下而上回流"；任一层缺口向上传播。

- **应用验证**：把要求反向应用到三种参考配置（A：MCP + OAuth 2.1 单组织；B：Amazon Bedrock Agents 托管云平台；C：跨组织 A2A 工作流，示例性组合），并给出一条被拒绝调用的端到端追踪（7 步：用户指令 → 日历读取 → 工具响应携带不可信内容 → 提议读取薪资被拒 → 提议外发邮件被拒 → PEP 生成哈希链决策记录 → 用户可复核与质疑）。

## 6. 主要结论与发现

- **缺口结构（三大类）**：
  - R1、R5、R7 在**单组织内**由 NHI 凭证、OAuth/OIDC、WIMSE/SPIFFE、IBCT 链、来源令牌得到良好服务，但**在组织边界处失效**——链重建、撤销传播、审计关联都预设了一个跨组织工作流并不具备的托管方。
  - R2、R3 有充足的构建块（RAR、Token Exchange、AIP/IBCT、Macaroon 附加限制），但**缺少共享词汇**，制品携带授权细节却无自描述语义，接收端无法验证衰减声明。
  - R6 研究动能最足（AgenTRIM、Progent、AgentBound、SEAgent、CaMeL），剩余问题是部署与标准化而非机制设计。
  - **R4 是唯一没有任何机制族评级超过 P 的要求**，属于"性质不同"的一类：需要关于工作流序列的**新型授权推理**，而非对现有机制的更强评估。
- **两个 C 评级具启发性而非安慰性**：沙箱在主机层完全中介，能力系统按构造完全保证衰减——但两者都很窄：沙箱证据仅达单智能体范围，对应用级调用是否获授权一无所知；ocap 纪律在智能体系统中仅为概念性证据。**窄范围内的完全覆盖 ≠ 宽范围内的部分覆盖**。
- **跨三种可部署配置的发现**：A（MCP+OAuth 2.1）、B（Bedrock Agents）、C（跨组织 A2A）**全部在 R3、R4 与跨边界 R1 上失分，原因相同：组件间传递的制品携带的是"凭证"而非"任务"**。B 在 R1/R6/R7 上明显强于 C，但在 R3/R4 上并不更强。今天可用的最强安排是**组合而非单一产品**。
- **提示注入的重构**：注入不是纯对抗性 ML 问题，而是**授权绕过**——Layer 4 的不可信内容借用 Layer 0 的权威，是混淆代理人的变体。因此正确的问题不是"能否拦住这段文本"，而是"不可信内容能导致何种权威被行使，它是否有界、衰减、可归属"。文本级防御（检测过滤、Spotlighting、StruQ、SecAlign）只降低概率，不能使被服从的指令无法行使权威；持久记忆与投毒检索会放大爆炸半径。
- **标准格局"前收敛"**：OAuth 2.

- **标准格局"前收敛"**：OAuth 2.1、MCP 授权规范、A2A、WIMSE/SPIFFE、RAR（Rich Authorization Requests）等标准正在快速收敛，但**尚未形成跨协议的统一委托语义**。作者判断当前处于"前收敛"（pre-convergence）阶段：各标准各自定义了凭证格式、范围表达与撤销机制，却缺乏把"一次任务"从一个组织连贯地传递到另一个组织的公共制品。这解释了为何 R2、R3 的构建块充足却难以组合——它们分属不同标准的方言。
- **组织与从业者层面的含义**：
  - 授权不能再被视为"部署后的加固项"，而必须与工具注册、凭证发放、编排逻辑同步设计。
  - 最有效的近期改进不是替换模型，而是**在调用边界引入独立的策略执行点（PEP）**，并让授权制品自描述（携带操作、资源、接收方、时间窗、深度、目的）。
  - 组织应优先投资"可质疑性"基础设施：哈希链决策记录、来源证据留存、人类可复核的拒绝路径。作者强调，**事后可质疑的能力**往往比事前完全阻断更现实、也更具工程价值。
- **对研究社区的议程性主张**：
  - 需要一门**智能体授权理论**，把主体链、委托衰减、聚合边界、时间有效性作为一等公民，而非从既有访问控制模型外推。
  - R4（聚合边界）被点名为最紧迫的理论空白：现有机制都在"逐调用"层面思考授权，而智能体的危害常来自**一系列各自合法、合起来越界的调用**。
  - 提示注入应被重新表述为**授权问题**，从而与访问控制、来源追踪、审计研究合流，而非仅停留在对抗性 ML 的子领域。
  - 呼吁建立**跨组织共享的委托词汇表**（自描述授权制品），这是 R2/R3 从"有构件"走向"可验证"的前提。

## 8. 总体评价与意义

- **定位**：本文的价值不在于提供新机制或新数据，而在于**把一个被碎片化处理的问题重新表述为一个统一的授权问题**，并给出可操作的分析词汇（主体层级、两图一决策、调用元组、R1–R7、四层架构）。
- **主要贡献**：
  1. 将"工具调用时刻"确立为智能体安全的**核心授权决策点**。
  2. 用"两张图、一个决策"统一了委托与来源两个此前分离的分析视角，并据此把提示注入重构为混淆代理人问题。
  3. 提出 R1–R7 与四层参考架构，为机制评估与系统设计提供共同标尺。
  4. 通过 70 格矩阵与三种参考配置，给出**结构化的缺口地图**，并识别 R4（聚合边界）为最紧迫的理论空白。
  5. 提出可检验的评估方案（9 项属性、5 个递进场景、8 项部署前检查清单），把研究议程推进到"可被证伪"的层面。
- **最值得记住的一句话式结论**：今天的智能体授权系统在组件间传递的是**凭证，而非任务**——这正是跨组织链、委托衰减与聚合边界三处缺口共同的根因，也是标准"前收敛"阶段最需要补齐的一环。
- **对后续研究的意义**：本文为智能体授权研究提供了**问题框架、术语与议程**；其真正的检验在于社区能否据此构建出可运行、可评估、可跨组织互操作的授权层，并填补 R4 的理论空白。
