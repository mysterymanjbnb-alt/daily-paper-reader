## 摘要
后门投毒攻击会向原本干净的微调数据中加入投毒样本，将触发器与目标行为配对，使模型在触发器出现时学会产生该目标行为。现有评估通常固定投毒样本的数量，并从候选池中随机采样。我们表明，这可能严重低估最坏情况下的脆弱性：在三个 LLaMA-3-8B 后门设置中，保持模型、干净数据和投毒数量固定，攻击成功率仅因所选投毒集合不同而从 3% 到 80% 不等。我们将投毒选择形式化为受 oracle 预算约束的集合优化，并引入 SAILS（Set-level Audit-Informed Iterative Learned Selection，集合级审计信息引导的迭代学习选择），它从数百次微调与评估运行中学习一个集合评分器，对数百万个候选集合进行排序，并仅审计一个小型入围名单。SAILS 在最强的影响力基线上平均将留出攻击成功率提高 30 个百分点，能够从小规模迁移到全规模微调，并可扩展到代码生成、智能体以及仅 API 后门。

## Abstract
Backdoor poisoning attacks add poisoned examples to otherwise-clean finetuning data, pairing a trigger with a target behavior that the model learns to produce when the trigger appears. Existing evaluations typically fix the number of poisoned examples and sample them at random from a candidate pool. We show that this can severely underestimate worst-case vulnerability: across three LLaMA-3-8B backdoor settings, holding the model, clean data, and poison count fixed, attack success ranges from 3% to 80% depending only on which poison set is chosen.   We formalize poison selection as oracle-budgeted set optimization and introduce SAILS (Set-level Audit-Informed Iterative Learned Selection), which learns a set scorer from a few hundred finetune-and-evaluate runs, ranks millions of candidate sets, and audits only a small shortlist. SAILS improves held-out attack success by 30 percentage points on average over the strongest influence baselines, transfers from small-scale to full-scale finetuning, and extends to code-generation, agentic, and API-only backdoors.

## 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：后门投毒攻击向干净的微调数据中注入少量投毒样本，每个样本将触发器（trigger）与目标行为（target behavior）配对，使模型在测试时只要触发器出现就产生攻击者指定的行为。由于现代模型普遍在第三方数据（公开指令集、众包数据、用户交互）上微调，攻击者只需控制极小比例的数据即可植入后门。

- **现有评估的盲点**：既有工作通常固定模型、干净数据、触发器、目标行为和投毒样本数量，然后**从候选池中随机采样**投毒集合。这隐含假设"投毒集合具体选哪些样本影响不大"。

- **核心发现**：论文证明该假设是**错误**的。在三个 LLaMA-3-8B 后门设定下，保持模型、干净数据、触发器、目标行为和投毒数量完全不变，仅改变所选投毒集合，留出攻击成功率（ASR）即可从 **3% 波动到 80%**。这意味着：
  - 仅用随机投毒集评估防御会**严重低估最坏情况风险**；
  - 攻击者在相同投毒预算下，通过精心选择投毒集合可获得远高得多的攻击成功率。

- **问题本质**：寻找最坏情况投毒集合是组合搜索问题（如 900 个候选中选 9 个，组合数约 10²¹），而每次评估一个集合需要一次完整的"微调+评估"运行（称为一次 **oracle 查询**），成本高昂。论文将其形式化为**带 oracle 预算的集合优化问题**（oracle-budgeted set optimization）。

## 2. 方法论：SAILS

### 2.1 核心思想

- **点式打分（pointwise scoring）的局限**：影响函数（influence functions）、TRAK、datamodel 等按单样本打分再取 top-k 的方法，隐含假设集合效用**可加**。但投毒样本之间通过微调过程产生交互：可能冗余（互相抵消）也可能互补。论文将点式方法的误差分解为**精度损失**（近似估计不准）与**可加性损失**（即使单个分数精确，集合效用仍非可加），后者是点式方法原理上无法消除的。

- **SAILS（Set-level Audit-Informed Iterative Learned Selection）**：把"寻找最佳投毒集合"拆成两步——先用少量 oracle 标签训练一个**集合级打分器** bR(S) 预测集合效用，再用它从海量候选中快速排序，仅对排名靠前的小名单用真实 oracle 审计，最终由 oracle 而非打分器决定返回哪个集合。

### 2.2 算法流程（Propose–Score–Audit–Refine）

1. **初始化**：随机采样 |D₀| 个 k-投毒集，各做一次 oracle 查询，训练初始打分器 bR₀。
2. **Propose（提议）**：每轮从可行集合族中生成 N 个候选 k-集合（可来自固定池、扩展池或 LM 生成）。
3. **Score（打分）**：用当前打分器对全部 N 个候选打分（秒级完成，无需微调）。
4. **Audit（审计）**：用 **ε-greedy 策略**（1−ε 取最高分集合，ε 随机探索）选出 m ≪ N 的短名单，用 oracle 逐个评估，更新当前最优集合。
5. **Refine（精炼）**：把新审计得到的 oracle 标签加入训练集，重训打分器，进入下一轮。
6. **输出**：所有审计过的集合中 oracle 效用最高的那个。

### 2.3 关键技术细节

- **打分器架构**：默认用 **DistilBERT + 回归头**，输入为按池索引排序后拼接的投毒集合文本（规范序列化），仅需文本内容，**不需要访问受害者模型的权重/梯度/激活**（支持 API-only 场景）。
- **训练目标**：回归**触发损失 L_trig**（连续、方差小），而非 ASR（REFUSAL 上 82% 的随机集合 ASR=0%，区分度差）。
- **理论保证（Theorem 1，短名单遗憾界）**：
  - R(S_best) − R(S_out) ≤ [R(S_best) − bR(S_best)]₊ + min_{S∈A} [bR(S) − R(S)]₊
  - 即：只要打分器能把某个强集合排进短名单（第一项小），且被审计集合的"高估"不大（第二项小），最终返回集合就接近最优。这为"打分器只需做检索、oracle 做最终选择"提供了理论支撑。
- **Goodhart 效应的应对**：候选数 N 增大时，高分集合会挤压真正强的集合。通过 Refine 步骤在"搜索实际访问的区域"补充标签来校准打分器（附录 D 证明随机标签对极端尾部覆盖率极低，如 N=500K、m=10 时 α=2×10⁻⁵，500 个随机标签覆盖到该区域的期望仅 0.01）。
- **跨规模迁移**：可在便宜的**小规模微调**上训练打分器，再用于**全规模微调**的候选排序与短名单审计。

## 6. 主要结论与发现

1. **投毒集合选择是决定性变量**：固定其他一切条件，ASR 可在 3%–80% 间波动，说明脆弱性不由触发器/目标/投毒数量单独决定。
2. **SAILS 显著优于点式方法**：B=1500 时 REFUSAL/COMMAND/COMPLIANCE 达 **72%/92%/67%**，比最强影响基线平均高 **+30pp**，比预算匹配的 TRAK+representer 平均高 **+21pp**；|D|=3000 时达 78%/91%/74%，在 REFUSAL 和 COMPLIANCE 上超过 oracle greedy。
3. **Goodhart 效应显著**：扩大候选池使 TRAK 代理分上升但 ASR 从 36% 降到 16%；对 TRAK 做文本优化可使代理分翻倍，但 COMMAND/COMPLIANCE 上 ASR 仍停滞在 9–13%。
4. **集合交互强**：REFUSAL 上 k=2→3→4 时 ASR 为 0%→33%→76%，出现"相变"；复制单个最佳样本 k 次得 0% ASR。
5. **跨规模/跨域/跨访问方式可迁移**：mini 标签训练的评分器可指导 full 微调（+41pp over random mean）；SAILS 集合在 6/9 未见模型上优于随机；扩展到代码生成（67% vs 随机 47%）、WebShop（91% vs 随机 84%）、Kimi API（72% vs 随机 16%/46%）。
6. **成本效率**：SmolLM 上 SAILS 以约 1/18 的 oracle 成本达到 oracle-RL 最佳 ASR 的 92%（68% vs 74%）。
7. **对防御的启示**：只用随机或影响函数基线评估防御会严重低估风险，防御评估必须说明攻击者的优化预算。
8. **SGD 下攻击更难消除**：干净数据翻倍可在全批量训练下使 ASR 归零，但在 mini-batch SGD 下攻击仍部分存活（最高 71%）。

## 7. 优点

- **问题新颖且有价值**：首次系统地把"投毒集合选择"本身作为优化对象，揭示了一个被普遍忽视的脆弱性维度，对防御评估方法学有直接冲击。
- **形式化严谨**：将问题清晰建模为带 oracle 预算的集合优化，并给出 Theorem 1（短名单遗憾界）与 Proposition 1–3（点式方法可任意次优、精确单点效应不保证好集合）等理论结果。
- **方法实用且访问要求低**：打分器仅依赖文本内容与标量 oracle 反馈，适用于 API-only 场景；propose–score–audit 框架把打分器限制为"检索器"，避免直接信任代理分，理论上更稳健。
- **实验极其充分**：跨模型族、跨任务域、跨访问方式、跨规模迁移、大量消融与多种子验证，并做了预算匹配和计算量匹配对比，公平性强。
- **成本意识明确**：量化了攻击的 GPU 小时与美元成本，为防御者建立现实威胁模型提供依据。
- **负责任的发布**：代码开源，数据不含隐私，不发布预构造投毒集合与带后门权重，恶意载荷使用保留域名且不执行。

## 8. 不足与局限

- **攻击范围有限**：主要研究 LoRA 指令级微调后门，未评估预训练数据投毒与 RLHF 投毒；触发器与目标行为均假设固定，最优投毒子集很可能依赖触发器语义，联合优化尚未验证。
- **Oracle 成本仍高**：每次查询需完整微调+评估（mini ~3 分钟、full ~40 分钟），B=500–3000 次虽属可行但并非廉价；扩展到 70B+ 模型可能需要更高效的代理或成本削减手段。
- **单目标优化**：仅优化 ASR/触发损失，未考虑隐蔽性（绕过数据过滤/人工审查）与鲁棒性（抵抗激活聚类等防御）。
- **未对抗主动防御**：没有在光谱特征、鲁棒聚合等先进防御下评估 SAILS 投毒集合，防御有效性未知。
- **迁移性不均衡**：跨模型迁移在 COMMAND 上较异质，部分目标模型上 SAILS 集合不如随机（如 Mistral-7B）；跨族迁移优势不如族内明显。
- **代理过优化风险**：贪心坐标下降和 RL 训练都可能出现代理分上升而 ASR 下降的 Goodhart 现象，说明框架仍需依赖 oracle 审计，扩展性受限。
- **可复现性细节**：部分实验（Kimi API 微调）存在 ±7pp 的随机波动；WebShop 等场景仅报告了少量配置。
- **潜在双用途风险**：论文自身承认框架可被用于优化针对微调即服务平台的真实攻击，尽管作者论证了防御价值占优。
