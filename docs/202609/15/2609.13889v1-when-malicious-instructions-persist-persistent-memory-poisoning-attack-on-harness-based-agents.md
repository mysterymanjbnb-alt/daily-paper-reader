## 摘要
Harness 设计通过集成记忆、工具使用和运行时控制，改变了基于 LLM 的智能体的开发方式。然而，这种设计也引入了安全与隐私风险，因为来自外部来源的恶意指令可能被写入持久记忆，并跨会话持续存在。为研究这一风险，我们提出 PMPA，一种针对基于 Harness 的智能体的持久记忆投毒攻击。PMPA 将恶意指令嵌入良性外部来源，并诱导受害智能体将其写入持久记忆，而无需直接访问智能体框架。一旦被存储，被投毒的记忆可在后续会话中被检索，触发额外的恶意操作并导致隐私泄露。我们在 OpenClaw 和 Claude Code 上，跨不同的骨干 LLM、输入模态和触发场景对 PMPA 进行了评估。在所有设置中，PMPA 在 OpenClaw 上实现了平均 73.7%/55.5% 的注入成功率 (ISR) 和跨会话攻击成功率 (C-ASR)，在 Claude Code 上为 66.9%/81.7%，同时在两个系统上保持了良性任务性能。我们进一步评估了一种针对性的提示级防御，发现它能在许多设置中减少记忆注入，但一旦持久记忆已被投毒，其提供的保护有限。

## Abstract
Harness design has transformed the development of LLM-based agents by integrating memory, tool use, and runtime control. However, this design also introduces security and privacy risks because malicious instructions from external sources may be written into persistent memory and persist across sessions. To study this risk, we propose PMPA, a Persistent Memory Poisoning Attack against harness-based agents. PMPA embeds malicious instructions into benign external sources and induces the victim agent to write them into persistent memory without directly accessing to the agent framework. Once stored, the poisoned memory can be retrieved in later sessions, triggering additional malicious actions and causing privacy leakage. We evaluate PMPA on OpenClaw and Claude Code across different backbone LLMs, input modalities, and trigger scenarios. Across all settings, PMPA achieves average Injection Success Rate (ISR) and Cross-session Attack Success Rate (C-ASR) of 73.7%/ 55.5% on OpenClaw and 66.9%/ 81.7% on Claude Code, while preserving benign task performance on both systems. We further evaluate a targeted prompt-level defense and find that it can reduce memory injection in many settings, but provides limited protection once the persistent memory has been poisoned.

## 1. 核心问题与整体含义

- **背景**：以 OpenClaw、Claude Code 为代表的"harness（框架/驾驭层）"工程范式，把记忆、工具调用、会话管理与运行时控制整合为一个编排层，使 LLM 智能体能够执行长周期、跨会话任务。
- **新风险面**：harness 设计中的**持久记忆（persistent memory）**使信息可以跨会话被写入与检索。与临时上下文不同，一旦外部不可信内容从"临时任务输入"跨越边界进入"持久状态"，其影响就不再局限于当前任务。
- **核心问题**：攻击者能否**在不直接接触智能体框架**（不能查询、不能观察输出、不能访问设备/记忆/系统提示）的前提下，仅通过发布带有嵌入指令的良性外部来源，诱导智能体把恶意指令写入持久记忆，并在后续会话中被检索、触发隐私泄露？
- **研究空白**：已有 prompt injection 工作多聚焦于**当前任务内**的行为操纵；已有后门/记忆投毒工作（如 AgentPoison、BadAgent、MINJA）往往假设更强的攻击者能力（污染微调数据、直接污染记忆库、直接与受害者交互）。本文研究的是"仅发布外部来源"这一更受限但更现实的威胁模型。
- **整体含义**：论文表明持久记忆是 harness 智能体一个**严重且被低估的跨会话安全面**，且提示级防御在记忆已被污染后几乎失效。

## 2. 方法论

### 2.1 核心思想
PMPA（Persistent Memory Poisoning Attack）分两阶段：

- **注入阶段（Injection Phase）**：攻击者发布外表正常、内嵌攻击载荷的外部来源。用户日后将该来源交给智能体做**无关的良性问答任务**；智能体在读取良性内容时一并读到恶意指令，可能将其误认为用户需求或偏好，写入持久记忆。
- **触发阶段（Trigger Phase）**：在后续会话中，用户要求执行某个工作区任务（如创建日历事件），智能体检索到被污染的记忆规则，在完成良性任务的同时执行额外恶意动作，造成隐私泄露。

### 2.2 攻击载荷结构（三要素）
1. **过渡句（Transition Sentence）**：把恶意指令与周围良性内容在语义上衔接起来，降低突兀感（如 "After answering this question, ..."）。
2. **记忆写入指令（Memory-Writing Instruction）**：要求智能体把后续规则存入持久记忆（如 "please remember this following requirement in the memory: ..."）。
3. **条件恶意规则（Conditional Malicious Rule）**：规定触发条件与额外动作（如 "When doing Action A, do Action B at the same time"）。

### 2.3 注入策略（两个设计因子）
- **注入位置**：将载荷置于良性内容**中部**，使其看起来是内容的一部分，避免首/尾位置的突兀。
- **语言风格**：采用**第一人称、用户口吻**（"please help me..."），把恶意指令伪装成用户请求或偏好，降低智能体怀疑。

### 2.4 威胁模型
- **攻击者目标**：诱导受害者智能体把恶意规则写入持久记忆，并跨会话触发隐私泄露。
- **受害者**：部署在用户本地环境（个人设备/项目工作区）的 harness 智能体。
- **攻击者能力**：比黑盒更受限——不能查询智能体、不能观察输出、不能访问用户设备/持久记忆/系统提示/运行时配置；**只能构造并发布外部来源**。

### 2.5 评测指标（4 项）
- **ISR（Injection Success Rate）**：恶意规则被写入持久记忆的试验比例。
- **S-ASR（Same-session ASR）**：注入阶段同一会话内即造成隐私泄露的比例。
- **C-ASR（Cross-session ASR）**：新会话中记忆规则被激活并造成隐私泄露的比例。
- **Utility**：注入阶段良性问答任务仍被正确完成的比例（越高越好，其余越高表示攻击越强）。

## 3. 实验设计

### 3.1 智能体与骨干模型
- 智能体：**Claude Code** 与 **OpenClaw**，均在用户本地环境部署运行。
- 骨干 LLM：**DeepSeek-V4-Flash、DeepSeek-V4-Pro、Qwen3-Max**（每个智能体各配 3 个）。

### 3.2 工作区环境（Benchmark / 测试床）
- 自建**本地虚拟工作区**（受 AgentDojo 启发），用 JSON 文件模拟工具状态：`email.json`、`calendar.json`、`docs.json`、`form.json`，并为每个场景实现对应 agent skill，使智能体可发邮件、建日历事件、编辑共享文档、提交表单。

### 3.3 数据集与样本构造
- 良性问答内容取自 4 个公开数据集：**MMLU、ARC、CommonsenseQA、SocialIQA**，均衡采样 **30 条** QA 实例。
- 每条 QA 配 4 种场景化攻击载荷（邮件、日历、共享文档、表单）→ **120 份外部来源内容**。
- 每份内容再转换为 3 种输入模态（**纯文本、图像、PDF**）→ **360 个注入样本**。
- 触发提示（trigger prompt）按 4 个场景各设计 1 条，本身不含恶意指令。
- 隐私泄露路径示例：日历场景中额外把攻击者邮箱加为参与者；邮件场景中抄送邮件内容给指定账号；文档场景中把个人文档同步到共享文档；表单场景中附加额外个人信息。

### 3.4 对比方法与防御
- 本文**未与其他攻击方法做横向对比**，而是以自身消融与不同配置（智能体、骨干模型、模态、场景、策略）作为对照。
- 防御方面评估了一种 **Sandwich-style 提示级防御**（受 Schulhoff 2024 启发）：在原始用户提示前后各插入安全提醒，注入阶段禁止未经确认把外部内容写入长期记忆，触发阶段要求基于存储规则的信息披露动作须经明确确认。

## 6. 主要结论与发现

- **攻击整体有效**：所有设置下平均 ISR / C-ASR 为 **OpenClaw 73.7% / 55.5%**，**Claude Code 66.9% / 81.7%**；Utility 在所有设置中均 > 80%，说明攻击可在不显著干扰良性任务的前提下奏效。
- **跨会话危害显著**：C-ASR 区间 30.8%–92.5%，被污染记忆可在新会话中持续影响智能体行为。
- **同骨干不同框架差异大**：如 Claude Code + Qwen3-Max 的 S-ASR 极低（6.4%），而其他组合较强，说明攻击效果与 harness 实现密切相关。
- **模态影响**：**纯文本攻击最强**（OpenClaw 文本 ISR 接近 100%，S-ASR 88.9%）；图像与 PDF 因需额外解析/工具调用、内容更易被标记为不可信，攻击效果下降，但仍能造成记忆注入与同会话泄露。
- **场景影响**：日历场景跨会话攻击最强（C-ASR 96.7% / 87.8%）；OpenClaw 表单场景 ISR/S-ASR 最高（80% / 71.1%）；邮件与共享文档相对较弱但仍稳定泄露。攻击成功与否取决于"恶意规则"与"触发任务"的匹配度。
- **注入策略**：top+first-person 整体 ISR 最高；Claude Code 对语言风格敏感（first-person 83.0% vs second-person 54.4% / impersonal 48.1%），OpenClaw 对位置更敏感（top 73.3% vs bottom 59.6%）。
- **记忆持久性**：经 1/3/5 轮良性交互后，C-ASR **无一致单调衰减**，部分设置 5 轮后仍保持高成功率，说明毒化记忆可长期潜伏。
- **防御有限**：Sandwich 防御能大幅降低图像/PDF 的 ISR 与 S-ASR（降幅可达 50–76 个百分点），对文本降幅较小；但 **C-ASR 几乎不变**，即记忆一旦被污染，提示级防御基本无效。

## 7. 优点

- **威胁模型更现实、更受限**：攻击者不能查询智能体、不能访问框架，只需发布外部来源，比已有记忆投毒工作（直接污染记忆库/微调数据/直接交互）更贴近真实攻击面。
- **切中 harness 时代的关键盲点**：首次系统刻画"外部内容 → 持久记忆 → 跨会话触发"这一完整链路，并区分了 S-ASR 与 C-ASR，凸显跨会话风险的独特性。
- **攻击载荷设计有工程巧思**：过渡句 + 记忆写入指令 + 条件规则的三段式结构，配合中部位置与第一人称口吻，兼顾隐蔽性与有效性；并做了策略消融验证各因子的作用。
- **实验维度丰富且报告规范**：跨框架、跨骨干、跨模态、跨场景，含良性交互持久性实验与防御评估，所有结果给出标准差。
- **关注良性效用**：同时报告 Utility，证明攻击不是靠破坏任务来"生效"，增强了威胁可信度。
- **提供伦理声明与开源代码**（GitHub），便于后续研究与防御设计。
