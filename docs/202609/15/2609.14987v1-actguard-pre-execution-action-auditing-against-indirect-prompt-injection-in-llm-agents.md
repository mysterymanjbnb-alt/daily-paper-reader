## 摘要
大型语言模型（LLM）智能体通过工具调用与外部环境交互，但工具输出也可能使其暴露于间接提示注入（IPI）攻击。现有防御主要依赖提示加固、内容过滤、预生成计划或权限约束。这些方法往往难以应对复杂任务，或对外部内容过度净化，因而难以兼顾安全性与实用性。因此，关键挑战在于：在保持执行灵活性的同时，精确识别并移除真正诱导不安全动作的恶意内容。为应对这一挑战，我们提出ActGuard，一个执行前动作审计框架。ActGuard不判断外部内容本身是否可疑，而是评估其是否导致当前动作偏离局部合理的预期。在每一步，ActGuard预测即将执行的动作可能使用的工具，并构建局部工具先验，而不约束执行轨迹。在执行前，它将候选动作与该先验进行比较，并进行工具级对比分析和参数级证据定位，以识别工具选择和动作参数上的偏差。随后，验证器检查定位到的证据，仅掩蔽被确认为恶意的片段，并从净化后的上下文重新生成动作。这种设计既保留了合法的规划灵活性，又最大限度减少了因不加区分过滤造成的信息损失。我们在面向工具使用智能体的挑战性基准上评估ActGuard。结果表明，ActGuard将攻击成功率降至与最先进防御相当的水平，同时将任务效用保持在接近无攻击设置的水平，实现了良好的安全—效用权衡。我们的代码公开于：https://github.com/binzhwang/ActGuard。

## Abstract
Large language model (LLM) agents interact with external environments through tool invocation, but tool outputs can also expose them to indirect prompt injection (IPI) attacks. Existing defenses mainly rely on prompt hardening, content filtering, pre-generated plans, or permission constraints. These approaches often struggle with complex tasks or over-sanitize external content, making it difficult to balance security and utility. The key challenge is therefore to preserve execution flexibility while precisely identifying and removing the malicious content that actually induces unsafe actions. To address this challenge, we propose ActGuard, a pre-execution action auditing framework. Rather than judging whether external content is inherently suspicious, ActGuard assesses whether it causes the current action to deviate from a locally reasonable expectation. At each step, ActGuard predicts the tools likely to be used by the upcoming action and constructs a local tool prior without constraining the execution trajectory. Before execution, it compares the candidate action against this prior and performs tool-level contrastive analysis and parameter-level evidence localization to identify deviations in tool selection and action parameters. A verifier then examines the localized evidence, masks only spans confirmed as malicious, and regenerates the action from the sanitized context. This design preserves legitimate planning flexibility while minimizing information loss from indiscriminate filtering. We evaluate ActGuard on challenging benchmarks for tool-using agents. Results show that ActGuard reduces attack success rates to a level comparable to state-of-the-art defenses while maintaining task utility close to the no-attack setting, achieving a favorable security-utility trade-off. Our code is publicly available at: https://github.com/binzhwang/ActGuard.

- **现有防御的四类局限**：
  - **提示加固类**（Spotlighting、Prompt Sandwich、Tool Filter）：恶意指令仍留在上下文中，难以可靠阻止其影响后续动作。
  - **内容过滤类**（ProtectAI、PromptGuard2、PIGuard）：难以区分合法任务信息与恶意内容，要么漏检，要么过度过滤损害效用。
  - **安全对齐类**：依赖模型对指令优先级的可靠服从。
  - **系统约束类**（Progent、CaMeL、DRIFT）：通过权限、信息流或执行计划限制动作空间，但可能过早阻断任务后期所需的合法操作。
- **核心矛盾**：动态执行使"合法任务驱动的重规划"与"注入诱导的偏离"难以区分，也难以将偏离归因到具体因果来源，形成固有的安全—效用权衡。
- **核心问题**：如何在保持执行灵活性的同时，精确识别并净化真正诱导当前动作的恶意内容？
- **两大挑战**：
  1. 执行轨迹依赖未观察到的环境反馈，固定全局计划脆弱。
  2. 恶意指令稀疏且常与合法内容相似，需精确定位而不丢弃任务相关信息。

## 2. 方法论

### 2.1 核心思想

- 将防御目标从"判断外部内容是否可疑"转变为"评估该内容是否使当前动作偏离局部合理预期"。
- 以**状态自适应的局部工具先验**作为审计参照，只审计与当前动作相关的证据片段，而非过滤整条观察或固定执行轨迹。

### 2.2 三大组件

- **Step-wise Planning（逐步规划）**
  - 每步在生成当前候选动作的同时，联合预测下一步可能使用的工具名集合 `F^t+1_prior`。
  - 只预测工具名、不预测参数，因为下一步参数高度依赖当前动作的观察结果。
  - 该先验**不是执行白名单**，而是软性局部行为参照，随任务状态动态更新，允许合法重规划。

- **Dual-Granularity Evidence Localization（双粒度证据定位）**
  - 将历史不可信观察 `o1…o_{t-1}` 切分为细粒度文本块，语义近重复块合并（相似度阈值 0.9），得到块集合 `S`。
  - **工具级定位（对比归因）**：当候选工具 `f_t ∉ F^t_prior` 时，检索与动作最相关的 top-k 块；用长度归一化对数概率选出最合理先验工具 `f^prior`；对每个块计算对比归因分数 `Δ(s)`，衡量掩蔽该块后候选工具相对参考工具的对数概率优势下降幅度；`Δ(s) > τ` 的块送入验证器。
  - **参数级定位（显式参数锚定）**：当工具符合先验时，仍可能被操纵参数（URL、地址、命令、收款人等）。从候选参数 `θ_t` 提取可检索内容，在 `S` 中检索源块作为参数级证据。

- **Verifier-Guided Context Sanitization（验证器引导的上下文净化）**
  - 将候选块扩展其同源相邻块，形成扩展证据集 `E_t`。
  - LLM 验证器联合检查用户请求、候选动作、历史观察序列与扩展证据，输出被确认为 IPI 的块集合 `M_t`。
  - 若 `M_t = ∅`，动作通过；否则仅掩蔽被确认的恶意块，从净化后的历史重新生成动作，并再次审计。
  - 每个动作最多允许 **2 次修复尝试**，重新生成的动作只有在无恶意证据被确认后才到达执行器。

### 2.3 关键公式（文字说明）

- 先验工具选择：`f^prior = argmax_{f∈F_prior} (1/|f|) log P(f | q, H_t)`，用长度归一化避免工具名 token 数差异带来的偏差。
- 对比归因分数 `Δ(s)`：等于"候选工具在完整历史与掩蔽块 s 后的对数概率差（按 token 归一化）"减去"参考工具在同样两种条件下的对数概率差"。当参考工具对应良性动作时，恶意块会拉大候选工具相对参考工具的优势，掩蔽后该优势缩小，`Δ(s)` 为正。
- 若参考工具概率在掩蔽后几乎不变，对比归因退化为朴素归因。

### 2.4 算法流程（Algorithm 1 概要）

1. 策略联合生成候选动作 `a_t` 与下一步工具先验。
2. 提取历史工具输出、分块、合并近重复块。
3. 若工具偏离先验 → 检索 + 对比归因，选出超阈值块；否则 → 参数锚定检索。
4. 扩展邻居块，交给验证器判定。
5. 若无恶意证据则返回动作；否则掩蔽确认块，更新历史并回到步骤 1 重新审计。

## 6. 主要实验结果与发现

### 6.1 主实验（Table 5、Table 6–9）

- **AgentDyn（三个后端）**：ActGuard 在保持与无防御接近的 NAU 的同时，将 ASR 压到显著更低的水平，UAU 损失有限。相较系统类基线（Progent、CaMeL、DRIFT），ActGuard 的优势主要体现在**不牺牲合法重规划**——当任务后期需要调用与初始计划不同的工具时，系统类方法容易过早阻断，而 ActGuard 通过状态自适应先验允许其通过审计。
- **AgentDojo（GPT-4o-mini）**：ActGuard 在 Banking、Slack、Travel、Workspace 四个套件上均取得较低 ASR 与较高 UAU；由于该 benchmark 轨迹较短、攻击更直接，多数防御 ASR 本已较低，ActGuard 的增益幅度小于 AgentDyn，但仍保持竞争力。
- **总体趋势**：提示加固类在长轨迹、跨交互场景下 ASR 明显上升；内容过滤类在含合法第三方指令的任务上过度过滤，UAU 下降；ActGuard 在安全—效用权衡上整体占优。

### 6.2 工具先验分析（Table 1）

- **Step-wise 先验 vs Global Plan**：逐步预测的下一步工具集合比一次性全局计划更贴合真实执行轨迹，在 NA 与 UA 两种设置下都带来更高的动作接受准确性与更低的误审计率。
- 说明"只预测工具名、不预测参数"的设计在动态环境下更稳健。

### 6.3 证据定位分析（Figure 4）

- **对比归因 vs 朴素归因**：在 5 个模型上，对比归因（以长度归一化的先验工具为参考）比朴素归因（只看候选工具概率下降）更能精确定位真正诱导偏离的恶意块，定位召回更高、误选更少。
- **阈值消融**：τ 过低会引入噪声块、增加验证器负担与误掩蔽；τ 过高会漏掉部分恶意块；论文给出经验最优区间。

- 4 种验证器后端（GPT-4o-mini、GPT-5-mini、Gemini-3.1-Flash-Lite、DeepSeek-V4-Flash）下 ActGuard 均能维持低 ASR 与高 UAU，表明框架不绑定特定验证器模型。
- 验证器的 **Recall** 与 **Precision** 共同决定最终安全—效用表现：召回不足导致漏放恶意动作，精度不足导致误掩蔽合法内容。

### 6.5 自适应攻击（Figure 5、Table 10）

- **重复载荷压力攻击**：攻击者多次注入相似载荷试图绕过证据合并与阈值判断；ActGuard 通过语义近重复合并与验证器复核保持较低 ASR。
- **验证器定向攻击**：攻击者构造诱导验证器误判的内容；在多个验证器后端下 ASR 有所上升但未失控，说明验证器是潜在薄弱点，作者建议将其作为后续加固方向。

### 6.6 计算成本（Table 3）

- ActGuard 的 token 消耗与延迟高于无防御，但低于 CaMeL 与 DRIFT；开销主要来自嵌入检索、对数概率归因与验证器调用，且可通过缓存与块合并降低。

### 6.7 组件消融（Table 4）

- 去掉**嵌入检索**、**对数概率过滤**、**对比参考**、**参数级定位**任一组件都会导致 ASR 上升或 UAU 下降，验证三大组件的必要性：
  - 无对比参考 → 定位精度下降，误掩蔽增多。
  - 无参数级定位 → 工具符合先验但参数被操纵的隐蔽攻击漏检。
  - 无对数概率过滤 → 验证器负担与误报上升。

## 7. 局限性

- **验证器依赖**：安全性上限受验证器能力约束，定向攻击可部分削弱其判定。
- **成本**：每步审计引入额外 token 与延迟，对高并发、低延迟场景可能不友好。
- **先验质量**：Step-wise 先验由同一策略模型生成，若模型规划能力弱，先验可能失真。
- **基准覆盖**：主要在两个文本类工具调用 benchmark 上评估，未覆盖多模态、代码执行等更广场景；AgentDojo 仅单后端主实验。
- **并发防御未定量对比**：AttriGuard、CausalArmor、AgentSentry、ICON 等仅作定性讨论。

## 8. 结论与启示

- ActGuard 将 IPI 防御从"内容是否可疑"重构为"内容是否使当前动作偏离局部合理预期"，用状态自适应工具先验 + 双粒度证据定位 + 验证器净化，实现较优的安全—效用权衡。
- 关键设计原则：**审计局部而非全局、软性先验而非硬性白名单、精确定位而非整条过滤**，从而在保持动态重规划灵活性的同时抑制注入诱导的偏离。
- 对后续研究的启示：验证器鲁棒性、跨模态扩展、更低成本的归因方法、以及与信息流控制类方法的互补组合，是值得探索的方向。
