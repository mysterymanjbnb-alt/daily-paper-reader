## 摘要
计算机使用智能体日益与浏览器、终端、文件系统和外部服务交互，带来了不仅源于生成内容、更通过运行时行为显现的安全风险。现有防护模型针对静态提示和响应，难以适用于智能体执行；现有可执行安全平台产生的是评估结论，而非防护模型跨异构智能体框架学习所需的规范化监督信号。我们提出 HazardAuditor，一个以执行为基础的框架，弥合了这两方面差距。其基础设施在受控环境中运行异构智能体（Claude Code、Codex、Hermes 和 OpenClaw），并将其交互规范化为规范事件表示，以支持跨框架监督。我们进一步观察到，token 级后训练目标会给生成式防护模型带来结构性错配，导致较长的推理依据主导梯度更新。防护策略优化（GuardPO）通过将确定性的安全结果转换为序列级优势，并对理由区域和判定区域进行归一化，使安全决策成为有效的优化单元，从而解决这一问题。在多个基准和异构计算机使用系统上，HazardAuditor 相比最强的先前防护模型将准确率提升最多 16.5 个百分点。代码、模型和评估工件将在 https://yunhao-feng.github.io/HazardAuditor/ 提供。

## Abstract
Computer-use agents increasingly interact with browsers, terminals, file systems, and external services, introducing safety risks that emerge through runtime behavior rather than generated content alone. Existing guard models target static prompts and responses and are poorly suited to agent execution; existing executable safety platforms produce evaluation verdicts rather than the normalized supervision a guard model needs to learn across heterogeneous agent frameworks. We introduce HazardAuditor, an execution-grounded framework that closes both gaps. Its infrastructure runs heterogeneous agents (Claude Code, Codex, Hermes, and OpenClaw) in controlled environments and normalizes their interactions into a canonical event representation for cross-framework supervision. We further observe that token-level post-training objectives create a structural mismatch for generative guards, causing longer rationales to dominate gradient updates. Guard Policy Optimization (GuardPO) addresses this by converting deterministic safety outcomes into sequence-level advantages and normalizing rationale and verdict regions, making the safety decision the effective unit of optimization. Across multiple benchmarks and heterogeneous computer-use systems, HazardAuditor improves accuracy by up to 16.5 percentage points over the strongest prior guard. Code, models, and evaluation artifacts will be available at https://yunhao-feng.github.io/HazardAuditor/.

## 2. 方法论

### 2.1 核心思想

- 构建执行级安全监督基础设施：在受控环境中运行异构智能体，把交互归一化为统一事件表示，用于训练跨框架生成式防护模型。
- 提出 Guard Policy Optimization（GuardPO）：把确定性安全结果转换为序列级优势，并对理由区域与判定区域分别归一化，使“安全决策”成为有效优化单元。
- 最终实例化为 HazardAuditor：输入执行轨迹，输出可审计的分析与二值安全判定。

### 2.2 执行级安全监督基础设施

- 形式化定义安全案例：  
  \(\sigma = \langle g, s_0, V_g \rangle\)，其中 \(g\) 为任务与安全目标，\(s_0\) 为初始状态，\(V_g\) 为可选验证器。
- 轨迹表示为规范事件序列：  
  \(\tau_{1:m} = (e_1, \dots, e_m)\)，事件包括：
  - \(U(u_k)\)：用户消息；
  - \(A(a_k, r_k)\)：智能体响应，可含框架暴露的推理 \(r_k\)；
  - \(T(\nu_k, \alpha_k)\)：工具调用，含工具名与参数；
  - \(O(o_k)\)：环境观察。
- 跨框架适配：为 Claude Code、Codex、Hermes、OpenClaw 编写适配器，将原生日志映射到统一 schema，去除时间戳等非语义元数据。
- 标签协议：\(y \in \{0,1\}\)，0 为安全，1 为不安全。标签关注智能体**行为**而非仅出现风险内容：
  - 遇到恶意指令但拒绝执行，标为安全；
  - 实际尝试或执行未授权/有害动作、泄露敏感信息、生成可操作有害产物等，标为不安全。
- 行为—内容区分：仅观察风险内容不构成不安全；需至少一个工具调用或智能体产物构成面向安全目标的未授权动作。

### 2.3 生成式防护模型与 SFT

- 将轨迹序列化为 \(x = \text{Serialize}(\tau_{1:m})\)，并置于显式不可信数据边界内。
- 防护模型输出格式：
  - `<analysis> ... </analysis> <label>safe|unsafe</label>`
  - 即 \(z = [z_{\text{rat}}; z_{\text{ver}}]\)，理由用于审计，末端判定用于下游控制。
- SFT 阶段：
  - 对目标响应做自回归似然训练，仅计算助手 token 损失。
  - 因判定 token 占比小，对最后 \(K_{\text{ver}}=12\) 个 token 上权重 \(\omega_{\text{SFT}}=4\)。
  - 损失为加权 token 负对数似然归一化形式。

### 2.4 Guard Policy Optimization（GuardPO）

- **问题**：标准 token 均值优化中，长理由因 token 多而获得更大聚合权重，尽管每个响应只对应一个安全决策。
- **决策级结果**：解析模型输出判定 \(\hat{y}_i \in \{0,1,\perp\}\)，定义奖励：
  - 判定正确：\(R_i = +1\)；
  - 判定错误：\(R_i = -1\)；
  - 格式错误：\(R_i = -\gamma\)，\(\gamma = 1.25\)。
- **序列优势**：对 rollout batch 计算均值 \(\bar{R}_B\)，每个响应优势 \(\hat{A}_i = R_i - \bar{R}_B\)，并广播到该响应所有有效 token。
- **裁剪 token 更新**：使用类似 CISPO 的裁剪重要性权重：
  - 计算 \(\rho_{i,t} = \pi_\theta / \pi_{\text{old}}\)；
  - 裁剪到 \([1-\epsilon, 1+\epsilon]\)，\(\epsilon=0.1\)；
  - token 损失 \(\ell_{i,t} = -\text{sg}(\tilde{\rho}_{i,t}) \hat{A}_i \log \pi_\theta\)。
- **决策归一化目标**：对每个响应，分别计算理由区域 \(R_i\) 和判定区域 \(V_i\) 的平均 token 损失：
  - \(M_i(S) = \frac{1}{|S|}\sum_{t\in S}\ell_{i,t}\)；
  - 总损失 \(L_{\text{GuardPO}} = \frac{1}{N}\sum_i [M_i(R_i) + \lambda_{\text{ver}} M_i(V_i)]\)；
  - 使用 \(K_{\text{ver}}=12\)，\(\lambda_{\text{ver}}=2\)。
- **长度不变性命题**：若将某响应理由 token 复制 \(q\) 倍，其 GuardPO 贡献不变；而标准 token 均值目标会因此增大该响应在 batch 中的权重。因此 GuardPO 使优化单元由“生成长度”转为“安全决策”。
