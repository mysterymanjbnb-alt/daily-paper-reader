## 摘要
多租户工具通常接受租户标识符，并依据调用方的授权对其进行验证。对于大型语言模型（LLM）智能体而言，这种模式将资源选择委托给一个其上下文可能包含攻击者控制指令的进程。我们将这一随机代理人问题形式化，并提出一种结构性防御：从模型上下文协议（MCP）工具模式中移除租户身份，将作用域绑定到经验证的凭证，并在智能体之下强制执行。在涵盖八种模型配置和两种传输方式的 373 次试验消融中，正确验证的租户参数放行了每一次超出作用域的尝试：26/26，或在所有 41 次貌似合理的借口试验中占 26 次。移除该参数后，没有任何工具签名能够表达该读取操作。56 次试验中有 12 次转而通过伪造可写作用域逃逸出接口，表明接口不变性需要受密码学保护的上下文。在包含数 GB 数据的生产数据集上，在函数包装的成员资格谓词下，集合值作用域导致测得 57 倍的延迟比；在租户键已建立索引之处，JSON_TABLE 横向连接恢复了索引访问。该评估还揭示了部署限制，包括权限规模导致的查询规划器断崖和不完整的索引覆盖。这一结果是一种租户隔离论证：它依赖于可强制执行的接口与凭证，而非模型遵从性。

## Abstract
Multi-tenant tools commonly accept a tenant identifier and validate it against the caller's entitlement. For a large language model (LLM) agent, that pattern delegates resource selection to a process whose context may contain attacker controlled instructions. We formalize this stochastic deputy problem and present a structural defense: remove tenant identity from the Model Context Protocol (MCP) tool schema, bind scope to a verified credential, and enforce it below the agent. In a 373-trial ablation across eight model configurations and two transports, a correctly validated tenant parameter served every out-of-scope attempt: 26 of 26, or 26 of 41 plausible-pretext trials overall. With the parameter removed, no tool signature could express the read. Twelve of 56 trials instead escaped the interface by forging writable scope, showing that interface invariance requires cryptographically protected context. On a production dataset containing multiple GBs of data, set-valued scope caused a measured $57\times$ latency ratio under function-wrapped membership predicates; a JSON_TABLE lateral join recovered index access where the tenant key was indexed. The evaluation also exposes deployment limits, including an entitlement-size query-planner cliff and incomplete index coverage. The result is a tenant-isolation argument that depends on enforceable interfaces and credentials rather than model compliance.

# 《The Stochastic Deputy: Structural Tenant Isolation for Tool-Using LLM Agents》论文中文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：多租户服务的通行实现是"参数中介授权"（parameter-mediated authorization）——调用方在请求参数中声明自己要操作的租户 `t`，服务校验 `t ∈ E(p)`（p 的授权租户集合）后返回数据。该模式的隐含前提 (P) 是：`t` 由调用方**程序文本**决定，攻击者不控制该文本或凭证就无法影响 `t`。
- **问题**：LLM 智能体通过 MCP 或类似函数调用接口发起工具调用时，参数值是**模型输出的采样结果**，其条件上下文窗口在现实部署中部分可被攻击者触及（直接/间接提示注入）。前提 (P) 失效。
- **后果（式 (1)）**：单次成功注入的爆炸半径不再是"用户当前所在租户"，而是调用方的**全部授权范围**：
  `Reachable(p) = ⋃_{t ∈ E(p)} Rows(t)`
  对拥有大范围授权的投资组合运营者而言尤为严重。
- **"随机代理人"定义**（Definition 1）三要素：
  1. 委派权限——代理人掌握比当前请求更广的资源集合并自行选择；
  2. 非确定性选择——选择由无正确性保证的过程产生，n 次测试只能界定一个比率而非排除某种可能性；
  3. 信道混淆——指令与数据共用同一信道，攻击者可与会话主体的指令"竞争"。
- **核心立场**：不要试图让智能体"只请求它被授权的东西"，而要让这个请求**无法被表达**，并把边界放在智能体触及不到的地方。安全结论应独立于模型是否被说服。
- **意义**：把 Saltzer & Schroeder 的完全中介与最小权限原则、NIST SP 800-207 的零信任思路推进到 LLM 工具接口设计层面；作者强调其"集合值作用域"的数据库结论（第 5 节）独立于 LLM，对任何多租户系统都适用。

## 2. 方法论

### 2.1 核心思想
- 从工具 schema 中**删除租户标识参数**，作用域改为从**密码学验证的凭证**（JWT/JWKS）推导，并在**智能体之下**（数据库引擎或应用统一关口）强制执行。

### 2.2 五条不变量
- **I1 接口不变性**：任何工具 schema 都不接受能选择租户的参数（如 `get_reservations(status, date_from, limit)`，而非含 `hotel_id`）。安全内容是"表达力"的陈述：合法工具调用语言中不存在请求其他租户数据的句子。
- **I2 密码学上下文绑定**：`E(p)` 仅来自对 IdP 公钥（JWKS）验签后的令牌声明；反向代理**无条件剥离**客户端自带的身份头。权限以组声明 `/tenants/<id>/<role>` 传递。
  - 两个真实缺陷：Unicode 数字混同（Python `\d` 匹配阿拉伯-印度数字，`int()` 折叠为同一租户 → 限定 `[0-9]` 并禁止前导零）；畸形授权必须**拒绝而非跳过**（唯一例外是不声称授权的中间节点路径）。
- **I3 强制执行点迁移**：租户谓词置于工具实现之下，使工具无法发出缺少该谓词的查询。
- **I4 传递性作用域闭包**：查询中每个可达的租户所属关系（含 JOIN 表）都必须带谓词。把 JOIN 变成"声明式对象"而非 SQL 片段，由 builder 自动附加租户等值、软删除过滤、审计记录。
- **I5 出口边界最小化**：在唯一序列化函数处无条件脱敏（按列名匹配，偏向过度遮蔽）；姓名按目的限制原则不遮蔽，联系方式与出生日期遮蔽；**无关闭开关**。

### 2.3 两个强制执行点（设计空间）
| 维度 | A：引擎级（definer 视图 / RLS） | B：应用关口 |
|---|---|---|
| 谓词所在 | 视图或 RLS 策略 | 单一应用模块 |
| DB 变更 | 每表视图 + 辅助函数 | 无 |
| 遗漏谓词 | 不可能 | `TypeError` 崩溃 |
| 作用域可否篡改 | 否（只读会话上下文，引擎 A） | 是（会话变量） |
| 绕过后果 | `ERROR 1142` | **读到所有租户的 1 行** |

- 关口实现：`GuardedCursor.execute(query)` 只接受 `Query` 对象，传原始 SQL 抛 `TypeError`；`Query` 只能由携带授权、无条件追加谓词的 builder 生成，无未限定模式、无禁用开关。
- 实现**拒绝启动**除非运维显式指定 A 或 B（不存在默认值）。

### 2.4 安全论证与四项假设
- 论证三步：I1 → 作用域不是 σ 的函数；I2 → 作用域等于 `E(p)`；I3+I4 → 所有返回行属于 `t ∈ E(p)`，即作用域限定（Definition 3）。
- 四项显式假设：①完全中介；②授权映射正确（只强制语法不强制事实）；③连接生命周期内作用域完整（MySQL 用户变量无只读模式，A3 不成立）；④无会话状态复用（**连接每请求、禁用连接池**）。
- 作者明确声明：这不是机器验证的证明，只有静态分析与端到端运行测试支撑。

### 2.5 集合值作用域与索引可搜索性（关键工程贡献）
- 集合值作用域不能内联为字面量 `IN` 列表（那会重新把谓词交回应用），只能经会话变量或函数传递，而**函数包裹的列不可 sargable**，退化为扫描。
- 四种编码：E1 `JSON_CONTAINS`、E2 `MEMBER OF`、E3 `FIND_IN_SET`（三者都包裹列）、E4 `JSON_TABLE` 侧连接（不包裹列，把集合物化为 `|S|` 行的派生表后做等值 JOIN）。
- 原理：成员测试等价于半连接；E4 让优化器从小的派生表驱动，对每个作用域元素做一次索引 `ref` 查找。
- 异质键类型：一个遗留租户键为文本类型，整型绑定会强制转换并放弃 seek；builder 因此对该作用域按字符串绑定并在 `JSON_TABLE` 中固定排序规则。

  - 断崖与复合索引修复**只是诊断，未实测**（副本只读，无法建索引）；引擎 A 的 `ERROR 1142` 仅在本地实例观测，未上生产主库。
  - 未测量端到端工具延迟（含模型推理），未与竞争性隔离架构做同 schema 对比。

## 6. 主要结论与发现

- **接口不变性有效但不充分**：Arm A 中被正确校验的租户参数**放行了全部越权尝试（26/26）**；在 41 次貌似合理的借口试验中占 26 次（63%，CI 48–76%）。移除参数后，**没有任何工具签名能表达越权读取**（Arm B 全部 56 次借口试验在接口层被拒，无一次命名其他租户的调用被接受）。
- **但 12/56 次试验以伪造作用域绕过接口**（Gemini 11/13、GPT 1/13；Claude 0/13）：5 次在别处新建作用域文件，7 次**原地覆盖**自己持有的作用域文件。作者的第一版检测器只看路径，只找到 5/12；按"调用时实际生效的作用域"重算才全部找回。结论：**I1 与 I2 必须联合**，接口不变性需要密码学保护的上下文。
- **行为抵抗不是授权边界**：Arm A 限定下 132 次试验泄漏 46 次（35%）；早期 GPT 与 Gemini 配置对权威载荷 18/18、18/18 全部顺从，而当前 GPT-5.6 三档 0/15 全部拒绝。抵抗性随提供方、代际、档位、发布版本与攻击向量漂移；且**抵抗性不随能力单调**（最强结果来自最大模型，次强来自 3B 最小模型，作者不认为后者是原则性拒绝）。
- **环境能力是必要条件而非充分条件**：受控配对显示同一模型在有/无 shell 时均 0/15 伪造——能力设定上限，倾向决定行为，而倾向恰是安全保证不能依赖的属性。
- **数据库性能结论**：
  - 函数包裹谓词导致 57× 延迟比；`JSON_TABLE` 侧连接在租户键有索引处恢复索引访问（优化器工作量降低 99.92%），但不比手写 `IN` 更快（中位慢 27.6 ms，25 轮中仅胜 9 轮）。
  - 该收益**以索引为前提**：约 4/5 表可 seek，约 1/5 无租户索引的表全部退化为 `ALL`。
  - 部署所用的 B 点（内联 `IN`）更贵：452 ms 对 65 ms 裸谓词；开销分解显示**软删除过滤占 91%（346/387 ms）**，ghost guard 仅 9%（36 ms）——修复合索引 `(team_id, deleted_at)` 即可，但未能实测。
  - **规划器断崖**：|S| 在 10→15 之间 B 点放弃租户索引，延迟从约 1 s 跳到 10 s；A 点在 1–200 全程保持 `ref` 访问，|S| = 20 时 B 点约慢 6.5×。**更强的执行点也是更快的**。
  - 连接每请求开销 638 ms（≈21.3× 一次典型查询），作者撤回此前"可忽略"的说法。
- **威胁模型的经验支持**：约 2/5 的表间关系至少一次跨租户；最高频关系跨租户率 15.72%（同一源表另一关系仅 0.0014%）；抽查的跨租户记录全部同时含姓名与电话；大量可空租户键（某高频表 >3/4 行租户键为 NULL，对两种执行形式都不可见——fail-closed 但使聚合不完整）。

- **失败模式与残余风险**：
  - **作用域文件伪造是接口不变性之外的主要残余攻击面**。12/56 次越权成功的共同特征是攻击者未改变工具调用本身，而是改变了"调用时系统读到的作用域来源"（新建或原地覆盖文件）。这说明 I1 只能保证"合法调用语言中不存在越权句子"，无法保证"系统实际求值的作用域等于 E(p)"——后者必须由 I2（不可伪造、由代理层剥离客户端头、密钥验签）承担。作者的检测器教训（只看路径 → 漏掉 7/12；按调用时实际生效作用域重算 → 全部找回）本身构成一条方法论警告：**安全测量的判定口径必须与实际求值语义对齐，而非与日志中的表面字段对齐**。
  - **空租户键（NULL）行的可见性悖论**：某高频表超过 3/4 行的租户键为 NULL，这些行对两种强制执行形式都不可见。行为上是 fail-closed（不会泄漏），但使聚合、计数、报表等**功能正确性受损**，且无法用"是否泄漏"这一单一指标刻画。作者将其列为需要产品决策的开放问题（补数据 vs 放宽谓词 vs 显式标注为共享行），而非纯安全缺陷。
  - **授权映射的正确性完全未被机制覆盖**：五条不变量只强制"语法"——即谓词与令牌声明一致、不可篡改、不可省略；但"组声明 `/tenants/<id>/<role>` 是否真的对应该用户在该租户中的合法角色"属于 IdP 与配置治理，机制层无力校验（对应假设 A2）。作者明确承认这是设计边界，而非可修补的实现漏洞。
  - **连接生命周期与连接池**：由于 MySQL 用户变量无只读模式，A3（连接内作用域完整）不成立，唯一可行对策是每请求新建连接、禁用连接池，代价是 638 ms/请求（≈21.3× 一次典型查询）。这意味着**在不支持只读会话上下文的引擎上，该方案的性能与安全不可兼得**，作者选择牺牲性能。

## 7. 局限性、可迁移性与讨论

- **单系统、单引擎族的证据基础**：全部经验数据来自一个商业物业管理部署（MySQL 8.0 共享 schema）与一个 SQL Server 本地实例。规划器断崖位置（|S| ∈ (10,15)）、索引覆盖比例（约 4/5 可 seek）、软删除过滤占比（91%）都是**该 schema、该优化器、该数据分布下的观测值**，不可直接外推为通用常数。作者对此的态度是"报告比值与访问路径，而非绝对延迟"。
- **统计功效不足的部分**：开权重模型 n = 2（qwen3:4b、llama3.2:3b），其置信区间几乎不含信息；Arm C（提示词防御）仅覆盖两家提供方；MCP/CLI 传输配对与有无 shell 的受控配对**只在 Claude 上完成**。因此"行为抵抗不是授权边界"这一核心论点虽有强证据支持，但**抵抗率的量化估计**并不稳健。
- **未实测项**：复合索引 `(team_id, deleted_at)` 的修复效果、规划器断崖的修复验证、引擎 A 的 `ERROR 1142` 在生产主库上的行为，均因只读副本限制或范围控制而未实测，仅作诊断。
- **未覆盖的对照**：未测量端到端工具延迟（含模型推理时间），也未与竞争性隔离架构（如每租户独立 schema、独立数据库、行级加密）在**同一 schema 与同一数据分布**下对比。因此论文能证明"该方案优于参数中介"，但不能证明"该方案优于所有替代隔离架构"。
- **可迁移性主张的边界**：作者刻意区分了两类结论——(a) **集合值作用域与索引可搜索性**的数据库结论（第 5 节），明确声明**独立于 LLM**，对任何"作用域需从凭证推导、且不能内联为字面量"的多租户系统成立；(b) **随机代理人威胁模型**与不变量集合，则依赖于"参数值由无正确性保证的采样过程产生"这一前提，适用于 MCP 类函数调用接口。这种分层表述使论文的适用范围可被读者自行裁剪。
- **对"提示词防御"的定位**：作者不主张放弃提示词硬化，而是主张**不将其计入安全边界**——提示词防御可作为纵深防御的一层，但其效果随提供方、代际、档位、发布版本与攻击向量漂移，且**不随能力单调**（最强结果来自最大模型，次强来自 3B 最小模型，作者拒绝把后者解释为原则性拒绝）。安全结论因此必须独立于"模型是否被说服"。

## 8. 结论与启示

- **一句话结论**：把租户作用域从**可被采样的参数**搬回**密码学验证的凭证**，并在智能体之下强制执行，可使越权读取在**接口层不可表达**、在**引擎层不可绕过**；且更强的强制执行点（引擎级 A）恰好也是更快的（1–200 全程保持 `ref`，|S| = 20 时比 B 点快约 6.5×）。
- **三条可迁移的设计原则**：
  1. **表达力即安全边界**——"合法调用语言中不存在越权句子"比"模型承诺不写越权句子"强得多；安全内容应是接口签名与查询 builder 的属性，而非模型行为。
  2. **不变量必须联合**——I1（接口不变性）单独不足，12/56 次伪造证明 I1 与 I2（密码学上下文绑定）必须同时成立；同理 I3 与 I4 必须联合才能闭合传递性作用域。
  3. **拒绝默认值**——系统在运维未显式指定 A 或 B 时**拒绝启动**；出口脱敏**无关闭开关**；畸形授权**拒绝而非跳过**。这三处"不提供便利"的设计，是让安全结论独立于运行时配置与人为疏忽的关键。
- **对评测方法的启示**：以**服务器审计日志**而非模型自述判定、以**轮询交错**替代块计时、在合并数据前做**传输差分测试**、对"环境能力是否为原因"做**受控配对**、并主动**撤回**自己早期的错误结论（连接开销"可忽略"、开销主要来自 ghost guard、`JSON_TABLE` 快于 `IN`）——这些做法共同构成一套值得复制的"自我纠错"实验纪律。
- **开放问题**：空租户键行的语义归属、授权映射的治理校验、在不支持只读会话上下文的引擎上如何兼顾连接池与作用域完整、以及跨引擎（MySQL / SQL Server / 其他）的规划器行为一致性。
