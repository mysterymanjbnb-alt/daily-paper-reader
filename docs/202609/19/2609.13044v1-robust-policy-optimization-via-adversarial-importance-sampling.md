## 摘要
在保护深度强化学习（DRL）策略免受输入扰动影响方面已取得显著进展。开发鲁棒的 DRL 涉及三个主要阶段：算法设计、实现和评估。在本工作中，我们识别并解决了每个阶段的一个关键局限。首先，我们提出对抗重要性采样（Adversarial Importance Sampling, Advis），一种通过对标准训练得到的轨迹进行重要性采样，来估计并优化可验证最坏情况回报的方法。Advis 满足先前工作未能同时实现的三项理想标准：无需额外环境交互、无需辅助网络，并且能够捕捉长期鲁棒性。其次，我们提出 advrl，一个模块化的 PyTorch 库，为现有鲁棒性方法和对抗攻击提供简洁的单文件实现，促进快速原型设计，并支持可复现且可追溯的评估。第三，我们重新审视在学习型对抗者下的评估，并表明最优对抗超参数无法在不同智能体之间迁移，这在使用有限攻击者配置时可能导致对鲁棒性的高估。因此，我们使用比先前工作多 6–14 倍的配置，针对大量且多样的攻击者评估策略。最后，我们在连续控制环境中评估我们的方法，展示其相对于现有基线的有效性。代码见：https://github.com/AmineAndam04/advrl

## Abstract
Significant progress has been made in safeguarding deep reinforcement learning (DRL) policies against input perturbations. Developing robust DRL involves three main stages: algorithm design, implementation, and evaluation. In this work, we identify and address a key limitation at each stage. First, we introduce Adversarial Importance Sampling (Advis), a method that uses importance sampling over trajectories from standard training to estimate and optimize verifiable worst-case returns. Advis satisfies three desirable criteria not jointly achieved by prior work: it requires no additional environment interactions, no auxiliary networks, and captures long-term robustness. Second, we introduce advrl, a modular PyTorch library that provides clean, single-file implementations of existing robustness methods and adversarial attacks, facilitating rapid prototyping and enabling reproducible and traceable evaluations. Third, we revisit evaluation under learned adversaries and show that optimal adversarial hyperparameters do not transfer across agents, which can lead to an overestimation of robustness when using a limited set of attacker configurations. Accordingly, we evaluate policies against a large and diverse set of attackers, using 6-14x more configurations than prior work. Finally, we evaluate our approach on continuous control environments, demonstrating its effectiveness relative to existing baselines. The code is available at: https://github.com/AmineAndam04/advrl

- **核心问题**：作者指出这三个阶段各自存在一个关键局限，且此前工作未能同时解决：
  1. **算法层面**：现有方法往往需要额外环境交互（如用 DRL 训练对抗者）、需要训练辅助网络（估计最坏情况回报或学习对抗策略），或只关注单步鲁棒性而忽略扰动的长期累积效应。
  2. **实现层面**：现有代码库递归、单体化（一个 `agent.py` 混杂多种算法与评估），存在论文伪代码与实现不一致、继承性 bug（如 SA-Reg 的 SGLD 实现错误被后续代码库沿用）、依赖已废弃的旧版 MuJoCo（-v2）等问题。
  3. **评估层面**：针对"学习型对抗者"的鲁棒性评估高度依赖对抗者训练超参数，而最优对抗配置在不同防御算法之间**不可迁移**，导致用有限攻击者集合评估时会**高估鲁棒性**。
- **整体含义**：论文试图在算法、实现、评估三个维度上统一改进鲁棒 DRL 研究，提出一种既无额外采样、又无辅助网络、且显式优化长期最坏情况回报的方法，并强调评估方法的可靠性。

## 2. 方法论

### 2.1 核心思想

- 将两种技术结合：**神经网络的凸松弛（convex relaxation）** + **重要性采样（importance sampling, IS）**。
- 给定策略 π，用凸松弛计算可证明的最坏情况策略分布 **π_wc**（即最优对抗者下智能体会遵循的策略）；随后用 IS 从**标准 DRL 训练中已采集的轨迹**估计 π_wc 的折扣回报，并将其作为鲁棒性目标在训练中优化。
- 关键优势：复用已有轨迹（无额外环境交互）、无需训练额外网络、通过轨迹级回报估计自然捕捉长期鲁棒性。

### 2.2 关键技术细节

- **最坏情况策略构造**：对高斯策略 π(·|s)=N(μ_θ(s), Σ_θ)，凸松弛得到均值向量的逐元素上下界 [μ_θ, μ̄_θ]，再按优势符号构造：
  - 当 A_t > 0（有利动作）时取使动作概率最小的均值 μ⁺；
  - 当 A_t ≤ 0 时取使概率最大的均值 μ⁻；
  - 即 π_wc(a_t|s_t) = N(a_t; μ⁺_θ(s_t), Σ_θ) 或 N(a_t; μ⁻_θ(s_t), Σ_θ)。
- **IS 估计**：重要性权重 ρ^advis_t(τ) = ∏_{k=0}^{t} π_wc(a_k|s_k)/π(a_k|s_k)。
- **三种鲁棒损失（编码不同归纳偏置）**：
  1. **最大化最坏情况表现**：L = −Ĵ(π_wc)
  2. **最小化回报差异（MSE）**：L = (J(τ) − Ĵ(π_wc))²
  3. **仅惩罚性能下降（ReLU）**：L = max(0, J(τ) − Ĵ(π_wc))
- **方差与分布失配的处理**：
  - **ε-scheduling**：训练中逐步增大攻击预算 ε，早期限制 π 与 π_wc 的偏离。
  - 采用比普通 IS（OIS）低方差的估计器：**PDIS**（无偏、低方差）、**WIS**、**WPDIS**（有偏但一致、方差显著更低）。
  - 在**采样轨迹窗口**（而非完整轨迹）上计算，缓解"horizon 诅咒"。
  - 数值稳定：PDIS 截断重要性权重，WIS 用 log-sum-exp 技巧。
- **理论支撑（Lemma 1）**：OIS 估计器的方差满足 Var[Ĵ_IS] ≤ ‖R‖²_∞/N · d₂(p(.|π_wc), p(.|π))，其中 d₂ 为指数化 2-Rényi 散度；该散度可用重要性权重高效估计（见 Eq. 17）。选择 Rényi 散度作为轨迹级差异度量可同时改善鲁棒性与稳定性。

### 2.3 配套工具

- **advrl**：模块化 PyTorch 库，提供各鲁棒方法与对抗攻击的**单文件干净实现**，支持标准化配置、可控随机种子、可移植 checkpoint、CPU 多核并行评估与详细日志。
- 实现层面还修正/改进了若干细节：SA-Reg 的 SGLD bug 修正、新增 Power Iteration 方法、Radial 按论文而非代码库的损失实现、WocaR-RL 支持 IBP/CROWN/CROWN-IBP 且不再固定 ε=0.01 等。

- **对比方法（防御基线）**：SA-Reg、Radial、SA-ATLA、PA-ATLA、WocaR-RL，以及本文 **Advis**。所有方法独立训练（不再像先前工作那样把 SA-Reg 损失叠加到其他方法）。
- **攻击者（benchmark 中的攻击套件）**：

## 6. 主要结论与发现

- **Advis 在多个环境的最坏情况鲁棒性上一致最优**：在 HalfCheetah 与 Hopper 中，Advis 在全部 α 范围内 CVaR 曲线均占优；Walker2d 表现更微妙——小 α（极端尾部）优于 SA-Reg，大 α 则相反，说明算法排名会随风险偏好变化。
- **最优对抗超参数不可跨防御迁移**：top-5% 最强 PA-AD 配置在不同防御之间的 Jaccard 相似度很低（对角线 1.00，非对角线多在 0.00–0.17），证明用少量攻击配置评估会高估鲁棒性。
- **均值/中位数会误导鲁棒性排序**：在 432 个 PA-AD 攻击下，最鲁棒（无灾难性失败）的智能体在均值/中位数上并非第一，需采用最小回报或 CVaR 等尾部敏感指标。
- **Grid search 未被 random search 超越**：在同等超参数域内，随机搜索（预算最高 56）未找到比网格搜索更强的攻击，但随预算增加会趋近网格搜索强度。
- **IS 估计器**：加权变体（WIS、WPDIS）通常优于 PDIS，尤其在小 α 下；WPDIS 方差最低。**对抗损失**：无单一损失在所有环境一致最优，需按环境调参。

## 7. 优点

- **方法层面**：首次同时满足三项理想标准——无需额外环境交互、无需辅助网络、显式优化长期最坏情况回报；用 IS 复用已有轨迹，样本效率高；对 IS 高方差问题给出了系统化处理（ε-scheduling、PDIS/WIS/WPDIS、窗口化、数值稳定技巧），并有 Lemma 1 的方差上界理论支撑。
- **实现层面**：advrl 库提供单文件、模块化、可复现、可追溯的实现，并主动指出并修正了前作中的实现 bug（如 SGLD 错误）与伪代码/代码不一致问题，对社区有实用价值。
- **评估层面**：揭示"对抗超参数不可迁移"这一被忽视的方法学问题，用 6–14 倍攻击配置规模进行评估，并倡导使用 CVaR 等尾部风险指标，显著提升鲁棒性评估的可靠性。
- **实验公平性**：所有方法同等训练步数、相同网络结构、统一超参数搜索流程，并独立训练以避免损失项混用带来的混淆。

## 8. 不足与局限

- **覆盖范围有限**：仅针对连续控制 MuJoCo 三环境与 PPO 策略优化范式，未验证离散动作、离线 RL、其他策略优化算法（如 SAC/TD3）或高维视觉输入场景。
- **算力报告不充分**：仅说明使用 Intel Xeon Platinum CPU，未给出 GPU/CPU 数量、总机时等，影响可复现性与成本评估。
- **性能权衡**：Advis 在部分环境的自然（无攻击）回报低于某些基线（如 HalfCheetah 中 WocaR-RL 自然回报 5666 vs Advis 4781），鲁棒性与清洁性能间存在权衡；Walker2d 上并非全面占优。
- **调参与计算开销**：凸松弛（CROWN 等）计算成本较高；对抗损失需按环境选择，增加调参负担。

- **评估的对抗者仍受限于搜索空间**：虽大幅扩大配置数，但仍基于预定义的网格/对数均匀分布，可能存在未覆盖的更强攻击；且作者也指出自动超参数调优尚未集成。
- **应用限制**：方法聚焦状态观测扰动（ℓ∞ 有界），未涵盖动作空间攻击、奖励投毒等其他威胁模型。
