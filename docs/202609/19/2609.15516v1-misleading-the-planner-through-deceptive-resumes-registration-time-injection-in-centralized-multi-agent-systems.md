## 摘要
基于 LLM 的集中式多智能体系统（MAS）通过注册新的工作智能体来扩展功能，其描述由规划器读取，以决定任务如何分解、由哪个工作智能体执行每个子任务，以及每个子任务需要什么。第三方描述由系统外部编写，却被规划器信任，从而形成注册时注入通道。攻击载荷在任何用户指令到达之前就被植入，针对规划器，并通过生成的计划传播到良性工作智能体，即使该精心构造的工作智能体从未被分配子任务或从未被调用，也能生效。我们定义了四个工作智能体描述字段：功能、输入规范、输出规范和使用约束。在来自三个公开智能体市场的 32,000 条描述中，大多数省略了输入规范和使用约束，而至少 23.35% 包含这些字段之外的内容。我们构建了八种针对任务分解、能力接地和子任务规范的描述操纵攻击策略，并在 GAIA 上进行评估。在最严重的情况下，单条被操纵的描述将任务成功率从 84.31% 降至 37.25%，或将 token 消耗或执行时间增加超过 111%，而用户目标保持不变，且工作智能体忠实地执行生成的计划。这些影响在两种 MAS 实现、六种规划器 LLM、四种 LLM 评估器以及来自三个市场的真实描述中持续存在。我们进一步提出 DescGuard，一种注册时防御方法，在描述到达规划器之前仅保留工作智能体作用域内的接口信息。DescGuard 在不修改工作智能体实现、规划器或编排逻辑的情况下，将受影响的规划指标和下游性能恢复至接近其基线水平，并且可与现有的隔离、权限控制和运行时机制组合使用。

## Abstract
A centralized LLM-based multi-agent system (MAS) extends its functionality by registering new worker agents, whose descriptions are read by the planner to decide how a task is decomposed, which worker executes each subtask, and what each subtask requires. Third-party descriptions are authored outside the system but trusted by the planner, creating a registration-time injection channel. The payload is planted before any user instruction arrives, targets the planner and propagates through the generated plan to benign workers, taking effect even when the crafted worker is never assigned a subtask or invoked. We define four worker-description fields: functionality, input specification, output specification, and usage constraints. Among 32,000 descriptions from three public agent marketplaces, most omit input specifications and usage constraints, while at least 23.35% contain content outside these fields. We construct eight description-manipulation attack strategies targeting task decomposition, capability grounding, and subtask specification, and evaluate them on GAIA. In the most severe cases, a single manipulated description reduces task success from 84.31% to 37.25%, or increases token consumption or execution time by over 111%, while the user objective remains unchanged and workers faithfully execute the resulting plan. These effects persist across two MAS implementations, six planner LLMs, four LLM evaluators, and the real-world descriptions from three marketplaces. We further propose DescGuard, a registration-time defense that retains only worker-scoped interface information before descriptions reach the planner. DescGuard restores the targeted planning metrics and downstream performance toward their baseline levels without modifying worker implementations, the planner, or the orchestration logic, and composes with existing isolation, permission-control, and runtime mechanisms.

## 1. 核心问题与研究背景

- **系统背景**：基于 LLM 的集中式多智能体系统（MAS）采用"规划器 + 多个工作智能体（worker）"的层级结构。规划器读取每个 worker 的自然语言描述，据此决定：任务如何分解、每个子任务由谁执行、每个子任务需要什么。
- **结构性缺陷**：worker 描述由系统**外部**的第三方提供者单方撰写，却在系统**内部**被规划器当作可信的规划输入逐字读入，且未经净化、未与规划器自身指令分离。文档被当作指令消费，形成一条**注册时注入通道（registration-time injection channel）**。
- **攻击的四个特殊性**（区别于用户输入、检索内容、工具输出引发的 prompt injection）：
  - 载荷在任何用户指令到达**之前**植入，一次注册可污染此后所有用户请求，而非单个会话；
  - 目标是**规划器**本身，而非某个 worker；
  - 影响经由**生成的计划**传播，在第一次 agent 间通信之前就已到达良性 worker；
  - 位于隔离、沙箱、权限中介、运行时监控的**上游**，这些机制都在规划之后才生效。
- **关键性质**：被构造的第三方 worker **无需被分配子任务或调用**即可生效——损害由忠实执行被污染计划的良性 worker 造成。这与 ACE、ToolHijacker 等"被操纵组件既是载荷又是受益者"的工作形成本质区别。
- **整体含义**：worker 描述应被重新定位为**安全敏感的编排输入**，必须在 MAS 的信任边界上加以约束。

## 2. 方法论

### 2.1 形式化建模

- 规划过程：`π = p(x, D)`，其中 `x` 为用户请求，`D` 为规划器可见的 worker 描述集合，`π` 为生成的计划。
- 计划的分析表示：`π = (S, E, g, U)`
  - `S`：子任务集合；`E ⊆ S × S`：子任务间依赖关系 → 对应**任务分解**
  - `g: S → A`：子任务到 worker 的分配函数 → 对应**能力接地**
  - `U = {u_s}`：各子任务的具体规格 → 对应**子任务规格**
  - 该分解仅为分析用途，不假设规划器显式物化这些中间输出。
- 威胁模型：用户请求良性；规划器、底层 LLM、worker 实现、工具接口、系统提示、运行时配置均**可信**；攻击面仅限规划器可见的 worker 描述。篡改函数 `τ` 下 `d'_i = τ(d_i)`（i ∈ I），否则 `d'_i = d_i`，`π' = p(x, D')`。攻击者可克隆并重发布市场 worker，或直接发布新 worker。

### 2.2 描述即接口：四字段定义

借鉴软件接口声明组件功能与调用需求的原则，定义 worker 描述应提供的四类信息：

- **功能（Functionality）**：能做什么（如分析图像内容）
- **输入规范（Input Specification）**：接受什么形式的输入（如可访问的图像路径、Base64 编码图像）
- **输出规范（Output Specification）**：产生什么形式的结果
- **使用约束（Usage Constraints）**：使用条件（如需要网络连接、输入文件需置于可访问路径）

四字段同时界定了**必须提供什么**与**不应包含什么**：描述应限定于 worker 自身，不应规定规划器如何分解任务、由谁执行子任务、或任何其他 worker 该做什么。

**实证测量**：从 GPT Store（n=20,000）、Coze（n=8,000）、Baidu Wenxin（n=4,000）共采样 32,000 条描述，用 LLM-as-a-judge 检验。结果显示：功能几乎全部陈述，但输入规范缺失 ≥89.73%、输出规范缺失 ≥74.82%、使用约束缺失 ≥94.61%；**≥23.35% 含四字段之外的内容**（无界能力声明、直接对规划器说的话等）。这意味着恶意描述**不会在良性描述中显得突兀**。

### 2.3 两条防御原则

- **原则一**：内容的保留或丢弃应依据**其描述的是谁的行为**。
- **原则二**：重述后的描述**只应为其命名的 worker 说话**。
- 重要推论：由于 adversary 的立足点在于接口**之外**的内容（而非缺失字段），任何处理都应致力于**移除多余内容**，而非填补缺失字段。
