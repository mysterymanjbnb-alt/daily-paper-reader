## 摘要
由工具增强的大语言模型（LLM）智能体能够通过工具调用作用于外部系统，从而自动化复杂的多步骤任务，如网页导航、代码生成和工作流编排。然而，LLM中的幻觉、分布不稳定性与对抗性操纵，以及某些工具调用的不可逆后果，可能导致有害结果。现有防护措施要么使用随机LLM评判器对记录轨迹进行事后评分，要么一次一个调用地阻止不安全动作，且没有单一确定性构件能同时支持这两种角色。我们提出ContrAgent，一个基于契约的、用于LLM智能体符号时序监督的框架。ContrAgent将智能体的行为捕获为一系列工具调用，并将其形式化为在固定可检查谓词集合上的迹（trace）。然后，它使用有限迹线性时序逻辑（LTLf）中的假设-保证契约来规约所需行为。每个契约都被编译为一个确定性有限自动机（DFA），该自动机承担两种角色：在线门控智能体动作，以及离线评估记录的迹。一个契约库作为可复用的知识库，独立于智能体的模型进行维护，并可应用于同一任务领域内的不同智能体。我们在涵盖这两种角色的四个基准上展示了该方法的有效性；在这些基准上，ContrAgent与最先进的LLM评判器和基于规则的防护栏基线相当，同时产生确定性、可复现的判定，并且在线模式下每次调用的延迟降低了数个数量级。

## Abstract
Large language model (LLM) agents augmented by tools can automate complex, multi-step tasks, such as web navigation, code generation, and workflow orchestration, by acting on external systems through tool calls. However, hallucinations, distributional instability, and adversarial manipulations in LLMs, and the irreversible consequences of certain tool calls can lead to harmful outcomes. Existing safeguards either grade recorded trajectories post hoc with stochastic LLM judges or block unsafe actions one call at a time, and no single deterministic artifact supports both roles. We present ContrAgent, a contract-based framework for symbolic temporal supervision of LLM agents. ContrAgent captures an agent's behavior as a sequence of tool calls and formalizes it as a trace over a fixed set of checkable predicates. It then specifies required behaviors using assume-guarantee contracts in linear temporal logic over finite traces (LTLf). Each contract is compiled to a deterministic finite automaton (DFA) that serves two roles: gating agent actions online and evaluating recorded traces offline. A contract library, acting as a reusable knowledge base, is maintained independently of the agent's model and can be applied across different agents within the same task domain. We show the effectiveness of our approach on four benchmarks spanning both roles, where ContrAgent matches state-of-the-art LLM-judge and rule-based guardrail baselines while producing deterministic, reproducible verdicts and, in the online mode, orders-of-magnitude lower per-call latency.

## 1. 核心问题与研究动机

- **背景**：工具增强型 LLM 智能体（如 OpenClaw、HermesAgent、LangChain）通过工具调用接口（shell 命令、API、MCP）作用于外部系统，能自动化网页导航、代码生成、工作流编排等复杂多步任务。
- **风险来源**：LLM 的幻觉、分布不稳定性、对抗性操纵（间接提示注入），加之某些工具调用的**不可逆后果**，可能导致有害结果。典型失效模式包括间接提示注入、绩效压力下的指标刷分（metric gaming）、危险代码执行、跨委派智能体的身份混淆。
- **现有防护的两难**：
  - **事后评判**类（LLM-as-judge、学习型检测器如 PolicyGuard、AgentPex）：判定随机、难以复现，安全性判断尤其不稳。
  - **实时拦截**类（AgentSpec 等逐动作规则、信息流控制类 Progent/CaMeL/RTBAS/Fides）：只判断单个动作，无法覆盖跨轨迹性质（顺序、历史、计数）；或依赖语义意图、或依赖特定智能体模型。
- **核心缺口**：**没有任何单一确定性构件能同时承担"在线门控"和"离线评分"两种角色**。
- **整体含义**：论文借鉴信息物理系统（CPS）中的假设-保证（A/G）契约式设计，提出 **ContrAgent**——一个基于契约、模型无关、确定性的 LLM 智能体符号时序监督框架。

## 2. 方法论

### 核心思想
把智能体的工具调用行为抽象为**可检查谓词上的有限迹（trace）**，用 **ALTLf（算术线性时序逻辑，有限迹）** 的 A/G 契约规约轨迹级要求，再编译为 **DFA**，同一套 DFA 既在线门控又离线评分。

### 关键技术细节

- **会话形式化（Def. 1）**：会话为转移系统 T=(S, s₀, Σ, R)。每个工具调用产生两个事件——调用事件 a=(tool, args) 与返回事件 a′=(tool, result)。状态 s:=(τ, κ, ρ)，含已发生事件迹 τ、上下文映射 κ（跨事件事实，如调用者身份）、数值计数器向量 ρ（如 token 消耗）。

- **交互谓词（Def. 3，Table 1）**：定义在会话状态 s、事件 a、参数 c 上的确定性布尔谓词，分两族：
  - **结构谓词**：Call(T)、ArgHas(T,f,p)、OutHas、Said/In、Match、Subset、Flow(s,d)、Perm(P) 等，纯离散条件匹配，无模型介入。
  - **数值谓词**：形如 θ(s,a) ▷◁ c（Cnt(T)、Num(T,f)、Tok 等），由监控器在计数器 ρ 上确定性累积更新，将逻辑从命题 LTLf 提升到 ALTLf。

- **智能体契约（Def. 4）**：三元组 C=(V, φA, φG)，V=Vag∪Venv 为谓词集合（受控/非受控变量划分，对应契约设计中的 controlled/uncontrolled variables）。φA 是 Venv 上的 ALTLf 假设，φG 是 V 上的保证。

- **运行时三值语义（Def. 2）**：对具体迹 τ，契约取值 ∈ {IDLE=1, ACTIVE=e, FAIL=0}：
  - τ ⊨ A → 1；τ ⊨ A∧G → e；τ ⊭ A∧G → 0。

- **轨迹监督问题（Problem 1）**：对契约集 C={Cᵢ}，
  - venv(τ)=⋁ᵢ⟦(Aᵢ,Gᵢ)⟧(τ)，vag(τ)=⋀ᵢ⟦(Aᵢ,Gᵢ)⟧(τ)。
  - **在线执法**：σ: Σ*→{pass, block}，在第一个 v(τₖ)≠(e,e) 的前缀处 block。
  - **离线评估**：μ: Σ*→{0,e,1}²，返回末端判定。

- **契约编译（§5.1）**：
  - **契约形成**：采用 lift-then-ground 分解，LLM 先把自然语言/政策文档提升为带占位叶的 ALTLf 模板，再由确定性步骤把占位符落地到固定谓词词表；公式可回译自然语言供人工审阅。
  - **自动机构造**：每个公式经标准 LTLf→DFA 构造，字母表为 2^V。数值谓词在 grounding 时对计数器求值，计数器状态**不进入 DFA 状态**，保证 DFA 有限。
  - **契约库**：编译后的 checker 构成模型无关、可跨智能体/模型迁移的契约库；加载时检查一致性、兼容性，以及库的**无冲突性**（⋀ᵢ(Aᵢ∧Gᵢ) 可满足），冲突时用极小不可满足核（mus2muc）定位需修复契约。

- **运行时监督（§5.2）**：
  - 调用执行**前**推进所有契约，首个异常事件即 block；会证伪保证的调用被拒绝，会证伪假设的返回/输入事件被**抑制**（双向运行时执法）。被抑制事件不记录，会话从最后一个 (e,e) 前缀继续。
  - 采用**增量残余公式推进**（而非整 DFA 合成），每次事件代价 O(|C|)，与迹长度无关。
  - 违规处置策略：默认 block、重定向到安全替代、升级人工；回传结构化消息（契约 ID、解释、建议替代动作）。
  - 支持**主动提示**：满足触发条件时提示智能体执行必需工具；对 G(trig→F resp) 类活性保证，会话结束时将未决保证作为反馈抛出，未满足则坍缩为 FAIL。
  - **离线评估**：重放记录迹，DFA 只建一次可复用，每事件 O(1) 查表，判定确定可复现，并给出逐契约归因。

## 6. 主要结论与发现

- **SOPBench**：ContrAgent 保持 base 级成功率（均值 91%→90%），把安全率从 32% 提到 **98%**（高于 prompt 的 94%）；prompt 与 LLM-guard 虽安全率高（94%/98%），但因过度拦截把成功压到 64%/24%。运行开销 +0.135s，低于 prompt(+0.905s) 与 LLM-guard(+1.34s)。
- **模型无关性**：换到弱模型 gemini-2.5-flash-lite，prompt 的安全率从 94% 崩到 45%，而 ContrAgent 保持 **98% 不变**（判定由迹确定，不由智能体推断）；23 个模型中 19 个假阳性率 <1%（最高 4.5%，Llama-3.1-8B）。
- **约束规模扩展**：约束数增长时 prompt 成功率从 87% 崩到 18%、base 安全率从 79% 崩到 0%，而 ContrAgent 全程成功 ≥77%、安全 ≥89%。
- **AgentDojo**：ND 把 ASR 从 18.0% 降到 5.3%（效用 FP 0.8%）；TL 降到 **1.7%**（FP 0.3%）。gpt-4o 上 ND 使 ASR 47.7%→11.1%（效用 71.8%，仅少完成 1 个任务），TL 达 **0.79%** 且效用与无防护持平；两者仅增加 **0.16 ms/调用**，对比分类器约 50ms、LLM filter 约 500ms。漏检中 82% 根本不发恶意工具调用（DoS 式转移或文本回复攻击），18% 的参数本身合法而无可标记的不可信目标。
- **R-Judge**：平均 F1 **91.8%**（P 97.0%、R 87.0%），超过 GPT-4o（74.4%）与人类基线（≈89%）；漏检属语义而非过程性，超出确定性工具调用检查能力。
- **τ²-bench**：揭示**奖励黑客**现象——Claude 3.7 的 outcome pass⁴ 达 25–60%，但 joint⁴ 在三个领域全为 **0%**，即没有任何任务能在不违反过程规则的前提下可靠完成（proc-clean⁴ 全为 0%）。
- **总体结论**：契约库是独立于模型、可跨智能体复用的知识库，为 LLM 智能体提供确定性、可复现、可逐契约归因的时序监督，判定质量媲美 SOTA，在线延迟低数个数量级。

## 7. 优点

- **单一构件双角色**：同一份 DFA checker 同时支持在线门控与离线评分，在线重放与离线评估遍历相同状态、逐前缀判定一致，这是现有工作未能统一的。
- **模型无关与可移植**：契约写在交互谓词而非模型内部语义上，同一契约库可跨模型、跨智能体迁移，安全保证不随基座模型能力退化（弱模型实验中表现突出）。
- **确定性与可复现**：无 LLM 在环判定，跨种子偏差极小，且违规可**逐契约归因**（定位到契约与触发事件），便于区分是智能体流程、环境还是契约过严的问题。
- **效率优异**：增量残余公式推进，每事件 O(|C|)、与迹长无关；离线 O(1) 查表；0.16ms/调用量级。
- **形式化严谨**：A/G 契约 + ALTLf + 三值运行时语义 + 双向执法（拒绝调用 / 抑制返回），并有库级无冲突性检查与极小不可满足核定位；附录还给出与无状态 guard 的四类时序表达性对照。
- **主动性与可修复反馈**：不仅拦截违规，还能基于满足的触发条件主动提示下一步动作，并把结构化拒绝消息回传使智能体回到安全区。

## 8. 不足与局限

- **表达边界**：只能执法"工具调用结构所暴露"的性质，**自由形式的语义危害需另设内容级检查**；R-Judge 的漏检即为语义残留。
- **人工在环**：本文中契约库使用前需人工审阅，自然语言政策的**自动形式化超出本文范围**，留作未来工作。
- **可信执行假设**：grounding 数值谓词的计数器**信任框架忠实上报事件**，观测通道本身的防护不在范围内。
- **算力信息缺失**：未报告构建契约库所用 LLM 推理的算力/成本；评测硬件仅为单台笔记本，未见大规模部署开销评估。
- **评测偏差风险**：AgentDojo/τ²-bench 为迹重放，基线取自已发表数字而非同条件重跑，跨方法比较存在口径差异；R-Judge 的对比方 AgentAuditor 使用了更强的 judge + 检索记忆，不完全对等。
- **覆盖缺口**：AgentDojo 上仍有约 82% 漏检属"根本不发工具调用"的攻击类型，说明工具调用层盾牌对纯文本/DoS 类注入无能为力。
- **契约维护成本**：需为每个领域/工具接口手工（或半自动）构建契约与谓词 grounding hook；冲突检测、一致性检查虽已工具化，但契约覆盖率不足（SOPBench 残差约 25%）仍会限制召回。
- **未来方向**（作者提出）：将契约编译为 reward machine 用于后训练与约束解码；面向多智能体系统的契约分解机制。
