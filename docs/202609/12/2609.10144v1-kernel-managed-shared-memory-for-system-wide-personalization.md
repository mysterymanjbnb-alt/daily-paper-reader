## 摘要
AI 系统在能够适应其使用者时会变得更有用，但在多智能体系统中，一个智能体学到的有用上下文往往无法被其他智能体使用。我们提出内核管理共享内存，这是一种系统级抽象：专用智能体写入结构化、带标签的记忆，而由智能体系统内核（而非单个智能体）管理检索、隐私执行和提示注入。我们在 AIOS 上实现并评估该设计，并在三个助手模型（GPT-4o、Llama-3.1:8B、Qwen-2.5:7B）和总计 1,800 次试验中将其与三种替代方案进行比较。在与使用相同底层存储的非托管外部记忆后端（Mem0）对比时，内核管理的检索与注入将个性化得分在 5 分制上提高 2.4-4.0 分（例如，GPT-4o 上的 profile usage 从 1.05 提高到 4.69），所有比较均在 p < 10^-18 下显著。与标准检索增强注入相比，其增益同样很大，并在所有三个模型上保持一致。与完整、未过滤的上下文拼接（其限制的是可用上下文的软上限，而非响应质量）相比，内核管理的注入在三个模型中的两个上统计上匹配其性能，并在第三个上表现出小的、模型特定的性能缺口，同时使用显著更短的提示：所有三个模型的端到端延迟降低 15-61%，并相应减少每次调用的 token 使用量和推理成本。这些结果表明，将记忆管理集中到智能体系统内核中，而不是将检索和隐私执行留给单个智能体，能够以一小部分成本实现无约束上下文的大部分个性化收益。

## Abstract
AI systems become more useful when they can adapt to the people using them, but in multi-agent systems, useful context learned by one agent often remains unavailable to others. We present kernel-managed shared memory, a system-level abstraction in which specialized agents write structured, tagged memories while the agent-system kernel, not individual agents, governs retrieval, privacy enforcement, and prompt injection. We implement and evaluate this design on AIOS and compare it against three alternatives across three assistant models (GPT-4o, Llama-3.1:8B, Qwen-2.5:7B) and 1,800 total trials. Against an unmanaged external memory backend (Mem0) using identical underlying storage, kernel-managed retrieval and injection improve personalization scores by 2.4-4.0 points on a 5-point scale (e.g., 1.05 to 4.69 profile usage on GPT-4o), with every comparison significant at p < 10^-18. Against standard retrieval-augmented injection, gains are similarly large and consistent across all three models. Against full, unfiltered context concatenation, a soft ceiling on available context rather than on response quality, kernel-managed injection statistically matches performance on two of three models and shows a small, model-specific deficit on the third, while using substantially shorter prompts: end-to-end latency is 15-61% lower across all three models, with corresponding reductions in per-call token usage and inference cost. These results indicate that centralizing memory management in the agent-system kernel, rather than leaving retrieval and privacy enforcement to individual agents, delivers most of the personalization benefit of unconstrained context at a fraction of its cost.

# 论文总结：Kernel-Managed Shared Memory for System-Wide Personalization

## 1. 核心问题与研究动机

- **背景**：个性化是 AI 系统实用性的关键，尤其在多智能体（multi-agent）系统中，不同智能体各自学到用户上下文的不同片段（如 ProfileAgent 学稳定偏好、TaskAgent 学当前任务、AssistantAgent 直接面向用户）。
- **核心问题**：这些上下文通常彼此隔离，导致系统无法作为一个整体给出一致的个性化行为；若把记忆管理交给各智能体自行处理（agent-managed memory），会造成检索/过滤/注入逻辑在各智能体间重复实现，隐私执行仅靠"约定"，极易出错。
- **整体含义**：作者主张把个性化从"应用层重复逻辑"提升为"系统层能力"——即由 agent-system kernel（而非任何单个智能体）统一治理写入顺序、隐私执行、检索、排序与提示注入。论文的总体判断是：内核集中管理能以远低于"无约束全上下文"的成本，拿到其大部分个性化收益。

## 2. 方法论

### 2.1 核心思想

- 提出 **kernel-managed shared memory** 这一系统级抽象，并在 **AIOS**（LLM agent 操作系统式框架）上实例化；作者强调该抽象不绑定 AIOS，任何具备共享内存后端与受控 prompt 构造路径的多智能体运行时都可实现。
- 系统模型：智能体集合 $A=\{a_1,\dots,a_n\}$ 与记忆库 $M$；查询 $q=(a_i,u,x)$；记忆项 $m=(u,o,t,s,c)$，其中 $u$ 为用户标识、$o$ 为 owner agent、$t$ 为记忆类型（profile / task_context / conversation）、$s$ 为共享策略（private / shared）、$c$ 为内容。
- 智能体分工：**ProfileAgent** 抽取稳定用户属性，**TaskAgent** 抽取短期工作上下文，**AssistantAgent** 为"无检索消费者"（不自行检索、不自行构造个性化提示，全部经内核注入）。

### 2.2 关键技术细节

- **用户身份解析**：按显式优先级统一在内核边界解析 $u$——请求附带的标识符 → 最近注册的会话标识符 → 历史标识符回退注册表 → 请求智能体自身标识符（最后手段）。用于关闭并发试验下的跨用户污染类 bug。
- **五步内核操作**：(1) 对目标用户强制 write-before-read 顺序；(2) 检索候选 $R=\text{search}(M,u,x)$；(3) 按可见性规则过滤；(4) 按语义相关性与 token 预算排序截断；(5) 注入 $x'=\text{inject}(x,R_k)$，作为系统调用路径的一部分而非应用层提示拼装。
- **可见性规则与隐私不变量**：`visible(m, a_i)` 为真当且仅当 $o=a_i$，或 $s=\text{"shared"}$；共享策略缺失/畸形/显式 private 一律视为 private。形式上对任意 $o(m)=a_j\neq a_i$ 且 $s(m)=\text{private}$ 的记忆，在所有执行历史下 `visible(m,a_i)=False`——这是一个**无条件成立的安全性（safety）属性**，与下面只在一定超时内成立的一致性属性不同。
- **写屏障（write-ordering guarantee）**：写入受理时按 `user_id` 打上单调递增序号 $\sigma(w)$；检索时取该用户当前最高序号快照 $\sigma^*(u)$，阻塞直到所有 $\sigma(w)\le\sigma^*(u)$ 的写入被确认排空，默认超时 5000 ms，超时后 **fail-open**（优先活性）。保证 $r$ 观察到 $\{w:o(w)=u,\ \sigma(w)\le\sigma^*(u)\}$ 或超时。只做单用户作用域内的 read-after-write 一致性，无全局锁。
- **格式化**：结构化存储不等于结构化注入——早期实验显示原始 JSON 对小型本地模型难以使用；内核用 `format(c_m)` 把 profile/task 记忆渲染为自然语言陈述，结构化形式保留用于检索与审计（作为独立消融）。
- **两阶段跨智能体检索**：先取 agent-scoped 记忆并推断 `user_id`，再取其他智能体的共享记忆；本地找不到用户时回退到全局已知用户注册表，实现零样本跨智能体个性化。
- **系统调用接口**：MemoryManager（address_request、register_user_id、stamp_barrier）、Mem0Provider、ContextInjector、MemoryWriteBarrier（acquire/release/snapshot/wait_until_drained）、MemoryFormatter、ConversationExtractor；智能体从不直接调用 provider 或 barrier，从而可替换 provider / 检索策略 / 超时而不改 agent 代码。
- 配置：`auto_extract: true`、`auto_inject: true`、相关性阈值 0.3、最多注入 10 条、记忆 token 预算 2000、写屏障 5000 ms；**纯推理时，无需重训练**。

## 3. 实验设计

- **数据/场景**：无公开数据集，采用合成评测。每次试验生成一个合成用户画像、一段合成任务上下文，以及一个**刻意欠指定**的追问（如 "What should I focus on next?"），使个性化内容必须来自注入记忆而非查询本身。
- **Benchmark 构造**：自建 harness，记录注入记忆数、跨智能体检索、个性化得分与延迟；每试验由 **GPT-5.4** 在 1–5 分制上评三个维度：Profile Usage、Task Usage、Integration（画像与任务信息是否被连贯结合）。使用与被评模型均不同的 GPT-5.4 作唯一裁判，以规避自偏好效应。
- **对比方法（4 种）**：
  - `naive_concat`：完整合成 profile/task 上下文直接拼接，无检索无过滤（可用上下文的软上限，非响应质量上限）；
  - `vanilla_rag`：上下文分块索引后 embedding 检索 top-k；
  - `mem0_default`：使用 Mem0 外部记忆后端、仅 private、无内核编排/写序/跨智能体共享；
  - `kernel_shared`：本文方法。
- **模型**：GPT-4o、Llama-3.1:8B、Qwen-2.5:7B（能力梯度）。
- **规模**：12 个 (模型 × 方法) 条件 × 150 试验 = **1800 次试验**。
- **统计检验**：Welch's t 检验、Mann–Whitney U、bootstrap 95% CI（九个模型×维度对比）。
- **人类验证**：盲评子集 30 个 GPT-4o 试验（每方法 6 个唯一项共 24 项 + 6 个重复项测评分者内一致性），单评分者按同一 1–5 量表评 Integration 维度。

## 5. 实验数量与充分性

- **主实验**：12 个条件 × 150 试验 = 1800 次，覆盖 3 个模型能力档位，跨模型结论较稳健。
- **对比充分性**：设置了四类方法，其中 `mem0_default` 与 `kernel_shared` 使用**同一底层 provider**，因此能干净地隔离"写序 + 身份解析 + 隐私执行 + 跨智能体可见性"的贡献，而非"有没有注入上下文"这一混淆因素——这是设计上的亮点。
- **辅助实验/分析**：
  - 统计显著性全套：九个 (模型, 维度) 的 kernel_shared vs. naive_concat 对比（Welch / MWU / bootstrap CI）；
  - 延迟机制分析：按条件的输出词数、Welch 检验、条件内 word-count 与 latency 相关性（r = 0.52–0.86，p < 10⁻¹¹）；
  - 隐私经验验证：全 private 端点 450 试验 0/450 暴露；全 shared 端点 1,798 条被检索记忆中无一条为 private-by-default 的 conversation 类型；
  - 消融试点（Ablation Pilot，Qwen-2.5:7B，30 试验）：原始 JSON 注入 → +自然语言格式化 → +显式系统提示 → +HybridJudge；
  - 人类验证子集（30 试验）。
- **公平性与客观性**：
  - 优点：裁判模型与被评模型不同；有盲评人类验证；对基线不利的方向也如实报告（承认裁判**低估** vanilla_rag：人类 3.67 vs 裁判 2.17），即偏差方向是"不偏向本文方法"。
  - 局限：数据全为合成，无真实用户/公开基准；主实验只用单一 LLM 裁判；人类验证仅 30 项、单一评分者，无法计算评分者间信度（Krippendorff's α）；消融试点作者自承"早于主结果的验证流程、对中心主张无证据权重"；未做中间共享配置的扫描、未做对抗性查询 campaign、未测更大记忆库规模。

## 6. 主要结论与发现

- **相对无管理外部记忆后端（Mem0）**：内核管理检索与注入在 5 分制上提升 2.4–4.0 分（GPT-4o profile usage 1.05 → 4.69），全部比较 p < 10⁻¹⁸；由于二者共享底层存储，说明差距来自内核级写序/身份解析/隐私保证，而非"有记忆后端"本身。
- **相对标准 RAG 注入（vanilla_rag）**：增益同样大且跨三模型一致（p < 10⁻¹⁸，rank-biserial 0.44–1.00）。
- **vanilla_rag 的失败是架构性的而非能力性的**：profile 得分在三模型上几乎恒定（1.84 / 1.91 / 1.84），task 得分更高但也恒定（3.84 / 3.78 / 3.84）——因为追问更接近任务内容，检索系统性地丢弃 profile 分块，与模型能力无关。
- **相对全上下文拼接（naive_concat）**：GPT-4o 的 Profile/Integration 与 Qwen-2.5:7B 全部三维度统计持平；GPT-4o Task 上更高（p = 0.006）；Llama-3.1:8B 的 Task/Integration 上显著更低（rank-biserial 0.13–0.19，且无法用规模解释）。九项对比中六项置信区间跨零。
- **成本优势**：端到端延迟全部降低 15–61%（GPT-4o 7.5s vs 19.2s；Llama 21.7s vs 25.5s；Qwen 26.3s vs 36.3s），token 使用与推理成本相应下降。GPT-4o/Qwen 上 naive_concat 输出显著更长（+159、+83 词，p < 0.0001），Llama 上输出长度无显著差异（p = 0.27）却仍快 15%，指向输入侧节省。
- **总体结论**：把记忆管理集中到 agent-system 内核，能以一小部分成本实现接近无约束上下文的个性化收益，并比无管理后端或朴素 RAG 更可靠；劣势被限制为"对未过滤上下文的一个小的、模型特定的缺口"。

## 7. 优点

- **抽象层次清晰**：把检索、隐私、格式化、注入提升为内核系统调用，而非各 agent 的应用层重复逻辑；provider、检索策略、超时可插拔而无需改 agent 代码。
- **隐私被表述为内核不变量（安全性属性）**：默认 private、元数据静态判定、单点强制，使"某个 agent 省略自己的过滤逻辑"不再能造成泄露，并以双端点经验数据（0/450；1,798 条中无 conversation 泄露）佐证。
- **写屏障设计务实**：按 user_id 作用域的序号 + 高
