## 摘要
将大型语言模型（LLMs）集成到安全运营中心（SOCs）中可简化威胁情报处理，但也会引入关键漏洞，尤其是通过日志投毒实施的间接提示注入。攻击者利用这一途径，通过将恶意载荷嵌入系统日志来劫持 LLM 的运行逻辑，从而执行多步“promptware”杀伤链。保护这一流水线面临两难：确定性防御计算高效但语义盲区，而纯神经评估则带来难以承受的延迟和概率性缺陷。为解决此问题，我们提出一种新颖的神经符号纵深防御架构，确保端到端流水线完整性。主层采用定制的 SIEM 解码器作为确定性预过滤器，在摄取边缘执行即时结构化清洗，以消除体积填充和基于签名的注入。次级层利用 NeMo Guardrails，在 LLM 处理之前对结构化 SIEM 告警进行自检式验证，从而强制执行严格的语义边界。此外，该框架集成闭环遥测系统，在 SOC 仪表板中直接为被阻断攻击提供关键的人在回路（HITL）可见性。我们提出了一套映射到 MITRE ATLAS 分类体系的综合实验评估，针对多种提示注入评估该框架。结果表明，这种协同方法能有效瓦解 promptware 杀伤链——以可验证约束限制 LLM 随机性，并为下一代 AI-SOC 提供弹性且高度可观测的防御机制。

## Abstract
The integration of Large Language Models (LLMs) into Security Operations Centers (SOCs) streamlines threat intelligence but introduces critical vulnerabilities, notably indirect prompt injection via log poisoning. Adversaries exploit this vector to execute multistep ``promptware'' kill chains by embedding malicious payloads within system logs to hijack the LLM's operational logic. Securing this pipeline presents a dichotomy: deterministic defenses are computationally efficient yet semantically blind, while purely neural evaluations introduce prohibitive latency and probabilistic flaws. To address this, we propose a novel neurosymbolic defense-in-depth architecture that ensures end-to-end pipeline integrity. The primary layer employs customized SIEM decoders as a deterministic pre-filter, performing immediate structural sanitization to neutralize volumetric padding and signature-based injections at the ingestion edge. The secondary layer leverages NeMo Guardrails to enforce strict semantic boundaries through self-checking validation on the structured SIEM alerts prior to LLM processing. Furthermore, the framework integrates a closed-loop telemetry system, providing critical Human-in-the-Loop (HITL) visibility into thwarted attacks directly within the SOC dashboard. We present a comprehensive experimental evaluation mapped to the MITRE ATLAS taxonomy, assessing the framework against diverse prompt injections. Our results demonstrate that this synergistic approach effectively dismantles the promptware kill chain - bounding LLM stochasticity with verifiable constraints, and delivering a resilient, highly observable defense mechanism for next-generation AI-SOCs.

# 论文总结：《Architecting the Secure AI-SOC: A Neurosymbolic Framework for Pipeline Integrity and Threat Mitigation》

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM 被引入安全运营中心（SOC）以自动化网络威胁情报（CTI）分析、告警分诊与事件响应，形成所谓“AI-native SOC”，可显著降低分析师疲劳与响应延迟。
- **核心问题**：将关键分析任务委托给 LLM 引入了新的攻击面——通过**日志投毒（log poisoning）实现的间接提示注入**。攻击者将恶意载荷嵌入常规系统日志（如 HTTP User-Agent、认证错误信息、DNS 查询）或外部 CTI 数据源，当 SIEM 关联这些日志并送入 LLM 上下文窗口时，隐藏指令会劫持模型运行逻辑。
- **威胁演化**：提示注入已从孤立的输入操纵漏洞演化为多步恶意软件执行机制，即 **“promptware” 杀伤链**，涵盖初始访问、权限提升、持久化与目标行动，可能导致数据外泄甚至 SOC 生态系统内的远程代码执行。
- **防御两难**：
  - **确定性/结构性防御**（正则、签名过滤、plan-then-execute）：计算高效，但对复杂语义混淆“结构性失明”，需持续维护签名。
  - **神经防御/对齐**（对抗训练、指令层级、行为监控）：语义能力强，但概率性缺陷（幻觉、零日越狱）且延迟与算力开销巨大。
  - NeMo Guardrails 等可编程护栏若单独部署，易受体积填充攻击导致上下文耗尽与拒绝服务。
- **整体含义**：论文主张通过**神经符号纵深防御**在流水线中分散防御负担，避免单点失效，确保端到端流水线完整性。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：不抛弃传统清洗器，而是重新定位其角色——将 SIEM 层确定性过滤作为“符号层”，与 NeMo Guardrails“神经层”结构性耦合，形成职责严格分离的纵深防御。

- **Layer 1：基于 SIEM 的确定性预过滤（符号层）**
  - 在 Wazuh 摄入阶段、事件关联之前介入，避免载荷在事件聚合中被掩盖。
  - **载荷提取**：定制解码器（`local_decoder.xml`，基于 PCRE2）识别结构性异常、体积填充、已知规避编码（如 Base64），将恶意字符串隔离到专用动态字段 `llm_injection_payload`，同时保留取证元数据。
  - **原子规则评估**：如 Rule ID 100050（Level 10）在解码后立即评估隔离字段。
  - **主动响应（清洗）**：Rule 100050 触发后，脚本对载荷执行两步操作：① 严格截断超长载荷（缓解上下文耗尽 / AML.T0040）；② 用模式匹配替换指令覆盖、提示重写、权限提升等已知 promptware 语义为惰性安全标记（缓解 AML.T0051）。
  - 输出：结构化、归一化、长度受限的净化 JSON 告警。

- **Layer 2：基于 NeMo Guardrails 的语义自检（神经层）**
  - 作为 SIEM 与 LLM 之间的代理，用 Colang 定义规则，包裹认知引擎。
  - **输入 Rail（注入检测）**：LLM 对输入消息自检，若含指令覆盖、角色操纵、提示提取、未授权动作操纵（如 `action=delete_file`）、日志中嵌入的针对 AI 的指令，则返回 “Yes” 阻断。
  - **输出 Rail（响应验证）**：LLM 自检生成响应，若非法 JSON、缺 `action` 字段、`action` 不在批准集合（`block_ip`、`delete_file`、`kill_process`、`none`）、尝试执行任意命令/Shell、或幻觉出系统未执行的动作，则阻断。
  - 作用：用可验证约束限制 LLM 随机性，即使零日注入越过 SIEM 边界，动作与输出仍保持可验证、可预测、符合策略。

- **闭环遥测与 HITL**
  - 被阻断攻击不静默丢弃，而是生成结构化遥测记录，写入 `/var/ossec/logs/injection-alerts.log`。
  - 输入 Rail 返回 `SOC_INPUT_RAIL_BLOCKED`、输出 Rail 返回 `SOC_OUTPUT_RAIL_BLOCKED`，由 Python 编排器拦截并生成预定义回退 JSON 响应。
  - Wazuh 实时摄取该流，Rule ID 100300（Level 12）分类为 “llm/injection” 组，仪表板显示 `PROMPT_INJECTION_ATTEMPT` 及攻击者网络足迹（如 `src_ip`）。

- **MITRE ATLAS 映射**：框架显式拆解七阶段 promptware 杀伤链——SIEM 边缘拦截 Initial Access（AML.T0051）；神经护栏中和 Privilege Escalation（AML.T0054）、Reconnaissance、Retrieval-Dependent Persistence；输出验证切断 Lateral Movement 与 Actions on Objective（AML.T0053、AML.T0057、AML.T0040）。

## 3. 实验设计：数据集 / 场景、Benchmark 与对比方法

## 6. 主要结论与发现

- Layer 1 确定性预过滤成功拦截 **3/20** 注入尝试，体现其聚焦结构异常与显式签名匹配，而非深层语义分析。
- Layer 2 语义护栏成功识别并中和 **18/20** 对抗载荷，防御效能显著。
- 仍有 **2 个漏网**：1 个未授权工具滥用（横向移动）和 1 个复杂指令覆盖导致模型越狱，凸显纯神经层处理零日语义操纵时的概率性局限。
- 提出的改进方向：在 Colang 用户意图中直接加入被绕过载荷的具体对抗措辞、升级嵌入模型、动态收紧意图相似度阈值、在分类提示中集成少样本对抗示例、强制严格输出 Rail 作为最终失效保护。
- 总体结论：神经符号纵深防御可有效拆解 promptware 杀伤链，在摄入边缘中和体积填充、在 LLM 评估前拦截语义越狱，以可验证约束限制 LLM 随机性，并通过结构化遥测保持 HITL 可见性。

## 7. 优点（方法与实验设计亮点）

- **架构创新性**：将传统 SIEM 清洗器重新定位为确定性预过滤器，与神经护栏形成职责分离的纵深防御，避免单点失效，思路清晰且工程可行。
- **左移防御（shift-left）**：在 SIEM 摄入边缘、事件关联之前拦截，避免载荷在聚合中被掩盖，同时大幅降低下游神经层的计算负担与延迟。
- **可验证性与可观测性并重**：输出 Rail 用严格 JSON schema 与白名单动作集约束 LLM 行为；闭环遥测将阻断事件回灌 SIEM，解决自动化抑制的“黑箱”问题，保持分析师态势感知。
- **威胁模型严谨**：明确信任边界（外部不可信 / SIEM 半可信 / 认知域可信但脆弱），并覆盖日志投毒与 CTI 供应链/API 劫持两类向量。
- **标准化映射**：系统性映射 MITRE ATLAS 与 ATT&CK，使防御覆盖可审计、可对照。
- **原型完整**：给出具体 Wazuh 解码器、规则 ID、PCRE2 正则、NeMo 输入/输出/主动响应提示全文，具备较强可复现性。
