## 摘要
本文提出一个端到端评估框架，用于针对计算机使用智能体（CUA）的图像触发命令注入。目标是测试局部视觉补丁能否在截图输入、VLM生成、动作解析和环境执行的全链条中诱发可验证的环境后果。我们在作者控制的 GitHub Pages 页面和本地部署的 CSDN 克隆上训练并部署补丁，并在真实环境中跨五个开源或公开可用的 GUI 智能体或视觉语言模型（VLM）后端进行评估。我们的实验汇总了 600 个实例级在线案例，T-ASR、TAPR 和 E2E-ASR 分别达到 84.5%、47.0% 和 20.3%。轨迹分析进一步表明，在一些成功案例中，智能体先执行恶意终端命令，然后继续原本的良性任务。这些结果表明，优化后的局部视觉信号不仅会影响 VLM 输出，还会通过开放 CUA 的执行流水线传播，并造成真实环境风险。

## Abstract
This paper presents an end-to-end evaluation framework for image-triggered command injection against computer-use agents (CUAs). The goal is to test whether a local visual patch can induce verifiable environmental consequences along the full chain of screenshot input, VLM generation, action parsing, and environment execution. We train and deploy patches on author-controlled GitHub Pages pages and a locally deployed CSDN clone, and evaluate them in real environments across five open-source or publicly available GUI-agent or vision-language-model (VLM) backends. Our experiment aggregates 600 instance-level online cases, with T-ASR, TAPR, and E2E-ASR reaching 84.5%, 47.0%, and 20.3%, respectively. Trajectory analysis further shows that in some successful cases the agent first executes a malicious terminal command and then continues the original benign task. These results indicate that optimized local visual signals can affect not only VLM outputs but also propagate through the execution pipeline of open CUAs and create real environmental risk.

## 1. 核心问题与研究动机

- **背景演进**：计算机使用智能体（CUA）已从"界面理解"走向"界面执行"，能够把截图、网页与自然语言任务转化为浏览器、鼠标、键盘或终端动作（VisualWebArena、OSWorld、OpenCUA、UI-TARS 等）。
- **关键风险转移**：在此类系统中，VLM 的错误不再止步于"回答层"，而会经动作解析与环境执行传播，最终变成可观测的系统行为（文件、配置、服务状态的真实改变）。
- **已有研究缺口**：
  - 已有工作证明不可信网页内容、工具返回值可经间接提示注入影响智能体决策；
  - 细字体、弹窗、广告等"可见载体"也被证明可成为攻击面；
  - 但**尚缺乏对"可训练的视觉触发器能否穿过智能体流水线后段（动作解析、环境执行）"的系统性分析**。
- **本文定位**：研究一个更贴近运营风险的威胁场景——攻击者不在页面显式写入恶意文本，而是部署一个**训练好的局部视觉补丁**，诱导智能体执行涉及机密性（C）、完整性（I）、可用性（A）的终端命令。
- **核心追问**：优化后的视觉信号能否迫使 VLM 输出**与动作解析器兼容**的结果，从而真正改变环境状态？即关注"闭环执行风险"而非单纯的输出扰动。

## 2. 方法论

### 2.1 核心思想
- 提出 **AgentHijack 端到端评估框架**，采用**两阶段设计**：
  1. **离线补丁优化**：在作者可控网页截图上训练固定位置的局部补丁；
  2. **在线真实环境评估**：把训练好的补丁冻结后部署到真实任务工作流访问的网页中，记录从截图输入 → VLM 生成 → 动作解析 → 环境状态改变的完整轨迹。
- 该分离带来三点好处：离线可系统比较不同提示/截图/后端的命中率；在线更贴近"先发布、后观察"的真实威胁模型；便于分层归因失败发生在哪一环节。

### 2.2 形式化建模
- 将 CUA 建模为闭环系统 **A = (M, P, T)**，其中 M 为多模态模型、P 为动作解析器、T 为环境状态转移函数。
- 单步演化：
  - yt = M(It ⊕Ω δ, b, ht) —— 截图叠加补丁 δ（置于固定区域 Ω）后经 VLM 生成输出；
  - at = P(yt) —— 输出被解析为动作；
  - Et+1 = T(Et, at) —— 动作改变环境状态。
- **理想在线目标**：δ* = argmax_δ Pr[Gadv(ET) = 1 | b, I, δ]，即在补丁可行集 C 内最大化最终状态满足攻击评估器 Gadv 的概率。
- **离线代理目标**（因解析器与执行链不可微，改用目标字符串 s* 做代理监督）：
  - min_δ E_{i∈I, m∈M} L( m(i ⊕Ω δ), s* )，约束 ‖δ‖∞ ≤ ε。

### 2.3 关键技术细节
- **补丁规格**：尺寸固定 700×500，页面模板固定可见区域；GitHub Pages 场景固定左上角坐标 (361, 165)，CSDN 场景对齐训练模板的固定可见区域。
- **训练配置**：Adam 优化器，学习率 0.003，最大 9000 步，训练损失低于 0.01 时早停；L∞ 扰动预算 0.1255（约对应 8-bit 空间 32 个灰度级）。
- **目标监督方式**：仅监督目标字符串对应的 token 跨度，忽略提示词 token、模板分隔符与图像占位 token——因为攻击关心的是"输出可被解析的命令片段"，而非复现长模板回答。
- **统一模型适配层**：为不同 VLM 后端封装聊天模板、图像预处理、提示-目标对齐与目标 token 定位。
- **攻击设置**：train-on-target, evaluate-on-target（每个后端用自身优化的补丁攻击自身），而非代理模型迁移。

### 2.4 威胁模型
- **受害者/资产**：接收良性任务的 CUA；受保护资产为本地文件、配置状态、服务与任务完整性。
- **攻击者能力**：控制作者可控网页上一个可见图像区域；可为目标后端训练有界局部补丁并固定部署。
- **攻击者限制**：不能修改系统提示、用户指令、VLM 权重、动作解析器、环境控制器或最终评估器；不能直接执行命令或篡改日志；补丁只能经正常的"截图→动作"环路生效。
- **实验范围**：全部实验限于作者可控的 GitHub Pages、本地 CSDN 克隆、测试仓库、可恢复虚拟机与隔离环境。

## 6. 主要结论与发现

- **总体指标**：600 例中 T-ASR = 507/600（84.5%）、TAPR = 282/600（47.0%）、E2E-ASR = 122/600（20.3%）。
- **逐后端表现**：
  - Qwen3.5-4B 最强：89.2% / 66.7% / 55.8%；
  - Aguvis-7B：83.3% / 50.0% / 25.0%；
  - EvoCUA-8B：79.2% / 50.0% / 6.7%（损失主要在执行阶段）；
  - Qwen3.5-9B：70.8% / 43.3% / 14.2%；
  - UI-TARS-1.5-7B：T-ASR 100%，但 TAPR 仅 25.0%、E2E-ASR 为 0%。
- **核心发现**：指标呈**逐层一致衰减**（整体生成→解析落差 37.5 个百分点，解析→执行落差 26.7 个百分点）。**文本命中不等于可执行攻击动作，更不等于真实环境危害**——UI-TARS 的"高 T-ASR、零 E2E"即为典型反例。
- **失败归因**：离线训练在静态图上，在线需经网页渲染、视口裁剪、压缩与布局变化，触发模式被扰动；各后端有稳定失效签名（Aguvis 输出格式不匹配、EvoCUA 先观察后行动、Qwen 系可触发但不稳定而回退良性任务、UI-TARS 单帧强但闭环弱）。
- **成功案例**：智能体看到含补丁页面后立即 Ctrl+Alt+T 打开终端，输入预定义攻击命令，把目标文件复制到攻击者暂存目录，随后**回到原本的 tmux 安装良性任务继续执行**——攻击可作为"隐蔽辅助步骤"嵌入正常任务轨迹。
- **位置特异性**：补丁偏离训练坐标后命中率骤降为 0，说明攻击依赖精确空间对齐而非任意可见噪声。
- **防御启示**（表 5）：在网页输入层（来源标注、完整性校验）、VLM 输出层（任务一致性检查、危险命令检测）、动作解析层（终端调用/文件复制/配置写入/服务控制的专门门控）、环境执行层（权限分离、二次确认、沙箱）、审计层（保留截图、解析动作、日志与状态检查结果）分别设钩子。

## 7. 优点

- **分层指标设计**：T-ASR / TAPR / E2E-ASR 对应文本、动作、环境三个接口，明确回答了"单一 ASR 数字不足以刻画真实智能体风险"这一问题，能精确定位损失环节。
- **闭环真实环境验证**：不满足于离线输出扰动，而是打通截图 → VLM → 解析器 → 执行器 → 状态评估器的完整链路，危害由真实环境状态（文件存在性、配置内容、服务状态）判定。
- **任务体系结构清晰**：以 CIA 三元组组织 15 个对抗目标，覆盖复制、追加、覆写、删除、移动、停服务等动作族，并配有明确的环境级评估器。
- **对照实验严谨**：clean-patch、random patch、3×3 位置控制三重验证，有效排除"任意可见噪声即可触发"和"位置无关"的替代解释。
- **失败分析与审计链**：逐后端归纳失效签名，保留截图、解析动作、日志、状态检查的可审计证据链，支持后续系统级防御设计。
- **伦理边界明确**：全部实验限于作者可控环境与合成资产，不针对第三方平台或真实用户数据；同时以"支持更严格的评测与防御设计"定位自身工作。

## 8. 不足与局限

- **威胁模型偏强，外部效度受限**：全部实验采用 train-on-target（针对每个后端单独优化补丁），未评估跨模型迁移、黑盒查询或代理模型设定。这意味着结论只刻画了"攻击者已掌握目标 VLM 权重与提示模板"这一上限场景，无法回答现实中更常见的"未知后端 + 少量查询"条件下攻击是否仍成立。
- **未覆盖闭源/商用 CUA**：评估对象均为 4B–9B 开源模型，未涉及 OpenAI Operator、Claude Computer Use、Gemini 等真实生产级智能体。由于这些系统的输入分辨率处理、安全过滤、多步规划与人工确认机制差异较大，本文的 E2E-ASR 数值难以外推。
- **样本规模与统计严谨性不足**：每后端仅 120 例、总计 600 例，且**未报告随机种子、重复次数、置信区间与显著性检验**。因此逐后端排序（如 Qwen3.5-4B 优于 Aguvis-7B）可能受单次运行波动影响，差异的统计显著性无法判定。
- **缺少超参数消融**：补丁尺寸（固定 700×500）、L∞ 预算（0.1255）、优化步数（≤9000）、补丁位置、目标字符串长度等因素均未做敏感性分析，无法判断攻击成功对哪些设计选择高度敏感，也难以界定"最小可行攻击条件"。
- **补丁可见性带来隐蔽性质疑**：700×500 的补丁占网页可见区域相当大比例，在真实页面中属于高度显眼的异常元素。论文未讨论人类用户是否会察觉、是否会被常规页面完整性检查或视觉异常检测拦截，也未评估更小补丁或半透明/低频扰动下的性能折损。
- **防御钩子仅停留在设计层面**：第 8 节/表 5 提出的输入层、输出层、解析层、执行层、审计层防御均**未做任何实证验证**，既未量化各钩子的拦截率，也未测试攻击者针对防御的自适应绕过（如补丁训练时加入防御损失），因此防御建议目前只是方向性提示而非已验证结论。
- **离线—在线域差距削弱了攻击的稳定性**：训练在静态截图上完成，在线却需经历网页渲染、视口裁剪、图像压缩与布局变化，导致触发模式被扰动。这既是失败归因的核心，也说明当前攻击对渲染管线高度敏感，在动态内容多、分辨率多变的真实网页上可能进一步退化。
- **环境生态有效性有限**：测试环境为 GitHub Pages 镜像、本地 CSDN 克隆、隔离虚拟机等作者可控资产，网页结构与任务模板较规整；真实企业环境中的多标签页、弹窗、登录态、异步加载等复杂性未被纳入，可能同时低估执行难度与触发难度。
- **评估器与指标的代理性**：T-ASR 依赖目标字符串精确命中，可能低估语义等价但表述不同的成功输出；E2E-ASR 依赖任务特定评估器，其阈值与判定规则由作者定义，未做第三方复核或人工标注一致性检验。
- **未报告算力与训练成本**：如第 4 节所述，缺乏 GPU 型号、数量、时长等披露，使复现门槛与"攻击者可负担性"难以评估——这本身也是攻击可行性论证中的一块空白。
- **双用途风险披露较简略**：论文虽限定实验边界并定位为防御导向，但未深入讨论补丁训练流程的可迁移性、公开代码/补丁可能被滥用的风险，以及是否需要负责任的发布策略。

## 9. 讨论与启示

- **对风险度量的启示**：本文最有力的论点不是某个具体 ASR 数值，而是**"文本命中 ≠ 动作可解析 ≠ 环境危害"**的三级落差。仅以 VLM 输出层命中率报告智能体安全性的评测范式会系统性高估威胁（如 UI-TARS 的 100% T-ASR / 0% E2E-ASR），也会掩盖真正危险的中间环节——动作解析器的格式鲁棒性。
- **对系统设计的启示**：解析层与执行层是天然的"减速带"。由于 47.0% 的输出在解析阶段就被阻断，说明**严格的动作语法校验、白名单化工具调用、终端/文件操作门控**能在不牺牲太多可用性的前提下显著压缩端到端危害，是性价比最高的防御位点。
- **对评测方法论的启示**：CUA 安全评测应默认采用闭环、带环境状态判定的协议，并把"良性任务完成率"作为并行效用指标，以区分"攻击有效"与"智能体整体崩坏"两种不同性质的现象。
- **对攻击面认知的启示**：位置特异性实验（原坐标 91.67% vs 偏移位置 0/96）表明视觉补丁攻击依赖精确空间对齐，这既是攻击的脆弱点，也提示防御方可借助**布局稳定性检测**（如页面结构突变告警）来发现异常注入。

## 10. 可复现性与开放性问题

- **可复现性**：任务构造、目标字符串、评估器定义、优化超参数与判定协议描述较完整，具备基本可复现基础；但缺失随机种子、硬件配置、完整提示模板与补丁图像，实际复现仍需与作者联系或做大量逆向推断。
- **值得后续回答的开放问题**：
  1. 在仅黑盒查询、无权重访问的条件下，补丁能否通过迁移或查询优化达到可比 E2E-ASR？
  2. 加入渲染增强（随机裁剪、压缩、JPEG 噪声、布局抖动）做训练时，攻击的在线稳定性会提升多少？
  3. 针对表 5 的防御钩子，攻击者的自适应绕过代价有多高？
  4. 更小、更隐蔽（如 64×64 或低频纹理）的补丁是否存在可行折衷？
  5. 在真实生产级闭源 CUA 上，多步规划与人工确认机制会把 E2E-ASR 压到何种水平？

## 11. 总体评价

本文的价值在于**把一个容易被笼统讨论的问题拆解为可测量的三段链路**：它没有停留在"VLM 会被视觉扰动误导"的离线结论，而是以 AgentHijack 框架把补丁攻击推进到真实环境状态改变，并用 T-ASR / TAPR / E2E-ASR 三层指标与 clean-patch、random patch、3×3 位置对照，清楚地展示了危害在流水线中的衰减与瓶颈。其主要贡献是**问题定义、评测协议与失败归因**，而非攻击强度本身——20.3% 的端到端成功率、train-on-target 的强假设、偏小的样本规模与未验证的防御设计，都使其更像一份"风险存在性与评测方法论"的证明，而非一份可直接迁移的攻击配方。对智能体安全研究者而言，它最实用的产出是那条贯穿全文的结论：**在文本、动作与环境三个接口之间，每一层都会流失大量风险，而防御与评测都应把资源投向流失最剧烈的那一层。**
