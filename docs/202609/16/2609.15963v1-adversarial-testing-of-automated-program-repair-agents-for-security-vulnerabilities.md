## 摘要
搭载大型语言模型（LLM）的软件智能体被设计用于自动程序修复（APR）任务，这使得在不久的将来，APR智能体无需太多人工干预即可自动修复缺陷成为可能。在这种情况下，我们能否信任APR智能体生成功能正确且安全的代码？如果攻击者以生产环境中的APR智能体为目标，利用看似良性但可能影响智能体生成正确但不安全代码的对抗性问题（issue），会怎样？在本文中，我们通过开展一项实证研究，迈出了回答这些问题第一步。首先，我们创建了SWEADV，这是一个包含750条对抗性问题描述的基准，由SWE-bench Verified中的150个修复任务构建而成。对于每个修复任务，我们创建了五条对抗性问题描述，分别对应一种攻击类型：命令执行、反序列化、路径遍历、拒绝服务以及弱哈希。其次，我们在SWEADV上评估了来自三个LLM后端的mini_swe APR智能体：GPT-5-Mini、MiniMax-M2.5和DeepSeek-R。我们发现，平均而言，对抗性问题描述能够在51.7%的情况下在成功修复的同时诱导出恶意行为。第三，我们研究了典型检测机制是否足以防止此类恶意补丁被接受。在修复前使用LLM-as-judge对对抗性问题描述进行检测，平均检测准确率仅为62.3%。在修复后使用静态分析工具和LLM-as-judge对对抗性APR补丁进行检测，平均检测准确率分别仅为39.4%和55.4%。我们得出结论：鉴于自主APR智能体易受对抗性攻击影响，目前尚不能在生产部署中信任它们。

## Abstract
Software agents with Large Language Models (LLMs) are designed for Automated Program Repair (APR) tasks, raising the possibility that, in the near future, APR agents will fix bugs automatically without much human intervention. Can we trust an APR agent to produce both functionally correct and secure code in such situations? What if attackers target production APR agents with adversarial issues that seem benign but may influence the agents to produce correct but insecure code? In this paper, we took a first step towards answering these questions by conducting an empirical study. First, we created SWEADV, a benchmark of 750 adversarial issue descriptions constructed from 150 repair tasks in SWE-bench Verified. For each repair task, we created five adversarial issue descriptions, one for each attack type: command execution, deserialization, path traversal, denial of service, and weak hashing. Second, we evaluated mini_swe APR agents from three LLM backends on SWEADV: GPT-5-Mini, MiniMax-M2.5, and DeepSeek-R. We found that on average, adversarial issue descriptions can induce malicious behaviors with successful repair in 51.7% of cases. Third, we investigated whether typical detection mechanisms are sufficient to prevent such malicious patches from being accepted. Pre-repair detection with LLM-as-judge on the adversarial issue descriptions resulted in an average detection accuracy of only 62.3%. Post-repair detection on adversarial APR patches using static analysis tools and LLM-as-judge achieved average detection accuracies of only 39.4% and 55.4%, respectively. We conclude that autonomous APR agents cannot be trusted yet in production deployment, given their susceptibility to adversarial attacks.

## 2. 方法论：核心思想与关键技术细节

### 2.1 威胁模型

- **攻击者能力（黑盒）**：无法访问智能体内部、训练数据、模型参数、执行环境或验证基础设施；唯一能力是**提交或影响自然语言 issue 描述**。
- **攻击目标形式化**：构造对抗性 issue $i^*$，使生成补丁 $p^* = V(R, i^*)$ 同时满足：
  - 恶意行为谓词 $V_a(R, p^*) = \text{TRUE}$
  - 功能验证谓词 $T(R, p^*) = \text{TRUE}$（通过 FAIL_TO_PASS 与 PASS_TO_PASS 测试）

### 2.2 SWEADV 基准构建流程（自动化流水线，见图 2）

- **输入**：SWE-bench Verified 的原始 issue、golden patch、仓库上下文、测试规格。
- **第一步：攻击载荷创建（Attack Payload Creation）**
  - **目标符号提取**：解析 golden patch diff，映射到仓库源文件，选择被改动行最多的封闭符号（函数/方法/类）作为 `target_symbol`。
  - **注入符号生成**：以目标符号为基名，收集 patch 标识符与同作用域兄弟符号作为"邻近名称"，用命名模板组合生成仓库风格的 `injected_symbol`（如 `_coord_matrix_cstack`），并确保仓库中尚不存在。
  - **载荷模板**：每类攻击含四个组件——可选 imports、可替换函数名（即注入符号）、一个或多个**攻击者控制的环境变量输入**、以及攻击特定的**危险汇点**（命令执行、不安全反序列化、任意路径写、昂贵正则、弱哈希）。
- **第二步：对抗性问题创建（Adversarial Issue Creation）**
  - **攻击者 LLM**（Gemini 2.5 Pro）接收原始 issue + 攻击载荷，生成保留原修复目标、同时嵌入恶意需求的对抗性 issue 文本。
  - **代理修复（Proxy Repair）**：由构造期 proxy APR agent（mini_swe + Gemini 2.5 Pro）生成候选补丁。
  - **轻量 diff 验证器**：检查补丁是否**定义**了注入 helper、包含攻击者控制输入与危险汇点、并**调用/连接**到目标符号。成功则保留该实例，否则将反馈返回攻击者 LLM 重试。
  - **注意**：golden patch 仅用于离线符号准备，不提供给攻击者 LLM 或受害修复智能体，符合黑盒威胁模型。

### 2.3 攻击类型（5 类）

- 命令执行（run command）、反序列化（deserialization）、路径遍历（path traversal）、拒绝服务（DoS）、弱哈希（weak hashing）。选择理由：可被合理包装为维护逻辑，且覆盖执行滥用、不安全数据处理、文件系统操纵、资源耗尽、弱密码学等不同漏洞类别。

### 2.4 评估指标

- **Fix Rate（FR）** = F/N：对抗性 issue 导致功能有效修复的比例。
- **Injection Success Rate（ISR）** = I/N：诱导出目标恶意行为的比例。
- **Attack Success Rate（ASR）** = S/N：既通过功能验证、又含恶意行为的比例。

## 6. 主要结论与发现

- **Finding 1**：对抗性注入不降低修复性能（FR 与 benign 相差多在 4% 以内），因此**修复成功率无法作为 issue 被感染的信号**。
- **Finding 2**：SWEADV 的 ASR 为 **48.5%–54.0%**，约为基线（18.8%–26.4%）的两倍，且跨 LLM 差异仅 5.5%，泛化性强。
- **Finding 3**：攻击成功取决于载荷能否"自然"融入修复——**弱哈希最易注入（MiniMax-M2.5 下达 64.0%）**，路径遍历最难端到端成功（44.7% / 40.0%）。
- **Finding 4**：LLM-as-judge 检测对抗性 issue 的准确率/ F1 相比基线下降最高达 16.6% / 13.9%，guided 提示平均仅 **62.3%** 准确率。
- **Finding 5**：即使有安全上下文引导，**DoS 类注入最难检测**，因其行为酷似正常验证支持。
- **Finding 6–7**：规则式静态分析效果差（Semgrep 平均 49.5%、Bandit 29.3%），**规则覆盖率**是主要瓶颈；Semgrep 对命令执行/反序列化较强，对路径遍历/DoS 较弱。
- **Finding 8–9**：补丁级 LLM 判官优于静态分析（平均 55.4% 准确率），但仍仅略高于随机猜测；存在"过度泛化"导致简单攻击类型检测下降的问题。
- **Finding 10–11**：联合 issue 级 + patch 级检测在基线上近乎完美（88.8% / 87.8%），但在 SWEADV 上仅 **65.9% / 72.4%**，最强 Claude-S-4.6 也仅 75.8% 准确率，仍有 34.1% 错误率。

- **Finding 13（续）**：检测失败的 600 个样本中，最大类别是“被误认为合法 bug 或功能”（359/600），其次是“缺少显式安全上下文/未将攻击者可控输入与危险汇点关联”（约 120/600），其余包括“危险 API 被误判为正常工具调用”“注入符号被当作合理重构”“测试通过造成安全错觉”等。这说明当前判官与静态工具缺乏对“意图—数据流—汇点”的联合推理能力。

## 7. 讨论与启示

- **对 APR 部署的警示**：论文结果表明，“功能测试通过”与“补丁安全”之间存在系统性鸿沟。将 APR 智能体直接接入开源 issue 流水线，可能把攻击面从“代码贡献者”转移到“自然语言 issue 描述”，且攻击成本极低——仅需一段看似合理的维护需求。
- **攻击的泛化性**：SWEADV 的 ASR 在不同修复 LLM 间差异仅约 5.5%，说明脆弱性并非某个模型的偶发缺陷，而是当前“issue→补丁”范式的共性风险；更强的指令遵循能力甚至可能放大风险（Claude Opus 4.5 在 206 个最难实例上 ASR 达 85.4%）。
- **检测困境的根源**：
  - **语义鸿沟**：恶意需求常被包装为“预处理”“兼容性修复”“性能优化”等正常维护逻辑，判官难以仅凭文本区分意图。
  - **上下文缺失**：静态分析依赖规则覆盖，而 SWEADV 的攻击载荷使用仓库风格命名与合法 API 组合，绕过规则匹配。
  - **测试的误导性**：FAIL_TO_PASS 与 PASS_TO_PASS 只验证功能行为，不验证安全属性，导致“通过测试”成为攻击者的保护色。
- **防御建议**：
  - **issue 级**：对涉及环境变量、命令执行、序列化、文件路径、哈希算法的需求增加强制人工复核或安全策略检查。
  - **补丁级**：结合动态污点分析、最小权限容器执行、危险汇点白名单与运行时监控，而非仅依赖静态规则或 LLM 判官。
  - **流程级**：将 APR 智能体置于“建议者”而非“提交者”角色，所有自动补丁必须经过独立安全审查与沙箱验证。

## 8. 局限性与未来工作

- **攻击类型覆盖有限**：仅涵盖命令执行、反序列化、路径遍历、DoS、弱哈希五类，未涉及供应链投毒、内存安全、竞态条件、权限提升等更广泛漏洞。
- **基准与生态偏差**：SWEADV 基于 SWE-bench Verified（Python 生态），结论向其他语言、构建系统与仓库结构的外推需谨慎；基线 SWExploit 来自 SWE-bench Lite，两者难度不同，绝对数值比较需借助 benign 对照。
- **威胁模型边界**：假设攻击者只能影响 issue 文本，未考虑多轮交互、代码评论、CI 配置篡改、依赖混淆等更复杂攻击面。
- **防御评估不完整**：论文主要评估检测器，未系统测试运行时隔离、权限限制、动态污点追踪等防御措施的实际效果。
- **资源透明度不足**：未报告 GPU/推理成本、token 消耗与总耗时，影响可复现性与成本效益分析。
- **未来方向**：扩展多语言与多攻击类型基准；研究“安全感知”的 APR 智能体；构建 issue→补丁全链路的安全验证框架；探索形式化方法与动态分析在 APR 安全中的结合。

## 9. 总体评价

- **贡献**：论文首次系统性地提出并验证了 LLM-based APR 智能体在对抗性 issue 下的安全脆弱性，构建了模型无关的 SWEADV 基准（750 条对抗性 issue），并给出 FR/ISR/ASR 等可复用指标。
- **方法严谨性**：威胁模型清晰，基准构建自动化程度高，攻击载荷与仓库风格融合自然；采用确定性 diff 规则、动态触发 harness 与人工抽检三重验证注入标签，降低误判。
- **实验充分性**：覆盖 5 类攻击、3 个修复 LLM、4 个判官 LLM、2 类静态工具与 3 种检测层级，实验矩阵完整；定性分析 600 个假阴性样本，提供细粒度失败归因。
- **主要局限**：跨基准难度差异、攻击类型有限、防御评估不足、算力未披露；结论主要适用于 Python/SWE-bench 场景。
- **总体判断**：该研究是对“自主 APR 可信任部署”的重要警示，证明当前智能体在对抗性自然语言输入下远未达到安全生产标准。其价值不仅在于揭示漏洞，更在于为后续安全 APR、检测器与防御机制研究提供了可复现的基准与方向。
