## 摘要
代理式AI系统越来越多地被部署用于在推理时处理敏感数据，例如在系统回答之前将医疗记录或财务文件组装成隐藏的\emph{上下文}。先前的研究主要通过\emph{越狱}攻击来研究隐私风险，这些攻击诱导模型直接披露敏感内容，但在很大程度上忽略了代理式设置，其中上下文由代理自身的工具调用组装。我们表明，尽管我们测试了针对这些代理的控制措施，即不披露上下文的指令、逻辑抑制和上下文稀释，我们评估的代理仍然容易受到隐藏上下文泄露的影响。例如，一个回答良性用户查询的网页浏览代理仍然携带关于静默加载到其上下文中的记录的可利用信号。我们通过安全博弈引入并形式化\emph{上下文推断攻击}，并在攻击者知识递减和上下文传递日益间接的情况下评估三种设置：已知上下文、未知上下文以及代理通过自身工具调用检索的上下文。我们区分了灰盒设置（其中使用目标模型对观察结果进行评分）与黑盒设置（其中攻击者使用其控制的替代模型进行评分）。我们进一步描述了泄露如何随查询预算、上下文大小和目标模型大小而变化。单个攻击无需修改即可贯穿所有三种设置，在小候选集上达到$100\%$的ASR，在针对已知上下文的$1024$个候选时达到$63\%$，当模板和周围记录未知时AUROC为$78.9$，当14B替代模型对32B目标模型进行评分时AUROC为$92.5$，当记录作为代理的检索结果到达时AUROC为$81.8$，而随机水平分别为$1/|\mathcal{Z}|$和$50$。

## Abstract
Agentic AI systems are increasingly deployed to process sensitive data at inference time, such as healthcare records or financial documents assembled into a hidden \emph{context} before the system answers. Prior work has studied privacy risks primarily through \emph{jailbreaking} attacks that induce models to directly disclose sensitive content, but has largely overlooked the agentic setting where the context is assembled by the agent's own tool calls. We show that the agents we evaluate remain vulnerable to hidden-context leakage despite the controls we test against them, namely an instruction not to disclose the context, logit suppression, and context dilution. For instance, a web-browsing agent answering benign user queries still carries exploitable signals about records silently loaded into its context. We introduce and formalize \emph{context-inference attacks} through a security game and evaluate three settings under decreasing attacker knowledge and increasingly indirect delivery of the context: a known context, an unknown context, and a context the agent retrieves through its own tool calls. We distinguish a grey-box setting, in which the target model is used to score observations, from black-box settings in which the attacker scores with a surrogate it controls. We further characterize how leakage varies with query budget, context size, and target-model size. A single attack carries through all three settings without modification, reaching $100\%$ ASR on small candidate sets and $63\%$ at $1024$ candidates against a known context, $78.9$ AUROC when the template and surrounding records are unknown, $92.5$ AUROC when a 14B surrogate scores a 32B target, and $81.8$ AUROC when the records arrive as an agent's retrieval returns, against chance rates of $1/|\mathcal{Z}|$ and $50$ respectively.

## 1. 核心问题与整体含义（研究动机与背景）

随着代理式 AI 系统（Agentic AI）的广泛部署，系统在推理时会将大量敏感数据组装为隐藏上下文（hidden context），例如系统提示词、检索到的文档、用户记录、浏览痕迹或工具调用返回。以往针对此类隐私风险的研究**几乎完全聚焦于"越狱"（jailbreak）式直接提取**，即攻击者通过对抗性指令诱导模型输出敏感内容本身。

然而，本文指出这忽视了代理式 AI 一个更本质的隐私面向：**即使隐藏上下文从未被模型直接披露（不引用、不复制、不输出），模型的响应分布本身依然会受到隐藏上下文的影响**，从而为攻击者提供可利用的统计信号。这种"非语义泄露"（non-semantic leakage）构成了传统防御（如指令级禁止披露、输出过滤）无法覆盖的新型攻击面。

核心贡献是将隐私问题从"内容能否被提取"拓展为"**上下文能否被推断**"，并证明在代理式 AI 场景下，仅通过普通良性查询（benign queries）即可实现高精度的隐藏上下文推断。

> 总体含义：一条推理时上下文即使完全不可见、且模型被有效阻止直接泄露内容，也仍然可能在响应分布中留下可被系统性利用的痕迹。AI 系统服务商不能仅因为"隐藏上下文不被直接输出"就将其视为隐私安全的。

## 2. 方法论：核心思想与技术细节

### 2.1 核心思想：将隐藏上下文视为潜在假设

攻击的基本思路是将"隐藏上下文中是否存在目标记录"视为假设检验问题。攻击者向目标模型提交若干**良性查询**（不含对抗指令、不依赖被测候选记录），观察输出文本，然后构建不同的候选上下文假设，评估哪个假设能最好地解释观测到的响应分布。

整个攻击的框架由三组算法协同完成：

- **攻击流程（Algorithm 1, Replay-based context inference）**：先离线选择查询，再在线提交 K 次查询并收集响应，最后对每个假设 h 计算 NLL，得出决策。
- **查询优化（Algorithm 2, OPTIMISE QUERIES）**：从 102 条良性查询池中离线筛选出最具判别力的查询子集，不消耗在线查询预算，每轮对比目标记录存在与不存在两种场景下响应 NLL 的可分性。

### 2.2 三种威胁模型设置（由已知到已知递减）

- **TM1：已知上下文**。攻击者已知上下文模板和一个有限的候选集 Z，任务是判断哪个候选记录被部署。最保守的假设下，隔离出核心问题：隐藏上下文是否会对响应产生可测量的影响。
- **TM2：未知上下文**。攻击者仅掌握一个目标记录 z 的文本，模板、其余上下文内容皆未知，任务是二元判断：z 是否在隐藏上下文中。
- **TM3：代理检索（agent-retrieved）上下文**。攻击者知识状态同 TM2，但上下文中的记录不再作为文本直接附带，而是由代理自己通过 URL 工具检索后进入上下文——这是最接近真实部署的智能体场景。

### 2.3 评分方式：灰盒与黑盒

- **灰盒（grey-box）**：攻击者可用目标模型本身计算响应似然，即 ˆθ = θ。
- **黑盒（black-box）**：攻击者用代理模型（surrogate model）进行似然评分，即 ˆθ ≠ θ（例如 14B 代理模型评分 32B 目标模型）。

对于每个候选假设的评分基于**逐token负对数似然**（NLL）：

```
NLL(y_1:T | x; θ) = -1/T · Σ_t log p_θ(y_t | x, y<t; T=1)
```

分数低的候选记录表示模型更倾向于在该假设下产生观测到的响应。决策时，攻击者比较"含目标记录"与"不含目标记录"两种假设的分数差异（likelihood-ratio 对比）。

### 2.4 防御措施

论文对其攻击评估了三种防御配置：**指令式不披露防御**（系统明确要求模型不得直接或间接泄露上下文内容，同时仍然有义务回答问题）、**logit 抑制**（TM1 中屏蔽所有含敏感数字的 token 生成路径）以及**上下文稀释**（增加填充记录以稀释目标信号）。

## 3. 实验设计：数据集、场景与基准

## 6. 主要结论与发现

- **针对已知上下文**：攻击在小候选集上达到 100% 的 ASR，在 |Z|=1024（随机猜测率仅为0.1%）时仍能保持 63% 的 ASR；查询优化（LR-optimal）显著优于随机查询（LR-random）。
- **针对未知上下文**：在 N=10、K=20 的设定下 AUROC 最高达到 78.9；灰盒环境下，1.5B–32B 全部出现泄露且随查询预算上升。
- **跨代理模型评分**：14B 代理模型评分 32B 目标模型时，AUROC 达到 92.5；跨家族 VLM 查询转移同样有效。
- **针对代理检索上下文**：攻击在智能体工具调用场景下达到 81.8 的 AUROC（过滤无信息查询后），说明记录是否被检索本身即可被体外推断。
- **跨模态迁移**：文本模型攻击可迁移至 VLM（LLaVA、Qwen2.5VLM 家族），用图像作为候选记录时 ASR 高达 99%（随机猜测率仅1.6%）。
- **泄露是非语义的**：GPT-4o-mini 基线几乎始终处于随机水平（TM1中4–20% vs 随机6.25%；TM2/3中49–60 AUROC 附近），说明信号只能通过似然而非文本内容读取。
- **防御均不能阻断**：指令禁止、logit 抑制、上下文稀释等控制手段均无法消除泄露，只能降低泄露程度。上下文翻倍、响应裁剪（从500降到100 token）仅损失约3.4个百分点的ASR。

## 7. 优点

1. **指出了新的攻击面**：系统性地识别了"不直接输出内容也可能造成上下文泄露"这一深层漏洞，对以往以越狱为主的攻击面形成了重要补充。
2. **威胁模型高度清晰且分层精准**：从已知上下文到未知上下文再到代理检索上下文，逐步解耦知识的减少对攻击效果的影响。
3. **攻击框架统一简洁**：本文用同一攻击在不同设置间无修改转移，展示了从"机制验证"到"真实部署"的强大一致性。
4. **强调非语义泄露的证据链完整**：通过 BLEU 审计确认所有响应与目标记录几乎无直接重叠，充分证明了攻击定义中所说的信息渠道与以往完全不同。
5. **引入了黑盒/灰盒分级和查询优化方法**，使攻击范式与实际工业部署之间的连接（应用和防御）更紧密。
6. **对抗基准设计有合理控制**：GPT-4o-mini 作为人类可读判断器的对照，令攻击结果更有说服力，且确认了隐私风险的意义——即便无法从响应本身读出任何私密内容，统计层面的信号仍构成重大风险。

## 8. 不足与局限

1. **黑盒替代模型的泛化范围有限**：论文所采用的替代模型全部来自与目标同一模型家族或同一任务域（如以 Qwen2.5-14B 评分 Qwen2.5-32B，或以 LLaVA-7B 评分 LLaVA-13B）。并没有验证来自完全不同家族的替代模型能否有效实现转移（文中只给出有限的 LLM 弱化迁移案例）。
2. **实验为非对称的成员关系基线**：TM2 和 TM3 的成员设置人为平衡各占一半，实际部署中某一具体记录在上下文的先验可能与 0.5 相差很远，基线设定放大或弱化攻击的实际效果。
3. **TM3 的人为受限部署近似**：该场景强制代理检索全部 N 条记录，并未评估由代理自主决策应访问哪些 URL 的真实行为——也就是说，仍然无法将上下文选择带来的"成员差异"与"查询/排名不确定性"完全解耦。
4. **外部 API 影响结果稳定性**：TM3 的部署依赖托管服务（Fireworks AI、DeepInfra），由于不同端点返回的 log-probabilities 可能只有有限条目（最多五个），评分必须重新归一化，这种方法对响应质量产生哪些系统性影响尚未评估。
5. **未考虑实时性或自适应攻击**：论文采用固定查询集并承认攻击者是非自适应的，不包含策略改进的动态交互或基于上下文的针对性连续攻击，因而不覆盖更主动的攻击面。
6. **未详细分析何种"上下文内容类型"更容易泄露**：目标记录类型集中于数字串（TM1）、凭据（TM2）和新闻文字（TM3），没有评估医学/金融等高风险异质文本的特征，也没有讨论上下文语义多样性。
7. **缺少有效可规模化的防御方案**：文末只指明"上下文稀释"和"响应长度裁剪""看似"能降低泄露程度，但没有给出一种实用的端到端缓解方案，或对推理成本与隐私保护强度权衡的分析。
