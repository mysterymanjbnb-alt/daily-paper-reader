## 摘要
具有持久性记忆的代理式AI系统引入了一种独特的攻击面，称为记忆投毒攻击，其中对抗性构造的内容被存储在长期记忆中，并随后影响未来的智能体行为。此类攻击可以抑制安全警报、促进权限提升、改变信任关系或覆盖安全策略，而无需修改底层模型权重或系统提示。为了应对这一威胁，我们提出了MemSentry，一个正式的、配置驱动的框架，它拦截提议的持久性记忆写入，并产生确定性的接受、审查或隔离决策。MemSentry通过联合考虑来源信任度、语义风险、组件依赖DAG上的攻击半径、访问风险以及标记操作是削弱还是增强系统安全姿态的带符号安全状态增量来评估每次写入。我们使用包含20个资产的随机依赖DAG和一个10×20的用户访问控制矩阵实例化受保护环境，并使用分层70/30训练/测试划分，对由GPT-4生成的1,000个场景框架进行评估。语义分类被视为可插拔组件而非主要贡献，我们比较了四种代表性方法：基于规则的Regex、TF-IDF+SVM、SBERT+LR和SetFit。SBERT+LR取得了最佳整体性能，准确率为91.7%，宏F1分数为0.908，而所有四种方法均能检测出100%的外部隔离类威胁。对于可信内部人士，当来源信任度最大（T=1）时，MemSentry不会自动隔离可疑操作，而是将潜在危险的写入升级为人工审查，这使得语义分类对于准确捕获内部人员意图变得重要。

## Abstract
Agentic AI systems with persistent memory introduce a distinct attack surface known as memory poisoning, in which adversarially crafted content is stored in long-term memory and subsequently influences future agent behavior. Such attacks can suppress security alerts, facilitate privilege escalation, alter trust relationships, or override security policies without modifying the underlying model weights or system prompts. To address this threat, we present MemSentry, a formal, configuration-driven framework that intercepts proposed persistent-memory writes and produces deterministic Accept, Review, or Quarantine decisions. MemSentry evaluates each write by jointly considering source trust, semantic risk, attack radius over a component-dependency DAG, access risk, and a signed security-state delta that captures whether an operation weakens or strengthens the system's security posture. We instantiate the protected environment using a 20-asset random dependency DAG and a 10 x 20 user access-control matrix, and evaluate the framework over 1,000 GPT-4-generated scenarios using a stratified 70/30 train/test split. Semantic classification is treated as a pluggable component rather than a primary contribution, and we compare four representative approaches: rule-based Regex, TF-IDF+SVM, SBERT+LR, and SetFit. SBERT+LR achieves the best overall performance with 91.7% accuracy and a 0.908 macro-F1 score, while all four methods detect 100% of external quarantine-class threats. For verified insiders, where source trust is maximal (T = 1), MemSentry does not automatically quarantine suspicious operations but instead escalates potentially dangerous writes for human review, making semantic classification important for accurately capturing insider intent.

## 1. 核心问题与整体含义（研究动机与背景）

- **核心威胁**：具备持久记忆的 Agentic AI 系统面临一种名为 **Persistent Memory Poisoning（PMP，持久性记忆投毒）** 的攻击面。攻击者可通过电子邮件、网页、共享文档等外部不可信渠道将恶意构造的内容写入智能体的长期记忆，使后续的推理、规划与行动持续受污染影响。
- **与传统提示注入的本质区别**：PMP 不需要在每次交互中重复进行对抗性诱导，**一次成功的记忆写入即可持续影响未来行为**，也不需要修改模型权重或系统提示，因而更难被发现和清除。
- **现实危害**：中毒记忆可导致 SOC 智能体抑制安全警报、推动权限提升、篡改信任关系、覆盖安全策略等，进而危及受保护资产和下游组件。论文以“SOC 智能体被诱导抑制特定 IP 警报”的场景为例说明攻击逻辑。
- **现有防御的不足**：多数已有方案（如 SMSR、MEMSHIELD、MemAudit、A-memguard 等）属于 **反应式防御**——要么在检索阶段过滤、要么在恶意行为已经发生后的审计阶段发现中毒记忆，缺少在**写入前（pre-commit）**进行系统性安全评估的框架。
- **研究定位**：MemSentry 提出一种配置驱动、确定性、可审计的**写入前防御框架**，解决“该记忆是否可能被信任、写入后会引发什么后果”这一核心安全问题。

## 2. 论文提出的方法论

### 2.1 总体思路

MemSentry 将系统建模为`G = (C, E)`——即组件（资产）有向依赖图，组件带关键性权值`q_i ∈ [0,1]`。它拦截每条待写入的持久性记忆操作，在提交前评估其来源、语义、授权、影响范围和安全状态变化，输出三类确定性决策：**Accept（接受）**、**Review（人工复核）** 或 **Quarantine（隔离）**，并生成可审计的结构化解释。

### 2.2 九步评估流水线

1. **Step 1 – 来源信任（Source Trust）**：根据来源类型与身份验证情况量化`T ∈ [0,1]`：外部未验证为 0.0，外部已验证为 0.5，内部未验证为 0.5，内部已验证（内部人员）为 1.0。
2. **Step 2 – 语义分类（Semantic Classification）**：将操作映射到语义类别与语义风险`r_sem`，类别包括安全增强（−0.30）、偏好（0.05）、时间/调度（0.05）、操作事实（0.10）、警报抑制（0.80）、凭证存储（0.90）、信任修改（0.70）、策略覆盖（0.80）、权限主张（0.90）、条件触发（0.85）等。
3. **Step 3 – 攻击半径（Attack Radius）**：通过深度受限图遍历，找出该操作直接命中的组件以及所有可通过依赖边到达的下游组件，计算攻击半径`AR = |C_O| / |C|`，用于衡量受影响系统组件的比例。
4. **Step 4 – 访问风险（Access Risk）**：计算`R_access`——受影响组件中主体验无权访问的部分，按组件关键性加权求得比例。
5. **Step 5 – 安全状态（Security State）**：计算当前全局安全姿态`π(S_i)`，即各组件安全强度按关键性加权平均。
6. **Step 6 – 投影状态（Projected State）**：依据语义风险的正负方向与持久性因子`f_pers`（临时 0.3 / 有限周期 0.6 / 永久 1.0），预测写入该记忆后的安全姿态`π(S_{i+1})`。关键规则为：促进安全类的操作效果与来源信任`T`正相关，而危害下降类的操作幅度与来源不信任度`(1 − T)`负相关。
7. **Step 7 – 安全偏差（Security Delta）**：计算`δ(O) = π(S_{i+1}) − π(S_i)`，表示系统安全姿态的**带符号变化**——负值代表安全降级，正值代表安全增强。
8. **Step 8 – 风险评分（Risk Score）**：综合来源不信任、语义风险、访问风险、安全偏差降级量和攻击半径进行加权求和，得到风险值`R`。
9. **Step 9 – 决策规则（Decision Rules）**：基于若干确定性规则判定：
   - 外部未验证来源**一律隔离**，不看内容——这是保证外部攻击威胁零放过的关键硬约束；
   - 安全下降超过阈值或风险分超过阈值则隔离；
   - 仅当来源内部可信、授权充分、语义风险低、类别为良性时才接受；
   - 其余情况转人工复核。
   - **值得注意**：内部已验证来源（T=1）的操作，即使具有危险性也不会被自动隔离，而是**升级为人工复核**（有意的“fail-to-review”策略）。

### 2.3 可审计性与可解释性

- 每条评估产生结构化说明记录，包含来源可信度、语义类别、攻击半径、访问风险、安全偏差、持久性因子、内幕威胁标志、风险分、决策和原因列表等中间值。
- 解释由**模版自然语言生成，而非调用 LLM**，保证相同输入必得相同输出，输出具有完全确定性和可复现性。

## 6. 主要结论与发现

1. **外部威胁 100% 拦截**：所有四种语义方法都能 100% 检测出外部未验证来源的隔离类攻击，在“外部隔离”这一主要攻击向量的防护上非常有效。
2. **SBERT+LR 综合最优**：整体准确率 91.7%，宏 F1 0.908，Review 类精确率 72.2%——是区分“安全临界/模糊”操作的最佳选择。
3. **TF-IDF+SVM 计算成本更优**：以 88.0% 的准确率表现出较强的竞争潜力，是成本敏感场景的合理替代方案。
4. **SetFit 反而不如常规线性方案**：仅 76.7% 准确率，Review 类仅 22.2%，在语义模糊类别上明显落后，显示任务适应型微调也并非默认更优。
5. **内幕攻击存在结构性瓶颈**：由于对内部已验证来源设计了 fail-to-review 原则（T=1 时风险分永不达到隔离阈值），危险内部操作全部转人工审查而非自动隔离。SBERT+LR 在 100% 授权时仍保持 91% 的 Review 准确率，而 SetFit 降至 2.7%。
6. **表层语义模型的短板**：任何语义方法都不能可靠区分表层相似但安全含义相反的内容对（最优仅解决 3/10 对），反映出语义分类与真实安全意图推理之间存在明显的差距。

## 7. 优点

- **前置防御定位**：可在写入前拦截恶意记忆，避免“恶意内容先落库再亡羊补牢”的被动局面。
- **配置驱动且确定性**：决策逻辑完全确定且规则配置化（阈值、权重均可调），排除模型输出随机性导致的不可靠问题。
- **可审计与可解释**：每条决策生成完全确定、非 LLM 生成的解释记录，满足安全场景的合规审计与事后追溯需求。
- **影响感知的威胁建模**：将攻击半径和安全状态偏差嵌入决策，不仅判断“记忆本身是否可疑”，还能推理“若被信任会怎样”，在概念上优于纯内容过滤思路。
- **语义分类解耦设计**：将语义分类定位为可插拔组件，对比实验方法框架也足够透明、集中，并专门设计了反事实的语义对比诊断集（SC01–SC20），这是很好的测试方法。
- **“外部隔离、内部复核”的差异化策略**：在最大信任场景下有意不自动隔离而是升级审查，体现了防御安全、误报控制与组织信任伦理之间的平衡。

## 8. 不足与局限

### 8.1 实验覆盖上的局限

- **数据完全依赖 GPT-4 生成**，所有语义模式的分布均受生成器固有的人为设计影响，可能与真实攻击分布存在偏差。
- 系统模型是小型仿真（20 资产、10 用户、28 条边），不能代表企业级大规模系统的复杂度。真实系统在组件范围、依赖深度、并发写入、更多用户访问策略方面都需要重新测试。
- 只考虑独立操作，未覆盖**多步协作攻击**与**时间上关联的系列投毒操作**（本文未覆盖多智能体间的传播）。

### 8.2 方法与架构局限

- 未做消融实验，框架内部的注意力权重、阈值与部分规则消融后对决策的影响无法衡量。
- 安全状态投影公式的设计虽然直观，但其量化基础（α_base、α_access、持久性因子、线性加权结构）缺乏现实系统的校准证据。
- 将“内部已验证身份”赋予最高可信度`T=1`可能过于宽松，历史上一些严重危害即来自已认证账号被合法使用的场景。
- 未考虑“来源被验证”但验证机制本身被攻破的情形。

### 8.3 模型能力边界

- 语义分类器对于“已认证 vs. 被授权”“短期 vs. 永久”“记录 vs. 抑制”等意图级差别的辨别效果有限，论文承认这一结构性短板，并建议未来引入 LLM 或 NLI 级别推理。
- 语义分类的映射方案依赖人工预设风险表，可解释性有限，实时性也可能受预训练模型容量约束。

### 8.4 应用限制

- 目前框架是静态快照式的评估（未考虑记忆间的相互作用、检索时的热度差异），需要配合检索阶段防御（如 MEMSHIELD）形成多级防线。
- 论文整体论证侧重框架设计和仿真验证，缺乏真实企业部署数据和可用性（误报率）评估。
