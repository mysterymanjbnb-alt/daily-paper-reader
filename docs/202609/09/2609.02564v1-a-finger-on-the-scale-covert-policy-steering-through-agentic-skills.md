## 摘要
可复用的智能体技能为大型语言模型智能体提供了任务流程、工具使用指导和输出约束。然而，这些技能也充当了外部化的行为策略，由此产生供应链风险：第三方技能可能保留声明的任务和有效的输出接口，同时暗中将智能体决策引向未公开的目标。我们正式定义了技能政策完整性（Skill Policy Integrity），要求技能诱导策略始终保持与其声明功能及用户授权目标一致。我们进一步提出SkillShift——一个用于隐蔽政策引导的受限黑盒框架，无需显式目标命令注入或任务劫持。它结合了语义上合理的策略编辑、层级验证、失败引导优化和策略压缩，以保持有效性、输出合法性、可迁移性和隐蔽性。我们在智能体商务和软件依赖使用场景中实例化了这一威胁，SkillShift实现了攻击者偏好的81.33%和63.33%选择率，同时保持了100%的效用保留率。冻结策略无需进一步优化即可跨异构LLM后端和智能体环境迁移。此外，评估中的扫描器未能检测到构造的技能，这促使将对可复用技能的行为审计作为智能体政策工件。

## Abstract
Reusable agent skills extend large language model (LLM) agents with task procedures, tool-use guidance, and output constraints. Yet these skills also act as externalized behavioral policies, which create a supply-chain risk: a third-party skill may preserve the declared task and valid output interface while covertly redirecting agent decisions toward an undisclosed objective. We formalize Skill Policy Integrity, which requires a Skill-induced policy to remain aligned with its declared functionality and the user-authorized objective. We further present SkillShift, a constrained black-box framework for covert policy steering without explicit target command injection or task hijacking. It combines semantically plausible policy edits with hierarchical validation, failure-guided optimization, and strategy compression to preserve effectiveness, output validity, transferability, and inconspicuousness. We instantiate this threat in agentic commerce and software dependency use, with SkillShift achieving attacker-favored selection rates of 81.33% and 63.33% while maintaining a 100% utility-preserving rate. The frozen policies also transfer without further optimization across heterogeneous LLM backends and agent environments. Moreover, the evaluated scanners fail to detect the constructed skills, motivating behavioral auditing of reusable skills as agent policy artifacts.

- **与传统威胁的区别**：既有研究集中在执行层面威胁（恶意代码、指令劫持、越权工具调用等）——这些攻击改变了智能体“做什么”；而本文聚焦软策略层攻击——智能体仍处理同一查询、返回合法输出，但“选择谁”被暗中操纵，因此是任务边界之内的隐蔽政策偏移而非显式劫持。

### 2. 方法论：SkillShift 框架

SkillShift 是本文提出的**约束黑盒政策引导框架**，核心目标是在满足四项实际要求（有效引导、功能保真、黑盒可复用、语义隐蔽）的前提下实现隐蔽的目标偏好偏移。

**结构化的策略表示**

- 攻击被限制为一个由四部分组成的结构化策略对象 A = (G, U, T, X)：
  - **G（Global principles）**：全局评估原则；
  - **U（Task-specific rules）**：任务级选择规则；
  - **T（Tie-breaking criteria）**：平局打破规则；
  - **X（Semantic examples）**：语义示例（含使用示例和少样本示例）。
- 策略通过确定性的渲染器追加到基础技能后：SA = Sbase ⊕ Format(G, U, T, X)。

**三种协同引导机制**

| 机制 | 作用方式 |
|---|---|
| 政策框架（Policy framing） | 通过为任务相关属性赋予不同语义显著性，改变目标候选在隐式比较函数中的加权——只改变已有证据的权重，不改证据本身 |
| 平局打破操纵（Tie-breaking manipulation） | 引入“看似合理”的次要标准，使多个同样合适的候选中特定对象被优先选中 |
| 语义锚定（Semantic anchoring） | 使用代表性示例稳定抽象原则在查询间和不同模型间的应用方式 |

**优化流程（Algorithm 1：约束黑盒搜索）**

1. **上下文一致初始化**：由初始器 LLM 在干净的基线技能之上生成一个紧凑且符合约束的策略起点；
2. **约束黑盒策略搜索**：迭代进行“局部编辑→分层验证→受害者执行→指标评估”，候选策略在 `Validate(A) = V_str(A) · V_iso(A) · V_con(A) = 1` 的三重验证通过后才被执行——检查结构/长度、确保仅修改追加策略部分、禁止显式目标命令或候选位次捷径等；
3. **失败引导覆盖修补**：将在各语义类别上系统失败的查询按类别聚合，只提供类别描述与聚合统计给提议器，防止在单条查询上过拟合、避免实例级捷径；
4. **效果保持策略压缩**：删除冗余/低贡献规则、合并相似语义、泛化近义示例，在 PSR/VR 不显著下降（容差 εc）的前提下缩短文档，减少攻击面并提升跨模型迁移性。

**关键约束条件**：禁止修改查询、候选数据、候选顺序、输出模式；目标名称仅允许出现在合法示例中；攻击者仅能观察到最终的模型输出——无参数、无梯度、无概率/logits、无隐藏状态。

- 评估指标：**PSR**（策略引导成功率，衡量攻击者目标被选中的比例）、**VR**（有效输出率）、**Lift**（相对干净技能在 PSR 上的绝对百分点提升）。

**对比基线**

- 两类非对抗基线：No Skill（无技能）、Clean Skill（干净技能）；
- 四类攻击基线：Target Name Only（仅提目标名）、Keyword Stuffing（关键词堆砌）、Generic Prompt Injection（通用提示注入）、Direct-Skill Injection（直接技能注入——作为显式的非隐蔽正控制基线）。

**跨域安全性评估**

- **跨模型迁移**：Claude Haiku 4.5（受害者模拟器）、DeepSeek v4-Flash、GLM-4.7、Gemini 3-Flash、Qwen3.5-Flash、GPT-5.4 共 6 个模型；

### 6. 主要结论

- **攻击有效性**：SkillShift 在 Shopping 上将 PSR 从干净技能的 37.33% 提升到 81.33%（Lift = +44.00 pp）；在 Python 上从几乎为 0 提升到 63.33%（Lift = +62.66 pp），两域中 VR 均保持 100%。
- **泛化能力**：冻结策略在 held-out20 未见查询上保持强效果（Shopping 80%、Python 75%）；迁移至 6 个异构后端（含 GPT 与 Gemini 等），Lift 显著为正（Shopping: +20~+51.33；Python: +52.67~+100）；在 Claude Code 和 Codex 兼容智能体中也无需调整即可生效。
- **消融发现**：Shopping 攻击的最强驱动是任务语义提示/示例/框架效应，而非文档长度——长度为中性的语义控制条件几乎不能提高 PSR，这与“策略内容本身决定行为偏移”的核心假设一致；Python 场景中，“所有示例模块”是对攻击效果贡献最大的单个组件（删除后 PSR 下降 33.33 pp）。
- **脆弱性缺口**：6 个检测器（skill-scanner-full、Aguara、Snyk、STARS、SkillSpector、ProtectAI）无一将 SkillShift 技能与干净技能区分开，而对显式直接注入的检测率则达到 66.7%——说明现有安全工具偏重“结构化指令注入”而忽视“语义级偏好操纵”。
- **安全与效用并不等同**：虽然技能层的 VR 指标 100% 合法——攻击技能将 Python 代码质量的平均分从 0.558 降至 0.506（QPR 降幅达 16–20 个百分点）——但 Syntactically valid ≠ functionally good。

### 7. 优点

- **问题构造和形式化清晰**：首个提出“技能政策完整性”这一安全语义，并明确区分“执行级指令劫持”和“策略级偏好操纵”两个不同攻击轴的工作。
- **攻击设计精巧**：结构化策略抽象将任意大且无约束的整文档改写转化为模式明确、可验证的策略搜索空间；约束规则（禁止修改候选数据/顺序等）既保持了任务边界，同时显式排除“实例级捷径”，这让攻击效果更有说服力——不是简单地通过提示注入取胜。

- **长度混淆控制的细节**：区分了“长度过长导致的行为变化”和“目标方向语义导致的偏向”两种替代解释，这种关注“文档长度作为混淆变量”的做法对检测研究有价值。
- **多样化的受害者评估**：覆盖 6 个模型后端、2 个完整智能体环境、3 个注册中心和 6 类检测器，且由人工审阅了注册中心的发布安全流程，实验相对立体。
- **透明度较好**：对“未设置种子”、“未进行统计显著性检验”、STARS 规则回退配置受限、ProtectAI 分数低于阈值仍然合格等限制进行了明确标注，整体呈现较客观。

### 8. 不足与局限

- **实验泛化有限**：仅两个固定候选域（购物 + Python 包）、每查询 3 次运行、数据集规模相当有限；动态候选集、更广泛的任务类型（如代码生成、RAG 检索、医疗 / 金融决策）未覆盖。
- **统计严谨性不足**：论文自述未做置信区间、显著性检验或多次随机评估；部分结论（如 Python 上 held-out PSR 升幅大）是否源于偏差难以判断。
- **转换性与真实性因素**：在跨模型评估中，部分模型端点（如 Qwen、GLM、GPT-5.4 等）标注为“别名”而非固定快照，导致绝对比较的识别度不够；Claude Code 版本与 Victim Simulator 的模型快照不能完全对等。
- **下游评估局限**：下游代码质量评估使用的是单次 LLM 评判器调用（GEval），并非“真实执行 + 测试集”，因此对攻击对真实程序功能的影响缺乏强证据。
- **漏检的边界案例**：STARS 在 Shopping 场景的未检测可能归因于语言覆盖不足而非语义上确实安全，直接注入（Direct Injection）也未被 ProtectAI 捕捉，说明“更傻瓜”的攻击未必都能被识别。
- **总体局限性**：论文自身承认——偏策略层攻击只考虑“候选集内出现目标”的条件，未考虑目标不在候选集中的情况；对技能的“行为审计”的建议（如反事实测试）仍只是方向性建议，并未给出可行防御方案。
