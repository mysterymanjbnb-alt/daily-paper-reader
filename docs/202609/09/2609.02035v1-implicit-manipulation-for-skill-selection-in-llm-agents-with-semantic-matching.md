## 摘要
技能选择是LLM智能体工作流程中的关键环节，决定应由哪个已安装的技能来处理用户请求。现有针对该环节的攻击主要依赖于显式提示注入或指令级引导，这可能暴露出可识别的操纵信号。在本工作中，我们识别出技能选择面临的一个新的隐式攻击面：即使用户提示和技能描述在孤立状态下看似良性，它们的语义关系仍可能被策略性地塑造，以偏向攻击者选择的技能。基于这一观察，我们提出了通过语义匹配实现的隐式技能选择操纵（ISM），该方法联合塑造目标技能元数据和可重用提示，在无显式选择指令的情况下操纵技能选择。具体而言，我们开发了一种三阶段策略，以扩大语义覆盖范围、增强目标独特性并保持提示措辞自然。在四个任务领域和八个选择器模型上，ISM将平均目标选择率（TSR）从15.2%提升至63.5%。在匹配比较中，ISM达到73.5%的TSR，仅比显式引导低9.8个百分点。人工评审者在仅2.9%的判断中阻止ISM，而显式引导则为91.4%；同时，五个基于LLM的检查器对ISM的平均通过率为82.9%，而对显式引导仅为37.4%。此外，ISM对PPL-W、Llama Prompt Guard 2和PIGuard仍然有效。

## Abstract
Skill selection is a key stage in LLM-agent workflows, determining which installed skill should handle a user request. Existing attacks on this stage primarily rely on explicit prompt injection or instruction-level steering, which can expose recognizable manipulation signals. In this work, we identify a new implicit attack surface for skill selection: even when the user prompt and skill description appear benign in isolation, their semantic relationship can still be strategically shaped to favor an attacker-chosen skill. Based on this observation, we present Implicit Skill-Selection Manipulation via Semantic Matching (ISM), which jointly shapes target-skill metadata and reusable prompts to manipulate skill selection without explicit selection instructions. Specifically, we develop a three-stage strategy to broaden semantic coverage, strengthen target distinctiveness, and preserve natural prompt wording. Across four task domains and eight selector models, ISM increases the average target-selection rate (TSR) from 15.2% to 63.5%. In a matched comparison, ISM achieves a 73.5% TSR, only 9.8 percentage points below Explicit Steering. Human reviewers block ISM in only 2.9% of judgments, versus 91.4% for Explicit Steering, while five LLM-based inspectors pass ISM at an average rate of 82.9%, versus 37.4% for Explicit Steering. Moreover, ISM remains effective against PPL-W, Llama Prompt Guard 2, and PIGuard.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：LLM（大语言模型）智能体在执行任务前需要从其安装的技能库中选择合适的技能。这一"技能选择"（Skill Selection）阶段依赖LLM对用户提示（prompt）与技能元数据（skill metadata）进行语义匹配来决定调用哪个技能。现有针对该阶段的攻击主要采用显式提示注入或指令级引导（如"始终选择此技能"），但这些攻击会暴露可识别的操纵信号，容易被人类审查或注入检测防御识别。
- **新攻击面识别**：论文提出一个关键观察——即使用户提示与技能描述各自孤立地看都是良性的，两者之间的*语义关系*仍可能被人为策略性塑造，从而使某一攻击者控制的技能获得更高的被选中概率。这是以往研究未触及的"隐式攻击面"。
- **研究含义**：这一发现表明技能选择不是一个"良性预处理"过程，而是智能体安全的关键边界。攻击者可以不注入任何显式指令，仅仅通过协调提示词与技能描述的语义内容即可改变技能选择结果，进而影响后续执行路径（可能带来安全风险或商业竞争中的不公平流量分配）。
- **现实场景**：用户从 Prompt 市场（如 AIPRM、PromptBase）复用第三方提示词（含 mega-prompt），以及从技能注册中心安装第三方技能，构成了此类攻击的现实传播链条。

## 2. 论文提出的方法论

### 2.1 核心思想

ISM 利用 LLM 选择器基于**用户提示与技能描述之间的语义匹配度**来挑选技能这一机制。攻击者（同时也是技能发布者与提示发布者）在目标技能的描述和可复用提示中"注入"相互呼应、任务一致但无显式选择指令的内容，使得目标技能在候选池中具有最高的语义匹配度。

### 2.2 三阶段攻击策略

#### 阶段一：任务相关线索构建（Task-Related Cue Construction）
- **目的**：扩大目标描述与同一任务场景下不同提示表述的语义兼容性，覆盖用户可能改写提示词的情况。
- **技术要点**：
  - 从同一场景收集到的多个提示中提取候选短语；
  - 经过**场景导向过滤**（保留跨提示高频出现的短语）和**任务导向过滤**（保留与目标任务语义相关的短语）两层筛选；
  - 使用 MiniLM 编码器计算语义得分 `S(x,y) = E(x)ᵀE(y)/(‖E(x)‖·‖E(y)‖)`，并结合频率排名百分位构建排序分 `R(c) = ½FRP(c) + ½S̃(c, m_t)`；
  - 将筛选出的提示侧共享线索（prompt-side shared cues）追加到目标技能描述中，同时将描述侧能力线索（description-side capability cues）转化为任务要求加入提示中，形成双向语义对应。

#### 阶段二：定制化技术钩子注入（Customized Technical-Hook Injection）
- **目的**：同领域的竞争技能可能也包含相似的宽泛任务线索，需要引入更具区分度的内容，突出目标技能的独特性。
- **技术要点**：
  - 技术钩子（technical hook）定义为：目标技能支持、且与任务上下文一致但在现有同类技能描述中较少出现的具体技术表达（如"semantic key-point extraction""section-aware slide decomposition"）；
  - 将技术钩子以固定句式同时注入目标技能描述（作为技术能力细节）和用户提示（作为任务要求），使目标技能在同类技能中获得"独有证据"；
  - 实验显示，目标相关的技术钩子同时降低了选择熵（选择更集中）并提高了目标选择率，表明其有效提升了目标技能的区分度。

#### 阶段三：提示自然化（Prompt Naturalization）
- **目的**：直接使用技术性措辞会让用户提示显得可疑，需在不改变技术钩子语义的前提下，将提示侧措辞转化为自然的用户表达。
- **技术要点**：
  - **语义关系确定**：利用 WordNet、ConceptNet、FrameNet 的关系库，界定技术钩子与用户层面表达之间的四种语义关系家族——分类关系（taxonomic）、部分-整体关系（part-whole）、目标-功能关系（goal-function）、使用情境关系（use-context），由此构建"语义桥"（semantic bridge）；
  - **语义桥约束转换**：以语义桥为约束，用LLM将技术钩子改写为自然的用户请求表达，避免直接复用技术词汇、不引入显式技能选择指令；
  - **转换后检查**：检查改写是否保留原始任务、是否保留所选语义关系、是否降低技术措辞直白度、是否自然流畅，不合格则重新生成；
  - 注意：技能描述侧保留技术形式不自然化，因为技能描述中技术细节是合法的能力元数据，具有功能适当性，且现有检测器不将其视为恶意。

### 2.3 方法整体流程（文字概述）
1. 收集同一任务场景下的多个可复用提示与目标技能的原始描述；
2. 提取并交叉注入任务相关线索（提示↔描述）；
3. 选定并注入定制技术钩子（描述侧保留技术形式，提示侧作为任务要求）；
4. 提示侧经语义桥约束的自然化改写，生成最终的攻击材料（可发布提示 + 目标技能描述）；
5. 发布到提示市场和技能注册中心，等待用户复用与安装，随后依靠正常的LLM语义选择过程偏向目标技能。

## 6. 论文的主要结论与发现

1. **技能选择可被隐式操纵**：LLM选择器的语义匹配机制构成可攻击面——无需显式指令即可让目标技能被偏向选中。
2. **ISM效果显著**：
   - 宏观平均目标选择率（TSR）从 Native 的 **15.2%** 提升至 ISM 的 **63.5%**（绝对提升48.3个百分点）；
   - 在匹配比较中 ISM 达 **73.5% TSR**，仅比 Explicit Steering（83.3%）低9.8个百分点；
   - 8个选择器全部出现正向宏观提升，64个"模型-目标"组合中62个正向。
3. **组件贡献明确**：Task-Related Cues 将TSR提升至47.8%；Technical Hooks 进一步推高至79.2%；Prompt Naturalization 将TSR回调至63.5%，但大幅提高了不可检测性。
4. **隐式性显著优于显式攻击**：
   - 人类评审者对ISM的拦截率仅 **2.9%**（Native为0.0%，Explicit Steering为91.4%）；
   - 五个LLM检查器对ISM的平均通过率为 **82.9%**，Explicit Steering仅37.4%；
   - 自然化步骤将LLM检查器通过率从技术钩子阶段的74.8%恢复到82.9%。
5. **规则型防御覆盖率有限**：PPL-W对ISM零拦截；Llama Prompt Guard 2 与 PIGuard 拦截率分别仅25.4%和23.1%，且对良性输入产生26.5%和37.5%的误报率。有效降低ISM TSR的防御伴随较高误报，呈现明显的安全-效用权衡。
6. **防御方向建议**：结构性改写/规范化的技能描述（预选择规范化层）、来源验证、选择过程级审计（非逐文本分类）、语义优势正则化、高影响技能调用前的显式用户确认等。

## 7. 优点（方法或实验设计的亮点）

- **新攻击面发现**：将攻击从"文本是否恶意"的二元视角扩展到"提示-描述语义关系"的相对视角，机制上有说服力（先建模语义匹配对选择率的影响，再据此设计操纵）。
- **三阶段方法逻辑闭环**：覆盖广度（cue构建）→ 区分度（technical hooks）→ 隐蔽性（自然化），每一步都有诊断性实验支撑设计决策（如词频-相关性的二维分析、钩子族探测、选择熵分析），方法论严谨。
- **隐蔽性验证深入**：同时采用人工评审和LLM检查器进行判断型检测，又纳入三种现有规则型防御进行拦截评估，形成多层次、多视角的完整性验证。
- **跨模型-跨领域系统评估**：8个选择器横跨开源/商业、不同模型家族与代际，4个任务域各有2个目标技能配对竞争技能，实验矩阵较完整。
- **控制实验设计合理**：Random Keywords 和 Domain Wording 两个文本控制有效排除了"仅加词就有用"的替代解释；Explicit Steering 为效果上界和显式性对比提供了锚点。
- **对防御的反思**：明确讨论了规则型防御的安全-效用权衡，没有单方面夸大攻击效果，态度客观。
- **补充实验较充分**：逐目标明细、语义桥关系消融、提示单独审查等补充材料帮助读者独立判断结论的稳健性。

## 8. 不足与局限（实验覆盖、偏差风险、应用限制）

### 实验覆盖层面的局限
- **技能覆盖范围有限**：虽然采集了62,055个技能，但最终只保留了4个领域56个技能和8个目标技能的候选池，未涉及更广泛的领域或真实生产环境的复杂技能选择过程（如多跳调用、组合技能选择等）。
- **未覆盖更强的变体**：作者称未针对更先进的语义级防御或语义优势检测器进行评估；ISM在未来的专用防御下是否依然有效未知。
- **商业模型数量少**：仅2个商业模型（GPT-4o、GPT-5.1），各模型内部版本迭代可能使结果时效性有限。

### 方法与有效性层面的局限
- **对MiniLM依赖**：线索提取与过滤依赖 all-MiniLM-L6-v2 的嵌入相似度来度量语义相关性和做钩子选择，这一度量与LLM选择器内部的实际匹配机制并不完全一致，可能存在代理偏差。
- **人工审查样本有限**：仅7名评审者（技术上熟练但未必代表普通用户），小样本下2.9%与0.0%的差异在统计上未必显著；评审者的技术背景可能使其比普通用户对操纵更敏感。
- **未做因果严格分析**：语义桥消融实验等被作者自己定位为"构建证据"而非因果结论。
- **领域措辞控制（DW）的构造**：论文未详细描述如何确保DW与ISM除操纵语义外的其他属性均衡，可能残留混淆变量。

### 现实场景与安全层面的限制
- **攻击前提苛刻**：目标技能必须已被用户安装、用户必须实际复用攻击者发布的提示、技能池中必须恰好有可匹配的同域竞争者——这些条件的组合在实际用户生态中的普遍性未被量化。
- **不评估下游危害**：论文只证明前置选择阶段被偏向，不证明选中的恶意/落后技能后端确会造成伤害；作者承认"选择被操纵"与"实际安全后果"之间存在距离。
- **伦理与双面性问题**：论文发布的攻击方法可能被恶意第三方直接利用；虽然可用于推动防御研究，但未讨论漏洞披露责任或负责任的发布策略。
- **未见防御方案的实验实现**：第5节提出的结构性改写（structural rephrasing）等对策只做了概念性说明，没有在实验中验证其实际效果与代价，属于前瞻建议而非验证结果。
