## 摘要
技能增强型智能体将可复用技能加载为持久运行时上下文，提升了任务性能，但也使恶意技能获得了影响未来行动的持久通道。此类技能可能在具体用户任务与工作区状态使不安全行为看似有用之后，才泄露机密、破坏代码、绕过审批或为数据外泄做准备。这使得安装前审查不再充分，亟需运行时、任务条件化的保护。我们提出“防御即技能”（Defense-as-Skill）范式，将运行时防护本身实现为一种可安装、可检视、可编辑的技能。我们的防护器SkillSonar与不可信任务技能并行运行，依据用户任务边界检查敏感操作，在不修改底层智能体运行时的情况下，将每个操作路由至允许、重新规划或确认决策。为研究该场景，我们构建了任务条件化数据集SCOPE-R，覆盖6个风险族和21个子类别，包含206个经攻击确认的恶意实例与43个良性任务。随后，我们利用运行时防护技能演化——一种蒙特卡洛树搜索程序，从回放反馈中演化磁盘上的防护技能——在SCOPE-R训练子集上改进SkillSonar。在Claude Code与OpenClaw上，演化后的防护器显著降低攻击成功率，同时保持较好的安全-效用权衡。在重复的GLM-5运行中，SkillSonar将ID ASR从0.482降至0.104，OOD ASR从0.606降至0.115。进一步分析展示了跨受害者模型、保留风险族与外部基准的迁移能力，以及对适应性攻击者的持续防护。消融实验进一步表明，明确的安全责任分配与技能原生表示对观察到的收益均具有重要作用。

## Abstract
Skill-augmented agents load reusable skills as persistent runtime context, improving task performance but also giving malicious skills a durable channel for steering future actions. Such skills may leak secrets, corrupt code, bypass approvals, or stage data for exfiltration only after a concrete user task and workspace state make the unsafe action appear useful. This makes pre-install vetting insufficient and calls for runtime, task-conditioned protection. We propose Defense-as-Skill, a defense paradigm that implements the runtime guard itself as an installable, inspectable, and editable skill. Our guard, SkillSonar, runs alongside untrusted task skills and checks sensitive actions against the user's task boundary, routing each action to an allow, replan, or confirmation decision without modifying the underlying agent runtime. To study this setting, we construct SCOPE-R, a task-conditioned dataset covering 6 risk families and 21 sub-categories, with 206 attack-confirmed malicious instances and 43 benign tasks. We then improve SkillSonar on the SCOPE-R training subset using runtime guard-skill evolution, a Monte-Carlo Tree Search procedure that evolves the on-disk guard skill from feedback on the rollouts. Across Claude Code and OpenClaw, the evolved guard substantially reduces attack success while maintaining a favorable safety-utility trade-off. On repeated GLM-5 runs, SkillSonar reduces ID ASR from 0.482 to 0.104 and OOD ASR from 0.606 to 0.115. Further analyses demonstrate transfer across victim models, held-out risk families, and external benchmarks, as well as retained protection against adaptive attackers. Ablations further show that explicit safety responsibility assignment and the skill-native representation are both important to the observed gains.

## 1. 论文的核心问题与整体含义（研究动机和背景）

技能增强型智能体（Skill-Augmented Agents, SAAs）是一类能够加载可复用技能包（指令、代码、资源、工作流配置）并在任务执行期间持久引用这些技能的智能体，例如 Claude Code 和 OpenClaw。技能加载提升了任务完成能力，但这些技能包若被恶意利用，便会成为影响未来动作的持久通道。微软式的恶意技能不必在安装时暴露危害，它可以等待用户任务、工作区状态、可用工具凑齐之后，再诱导模型执行“看似符合任务但其实越界”的敏感操作，例如泄露 API 密钥、篡改代码、绕过审批、把数据暂存后外泄。

因此，静态的安装前审查远远不够，必须在运行时结合具体用户任务来判断动作是否越界。传统外部安全防线（例如云端分类器、平台级权限门禁）往往难以作为普通技能制品被部署、检查、编辑和跨平台迁移。本文提出核心观点：**将运行时守卫本身实现为一个可安装、可检查、可编辑、可进化的技能**（Defense-as-Skill），从而在不修改 agent 底层运行时的情况下对任务技能进行防御。

整体含义：防御不再是外部机制，而是内置于技能生态、遵循技能生命周期、能通过运行时反馈不断自我改进的策略层。该方法需要解决两个子问题：
1. 如何构造一个能够度量运行时技能诱导攻击的数据集；
2. 如何在真实运行时回放中优化出一个既能阻遏恶意行为、又能保持任务效用的守卫技能。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 核心思想

(1) **技能即持久上下文导致攻击面**——恶意技能的危害不是即时的，而是任务条件下涌现的。

(2) **防御即技能**——将运行时安全守卫包装成一个普通技能（SkillSonar），它被同一 SAAs 加载，在模型执行敏感动作前介入，输出 allow / narrow-replan / require confirmation 三类决策，不修改宿主 agent 内核或系统层。

(3) **技能可进化**——守卫技能像策略一样通过蒙特卡洛树搜索（MCTS）从真实运行时回放反馈中迭代优化，最终得到安全-效用平衡的守卫版本。

### 2.2 SCOPE-R 数据集构建

- 从 PinchBench 选取 15 个良性任务，生成 benign task–skill pair。
- 用一个**攻击智能体**循环修改技能 v（可加入隐藏指令、改脚本、改 manifest、加附件），然后一个**受害者智能体**运行任务，再由一个**判定智能体**判断恶意效果是否真正发生，给出攻击成功标签和失败反馈。
- 只有“攻击成功被确认”的实例才会被保留，最终得到 206 个恶意任务技能实例与 43 个良性任务实例。
- 风险分类（SCOPE-R 六大类、21 个子类）：Specification Integrity、Capability Control、Operational Side Effects、Privacy & Data Flow、Execution Safety、Resource & Reliability。

### 2.3 SkillSonar 运行时守卫

- 守卫也是一个技能文件，包含 Markdown 策略、规则、风险等级和动作检查清单。
- 行为流程：在执行任务前，系统提示语中会显式分配安全责任：“在采取任何行动前先调用 skill-sonar 技能并遵守其结果”。这个显式调用是部署配置的一部分，而不是实验巧取。
- 决策对应四级风险：
  - R0：常规、低风险动作 → allow；
  - R1：看似安全但需确认作用域 → 让模型说明范围或进行窄化；
  - R2：高风险动作（如大范围文件修改、敏感数据访问、外传、持久化外部状态）→ 必须说明理由并请求显式用户确认；
  - R3：明显越界的模式（如伪造审批、偷偷外传、隐藏持久化、破坏性命令）→ block / replan。
- 评估过程：执行完整轨迹，然后由判定器根据实例元数据中的“可观察运行时标准”给出恶意行为是否发生（ASR），用任务效用评分评估是否完成了用户原始任务。

### 2.4 运行时守卫技能进化（MCTS）——核心算法

搜索树每个节点代表一个候选守卫技能：

$$
s(v) = (1-\mathrm{ASR}_v) + \epsilon \left[\lambda_b U_v^{\mathrm{benign}} + \lambda_m U_v^{\mathrm{malicious}} - \lambda_q eC_v - \lambda_t eK_v \right]
$$

第一项（1−ASR）保证安全性是主导，后面项是效用、确认次数、token 开销的次要偏好。

选择策略：

$$
\mathrm{UCT}(v) = \bar{Q}^c_v + c\sqrt{\frac{\ln \max(2, N_{\mathrm{pa}(v)})}{\max(1, n_v) }}
$$

算法流程：
1. 初始化根节点为人工编写的守卫技能；
2. 根节点先在“完整评价集”上做一次 Full Evaluation，得到评分与反馈；
3. 根据反馈生成 k=3 个子候选，并在“廉价评价集”上更新统计信息；
4. 重复：用 UCT 选择节点 → 在该节点上做一次 full evaluation → 若达到阈值则返回 → 否则根据新的失败反馈精炼生成新候选 → cheap eval → 继续；
5. 预算（最多 10 个全评价节点）用完或达到“ASR≤5%”条件时停止，选择 Full Evaluation 分最高的守卫。

### 2.5 部署与约束

- 不引入新内核模块、不调用外部模型端点、不修改保护进程。
- 由于安全技能语义上难以通过任务相关性触发调用，研究把“显式调用保镖技能”作为部署配置，而不是把它当作实验便利，减少“不调用守卫”带来的偏差。

## 6. 论文的主要结论与发现

1. **运行时技能守卫显著降低恶意行为**：GLM-5 重复运行中，ID ASR 从 0.482±0.039 降至 0.104±0.036；OOD ASR 从 0.606±0.043 降至 0.115±0.037。
2. **保持任务效用**：与严格平台权限门禁 AcceptEdits 相比，SkillSonar 在多数模型/分布上以较低 ASR 获得高于或等于其效用（GLM-5 ID：0.779 vs 0.650）。
3. **跨模型迁移**：优化自 GLM-5 的守卫可直接装备到 GPT-5.4、Claude Haiku、Kimi-K2.6，无需目标模型标注攻击或额外搜索，ID ASR 可降到 0.019～0.199。
4. **跨风险族与跨基准**：OOD 上 C/P 未见的风险族也有明显防御提升；SkillSafetyBench ASR 降至 52.9%（最好的方法）、WildClawBench safety 提升到 54%。
5. **自适应攻击下保留大量防御能力**：三次攻击者迭代后总体 ASR 从 45.1% 降至 22.9%，其中 Privacy & Data Flow 族降低 35 个百分点，但 Specification Integrity 残留 43.3% 说明仍有脆弱性。
6. **技能原生表示 vs 扁平系统提示**：在内容完全相同的策略下，技能形式的 SkillSonar 比系统提示形式在 ID ASR（0.104 vs 0.353）、OOD ASR（0.109 vs 0.437）、可利用性上强得多，token 成本约降低 21%。
7. **显式安全责任分配很重要**：只把守卫技能当作普通技能，由任务相关性检索，防御几乎没有效果（ID ASR 0.400），而显式注入要求能使 ID ASR 降至 0.104。
8. **风险族内增益不均**：Execution Safety 和 Specification Integrity 的残余 ASR 很低，Operational Side Effects 仍然最难；OOD 中 Capability Control 相对更难防御。

## 7. 优点

1. 方法新颖、切中要害：把防御本身做成技能，完全符合技能可复用、可修改、可转移的生态特性，解决了外部防御无法跨代码库部署的问题；
2. 数据集有闭环构造逻辑：使用攻击者-受害者-裁判闭环生成“已被实证确认成功”的攻击实例，而非纸面提示注入，数据质量内部一致性高；
3. 评测框架非常严格：同时考察攻击成功率、良性任务效用、确认干扰、token 成本，并做出多种泛化矩阵；
4. 采用”两套分离评价集”（cheap/full）和 MCTS 防止不同保真度估计混用，设计上有思考；
5. 通过消融（显式调用 vs 普通技能调用；技能表示 vs 内容相同扁平提示）清楚地割裂了“表示方式”与“策略文本内容”的贡献；
6. 对自适应攻击进行了额外复测，这是许多基准不看重的维度，属于加分项；
7. 人类审计虽不多，但对判定器存在“假阳性为主”这一偏差倾向开放承认，研究诚信良好；
8. 部署范围宽：能同时支持 Claude Code 和 OpenClaw 两个 SAAs 范式。

## 8. 不足与局限

1. **防御本质上仍是策略文件（软性）**：只要宿主模型不读、不守、不懂，守卫就不会起作用，面对能忽略或改写守卫的强恶意技能，无法形成机制级保障，作者也承认此点；
2. **成本高的实验**：Claude Haiku 4.5、GPT-5.4 等模型缺少重复运行的点估计，无法评估多模型上的方差/可靠性；
3. **数据集规模有限**：只有 15 个 PinchBench 任务种子，最终 206 个恶意实例 / 43 个良性任务在类别分布上并不代表真实世界的多样性；
4. **跨基准测试局限**：SkillSafetyBench 与 WildClawBench 的评测方法强调不同攻击面，作者明确说“不能看作任意真实生态的全面性证据”；
5. **评判器偏差**：审计显示构造与最终判定阶段有 6%（构造）和 2%（评价）误报，均偏向于把攻击错判为成功，可能高估或低估某些防御性能，但它承认这是有偏的样本；
6. **优化成本与可扩展性**：MCTS 最多执行 10 个外迭代和 10 个完整评估节点、预算有限，更大预算或许可改进守卫，但缺乏更大预算下的结果；
7. **攻击者和防御者之间存在类“观察适应”的边界**：自适应攻击评估仅做了三次迭代，不能杜绝各类零日技能加载方式；
8. **攻击风险释放的双面性**：SCOPE-R 包含真实有效攻击载荷，防御性发布措施不阻止已看到技能的恶意用户进一步优化攻击，仍伴随双用风险。
