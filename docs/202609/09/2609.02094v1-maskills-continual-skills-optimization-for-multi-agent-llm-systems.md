## 摘要
基于LLM的多智能体系统在复杂任务上表现出色，但从交互经验中持续改进仍然具有挑战性。现有的自我反思方法会构建经验记忆，但这些记忆大多难以调用、细化或扩展，而智能体技能提供了一种更具可操作性的单元：结构化的程序性知识，规定了何时行动、如何行动以及使用哪些资源或工具。我们提出了MASkills，一种通过智能体技能优化多智能体LLM系统的持续学习框架。MASkills提出了一种新的智能体优化流程，该流程整合了技能条件化的信用分配、层级信用聚合和动量平滑优化，使智能体技能库能够通过细化、归纳、整合和剪枝进行演化。在HotpotQA、LoCoMo和GAIA上的实验证明了MASkills在多种智能体任务上的有效性。我们的代码可在https://github.com/DaRL-GenAI/MASkills获取。

## Abstract
LLM-based multi-agent systems have shown strong performance on complex tasks, yet continual improvement from interaction experience remains challenging. Existing self-reflection methods build experience memories, but memories are mostly hard to invoke, refine, or scale, while agent skills offer a more actionable unit: structured procedural knowledge that specifies when to act, how to act, and which resources or tools to use. We introduce MASkills, a continual learning framework that optimizes multi-agent LLM systems through agent skills. MASkills presents a new agent-optimization pipeline that integrates skill-conditioned credit assignment, hierarchical credit aggregation, and momentum-smoothed optimization, enabling agent skill libraries to evolve through refinement, induction, consolidation, and pruning. Experiments on HotpotQA, LoCoMo, and GAIA demonstrate the effectiveness of MASkills across multiple agentic tasks. Our code is available at https://github.com/DaRL-GenAI/MASkills

### 2. 论文提出的方法论：核心思想与关键技术细节

**总体框架：MASkills 持续学习循环**

论文将多智能体系统建模为 Dec-POMDP，每个智能体的策略通过技能库 Ki 重新参数化，通过一个四阶段闭环执行持续优化：

1. **多智能体技能执行（Multi-Agent Skill Execution）**
   - 每个智能体（LLM）配备一个技能库 Ki。
   - 每个技能是一个结构化文件系统式工件：`k = (y, m, R)`，即元数据文件（y，如 skill.yaml）、程序性指令文件（m，如 SKILL.md）和辅助资源集（R，如脚本、参考文件）。
   - 执行时仅在 prompt 中注入轻量的技能名称与描述，用户按需选择技能并动态加载完整指令，控制上下文长度，同时保留策略行为。
   - 由此产生的轨迹 τ 中明确记录每个智能体在每个时间步是否调用了技能（cit ∈ Ki ∪ {∅}），形成显式的技能调用痕迹 ξi，为技能级信用分配提供基础。

2. **技能条件化的信用分配（Skill-Conditioned Credit Assignment）**
   - 目标：将团队结果归因到"正确的智能体"和"正确的技能"两个层面。
   - 集中式语言批评者（Centralized LLM Critic）对每条轨迹中的每个被调用技能输出结构化自然语言信用 `C_text_i(τ, k)`，判断其对最终团队结果的贡献（帮助协调、冗余、导致失败、应泛化或应特化）。
   - 同时对智能体输出残差信用 `C_text_i(τ)`，用于捕捉无法归因于具体技能的效果，为"归纳新技能"提供信号。

3. **稳定化语言梯度下降（Stabilized Language Gradient Descent）**
   - 轨迹级编辑方向（Trajectory-level edit directions）：将信用文本转换为结构化的技能空间编辑方向 `g_i(τ, k)`（提出精炼、调整、泛化、移除等建议）。
   - 层级信用聚合（Hierarchical Aggregation）：使用 LLM 聚合算子，跨多条轨迹（批量 B）、跨多个技能、跨多个智能体、跨不同交互拓扑递归合并，形成稳定的技能级语言梯度估计 `G_i^(m)(k)`，解决语言反馈噪声大和相互矛盾的问题。
   - 动量平滑优化（Momentum-Smoothed Optimization）：公式 `K_i^(m+1) = LLM_Edit( K_i^(m), G_i^(m), G_i^(m-1) )` 中**当前编辑方向**和**历史编辑方向**共同用于本次编辑，相当于语言空间的动量法/指数滑动平均，抑制单轮噪声，保留长期一致的改进信号。注意这里"梯度"为概念类比，非数值求导。

4. **信用驱动的技能演化算子（Skill Evolution Operators）**
   - **Refinement（精炼）**：对"有用但不完美"的技能做局部差异式修改 `k ← k ⊕ Δk`，只修改被标记的问题区域，保留未涉及的结构。
   - **Induction（归纳）**：当聚合反馈指出已有技能无法解决顽固失败时，从难点轨迹集中提取新模式 `k_new ~ LLM_Propose(H_i, G_i^(m))`，新增技能补充能力空白。
   - **Consolidation（整合）**：将功能重叠的技能合并为更高级的抽象 `k_macro = LLM_Merge(k_a, k_b, …)`，防止技能库过度碎片化，增强可复用性。
   - **Pruning（剪枝）**：根据累积的稳定信用信号，删除长期边际效用为负、冗余、过时或极少调用的技能，控制库体规模。
   - **验证与回滚（Validation & Rollback）**：所有候选修改要先在留出验证集 D_val 中评估（固定其他智能体技能），式 `Ĵ_val(K'_i | K_−i) ≥ Ĵ_val(K_i | K_−i) − δ` 被满足才允许提交，否则丢弃并恢复原技能空间。相当于技能空间中的 trust-region 约束，防止错误编辑引入策略退化。

### 6. 论文的主要结论与发现

- **主实验层面**：MASkills 在三类基准（多跳问答 HotpotQA F1=76.3、长时记忆 LoCoMo 各项 F1/BLEU 均最高、通用助手 GAIA Avg=23.3）上均显著超过现有的提示工程方法、记忆方法和多智能体框架基线，表明技能空间优化能有效改善多种 agentic 任务。
- **技能演化本质**：技能比单纯 prompt 生成的技能或直接记忆中携带更多可复用的程序性行为模式。跨任务迁移实验显示，在一个环境中学到的技能可迁移到未见目标任务中并带来正向收益，说明学习到的是泛化的过程性抽象，而非过度拟合的任务提示词。
- **鲁棒性结论**：MASkills 在集中式、层级式和去中心化对等三种拓扑中均保持较好性能，不依赖特定协调结构。值得注意的是，最优拓扑具有任务依赖：HotpotQA/GAIA 偏好在去中心化对等（鼓励多样化探索），LoCoMo 偏好集中式协调（维护全局一致的长期记忆状态）。跨骨干实验证明在商业与开源模型上都有效。
- **关键机制验证**：验证/回滚机制对防止性能崩坏贡献最大（去除后 LoCoMo-MH F1 从 17.2 跌至 6.6），技能级信用分配和动量平滑带来一致增益，整合/剪枝有助于维持技能库健康。

### 7. 优点（方法与实验设计的亮点）

1. **研究范式创新**：将"经验记忆"全面升级为"结构化技能"——把单智能体的技能库演化（Voyager/EvoSkill）成功推广到多智能体协调场景，并给出了自洽的 Dec-POMDP 形式化与语言空间"伪策略梯度"理论框架。
2. **信用分配细化到技能层**：通过"技能级 + 智能体残差级"两级语言信用，解决了多智能体团队奖励与多技能交互之间的归因模糊问题。这一设计既清晰又具有可操作性。
3. **工程上稳健的优化管线**：动量平滑、层级聚合、验证-回滚机制三者协同，有效抑制了语言反馈噪声、单轮波动、以及离散高风险的技能修改，为可信的技能持续演化提供了方法论保障（类似 trust region 的约束）。
4. **完备的四算子技能库演化机制**：精炼（局部微调）、归纳（新能力生成）、整合（防碎片化）、剪枝（控规模）形成闭环库管理策略，直接回应了技能库可持续扩展的要求。
5. **消融与诊断设计较为全面**：对拓扑、骨干模型、组件消融、跨任务迁移等维度都做了覆盖，尤其是可视化区分"被接受的验证更新"与"被回滚的更新"（图2），直观展示了验证机制的实际意义。
