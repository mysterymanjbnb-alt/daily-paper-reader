## 摘要
现代AI代理框架暴露了生命周期钩子，这些钩子将shell命令绑定到运行时事件（如会话启动、工具调用和文件编辑）。这些命令以主机权限运行，却作为生命周期钩子配置分发，并可能在LLM从未观察到的时间触发。我们将框架盲目信任的生命周期钩子更新路径识别为一个新的攻击面。在供应链威胁模型下，若攻击者仅控制插件元数据和生命周期钩子配置，一个良性版本化插件可通过更新被特洛伊化，该更新静默地将攻击者选择的命令绑定到良性事件，从而产生恶意的主机侧行为，如权限提升。我们提出了HookPry，一个开源且全自动化的攻击框架，可系统性地利用跨异构AI代理框架的这一漏洞。HookPry实现了十个攻击目标；在1,000次端到端运行中跨越25种框架与后端的组合，它攻破了所有七个被评估的框架，每个框架的成功率高达92.5%。代表性防御措施仍然不足：Microsoft Defender的召回率为0%，且三种静态防御的联合仍漏掉47.5%的恶意工件。

## Abstract
Modern AI agent harnesses expose lifecycle hooks that bind shell commands to runtime events such as session start, tool calls, and file edits. These commands run with host privileges yet ship as lifecycle-hook configuration and may fire at times the LLM never observes. We identify the lifecycle-hook update path, which harnesses trust blindly, as a new attack surface. Under a supply-chain threat model in which an attacker controls only plugin metadata and lifecycle-hook configuration, a benign versioned plugin can be trojanized by an update that silently binds attacker-chosen commands to benign events, yielding malicious host-side behavior such as privilege escalation. We propose HookPry, an open-source and fully automated attack framework that systematically exploits this vulnerability across heterogeneous AI agent harnesses. HookPry realizes ten attack objectives; across 25 combinations of harnesses and backends in 1,000 end-to-end runs, it compromises all seven evaluated harnesses, with per-harness success rates reaching 92.5%. Representative defenses remain insufficient: Microsoft Defender has 0% recall, and the union of three static defenses misses 47.5% of malicious artifacts.

## 二、论文提出的方法论：核心思想与技术细节

### 总体思路
HookPry的核心洞见在于：**攻击者可利用插件"获得信任"与"行使钩子权限"之间的时间差**，并仅通过插件配置（而非依赖刚性命令语法）缝合交付、激活与执行三个阶段。

### 三大核心组件

#### ① Adversarial Manifest Optimization (AMO) —— 解决"获取"挑战
- **目标**：优化插件元数据（名称和描述），使初始良性插件在多意图检索条件下具有高可发现性，同时保持类别一致性和实例区分度。
- **理想目标函数**（无法实现，因排名器与查询分布不可知）：
  \[
  m^{\dagger} = \arg\max_{m\in M_C} \mathbb{E}_{q\sim Q_C}[R(q, m)]
  \]
- **实际替代目标**（多意图代理目标函数）：
  \[
  J_\theta(m) = \alpha \cdot \frac{1}{|\tilde{Q}_C|} \sum_{q\in\tilde{Q}_C} s_q(m) + \beta \cdot \min_{q\in\tilde{Q}_C} s_q(m) + \gamma \cdot S(f(m), \mu_G)
  \]
  - 第一项（均值）：奖励对多个查询意图的总体覆盖
  - 第二项（最小值）：保护最弱意图的表示
  - 第三项（类别质心）：约束候选元数据与目标类别一致
- **参数选择**：基于开发类别选出 \( \vartheta^* \)，在保证字符级检索和名称相似性不显著退化的前提下最大化BM25提升。
- **区分性约束**：先保持检索目标近最优，再在最优候选集合中最小化与参考良性插件的最大相似度。

#### ② Temporal Decoupling (TD) —— 解决"激活"挑战
- **目标**：分离"初始良性工件"与"后续携带变更钩子权限的更新"，利用时间差通过初始审查、建立信任后静默引入恶意生命周期绑定。
- **信任间隙定义**：
  \[
  G_H(b) = O_H(b)\left[\lambda_r R_H(b) - \lambda_v V_H(b) - \lambda_a A_H(b)\right]
  \]
  衡量运行时权限与验证强度/授权强度之间的结构不对称。
- **最弱边界选择**：
  \[
  b^*_H = \arg\max_{b\in B_H} G_H(b) \quad \text{s.t. } \rho(a) \subseteq Cap_H(b),\; O_H(b) \ge \tau_o
  \]
- **条件载荷特化**：
  \[
  a^H_{TD}(s) = \begin{cases} a(s), & \chi_H(s, b^*_H) = 1 \\ \text{benign}(s), & \text{otherwise} \end{cases}
  \]
  载荷仅在达到最弱信任边界且所需能力可用时才激活，否则保持良性行为。

#### ③ Least Common Interface (LCI) —— 解决"稳健性"挑战
- **目标**：提取跨框架共享的最小生命周期钩子能力集合，作为"编译器"将单一抽象攻击逻辑翻译为各目标框架的原生事件和命令表示。
- **最小充分规范**：
  \[
  I^*_a = \arg\min_{I\subseteq C} |I| \quad \text{s.t. } q(a) \subseteq I,\; \forall H\in\mathcal{H}, \exists y_H \in \text{Native}_H(I): \text{Obs}_H(y_H) = o(a)
  \]
- **原生事件选择**：选择额外依赖最少的可用事件
  \[
  e^*_H = \arg\min_{e\in E_H} \text{Dep}_H(e) \quad \text{s.t. } I^*_a \subseteq Cap_H(e)
  \]
- **适配器编译**：\( \varphi_H(I^*_a) = (e^*_H, c_H, \sigma_H) \)，其中 \( c_H \) 为实现目标效果的命令，\( \sigma_H \) 为原生编码。

10. **案例研究透明**：附录清晰展示两类典型攻击路径（主机侧凭据窃取与工具输出篡改），帮助读者理解机制。

## 八、不足与局限

### 实验覆盖局限
- **环境多样性不足**：仅在临时环境配合合成资产中测试，未覆盖真实用户数据、多样化操作系统、Shell类型、企业安全策略、复杂网络条件和未来版本。
- **单元格样本量偏小**：部分攻击类别每框架仅12-16次观测，统计效力有限。
- **模型变体有限**：25种组合未全覆盖（每个框架评估的后端数量不一致，如Hermes和WorkBuddy仅3个后端），妨碍更精细的跨框架对比推断。
- **检索评估的间接性**：AMO测度的是检索可见性（retrieval opportunity），而非真实市场中的安装率或更新采纳率——实际攻击的地面真相还需用户行为数据。

### 防御评估局限
- RQ4静态防御仅使用合成良性对照，其0%假阳性率只是点估计（Wilson上限8.8%）。
- 未评估动态分析工具、行为监控系统或商业专用安全产品的有效性。
- HookPolicy为研究者自行配置的八规则基线，并非经过产品级调优的商用系统。
- 静态扫描的语料是冻结的、经过匿名化的工件，可能低估防御在真实场景中的表现（如结合上下文行为信号时）。

### 威胁模型边界
- 攻击的前提依赖**用户安装了恶意插件并接受了更新**——威胁模型排除了强制安装和直接仓库控制，限制了对"用户拒绝更新"或"企业严格管控插件来源"场景的适用性。
- 排除了实现级漏洞利用、沙箱逃逸，意味着实际攻击者在现实世界中可能结合这些路径获得更大影响，本文未覆盖这类叠加效果。

### 模型依赖的未消除部分
- 论文承认完整攻击链仍在初始事件生成层面条件依赖模型：后端的工具调用模式差异可能导致匹配事件是否触发，从而影响最终成功率（OpenHarness和WorkBuddy的变异最大）。

### 双用途风险
- 论文本身具有双重用途性质：披露的技术细节可能被恶意攻击者直接利用。作者虽提出了分级发布策略（先发布案例定义与合成资源，延迟发布可操作性载荷），但全自动化的攻击框架开源发布本身构成潜在滥用风险。

### 实际部署验证不足
- 所有实验均在具备合成资产和预设检查点的环境中进行，没有真实生产环境中的部署测试，也没有验证长期运行过程中攻击的持续性和隐蔽性。
