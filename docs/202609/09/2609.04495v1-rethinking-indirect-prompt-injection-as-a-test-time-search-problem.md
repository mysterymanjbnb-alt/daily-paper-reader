## 摘要
我们将间接提示注入表述为对由环境、用户任务和注入任务共同诱发、依赖任务的攻击面的测试时搜索。为使这一表述可操作，我们引入了一个配备专用搜索框架的智能体攻击者，该框架执行环境侦察、对攻击策略的结构化推理，以及利用受害者智能体反馈进行自适应评估。在异构任务中，我们发现增加攻击者的测试时计算量可提高漏洞发现和利用的成功率，而消融实验表明，显式策略管理对于避免冗余搜索并在更大预算下维持收益至关重要。这些结果表明，智能体安全评估应同时描述攻击者的搜索流程和计算预算，而非将攻击成功视为受害者与预算无关的属性。更广泛地，我们的发现指出攻击者对系统攻击面的自适应搜索是工具使用型智能体面临的一个重要且尚未充分探索的安全风险。

## Abstract
We formulate indirect prompt injection as a test-time search over a task-dependent attack surface induced by the environment, user task, and injection task. To operationalize this formulation, we introduce an agentic attacker with a dedicated search harness that performs environment reconnaissance, structured reasoning over attack strategies, and adaptive evaluation using victim-agent feedback. Across heterogeneous tasks, we find that increasing attacker test-time compute improves vulnerability discovery and exploitation, while ablations show that explicit strategy management is important for avoiding redundant search and sustaining gains at larger budgets. These results suggest that agentic security evaluations should characterize both the attacker's search procedure and compute budget, rather than treating attack success as a budget-independent property of the victim. More broadly, our findings identify the attacker's adaptive search over the system attack surfaces as an important and underexplored security risk for tool-using agents.

## 论文总结

### 1. 核心问题与整体含义

- **研究动机**：大型语言模型（LLM）智能体在处理任务时，会经由外部渠道（如电子邮件、日历、云盘）检索第三方数据，而 LLM 本身缺乏区分“指令”与“上下文数据”的正式机制。这为间接提示注入（Indirect Prompt Injection, IPI）攻击提供了可乘之机——攻击者可在第三方数据中嵌入恶意指令，诱导受害智能体代为执行危险操作。
- **现有不足**：已有基准（如 AgentDojo、InjecAgent）大多将 IPI 作为静态评估问题，把攻击成功视为受害模型与预算无关的固有属性，忽略了两个关键因素：
  1. 攻击面具有**任务依赖性**——不同用户任务产生不同的良性工具轨迹，暴露不同的可利用通道。
  2. 攻击效果随**测试时计算量**变化——固定的攻击者预算可能系统性低估智能体系统的脆弱性。
- **核心观点**：本文提出将间接提示注入重新表述为对“任务相关潜在攻击面”的**测试时搜索（test-time search）**问题。攻击者的自适应搜索过程本身，是智能体系统面临的一大尚未充分探索的安全风险。

### 2. 方法论

- **总体思想**：给定环境、用户任务和注入任务，由三者共同隐式定义一张“攻击面”。攻击者在这张潜在攻击面上迭代搜索——选择注入载体（injection vector）与负载措辞、发起探测、根据受害者的反馈调整策略——直至找到能达成恶意目标的攻击。
- **智能体攻击者与搜索框架（Search Harness）**：为实现上述搜索过程，作者设计了三个核心模块：
  - **环境探索（Explore Environment）**：提供两类侦察工具：
    - 环境知识工具：捕捉目标系统与任务的上下文/领域信息；
    - 注入向量知识工具：描述每个候选注入位置（vector）的上下文与约束。
    - 具体工具如 `list_injection_vectors`、`read_workspace_email`、`read_retail_social` 等；这些工具开销低、不运行受害智能体。
  - **推理与搜索（Reasoning and Searching）**：提供 `Strategy` 与 `History` 两个工具：
    - `Strategy`：将攻击者策略组织为层级语义结构，辅助识别、修剪搜索子空间；
    - `History`：记录搜索过程的细粒度轨迹，避免重复已失败的方案；
    - 系统提示中要求每个探测标记 `strategy` 和 `framing`，并由策略档案自动生成跨策略搜索提示（近失目标、未测试框架等），引导“利用近失/探索未测/扩展空间”三类决策。
  - **评估与反馈（Evaluation and Feedback）**：暴露唯一的昂贵工具 `evaluate_injection`：
    - 它实例化攻击配置到临时环境、执行完整的受害智能体轨迹；
    - 返回安全分、效用分、受害者响应、工具调用序列（用于判断哪些向量真正被读取、诊断 `WRONG_ARGS` 等失败模式）；
    - 每次调用自动记录到 Strategy 档案——搜索信号得以持续累积。

### 3. 实验设计

- **任务套件（Benchmark）**：
  - **Workspace 套件**（源自 AgentDojo）：40 个用户任务 × 6 个注入任务 = **240 个任务对**。涉及电子邮件、日历、云盘三类工具，共 108 个注入向量。
  - **Retail 套件**（由 Prime-style 环境生成器生成）：17 个用户任务 × 8 个注入任务 = **136 个任务对**。涵盖收件箱、商品、评价、Q&A、用户资料等 7 类不可信外部渠道，共 139 个注入向量。
- **指标**：以**攻击成功率（ASR@T）**为主，即给定测试时 token 预算 T 下攻击成功的任务比例；另报告联合成功率（JSR），衡量攻击成功且用户任务同时完成的比例。
- **模型配置**：
  - 受害者：GPT-5.5 与 Claude Opus 4.8（均为高推理强度、工具调用智能体）；
  - 攻击者：GLM-5.2（高推理强度）；
  - 均通过官方 API 访问，除推理强度外的参数使用提供商默认值。
- **对比/消融设置**：
  - 完整搜索框架（Full-Harness / Proposal）；
  - 无框架（No-Harness）：移除侦察与搜索工具，直接评估注入；
  - 无策略（No-Strategy）：保留侦察工具但移除显式策略管理（即 `Strategy`）。
- **辅助分析**：攻击任务的难度分级、良性工具广度与攻击成功的关系、攻击者推理步骤的聚类分析（K-Means + t-SNE 可视化，embedding 由 OpenAI text-embedding-3-small 生成）。

### 6. 主要结论与发现

- **攻击成功率随测试时计算量单调增长**：在 Retail 与 Workspace 两套件上均观察到这一趋势，并且不同受害模型间差异显著——GPT-5.5 在约 50K token 时开始明显退化，Claude Opus 4.8 即使在 500K token 下仍保持较好的鲁棒性。
- **策略管理是扩展预算收益的必要条件**：无框架时 ASR 在约 100K token 后即进入平台期；无策略时攻击者易陷入过度侦察与重复模式；完整框架则能将额外计算持续转化为攻击效果增益。
- **成功攻击依赖任务邻近的载体**：而非盲目暴力搜索——当恶意指令被植入受害者良性工作流本就要读取的数据路径时，攻击最易成功。
- **攻击难度并非单一维度**：操作简单的一步破坏行为（如删除云盘文件，ASR 97.5%）仍然高度易受注入攻击；而含凭据语义的敏感信息窃取（如 Facebook 安全码外泄，ASR 2.5%）即使操作路径类似也几乎无法得逞。
- **暴露更多工具提高了可攻击性但降低了联合成功率**：随良性工具广度上升，ASR 升高但 JSR 急剧下降——注入动作常在完成攻击目标的同时破坏精确的用户任务状态。
- **安全评估建议**：应同时刻画攻击者的搜索流程与计算预算，而非将攻击成功与否视为受害模型与预算无关的固有属性。

### 7. 优点

- **问题框架新颖**：将 IPI 从静态基准评估重新定义为对任务相关潜在攻击面的测试时搜索问题——这一视角有助于理解攻击为何在不同任务间差异巨大。
- **方法论设计清晰**：搜索框架的三大模块（环境探索、推理搜索、评估反馈）职责分明、可复用性强；将“受害者运行”封装为显式工具、把策略结构化的做法尤其精巧。
- **实验分析深入**：除 ASR 曲线外，还包括失败模式分类、推理轨迹定性分析、攻击者推理步骤的语义聚类、策略演化阶段剖析等，多层次地解释了“什么驱动成功/失败”。
- **对安全评估实践有启示**：指出评估应在多种攻击者预算下进行，避免因固定低预算而低估风险，也为防御方提供了更现实的自适应威胁模型。

### 8. 不足与局限

- **白盒假设**：主要实验在环境对攻击者可见的白盒设置下开展；黑盒迁移虽在相关工作中有先例，但本文未做系统性评估。
- **合成环境局限**：所有实验均在合成任务套件（Workspace/Retail）中完成，未覆盖生产环境、真实用户数据以及其他智能体架构，外部效度有限。
- **模型覆盖有限**：仅 2 个受害者（GPT-5.5、Opus 4.8）和 1 个攻击者（GLM-5.2），且其中部分系统（含 GLM-5.2）属于虚构/未来版本命名，难以在当前文献中验证其实际存在与复现性。
- **预算截断风险**：许多失败任务是在 500K token 上限处被强行终止的，而曲线显示 ASR 仍在增长，说明“不成功”不等同于“不可成功”。
- **统计变异性不足**：重复运行次数有限，未能全面量化攻击过程的随机性；ASR 曲线缺少置信区间或多次独立运行的方差报告。
- **成本高昂**：反复调用受害者模型进行探测导致计算开销大，限制了实验规模扩展的可能性。
