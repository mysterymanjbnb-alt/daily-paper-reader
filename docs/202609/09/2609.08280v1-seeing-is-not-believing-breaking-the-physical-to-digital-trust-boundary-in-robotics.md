## 摘要
在多机器人协作中，任务交接依赖于下游验证器执行远程证明，这些验证器检查传感器遥测数据，以确保机器人的物理行为与其分配的任务严格一致。但这样的遥测数据能信吗？我们表明，它通常不可信。在本文中，我们揭示了机器人操作系统（ROS）2的一个严重漏洞：通过修改一个环境变量，攻击者可以执行一个预构建的钩子，在遥测和控制信号发布之前隐蔽地拦截并注入它们。因此，攻击者可以劫持机器人执行危险任务，同时用合成虚假遥测数据欺骗下游验证器。更糟糕的是，利用对第三方Docker容器和辅助工具的广泛依赖，攻击者可以分发嵌入这些恶意钩子的受损包，轻松发动此类攻击。在一台运行安全ROS 2的实体Franka Emika机械臂上，我们的攻击实时注入伪造的遥测数据，抖动仅约3毫秒，保持时间同步和硬件完整性，同时即使面对基于AI的检测器也达到了87%的成功率。我们已负责任地将这些发现披露给ROS 2开发团队。我们准备了一段演示视频，可在https://youtu.be/ExeiGqUrnhQ观看。

## Abstract
In multi-robot collaboration, task handovers rely on downstream verifiers performing remote attestation, which inspects sensor telemetry to ensure a robot's physical behavior strictly matches its assigned task. But can this telemetry be trusted? We show that it often cannot. In this paper, we uncover a severe vulnerability in Robot Operating System (ROS) 2: by modifying a single environment variable, an adversary can execute a pre-built hook to covertly intercept and inject both telemetry and control signals before they are published. Consequently, adversaries can hijack a robot to perform dangerous tasks while spoofing downstream verifiers with synthesized fake telemetry. Worse still, by exploiting the widespread reliance on third-party Docker containers and auxiliary tools, attackers can distribute compromised packages embedded with these malicious hooks to launch such attacks easily. On a physical Franka Emika robotic arm running Secure ROS 2, our attack injects fabricated telemetry in real time with only around 3 ms of jitter, preserving temporal synchronization and hardware integrity while achieving an 87% success rate even against an AI-based detector. We have responsibly disclosed these findings to the ROS 2 development team. We prepared a demo video available at https://youtu.be/ExeiGqUrnhQ.

### 1. 核心问题与整体含义（研究动机与背景）

- **信任依赖问题**：多机器人协作中，下游验证器（人类操作员、对等机器人或监控模块）难以持续观察对方机器人的物理行为，因此普遍依赖**传感器遥测数据**（如相机帧、关节状态）来**远程证明**任务是否被正确执行，该机制依赖一种“物理行为 ↔ 数字报告状态”的信任边界。
- **核心问题陈述**：该信任边界是否安全？**不一定**。论文发现 ROS 2 存在一个严重漏洞——攻击者只需**修改一个环境变量**（`LD_PRELOAD`），即可在消息发布前注入伪造遥测数据和控制信号，实现：
  - **劫持与欺骗**：篡改控制信号让真实机器人执行危险动作，同时通过替换出站遥测数据让下游验证器“看到”正常执行轨迹；
  - **拒绝服务（DoS）**：注入不一致的异常遥测，导致验证流程中断或反复诊断。
- **安全机制盲区**：Secure ROS 2（SROS 2）提供的认证与完整性保护只作用于**消息离开应用层之后**，并不能保证消息内容本身忠实反映物理真实状态。信任边界缺口位于**加密通道之前**。
- **供应链放大**：论文爬取了 4,429 个 ROS 相关 Docker 镜像和 5,322 个 GitHub 仓库，发现超过 4,000 个镜像由未经验证的个人发布，累计约 760 万次拉取（占 10.2%）；2,000 多个 GitHub 仓库星星少于 5 个。此类生态高度分散、缺乏统一可信来源，为恶意容器的分发提供了现实可行的渠道。
- **研究意义**：上述结果证明“安全通信 ≠ 物理真实执行”，是首次系统的物理-数字信任边界研究，且已向 ROS 2 开发团队披露，并在 PMC 会议上被讨论。

### 2. 方法论：核心思想、关键技术细节与流程

- **攻击切入点**：通过 Python 调试、radare2 反汇编工具分析 ROS 2 Python 发行版发布路径，确定所有消息都经过核心库中统一入口 `rcl_publish()`。
- **关键技术——用户态函数插桩（Pre-Publication Function Interposition）**：
  - 利用 Linux `LD_PRELOAD` 环境变量机制，指定恶意共享库（`Hook.so`）提前加载；
  - `Hook.so` 导出同名符号 `rcl_publish`，使动态链接器将过程调用先转入该钩子函数；
  - 钩子通过 `dlsym(RTLD_NEXT, "rcl_publish")` 找到并调用合法库中的真实实现；
  - 整个技术不修改任何官方 ROS 2 二进制、不需要 root 权限、不需要内核漏洞。
- **UAF 边界安全性说明**：该拦截发生在消息交给 RMW/DDS 通信栈之前，因此 **SROS 2 无法防御**此攻击；被篡改的消息随后照常经过认证和加密，作为合法流量传输到验证端。
- **攻击管线（5 步骤）**：
  1. 正常命令 → 策略模型输出合法控制信号；
  2. 恶意钩子同时拦截控制信号和真实传感器遥测数据 → 送到攻击者 PC；
  3. PC 使用 **Isaac Sim 高保真仿真器**，对被拦截的控制信号驱动虚拟机械臂执行合法动作；
  4. 从仿真器中提取合成遥测数据，经关键处理（见下述数学模型）产生“物理级真实”假遥测；
  5. 假遥测发送回钩子替换真实遥测 → 下游验证器与策略模型均被同步欺骗；与此同时，攻击者通过键盘远程操控真实机器人执行恶意任务（如抛下包裹）。
- **伪造遥测的现实性设计（核心公式与思想）**：
  - **潜隐微运动（Latent Micro-Motion）**：直接在仿真轨迹上叠加扰动，而非对每个遥测通道独立加噪声：
    \[
    q_j(t) = q_j^*(t) + \delta q_j(t)
    \]
  - **公式（2）**：将扰动分解为“振动 + 漂移 + 粘滑”三项：
    \[
    \delta q_j(t) = \sum_{m=1}^{M} s_{j,m}(t) + d_j(t) + J_j(t)
    \]
    - 振动项 \(s_{j,m}(t)\) 采用**阻尼随机振荡器**建模，保持时域频域结构；
    - 漂移项 \(d_j(t)\) 采用 **Ornstein-Uhlenbeck 过程**；
    - 粘滑项 \(J_j(t)\) 模拟摩擦导致的微小不连续跳变。
  - **关节间耦合（Inter-Joint Coupling）**：使用机器人质量矩阵 \(M(q^*)\) 设计协方差：
    \[
    \Sigma_w = M(q^*)^{-1}\Sigma_u M(q^*)^{-T}
    \]
    该操作确保不同关节的扰动相关性由物理结构派生，而非独立噪声。
  - **跨通道物理一致性**：位置 \(q(t)\)、速度 \(\dot{q}(t)\) 由同一受扰轨迹推导，力矩值通过逆动力学计算：
    \[
    \tau_{\mathrm{model}} = M(q)\ddot{q} + C(q, \dot{q})\dot{q} + g(q) + f_{\mathrm{fric}}(\dot{q})
    \]
    由于位置、速度、力矩来自**同一受扰轨迹**，假数据在时间结构、关节间关联、跨通道物理一致性上均无法分离。

### 6. 主要结论与发现

- **攻击可行性**：
  - 在真实 Franka 机械臂 + Secure ROS 2 条件下，攻击成功率为 **100%**（含 SROS 2 与否）；
  - 对 RViz 用户、策略模型、验证器均保持欺骗；机器人真实动作与验证器观察完全脱节。
- **隐蔽性**：
  - 消息注入实时性强：延迟抖动约 **2 ms**，控制在 3 ms 以下，完全低于 30 Hz（33 ms）遥测周期的实时需求；消息丢弃率 **0%**；
  - 伪造遥测在位置 RMSE、速度 DTW 距离、力矩标准差上均落在 **真实-真实差异区间（Real-Real reference）** 内；
  - 对 4 个检测器的绕过率分别为 **D1：98%、D2：100%、D3：95%、D4：87%**——时序预测型检测器成功拦截但误报高，单一检测器无法可靠检出；
  - 图像伪造在主观和结构上保持了对象放置结果的一致性和物理合理性。
- **消融实验结论**：
  - 未处理的问题：原始仿真数据仅能欺骗 D1，几乎不能欺骗 D2、D3、D4（绕过率低）；
  - 潜隐微运动是关键：把 D4（时序检测）绕过率从 13% 提升到 66%，但方向上是必要的非充分条件；
  - 关节间耦合极大强化 D3 绕过率（5%→92%）；
  - 唯有“潜隐微运动 + 耦合 + 跨通道一致性”的完整管线可同时绕过**全部四个检测器**，使位置/速度/力矩综合误差降低约 10%~34%。
- **核心论断**：移动设备上的 SROS 2 的加密保证不能证伪“真机遥测”，单纯“安全传输”不等于“物理真实”；建议将信任根移动到物理感知层（如安全 MCU/TEE 在采集时刻签名并附加单调计数器），才能真正杜绝预发布伪造与重放。

### 7. 优点与亮点

- **问题选取精准，通用性强**：直指多机器人任务交接中最基础的信任假设（远端遥测可证明物理行为），影响远超特定漏洞披露。
- **攻击面分析细致、由果溯因**：借助逐步调试 + radare2 静态分析定位 `rcl_publish` 统一入口，攻击在原系统架构上零修改即可运行，思路清晰。
- **现实性建模到位**：针对机器人物理信号的时间结构、频率特征、关节相关性、力矩-位置一致性分别设计了概率模型（阻尼振荡器 → OU 过程 → 质量矩阵 → 逆动力学），系统化超越简单加噪攻击。
- **威胁模型的克制性与实际性**：明确不假设 root 权限、不利用内核漏洞、不改动官方二进制、不需要破解 SROS 2；结合供应链统计分析证明了现实中可触发路径。
- **实验设计完整**：覆盖成功率、延迟/抖动/丢包率、保真度、多模态、检测器对抗、消融分析；
- **消融实验和对照基线**：引入“真实-真实”基线，消融逐级叠加各模块，对照清晰，证据充分；
- **负责任披露**：向 ROS 2 开发团队披露并通过项目管理委员会（PMC）讨论，具备工业界影响力。

### 8. 不足与局限

- **实验环境覆盖有限**：单臂平台，单任务（pick and place），无多机器人协同场景；未在真实工业控制系统中验证；
- **检测器针对性有待加强**：D1–D4 是论文自行设计的代理检测器，没有对商用/工业界实际远程验证软件进行攻击测试；
- **统计与潜在的偏差风险**：保真度的部分指标是以“真实-真实差异”为参照，无法完全排除伪造数据微小系统性偏差积累；图像数据只做定性比较，未量化与身份感知（identity-aware）验证的一致性；
