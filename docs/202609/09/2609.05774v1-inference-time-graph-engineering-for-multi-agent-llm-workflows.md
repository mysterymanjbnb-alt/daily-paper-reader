## 摘要
近期多智能体LLM系统日益依赖图结构通信来协调专业化智能体。我们从图工程的角度重新审视多智能体编排：不是优化静态拓扑，而是综合一个任务条件化的时间工作流图，该图共同指定智能体连接性和边级通信语义。我们引入ReActNet，一个无需训练的框架，它将查询和一组角色专业化智能体编译为一系列有向通信图。每个图快照对应一个推理阶段，每条边携带一条自然语言指令，指定源智能体应向目标智能体提供的消息。然后通过结构化消息传递执行编译后的时间图：智能体通过将先前的状态与来自控制器分配的邻居的消息集成来更新其推理状态，最终聚合器将结果状态综合为答案。这种设计将图编译与图执行分离，使多智能体协调明确、可检查且任务条件化，无需强化学习或基于梯度的拓扑优化。在知识推理、数学问题求解、代码生成和GAIA式助手任务中，ReActNet一致优于固定拓扑和学习拓扑基线，同时保持有竞争力的推理成本。这些结果表明，有效的多智能体编排不仅取决于哪些智能体通信，还取决于工程化可执行的工作流图，该图编码推理过程中信息应流动的时间、原因和方式。

## Abstract
Recent multi-agent LLM systems increasingly rely on graph-structured communication to coordinate specialized agents. We revisit multi-agent orchestration from a graph-engineering perspective: rather than optimizing a static topology, we synthesize a task-conditioned temporal workflow graph that jointly specifies agent connectivity and edge-level communication semantics. We introduce ReActNet, a training-free framework that compiles a query and a set of role-specialized agents into a sequence of directed communication graphs. Each graph snapshot corresponds to one reasoning stage, and each edge carries a natural-language instruction specifying the message that a source agent should provide to a target agent. The compiled temporal graph is then executed through structured message passing: agents update their reasoning states by integrating their previous states with messages from controller-assigned neighbors, and a final aggregator synthesizes the resulting states into the answer. This design separates graph compilation from graph execution, making multi-agent coordination explicit, inspectable, and task-conditioned without requiring reinforcement learning or gradient-based topology optimization. Across knowledge reasoning, mathematical problem solving, code generation, and GAIA-style assistant tasks, ReActNet consistently improves over fixed-topology and learned-topology baselines while maintaining competitive inference cost. These results suggest that effective multi-agent orchestration depends not only on which agents communicate, but also on engineering executable workflow graphs that encode when, why, and how information should flow during reasoning.

## 1. 论文的核心问题与整体含义（研究动机与背景）

- 多智能体LLM系统通常通过定义或学习“通信拓扑”来协调多个角色专业化的智能体协作——哪种拓扑被表示为有向/无向图，节点为智能体，边表示信息能否流动。
- 现有方法大多**以拓扑为中心**：只优化“谁可以和谁通信”的邻接模式，却把通信的**语义内容、时机、阶段和最终聚合方式**隐式化处理；例如程序员到验证者的边不仅应表示“允许通信”，还应明确是提供代码、指出失败案例、解释算法不变式，还是回应批评。
- 固定拓扑（链、树、星、完全图、随机图等）不具备任务自适应性；学习/优化拓扑的方法（GPTSwarm、G-Designer、DyLAN 等）需要训练阶段或迭代优化，成本高，且仍未显式编码信息传输的“原因”与“时机”。
- 因此，作者提出一种**“图工程”视角**：多智能体编排的核心对象不应当是静态拓扑，而是一个**可执行的、任务条件化的“工作流图”**，在节点（智能体）之外显式定义：边的含义、推理阶段、边级自然语言指令、状态更新方式。
- 核心研究问题：**在推理时、无需训练的情况下，如何为给定查询和一组角色智能体，综合出一个带有时序与通信语义的工作流图，以提升多智能体系统的推理与生成质量？**
- 整体含义：多智能体协作的效果不取决于“谁连谁”，还取决于是否人为工程化出一条规定信息在**何时、为何、如何**流动的可执行工作流图。

## 2. 论文提出的方法论：核心思想、关键技术细节与算法流程

### 核心思想：Compile-then-Execute（先编译后执行）

- 将多智能体协作分为**图编译**与**图执行**两个阶段：
  - **编译阶段**：LLM 控制器（controller）在单次前向中，将“查询 + 可用智能体角色”编译为一张**指令类型的时序工作流图**；
  - **执行阶段**：各角色智能体按照这张图进行结构化消息传递，逐步更新推理状态，最后由合成节点汇总并输出答案。

### 形式化模型

1. **多智能体交互图定义**
   - 图 \(\mathcal G = \{G^{(t)}\}_{t=1}^T\)：由 \(T\) 个图快照组成。
   - 每个 \(G^{(t)}=(V,E^{(t)})\)：节点集 \(V\) 固定，有向边集 \(E^{(t)}\) 随时间变化。
   - 有向边 \(e^{(t)}_{j\to i}\)：表示第 \(t\) 轮智能体 \(j\) 向 \(i\) 发送信息。
   - **边属性即控制器指令**：每条边带着一条自然语言指令，指明源智能体应给目标智能体发送**何种推理贡献**（如提出解题策略、检查计算、提供代码、找反例、验证一致性等）。

2. **角色专业化智能体作为工作流节点**
   - 每个智能体 \(A^{(i)}\) 由 LLM + 角色 prompt \(p^{(i)}_{\text{role}}\) 实例化；
   - 将多智能体系统描述为 \(\text{pMAS}\)（所有角色 prompt 拼接）。

3. **控制器作为推理时图编译器**
   \[
   \mathcal W_q = \{G^{(t)}\}_{t=1}^T = F_{\text{controller}}(p^{\text{controller}}_{\text{role}}; T; \text{pMAS}; q)
   \]
   - 控制器在**任何智能体交互发生前**，单次生成完整的时序工作流图（所有边与所有轮次的边指令），无在线重规划。

4. **指令类型边**
   \[
   e^{(t)}_{j\to i}=((j,i),\xi^{(t)}_{j\to i})
   \]
   - \((j,i)\) 定义通信路由；
   - \(\xi^{(t)}_{j\to i}\) 为自然语言指令（例子见附录）。
   - 由此把“通信拓扑”和“通信语义”统一。

5. **图的执行：结构化消息传递**
   - 初始状态：每个智能体独立对查询生成初始推理状态：
     \[
     r^{(i)}_0 = A^{(i)}(p^{(i)}_{\text{role}};q)
     \]
   - 每条边激活时，源智能体根据边指令生成消息：
     \[
     m^{(t)}_{(j\to i)} = A^{(j)}(p^{(j)}_{\text{role}}; q; r^{(j)}_{t-1}; \xi^{(t)}_{j\to i})
     \]
   - 目标智能体聚合所有 incoming 消息并更新状态：
     \[
     r^{(i)}_t = A^{(i)}\left(p^{(i)}_{\text{role}}; q; r^{(i)}_{t-1}; \mathcal m^{(t)}_i\right)
     \]

6. **最终合成节点**
   \[
   a = F_{\text{syn}}(p^{\text{syn}}_{\text{role}}; \{r^{(i)}_T\}_{i=1}^N; q)
   \]
   - 识别智能体间的一致与分歧，汇总为最终答案。
   - 可将整个 ReActNet 流程用 Algorithm 1 描述（附录 D）：先构建 pMAS；对每个查询编译图；初始化节点；逐轮执行消息传递与状态更新；最后聚合输出。

### 关键设计特点
- **无训练**：无需强化学习、梯度优化或拓扑学习；
- **可检查/可解释**：边指令、轮次快照、通信路由均显式；
- **全局前瞻规划**：一次前向生成所有时间步的图，保证跨轮连贯；
- **图中自带语义**：不同于二进制邻接矩阵，边本身是 LLM 生成的自然语言“微任务”。

## 6. 论文的主要结论与发现

- **性能**：ReActNet 在 6 个数据集上取得 5 个第一（MMLU 86.93、MultiArith 100.00、SVAMP 94.67、AQuA 87.70、HumanEval 92.74，平均 92.75）；在 GSM8K 上排名第三（94.45），但与最佳差距很小。
- 在 GAIA 验证集上，ReActNet 取得 12.72%，超过 DyLAN/GPTSwarm（11.52）和 G-Designer（10.91），且无需训练。
- **效率**：无训练 token，推理 token 低于需要训练或迭代优化的方法；推理墙钟时间与 G-Designer、Complete Graph 等相比更短。
- **可扩展性**：随着 N 从 5 增至 20，ReActNet 的推理时间几乎不变（约 7 分钟），而 Chain、Complete Graph、GPTSwarm、G-Designer 都有显著上升（如 GPTSwarm 从 62 分钟增至 412 分钟）。
- **轮数敏感性**：T=3 最佳；T=1 已超 G-Designer；T=5 效果回落——说明过多轮引入冗余/冲突信息有害。
- **模型兼容性**：Claude Sonnet 4 基座上，MMLU 比 G-Designer 高 9.15；Llama-3.3-70B-Instruct 上高 3.27；数学任务 GSM8K 上略低于 G-Designer 0.5~0.8 分。
- **结构可解释性**：由附录示例可见，ReActNet 生成的图具有任务依赖、阶段依赖的特征：第 1 轮偏向分解/信息收集，第 2 轮偏向计算/交叉验证/工具执行，第 3 轮偏向一致性检验与最终验证；边密度与方向都会随任务动态变化，会自动产生反馈环。
- 最终核心结论：**多智能体编排的有效性取决于显式工程化可执行工作流图：不仅规划谁与谁通信和传递的信息量，更应规划信息在哪个推理阶段传递、以怎样的边级语义组织协作。**

## 7. 优点

- **新颖的图工程视角**：首次明确把“multi-agent orchestration”问题转换为“在推理时合成任务条件化可执行工作流图”的问题，跳出了“拓扑学习 vs 静态拓扑”的旧二元框架。
- **编译-执行分离**：控制器一次性生成全时序图，执行器不必在零样本交互中即时调整；这既保证全局一致，又不像在线动态图那样产生重复规划成本。
- **边级自然语言指令**：使消息传递语义显式化——用同一 LLM 实现“控制器指定功能”和“智能体执行该功能”，模块化、可检查、可解释，不需要额外模型或特殊训练。
- **训练免费与高效**：无训练参数、无梯度/RL，兼容任意 API 与开源模型；推理时间近乎恒定，比 GPTSwarm、DyLAN、G-Designer 等更省 token 和时间。
- **评估覆盖广**：覆盖通用知识、数学、代码、GAIA 真实任务，对比 18 个基线；还从不同基座模型（GPT-4o、GPT-3.5、Llama、Claude）与不同 Agent 数做了交叉验证。
- **定量与定性结合**：不仅给出总体分数，还用 GAIA 中的轮次通信图示例展示 ReActNet 的“按阶段变化、任务自适应”行为，增加了说服力。

  - 文中对“何时停止/何时不应通信”没有明确约束，导致 T=5 时性能下降，说明冗余通信的风险还没有被机制性控制；
  - 没有讨论多智能体在图执行中放大幻觉、错误传播、以及指令跟随失败等安全可靠性问题。

> 总体而言，ReActNet 是一个角度新颖、方案简洁且有力的免训练多智能体协作框架，但在消融严格性、评测规模与统计可靠性上仍需进一步加强。
