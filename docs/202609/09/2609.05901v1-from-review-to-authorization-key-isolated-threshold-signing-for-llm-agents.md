## 摘要
自主LLM代理可以将不可信内容转化为实际动作，如支付和权限更改。如果同一进程解释此内容并控制可重用的签名凭证，则提示注入可能跨越判断边界并到达执行权限。我们提出了KITA，一种从审查到授权的架构，将用户的个人私密签名密钥和每个阈值签名密钥份额都保留在所有LLM进程之外。在阈值签名不可伪造性和我们的系统假设下，如果没有来自t个不同域的签名贡献，则破坏提议者和少于t个审查者签名域不能为新动作产生有效授权。因此，任何此类授权都包括来自未受损域的份额，该份额绑定到规范动作，并且仅在经过身份验证的审查者批准后释放。这建立了执行绑定的授权完整性。我们使用结构化输出LLM适配器和阈值BLS实现了完整的审查者到执行者路径。六个系统测试验证了该接口上的法定人数门控和消息绑定，而加密微基准测试测量了在线签名路径及其扩展行为。

## Abstract
Autonomous LLM agents can turn untrusted content into effectful actions such as payments and permission changes. If the same process interprets this content and controls a reusable signing credential, prompt injection can cross the judgment boundary and reach execution authority. We present KITA, a review-to-authorization architecture that keeps the user's personal secret signing key and every threshold signing-key share outside all LLM processes. Under threshold signature unforgeability and our system assumptions, compromising the proposer and fewer than t reviewer-signer domains cannot produce a valid authorization for a new action without signing contributions from t distinct domains. Thus, any such authorization includes a share from an uncompromised domain, bound to the canonical action and released only after authenticated reviewer approval. This establishes execution-bound authorization integrity. We implement the complete reviewer-to-executor path with a structured-output LLM adapter and threshold BLS. Six system tests validate quorum gating and message binding at this interface, while cryptographic microbenchmarks measure the online signing path and its scaling behavior.

# 从审查到授权：面向LLM代理的密钥隔离阈值签名（KITA）

## 1. 核心问题与整体含义（研究动机与背景）

- **核心安全问题**：自主LLM代理可将不受信任的内容（网页、邮件等）直接转化为有影响力的外部动作，例如支付或权限变更。如果同一个进程既负责解释上述内容又持有可重用的签名密钥/凭据，提示注入攻击就能跨越审查（语义判断）边界，直达执行的授权边界，造成未授权资金转移或权限更改。
- **现有方案的缺口**：当前的防护措施只覆盖了问题的一部分：
  - **多代理辩论/投票/模型小组**（Du et al., Verga et al., Choi et al.）仅改善了语义判断结果，但其输出仍属"建议"性质——除非有另外的安全组件强制执行。
  - **策略与委托约束系统**（AgentDojo、Progent、AP2等）以确定性代码处理机器可核查的硬限制，但模糊、开放场景仍需模型判断来评估意图或证据。
  - **门限签名与集体签名**（Borselius、Syta等的CoSi）从密码学上使消息在阈值门限下必须达到法定签名人数，但未定义"审查语义"和"执行边界"如何结合。
- **论文要填补的空白**：如何在保持所有签名材料**远离LLM进程**的前提下，把**基于模型的审查**绑定在一个确切可执行动作的**门限授权**之上，使执行者仅接受持有合法门限签名的"已被审查过"的动作。作者将这种组合称为**可执行绑定的授权完整性（execution-bound authorization integrity）**。

## 2. 提出的方法论：核心思想、技术与流程

### 核心设计思想——密钥隔离

- KITA 将用户个人私钥与每一个门限签名份额全部放在 LLM 进程之外。提议者（Proposer）可以接触不受信任内容、负责构建动作，但**不持有任何签名密钥份额**；多实例化的 LLM 审查者只做"语义评价"；隔离的签名服务持有密钥份额、只在收到配对审查者的认证化批准后对**同一个规范化动作**释放签名份额。
- 任何数目的审查通过"投票计数/软件逻辑"都不能代替密码学门限；执行者只能接受 t 个签名份额插值出的合法门限签名。

### 架构和参与方

- **Principal（委托人）**：设定策略 π，并授权委员会（t-of-n 审查–签名对）。
- **Proposer P**：处理不受信任内容，构建规范动作 m、证据清单 E 与策略 π，但**不持任何密钥份额**。
- **审查者–签名者域（Ri | Si）对**：Ri 审查规范对象；只有 Ri 发出认证化的"批准"后，隔离的 Si 才在确切字节上生成签名份额。
- **Combiner（组合器）**：可能是不可信的，逐一用公钥份额验证拉格朗日组合所需的各签名份额在 t 个不同索引上有效。
- **Verifier V / Executor（验证者/执行者）**：验证最终门限签名、策略/密钥 epoch、过期时间和 nonce 防重放，然后仅执行签名消息 m 中规定的动作。

### 正式协议流程（四个在线步骤）

1. **提议（Propose）**：P 把同一份（m，E，π）发送给所有审查者，确定一个公共决策目标；由于 P 无密钥份额，单单提出动作并不能使其落地执行。
2. **审查–认证–释放（review–authenticate–release）**：每个 Ri 返回拒绝、修订（附建议 c）或批准（m）。只有批准且认证化、回显目标摘要的信息才能触发配对的签名者 Si 释放 σ₀=SignShare(sk_i, m)。任何对金额、收款方、权限、证据摘要的改动都会造成新字节 m'，从而重启审查流程。
3. **验证与合并（validate & combine）**：合并且只使用来自至少 t 个不同有效索引的签名份额，拒绝畸形/重复/跨消息份额，进行拉格朗日插值得到门限 BLS 签名 σ。
4. **验证与执行相同字节（verify & execute same bytes）**：V 核验（m, σ）、策略/key epoch、过期时间、nonce 等，随后原子地消费 nonce 并只执行 m；防止"验证后替换"。

### 密码学基础与构造公式

- 采用 **阈值 BLS 签名**（基于 Boneh-Lynn-Shacham 短签名与 Shamir 秘密共享在指数上的门限构造，遵循 Boldyreva 方案）。
- 基表：
  - 公钥：`pk = g^x`；
  - 哈希到曲线：`h = H_DST(m)`（带域分离的哈希到 G1）；
  - 签名：`σ = h^x`；
  - 验签：`e(σ, g₂) = e(h, pk)`。
- 门限版本：DKG（或受控去中心化经销商）生成 deg(t-1) 多项式 f，签名者 Si 持有 xi=f(i)，发布认证化验证份额 pk_i=g^xᵢ₂。单个签名份额 σ_i = h^xᵢ。对集合 S（|S|=t）：
  - 拉格朗日插值系数: λ_i = Π_{j∈S,j≠i} −j/(i−j) (mod q)
  - 聚合签名: σ = Π_i σ_i^λ_i = h^x
- 在线阶段不需要签名者之间的通信，没有分布式 nonce 轮；同一签名者对于多个消息的份额不能跨消息组合。

### 安全保证（非正式表述）

- 在门槛签名的选择消息不可伪造性、可认证的批准通道、密钥份额的孤立安全存储、唯一规范编码、可信任的验证者等假设下：
  - 如果攻击者控制 Proposer 且破坏域少于 t 个审查–签名对，则无法让 V 接受一个新动作，除非获得来自 t 个不同签名索引的签名份额。
  - 由此，任何最终授权都必须包含至少一个来自**未破坏计算域**的份额，且该份额只能通过**已认证的审查者批准**释放到被批准动作规范字节——从而声明"消息绑定 + 法定人数门控"保证实体依赖键隔离与门限密码学的组合。

## 6. 主要结论与发现

- 避免双重角色，把“审查”与“持有密钥”相分离——即将提议与授权与审查绑定到同一规范化对象，甚至可以对不协调的不可信 DKG/公钥保持安全的阈值方案实现非常有效的防护。
- 针对注入提示和不可信数据流，一个干净抽象的能力边界：作者验证了提示或文本路径不能单独为该系统内的交易添加签名行为，密钥操作受批准门控，不能跨对象原子消费。
- 门限 t、不可预测因子的方差及相关性是指标选择对安全/可用性曲线的关键调节旋钮；t=4/n=7 在实际的合理评审质素下（均衡合理错误），而达成一致则存在更高的组织拒绝风险。
- 它们的微基准负载暗示纯 Python 的在线份额路径目前能支持对实际具有约束力场景进行的实时代理往返，配对最终验证为独立性主导瓶颈的时间固定数量级约为 0.56 s；纯 Python 加 48 字节签名用于多 t 验证范围。
- 最终文章突出了执行者未以可替换字节看待的环境，当过程条件吻合，最终保证：在单一诚实节点情况下必须包含一个诚实域份额，并绑定到已批准的确切规范动作，方能产生授权完整性。

## 7. 方法优点与设计亮点

- **密钥隔离的分区信任**极为干净：所有密钥份额与提示解释进程分开，减少了单层破坏攻击向量，形成一条很好的威胁模型（联合妥协 t--1）。
- **精确绑定与域分离**：将签名对象显示为结构化完整规范授权，包括证据哈希、策略版本、key epoch、expiry、nonce 和嵌套的“还原/修订/父摘要”链接，有助于规避批准迁移和 TOCTOU。
- **阈值 BLS 的在线复杂度**：每个签名在独立链路上无需内建通信轮次，聚合最终签名

聚合最终签名只需一次阈值 BLS 配对验证，且验证者无需与任何单一签名者交互，天然适配“不可信组合器 + 链下聚合 + 最终校验”的分层架构。

- **对抗性默认**：从第一条消息开始就假设审查者、组合器乃至部分签名域可能被攻破，所有接口都通过认证化、规范化编码与防重放机制来收敛风险，而非依赖“LLM 不会被越狱”的乐观假设。

## 8. 潜在局限与批判性分析

- **对审查者质量的隐性强依赖**：KITA 的密码学机制保证“必须有 t 个审查者批准”，但密码学无法保证“t 个审查者是否正确识别了恶意意图”。如果全部被攻破的域恰好达到 t 个，或者审查者本身在对抗样本上系统性误判，门限签名依然会被合法地铸造出来。论文用合成模型展示了这种退化趋势，却未给出真实对抗提示集上的失败率上限。
- **操作复杂度前置**：策略版本、密钥 epoch、过期时间、证据摘要和父动作链接都需要由 Proposer 与审查者共同正确构造与解析。任何一个环节的规范编码歧义都可能成为新的攻击面：不同审查者看到语义一致但字节不同的 m，便会产生“技术性不一致批准”，需要在协议层提供消歧机制（论文提到规范编码，但没有充分讨论语义等价但字节不同的消歧成本）。
- **实时模型的不可复现性**：使用 gpt-5.6-sol 的实时端到端测试展示了可运行性，但低层模型、解码参数、推理工作量等不可复现，即使公开代码也无法由第三方精确复现相同“审查通过/拒绝”结果。这使其更像系统可行性演示，而非可校准的安全评测。
- **缺少活性/延迟的完整建模**：论文证明的是安全性（恶意请求难以通过），但没有系统刻画合法性（活锁与拒绝风险）不受审查者崩溃、网络异步或签名域故障的影响。如果审查者之一长时间无响应，t-of-n 可以降级，但针对“签名份额已释放但组合器恶意丢弃”的活性场景仍依赖组合器诚实地至少提交足够份额。
- **阈值敏感性模拟的强假设**：合成审查者使用单因子高斯潜变量，允许通过相关系数 ρ 对相关性精调，但现实中审查者错误往往是与内容类别相关的（例如同一个误导性论据可能同时欺骗多个模型），ρ 可能本身也是内容相关的而非全局常量。因此 t=4/n=7 的最优性仅是特定参数群下的结论。

## 9. 与已有工作的比较定位

- **对比提示注入防御**：现有防御把精力集中在让模型“不采取危险动作”，本质上仍然假设模型能对每条输入做出正确语义判断；KITA 不试图提高模型判断力，而是降低“错误判断升级为不可逆操作”的概率。
- **对比策略引擎/沙箱**：确定性沙箱擅长执行机器可验证的硬规范（如“不得访问 /etc/passwd”“不得超过转账上限”），但在需要环境理解、用户意图推断或模糊证据评估时无能为力；KITA 的优势在于把开放语义审查留给 LLM，同时用门限密码学让这种开放判断必须经过多方独立共识才能触碰执行边界。
- **对比普通门限签名/多签钱包**：多签钱包往往只验证“多个私钥持有者同意”，而 KITA 强制每个私钥份额绑定在“已通过一次独立语义审查”的同一规范消息上，形成审查、签名、执行三者关于同一字节序列的可验证闭环。多签钱包中被恶意提案人欺骗所有签名者的情况，在 KITA 中仍要求审查者域同时犯错。
- **对比可验证执行/可信硬件**：TEE 可将“运行模型”和“签署动作”放入同一安全区域，但这类方案信任集中在芯片厂商与侧信道防御上；KITA 用分布式门限把信任分散到多个隔离计算域，不需要统一可信计算基。

## 10. 未来工作方向

- **在公开基准上的对抗评测**：将 KITA 的审查协议接入 InjecAgent、AgentDojo、Gaia 等基准，量化在真实网页/邮件混入恶意指令时的门限绕过率，给出更可信的 FA/FR 曲线。
- **审查者异质性建模**：将“不同审查者使用不同模型族/上下文/提示”的异质性纳入阈值模拟，研究如何通过审查者多样性最大化独立错误下的门限收益。
- **动态策略与可撤销授权**：为 KITA 增加 epoch 内动态策略更新路径，允许 Principal 在不重启系统的前提下撤销某一审查者域、替换签名份额或调整阈值 t。
- **异步活性优化**：设计基于乐观响应的最优聚合流程，使部分域崩溃时仍能自动切换可满足的签名子集，而回退路径仍保持安全不变量。
- **标准化审计接口**：将“执行者接受规范化动作对象”从原型扩展为一套可插拔审计日志，使每笔最终执行都能追溯到 t 个批准凭证、证据哈希与策略版本，便于事后追责与合规审计。

## 11. 总体评价

KITA 是一篇以密码学协议设计为骨架、以 LLM 安全语义为应用场景的系统论文。它没有宣称能彻底防御提示注入，而是把问题重新定义为“如何保证任何模型输出的动作意图都必须经过足够多的独立审查者以不可伪造的方式背书，才能进入执行域”。这一重新定义在工程上是清晰且可落地的：密钥隔离 + 阈值 BLS + 规范动作绑定给出了一个非常紧凑的实现，6 个端到端测试覆盖了最主要的攻击路径，密码学微基准也表明纯 Python 原型已经能支撑接近实时的事务往返需求。

论文最值得称道的贡献在于设计层的抽象——把“语义判断”与“授权权力”彻底解耦，并用绑定到字节序列的多方门限签名将两者缝合起来。它无法替代更好的模型判断或更细致的策略引擎，但为真实部署中的纵深防御增加了一个此前缺失的关键层：即便模型被成功诱导，攻击者仍然必须同时突破多个隔离审查域（并凑齐 t 个签名份额）才能让恶意动作被执行。对于从事 LLM Agent 安全研究、可信执行设计或密码学与 AI 交叉方向的读者，这是一个具有实际参考价值且验证思路清晰的工作。
