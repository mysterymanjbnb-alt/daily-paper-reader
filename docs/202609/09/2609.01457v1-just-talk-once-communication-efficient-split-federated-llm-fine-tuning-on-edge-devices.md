## 摘要
大语言模型（LLM）微调日益转向边缘设备上生成的数据，而内存、计算、带宽和连接性限制使得传统联邦学习难以维持。分离式联邦微调（SFT）通过将大部分模型参数和计算卸载到服务器来提高客户端效率，但需要在分离接口上进行逐步的双向通信循环，并迫使客户端在整个训练过程中持续参与。在本文中，我们提出了L形SFT，一种消除这种双向瓶颈的分离式微调框架。我们的关键见解是，现代LLM中的权重绑定使得服务器端的隐藏激活可以直接使用目标嵌入进行监督，从而无需将服务器输出返回客户端即可在服务器上计算训练损失。为了进一步消除持续客户端参与的需要，基于L形SFT，我们引入了一次性SFT，其中客户端上传一次激活然后离线，而服务器继续对缓存表示进行优化。我们在一个具有异构边缘客户端（包括商用智能手机和NVIDIA开发者板）的真实系统测试平台上实现了我们的设计。实验表明，与现有SFT基线相比，我们的方案显著降低了通信成本和客户端在线时间。

## Abstract
Large language model (LLM) fine-tuning is increasingly shifting toward data generated on edge devices, where memory, computation, bandwidth, and connectivity constraints make conventional federated learning difficult to sustain. Split federated fine-tuning (SFT) improves client-side efficiency by offloading most model parameters and computation to the server but requires step-by-step bidirectional communication loop across the split interface and forces continuous client involvement throughout training. In this paper, we present L-shaped SFT, a split fine-tuning framework that removes this bidirectional bottleneck. Our key insight is that weight tying in modern LLMs enables server-side hidden activations to be directly supervised using target embeddings, allowing the training loss to be computed on the server without returning server outputs to the client. To further eliminate the need for continuous client participation, based on L-shaped SFT, we introduce one-shot SFT, in which clients upload activations once and then go offline while the server continues optimization over cached representations. We implement our design in a real system testbed with heterogeneous edge clients, including commercial smartphones and NVIDIA developer boards. Experiments demonstrate that our schemes significantly reduce communication costs and client online time compared with existing SFT baselines.

## 2. 方法论

### 核心思想

- 利用现代 LLM 中常见的 **weight tying（权重绑定）** 性质（输出头权重为输入嵌入矩阵的转置），在服务器端直接用 **目标 token 的嵌入向量** 作为监督信号，对服务器端隐藏激活进行监督。
- 这样损失计算可以在服务器端“激活空间”完成，无需将服务器输出激活返回客户端，也无需客户端计算交叉熵损失，从而消除 U-shaped SFT 的“激活回传/梯度上传”双向循环。
- 进一步，由于训练过程不再需要客户端逐轮参与，可以扩展出 **one-shot SFT**：客户端在本地对数据只做一次前向传播，将（截断层激活，目标嵌入）对一次性上传后即可离线，服务器基于缓存的数据继续多轮优化。

### 关键技术细节

1. **L-shaped SFT 工作流**：
   - 模型划分为客户端子模型 \(f_c(x;\theta_c)\) 和服务器子模型 \(f_s(\cdot;\theta_s)\)。
   - 客户端计算截断层激活 \(h_c=f_c(x;\theta_c)\)，并本地计算目标嵌入 \(e_y=\mathrm{Embed}(y)\)，一起上传到服务器。
   - 服务器执行前向得到 \(h_s=f_s(h_c;\theta_s)\)，然后用激活空间损失（LA-Loss）进行监督和反向传播，更新服务器端参数。
   - 服务器将截断层梯度传回客户端，客户端用它更新本地浅层模型。
   - 注意：目标 token ID 不会离开设备，只暴露嵌入向量。

2. **激活空间目标函数（LA-Loss）**：
   - 采用对比学习形式（历史缓存 Q 作为负样本代理）：
     \[
     L_{\text{A-Loss}} = -\log \frac{\exp(s_y/\tau)}{\exp(s_y/\tau) + \sum_{e_k\in\mathcal{Q}}\exp(s_k/\tau)}
     \]
     其中 \(s_k=\mathrm{sim}(h_s,e_k)\)，\(\tau\) 为温度，\(\mathrm{sim}\) 常用点积或余弦相似度。
   - 目标是将服务器端隐藏状态拉向目标嵌入，同时推开缓存的负嵌入，等效于生成“服务器端可计算的 token 级监督”。

3. **One-shot SFT 工作流**：
   - 每个客户端对本地数据集做一次前向，得到缓冲 \((h_c,e_y)\) 对。
   - 一次性全部上传到服务器，缓冲清空，客户端即可离线。
   - 服务器将上传数据作为训练缓冲，反复迭代多轮，更新服务器端参数（例如若干 epoch）。

4. **理论分析**：
   - 定理：当温度 \(\tau=1\)、缓存 \(\mathcal{Q}\) 覆盖全词表、且满足权重绑定条件时，LA-Loss 关于隐藏状态的梯度与标准交叉熵损失的梯度完全一致，即 \(\nabla_{h_s}L_{\text{A-Loss}} = \nabla_{h_s}L_{\text{CE}}\)。
   - 当缓存为有限子集时，二者梯度误差可分解为两部分：**重归一化误差**（仅对缓存内 token 归一化）和**缺失负样本误差**（未包含词表中有概率质量的 token）。缓存若能覆盖主要竞争 token，近似误差会很小，因此该方法在实践中有充分理论支撑。

## 6. 主要结论与发现

- **L-shaped SFT 能保持接近 U-shaped SFT 的微调质量**，同时显著降低通信和端到端延迟：
  - 全量微调：MMLU 上通信减少 25%–66%，延迟减少 34%–70%；WikiText-2 上通信约减少 25%，延迟约减少 34%。
  - LoRA 微调：在多个 1B–8B 模型上，通信减少 24%–87%，延迟减少 26%–89%，其中 Llama3.2-1B/3B 达到 80% 以上的收益。
- **One-shot SFT 进一步压缩客户端参与**：在 Qwen2.5-0.5B 全量微调中，相比 U-shaped：
  - 总通信从 4.79GB 降至 0.98GB（MMLU），总延迟从 252.69min 降至 45.57min，客户端活跃时间从 240.66min 降至 4.83min（即从 95% 降至 11%）。
  - WikiText-2 上同样表现出类似量级节省。
- **two-shot? 不，是“one-shot 模式”特别适合不稳定/间歇连接环境**，客户端断线对训练影响很小（图8）。
- **权重绑定带来的嵌入自恢复率高**（GPT-2 和 Llama-3.2 Top-1 恢复率 >99.5%，Qwen2.5 >94%）是方法可行的经验基础，且理论上证明了在理想条件下与交叉熵梯度一致。

## 8. 不足与局限

- **隐私风险未被解决**：论文只保护了目标 token ID，但上传的激活和嵌入仍可能包含用户数据信息；作者也承认该问题属于 split learning 的共同挑战，本文未加处理。

- **适用模型假设**：方法依赖权重绑定属性。虽然 GPT/Llama/Qwen 等主流模型普遍满足，但对未使用权重绑定的模型（或词表极大、嵌入空间结构不满足语义一致性）效果可能打折。
- **训练目标为替代损失**：有限负样本缓存会带来近似误差，缓存设计、更新策略和温度选择等超参数需要仔细调优；论文未深入讨论缓存大小对通信和精度间的 tradeoff。
- **实验指标局限于下游精度和时延/通信**：没有评估内存/CPU/能耗等细粒度资源使用情况，也没有对模型质量在更多复杂任务上做验证。
