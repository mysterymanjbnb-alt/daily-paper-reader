## 摘要
真实世界中的高知名度AI代理程序框架通常依赖供应商专有或不透明的设计来组装上下文，导致组装上下文的来源和底层逻辑难以被理解，由此产生的安全风险也在很大程度上未被探索。在本文中，我们对真实世界AI代理程序框架中的上下文组装设计进行了首次系统性分析。我们研究并揭示了代理程序框架如何被设计为从不同来源收集和组装上下文，并识别出这些设计带来的一系列实际攻击向量。我们的分析揭示了真实世界框架上下文组装中两类新颖的攻击：(1) 消息角色上下文权限提升(M-CPE)，当源自低权限上下文的攻击者控制内容被纳入更高权限的消息角色时发生。(2) 跨范围上下文权限提升(X-CPE)，当攻击者控制的内容在其被引入的上下文之外持续存在时发生。我们对12个真实世界代理程序框架（包括Claude Code和Codex）的CPE攻击进行了系统性安全分析。由此产生的后果包括完全代理程序沦陷、远程代码执行、拒绝服务以及操纵工具或技能调用等。

## Abstract
Real-world, high-profile AI agent harnesses often rely on vendor-proprietary or opaque designs for context assembly, leaving the sources and underlying logic of assembled context poorly understood and the resulting security risks largely unexplored. In this paper, we present the first systematic analysis of context assembly designs in real-world AI agent harnesses. We study and uncover how an agent harness is designed to collect and assemble context from diverse sources, and identify a set of practical attack vectors arising from these designs. Our analysis brings to light two novel categories of attacks in the context assembly of real-world harnesses: (1) MessageRole Context Privilege Escalation (M-CPE), which occurs when attacker-controlled content originating from a low-privileged context is incorporated into a higher-privileged message role. (2) Cross-Scope Context Privilege Escalation (X-CPE), which occurs when attacker-controlled content persists beyond the context in which it was introduced. We performed a systemic security analysis of the CPE attacks against 12 real-world agent harnesses, including Claude Code and Codex. The resulting consequences include full agent compromise, remote code execution, denial of service, and manipulated tool or skill invocations, etc.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- 真实世界的高知名度 AI Agent（如 Codex、Claude Code、Gemini CLI 等）的“harness”（代理程序框架）通常采用供应商专有或不透明的设计来组装上下文，上下文的来源、加载逻辑和权限角色分配都缺乏透明度，导致安全风险未被充分研究。
- 已有研究主要关注间接提示注入（indirect prompt injection），聚焦于第三方工具或技能输出中的恶意指令；但对 agent harness 的“上下文组装”机制本身尚无系统性安全分析。
- 本文首次系统研究真实 agent harness 的上下文组装设计，揭示了两类新的上下文权限提升攻击：
  - **消息角色上下文权限提升（M-CPE）**：低权限上下文来源中的攻击者内容被组装到更高权限的消息角色中；
  - **跨作用域上下文权限提升（X-CPE）**：攻击者内容从临时作用域传播到更持久或影响更广的上下文来源。
- 这些攻击可导致 agent 完全被攻陷、远程代码执行（RCE）、拒绝服务、工具/技能调用被操纵等严重后果。

## 2. 论文提出的方法论

- 形式化建模：将 agent 的上下文视作多个消息子组件，每个消息带有一个权限角色 `ρ`；同时引入“上下文来源（context source）”概念，每个来源有内容 `s`、角色 `ρ`、作用域 `σ`。作用域分为 `σ_user`、`σ_project`、`σ_session`。
- 两类 CPE 的定义：
  - M-CPE：`ρ_j < ρ_k` 且 `s_j ≃ s_k`，即低权限来源内容进入高权限来源；
  - X-CPE：`σ_j < σ_k` 且 `s_j ≃ s_k`，即内容从低作用域（如 session）传播到高作用域（如 project/user）。
- 提出了 16 个攻击向量的分类体系，分为三大类：
  - **多样化上下文来源**（A-1 到 A-7）：特定 agent 的记忆文件、记忆搜索路径、运行时记忆加载、技能搜索路径、运行时技能发现、环境信息加载、递归记忆导入；
  - **上下文标记语法**（B-1/B-2）：伪造 XML 标记注入、利用模型输出标记解释；
  - **上下文组装逻辑**（C-1 到 C-7）：记忆文件加载优先级、技能加载优先级、技能重名消解、agent 配置自修改、上下文来源内联动作、上下文刷新、未沙箱化的内置工具。
- 研发了自动化分析工具 **CORA（Context Risk Analyzer）**，其流程包括：静态分析识别上下文来源（含角色/作用域）、通过插桩和 canary 随机填充做确定性运行时验证、再枚举候选 CPE 路径并执行两轮攻击验证（第一轮验证传播，第二轮验证注入指令产生行为效果）。

## 6. 论文的主要结论与发现

- 真实 agent harness 的上下文组装存在系统性设计级漏洞，且普遍影响所有被分析的 12 个高分 agent。
- 攻击者可通过不受信的外部内容或第三方组件，实现从低权限/临时上下文来源向高权限/持久上下文来源的权限提升。
- CPE 的攻击后果包括完全 agent 被控制、RCE、拒绝服务、操纵工具/技能调用、操纵代码审查/PR 合并等。
- 现有 LLM 的角色分级（system、developer、user、assistant、tool）不能阻止这类攻击，因为攻击利用的是 harness 层面的上下文组装逻辑而非单纯提示注入。
- 治理建议：agent 供应商应发布“上下文清单（context manifest）”，类似 SBOM，明确每个上下文来源、角色、作用域与加载逻辑，以提升透明度和可防御性。
- 已有部分厂商（如 Codex、Gemini CLI、Cline）发布新版以缓解部分威胁，作者正在进行负责任披露。

## 7. 优点

- **首次系统性研究 agent harness 上下文组装安全**：把上下文来源、消息角色、作用域、加载逻辑统一为形式化模型。
- 提出了两类的攻击类别（M-CPE/X-CPE），并给出直观数学化定义，便于后续研究复现和扩展。
- 建立了大规模攻击向量分类学（16 个向量），以结构化方式覆盖记忆、技能、环境信息、标记解析、优先级逻辑、配置自修改等面。
- CORA 工具区分“LLM 辅助候选识别”与“确定性 / canary 验证”，减少了幻觉和假阳性问题，且生成的结果具有可追踪证据。
- 实验覆盖范围很广：12 个流行 agent、多模型、端到端攻击演示，并辅以人工 ground truth 评估来证明工具效率。
- 展示了真实且隐蔽的攻击场景（如恶意 commit message、深层目录 GEMINI.md、SKILL.md 内 shell 执行），说服力较强。

## 8. 不足与局限

- 覆盖偏差：论文只覆盖当时选定的 12 个 agent 版本/模型，结果可能随版本升级而改变；部分 agent（如 Claude Code）只使用了特定渠道获得的源码，可能无法完全代表最新版。
- 对供应商不透明、专有实现的黑盒部分只能依赖源码静态分析或运行时观察，存在对“所有”真实人工设计的代表性不足问题。
- CORA 的自动化攻击验证只能验证一些较简单的注入指令，由于模型的对齐或指令遵循能力，真实恶意攻击者可能用更复杂的 payload 提升成功率；因此自动验证结果只是下界。
- 工具对复杂环境条件、运行时条件或高配置要求的来源可能无法构造验证环境，存在假阴性。
- 模型层面的随机性和上下文长度/位置可能影响结果，但论文未系统分析这些干扰；并且未报告详细的算力和时间开销，复现成本不透明。
- 缺少对防御机制的纵深讨论：尽管给出了“上下文清单”、减少上下文源等缓解建议，但没有评估这些防御是否会产生可用性或隐私上的副作用。
- 实验对比不足：没有与更多非 CPE 型注入攻击做对比，以验证 CPE 类别相对传统间接提示注入的增量危害。
