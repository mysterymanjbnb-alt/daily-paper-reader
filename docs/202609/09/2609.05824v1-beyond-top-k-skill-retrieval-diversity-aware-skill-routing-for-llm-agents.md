## 摘要
大型语言模型（LLM）智能体日益依赖外部技能，但在大型技能注册表上路由用户请求十分困难，因为许多技能在功能上冗余，而复杂任务往往需要互补的技能集。现有技能路由器通常独立地按查询相关性对候选进行排序，这可能浪费上下文预算在冗余技能上。我们提出多样性技能路由（DSR），一种基于行列式点过程的多样性感知重排序框架，用于平衡相关性与非冗余性。DSR 引入了一种查询残差多样性核，在惩罚冗余技能重叠的同时，减少仅由共享查询相关性引起的惩罚。在 SkillRouter 基准上，DSR 相比强点式重排序基线提升了召回率和完全覆盖率，在多技能查询上提升更大。这些结果表明，技能路由不仅应被视为相关性排序，还应被视为互补集选择。

## Abstract
Large language model (LLM) agents increasingly rely on external skills, but routing user requests over large skill registries is difficult because many skills are functionally redundant while complex tasks often require complementary skill sets. Existing skill routers typically rank candidates independently by query relevance, which can waste context budget on redundant skills. We propose Diverse Skill Routing (DSR), a diversity-aware reranking framework that uses a Determinantal Point Process to balance relevance and non-redundancy. DSR introduces a query-residual diversity kernel that penalizes redundant skill overlap while reducing penalties caused only by shared query relevance. On the SkillRouter benchmark, DSR improves recall and full coverage over a strong pointwise reranking baseline, with larger gains on multi-skill queries. These results suggest that skill routing should be treated not only as relevance ranking, but also as complementary set selection.

# 论文总结：Beyond Top-k Skill Retrieval: Diversity-Aware Skill Routing for LLM Agents

## 1. 核心问题与整体含义（研究动机与背景）

*   **研究背景**：LLM Agent 日益依赖外部技能库来执行超出纯文本生成的任务。随着技能库规模爆炸式增长（约为 8 万级），在推理时把所有技能暴露给 Agent 在上下文窗口方面不可行，也不可避免地存在功能冗余。
*   **核心问题**：现有技能路由方法大多把选择公式化为**点式（pointwise）相关性排序**，逐一独立评分并返回 Top-k，这种策略存在两个突出问题：
    1. 多技能（multi-skill）查询需要互补技能，点式排序容易返回一批相互重叠的相似技能（冗余），导致上下文预算浪费，同时遗漏必要但不相似的技能。
    2. 在大型冗余技能库中，技能路由不能只看作“独立排序”问题，而应看成“互补集选择”问题。
*   **整体含义**：论文主张技能路由需要同时考虑**查询相关性**与**集合多样/互补性**，将技能路由从相关性排序范式导向多样性感知的集合选择范式。

## 2. 论文提出的方法论

*   **方法名称**：Diverse Skill Routing（DSR），一种**多样性感知的重新排序框架**。

### 2.1 总体流程（Retrieve-Rerank-Select）

*   DSR 基于“检索-重排-选择”流水线：
    1. 通过编码器检索器（embedding retriever）从全量技能库中拉取 top-M 候选；
    2. 用点式重排器（reranker）给每个候选技能打相关性logit；
    3. 在候选集上应用**行列式点过程（DPP）** 进行贪心 MAP 集合选择；
    4. 最后按质量分数进行输出排序。

### 2.2 候选检索

*   用 L2 归一化的 query embedding 和 skill embedding 做余弦相似度 \(a_i(x) = e_x^\top e_i\)，取最高的 M 个作为候选集。DSR 只对候选集做重选，保证大规模下的可扩展性。编码器检索器主要负责高效初筛，而点式质量模型则对候选集精细打分。

### 2.3 质量感知的 DPP 选择（核心机制）

*   对 reranker 输出的 logit \(h_i(x)\) 应用 sigmoid 变为非负质量分数：\(q_i(x) = \sigma(h_i(x))\)。
*   构造 DPP 核矩阵（kernel）：
  \[
  L(x)_{ij} = q_i(x) \cdot \phi_x(s_i, s_j) \cdot q_j(x)
  \]
  其中 \(\phi_x(s_i, s_j)\) 是**查询条件化的技能间相似度**。
*   对子集 A 的得分即 det\((L_A)\)，DPP 会自动偏好“单个质量高”且“两两之间多样非冗余”的子集。

### 2.4 查询残差多样性核（Query-Residual Diversity Kernel）——关键技术细节

*   论文指出，**直接用标准技能余弦相似度做多样性核有风险**：两个技能相似可能因为功能真实冗余，但也可能因为都同属同一个查询的相关技能，此时不应该惩罚。
*   DSR 的解决方案是：
  1. 将每个技能 embedding 中与 query embedding 对齐的成分移除（投影到查询正交子空间）：
     \[
     r_i = e_i - (e_i^\top e_x) e_x
     \]
  2. 将残差与原始 embedding 线性混合（λ 控制残差强度）并归一化：
     \[
     \tilde{z}_i = \lambda r_i + (1-\lambda) e_i, \quad z_i = \tilde{z}_i / \|\tilde{z}_i\|_2
     \]
  3. 用映射到 [0,1] 的相似度作为核：
     \[
     \phi_x(s_i, s_j) = \frac{1 + z_i^\top z_j}{2}
     \]
*   这样，多样性惩罚聚焦于**“排除共享查询相关性后仍然存在的重叠”**，不误伤同一个多步任务中本来就关联互补的技能（如：“解析表格”和“生成可视化”可以在查询空间中接近，但功能上互补）。

### 2.5 贪心 MAP 选择与排序（算法流程）

*   精确 DPP MAP 推理是 NP-hard 的，因此 DSR 使用由空集出发的贪心增量式选择，每次加入边际增益最大的技能。使用增量 Cholesky 更新，避免重复计算行列式。
*   第一步选出的技能即质量分数最高的技能（与点式排序第一一致），后续步骤则兼顾排序靠前和质量分数靠前但冗余更小、互补更强的技能。
*   选满 k 个技能后，按质量分数降序排序，输出最终技能短列表。
*   最终 DSR 只改变“选择方式”而不改变底层检索器与相关性模型，从而便于可控隔离对比。

## 3. 实验设计

### 3.1 Benchmark 与数据集

*   **SkillRouter benchmark**：
  *   基于附有约 80K 技能的 Claude 技能注册表（Claude Skill Registry）；
  *   共 75 个专家验证查询，覆盖 55 个领域、8 个超类；
  *   单技能查询（24 个，要求 1 个目标技能）和多技能查询（51 个，要求 2~5 个目标技能）。
*   分为两个鲁棒性层级：
  *   **EASY**：78,361 个候选技能；
  *   **HARD**：79,141 个候选技能，额外混入 780 条 LLM 生成的干扰（distractor）技能。

### 3.2 对比方法与基线

*   **主基线（Full pipeline）**：SkillRouter（SR-Emb-0.6B 编码器检索 + SR-Rank-0.6B 点式重排器）。该基线用同样的底层模型，但输出独立排序。
*   **DSR 变体**：使用与基线相同的 SR-Emb-0.6B 检索器和 SR-Rank-0.6B 重排器，只在最后加一步 DPP 多样性感知选择。
*   **消融变体**：
  *   Kernel：标准 cosine kernel vs. query-residual kernel；
  *   Quality：重排器质量分数（reranker quality）vs. embedding 相似度质量分数（embedding quality）。
*   **分析对比**（不同排序/选择策略）：Embedding Top-k 检索、zero-shot LLM 重排（Qwen3-8B）、SkillRouter reranker、DSR。

### 3.3 主要实验设置

*   检索候选数 M=50；
*   残差混合系数 λ=0.85；
*   贪心 MAP 用增量 Cholesky 更新。

## 6. 主要结论与发现

*   **DSR 普遍提升覆盖类指标**：
  *   All queries：Recall@20 从 0.754 → 0.768；Full Coverage@20 从 0.560 → 0.573；@50 提升更明显（Recall 0.754 → 0.808；FC 0.560 → 0.633）。
  *   Multi-skill：Recall@20 从 0.704 → 0.739；Full Coverage@20 从 0.458 → 0.492；@50 的 FC 从 0.458 → 0.551。
*   **多技能查询增益明显更大**：单技能查询上 Top-k、SkillRouter、DSR 结果完全持平；多技能任务上 DSR 提升相对最大。表明多样性选择的核心价值在组合任务中充分释放。
*   **query-residual kernel 是关键**：在同样使用 reranker quality 时，将 residual kernel 替换成标准 cosine kernel 会让 multi-skill FC@10 从 0.441 骤降到 0.254，证明“无差别惩罚所有相似性”会误伤同查询相关的互补技能。
*   **质量信号同样重要**：使用 reranker quality 优于 embedding quality，说明 DPP 的候选质量基准确度影响很大。
*   **几乎不损失早期精度**：附录 MRR 显示 DSR 与 SkillRouter MRR 差异极小（全部查询 MRR@10 0.784 vs 0.788），说明覆盖提升并非牺牲相关性排序质量换来的。

*   **方法设计心思细密**：
  *   提出“查询残差多样性核”，区分“功能冗余造成的相似”与“同查询共享相关性造成的相似”，是很有洞察的技术方案；
  *   利用 DPP 很好的理论支撑，将贪心 MAP 的增量 Cholesky 技术落地到大候选集场景，工程可行性好；

## 8. 不足与局限

*   **基准评估规模偏小**：只有 75 条专家查询。虽然技能池规模很大，但查询数量有限，子任务类型覆盖仍受限，多样性路由的普适性需在更多 benchmark 上验证。
*   **对上游检索器有强依赖**：DSR 只在 top-M 候选内做选择，若原检索器缺失某个必要技能则无法补齐。文中也承认，最优做法应把检索与集合选择联合优化。

*   **缺少延迟/参数量/算力的详细报告**：如第 4 点所述，没有报告显存的 GPU 数量和训练时长、没有给出实际推理时间、没有对候选集大小进行充分可扩展性讨论。
