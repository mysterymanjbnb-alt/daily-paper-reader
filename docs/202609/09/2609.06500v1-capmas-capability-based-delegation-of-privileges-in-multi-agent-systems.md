## 摘要
智能体系统需要在多个协作智能体之间进行安全高效的权限委托。现有方法分为两类：一些方法直接将用户身份传播给智能体，模糊了问责制，并造成持续的超权限风险，而AI智能体的非确定性行为会放大这些风险；另一些方法则依赖与中央身份与访问管理（IAM）提供商的持续同步，从而引入额外的延迟和通信开销。我们提出了CAPMAS，一种用于多智能体系统中安全端到端查询执行的新型架构。CAPMAS新颖地结合了基于对比学习的语义范围界定流水线（在执行前将自然语言查询映射到有界权限集）与基于Macaroon的表达性令牌，后者支持跨智能体的离线、防篡改委托，并具有单调权限缩减特性。通过将身份验证和委托执行与智能体推理解耦，CAPMAS在实施严格的最小权限保证的同时，实现了实用的智能体执行。通过消除与IAM的同步委托交换，与OAuth 2.0令牌交换（RFC 8693）相比，CAPMAS的委托操作速度快30倍，委托相关延迟降低2倍，带宽使用量降低最多3倍。其语义范围界定流水线在包含超过3,100个端点的企业级API模式上，能在17毫秒内实现超过90%的完美权限捆绑检索，同时与将所有用户权限传播给智能体的系统相比，不必要的权限减少了99.5%。

## Abstract
Agentic systems require secure and efficient delegation of privileges across multiple collaborating agents. Existing approaches fall into two categories. Some propagate user identities directly to agents, obscuring accountability and creating persistent over-privilege risks that are amplified by the non-deterministic behaviour of AI agents. Others rely on continuous synchronization with a central Identity and Access Management (IAM) provider, introducing additional latency and communication overhead.   We present CAPMAS, a novel architecture for secure end-to-end query execution in multi-agent systems. CAPMAS newly combines a contrastive learning-based semantic scoping pipeline that maps natural-language queries to bounded privilege sets before execution with expressive Macaroon-based tokens that enable offline, tamper-evident delegation with monotonic privilege reduction across agents. By decoupling authentication and delegation enforcement from agent reasoning, CAPMAS enables practical agentic execution while enforcing strict least-privilege guarantees.   By eliminating synchronous delegation exchanges with the IAM, CAPMAS yields 30 times faster delegation operations, 2 times less delegation-oriented latency and up to 3 times lower bandwidth usage than the OAuth 2.0 Token Exchange (RFC 8693). Its semantic scoping pipeline achieves over 90% perfect privilege-bundle retrieval within 17 milliseconds on enterprise-scale API schemas containing over 3,100 endpoints, while reducing unnecessary privileges by 99.5% when compared to systems that propagate all the user's privileges to agents.

## 1. 核心问题与整体含义

- **研究动机**：多智能体系统（Multi-Agent Systems）日益成为复杂 AI 应用的标准架构，多个智能体需要代表用户跨服务执行任务。然而，如何安全地在智能体之间委托权限是一个核心挑战。
- **现有方案的两类缺陷**：
  - **基于身份令牌（如 JWT）**：直接将用户完整权限传播给所有智能体，导致过度授权；且 LLM 的幻觉或缺陷可能引发权限滥用和特权提升。
  - **集中式在线令牌交换（如 OAuth 2.0 Token Exchange / RFC 8693）**：每次委托都需要与中央 IAM 同步通信来铸造新令牌，引入大量延迟和带宽开销，成为规模化瓶颈。
- **核心需求**：既要将自然语言（NL）查询转化为严格有界的最小权限集，又要支持多跳委托下的离线令牌衰减，避免一次性或重复的中心化交互。
- **CAPMAS 的整体思路**：提出一种全新架构——将“语义权限范围界定”（利用对比学习编码器将 NL 查询映射到顶端 k 个相关权限）与“基于能力的令牌”（Macaroon，支持本地离线单调衰减）相结合，在执行前确定权限上界，并在委托链中逐步缩减权限。这样既保证最小权限，又消除中心化同步瓶颈。

## 2. 方法论：核心思想、关键技术细节与流程

### 2.1 总体架构
- 系统组件：用户、智能体（运行 ReAct 循环）、服务（REST API）、IAM（集中信任权威）。
- IAM 负责用户认证、语义权限解析、根令牌铸造、最终验证（加密 + 语义检查）。
- 服务在执行动作前，调用 verifyAndEvaluate 将令牌交给 IAM 验证。

### 2.2 令牌机制：Macaroon 的实例化
- 采用 **Macaroon** 作为核心授权令牌，替代 JWT。
- Macaroon 特性：
  - HMAC 链式签名：sig₀ = HMAC(root_secret, rid)，sig₁ = HMAC(sig₀, caveat₁)，以此类推。
  - 支持离线追加 caveat，任何中间方无需联系 IAM 即可本地衰减令牌。
  - 防篡改：修改或删除既有 caveat 会使签名链失效。
- 自定义两类 caveat：
  - **确定性验证 caveat**：包括 rid、iss、exp、aud、agent_id、permit。
    - permit 采用默认拒绝的“白名单”语义，权限交集随每次追加递减。
  - **推理与可追溯性 caveat**：query——嵌入初始用户意图和中间智能体的指令文本，供最终语义一致性检查。

### 2.3 语义权限范围界定（Semantic Scoping）
- 核心思想：将“从自然语言查询确定所需权限”重新定义为**语义检索问题**。
- IAM 预先将系统内所有权限（API 端点及其描述）用对比学习编码器映射到共享向量空间。
- 运行时对用户查询嵌入并检索 top-k 最相似权限，作为根令牌的 permit caveat，形成严格上界。
- 采用“共享（Siamese）编码器”而非双塔结构，减少参数并利用查询与 API 描述相近的语言分布。
- 训练目标：InfoNCE 对比损失。
- 引入 elbow-drop 阈值 α（0.2），允许按相似度骤降提前终止检索，进一步降低实际授权数量。

### 2.4 请求全流程
1. 用户凭据 + NL 查询 → IAM 认证 → 语义 scoping → 铸造带 rid 和根 caveat 的 Macaroon。
2. 智能体收到令牌，对每个子任务克隆令牌、追加限制（permit、aud、agent_id、query），再传给下游智能体。
3. 目标服务调用前，IAM 执行三步验证：
   - 重算 HMAC 链检查完整性；
   - 验证所有确定性 caveat（过期、aud/agent_id 一致性、permit 交集是否覆盖请求动作）；
   - 用 LLM 对 query caveat 与最终服务动作做语义异常检测（应对 prompt injection 和逻辑漂移）。
4. 验证通过后服务执行并返回结果。

## 6. 主要结论与发现

- **CAPMAS 可提供严格最小权限保障，同时大幅降低授权开销**：
  - 微观操作上：令牌创建 0.01ms，增加 caveat 0.01–0.18ms（随 caveat 数增长），验证仅需 0.01–0.30ms；
  - 相比 RFC 8693，委托操作快约 30 倍；端到端委托相关延迟降低约 2 倍；带宽用量最大减少 3 倍（图 3）；
  - Signed Nested 令牌因递归编码在 100 个 caveat 时超过 500MB，验证也因深度而劣化；
  - Macaroon 令牌尺寸比 JWT 更紧凑，随 caveat 数量线性增长。
- **语义 scoping 高效且精准**：
  - 在 ASTRA 和 XLAM 上，Perfect Bundle Capture 约 91% 和 92.3%，延迟 <20ms；
  - 相对于“传播全部用户权限”的旧方法，不必要权限减少 99.5%（Absolute Over-privilege 约为 0.12%–0.47%）；
  - 相比 Basic Agent（ASTRA 上 capture rate 仅 37.4%，complete miss 53.0%），CAPMAS 提升可靠性约 53%，而初始过度授权仅增加 0.37% 绝对值；
  - 在 Strict Zero-Shot 条件下仍有 83.5%（k=10）甚至 95.6%（k=20）的捕获率，证明对新权限的泛化能力。
- **端到端实现中安全性开销可忽略**：授权路径用时约占整个请求的 800ms 之外；LLM 推理平均 10s 才是主要瓶颈。

## 7. 优点

- **方法设计上的亮点**：
  - 将“最小权限推断”从“生成式推理”变为“对比检索”，避免了 LLM 的延迟、幻觉和上下文窗口限制，使权限指派具有显式上界。
  - 利用 Macaroon 的 HMAC 链式签名实现彻底的离线衰减、严格权限交集、防篡改和可追溯性。
  - 创造性结合“语义查询嵌入”与“密码学令牌”，使 token 可携带用户原始意图，以支持最终语义异常检测。
  - 采用默认拒绝（allow-list based）的 permit caveat，使故障方向为“拒绝”而非“越权”，安全性更稳健。
- **实验覆盖较全面**：涵盖端到端功能演示、密码学微观基准、网络扩展性模拟、语义 scoping 训练与评估，并公开代码和数据集，可复现性强。
- **工程集成性好**：提供 MCP 代理机制，使 Macaroon 无需修改即可与不支持 Macaroon 的 legacy 服务兼容。

## 8. 不足与局限

- **信任模型限制**：仅在 honest-but-curious 设置下有效；若中间智能体恶意篡改明文 caveat 视图或在链上伪造身份，仍需依赖 side-car 或非对称签名扩展，论文仅做了定性讨论，没有在恶意环境中进行定量实验。
- **信息泄露风险**：query caveat 以明文传播，包含用户的原始查询和中间推理，若下游看到不相关内容可能造成隐私泄漏；且无法控制智能体的内部记忆污染，目前只能靠代理通知，无强制执行。
- **k 带来的安全–效用矛盾**：top-k 上界虽严格，但过高会导致过度授权，过低使复杂任务无法完成；选择合适 k 依赖部署环境，论文靠 elbow-drop 来缓解，但仍缺少自动化、自适应的调节机制。
- **IAM 单点故障/单点信任**：即使 IAM 可水平扩展，也无法完全避开信任集中，这限制了在开放式、去中心化环境中的部署。
- **实验规模与真实性有限**：语义数据集为合成（ASTRA/XLAM），真实企业用户查询分布未知；没有大规模多用户并发、真实生产流量和多服务权限数量级（>10⁴以上）的测试；对 k>10 的 XLAM 结果未展开实验或讨论资源消耗。
- **LLM 语义检查的可靠性未被量化**：IAM 用 LLM 做语义异常检测，但论文未评估该检测器的误报/漏报率，可能成为实际部署中的薄弱环节。
- **算力信息不完整**：仅披露单卡训练耗时，未披露 LLM 推理评估成本（如 Basic Agent 的累计 token 消耗），这使得“CAPMAS 更廉价”的结论有一定支撑但不算完全一致地对齐。
