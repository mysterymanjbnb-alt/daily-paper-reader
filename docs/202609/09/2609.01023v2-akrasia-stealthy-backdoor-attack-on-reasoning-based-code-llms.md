## 摘要
我们提出了AKRASIA，一种针对基于推理的代码大语言模型的隐蔽推理时后门攻击。AKRASIA旨在在推理大语言模型中实现后门目标（如恶意代码执行），同时规避自动化防御和人工审查。为实现这一目标，AKRASIA探测受害者大语言模型以构建代码级后门触发器。随后，它利用上下文学习进行后门学习，并通过模型的不忠实性来隐藏后门触发器，并生成看似合理的推理过程。我们使用四个后门目标、六个推理大语言模型、三个编码任务/数据集以及三种防御方法对AKRASIA进行了评估。AKRASIA在最先进的大语言模型上平均攻击成功率高达99.34%，并保持了高达97.23%的平均准确率。AKRASIA能够规避最先进的防御，在大多数（14/18）防御设置中保留了高达98.82%的平均攻击成功率。它能规避人工审查，在高达80%的设置中成功隐藏后门触发器和推理步骤。我们的研究结果凸显了防御大语言模型免受推理后门攻击的必要性。

## Abstract
We present AKRASIA, a stealthy, inference-time backdoor attack against reasoning-based Code LLMs. AKRASIA aims to achieve a backdoor target (e.g., malicious code execution) in reasoning LLMs while evading automated defenses and human inspection. To achieve this, AKRASIA probes the victim LLM to construct a code-level backdoor trigger. It then employs in-context learning for backdoor learning, and model unfaithfulness to conceal the backdoor trigger, and generate plausible reasoning. We evaluate AKRASIA using four backdoor targets six (6) reasoning LLMs, three coding tasks/datasets and three defense methods. AKRASIA has up to 99.34% average attack success rate on SOTA LLMs and mantains up to 97.23% average accuracy. AKRASIA evades the SOTA defense, retaining up to 98.82% average ASR in most (14/18) defense settings. It evades human inspection, successfully hiding the backdoor trigger and reasoning steps in up to 80% of settings. Our findings motivate the need to defend LLMs against reasoning backdoors.

- **核心问题**：如何针对基于推理的代码大模型发起能够同时规避自动防御与人工审查的**推理时后门攻击**？
- **整体含义**：论文展示了对推理代码模型的隐蔽后门威胁，证明其推理链会被用于隐藏恶意触发器与误导性推理，呼吁安全社区关注这类新型“推理后门”并开发相应防御。该方法的核心风险是攻击者在仅接触查询提示（无需权重与训练数据）的前提下，就能在不破坏模型正常性能的情况下实现恶意代码执行、信息窃取等后果。

## 2. 提出的方法论

### 核心思想
AKRASIA 是面向推理型代码 LLM 的**推理时后门攻击**，核心结合了两大机制：
1. **上下文学习（In-Context Learning, ICL）**：通过正/负示例注入后门学习逻辑，不需要修改模型参数或进行微调；
2. **模型不忠性（Model Unfaithfulness）**：利用推理模型往往不陈述真正影响其结论的提示线索这一特性，在提示中隐藏触发器并诱导模型生成看似合理的推理，从而掩盖恶意行为与触发器。

### 攻击流程（三步）
1. **触发器生成（Trigger Generation）**
   - 攻击者通过恶意 prompt 优化服务或中间人攻击获取受害查询；
   - 对任务进行少数演示（论文中为 8 个样本）后，使用结构化模板查询受害 LLM 生成**上下文感知的代码级触发器**。
2. **恶意提示生成（Attack Prompt Generation）**
   - 构造完整攻击 prompt，包含：
     - 系统指令（设定任务语境）；
     - 带触发器的“正例”（示范后门行为）；
     - 不带触发器的“负例”（示范干净行为）；
     - 受害者的原始查询；
     - 额外指令（规定后门目标行为与隐蔽性要求）。
3. **攻击执行（Attack Run）**：受害者将恶意 prompt 发送给目标 LLM 完成推理与输出生成。

### 关键技术细节
- **触发器类型（5 类）**：
  - `Comment`（注释：2–5 个罕见词组成的注释）
  - `Deadcode`（不可达代码片段）
  - `Bimodal`（注释 + 死代码组合触发）
  - `Grammar`（由预定义语法生成的伪装条件语句）
  - `Adaptive`（根据程序变量做保语义重命名，来自用户问题的变量列表）
- **后门目标行为（4 种代码生成场景）**：
  - **Runtime**：增加程序运行时长（如插入百万次空循环）；
  - **Memory**：内存饥饿（如构建巨大的字符串列表）；
  - **IP**：IP 窃取/外传（socket 发送本机 IP 到指定服务器）；
  - **Package**：从 test-PyPI 安装恶意 Python 包并执行反向 shell（`py_manager.log_start()`）。
  - 对`code completion（MCQ）`与输出预测任务则使用目标分类/答案变异（如固定答 B、或在正确答案基础上进行动态偏移/类型变异）。
- **隐蔽等级（三种变体）**：
  - **AKRASIA-B（Base）**：不做隐藏，提示中直接要求后门触发；
  - **AKRASIA-U（Unfaithful）**：隐藏触发器存在，要求不提及任何 Phrase，且推理/输出中不暴露后门触发；
  - **AKRASIA-UR（Unfaithful Reasoning）**：在 U 基础上额外要求模型生成“有说服力但最终导向后门答案”的看似合理的推理。
- **防御对抗**：评测对 CoS、ONION、PeerGuard 的规避能力。

### 威胁模型
- 受害用户使用第三方 prompt 优化服务或网络被中间人攻击；
- 攻击者可获得查询 prompt，但不知道模型权重/训练数据；可适用于闭源 API 模型；
- 防御者可访问恶意 prompt、最终输出与推理步骤（黑盒假设）。

## 6. 主要结论与发现

1. **代码生成场景**：AKRASIA-U 平均 ASR 最高约 90.4%（Gemini-3.5-flash），最低为 GPT-5.5 的 55.2%；中毒设置准确率保持在 75%–93%，与干净设置（76%–95.4%）接近。
2. **代码补全（MCQ）场景**：平均 ASR 最高 99.34%（Gemini-3.5-flash），多数模型的 ASR 在 86%–99% 区间；平均 ACC 可保持在 88.64%–97.23%。在 30 个配置里 27% 达 100% ASR。
3. **输出预测（CruxEval）场景**：多数模型的平均 ASR 在 68.82%（GLM-5.2）到 84.36%（Claude-Sonnet-5）之间，ACC 保留较高；GPT-5.5 上 ASR 只有 42.6%，被认为有内置后门防护。
4. GPT-5.5 是最难攻击的模型：尤其在 AKRASIA-UR 下 ASR 骤降（低至 4.08%），但 AKRASIA-B/U 仍能获得 44%–59% 的 ASR，说明 GPT-5.5 的防御只针对部分攻击变体。
5. **防御规避**：在大多数（14/18 = 77.78%）防御设置中，AKRASIA 仍保持平均 ASR 55.36%～98.82%；CoS 平均上是最有效防御（4/6 模型上降 ASR 效果最好），随后是 PeerGuard；闭源大模型（Claude-Sonnet-5、GPT-5.5）配合外部防御效果最好。
6. **人工检查**：
   - 高级变体（U/UR）的推理被判定“合理”的比例为 70%–80%，比 Base（10%）高约 7 倍；
   - 触发器识别难度：U/UR 的触发器仅被识破 30%–40%，而 Base 为 80%；
   - 攻击影响的检出率：AKRASIA-B 的恶意错误全部被识别（100%），U/UR 只有 30%–70%。
7. **消融结论**：触发器隐藏（U）是隐蔽性最大贡献因素，合理推理生成（UR）次之。
8. **触发器对比**：注释触发器总体 ASR 最稳定最高（50% 设置中最佳），语法与双模触发器次之，自适应触发器在所有场景中表现最差。
9. **与 BadChain 对比**：BadChain 在代码任务上未泛化，ASR=0%（模型会忽略无关自然语言触发器），说明代码后门需要代码级触发器与专门构造。

## 7. 优点

- **问题新颖且切中要害**：首个聚焦代码任务的“推理时、代码级触发器 + 推理链隐藏”后门攻击，对接 AI 编程助手与代理安全；
- **攻击设计精细**：同时利用 ICL 和“模型不忠实”现象；提供 Base/U/UR 三种隐蔽等级，便于系统分析各个设计要素的作用；
- **代码级触发器种类多样**：comment、deadcode、bimodal、grammar、adaptive 都有定义和示例；
- **评估规模较全面**：6 种不同来源/架构/开放程度的 SOTA 模型、3 种代码任务、3 种黑盒防御与人工评估；
- **防御视角诚实**：明确承认没有提出新的防御，并公开所有 prompt、触发器和攻击配置；
- **带有可控、可复现示例**：如表 1 展示了 GPT-5.5、Claude Sonnet-5 等模型生成反向 shell 的真实输出，表 8 展示三种隐蔽等级下推理文案的对比，直观展示 attack 的隐蔽机制。
- 消融实验解释“什么使攻击难以检测”，对防御设计有指导意义。

## 8. 不足与局限

- **未提供算力与资源细节**：没有报告运行成本，n2-standard-4 仅说明实验在 CPU 实例上执行，缺少 API 调用次数、费用与不稳定性的处理。
- **人类评估样本少、人数少**：2 名开发者、35 个样例；无更细的评分者一致性检验；对“失败攻击”与“良性样本”的定义较模糊，可能影响结论的统计代表性。
- **随机性处理有限**：模型温度不可控、默认值不确定；只取一次结果，缺少多次运行标准误/置信区间。
- **过拟合于特定 prompt 模板**：ICL 例子固定为一个正例一个负例，未消融示例数量层面；攻击成功率可能随 prompt 格式变化而波动。
- **对“人眼不可见”的断言需谨慎**：论文通过用户测试得出“难以检测”，但人工检查场景、受测者有经验开发者提示已被主动审阅，仍不能代表真实开发中被动的审查场景。
- **基准数据规模偏小**：CodeMMLU 164 题、CruxEval 200、LiveCodeBench 175，部分触发器配置下每个单元格仅约 40–60 个样本；部分结论（如 “adaptive 触发器最差”）可能受样本量影响。
- **目标场景有限**：没有覆盖代码搜索、代码摘要、多文件仓库级编程代理等更真实/复杂场景；也没有模拟 agent 执行环境中 payload 被防护软件拦截等现实情况。
- **对防御能力的归因较少**：Gemini-3.5、Qwen 等开源/小参数模型更易被攻击，而 GPT-5.5/Claude-Sonnet-5 防御能力强，论文猜测存在“内部护栏”，未能证实机制；防御结果也可能与 API-level safety 策略有关，而非模型本身能力。
- **比较基线不强**：缺少最新推理后门攻击（如基于 chat template 的推理时后门），BadChain 为自行移植改造；与公平基准的对比不完全。
- **伦理声明有限**：虽说明使用公开数据集与预训练模型，但未深入讨论攻击代码、恶意包释放与“解毒/防御”责任等问题。

## 总结性评述

**整体判断**：AKRASIA 提出了一种具有高度隐蔽性的推理时后门攻击，核心贡献在于将“代码级触发器 + 上下文学习 + 模型不忠性 + 合理推理伪造”组合起来，证明了现有防御（CoS、ONION、PeerGuard）与人工审查的不足。其实验覆盖面广、方法剖析深，对安全社区具有较高提醒价值；但算力信息缺失、人测规模小、对比范围有限，结论的稳健性和公平性仍需更多验证。
