## 摘要
联邦学习允许银行、医院及其他受监管组织在不将原始记录移出自身服务器的情况下训练共享模型，这在数据保护法或竞争敏感性排除集中式数据池的场景中极具吸引力。然而，有两个问题限制了这一承诺在实践中能被信任的程度。首先，客户端交换的参数更新仍会通过梯度反演和成员推断攻击泄露关于本地记录的信息。其次，诸如FedAvg之类的诚实平均规则无法防御提交损坏或对抗性更新的客户端子集，因此少数恶意或受感染的参与者可以悄然使共享模型偏离正轨。本文提出了一种联邦学习框架DP-BR-FedAvg，它将高斯机制的差分隐私层与坐标式修剪均值拜占庭鲁棒聚合规则相结合，并在一个模拟的跨机构分类任务上进行了评估，该任务类似于欺诈和临床风险评分。在六十轮通信中，二十个客户端中有四分之一为拜占庭客户端，普通FedAvg在少数类上崩溃（F1分数为0.030），而所提框架显著恢复了更多信号（F1分数为0.119），同时限制了任何单个客户端贡献的隐私损失。没有隐私层的拜占庭鲁棒聚合器在原始准确率上表现最佳，这量化了隐私对鲁棒性施加的代价。结果表明，隐私与鲁棒性机制是交互作用而非简单叠加，因此在受监管、对抗性、跨机构场景下的系统设计需要为该交互作用预留预算。

## Abstract
Federated learning allows banks, hospitals, and other regulated organizations to train a shared model without moving raw records off their own servers, which is attractive wherever data protection law or competitive sensitivity rules out pooling data centrally. Two problems limit how far this promise can be trusted in practice. First, the parameter updates that clients exchange still leak information about local records through gradient inversion and membership inference attacks. Second, an honest averaging rule such as FedAvg has no defense against a subset of clients that submit corrupted or adversarial updates, so a small number of malicious or compromised participants can quietly steer the shared model off course. This paper presents a federated learning framework, DP-BR-FedAvg, that combines a Gaussian-mechanism differential privacy layer with a coordinate-wise trimmed-mean Byzantine-robust aggregation rule, evaluated on a simulated cross-institutional classification task resembling fraud and clinical-risk scoring. Across sixty communication rounds with twenty clients, a quarter of them Byzantine, plain FedAvg collapses on the minority class (F1-score 0.030) while the proposed framework recovers substantially more of the signal (F1-score 0.119) while bounding the privacy loss of any single client's contribution. A Byzantine-robust aggregator with no privacy layer performs best in raw accuracy, quantifying the cost privacy imposes on robustness. The results show that privacy and robustness mechanisms interact rather than simply add, and that system design for regulated, adversarial, cross-institutional settings needs to budget for that interaction.

## 1. 论文的核心问题与整体含义（研究动机与背景）

联邦学习使银行、医院等受监管机构可以在原始数据不出本地服务器的前提下协作训练共享模型，规避了数据保护法规（如 GLBA、HIPAA）和竞争敏感性对集中式数据池的阻碍。但在实际部署中，这一范式面临两大核心威胁：

1. **隐私泄漏问题**：客户端上传的参数更新（梯度）是本地数据的函数。恶意或好奇的服务器可通过梯度反演攻击、成员推断攻击重建训练样本的敏感信息，Zhu et al. 的工作已证明这种攻击的可行性。
2. **拜占庭鲁棒性问题**：标准 FedAvg 采用简单平均聚合，对提交损坏或对抗性更新的客户端毫无防御能力。少数恶意客户端（被攻破的端点、数据投毒、本地故障）即可通过投毒或后门攻击将全局模型带偏。

现有研究通常将差分隐私与拜占庭鲁棒聚合分开研究，而真实受监管场景（银行、医疗）需要**同时应对两种威胁**：服务器并非仅好奇但仍诚实（honest-but-curious），客户端群体也并非完全可信。论文的核心动机正是填补这一空白，研究两种机制在联合部署时的相互作用。

## 2. 方法论：DP-BR-FedAvg

**核心思想**：在联邦平均框架内，按"**梯度裁剪 → 添加高斯噪声 → 逐坐标截尾均值聚合**"的流水线同时实现隐私保护和拜占庭鲁棒性。

### 2.1 系统架构与威胁模型

- 假设 K 个机构客户端（银行、医院）各持本地不可共享数据，协调服务器无权直接访问原始数据。
- **两类对抗能力同时建模且相互独立**：
  - 服务器/窃听者为"好奇但不诚实"（honest-but-curious）：遵守协议但试图从更新中推断客户端信息 → 需差分隐私保护;
  - 比例为 f 的客户端为拜占庭节点：可提交任意损坏更新 → 需鲁棒聚合。

### 2.2 关键技术细节

**（1）本地训练与梯度裁剪**

每个客户端在本地进行 E 轮小批量梯度下降后，对累积更新施加 L2 范数裁剪：

> ĝᵢ = gᵢ · min(1, C / ‖gᵢ‖₂) …（公式 1）

裁剪一方面为后续差分隐私噪声校准提供灵敏度上界，另一方面限制了拜占庭客户端原始更新的偏离幅度。

**（2）拜占庭鲁棒聚合**

服务器不使用简单平均，而是对每一坐标维独立应用截尾均值（coordinate-wise trimmed mean）：

> wⱼ = (1 / |Sⱼ|) · Σ ĝᵢ,ⱼ …（公式 2）

对每个坐标，将所有 K 个客户端取值排序，丢弃最大和最小各 β 比例的极端值后再对剩余值取平均。β 需要大于等于假定的拜占庭客户端占比上界。文中对比了 Krum 作为替代方案，但采用截尾均值作为默认聚合器，原因是其逐坐标操作便宜，且受高斯噪声干扰的可预测性优于依赖近邻距离排序的 Krum。

**（3）差分隐私机制（客户端级别）**

每个客户端在裁剪后独立添加高斯噪声再传输：

> gᵢ = ĝᵢ + N(0, σ²C²I) …（公式 4）

这是 DP-SGD 中高斯机制在客户端更新层面的应用，提供客户端级别的 (ε, δ) 差分隐私保证。若 T 轮、每轮采样率 q = 1/K，累积隐私损失可近似为：

> ε ≈ (q/σ) · √(2T·ln(1/δ)) …（公式 6）

作者明确说明该近似仅用于可解释性，真实部署应使用严格的数值隐私计算器（moments accountant）。

**（4）全局聚合规则**

> w_{t+1} = w_t + TrimmedMean({g₁,…,g_K}, β) …（公式 7）

整体流程：**clip → noise → trimmed-mean**，即 DP-BR-FedAvg。算法 1 给出了完整伪代码（每个通信轮并行执行各客户端本地更新、裁剪、加噪，服务器统一做截尾均值聚合）。

## 3. 实验设计

### 3.1 数据集与场景

由于真实的银行交易和临床数据无法公开获取，论文使用**合成二分类数据集**模拟跨机构场景，刻意复现了欺诈检测和临床风险评分的关键结构特征：

- **12,000 个样本**，24 个特征（14 个有信息量），约 70:30 类别比例（类别不平衡），每个类别 3 个聚类簇（避免线性可分）；
- 训练/测试划分：9,600 / 2,400；
- 训练数据按 Dirichlet 分布（α = 0.5）分配到 **K = 20 个模拟机构客户端**，产生非 IID 分布，模拟不同机构间欺诈/疾病患病率差异。

### 3.2 攻击与超参数配置

- 20 个客户端中 **5 个（25%）为拜占庭节点**，执行符号翻转攻击（sign-flipping）：将合法更新取负并放大 2 倍后提交——这是标准的强鲁棒性测试基准；
- 主要超参数：60 通信轮、3 个本地 epoch、学习率 0.15、裁剪范数 C = 3.0、噪声乘数 σ = 0.20、剪裁比例 β = 0.30、目标 δ = 1e-5。

### 3.3 对比方法与评估指标

| 方法 | 说明 |
|------|------|
| FedAvg（受攻击） | 标准平均，无隐私，无鲁棒聚合 |
| DP-FedAvg（受攻击） | 裁剪 + 高斯噪声，简单平均 |
| Byz-Robust FL | 截尾均值聚合，无隐私噪声 |
| **DP-BR-FedAvg（提出的方法）** | 裁剪 + 噪声 + 截尾均值 |
| FedAvg（无攻击，参考上界） | 所有客户端诚实 |

评估指标：准确率（accuracy）、少数类 F1-score、二元交叉熵损失。其中 F1-score 是重点——在不平衡分类中准确率本身具有误导性。

## 6. 主要结论与发现

1. **隐私噪声本身不提供拜占庭防护**：受到 25% 拜占庭攻击时，FedAvg 和 DP-FedAvg 的准确率都仅约 0.66，远低于干净的 0.84 参考线；DP-FedAvg 的少数类 F1 仅 0.024，实际上几乎完全丢失少数类。
2. **联合框架优于纯隐私或纯基础方法**：DP-BR-FedAvg 的少数类 F1 = 0.119，约为 FedAvg（0.030）的 **4 倍**，同时提供有界的隐私保证。
3. **纯鲁棒聚合（无隐私）表现最好**：Byz-Robust FL 达到 0.767 准确率和 0.393 的少数类 F1——量化了差分隐私层所施加的鲁棒性代价。
4. **隐私与鲁棒性是交互而非简单叠加**：随着噪声增强（ε 收紧），鲁棒性优势逐渐被侵蚀；在 ε 低于约 10 后，DP-BR-FedAvg 与 DP-FedAvg 趋于收敛。此外，一旦拜占庭比例接近截尾阈值 β = 0.30，鲁棒性也会崩溃，因此 β 需留安全余量。

## 7. 优点

1. **问题选取得当**：关注了真实部署场景中同时存在且学界通常分开研究的两个威胁，切入角度有实际价值。
2. **框架设计清晰**：三个技术环节（裁剪、加噪、截尾均值）均有明确的公式与算法伪代码，易于复现。
3. **实验对比设计有区分度**：设置了"无任何防护→仅隐私→仅鲁棒→两者兼具"的完整对照阶梯，使得隐私/鲁棒各自的贡献及其交互成本能够被分离量化。
4. **诚实的负结果报告**：不回避"加入隐私后鲁棒性下降""隐私预算紧时优势消失"的发现，对实际系统设计有重要的警示意义。
5. **评价指标选择恰当**：在不平衡分类任务中强调 F1 而非仅看准确率，避免了被表面准确率误导。
6. **超参数考虑到了实践约束**：β > f 的安全余量建议以及 σ 与 β 需联合调优的结论，具有工程指导价值。

## 8. 不足与局限

1. **实验规模与真实性有限**：仅一个规模较小的合成数据集；缺少真实银行/医疗数据验证。作者也承认真实数据受限于数据使用与伦理协议。
2. **攻击模型覆盖单一**：仅测试了符号翻转攻击，未覆盖更复杂的后门攻击、自适应/协作型（colluding）拜占庭攻击——这类攻击可能专门针对截尾均值设计绕过策略。
3. **隐私计算方法不够精确**：ε 使用近似闭式公式计算而非严格的 moments accountant 数值方法，可能低估实际隐私损失；作者自己也在文中标注了这一点。
4. **资源信息缺失**：未报告任何算力环境细节（GPU/CPU、运行时间等），可复现性和效率评估受限。
5. **统计严谨性不足**：未报告多次运行的均值和方差，无法确认实验结果的稳定性。
6. **理论保障是"拼接"而非统一**：隐私保证与鲁棒性保证分别在各自假设下成立，未给出两者结合后的统一理论界；截尾均值本身改变了灵敏度计算，而论文未给出严格的联合隐私-鲁棒性证明。
7. **残余风险**：恶意服务器（不诚实执行聚合）未被处理——需另加安全聚合/可验证计算；隐私保护是客户端级别而非逐记录级别，可能不足以应对所有逐样本推断风险。
8. **客户端非 IID 程度有限**：Dirichlet α = 0.5 仅是中等异质性设置，未测试极端非 IID 分布。
