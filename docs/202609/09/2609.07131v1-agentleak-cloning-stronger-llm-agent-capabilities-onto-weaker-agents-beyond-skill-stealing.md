## 摘要
大型语言模型（LLM）智能体通过将基础模型与显式技能及执行中获得的隐式程序性知识相结合，日益实现长程任务。由此产生的任务解决能力已成为有价值的专有资产，引发了一个新的安全问题：一个能力明显较弱的攻击者控制的智能体能否通过有限的黑盒交互获取更强专有智能体的能力？现有的技能窃取攻击可以恢复显式技能工件，但我们表明工件泄漏不一定会转移能力：较弱的智能体可能拥有相同的技能但仍然失败，因为它缺乏由较强智能体隐式实现的程序性行为。我们的关键见解是，技能执行差距本身构成了一个泄漏面，其中缺失的行为通过成功的受害者执行和失败的攻击者执行之间的可观察差异暴露出来。基于此，我们提出了AgentLeak，一种黑盒能力克隆攻击，它从这些执行差异中识别能力关键行为，并将其纳入攻击者侧技能，同时保持攻击者的模型、框架和工具不变。在包含600个实例、多种智能体系统和多个骨干模型的20个任务场景中，与直接技能重用相比，AgentLeak将任务通过率提高了40%以上，并恢复了受害者-攻击者能力差距的80%以上。我们的发现揭示了LLM智能体中的机密性风险：仅保护显式工件是不够的，因为可观察的执行行为会泄漏重建专有任务解决能力所需的程序性知识，即使在低能力和攻击者控制的智能体中也是如此。

## Abstract
Large language model (LLM) agents increasingly achieve long-horizon tasks by combining foundation models with explicit skills and implicit procedural knowledge acquired through execution. The resulting task-solving capabilities have become valuable proprietary assets, raising a new security question: can a substantially weaker attacker-controlled agent acquire the capabilities of a stronger proprietary agent through limited black-box interaction? Existing skill-stealing attacks recover explicit skill artifacts, yet we show that artifact leakage does not necessarily transfer capability: a weaker agent may possess the same skills but still fail because it lacks procedural behaviors implicitly realized by the stronger agent. Our key insight is that the skill execution gap itself forms a leakage surface, where missing behaviors are exposed through observable differences between successful victim executions and failed attacker executions. Based on this, we present AgentLeak, a black-box capability-cloning attack that identifies capability-critical behaviors from these execution differences and incorporates them into attacker-side skills, while keeping the attacker's model, harness, and tools unchanged. Across 20 task scenarios comprising 600 instances, diverse agent systems, and multiple backbone models, AgentLeak improves task pass rates by over 40% compared with direct skill reuse and recovers more than 80% of the victim--attacker capability gap. Our findings reveal a confidentiality risk in LLM agents: protecting explicit artifacts alone is insufficient, as observable execution behavior can leak the procedural knowledge required to reconstruct proprietary task-solving capabilities in low-capability and attacker-controlled agents.

- **核心安全问题的提出**：技能窃取究竟能否将更强智能体的任务解决能力转移到弱智能体上？如果能力转移可行，攻击者可以低成本复制专有Agent服务。
- **关键发现与核心观点**：虽然技能执行差距看似是天然障碍，但它本身就是一个**泄漏面**。在正常交互中，智能体会暴露工具调用、中间观察、最终结果等执行信息。通过对比受害者的成功执行与攻击者的失败执行，可以暴露缺失的能力关键行为，从而将隐式程序性知识外化为显式技能，实现**能力克隆**。
- **整体含义**：这一发现揭示了LLM智能体的一种**机密性风险**——仅保护显式工件（模型、Prompt、技能）是不够的，可观察的执行行为本身就可能泄漏重建专有任务解决能力所需的程序性知识，对智能体商业服务构成实质性威胁。

### 2. 论文提出的方法论

#### 2.1 核心思想

AgentLeak 的核心理念是：利用受害者与攻击者之间的执行差异作为信息通道。较强的受害者智能体隐式实现的行为（任务分解、工具选择、反馈解释、结果验证等），若在较弱攻击者执行中缺失，即为"能力赤字"。AgentLeak通过迭代诊断、提取并编码这些缺失行为到攻击者侧技能中，在不改变底层模型、Agent框架和工具的前提下，完成能力克隆。

#### 2.2 问题形式化

- 智能体定义为三元组 **A = (M, H, U)**：底层LLM、Agent编排框架、外部工具。
- 任务实例执行产生可观察轨迹：`τ = Exec(A, K_s, t) = ((a₁,o₁), …, (a_T,o_T))`。
- 场景 s 下智能体的任务解决能力定义为期望任务通过率：`Capa(A, K_s, D_s) = E[V(Exec(...))]`。
- 攻击目标：为固定弱智能体 A_a 重建技能集 K*_s，使其满足 `Capa(A_a, K*_s, D_s) ≈ Capa(A_v, K_v, D_s)`。

#### 2.3 技术流程（四个核心组件）

1. **工作流抽象与技能映射（Workflow Abstraction & Skill Mapping）**
   - 将成功的受害者执行轨迹抽象为结构化**工作流技能** `K_wf = (W_s, V_s, Φ_s, R_s)`。
   - W_s：有序执行步骤及依赖；V_s：中间状态和完成条件的验证标准；Φ_s：工作流步骤到现有技能的映射；R_s：随重建轮次更新的细化指导。
   - 移除实例特定细节，保留可复用的流程、工具使用模式、验证要求和恢复策略。

2. **差分能力赤字诊断（Differential Capability-Deficit Diagnosis）**
   - 以工作流技能为参照，在同一实例上多次执行攻击者智能体，获取多条失败轨迹。
   - 对比受害者成功轨迹与多条攻击者轨迹，在工作流步骤级别定位导致失败的能力赤字（如缺失验证、恢复行为）。
   - 将语义相似的赤字分组并记录频率，区分"新赤字"与"复发赤字"（此前补丁已修改但仍不足）。
   - 只保留确实导致任务失败的行为差异，忽略任务特定数值、风格选择等良性差异。

3. **行为原语提取（Behavioral Primitive Extraction）**
   - 将每个能力赤字转换为**行为原语**，指定应引入/强化/纠正的行为与所需程序指导（不复制受害者轨迹中的具体动作）。
   - 每条原语包含：目标技能、缺失行为、所需程序、预期效果。

4. **结构化技能重写（Structured Skill Rewriting）**
   - 对行为原语生成**局部补丁** `π = (l, c, op)`，而非直接重写整个技能。
   - 仅支持两种操作：**插入**（在行为缺失处添加步骤）与**替换**（替换不完整或无效指令），保持有效的技能组件不变。
   - 迭代执行：修补→重执行→再诊断，直至任务成功或预算耗尽。最终对所有已解决实例执行回归校验。

#### 2.4 攻击约束

- 仅限黑盒查询受害者，观察正常接口暴露的执行证据。
- 攻击者模型比受害者明显更弱（开源开放权重模型）。
- 仅修改本地技能，不访问受害者私有技能、参数、推理隐藏状态等；不改变自身模型/框架/工具。
- 离线使用辅助LLM分析观察证据并生成技能更新（重建后不再需要）。

### 6. 论文的主要结论与发现

- **发现1：直接技能复用无法传递强智能体的能力。** Raw Skill 仅将 Qwen攻击者的IPR从21.13%提升到30.64%（CRR仅17%~20%），与受害者仍有巨大差距。
- **发现2：现有技能进化方法无法恢复隐式能力关键行为。** Trace2Skill 的CRR仅为21%~29%，说明从自身轨迹总结技能不足以恢复受害者能力。
- **发现3：AgentLeak高效实现能力克隆。** 在全部受害者-攻击者配置下实现70%以上的IPR、85%以上的CRR，比Raw Skill和Trace2Skill提高至少35个百分点，恢复80%以上能力差距。
- **发现4：重建技能可跨系统迁移。** 跨模型/框架后仍保持72%~85%的IPR和86%~107%的CRR，说明重建的是可复用程序性行为而非针对特定系统的模式。
- **发现5：四个组件均不可或缺。** 去除工作流抽象导致CRR暴跌至2%；去除结构化重写CRR降至30.5%；差分诊断和行为原语提取也各有显著贡献。
- **发现6：现有防御难以阻止行为级能力泄漏。** 工件级防御（检测器、SkillGuard、语义过滤）仅降低CRR 7~18个百分点；轨迹编辑（行为级防御）效果最强但也仅将CRR降至73%，仍无法根除泄漏。

- **问题选择新颖且重要**：超越现有工件窃取范式，首次系统研究"能力克隆"（而非单纯"技能窃取"），指出"技能执行差距"本身即泄漏面，揭示已有"保护工件即保护能力"假设的不足。
- **方法设计完整且自洽**：四个组件（工作流抽象→差分诊断→原语提取→结构化重写）形成闭环迭代，每步都有明确的问题定义和形式化表示；区分良性差异与能力赤字、新赤字与复发赤字，逻辑严谨。
- **攻击约束贴近实际**：黑盒假设严格，仅用1个查询实例、很低成本、不改动底层模型/框架/工具，攻击可行性高。
- **评估体系全面**：多受害者/多攻击者配置、跨系统迁移、四组件消融、轮次影响、复杂度影响、防御测试、攻击成本分析，覆盖维度广。held-out实例设计区分了泛化与记忆。

- **依赖丰富执行反馈**：攻击依赖受害者暴露工具调用、中间观察等执行信息；若受害者仅返回最终输出或高度受限接口，攻击效果将显著降低（论文明确承认此限制）。
- **无法重建依赖不可访问资源的能力**：私有数据、受害者专属工具、专有服务或模型内部知识不在可重建范围内——这些往往是商业智能体的关键差异点。
- **仅覆盖程序性技能可表达的能力**：对非技能型能力（如纯推理、隐性知识、需要特定模型涌现能力的任务）的适用性有限。

- **防御评估深度有限**：所测防御主要针对既有工件窃取范式设计，轨迹编辑仅代表一种初级行为级防御；未深入探索更精细的行为混淆或差分隐私类防御。
- **对商业前沿模型的实际效果需谨慎**：受害者使用Opus-4.8、GPT-5.5等假设性未来版本（论文标注时间为2026年），现实场景的模型能力差异和实际部署可能影响结果外推。
