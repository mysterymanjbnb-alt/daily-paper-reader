## 摘要
近年来的个性化LLM代理越来越多地将内存中保留的信息转化为压缩或结构化表示，我们称之为用户模型，以指导后续决策。当通过普通接口可达的状态中移除源文本时，这些模型通常被认为更具隐私保护性，因为直接的内存提取攻击会丢失其目标文本。然而，我们认为用户模型暴露了新的攻击面，因为攻击者仍然可以从它们塑造的个性化选择中恢复私有信息，即使源记录和后端状态不可访问。因此，我们引入了UMPeek，一种基于假设引导的自适应探测的黑盒攻击，以推断这种隐藏的用户模型。它从请求未决的选择中形成假设，在普通后续任务之间切换，并仅保留受可见行为支持且未被反驳的主张。我们在各种个性化任务和用户模型后端上进行了广泛的基准评估，与现有攻击进行比较。我们进一步在真实世界系统中使用确认被保留的信息验证UMPeek，并评估针对其自适应探测的防御措施。总体而言，UMPeek在基准测试和真实世界比较中均优于现有攻击，并在响应级防御下继续恢复用户信息，表明当保留的信息塑造可见行为时，使记录和后端状态不可访问并不能保证语义隐私。

## Abstract
Recent personalized LLM agents increasingly transform information retained in memory into compressed or structured representations, which we call user models, to guide later decisions. When source wording is removed from the state reachable through the ordinary interface, these models are commonly treated as more privacy-preserving because direct memory-extraction attacks lose the text they target. Yet we argue that user models expose a new attack surface because an attacker can still recover the private information from the personalized choices they shape, even when source records and backend state remain inaccessible. We therefore introduce UMPeek, a black-box attack based on hypothesis-guided adaptive probing to infer such hidden user model. It forms hypotheses from choices left open by a request, switches among ordinary follow-up tasks, and retains only claims supported and not contradicted by visible behavior. We conduct an extensive benchmark evaluation across diverse personalization tasks and user-model backends against existing attacks. We further validate UMPeek in real-world systems using information confirmed to be retained, and we evaluate defenses against its adaptive probing. Overall, UMPeek outperforms existing attacks in both benchmark and real-world comparisons and continues to recover user information under response-level defenses, showing that keeping records and backend state inaccessible does not guarantee semantic privacy when retained information shapes visible behavior.

## 1. 论文的核心问题与整体含义

**研究动机与背景：**

- 个性化LLM代理系统（如带记忆层的对话代理、管理服务等）使用历史交互信息为用户提供个性化服务。为了兼顾效率与效果，现代个人化系统不再简单地将完整历史记录注入提示，而是将历史保留信息转化为压缩或结构化状态——本文称之为**"用户模型（user model）"**。
- 该用户模型可能以嵌入（embeddings）、结构化配置文件（typed profile）或压缩软提示（soft-prompt）等形式存在，其典型特征是**紧凑性**与**抽象性**，即不再逐字保留源文本。
- 业界普遍认为这是一种隐私保护优势：源文本被移除，直接的内存/记录提取攻击失去了目标。已有研究显示，基于摘要等压缩方法可将记忆提取率降低64%-76%，同时保持个性化性能基本不降。
- **本文的核心论点**：这种"以隐藏状态换隐私"的假设存在缺陷。用户模型即使不可直接访问、没有源文本可供提取，只要其中保留的信息持续影响代理的可见决策（推荐内容、工具调用等），攻击者仍可通过观察这些行为推断隐私信息，这构成一个**新的语义推断攻击面**。

**整体含义：** 隐私保障不能仅依赖于隐藏源记录和后台状态；当个性化决策本身携带用户信息时，从可见行为中进行推断是可能的。这是与"记忆提取攻击"（memory extraction）性质不同的一类隐私风险。

## 2. 论文提出的方法论

**UMPeek攻击框架**——一种黑盒、假设引导的自适应探测方法，核心目标是从可见行为中推断代理后台保留的用户语义信息。

**核心思想：**
- 攻击者是代理预期会与之交互的外部参与者（如协作者、服务商），拥有普通任务接口的有限访问权限，但无账号权限和后端访问权限。
- 每次请求必须是普通任务请求，不得要求代理泄露记忆、配置文件或隐藏状态。
- 思路核心：当请求给某决策维度留有空缺（未指定取值）时，代理给出的个性化选择传递了关于隐藏用户状态的信息；但单次选择无法区分"代理真正知道用户信息"与"任务上下文的偶然结果"，因此需要多轮互动逐步消除歧义。

**整体框架流程（三阶段）：**

**阶段一：构建行为假设（Hypothesis Construction）**

- 从公共任务描述和接口中预定义若干决策维度（decision dimension）与声明模板（claim template），例如"饮食限制""旅行偏好"等。
- 检查请求是否已经固定该维度的值：若请求本身限制了取值，则该取值不携带个性化证据。
- 仅当请求未指定值、且回复中出现了影响最终答案/工具动作的具体选择时，才将该选择视为候选假设（行为假设），包含：语义声明、触发的可见选择、发生的交互记录（来源追踪）。
- 过滤不满足上述推导链的内容（如任务重述、泛泛的模板化建议等）。

**阶段二：自适应测试（Adaptive Testing）**

- 预算上限为B个后续请求，每轮更新每个假设的三种状态：受支持（supported）、被反驳（contradicted）、未解决（unresolved）。
- 第一个后续请求（若预算允许）用于重复原有任务（任务保持同样目标且维度留空），以检验同一任务语义下选择是否重现（重放证据）。
- 更强的测试是切换到不同的任务——保持目标维度开放但任务条件变更——用来检验候选解释能否在其他情境下预测一致行为。例如，从"推荐素食餐厅"切换到"安排餐饮"仍选素食，则支持该假设；若切换后选择了非素食，则构成反驳。但如果请求明确要求肉类，则请求固定了取值，不构成有效的反驳证据。
- 请求调度规则：按当前证据状态排序最优先—能同时覆盖多个未解决维度的请求、能区分仍竞争的候选值的请求优先级最高；已充分决定的维度或提前固定值的请求优先级低。

**阶段三：选择性恢复（Selective Recovery）**

- 将假设同义声明按决策维度+值进行规范化合并（canonicalization），不同交互可贡献同一声明的证据但保留各自的来源。
- 接受规则（acceptance rule）：一个声明必须满足——至少有具体可见选择作为基础；无相互矛盾行为；若为隐含（间接）声明，还需额外证实（重放或跨任务兼容行为）。
- 若无法区分互斥解释，则不将该假设纳入最终估计。
- 输出包含人类可读的语义声明集合，而不会尝试重建后端字段、嵌入坐标或图结构。

**数学化描述（文字化）：**
目标域x中用户信息记为S(u,x)，攻击者通过提交请求序列q0;m观测输出序列o0;m，并输出语义估计Ŝ(u,x)；所有假设的验证与选择均以可见行为为依据，在任何阶段都不访问内部状态。

## 6. 论文的主要结论与发现

1. **记录不可见≠语义隐私**：UMPeek表明，即使源记录和后端状态对攻击者不可访问，当用户模型所含的保留信息影响后续可见行为时，这些信息仍可被黑盒攻击语义性地恢复。
2. **UMPeek显著优于现有攻击**：在汇总基准评估中，UMPeek的UMR-F1达到0.619，是大多数强基线（0.100）的六倍以上；HBPS（0.289）也是最强基线（0.147）的约两倍。12个基准-后端组合全部具有非零恢复。
3. **优势来自假设引导的请求选择而非请求数量**：固定序列基线在类似请求预算下只能达到0.281 UMR-F1，而UMPeek可达0.651——差距源自任务选择与验证机制。
4. **真实世界系统同样暴露**：在Google Memory Bank、AWS AgentCore和Mem0平台上，UMPeek均取得最高UMR-F1（宏平均0.500 vs. 最强基线0.180），且在3个请求内达到最大恢复——不存在请求预算更大的测量假象。
5. **响应级防御无法有效防护**：在自适应多轮探测下，PrivacyChecker与基于思维论的防御恢复水平分别达到无防御时的约65%与90%；更直接的反事实状态控制（Stateful Counterfactual）可将UMR-F1压低至0.187，但仍有残余可恢复信息且同时也牺牲任务效用。个人化的好处与隐私风险来自同一机制——个人化差异决定既携带有用调整又携带攻击证据。

## 7. 优点

1. **定义清晰且理论框架直观**：对"记忆（memory）"与"用户模型（user model）"做出了有用区分——前者跨交互存储信息，后者为决策供应个人化信息；并提前形式化威胁模型，明确攻击对象是语义声明而非后端字段。
2. **威胁模型实操性强**：攻击者仅具备普通任务接口的黑盒访问权限——不需要账号、不需要后端权限、不需要辅助个人信息、不需要知道底层表示——贴近真实攻击场景。
3. **UMPeek设计严谨**：通过对决策维度留空的约束避免把任务固定值误当用户证据；通过重放断言排除单一次性解释，通过跨任务切换排除局部上下文解释，用有效的反驳条件约束归因风险。
4. **指标与归因相关联**：UMR-F1要求证据链归因（有可见选择支撑且不矛盾），HBPS要求恢复的语义确实预测未见的任务行为，避免仅为浅层表面相似而给分。
5. **评估科学性强**：
   - 匹配器是确定性的、无LLM判断，降低了评分偏差。
   - 置信区间用聚类自助抽样并保持后端配对。
   - 同一设置的消融实验精确地对组件贡献归属，有效论证了增益来自信息性的任务选择与接受规则而非请求配额。
   - 真实系统验证有"确认保留"环节，能精确区分攻击是否真的恢复平台保留的信息。
6. **诚实的防御评估**：UMPeek承认残余恢复，同时报告隐私-效用权衡，而非只报攻击成功率的片面结论。

## 8. 不足与局限

1. **应用场景有限制**：该攻击针对的是"能为第三方访问提供普通界面"的个人化代理（如代表用户与外部协作者交互的服务）。若代理只向同一用户提供服务，缺乏多方可观察交互面，则此攻击路径未必存在。威胁模型"输入外部参与者"需在应用时进一步明确适用边界。
2. **语义假设空间依赖公共任务**：假设空间由公共任务/接口预定义。如果目标域没有公开暴露并可穷尽枚举的决策维度，或界面不呈现可见选择（如纯文本自由形式对话），UMPeek的攻击效果会大幅受限。
3. **预算与规模问题**：基准实验可使用16个后续请求，且每目标可先有一个初始化请求。一旦服务层限制交互数量极低（如仅一个后续请求），恢复会显著下降，这与已有结果（图6b所示）一致。
4. **衡量方法可能偏差**：UMR-F1采用词法匹配（0.72重叠阈值），词义相同但措辞不同时漏报较大——难以测量语义恢复是否被低估；评估限制在基准测试的公开提示格式下（选项式离散选择占据多数），可能高估在实际产生复杂输出任务上的恢复能力。
5. **防御评估不够深入**：防御部分所测试的三种方法都属于推理时间控制，缺少训练时隐私保护（如差分隐私、记忆清洗策略）与架构级方案（如不可逆的用户状态抽象）研究。此外，"有状态反事实对照暴露控制"是本文自己提出的方法，与文献中对隐私-效用权衡的论证互相印证不完全独立。
6. **真实世界工作的边界条件**：管理服务的真实实验基于合成数据；服务由其提供方实现（作者代码不可控），但各自采用的模型相对较小（14B或Flash-Lite），不确定在更大的云模型（如闭源商用前沿模型）上攻击的可靠性。
7. **对初始响应高度依赖**：消融结果证实单独的初始响应几乎没有正确恢复。如果服务目标状态的证据无法在初始请求与后续有限交互中正常催生，则UMPeek的恢复率趋零——本工作没有提供如何在看似无个性化选择时主动引导证据出现的策略。
8. **计算成本与效率未作量化报告**：论文未说明每策略在真实托管服务中所需的令牌数、延迟与计算成本，对实际部署在攻击上尤其对并发账户数量大的场景下的可扩展性仍缺乏评估。
