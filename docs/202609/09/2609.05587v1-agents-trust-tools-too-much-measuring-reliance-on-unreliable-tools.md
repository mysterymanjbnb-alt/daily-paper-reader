## 摘要
现有的工具使用智能体评估主要衡量智能体是否能利用工具成功完成多样化任务，这些评估通常假设工具返回可靠信息。然而，现实系统中的工具返回可能看似合理却存在错误。我们通过使用三种工具——网络搜索、LLM子智能体委派和代码执行——评估十四个LLM，研究智能体如何应对不可靠的工具返回。对于每种工具，我们破坏其返回内容，并衡量智能体是否在最终答案中采纳了被破坏的内容。在所有三种设置中，智能体均表现出高度过度信任：每种工具的平均采纳率超过三分之一，其中网络搜索高达68.0%。对推理轨迹的分析揭示了一个尤为令人担忧的失效模式：智能体常常意识到冲突，甚至内部能恢复出正确答案，却只呈现被破坏的答案而不警告用户。为了缓解智能体对工具返回的过度信任，我们从三个层面进行干预：用户的提示、工具提供方的元数据、以及智能体构建者的后训练。尽管某些干预在特定模型或工具上有所帮助，但没有一种干预能始终如一地减轻跨工具的过度信任。这些发现表明，对不可靠工具的过度信任是一种严重且持续的失效模式，促使需要相应的评估和干预措施，使智能体能够验证工具输出并透明地沟通未解决的冲突。

## Abstract
Existing evaluations of tool-using agents primarily measure whether an agent can successfully complete diverse tasks with tools. These evaluations generally assume that tools return reliable information. However, tool returns in real-world systems can be plausible yet incorrect. We investigate how agents respond to unreliable tool returns by evaluating fourteen LLMs using three tools-web search, LLM sub-agent delegation, and code execution. For each tool, we corrupt its returns and measure whether agents adopt the corrupted content in their final answers. Agents exhibit high levels of overtrust across all three settings: the mean adoption rate exceeds one third for every tool and reaches 68.0% for web search. Analysis of reasoning traces reveals a particularly concerning failure mode: agents often recognize conflicts and even recover the correct answer internally, yet present only the corrupted answer without warning the user. To mitigate agents' overtrust in tool returns, we intervene at three levels: prompting by the user, metadata from the tool provider, and post-training by the agent builder. Although some interventions help for particular models or tools, none consistently mitigates overtrust across tools. These findings identify overtrust in unreliable tools as a serious and persistent failure mode, motivating evaluations and interventions that enable agents to validate tool outputs and transparently communicate unresolved conflicts.

## 一、论文的核心问题与整体含义

**研究动机与背景：**
- 现有工具使用智能体（tool-using agents）评测侧重于衡量智能体能否正确选择工具、发出有效调用并完成任务，**基本假设是工具返回可靠信息**。
- 然而，真实系统中工具可能返回**看似合理却错误的内容**：搜索引擎可能返回生成的摘要答案、LLM子代理返回合成报告、代码执行器返回模型生成程序的结果。这类输出可能看似合理但不符合事实。
- 已有知识冲突研究多局限于检索设置，将矛盾文本直接放入提示中，而工具智能体需要**在任务执行过程中自主决定是否及何时调用工具**，因此存在研究空白。
- 论文的核心问题是：**智能体是否会将不可靠工具返回的错误内容带入最终答案？这一依赖如何随内容合理性变化？哪些干预可以缓解？**

**核心含义：** 过度信任工具是不可靠工具场景下智能体的系统性失效模式，其严重性在于：即使智能体自身已具备正确答案，或内部已识别出工具返回内容与自身知识的冲突，仍可能向用户输出错误答案且不加警告。

## 二、方法论

### 2.1 总体设计思路
- 针对三种工具（网络搜索、LLM子智能体委派、代码执行器），在三个独立任务（事实问答、文档摘要、数学计算）中评估智能体行为。
- **核心实验范式**：对每种工具，先获得未污染的原始正确返回，再仅修改其内容，将修改后的内容呈现给智能体，检测其最终答案是否采纳被修改的内容。

### 2.2 核心指标
- **采纳率（Adoption rate）**：智能体将被污染的工具内容纳入最终答案的频率。
- **覆盖率/篡改率（Override rate）**：在智能体无工具情况下已能正确回答的项目中，被污染工具返回改变其正确答案的频率。
- **基线准确率（Base Accuracy, B）**：通过无工具条件下三次独立回答的多数投票确定。

### 2.3 污染等级设计（Plausibility Ladder）
针对各工具构建三级污染内容，以考察智能体对错误内容合理性的敏感度：
- **P1（看似合理）**：曾正确或容易混淆的真实值（Search）；用虚假声明替换一个头条声明（Sub-Agent）；小幅数值缩放（Code Executor，幅度参数从 log-uniform[1,100] 抽取的误差因子）。
- **P2（移植/编造）**：来自其他问题的正确答案，语义类型不匹配（Search）；保留真实声明但添加原文档不存在的编造内容（Sub-Agent）；大幅数值缩放（幅度参数从 log-uniform[101,10000] 抽取）。
- **P3（完全虚构，仅Search定义）**：对实体类答案使用音节池构造的不存在名称，对数字类答案使用机械式数字换位转换。

### 2.4 重要分析维度
- 在代码执行器场景中，污染方向进一步分为**符号保留 vs 符号反转**两个条件（通过 d 和 s 两个参数控制），以区分智能体对数值规模变化和符号变化的敏感性差异。
- **推理轨迹分析**：对具有推理能力的模型（如Qwen3 thinking配置）保留思维链`reasoning trace`，分析模型是否在内部识别冲突、是否内部恢复正确值、以及最终输出是否披露冲突。

## 六、主要结论与发现

1. **过度信任具有普遍性和跨模型持续性**：P1平均采纳率在每个工具下都超过三分之一（Search 68.0%、Sub-Agent 28.7%、Code Executor 35.4%），且Override rate在Search超过50%（56.4%），在Code中约33%（33.4%）。即使面对完全荒谬的P2/P3内容，采用仍然存在（Search的P2为12.6%，P3 override仍达26.8%）。
2. **非合理性依赖突出**：从不改变的事实中，P1的采纳率仍高达59.7%，超过一半的污染返回会覆盖智能体已证明能正确回答的答案。代码执行器中符号保留的污染值被采纳56.4%，而符号反转只有14.3%被采纳。
3. **检测与披露的割裂（最令人担忧的失效模式）**：推理轨迹分析显示，采纳污染结果的回答中，推理模型在Search情境约半数能意识到冲突（Code Executor超90%），许多还能内部推导出正确的值，但最终答案几乎从不警告用户。Search中仅5.3%、Code Executor中仅1.8%的采纳回答包含警告；这一状况与"模型不知道正确内容"有本质区别。
4. **工具权威性效应仅存在于计算输出**：对代码执行器而言，相同被污染数字以用户陈述方式（1.8%）或RAG上下文方式（3.8%）呈现时几无影响，以工具返回方式呈现采纳率高达39.9%，表明执行器返回具有独特的权威效应。但对Search和Sub-Agent，以任何方式呈现的污染文本信息均具有说服力。
5. **现有干预手段效果有限**：提示策略的效果依赖渠道和模型，没有一个策略能在保持无污染准确率的同时持续降低P1采纳率；来源/可靠性元数据不但无法持续缓解，且更高标注可靠性反而使污染返回更具说服力（0.95 vs 0.10：+4.0pp差异）；后训练效果取决于训练目标，正确工具轨迹的SFT反而提高污染采纳率（Override增加9.3pp），Fixed-context DPO虽在Search中有效降低5.1pp但无法迁移到Code Executor。
6. **无模型家族一致抵抗污染**：虽然Gemini/Gemma/Muse在Code Executor中表现较好，但没有任何模型家族在所有三个工具上均能抵抗，总体呈现持续性和系统性缺陷。

## 七、优点

- **统一跨渠道评测框架**：在同一实验逻辑下对三类性质各异的工具（信息检索型、生成型、计算型）进行等量污染和度量的实验设计是创新。
- **精细的双指标设计**：采纳率和Override率分离了"合理借助工具"与"对已证正确能力的不合理覆盖"，使行为度量具有规范性，避免了原生拒绝工具的偏见于指标外的偏差。
- **三级污染粒度（P1/P2/P3）**：区分合理误导、错误类型和完全虚构，可以量化和比较模型对可信度的敏感度。
- **关注检测-披露割裂的新颖视角**：通过思维链信号（意识到冲突、内部恢复正确值）与最终输出警告缺失的对立，揭示了比"简单错误"更深层的问题，具有可操作的政策启示。
- **多层次干预测试**：覆盖用户（prompt）、工具提供方（metadata）和模型构建方（post-training）三层，干预措施来源广泛，结论更具现实意义。
- **严谨的数据管控**：冻结缓存、交付载荷的暴露审计（fail-closed）、URL-leak重写、人工验证裁判、广泛的敏感性分析（不同gate）、item-bootstrap置信区间等多重质量保障增强了结果的可靠性。

## 八、不足与局限

- **后训练干预规模有限**：仅对单个模型（Qwen3-30B）进行后训练验证，结果泛化性不确定；训练数据规模较小（数百条轨迹）。
- **小说摘要的P0定义外部有效性受限**：摘要由LLM生成而非基于文本，接收智能体无法独立核对文稿，且生成器的P0中已无源文本校验渠道，评估结论在更真实代理设置下可能有所不同。
- **模型服务不一致造成比较偏差**：不同模型采用不同精度（fp8 vs bf16）、不同输出token预算（8k vs 24k）、不同API端点和缓存采集时间；论文承认这一点，但Cross-model comparisons的可靠性仍受此影响。
- **无法充分验证真实场景中"从自身参数知识中识别correctness"的程度**：以无工具多数投票作为证明"已能正确回答"的凭证，部分文档标题本身就泄露正确答案（如后期论文），因此override rate解释需谨慎。
- **元数据干预和提示干预样本较小**：仅60个固定条目和6模型，统计功效相对有限；实际工具层面更高阶的验证机制（如Web搜索结果的溯源验证）未在范围内。
- **Web Search工具依赖特定日期快照**：世界状态固定的评测设置与实际不断演变的搜索环境仍有偏差，真实动态污染可能更复杂。
