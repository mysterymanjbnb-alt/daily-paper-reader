## 摘要
我们介绍了HoneyRoute，这是一个推理服务层，能够检测传入请求是否为恶意请求，如果是，则将其路由到专用蜜罐模型，从而保护生产环境，同时不断收集攻击者的交互以获取情报。现有防御措施在模型内存中嵌入陷阱，或在协议层重建欺骗机制，导致服务层缺乏保护，也无法为检测提供任何反馈。HoneyRoute结合了(i)流式路由器（冻结的0.8B嵌入主干，带按领域的MLP头），(ii)双实现蜜罐（基于规则/提示工程的代码蜜罐或专用同族副本），以及(iii)分析循环，该循环将被捕获的交互转化为攻击者指纹，用于路由器重训练。在生产轨迹加上七个领域的攻击语料库上，路由器达到F1=.911，中位额外延迟38毫秒，在13种对抗性变换下逃逸率为0%，其F1为双层守卫LLM级联的96%，而延迟仅为后者的1/385；将恶意流量转移后，在真实GCG后缀负载的并发洪泛下，生产模型的令牌消耗减少了97.8%；训练后的副本在92.9%的良性保留请求上与生产模型一致，而朴素的无条件诱饵注入则骤降至7.6%，选择性的伪装注入则恢复至88.9%，从而描绘出可恢复的保真度-可追踪性边界；此外，经循环训练的修正头将合法安全研究的误路由降低9倍，同时检测F1提高至.933。

## Abstract
We introduce HoneyRoute, an inference-serving layer that detects whether an incoming request is malicious and, if so, routes it to a dedicated honeypot model, shielding production while the adversary's interaction is continuously harvested for intelligence. Existing defenses embed traps inside model memory or rebuild deception at the protocol layer, leaving the serving tier unprotected and feeding nothing back into detection. HoneyRoute couples (i) a streaming router (a frozen 0.8B-embedding backbone with per-domain MLP heads), (ii) a dual-implementation honeypot (a rule/prompt-engineered code honeypot or a dedicated same-family replica), and (iii) an analysis loop that converts trapped interactions into attacker fingerprints for router retraining. On a production trace plus a seven-domain attack corpus, the router reaches F1=.911 at 38 ms median added latency, matching 96% of a two-tier guard-LLM cascade's F1 at 1/385 of its latency with 0% evasion under 13 adversarial transformations; diverting the malicious share cuts production-model token consumption under concurrent flooding with real GCG-suffix payloads by 97.8%; the trained replica agrees with the production model on 92.9% of benign holdout requests, while naive unconditional bait injection collapses to 7.6% and selective camouflaged injection recovers to 88.9%, mapping the recoverable fidelity-traceability frontier; and a loop-trained correction head cuts misrouting of legitimate security research 9x while raising detection F1 to .933.

大型语言模型（LLM）的推理/服务部署已成为标准攻击面。攻击者通过 API 窃取系统提示词、发起多轮越狱、进行模型行为提取甚至资源耗尽攻击。现有多数防御的主流做法是在服务入口部署更强大的“守卫模型”过滤流量；另一类研究则将“欺骗”引入防御：通过蜜罐与攻击者交互并收集情报，但这工作大多发生在网络协议层（SSH/HTTP等）或模型内部（内存、知识层陷阱），**模型服务层本身——即 API 网关和模型农场——仍是防护与情报收集的空白地带**。

针对该缺口，论文提出 **HoneyRoute**，一个位于推理网关的蜜罐路由系统：运行时区分恶意与良性请求，将恶意请求分流至“蜜罐模型”，在保护生产模型的同时持续捕获攻击交互并回注检测器，形成闭环。核心含义是：将传统上被视为“被动管道”的服务层转变为主动欺骗面与情报来源。

### 论文提出的方法论

#### 核心思想
- **分流而非阻断**：恶意请求不直接拒绝，而是被导向蜜罐（honeypot）。生产模型得到保护，同时攻击者的行为被完整记录和分析。
- **欺骗与情报一体化**：蜜罐不只是诱饵，而是情报采集器；采集到的攻击指纹反哺路由器训练，实现自强化防御。

#### 系统架构三组件

1. **流式路由器（Streaming Router）**
   - 固定不变的约 0.8B 嵌入骨干网络（完全冻结，避免表示漂移），后接各攻击领域独立的微型 MLP 头（每头约 0.07M 参数）。
   - 每个请求获得一个风险分数 \( s_d = \sigma(w_d^\top h(x) + b_d) \)，经领域归一化阈值比较后决定是否分流（\(\max_d s_d/\tau_d \ge 1\)）。
   - 新增攻击家族只需训练单个 0.07M 参数的小头，无需重训骨干。
   - 会话级风险追踪器：针对“软升级”（soft escalation）攻击——攻击者将越狱拆成多轮，每轮单独不足以触发警报——追踪器累加多轮风险分数，尤其关注分数跨轮的**趋势**（上升 vs. 平坦）而非累加水平。

2. **双实现蜜罐（Dual-Implementation Honeypot）**
   - **(a) 代码蜜罐 \(f_{Mc}\)**：无独立模型，基于规则/提示工程的响应器，零 GPU 开销；回复简短且缓存友好，擅长吸收洪泛攻击；可在回复中植入诱饵（如伪造的凭据）。
   - **(b) 训练副本蜜罐 \(f_{Mt}\)**：专用同族模型副本（9B，生成模式），与生产模型使用相同聊天模板，尽量逼真地模仿生产模型的回复分布；可追踪性不依赖注入诱饵，而是通过对全会话的完整侧信道记录实现。

3. **持续分析回路（Continuous Analysis Loop）**
   - 被捕获的会话被挖掘为攻击者指纹：战术签名（攻击家族与变换类型）、内容目标（请求针对的能力）、行为画像（嵌入指纹 + 请求节奏）及会话身份哈希。
   - 指纹用于：(i) 法证归因——即使攻击者轮换身份也能重链同一持续攻击；(ii) 作为弱标签重训下一代路由器，形成“越用越强”的检测闭环。

#### 关键权衡：保真度与可追踪性
论文定义了保真度 \(F\)（蜜罐回复与生产模型在良性请求上的一致率）与可追踪性 \(T\)（蜜罐信号的信息密度）。两者存在张力：诱饵注入提升 \(T\) 但降低 \(F\)；完全模仿降低 \(F\) 的损失但依赖攻击者自愿暴露行为。论文以率失真理论视角刻画：带内诱饵注入遵循率失真约束，侧信道记录（\(f_{Mt}\)）以零失真代价获取信息。实测边界为：\(hpT(.93, 1.0)\)、选择性 \(hpC(.89, .83–1.0)\)、朴素 \(hpC(.08, 1.0)\)。

### 实验设计

#### 数据集与场景
1. **良性生产轨迹**：710 条教师重标注请求（645 条良性）。
2. **七领域攻击种子语料**：注入/越狱、恶意代码、敏感信息窃取、危险操作、资源滥用等，附 13 种对抗变换。
3. **真实攻击负载**：JailbreakBench（GCG 优化后缀、PAIR、人工越狱，496 条独特提示，366 条确认越狱）。
4. **指纹探测**：canary-echo 探针。
5. **资源耗尽压力测试**：GCG 后缀洪水、长文档提取滥用、lorem-flood 对照。
6. **多轮软升级与良性脚本**（GLM-5.3 生成，E7 使用）。
7. **仿冒/伪装攻击**：83 条教师生成的学术/翻译/代码注释壳包装的恶意请求。

#### Benchmark 与对比方法
- **E1 检测质量**：对比 (a) 多语言关键词/正则启发式；(b) 守卫 LLM 内容审核器；(c) 标准双层级联（自身 L1 门槛 + 中型请求升级至守卫 LLM）。结果：HoneyRoute 在 F1 上为级联的 96%，延迟仅为后者的 1/385。
- **E2 欺骗保真度**：GLM-5.3 教师（先判决后评理）评判蜜罐回答与生产回答的语义等价性；交叉家族裁判用 Deepseek-V4-Flash 复评。
- **E6 归因检索**：30 个攻击活动（每活动 6 个旋转变体），三种视角融合检索（嵌入、风格特征、风险概率向量），对照随机检索基线概率（top-1 3.3%）。
- **E7 多轮软升级**：对比单轮触发规则与累加怀疑启发式；复现人类 Crescendo playbooks。

#### 主要实验组
E1（检测质量）、E2（保真度与可追踪性边界）、E3（成本与延迟）、E4（闭环增益）、E5（消融）、E6（洪泛吸收与归因）、E7（多轮软升级），另加单轮逃逸攻击、对抗变换逃逸、裁判位置敏感性/跨家族验证、知识库规模扩展等子实验。

### 论文的主要结论与发现

1. **检测性能**：路由器 F1=.911（精确率 .903、召回率 .918），AUROC 0.975，95% 召回率下 FPR=0；中位延迟仅 38ms——为双层 LLM 级联 F1 的 96%，延迟仅为其 1/385；13 种对抗变换下逃逸率为 0。
2. **洪泛防御**：真实 GCG 后缀并发洪泛场景下，生产模型 token 消耗削减 **97.8%**（708,077→15,351），三类洪泛请求全部分流（分流率 1.0），良性 p50 延迟仅从 21.4s 升至 22.7s。
3. **蜜罐保真度边界**：训练副本 fMt 良性保真度 92.9%；朴素无条件诱饵注入骤降至 7.6%；选择性、伪装注入可恢复至 88.9%（与副本相差 4 个百分点内）且保持 83–100% 攻击者可追踪率。
4. **闭环增益**：连续三代的增量更新无回归（F1 恒定 .912）；良性安全研究语域校正头将误路由从 30% 降至 3.3%（9 倍改善），F1 升至 .933。
5. **归因能力**：三视角融合检索将身份旋转的请求重链到源活动，top-1 56.7% / top-5 80.7%（分别 17×/24× 于随机概率）；数据库扩至 150 锚点时仍保持 38×/72× 于随机。
6. **多轮软升级检测**：会话内风险分数趋势（斜率）而非累加水平是判别关键——攻击会话斜率 .155 对良性 .012，趋势规则实现 100% 检测、0–7% 良性误报；Ceasendo 类人类越狱开场即在单轮通道触发。
7. **逃逸鲁棒性**：黑盒分数感知攻击者（4 轮最低分改写）仅 2.5% 逃逸；白盒梯度访问与重复查询阈值估计未覆盖。
