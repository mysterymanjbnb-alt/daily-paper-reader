## 摘要
特权语言模型智能体可以通过驱逐一个健康的在位者来满足新的系统任务，而该在位者依赖于相同的文件、进程、套接字、锁或容量分配。这种失败之所以发生，是因为执行特权决定了一个操作能否运行，而不是请求者是否可以抢占当前资源所有者。我们提出了 LeaseGuard，一种确定性准入层，在适配器执行之前，通过规范化资源租约、在位者健康检查、效果感知准入、共存限制、安全替代方案以及资源作用域覆盖来表示抢占权限。我们在一个冻结基准上对其进行评估，该基准包含 60 个新编写的冲突场景，并跨两个本地模型家族设置了匹配对照。与保留提示相比，LeaseGuard 将未授权抢占从 73.3% 降至 0.0%，并将安全完成率提高 70.0 个百分点（按场景聚类的 95% CI [60.8, 79.2]）。请求任务成功率变化为 -3.3 个百分点（95% CI [-9.2, 2.5]）。经过完整评估的 v0.2 broker 还在哈希链接压力审计中拒绝了一个伪造的在位者任务身份。仅依赖到期的回收在错过续期后仍可能使健康的在位者暴露。证据支持在效果被完全中介、任务所有权经过认证且租约到期反映在位者存活状态时，采用在位者保持型准入控制。

## Abstract
Privileged language-model agents can satisfy a new system task by displacing a healthy incumbent that depends on the same file, process, socket, lock, or capacity allocation. This failure arises because execution privilege determines whether an operation can run, not whether the requester may preempt the current resource owner. We present LeaseGuard, a deterministic admission layer that represents preemption authority through canonical resource leases, incumbent-health checks, effect-aware admission, coexistence limits, safe alternatives, and resource-scoped overrides before adapter execution. We evaluate it on a frozen benchmark of 60 newly authored conflict scenarios with matched controls across two local model families. Relative to a preservation prompt, LeaseGuard reduces unauthorized preemption from 73.3% to 0.0% and increases safe completion by 70.0 percentage points (scenario-clustered 95% CI [60.8, 79.2]). Requested-task success changes by -3.3 points (95% CI [-9.2, 2.5]). The fully evaluated v0.2 broker also rejects a forged incumbent task identity in a hash-linked stress audit. Expiry-only reclamation can still expose a healthy incumbent after missed renewal. The evidence supports incumbent-preserving admission when effects are completely mediated, task ownership is authenticated, and lease expiry reflects incumbent liveness.

## 一、核心问题与整体含义（研究动机与背景）

- **问题定位**：特权 LLM 智能体在共享环境中执行新任务时，可能通过杀死进程、覆盖状态、占满容量等方式"挤占"一个健康的在任者（incumbent），而该在任者正依赖同一文件、进程、套接字、锁或容量分配。论文引用 ClashBench 证实这一"破坏性资源抢占"模式跨多种资源类别普遍存在。
- **根本原因**：执行特权（execution privilege）只回答"这个操作能否运行"，并不回答"请求者是否有权抢占当前资源所有者"。权限与抢占权被混为一谈，是失败的根源。
- **现有机制的空缺**：运行时策略门控、能力系统、事务机制、资源控制器分别解决相邻问题（动作约束、主体权限、效果排序与恢复、容量隔离与计量），但都不表示"健康在任者对具体资源的占有主张"，也不要求"破坏该主张的专门授权"。互斥/串行化只能改变顺序，不能赋予或剥夺抢占权。
- **核心洞见**：把**抢占权（preemption authority）作为一等公民、资源作用域的准入条件**，在适配器执行之前进行判定。
- **整体含义**：提出"适配器级在任者保持（incumbent-preservation）"属性，把普通操作许可与抢占权分离，并在进程、套接字、文件、锁、有界容量五类资源上落地。

## 二、方法论：核心思想、技术细节与判定流程

### 2.1 核心思想

- 在**结构化动作选择**与**适配器执行**之间插入一个**确定性 broker（准入层）**，只有通过资源租约语义检查的动作才被放行。
- 用**可续期的规范化资源租约**记录在任者主张；抢占必须凭**显式、作用域受限的一次性覆盖令牌**，而非宽泛的 shell/root 权限。

### 2.2 租约（Lease）的数据内容

每条租约 ℓ 记录：资源的规范化身份、在任任务与主体（principal）、生命周期、健康谓词、共存规则、是否要求显式覆盖、版本号。

### 2.3 形式化契约

在完全中介（complete mediation）假设下，论文给出核心蕴含式：

> Admit(a, s, ℓ) ∧ Active(ℓ, s) ∧ H_A(s) ∧ Foreign(a, ℓ) ∧ ¬Override(a, ℓ) ⇒ H_A(Exec(a, s))

即：**对健康、活跃的在任者，来自外部请求者且无有效覆盖的已准入动作必须保持其在任状态**。健康谓词 H_A(s) 由 true 变为 false 即定义为未授权破坏性抢占。

### 2.4 准入流程（算法流程，文字描述）

1. **规范化目标**：解析别名；文件系统、锁、套接字身份在沙箱内解析，进程与容量别名映射到实验域注册表键。
2. **失败关闭**：无法解析的目标与未知操作一律 fail closed，防止改名绕过租约。
3. **匹配活跃租约**：对每个匹配的活跃租约刷新在任者健康状态。
4. **效果分类**：将动作分类为 non-interfering / coexistence-safe / degrading / destructive / release / escalation。
5. **决策**：无健康的外部租约冲突，或请求任务标识与主体与所有租约一致时直接准入；面对健康外部在任者时，良性效果与 release 放行，degrading 效果在有安全上限时用 **ALLOW-WITH-LIMITS** 限制执行，destructive 效果必须有有效的作用域覆盖；否则返回**安全替代方案**、**等待决策**或**要求覆盖**。
6. **恢复**：智能体可把 broker 返回的替代方案作为第二次结构化动作提交（B4 允许一次恢复调用）。
7. **审计回执**：记录规范化资源、匹配租约、效果与健康状态、限制、覆盖状态、延迟、执行情况、前后证据。

### 2.5 适配器与授权

- **五类适配器共享同一契约**（效果分类、健康观测、安全上限、替代方案）：进程生命周期与隔离、TCP/Unix 端点、破坏性 vs 非破坏性文件更新、锁与 PID 文件获取、容量余量。
- **替代方案**：隔离进程、替换资源、复用或排队、临时工作区、有界容量份额。
- **覆盖令牌**：HMAC 认证、时限、一次性使用；验证时须匹配主体、请求任务、操作、规范化资源与租约，并记录令牌消耗。宽泛的 shell 权限不足以放行破坏性动作；有意的管理性抢占在回执中显式留痕。
